# Tighten deletion gates and avoid optional rename churn

## Notes



## Findings

1. Step 3's grep gate is internally impossible as written. `StepRecipe` still appears in `foundation/toolchains/__init__.py`, `tests/unit/foundation/toolchains/test_recipe_steps.py`, and `coding_lsp/lsp_recipe.py` until the planned deletions happen. Fix: define the pre-delete proof as “no production consumers except `coding_lsp/lsp_recipe.py` and no public imports except `foundation/toolchains/__init__.py` export scheduled for removal”, then do a post-delete grep requiring zero references outside docs/planning/history.

2. Step 4 leaves too much optional design discretion inside a reduction item. Renaming `CliInstallRecipe` to `CliInstallSpec` touches descriptors/base.py, descriptors/loader.py, lifecycle.py, provider tests, docs, and maybe serialized terminology. That is not the same risk profile as deleting dead test-only scaffolding. Fix: choose the docstring-only clarification in SL14; split any rename into a separate item with compatibility/serialization checks.

3. Package metadata is omitted. `src/audiagentic.egg-info/SOURCES.txt` currently lists `src/audiagentic/foundation/toolchains/recipe_steps.py`; if egg-info is tracked, deleting the file without updating/regenerating metadata leaves stale source references. Fix: add `src/audiagentic.egg-info/SOURCES.txt` to Files/Validation if tracked, or explicitly state generated metadata is ignored.

4. Validation for real LSP behavior is too vague. “LSP enable/install integration tests green” should name the concrete suites/functions because the deleted wrapper has its own test suite and the real path is `lsp_config_api.py` + `build_dependency_workflow`. Fix: require at least `tests/unit/coding_lsp/test_language_registry.py`, `tests/integration/coding_lsp/test_install_deps.py`, and relevant `test_provider_lsp_e2e.py`/`test_mcp_tools_e2e.py` collect or targeted cases.

5. `>=250 lines` reduction acceptance is brittle and can fail for irrelevant formatting/doc churn. Fix: make it informational (“expect ~250+ production LOC removed”) and gate on zero references + tests, not exact line count.

6. Docs update scope misses `providers/services/recipes.py` docstring. Current docstring references reusable recipe patterns, and SL13 also plans to edit it. Fix: add it to Files/Validation and note coordination with SL13 so doc updates do not conflict or reintroduce dead concepts.

## Conclusion

SL14 is directionally sound: delete `StepRecipe`, LSP recipe wrapper, and LSP metadata adapter if current grep proof still holds. Make it safer by clarifying pre/post grep gates, choosing docstring-only for `CliInstallRecipe`, and adding package metadata + concrete LSP validation.
