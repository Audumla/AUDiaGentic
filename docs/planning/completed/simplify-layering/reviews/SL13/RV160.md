# Tighten for average-agent implementability: split mechanical DO-steps from DECISION-steps

## Notes



## Findings

As drafted, SL13 mixes concrete behaviour-preserving rewires (MCP→provider machinery, rules→surfaces, composite collapse, zero-consumer deletions) with open judgment calls (plugin-array consolidation 'if callbacks map cleanly'; OwnedFileRecipe 'only if a second consumer appears'; installer-path convergence 'decide whether to converge'). An average-capability agent would stall on the judgment steps or force a bad abstraction — the exact ManagedEntryRecipe over-reach this item corrects. The mechanical core IS average-agent-safe when given exact call sites, deletions, and goldens gates. Fix: restructure Steps into PHASE A (mechanical, ordered, do now — each step names the exact functions to call, the exact class/methods to delete, and 'goldens must stay green' as the gate) and PHASE B (decisions — leave code as-is unless explicitly directed by a maintainer; record the decision, do not implement speculatively). Add explicit gotchas: grep-before-delete for zero consumers (§10), the list_provider_mcp_servers full-entry-read gap, and 'never invent a foundation pattern for one consumer'. Point implementers at the new docs/standards/USING_RECIPES.md for the target doctrine.

## Conclusion

Restructure SL13 Steps into Phase A (mechanical/now) + Phase B (decision/deferred). After that, Phase A is implementable by an average agent; Phase B stays a senior call. Reference the recipes standard.
