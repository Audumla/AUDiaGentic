# Clarify surfaces rewrite and MCP adapter contracts before implementation

## Notes



## Findings

1. A7 is underspecified and can produce destructive surface rewrites. `apply_provider_surfaces()` rebuilds all active contribution blocks, not one ad hoc Hindsight block. An implementer following the current wording may wipe, reorder, or reshape unrelated provider surface content while trying to add the Hindsight rule block. Fix: require a concrete single-block path, such as a new helper `apply_surface_block(path, block)` / `remove_surface_block(path, block_id)`, or an explicit algorithm that merges `build_provider_surface_blocks()` output with the Hindsight block for only the target file before calling `apply_managed_blocks()`.

2. A1's `get_managed_entry_status(...)` contract is too vague for lifecycle callers. “reports present/matches” does not define fields, failure behavior, or how callers should distinguish no provider MCP support from stale config. Fix: specify return keys at minimum: `ok`, `present`, `matches`, `config_path`, `server_name`, `actual_entry`, `desired_entry`, `reason`; define behavior when descriptor has no `mcp_config`.

3. A2 says remove `_McpConfigAdapter._inner`, but current `provision_steps()` depends on the inner recipe for `backend` and inner MCP steps. The plan must state where the backend is stored after the rewire and whether MCP provision-step introspection is removed, preserved, or rebuilt from row/backend data.

4. A7 validation covers coexist/prune, but misses idempotence and enabled-provider behavior. Surfaces prune/apply are enabled-aware; Hindsight rules may need to persist even when provider surface feature is disabled, or deliberately disappear. The item should decide and test this case.

5. “one commit per step” is process coupling inside the plan item. Agents may not have commit permission or the user may not want commits. Move to notes or drop unless commit slicing is explicitly part of execution.

6. A8 “collapse `_CompositeRecipe`” is too open-ended after A3/A7. Fix: define acceptable end state: delete the class if no custom merge remains, or keep a minimal combiner preserving `provision()` / `teardown()` semantics and artifact aggregation.

## Conclusion

SL13 has the right architectural direction after RV160, but is not implementation-safe yet. Tighten A7 with an explicit single-block surfaces API or merge algorithm, and tighten A1/A2 contracts before coding.
