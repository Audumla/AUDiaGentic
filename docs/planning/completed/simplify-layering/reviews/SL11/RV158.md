## Notes



## Findings

During implementation 2026-07-07: step 1's 'strip per-method stamping from hindsight primitives, one class per commit' was re-evaluated against SL12's scope. SL12 rewrites ALL 8 hindsight recipe classes into pattern-delegating wiring (HooksInstaller→DeclaredStepRecipe, _PluginArray/_McpConfigAdapter→ManagedEntryRecipe, GuidanceOnly→NoAutomationRecipe, _Composite→CompositeRecipe, etc.). The current primitive bodies do not survive SL12 — they are replaced by pattern delegation where the foundation pattern returns plain RecipeResult and the wiring's to_result stamps at the boundary. Stripping stamping from those primitives NOW, then deleting them in SL12, is redundant churn (§10 spirit: don't create intermediate states that get rewritten). What SL11 MUST deliver — and did — is the enabling infrastructure: (1) action_needed promoted to foundation RecipeResult with ok/fail kwargs + replace()-safety tests; (2) boundary stamping so primitives CAN return plain RecipeResult (ProviderRecipeRegistry.status/dry_run/repair + lifecycle._reconcile prune route through recipe.to_result via the _stamped helper; install/uninstall already did via provision/teardown); (3) §10 getattr→direct-access cleanup for the now-universal action_needed field (_stamp, ProviderCapabilityRecipe.to_result, status.py); (4) a golden regression test pinning all 8 classes' stamped output. The strip itself is delivered incrementally by SL12 as each class is converted to wiring — not wasted, just relocated to where it isn't double-work.

## Conclusion

Complete SL11 on delivered scope (promotion + boundary infra + cleanup + goldens). SL12 absorbs the per-method strip as a natural consequence of pattern extraction. No behavior change (goldens + full unit suite green; double-stamp is idempotent).
