# SL15 impl (attempt 2) is a net-negative: 444-line metaprogramming engine, dead validators, no actual config

## Notes

Reviewed the re-landed SL15 (config-driven RecipeSpec assembly). The provision() crash that sank attempt 1 (SL16 revert) is fixed — no_automation overrides provision() to delegate to NoAutomationRecipe.provision(); declared_step inherits base orchestration; memory unit suite green (108 tests). BUT the implementation reproduces the exact flaw that got attempt 1 reverted, and misses the stated goal.

EVIDENCE:
1. LOC-UP, not down (gate 7 violated). recipe_spec.py is a NEW 444-line file. recipes.py shrank by 126 (GuidanceOnlyRecipe + HooksInstallerRecipe deleted, ~108 lines). strategies.py grew ~+50. Net ~+400 lines to delete two small, readable subclasses.
2. Sits ON TOP of the foundation patterns, does not replace anything (USING_RECIPES.md doctrine: 'a config layer REPLACES classes, never sits on top of them'). RecipeSpec wraps NoAutomationRecipe/DeclaredStepRecipe via a bespoke interpreter layer.
3. NOT config-driven. _GUIDANCE_SPEC/_HOOKS_SPEC are Python module constants in strategies.py; there is NO YAML/external config. The user's goal ('generic reusability via config') is unmet — specs are still code, living where the deleted classes lived, now interpreted by an engine.
4. Dead validation subsystem. validate_recipe_spec (38 lines, error codes VAL-RSPEC-001..007) has ZERO callers anywhere (not even a test — test_recipe_spec.py does not exist). _validate_path_policy (26 lines, VAL-RSPEC-008) has zero callers. ~64 lines validating developer-authored constants that are never user input.
5. Fragile metaprogramming: _create_assembled_recipe_class synthesizes classes at runtime via type(); _make_stamp_method has a 5-branch closure factory; hook dispatch sniffs arity via inspect.signature(hook_fn).parameters == 4. Far harder to debug/step/type-check than the two subclasses removed.
6. No call-site simplification: strategies.py went from direct instantiation to assemble_hindsight_recipe(row, backend, _SPEC) + spec constants — more verbose, more indirection. The recipe-kind dispatch was already a small factory dict driven by HINDSIGHT_RECIPE_MATRIX rows; RecipeSpec adds a layer the matrix+factory already covered.
7. Stale docstring ref to deleted class at strategies.py:287 ('fall back to GuidanceOnlyRecipe').

CONCLUSION: This is attempt 1's failure mode with the crash patched — an interpreter for two hardcoded specs, net +400 LOC, dead validation infra, dynamic class synthesis, and zero delivered config. Recommend REVERT (restore GuidanceOnlyRecipe + HooksInstallerRecipe as direct subclasses, delete recipe_spec.py), same as SL16 did for attempt 1, and mark SL15 as a Phase B deferred decision — not to be attempted again without a real external-config consumer that justifies the machinery.
