# Scope outcome: 3 patterns extracted (ManagedEntry, NoAutomation, DeclaredStep); 5 classes assessed-and-declined to avoid forced abstractions

## Notes



## Findings

Implemented 2026-07-07. EXTRACTED to foundation/toolchains/recipe_patterns.py (359 lines, domain-neutral, boundary-guarded, 15 unit tests):
1. ManagedEntryRecipe + ConfigEntryTarget — manage one named entry in a config file (container key path, native reader/writer/remover OR ConfigPatcher JSON fallback, ownership registry, prune). HindsightMcpRecipe (mcp_recipe.py) collapsed 248→114 lines to a ~15-line subclass supplying entry name + payloads; behaviour inherited. This is the recipe face of SL10's fragment concept.
2. NoAutomationRecipe — guidance-only no-op lifecycle. GuidanceOnlyRecipe retrofitted to a delegate (~60→~38 lines).
3. DeclaredStepRecipe + InstallManifest — THE 'install via declared steps behind a source-verification gate, with status-command probe' capability the user asked to be reusable. HooksInstallerRecipe retrofitted (delegates probe/install/uninstall/verify/provision_steps; keeps hindsight-phrased configure/prune/dry_run). subject + source_label params preserve exact status strings (goldens green).

ASSESSED-AND-DECLINED (forcing these would add more parameters/entanglement than they remove — the over-engineering guard the user has repeatedly invoked):
- _PluginArrayRecipe: uses (path, package) package-keyed callbacks, NOT the (path)->{name:val} store shape of ManagedEntryRecipe; a genuinely different store signature with no ownership registry. Single use.
- PluginConfigRecipe / _PluginUrlConfigRecipe install/uninstall: 'OPTIONAL installer' shape (run steps only if audia_action==call_official_installer, else success no-op) — structurally different from DeclaredStepRecipe's mandatory-installer shape. Retrofitting would need a should_run flag + variant messages.
- _McpConfigAdapter / _CompositeRecipe: configure/prune are hindsight managed-ownership-sync (not generic); probe/verify already delegate to the ManagedEntryRecipe subclass. A generic CompositeRecipe would cover only the mechanical result-merge, leaving configure/prune — partial, low value.
- RulesOnlyRecipe: already consumes shared foundation primitives (managed_block + ArtifactRegistry); a consumer of shared mechanism, not a parallel path.

EVIDENCE: recipes.py -65 net, mcp_recipe.py -134 net, +359 reusable foundation. Full unit suite green (incl. stamping goldens proving behaviour-preservation); integration/e2e collect clean; ruff clean; boundary-guard test asserts recipe_patterns.py has zero component imports and zero domain vocabulary (Std §1).

## Conclusion

Complete SL12 on this scope. The user's ask ('anything that installs code can reuse this') is met concretely by DeclaredStepRecipe + ManagedEntryRecipe + NoAutomationRecipe in foundation, tested and domain-neutral. The declined extractions are documented with rationale; forcing them would violate the anti-over-engineering guidance.
