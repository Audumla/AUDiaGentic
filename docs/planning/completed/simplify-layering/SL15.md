# Config-driven capability recipes: collapse per-kind recipe classes into one spec-driven assembler + named hooks

## Description

Direction set by the user 2026-07-08: recipe reusability should come from CONFIG, not many tiny per-kind Python classes that are just configuration binding + provenance stamping (ARCHITECTURE_STANDARDS.md §2 Config Over Code). Reshaped by RV164 to avoid recreating the single-consumer speculative-abstraction problem SL13/SL14 exist to undo.

HONEST CONSUMER COUNT (RV164-1): the '8 kinds' are variants inside ONE production capability family (hindsight), not 8 independent consumers. After SL14, recipes are effectively hindsight-scoped. Therefore the assembler is HINDSIGHT-LOCAL (in components/memory/hindsight), NOT a new providers/services framework. Promotion to a shared providers-layer SpecDrivenCapabilityRecipe is a SEPARATE future item, gated on a REAL second capability adopting it — never on a synthetic/test consumer.

WHAT THIS ITEM DOES: within hindsight, replace the config-shaped recipe classes with a small local assembler that binds a declarative RecipeSpec (pattern + param bindings + resolve_ref hooks) to the foundation patterns, keeping strategy LOGIC and genuinely-custom kinds as code. It ASSEMBLES existing mechanisms (foundation patterns from SL12, resolve_ref from foundation/refs — already used by plugin_array_*, the recipe_kind registry, the SL11 to_result overlay). It does NOT invent a config interpreter and does NOT move code to the provider layer.

WHAT STAYS CODE (RV164-6, explicit): strategies.py strategy decisions are NOT pure recipe_kind dispatch — platform fallback, source gating, remote-MCP capability fallback, config-path resolution, rule-path fallback, and plugin subvariant selection. ONLY the field-presence subvariant selection is a candidate to become spec data; the gates/fallbacks REMAIN code. Genuinely-custom kinds (Windows plugin repair, composite ordering, payload builders) stay as small classes/hooks referenced from config by dotpath.

EVIDENCE the config-shaped kinds are config: HindsightRecipeRow already carries install_steps/uninstall_steps/status_command/plugin_*/notes/source_*/audia_action; GuidanceOnly = NoAutomationRecipe + strings, Hooks = DeclaredStepRecipe + row fields, and (post-SL13) MCP/Rules = provider-machinery call + a payload/text.
