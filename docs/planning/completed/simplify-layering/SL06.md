# External dependencies lack version pinning

## Description

The `source-control` component declares platform-specific installers (`winget`, `scoop`, `brew`, etc.) but never pins versions. A package manager update could install an incompatible version of `git`, `gh`, or `uv`.

## Proposed Solution

Add an optional `version` field to dependency declarations:
```yaml
dependencies:
  gh:
    display-name: GitHub CLI
    probe: binary:gh
    version: ">=2.60.0"
    via:
      winget: GitHub.cli
```
The dependency installer checks the installed version against the constraint and warns if unsatisfied. Keep it optional — components without version requirements don't need to specify it.

## Architecture Standards Assessment

**Standards risk: None.** Purely additive optional field. No layer boundary or config-over-code concerns. Uses `packaging.version` for constraint matching (standard library pattern).

## Resolution Assessment

**Complexity: Easy.** Straightforward implementation.

**Solution:** Add optional `version` field to dependency declarations in component YAML. Add version constraint checker in dependency installer using `packaging.version` for constraint matching. Installer warns if installed version does not satisfy constraint. Keep optional — components without version requirements don't need to specify it.
