# Extract five install patterns to foundation/toolchains recipe_patterns.py

## Description

With boundary stamping and action_needed promotion delivered by SL11, the five reusable install patterns instantiated by copy in hindsight/recipes.py (1064 lines, ~250 genuinely domain-specific) can be extracted to foundation as data-parameterized pattern classes returning plain RecipeResult. Rule-of-three satisfied WITHIN current code: installer block has 3 in-file copies, entry pattern has 2 + the services/mcp adapter.

Patterns to extract:
(a) DeclaredStepRecipe: install/uninstall step dicts, source-status gate, status-command probe, params. Covers HooksInstallerRecipe, PluginConfigRecipe, _PluginUrlConfigRecipe — all already inherit from _RowRecipe, so composition (field delegation) is the only viable approach; mixin would create diamond inheritance. Accepts generic `StepManifest` spec + `param_resolver` callback — no hindsight vocabulary in foundation API.
(b) ManagedEntryRecipe: FragmentStore + injected registry io + owner scope + entry name/payload builder. Covers _PluginArrayRecipe and _McpConfigAdapter — the recipe face of SL10's fragment engine. _McpConfigAdapter's probe/verify currently delegate to HindsightMcpRecipe which uses ConfigPatcher for JSON file writes (set_key/remove_key under container path) + managed MCP ownership sync. Evaluate post-wiring: if ManagedEntryRecipe covers both, DELETE HindsightMcpRecipe (2 direct instantiators in recipes.py:282 and strategies.py:264, all internal to hindsight) and HindsightTarget; otherwise port ConfigPatcher logic.
(c) CompositeRecipe: children list with per-primitive RecipeResult field merge and state combination table (~175 lines of mechanical merging).
(d) NoAutomationRecipe (was GuidanceOnlyRecipe): guidance statuses + action_needed string — generic shape parameterized by text.
(e) OwnedFileRecipe: path, expected_dict_fn, post_configure hook for Windows repair scenario.

Target: recipe_patterns.py beside recipe_contract — all data-parameterized, all returning plain RecipeResult, zero component imports (boundary-tested like fragments.py). Hindsight/recipes.py shrinks to ~350-400 lines of domain content: param vocabulary, plugin JSON schema, Windows plugin repair hooks, rule text, per-row pattern wiring.

## Steps

1. Extract DeclaredStepRecipe (not 'DeclaredInstallerRecipe') to foundation/toolchains/recipe_patterns.py: fields = install_steps/uninstall_steps (dicts), status_command, source_status, gate_message/notes, params; optional CommandProbe; install/uninstall = gated run_steps. Use composition — all 3 current classes (HooksInstallerRecipe, PluginConfigRecipe, _PluginUrlConfigRecipe) already inherit from _RowRecipe, so mixin would create diamond inheritance; hold DeclaredStepRecipe as a field and delegate install/uninstall to it (matching existing delegation pattern used by PluginConfigRecipe._inner and _McpConfigAdapter._inner). Constructor accepts `StepManifest` spec (generic name — not 'row data') and `param_resolver: Callable[[BackendConfig], dict]` callback instead of hindsight-specific '_hindsight_params'. HooksInstallerRecipe and the other 2 classes become thin wrappers that pass their row fields into StepManifest and supply _hindsight_params as the resolver.
2. Extract ManagedEntryRecipe: FragmentStore wrapper with injected registry io, owner scope, entry name/payload builder. _PluginArrayRecipe becomes wiring (store from row-declared reader/writer/remover with signature adaptation). _McpConfigAdapter becomes wiring (store from descriptor spec, managed-mcp registry io, HINDSIGHT_MANAGED_ID); fold its probe/verify reader-comparison into ManagedEntryRecipe.probe(expected payload). HindsightMcpRecipe decision: its current behavior is ConfigPatcher-based JSON file writes (set_key/remove_key under container path like ('mcpServers',)) plus managed MCP ownership sync. If ManagedEntryRecipe wiring covers both the entry management and the ownership sync, DELETE HindsightMcpRecipe + HindsightTarget — only 2 direct instantiators (PluginConfigRecipe.__init__ line 282, strategies.py _build_mcp_recipe line 264), all internal to hindsight. If ConfigPatcher's default-container navigation is needed elsewhere post-wiring, port; otherwise delete (§10).
3. Extract CompositeRecipe (children: list[recipe]; per-primitive merge; state combination table) and NoAutomationRecipe (statuses + action_needed) and OwnedFileRecipe (path, expected_dict_fn, post_configure hook). Hindsight classes become thin wiring subclasses or direct instantiations in strategies.py.
4. Boundary test: recipe_patterns.py imports nothing from audiagentic.components (mirror test_fragments.py guard pattern).
5. Migrate hindsight unit tests that pin implementation details of deleted/absorbed classes; keep behavior goldens as safety net. Full unit suite + integration/e2e green; ruff clean.
6. Update providers/services/recipes.py and hindsight READMEs/docstrings: foundation = lifecycle + patterns (SL11 boundary + SL12 patterns); providers = registry + provenance overlay; capability = data + wiring.
