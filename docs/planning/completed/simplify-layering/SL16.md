# Revert the broken SL15 assembler (net-increase duplication + provision() crash); restore direct class instantiation

## Description

Corrective item for the SL15 implementation defects found in RV169 (2026-07-08). The landed assembler (recipe_assembler.py ~706 lines + recipe_spec.py ~207 lines, wired into strategies.py) is a NET NEGATIVE and contains a verified latent crash. It must be reverted to restore correctness; the config-collapse goal returns to SL15 under stricter gates.

WHY REVERT (not fix-in-place): even fixing the crash leaves the core problems — (1) it ADDED ~900 lines and DELETED nothing (all original classes HooksInstallerRecipe/GuidanceOnlyRecipe/RulesOnlyRecipe/_McpConfigAdapter/_PluginArrayRecipe still exist, so it is pure duplication); (2) _SpecDrivenRecipe RE-IMPLEMENTS RulesOnly/Mcp/PluginArray logic inline instead of delegating; (3) it baked in the pre-A7 rules writer (apply_managed_block); (4) the MCP config_path is never resolved (uses project_root — wrong artifact/step paths). A minimal patch cannot salvage this shape; the classes are still present and tested, so reverting is clean and low-risk.

VERIFIED CRASH: _SpecDrivenRecipe.provision() raises NotImplementedError for every pattern except no_automation. Reproduced end-to-end: registry.install() -> recipe.provision() -> NotImplementedError for an assembled declared_step (hooks) recipe. ACTIVE surface today = HOOKS + WRAPPER_CLI (both route _build_hooks_recipe -> declared_step). GUIDANCE_ONLY uses no_automation (safe). MCP/HYBRID/PLUGIN_CONFIG still use the old classes (not yet migrated). The full unit suite passes ONLY because the stamping goldens exercise the OLD classes directly and apply_hindsight integration is Docker/live-gated — a coverage gap that hid the crash.

SCOPE: this item is a REVERT to the pre-SL15 (classes-only) state, which is correct and green. It does NOT attempt the config collapse — that stays in SL15 with the RV169 lessons added as mandatory gates.
