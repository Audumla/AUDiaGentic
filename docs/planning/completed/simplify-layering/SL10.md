# Generic managed-fragment reconciler in foundation — MCP/blocks become domain adapters, no MCP types in the generic layer

## Description

providers/services/mcp.py:_sync_managed_entries (lines 169-258) implements a reconciliation engine whose algorithm is entirely domain-generic: desired set keyed by stable managed_id → (name, payload); persisted ownership registry (owner scope → {managed_id → name}); stale-entry removal; rename handling (write new name, remove old); cross-owner name-collision detection; post-change refresh trigger. Nothing in the ALGORITHM is MCP-specific — only its bindings are: McpServerEntry payload type, the descriptor mcp_config reader/writer/remover trio, config-path resolution, reload_provider_mcp refresh, and the registry file name (load/save_managed_mcp_registry).

foundation/toolchains/managed_block.py is the SAME desired-state pattern for sentinel-marked text blocks (block_id ≈ managed_id, text ≈ payload) with its own ad-hoc ownership via ArtifactRegistry. So the codebase has two sibling implementations of 'reconcile audiagentic-owned fragments inside a user-owned file' and a third consumer (hindsight, HM21) about to need it.

Opportunity: pull the reconciler UP into foundation as a generic capability WITHOUT binding MCP into it. Foundation gets a payload-opaque engine parameterized by a small store protocol; MCP stays a thin domain adapter in providers/services; managed text blocks become (optionally, later) a second adapter. Constraint (hard): no MCP types, no provider descriptor knowledge, no imports from components/* in the foundation engine — payloads are opaque Any, refresh is an injected callable, ownership scope is an opaque key string.

## Steps

**Validate-first:** (a) unit-test the CURRENT _sync_managed_entries behavior exhaustively first (stale removal, rename, collision, subset managed_ids, no-op path, refresh trigger) as characterization tests — these become the contract tests for the generic engine; (b) confirm the ownership registry format (load/save_managed_mcp_registry) and where it lives, to design the generic registry as a superset that migrates or namespaces cleanly; (c) grep all _sync_managed_entries/sync_managed_provider_mcp* callers.

1. Define the store protocol in foundation/toolchains (e.g. fragments.py): `FragmentStore` with read(path) -> dict[str, Any], write(path, {name: payload}) -> None, remove(path, name) -> bool. Payload is opaque; equality/serialization is the store's business.
2. Implement `reconcile_fragments(store, path, owner_scope, desired: dict[managed_id, (name, payload)], *, managed_ids: set|None, registry_io, on_change: Callable|None) -> ReconcileResult` — a faithful port of the _sync_managed_entries algorithm: removal of stale owned entries, collision detection against other owners in the same scope, rename move, ownership persistence, on_change refresh hook, structured result (updated/removed/collisions/ok). registry_io is injected (load/save callables) so foundation does not fix the storage location.
3. Rewrite providers/services/mcp.py as the MCP domain adapter: FragmentStore built from descriptor mcp_config (reader/writer/remover), owner_scope = f"mcp:{provider_id}", on_change = reload_provider_mcp, registry_io = existing managed-mcp registry (format-compatible — keep the file as-is to avoid migration). Public functions (sync_managed_provider_mcp, _subset, add/remove/list) keep signatures; bodies shrink to adapter + engine calls.
4. Do NOT convert managed_block in this item — record the adapter sketch (block_id→name, text→payload, marker parsing as read()) in the item notes for a follow-up; converting it now would couple this change to surfaces/skill consumers unnecessarily (rule of three is satisfied for the engine by MCP + hindsight; block conversion is optional value later).
5. HM21 integration point: hindsight's MCP fragment sync targets the providers adapter (sync_managed_provider_mcp_subset with managed_id 'ag-hindsight') — which after this item is the generic engine underneath. If this item lands first, HM21 step 1 needs no change; if HM21 lands first, its calls migrate transparently.
6. Characterization tests from validate-first run unchanged against the refactored adapter (same public API); add engine-level tests with a dict-backed fake store proving foundation isolation (no provider imports in test).
7. Import-boundary check: assert foundation/toolchains/fragments.py imports nothing from audiagentic.components (add to the architecture-boundary test suite, tests/unit/foundation/toolchains/test_architecture_boundaries.py).

## Effort & Risk

Mid effort, low-medium risk — the algorithm port is mechanical and gated by characterization tests written before any change. Main design risk: over-generalizing (e.g. absorbing ArtifactRegistry or managed_block now) — explicitly out of scope; the engine earns its foundation placement from two real consumers (MCP adapter + hindsight via HM21), matching the location-follows-usage doctrine from the descriptors cleanup. Ordering: ideally BEFORE HM21 (its MCP step then lands on the final engine); acceptable after.
