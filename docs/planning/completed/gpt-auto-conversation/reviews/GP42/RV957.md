# Live GPT code review found a real merge blocker: get_page erased _pages on any CdpError, not just genuine target loss

## Notes



## Findings

B1 (blocker): _refresh_page()'s `except CdpError as exc:` around Target.getTargetInfo conflated a genuine protocol-level "no such target" response with a transport-level failure (connection closed, client stopped, stale connection detected). GP18 established the explicit invariant that _pages (handle->targetId identity) deliberately survives a CDP WebSocket reconnect, while only _sessions is generation-scoped and invalidated. The new get_page catch violated that: a transient connection failure during Target.getTargetInfo would erase a perfectly live handle->targetId binding and report "unknown or closed page handle", turning a recoverable connection event into apparent page destruction. The reviewer noted the new test codified this over-broad behavior by using a generic CdpError to simulate closure, never distinguishing it from a transport CdpError.

Non-blocking findings (not required for merge, logged for follow-up): (1) get_page still calls Browser.getWindowForTarget on every poll tick even though the hot snapshot path never consumes page.window_id -- windowId is only genuinely needed on the list_pages() discovery/reconciliation path; (2) url_matches_provider_session() is host-blind (matches /c/<id> on any hostname), incidentally protected today only by dedicated-window mode's windowId=None rejection -- pre-existing, not caused by GP42, but now that URL ownership is an explicit concept (is_gpt_auto_relevant_url), centralizing one is_chatgpt_host() primitive would prevent drift; (3) GP38's reconciliation still only imports response-complete's any_of_groups rather than evaluating the full EvidencePolicy object, so a future all-of/none-of/any-of addition to the config could drift normal completion and recovery apart again.

Everything else in the diff was assessed as correct: GP42 URL/window scoping preserves runtime.py's dedicated-window duplicate-tab matching (both chatgpt.com and chat.openai.com still get windowId, satisfying find_conversation_page()'s page_belongs_to_dedicated_window() + url_matches_provider_session() conjunction); GP41's AND-selector fix is correct defense-in-depth; GP38's empty-groups guard is semantically aligned with EvidencePolicy.evaluate(); GP38's timer-reset is correctly placed on every invalidation path checked; GP40's candidate-reset ordering (PROGRESS wins, then terminal-candidate loss resets, only continuous candidacy ages toward verification) is correct and complete for the reported flicker hole.

## Conclusion

B1 fixed 2026-08-17: added CdpProtocolError(CdpError) in cdp/client.py, raised specifically at the one site where the CDP server itself returns a JSON-RPC "error" field for a command (client.py's _read_loop, previously a bare CdpError) -- this is the only site that is genuine positive evidence a target/command target is gone.
