# gpt-auto backlog review: define a stricter state matrix before implementation

## Notes



## Findings

'Requests from proven-dead owners → interrupted' is too broad. A running/provider-side-effect-capable request owned by a dead generation should generally become interrupted; a merely durable queued request may have a fundamentally different safe recovery path (no provider action necessarily occurred). 'Provably dead' must be defined via process-instance/owner epoch with PID-reuse-safe evidence, not just 'PID isn't visible'.

## Conclusion

Define behavior by durable state + attempt state + ownership evidence, not one blanket owner-loss rule. Preserve session exactly as GP06 says: active durable provider session, missing process-local runtime, lazily rehydratable. Runtime death never means provider-conversation death. Heavily fenced, CAS/idempotent transition.
