# Deep adversarial review of GPT conversation exhaustion handling

## Notes

Reviewed live maximum-length banner evidence and the current snapshot, turn, error registry, retry, artifact, and session-resume seams.

## Findings

Conversation exhaustion must be a distinct provider-terminal failure. Require one fresh current-turn observation containing the normalized complete banner and an enabled visible exact Start new chat control, with page idle and no Stop control. Banner/control alone, historical text, user prompt text, partial phrases, generic navigation, or busy contradictions must not qualify. The current request fails before normal completion/artifact persistence; no automatic same-binding retry and no autonomous new-chat click. The durable provider binding becomes non-resumable using existing session/error mechanisms; later normal admission creates a fresh provider conversation. Local cross-check adds that the new code must use the registered EXT-GPTAUTO namespace and explicitly bypass the default transient retry classifier.

## Conclusion

Agreed target after adversarial review: implement narrowly in provider-private detection plus existing gateway error/session seams. Register EXT-GPTAUTO-006 for conversation exhaustion, classify it terminal/no-retry, preserve only bounded evidence, and keep remote deletion and automatic migration out of scope.
