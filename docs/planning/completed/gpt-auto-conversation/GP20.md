# Add three-tier gpt-auto config loader (packaged defaults / machine override / project overlay)

## Description

Slice 1 of GP09 (see GP09's notes for the full live design consultation). Introduces the layered config resolution GP09 recommends: packaged defaults at src/audiagentic/components/providers/adapters/gpt_auto/defaults.yaml, an optional machine override at ~/.audiagentic/config/providers/gpt-auto.yaml, and project config becomes a sparse overlay specifying only overrides. Configuration flow: load defaults -> load optional machine override -> deep_merge(defaults, machine, project) -> strict GptAutoConfig.from_dict(). This is the foundational piece the other GP09 slices (schema migration, drift detection) build on.

## Steps

- Add defaults.yaml with the full current schema populated from today's typical project config values.
- Implement deep_merge() and the three-tier load order in config.py or a new loader module.
- Update project gpt-auto.yaml/gpt-auto-t1.yaml/gpt-auto-t2.yaml to become sparse overlays (only actual overrides).
- Add a provider-level config resolver hook so gateway fingerprinting and session creation see the same effective merged config (per GP09's get_provider_runtime_config_state() note).
- Test fixtures: add load_packaged_gpt_auto_defaults() + patch-only-needed-values helper; stop maintaining separate full valid_config() copies across test files.

Full gpt_auto suite (142 tests) passes.

LIVE-VALIDATED on gpt-auto-t1 (req_9f51b1c744974bc7, session ses_b09ab6094cc14385) post-restart -- completed cleanly, proving the still-fully-specified existing project config files resolve identically through the new merge path (deep_merge always lets a fully-specified overlay override every default leaf, so this is a functional no-op for today's configs; the payoff is that FUTURE/new project configs can now be sparse).

Deliberately scoped down from the full three-tier design: only packaged-defaults + project-overlay implemented; the machine-override tier (~/.audiagentic/config/providers/gpt-auto.yaml) is explicitly deferred, since GP09's actual motivating incident was schema-version drift (GP21's scope), not a missing machine tier, and adding a new global file-system location plus gateway-startup wiring was judged too much added risk/scope for tonight. Existing project config files (.audiagentic/config/providers/gpt-auto*.yaml) were deliberately NOT trimmed into sparse overlays as part of this change -- they remain fully-specified (harmless, since a full override is a no-op through deep_merge) to avoid touching live production config during an already-eventful restart session; trimming them to prove the sparse-overlay win in practice is a safe, low-risk follow-up for a calmer session.

Note: the live validation for this item happened in the same restart cycle where GP31 (gateway restart workaround killed the running Brave browser process) was discovered -- GP20's own functional correctness is not in question (the config merge logic itself is what was being tested, and it worked correctly both in the completed test turn and deterministically), but see GP31 for the unrelated, serious side-effect finding from that same restart.
