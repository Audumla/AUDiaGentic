# Add gpt-auto contract-version schema migration helper (v1 -> v2)

## Description

Slice 2 of GP09 (see GP09's notes for the full live design consultation), depends on slice 1 (three-tier config loader) landing first. Introduces real schema versioning instead of a hardcoded contract-version:'v1' check that hard-fails the whole gateway when one project's config predates a schema-affecting code change (the exact bigcherry incident that motivated GP09). Adds CURRENT_CONTRACT_VERSION='v2', SUPPORTED_CONTRACT_VERSIONS=('v1','v2'), and migrate_v1_to_v2() so an old-schema project config degrades gracefully instead of hard-failing.

## Steps

- Add CURRENT_CONTRACT_VERSION/SUPPORTED_CONTRACT_VERSIONS constants and migrate_v1_to_v2() to config.py.
- Distinguish missing-in-overlay (inherit from defaults/machine) from missing-after-full-resolution (real validation error) from unknown-field (typo, fail with exact path).
- A project config newer than the gateway's own supported version must be rejected as an incompatible PROJECT (blocks only that project), never silently degraded and never crashing the shared gateway.
- Do NOT implement multi-version service branches in turn.py/chat.py -- migration happens once, at config-load time, producing one current-schema GptAutoConfig.
