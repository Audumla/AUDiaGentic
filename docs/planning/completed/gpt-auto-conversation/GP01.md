# Humanize gpt-auto: prompt pool + variable delays to avoid bot detection

## Description

The gpt-auto test triggered ChatGPT bot detection because it reused a single obvious test prompt ('What is the capital of France?') and submitted repeatedly with uniform timing. Build a prompt pool that cycles/randomizes real-world prompts (and optionally pulls random content from an online source), and make typing/send delays variable and human-like.

## Steps

- Create a prompt pool module with a large set of realistic prompts grouped by category
- Add optional random-content fetch from an online source (e.g. random sentence/quote API) with graceful fallback to the local pool
- Make typing delays variable (jitter around a mean), add random mid-typing pauses, and a random think-delay before pressing send
- Wire pool selection + human delays through inject_prompt and the adapter so each call behaves differently
- Validate with the full conversation test that consecutive runs use different prompts
- Update gpt_auto.yaml with humanize config knobs (delay ranges, pool size)

## Detailed Solution & Technical Design

prompt_pool.py: exposes pick_prompt(category=None) returning a prompt. Backing = a curated list of ~100 realistic prompts (technical questions, code review requests, planning queries, opinion questions) + optional online fetch via requests to a random-content endpoint with timeout + fallback. humanize.py: jittered_delay(mean, jitter), typing generator that yields per-char delays with occasional pauses, and think_delay() between injecting text and clicking send. inject_prompt gains optional humanize flags; adapter reads config keys like typing-delay-mean/typing-delay-jitter/think-delay-min/think-delay-max/send-delay.
