# message-finalized wrongly declared dead under GP32 -- reinstated as a third any-of-groups entry paired with not-generating

## Description

GP32 (earlier 2026-08-17) concluded ChatGPT had removed the [data-is-last-node] DOM marker entirely, based on it being absent document-wide for one specific long technical-essay response. Live-reproduced later the same night on a trivial single-paragraph answer (a basic conversation smoke test): the response text was fully rendered and stable for several minutes with NEITHER completion-control NOR more-actions-menu present anywhere in the document (not merely out of scope -- genuinely absent), while message-finalized was present and correctly scoped to the assistant message the whole time. The user independently confirmed this by inspecting the live DOM directly. Conclusion: message-finalized was never removed by ChatGPT -- it is conditional on the response's last rendered block being a plain paragraph (present) versus something else like a list/code-block/heading (absent, which is what GP32's original test case likely hit).

## Steps

1. Reinstated the message-finalized dom-signal definition ([data-is-last-node], scope latest-assistant-turn) in defaults.yaml, deleted under GP32.
2. Added a third any-of-groups entry to response-complete: [message-finalized, not-generating] -- paired with not-generating (the same derived fact GP34 added for the canvas group) rather than completion-control, since completion-control/more-actions-menu never appearing at all within a reasonable window is exactly the gap this group exists to route around. Never trusted alone: GP17 (2026-08-16) already proved message-finalized fires on genuinely-incomplete 7-35 char responses too.
3. chat.py's unresolved-turn reconciliation required no code changes -- it already reuses config.workflow.policy('response-complete').any_of_groups directly (GP38), so the new group was picked up automatically.
4. Corrected the historical 'ChatGPT removed the marker' claim in defaults.yaml's comments to the accurate 'conditional on last-block type' explanation.
5. Investigation was briefly confounded: a hover-simulation experiment and a scoping-bug hypothesis were pursued based on an ad-hoc unscoped DOM query that turned out to be the USER's own prompt-message copy button, not the assistant's (caught and corrected by the user); the conversation was also being concurrently, manually used by the user partway through the investigation, invalidating the 'stuck forever' framing for that specific turn even though the underlying message-finalized gap and fix are real and independently confirmed.
