# Composer selector (.ProseMirror) ambiguously matched a canvas turn's inline editor instead of the real chat composer -- misdirected prompt submission

## Description

Live-reproduced 2026-08-17 running test_out_of_sequence_injection_live.py's E3 control-turn: the user directly observed the script typing into the WRONG prompt box, corroborated by an EXT-GPTAUTO-003 'composer action was not confirmed by the browser' failure (send-button-clicked=false). Root-caused via direct CDP DOM inspection: every ChatGPT canvas/writing-block response renders its OWN .ProseMirror-based contenteditable INLINE in the conversation history (data-testid="writing-block-container"), positioned BEFORE the real chat composer (#prompt-textarea) in DOM order. gpt_auto_cdp.py's composer-detection and composer-typing code both used a bare document.querySelector('.ProseMirror') -- a first-match query with no scoping -- so whenever ANY canvas turn existed anywhere in the conversation history (not just the latest turn), it silently matched the canvas editor instead of the real composer. This is a genuine correctness/safety bug, not just a completion-detection gap: it could type a prompt into the wrong place, or (per the observed failure) fail submission confirmation entirely once a send-button click landed on the wrong element's context.

## Steps

1. Confirmed via CDP: every open tab with a canvas turn in its history had 2-3 .ProseMirror elements (one per canvas turn, all appearing before #prompt-textarea in DOM order); #prompt-textarea was present, unique, and stable across every observed page state (canvas or not).
2. Changed both composer-detection (_SNAPSHOT_FN's composerPresent/composerEditable check) and composer-typing (submit()'s insertText target) in gpt_auto_cdp.py from document.querySelector('.ProseMirror') to document.querySelector('#prompt-textarea').
3. Updated the one deterministic test with a synthetic composer fixture (test_python_cdp_bridge.py) to include id='prompt-textarea' on its fake ProseMirror div, matching the new selector.
4. Validated read-only against every live tab open at the time (5 tabs across gpt-t1/gpt-t2, several with canvas turns in history): #prompt-textarea correctly resolves to the real composer (inside the chat <form>, never inside a writing-block-container) in every case, with zero new ChatGPT interaction.

## Detailed Solution & Technical Design

This may also explain GP33 (2026-08-17, earlier the same night): a composer-operation-timeout with a prompt-text-length mismatch (242 observed vs 166 expected) on a second turn in the same session as a very long first response -- worth re-examining GP33 in light of this fix, since a misdirected .ProseMirror match is a plausible alternative explanation for that mismatch that was not considered at the time.
