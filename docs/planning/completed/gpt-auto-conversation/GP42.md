# PythonCdpBridge polled every browser tab on every conversation poll tick instead of scoping to gpt-auto's own tabs

## Description

Live-diagnosed 2026-08-17 via gp18_trace.log (513,049 total Browser.getWindowForTarget calls, Target.getTargets firing far more often than the configured ~1s poll_interval_seconds, a 271:14 ratio of Browser.getWindowForTarget to Runtime.evaluate in the last 300 trace lines -- meaning the actual completion-check Runtime.evaluate calls were being starved of scheduling time by an unrelated fan-out). Two compounding root causes traced through the code:

1. PythonCdpBridge._refresh_pages() (cdp/bridge.py) called Browser.getWindowForTarget once per page TARGET returned by Target.getTargets -- every single tab open anywhere in the shared browser (Reddit, Amazon, Claude.ai, Fastmail, Google Sheets, dozens of unrelated tabs observed live), not just gpt-auto's own ChatGPT/dashboard tabs. One extra CDP round-trip per unrelated tab, on every call.

2. chat.py's snapshot() -- called on EVERY poll tick of EVERY open conversation's turn-completion loop (poll_interval_seconds, so multiple times a second per open gpt-auto tab, with each tab polling independently/"each having its own cycle" per the user's framing) -- called CdpBrowserController.page_by_handle(), which called the FULL pages()/_refresh_pages() enumeration (a Target.getTargets scan of the entire shared browser) purely to re-resolve a handle it already held. evaluate() itself never actually needed that: it resolves the target straight from PythonCdpBridge's own local handle->targetId map (_target()), a pure dict lookup with no CDP round-trip at all.

Together these turned every poll of every gpt-auto conversation into a browser-wide Target.getTargets scan plus a per-unrelated-tab window lookup -- exactly the design the user called out as bad ("spawning calls for each tab", "hopefully that is only for its own tabs and not other tabs as well").

## Steps

- Add urls.is_gpt_auto_relevant_url(url): true for chatgpt.com/chat.openai.com hosts, the data: scheme (covers status_page.py's STATUS_PAGE_URL dashboard tab), and about:blank/empty (freshly created, not-yet-navigated tabs). False for everything else.
- _refresh_pages(): only call _window_id(target_id) (Browser.getWindowForTarget) for targets whose url passes is_gpt_auto_relevant_url; default windowId to None for everything else. Cuts the per-call fan-out from "every browser tab" to "only gpt-auto-relevant tabs".
- Add PythonCdpBridge._refresh_page(handle) / bridge method "get_page": resolves ONE already-known target via Target.getTargetInfo (single-target, not a full Target.getTargets enumeration), applying the same relevance-scoped windowId lookup. Handles the closed-target case by forgetting the stale handle/session and raising, mirroring the old page_by_handle contract.
- Route CdpBrowserController.page_by_handle() through bridge.call("get_page", ...) instead of pages()/list_pages(). This is the hot path (called on every poll of every conversation via chat.py's snapshot()) and is the primary fix for the call-frequency problem, not just the per-call cost.
- runtime.py's find_conversation_page()/page_belongs_to_dedicated_window() still use the full list_pages() path for multi-candidate resume/recovery matching (genuinely need to see every candidate page's windowId) -- left unchanged, verified those candidates are always chatgpt.com-hosted so the relevance filter never excludes a page they need.

## Detailed Solution & Technical Design

urls.py: added is_gpt_auto_relevant_url(url) as a pure function alongside the existing canonical_project_url/canonical_chat_url helpers.

cdp/bridge.py: _refresh_pages() now checks is_gpt_auto_relevant_url(url) before calling self._window_id(target_id); irrelevant targets get windowId=None without any CDP round-trip. Added _refresh_page(handle) using Target.getTargetInfo (scoped to the bridge's own locally-cached handle->targetId map via _target(), no full enumeration) plus the same relevance-scoped windowId resolution; wired into call() as bridge method "get_page".

cdp/cdp_browser.py: CdpBrowserController.page_by_handle() now calls bridge.call("get_page", {"pageHandle": handle}) instead of iterating the full pages() list.

No changes needed to chat.py, runtime.py, or gpt_auto_cdp.py -- evaluate()/snapshot() already only depended on page.handle, and runtime.py's multi-candidate matching still gets full windowId-populated pages via the unchanged list_pages() path (all candidates there are chatgpt.com URLs, which the relevance filter always includes).
