# Persistent conversation reuse via conversation-id URL

## Description

Currently the adapter always lands on /project (the project's new-chat page), which starts a brand-new chat every run. To have a continuous conversation, reuse the existing chat: capture conversation-id after a turn, then build the workspace chat URL (https://chatgpt.com/g/g-p-{id}-{slug}/c/{conv-id}) and navigate there on the next run. Only fall back to /project (new chat) when no conversation-id is available (fresh session).

## Steps

- Adapter captures conversation-id after wait_for_response (already present)
- find_workspace/ensure_workspace accept conversation_id and navigate to /c/{conv-id} URL
- Adapter passes conversation-id from provider_cfg/packet_ctx and skips fresh-chat reset when resuming
- Test supports --conversation-id CLI arg to resume an existing chat
- Live two-turn validation pending

## Detailed Solution & Technical Design

Add optional param conversation_id to ensure_workspace/find_workspace. When provided, navigate directly to workspace_base_url + /c/{conversation_id} instead of /project. Capture the post-response URL (adapter already returns metadata with conversation-id) and surface it as session-id output so callers can persist it.
