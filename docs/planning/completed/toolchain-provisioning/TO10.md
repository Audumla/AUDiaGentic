# ProvisionStep unified step model

## Description

Introduce a ProvisionStep protocol in foundation/toolchains/provision_step.py that gives every execution primitive — shell commands, config-key writes, managed rule blocks, file writes — a common run(context) / revert(context) / dry_run(context) interface.

This is the foundation layer for TO11 (CompensatingSequence) and TO12 (recipe migration). It does NOT change any callers, recipe classes, lifecycle orchestration, or YAML schema yet.

**Why this unification is valid:**

ConfigPatcher already captures revert state in OwnedChange.prior_value. managed_block already has apply_managed_block / remove_managed_block as inverse pairs. File writes can capture prior file existence/content during run(). Shell operations are not automatically reversible and need an explicit revert command, or no-op best-effort revert when none is declared.

The primitives split into two groups:
- Self-reverting: ConfigSetStep, ManagedBlockStep, WriteFileStep — revert is derived from captured run() state or inverse operation
- Explicit-revert: ShellProvisionStep — caller declares the revert command or leaves it None

**Relationship to existing step system:** ShellProvisionStep wraps ShellStep for normal argv commands. For shell-only commands such as pipes, ShellProvisionStep owns the shell subprocess execution unless ShellStep is extended in the same change. The workflow step system (SequenceStep, SelectStep, ConditionalStep) stays for non-provisioning orchestration. ProvisionStep is narrowly scoped to installable-integration lifecycle operations.

**S1 — Layer boundary constraint:** provision_step_from_dict lives in foundation/ and CANNOT import HindsightBackendConfig or any components/ type. The factory takes params: dict[str, str] only. Callers in components/ build this dict from backend config before calling the factory.

## Steps

Implementation order for a smaller agent:

1. **Read existing primitives first**:
- `src/audiagentic/foundation/workflow/invocation/models.py` for `StepResult`
- `src/audiagentic/foundation/workflow/invocation/steps.py` for `ShellStep`
- `src/audiagentic/foundation/toolchains/config_patcher.py` for `ConfigPatcher` / `OwnedChange`
- `src/audiagentic/foundation/toolchains/managed_block.py` for managed block helpers
- `src/audiagentic/foundation/toolchains/artifact_registry.py` for `ArtifactRegistry.register()`

2. **Create `ProvisionStep` protocol** in `foundation/toolchains/provision_step.py`:
```python
class ProvisionStep(Protocol):
    id: str
    def run(self, context: dict[str, Any]) -> StepResult: ...
    def revert(self, context: dict[str, Any]) -> StepResult: ...
    def dry_run(self, context: dict[str, Any]) -> StepResult: ...
```

3. **Implement `ShellProvisionStep`**:
- Inputs: `id`, `command`, optional `revert_command`, optional `shell: bool = False`, timeout/cwd/env if needed.
- For `shell=False`, delegate run/revert to `ShellStep`.
- For `shell=True`, execute the command string through `subprocess.run(shell=True, capture_output=True, text=True, encoding='utf-8', errors='replace')`.
- `revert()` with no revert command returns `StepResult(status='skipped', reason='no revert declared')`.
- `dry_run()` returns planned command details and does not mutate.

4. **Implement `ConfigSetStep`**:
- Inputs: `id`, `path`, `key_path`, `value`, optional `registry`, optional `recipe_id`.
- `run()` calls `ConfigPatcher.set_key(...)`, stores the returned `OwnedChange` on the instance, and registers it when both `registry` and `recipe_id` are provided.
- `revert()` skips if no successful `OwnedChange` exists; otherwise restores prior value or removes key based on `OwnedChange.prior_value` semantics.
- `dry_run()` returns planned path/key/value details only.

5. **Implement `ManagedBlockStep`**:
- Inputs: `id`, `path`, `block_id`, `content`, optional `registry`, optional `recipe_id`.
- `run()` calls `apply_managed_block(...)` and registers returned block ownership when registry/recipe_id are present.
- `revert()` calls `remove_managed_block(...)`.
- `dry_run()` returns planned path/block_id only.

6. **Implement `WriteFileStep`**:
- Inputs: `id`, `path`, `content`, `create_parents=True`, optional `registry`, optional `recipe_id`.
- `run()` captures prior existence/content before writing, writes content, and registers file ownership when registry/recipe_id are present.
- `revert()` skips if run never succeeded; deletes created file or restores prior content.
- `dry_run()` returns planned path/create_parents only.

7. **Implement placeholder substitution helper**:
- Substitute `{KEY}` style placeholders in strings, nested lists, and nested dicts.
- Unknown placeholders should raise `AudiaGenticError` with a validation code, not silently remain unresolved.
- Do not import Hindsight or component types.

8. **Implement `provision_step_from_dict(data, params, *, registry=None, recipe_id=None)`**:
- Supported `type`: `shell`, `config-set`, `managed-block`, `write-file`.
- Validate required fields per type before constructing.
- Pass registry/recipe_id only to steps that can register artifacts.
- Unknown type raises `AudiaGenticError(code='VAL-PSTEP-001', ...)`.

9. **Export from `foundation/toolchains/__init__.py`**:
`ProvisionStep`, `ShellProvisionStep`, `ConfigSetStep`, `ManagedBlockStep`, `WriteFileStep`, `provision_step_from_dict`.

## Validation

Smaller-agent acceptance checklist:

- `tests/unit/foundation/toolchains/test_provision_step.py` exists and covers each step class independently.
- ShellProvisionStep success and failure paths return `StepResult(status='ok')` and `StepResult(status='failed')`.
- ShellProvisionStep `shell=True` path is unit-tested without executing network commands; use a local harmless command or monkeypatch subprocess.
- ShellProvisionStep `revert()` with no revert command returns `skipped`.
- ConfigSetStep creates a missing key, overwrites an existing key, and reverts both cases correctly.
- ConfigSetStep `revert()` before successful `run()` returns `skipped` and does not mutate.
- ManagedBlockStep run/revert leaves target file without the managed block.
- WriteFileStep run/revert covers both created-file and overwritten-file cases.
- Registry integration is tested with a fake or temp `ArtifactRegistry`: config, block, and file steps register only after successful mutation.
- Placeholder substitution covers strings, lists, dicts, unknown placeholder error, and repeated placeholder usage.
- `provision_step_from_dict({'type': 'unknown', ...}, ...)` raises `AudiaGenticError(code='VAL-PSTEP-001')`.
- No imports from `audiagentic.components.*` exist in `provision_step.py`.
- `pytest tests/unit/foundation/toolchains/test_provision_step.py` passes.
- Existing foundation toolchain tests pass.

## Effort & Risk

Mid complexity, low risk. This item creates a new module with no callers, so it should not regress existing behaviour. Main risks are reversible state capture and shell=True execution. Keep tests focused on exact rollback state and error shapes.

## Standards

- S1 (Layering): provision_step_from_dict lives in foundation/toolchains/ and MUST NOT import HindsightBackendConfig or any components/ type. The factory signature is provision_step_from_dict(data: dict, params: dict[str, str]). The caller in components/ builds the params dict from backend config.
- S8 (Error handling): Unknown type in provision_step_from_dict raises AudiaGenticError(code='VAL-PSTEP-001'), not ValueError. All public-boundary exceptions use AudiaGenticError.
- S10 (Migration doctrine): This item does not write install_command. That field must not be added to HindsightRecipeRow or any YAML row as part of TO10. TO12 removes the old command-string fields atomically and migrates all matrix rows to install_steps. No fallback shim is introduced at any point.

## Notes

Prerequisite for TO11 (CompensatingSequence) and TO12 (recipe migration).

**ArtifactRegistry integration:** `ConfigSetStep`, `ManagedBlockStep`, and `WriteFileStep` may accept optional `ArtifactRegistry | None` plus `recipe_id`. When provided, `run()` registers owned artifacts after successful mutation so a later prune in a separate process can discover them. Registry support is not required for in-process rollback, but is required for cross-session prune.

**Placeholder params:** Hindsight callers must pass params such as {"URL": backend.base_url, "MCP_URL": backend.mcp_url, "KEY": backend.api_key}. The foundation factory only substitutes supplied params; it does not construct or require Hindsight-specific keys.
