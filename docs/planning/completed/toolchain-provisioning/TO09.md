# Validate official harness integration matrix (discovery gate)

## Description

Discovery-only gate for the recipe model: build a source-backed matrix of official Hindsight (and LSP) integration methods for each AUDiaGentic-supported provider/harness, so recipes are designed from real install mechanics rather than assumptions. No code until each provider/harness is classified by actual install technique. Supersedes the former harness-integration-strategy plan (HI01-04); the implementation stages of that plan are now TO01-TO08.

## Steps

['For each in-scope provider/harness (codex, claude, cline, copilot, gemini, opencode, openhands, roo, continue_, and any other first-class adapters), capture the official Hindsight integration page URL with date checked.', 'Classify each integration by install technique: hooks, mcp-config, plugin, rules-only, skills, native-built-in, or hybrid.', 'Capture the concrete install/uninstall/status mechanism: command/package or named installer (e.g. curl|bash), config files touched, runtime prerequisites, and whether the Hindsight server must already be running.', 'Map each official method to the planned recipe primitives (TO01-TO06): ShellStep install/uninstall, status probes, config patch, artifact ownership.', 'Produce a gap table: official method vs current toolchain primitive coverage vs missing primitive. Drives scope of TO02-TO06.', 'Do the same lightweight validation for coding-lsp native-vs-generic provider handling so memory and LSP share terminology (feeds TO07).']

## Validation

['Every targeted provider/harness has a cited official source URL or an explicit no-official-source-found entry.', 'Each row has exactly one primary install-strategy classification.', 'Matrix identifies which current toolchain primitives can already model the integration and which require new primitives (TO02-TO06).', 'LSP comparison notes recorded so memory does not invent a parallel abstraction.']
