# CompensatingSequence executor

## Description

Add `CompensatingSequence` to `foundation/toolchains/provision_step.py`.

The executor runs a `ProvisionStep` list forward; on failure it reverts only committed steps in reverse order. Revert is best-effort: failures are logged and captured in result details, but never mask the original run failure.

This item is executor-only. It does not change `ProvisioningRecipe.provision()` lifecycle behavior yet. TO12 wires recipes into the executor after recipe classes can produce complete provision step lists.

**Rollback semantics:**
```
Step 1 -> ok (committed)
Step 2 -> skipped (not committed, continue)
Step 3 -> ok (committed)
Step 4 -> failed
Rollback: Step 3.revert(), Step 1.revert()
Returns: Step 4 failure as primary result, rollback results in details
```
A skipped step is a successful no-op and is not reverted. A failed step is never reverted because it did not commit.

**Why `SequenceStep` is not extended:** `SequenceStep` lives in `foundation/workflow/` and is used by non-provisioning orchestration. Mixing rollback semantics there violates the boundary. `CompensatingSequence` lives in `foundation/toolchains/` and is only used by provisioning recipes.

## Steps

Implementation order for a smaller agent:

1. **Read TO10 output first**:
- Confirm `ProvisionStep` and step classes exist in `src/audiagentic/foundation/toolchains/provision_step.py`.
- Confirm `StepResult` shape from `src/audiagentic/foundation/workflow/invocation/models.py`.

2. **Add status policy constants** in `provision_step.py` near `CompensatingSequence`:
- committed run status: `ok`
- successful no-op run status: `skipped`
- dry-run success status: `planned` and `skipped`
- all other statuses are failures

3. **Implement `CompensatingSequence` constructor**:
- Inputs: `steps: Sequence[ProvisionStep]`, optional `id: str = 'compensating-sequence'`.
- Store a list copy of steps.

4. **Implement `run(context)`**:
- Execute each step in order.
- Append a step to `committed` only when its result status is `ok`.
- Continue on `skipped`, but do not commit it.
- On first failure status, call `_rollback(committed, context)`, then return a failed StepResult preserving the original failure reason/status and adding rollback results to outputs.
- On full success, return `StepResult(status='ok', outputs={'steps': per_step_results})`.

5. **Implement `_rollback(committed, context)`**:
- Iterate committed steps in reverse order.
- Call `step.revert(context)` for each.
- Catch `Exception` per step, log `logger.warning('Revert of step %s failed: %s', step.id, exc, exc_info=True)`, and convert it into a failed StepResult entry.
- Return the full rollback result list.

6. **Implement `revert(context)`**:
- Revert all configured steps in reverse order, using the same best-effort exception handling as `_rollback`.
- Return `ok` if every revert result is `ok` or `skipped`; otherwise return `failed` with per-step results.

7. **Implement `dry_run(context)`**:
- Call each step's `dry_run(context)` in forward order.
- Do not call `run()` or `revert()`.
- Return `ok` if every dry-run result is `planned`, `ok`, or `skipped`; otherwise return `failed` with per-step results.

8. **Export `CompensatingSequence`** from `foundation/toolchains/__init__.py`.

## Validation

Smaller-agent acceptance checklist:

- `tests/unit/foundation/toolchains/test_compensating_sequence.py` uses fake ProvisionStep objects; no filesystem or subprocess needed.
- Successful run calls each step once in order and returns status `ok`.
- Failure at step 2 after step 1 ok calls step 1 revert, does not run step 3, and returns original failure reason.
- Failure at step 4 after ok/skipped/ok reverts only the two ok steps in reverse order; skipped step is not reverted.
- Step `skipped` during run continues execution and is included in outputs as a no-op.
- Revert exception is logged with `exc_info=True`, converted into failed rollback result, and does not raise.
- Revert failure does not hide the original run failure.
- `revert(context)` reverses all configured steps and reports aggregate failure when any revert fails.
- `dry_run(context)` calls only dry_run methods in forward order and treats `planned`, `ok`, and `skipped` as successful dry-run statuses.
- `pytest tests/unit/foundation/toolchains/test_compensating_sequence.py` passes.
- Existing `tests/unit/foundation/toolchains` tests pass.

## Effort & Risk

Low to mid. This item is pure executor logic around already-defined ProvisionStep primitives. Main risk is unclear status handling; define `ok` as committed, `skipped` as successful no-op, dry-run `planned` as successful only in dry_run(), and all other statuses as failures.

## Standards

- S8 (Error handling): _rollback() catches Exception at external-boundary revert calls. It never re-raises and always captures exception details.
- S9 (Logging): Every caught exception in _rollback() MUST be logged at logger.warning level with exc_info=True before continuing to the next revert step. Silent exception swallowing is a violation.
