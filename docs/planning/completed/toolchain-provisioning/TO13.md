# Fix ProvisionStep migration gaps and update tests

## Description

TO10-TO12 implementation introduced the new ProvisionStep workflow, but review found migration gaps and tests that do not yet enforce the new behavior. This item is for a smaller agent to finish the workflow migration safely: update tests first, then fix implementation until the new workflow contract passes.

Scope is limited to defects in the current ProvisionStep/Hindsight migration. Do not refactor unrelated provider dispatch, release tooling, or non-Hindsight dependency installers.

## Steps

1. **Start with tests that fail on current gaps**. Keep or add tests covering:
- Shell step factory substitution for `command` and `revert_command` using backend params (`URL`, `MCP_URL`, `TOKEN`, `KEY`, `ID`).
- Unknown placeholders fail at factory time with `AudiaGenticError`, not at runtime with raw `KeyError`.
- `ConfigSetStep` and `WriteFileStep` expand `~` to the user home before writing.
- Actual verified Hindsight matrix rows can construct `provision_steps()` without unresolved placeholders.
- MCP-config recipes provision through the structured step path and still write provider config.
- Hybrid/composite recipes include installer steps, MCP config steps, and rule-block steps in the right order.
- Rollback pairs install steps with uninstall/revert behavior where possible.

2. **Fix shell placeholder substitution** in `provision_step_from_dict()`:
- Apply `_substitute()` to shell `command`, `revert_command`, `cwd`, and `env` where applicable before constructing `ShellProvisionStep`.
- Do not rely on `ShellProvisionStep._render()` for backend placeholders.

3. **Fix path expansion** in provisioning step primitives:
- `ConfigSetStep` must use `Path(path).expanduser()` before passing to `ConfigPatcher`.
- `WriteFileStep` must use `Path(path).expanduser()` for read/write/revert.
- `ManagedBlockStep` should also expand user paths for consistency.

4. **Fix Hindsight params and config paths**:
- `_hindsight_params()` should still return URL/MCP_URL/TOKEN/KEY/ID.
- Add provider/config-path params at the recipe layer when needed, especially `CONFIG_PATH` for rows with config-set steps.
- Do not add Hindsight-specific keys to foundation.

5. **Fix MCP recipe structured steps**:
- Add `HindsightMcpRecipe.provision_steps()` or remove adapter-level `provision_steps()` until it can return real steps.
- Generated MCP config steps must preserve provider-specific writer/reader/remover behavior where callbacks exist. If generic `ConfigSetStep` cannot support callback formats, keep callback recipes on primitive lifecycle path and do not expose `provision_steps()` for them.

6. **Fix hybrid/composite step order**:
- Composite recipes must include row-level install steps before MCP config/rule configure steps when the previous lifecycle did so.
- Hybrid order should be installer/init -> MCP config -> rule block.

7. **Fix rollback wiring for shell installers**:
- When install and uninstall step definitions correspond, wire uninstall commands as `revert_command` on install shell steps or otherwise ensure `CompensatingSequence` rollback invokes real uninstall steps for committed installs.
- If mapping cannot be made safely for a provider, document no explicit revert and add a test asserting best-effort behavior.

8. **Run focused tests, then broader tests**:
- Foundation toolchain tests.
- Hindsight memory tests.
- Architecture boundary tests.
- Full unit suite if runtime allows.
