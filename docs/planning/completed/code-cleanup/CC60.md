# Move root-level AUDiaGentic configs under .audiagentic/config/

## Description

Move Pi's .mcp.json (project root) to .pi/mcp.json (an already-natively-scanned Pi project-config source, not an AUDiaGentic invention). Keep Copilot's .vscode/mcp.json where it is — VS Code MCP extensions read it natively. Root .lsp.json is NOT moved — it is Qwen's own native LSP discovery file (confirmed against the installed qwen-code source), not AUDiaGentic-owned cache; moving it breaks Qwen's LSP feature outright with no workaround. Establish standard: config under .audiagentic/config/, cache under .audiagentic/runtime/cache/ (safely deletable). All paths resolve from foundation.paths constants with hard fail if config missing.

## Steps

- Move Pi's .mcp.json → .pi/mcp.json (update pi.yaml mcp.mechanism.config_path from ".mcp.json" to ".pi/mcp.json")
- Do NOT move root .lsp.json — it is Qwen's native LSP config file (hardcoded path.join(workspaceRoot, ".lsp.json") in qwen-code's own source, no override surface exists)
- Move .coding-lsp/ (CODING_LSP_DIR) under .audiagentic/runtime/cache/ — pure AUDiaGentic-internal cache, no external harness reads it
- Keep Copilot's .vscode/mcp.json at root — VS Code reads it natively
- Establish standard: config under .audiagentic/config/, cache under .audiagentic/runtime/cache/
- Update foundation.paths constants for new locations
- Ensure all path resolution uses constants, not hardcoded literals

## Detailed Solution & Technical Design

Current state:
- Root has scattered config: .lsp.json (Qwen's native LSP registry — NOT AUDiaGentic cache), .mcp.json (Pi's registration file, also scanned natively by pi-mcp-adapter for bare/manual launches)
- CODING_LSP_DIR = ".coding-lsp" is hardcoded in coding_lsp_config.py — this one genuinely is AUDiaGentic-internal generated cache
- No standard for cache vs config vs generated data separation

Evidence gathered against installed packages (not just docs), see RV929:
- Qwen: @qwen-code/qwen-code/cli.js LspConfigLoader.loadUserConfigs() does `path.join(this.workspaceRoot, ".lsp.json")` — hardcoded, no settings.json/env/CLI override (`qwen --help` confirms no --lsp-config/--config flag). Root .lsp.json MUST stay at project root.
- Pi: pi-mcp-adapter/config.ts getConfigSources() — 4 merge sources when --mcp-exclusive isn't passed: shared-global (~/.config/mcp/mcp.json), pi-global (Pi's agent-dir mcp.json — the only redirectable slot, already used by AUDiaGentic's --mcp-config), shared-project (<cwd>/.mcp.json), pi-project (<cwd>/.pi/mcp.json — has its own writePath, natively scanned same as .mcp.json). AUDiaGentic-orchestrated launches (execute/interactive/acp, see mcp_surface.py) never read config_path at all — they materialize a request-owned launch.json and pass --mcp-config/--mcp-exclusive explicitly. Only a bare/manual `pi` invocation outside AUDiaGentic depends on config_path's literal location, via pi-mcp-adapter's own native discovery.

Target state:
```
.audiagentic/config/         ← source-of-truth config
  linting/                  ← shared lint rules (CC58)

.audiagentic/runtime/        ← cache & generated data, safely deletable
  cache/                    ← LSP cache (was .coding-lsp/), indexes, temp data
  logs/                     ← component logs

.pi/mcp.json                 ← Pi's MCP registration (native pi-project source; NOT under .audiagentic/)
.lsp.json                    ← stays at root; Qwen's native LSP config, unmovable
.vscode/mcp.json              ← stays at root; VS Code's native MCP config, unmovable
```

All paths resolve from constants in foundation.paths — no hardcoded literals.
Coding-lsp component projects all config to providers on enable.
