# Move provider global config paths to project-local

## Description

Multiple providers write MCP/hook/model config to user-home paths (~) instead of project-local paths. This pollutes the user's home directory with project-specific config and means multiple projects share the same config file. All supported tools have documented project-local paths that should be used instead.

**Current state (global, problematic):**
- Claude MCP: ~/.claude/mcp.json
- Qwen MCP: ~/.qwen/settings.json  
- Antigravity MCP: ~/.gemini/antigravity/mcp_config.json
- Codex hooks: ~/.codex/hooks.json + hardcoded enable flag in ~/.codex/config.toml
- Pi models: ~/.pi/agent/models.json

**Target (project-local):**
- Claude: <project>/.mcp.json (--scope project supported)
- Qwen: <project>/.qwen/settings.json (--scope project overrides global)
- Antigravity: <project>/.agents/mcp_config.json (workspace path exists)
- Codex hooks: <project>/.codex/hooks.json + project-local config.toml enable
- Pi models: $PI_CODING_AGENT_DIR/models.json if set, else ~/.pi/agent/models.json

**Goose exception:** No project-local config exists. Remains global-only.

**Approach:**
1. Define callable path resolvers in adapter modules (e.g. resolve_claude_mcp_config_path)
2. Change YAML descriptors to use callables instead of hardcoded ~/ strings
3. Fix Codex hardcoded enable flag to be project-aware
4. Update tests that monkeypatch Path.home

## Steps

- 1. Add callable config_path resolvers to adapter modules: claude/config.py, qwen/config.py, antigravity/config.py, codex/hooks_format.py (project-aware enable), pi/model_config.py (env-aware)
- 2. Update YAML descriptors: claude.yaml, qwen.yaml, antigravity.yaml, codex.yaml, pi.yaml — change config_path from ~/ string to callable ref
- 3. Fix codex hooks_format.py _enable_codex_hooks to accept project_root and write to project-local config.toml instead of hardcoded home path
- 4. Update tests: test_managed_hooks_family.py (remove Path.home monkeypatch), test_provider_mcp_config.py, test_provider_config_loading.py
- 5. Verify with lens_diagnostics and run affected tests
