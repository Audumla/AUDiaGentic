# SES-001 — Replace session if/elif scope dispatch with registry tables

## Description

Two prohibited if/elif chains branching on scope strings (Standard #2 violation):
- `session_api.py:90-98` — scope dispatch for `update_rig()` ("local", "global")
- `session_visibility.py:13-24` — scope dispatch for `config_path()` ("project", "global")

Plus 7 duplicate `report_error()` try/except patterns in `session_mcp.py` and direct `AudiaGenticError` construction instead of `make_error()` in `session_visibility.py` and `session_runtime_status.py`.

## Steps

1. Create `_UPDATE_SCOPE_REGISTRY` in `session_api.py` mapping scope names to handler functions
2. Create `_SCOPE_PATH_RESOLVERS` in `session_visibility.py` mapping scope names to path builder callables
3. Extract `@guarded_tool` decorator from `session_mcp.py` to eliminate 7 duplicate try/except boilerplate patterns
4. Replace direct `AudiaGenticError(code=..., kind=..., message=...)` with `make_error()` in `session_visibility.py` and `session_runtime_status.py`
5. Define `Scope` enum for magic strings ("local", "global", "project")

## Files

Modified: `session_api.py`, `session_visibility.py`, `session_mcp.py`, `session_visibility.py`, `session_runtime_status.py`
New: `components/session/decorators.py` (optional — for `@guarded_tool`)

## Validation

No if/elif on scope strings remains, `@guarded_tool` decorator used for all 7 MCP tools, all errors use `make_error()`, `Scope` enum replaces magic strings

## Architecture Standards Assessment

**Standard #2 (Config Over Code):** Explicitly prohibits if/elif chains branching on entity names. **Standard #8 (Error Handling):** Direct `AudiaGenticError` construction instead of `make_error()`.

## Resolution Assessment

**Complexity: Simple.** Registry tables are straightforward dicts. Decorator extraction is mechanical.

**Why simple:** Each scope handler is already a separate function. Decorator wraps existing try/except.

## Effort & Risk

Low — additive dispatch tables, no behavioral change.
