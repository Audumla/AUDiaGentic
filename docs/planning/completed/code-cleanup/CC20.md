# COMP-001 — Default component marker file + detection-marker from id

## Description

All 9 component descriptors in src/audiagentic/config/components/*.yaml hand-write an identical install-marker block fully derivable from the component `id`:

    detection-marker: .audiagentic/components/<id>.yaml
    files:
      - path: .audiagentic/components/<id>.yaml
        lifecycle: create-if-missing
        description: Installation marker

This is boilerplate (~5 lines/component) and a drift source. session.yaml is ALREADY inconsistent: its marker is `components/session.yaml` (missing the `.audiagentic/` prefix) with description 'Component installation marker'. Make the loader default both the detection-marker and the marker ComponentFile from `id` when they are not explicitly declared, then strip the redundant blocks from the descriptors. This directly shortens the new-component recipe in docs/standards/CREATING_A_COMPONENT.md.

## Steps

1. In foundation/components/loader.py (register_from_yaml), after reading `id`: if the descriptor declares no `detection-marker`, default it to `.audiagentic/components/<id>.yaml`.
2. When building the `files` tuple, if no ComponentFile has `path == detection-marker`, synthesize one: ComponentFile(rel_path=<detection-marker>, lifecycle=MODE_CREATE_IF_MISSING, description='Installation marker'). Keep explicit entries authoritative (do not duplicate if already present).
3. Decide scope interaction: SCOPE_HARNESS components install into audiagentic_home() not project_root/.audiagentic/. Confirm the default marker path is correct for harness-scoped components or gate the default on scope == SCOPE_PROJECT. Inspect existing harness-scoped descriptors before defaulting.
4. Remove the now-redundant `detection-marker:` line and the `files:` marker block from each of the 9 descriptors where they match the default. Leave any non-default entries.
5. Fix session.yaml: deleting its block + relying on the default corrects the missing `.audiagentic/` prefix. Verify nothing depended on the old wrong path (grep for 'components/session.yaml').
6. Update docs/standards/CREATING_A_COMPONENT.md sections 4-5 and the step-by-step recipe to state the marker is auto-derived and only needs overriding for non-default cases.

2. Confirm every component still has its create-if-missing marker ComponentFile after defaulting.
3. Full test suite green. Add a loader test: a descriptor with no detection-marker/files yields the derived marker; an explicit detection-marker is preserved.
