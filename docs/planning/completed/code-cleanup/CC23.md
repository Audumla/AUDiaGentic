# COMP-004 — Rigid ComponentStatusPayload contract for status-hook

## Description

project_status()/list_components() invoke each component's status-hook (dotted fn(project_root) -> dict) and pass the raw dict through verbatim into component_details/component_status with no shared schema. The four current implementations (memory, planning, source-control, coding-lsp) each return a different shape: mixed key casing (snake_case in memory/planning vs kebab-case in source-control/coding-lsp), the same concept named differently (memory's active_implementation vs planning's implementation), enabled/configured present in some and absent in others, and coding-lsp can return {} which is falsy and gets silently dropped by the `if payload:` guards in project_components.py (get_component_status callers can't distinguish 'no hook' from 'hook ran, nothing to report'). Per Standard 3 (Logic Containment), this cross-cutting contract belongs in foundation, not duplicated per component.

## Steps

["Define a ComponentStatusPayload contract (dataclass or TypedDict) in foundation/components/hooks.py (or a new foundation/components/status.py): required enabled: bool, configured: bool, active_implementation: str | None, missing_required: list[{option, description}], plus an open details: dict[str, Any] bucket for component-specific extras (source-control's mcp-servers, coding-lsp's missing-dependencies/dependency-install-offer).", "Update get_component_status() in foundation/components/hooks.py to require hooks return the typed payload (or None) and serialize via .to_dict()/asdict() with snake_case keys only; replace the current silent {'status-hook-error': ...} swallow with a proper AudiaGenticError per Standard 8 (log exc_info=True, canonical error code, safe default) instead of embedding an ad hoc error dict in the payload.", 'Migrate the four existing hooks to the new contract: memory_status (memory_api.py), planning_status (planning_api.py) — rename implementation -> active_implementation, no back-compat alias per Standard 10 — source_control status_payload (source_control_bootstrap.py) — move mcp-servers/ledger-integration-enabled/hint into details, coding_lsp status_payload/status_hook (coding_lsp_bootstrap.py) — return configured=True/missing_required=[] instead of {} when nothing is missing.', "Grep and update any consumers of the old shapes in the same change (planning_status().implementation callers, any MCP/CLI surface formatting component_details or component_status), and update docs/standards/CREATING_A_COMPONENT.md's status-hook row (currently just 'fn(project_root) -> dict') to document the new required contract.", "Update/add tests alongside the migration per Standard 10 (test-driven migration, no deferred testing) covering each migrated hook's new shape and the hooks.py validation/error path."]
