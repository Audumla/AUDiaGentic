# LSP-001 — Decompose LSP god objects and extract shared utilities

## Description

Three god objects in coding_lsp component:
- `LspSession` in `lsp_lifecycle.py` (739 lines, 6+ responsibilities)
- `LspJsonRpc` in `lsp_bridge.py` (283 lines, 5+ responsibilities)
- `SessionManager` in `lsp_session_manager.py` (149 lines, 4+ responsibilities)

Plus 8 hardcoded dicts/mappings scattered across `lsp_api.py`, `lsp_lifecycle.py`, `lsp_bridge.py`, and 12+ repeated session-opening boilerplate patterns in `lsp_api.py`.

## Steps

1. Split `LspSession` → `LspSession` (lifecycle/doc-sync), `LspProtocolOps` (method dispatch), `LspDiagnostics` (diagnostic handling), `LspUriUtils` (URI/path conversion)
2. Split `LspJsonRpc` → `LspBridge` (process mgmt), `LspJsonRpcClient` (request/response framing), `LspStreamReader` (message parsing), `LspNotificationRouter` (notification dispatch)
3. Split `SessionManager` → `SessionPool` (creation/caching), `DiagnosticCache` (TTL caching), `SessionStatus` (status reporting)
4. Extract 8 hardcoded dicts to `lsp_constants.py`: `kind_map`, `method_labels`, `_METHOD_TIMEOUTS`, `_CLI_SEVERITY`, `_CLIENT_CAPABILITIES`, `_LANGUAGE_MARKERS`, `_path_to_language_id`, `_BATCH_DIAGNOSTIC_CLIS`
5. Extract URI/path utilities to `uri_utils.py` (deduplicate `lsp_api.py:60-69` vs `lsp_lifecycle.py:699-733`)
6. Extract session-opening decorator/helper to eliminate 12+ boilerplate repetitions in `lsp_api.py`

## Files

New: `components/coding_lsp/lsp_constants.py`, `components/coding_lsp/uri_utils.py`, `components/coding_lsp/lsp_protocol_ops.py`, `components/coding_lsp/lsp_diagnostics.py`, `components/coding_lsp/lsp_bridge_client.py`, `components/coding_lsp/lsp_stream_reader.py`, `components/coding_lsp/lsp_notification_router.py`, `components/coding_lsp/session_pool.py`, `components/coding_lsp/diagnostic_cache.py`, `components/coding_lsp/session_status.py`
Modified: `lsp_lifecycle.py`, `lsp_bridge.py`, `lsp_session_manager.py`, `lsp_api.py`, `language_registry.py`, `lsp_mcp.py`, `lsp_manage_mcp.py`

## Validation

No file over 350 lines, no hardcoded dicts in logic modules, URI/path conversion used uniformly, all 12+ session operations use shared decorator

## Architecture Standards Assessment

**Standard #3 (Logic Containment):** Direct violation — 3 god objects (>350 lines, >3 responsibilities each). **Standard #2 (Config Over Code):** 8 hardcoded dicts that should be constants or config-driven.

## Resolution Assessment

**Complexity: Complex.** Multi-file decomposition with careful interface boundaries. 10 new files, 4 major refactors.

**Why complex:** Each god object has many cross-cutting concerns. Decomposition requires careful interface design to avoid breaking existing consumers (MCP wrappers, API functions).

## Effort & Risk

Medium-High — large refactor but additive (new files first, then migrate consumers).

## Notes

Thin MCP wrappers (`lsp_mcp.py`, `lsp_manage_mcp.py`) could later be auto-generated from the API surface.
