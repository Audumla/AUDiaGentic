# REL-001 — Consolidate release-please template rendering and workflow sources

## Description

Duplicate `_render` logic in `install.py:14-18` and `manage.py:99-101` (template string substitution). Dual workflow template sources: inline `BASELINE_WORKFLOW` string in `manage.py:26-59` vs `templates/release.yml` file. Hardcoded `SUPPORTED_RELEASE_TYPES` list in `install.py:11` violates Standard #2.

## Steps

1. Extract `_render(template_name, subs)` helper to `release_please/utils.py`
2. Replace inline `_render` in `manage.py:99-101` with import from `utils.py`
3. Move `BASELINE_WORKFLOW` inline string from `manage.py:26-59` to `templates/baseline.yml` resource file
4. Load baseline via `_render("baseline.yml", subs)` instead of inline string
5. Move `SUPPORTED_RELEASE_TYPES` to YAML/JSON config file (e.g., `release-please-config-types.json`)
6. Load supported types from config at startup, validate against loaded config

## Files

New: `components/release/release_please/utils.py`, `components/release/release_please/templates/baseline.yml`, `components/release/release_please/config-types.json`
Modified: `install.py`, `manage.py`

## Validation

No inline `_render` implementation remains, single source of truth for baseline workflow, release types loaded from config, `_TEMPLATES` path computed once

## Architecture Standards Assessment

**Standard #2 (Config Over Code):** Hardcoded `SUPPORTED_RELEASE_TYPES` list requires Python edit to add new types. **Standard #3 (Logic Containment):** Duplicate `_render` implementation, dual template sources.

## Resolution Assessment

**Complexity: Simple.** New utility module, template file move, config file addition.

**Why simple:** `_render` is a 5-line helper. Moving inline YAML to file is mechanical.

## Effort & Risk

Low — additive new files, mechanical replacements.

## Notes

`manage.py` has 141 lines with 6+ responsibilities — consider splitting into `manage.py`, `detect.py`, `constants.py` for future growth.
