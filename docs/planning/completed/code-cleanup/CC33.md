# Externalize LSP label constants: SYMBOL_KIND_LABELS, COMPLETION_KIND_LABELS, METHOD_LABELS, EXTENSION_TO_LANGUAGE

## Description

LSP protocol constants in `lsp_constants.py` contain ~80 user-facing string labels that are currently hardcoded dict literals. These map LSP spec integers (e.g., SymbolKind 5 = class) to display strings. While the integer values are structural and stay in code, the string labels are user-facing text that should be externalized.

## Steps

['1. Add label-maps: block to coding-lsp.yaml with current SYMBOL_KIND_LABELS, COMPLETION_KIND_LABELS, METHOD_LABELS, EXTENSION_TO_LANGUAGE, FILE_BASENAME_TO_LANGUAGE values\n2. Wire loading in component loader; store in a module-level dict that lsp_constants re-exports\n3. Replace module-level dict literals in lsp_constants.py with references to the loaded dicts\n4. Verify LSP tool output is byte-identical before/after']

## Files

- lsp_constants.py — replace dict literals with YAML-loaded values
- coding-lsp.yaml — add label-maps section with all current entries as baseline
- loader.py — parse label-maps into descriptor or a coding-lsp-specific registry

## Validation

['- LSP tool results (lsp_symbols, lsp_completion) show identical labels before/after\n- A modified label in YAML renders the new value correctly']
