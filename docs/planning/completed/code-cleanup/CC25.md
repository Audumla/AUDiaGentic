# Fix preferred-targets vocabulary: validator warns on every doctrine block's 'skill'/'instruction' (and misses 'rule')

## Description

Every apply_provider_surfaces run logs two warnings per doctrine contribution -- 'unknown preferred-target skill/instruction (known: aider, claude, cline, codex, copilot, gemini, goose)' -- 16+ warnings per apply. Verified 2026-07-06: KNOWN_SURFACE_TYPES (components/providers/surfaces/base.py:39-41) contains only provider ids, but the field's actual production vocabulary is target KINDS: all 8 doctrine contributions in config/components/*.yaml declare 'skill' and/or 'instruction' (agent-jobs.yaml:34, agent-ledger.yaml:56, agents.yaml:110, memory.yaml:49, planning.yaml:109, release.yaml:54, session.yaml:31, source-control.yaml:100), and renderers branch on a third kind, 'rule' (adapters/claude/surface.py:28, adapters/cline/surface.py:26), which is ALSO missing from the known set. Rendering works despite the warnings (the value is advisory routing, not gating), so this is a validator-vocabulary bug, not a rendering bug. DECIDED SOLUTION: the known set is the union of target kinds and provider ids -- define KNOWN_TARGET_KINDS = frozenset({'skill', 'instruction', 'rule'}) alongside the provider-id set, validate against the union, and comment each set's meaning (kinds = how content should surface; provider ids = which provider it prefers). Warning behavior for a genuinely unknown string stays as-is.
