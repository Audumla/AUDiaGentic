# Provider contract and type-safety review

## Notes



## Findings

1. Do not replace every family-specific mode type with one four-value ProviderAction. Preserve the three actual capability sets: full lifecycle (plan/apply/prune/status), reconciliation (apply/prune/status), and apply/status. Family aliases may reuse those shared Literal aliases without widening their public APIs.

2. “Mode” is the established contract/config term (_families.yaml supported_modes and mode parameters). ProviderAutomationMode is clearer than ProviderAction; Action already has other lifecycle/control meanings.

3. _families.yaml already owns supported modes per automation family. Remove repeated handler frozensets by validating through a shared family-mode validator backed by the catalogue. Shared type aliases provide static narrowing; catalogue validation provides runtime authority.

4. Provider isolation consolidation must include all three current definitions/usages: provider_execution.ProviderIsolationTier, descriptors.base.IsolationTier/ProviderDescriptor.execution_isolation_tier, and agents.execution_context.IsolationTier. One provider-owned public ProviderIsolationTier should serve all three through providers_api. McpLaunchIsolationTier remains separate because it describes a different capability.

5. CapabilityAuthority must not consolidate the current aliases blindly. descriptors.base has automation/operational/evidence-only and appears unused; capability_catalogue owns provisioned/operational/evidence-only. Confirm and delete the unused base alias, then name/type the catalogue vocabulary at capability_catalogue.

6. Entry status is a reason code, not a lifecycle status. Prefer ManagedMcpEntryStatusReason (NO_MCP_CONFIG='no mcp_config', READ_FAILED='read failed', ABSENT='absent', STALE='stale', MATCH='match') if an enum is justified, or a Literal alias plus TypedDict/result dataclass. Preserve current serialized values unless an explicit contract migration is approved.

7. CliLifecycleState and SelfProvidedLspState are wire result fields. The least disruptive improvement is a Literal alias on the field plus validation derived with typing.get_args; use StrEnum only if from_mapping and every constructor normalize strings to enum instances. The same boundary rule applies to isolation tiers.

8. The proposed LifecycleInstallation duplicates a different existing foundation enum. The provider observer values session-open/first-turn/lazy describe timing, whereas foundation LifecycleInstallation values none/managed-hook/managed-plugin/structured-output describe mechanism. Name the provider type ObserverInstallationTiming or ObserverActivationTiming.

9. GeneratedSurfaceMode should join the full lifecycle alias rather than remain str. Exact shared aliases can be: ProviderAutomationMode, ProviderReconcileMode, ProviderApplyStatusMode; then preserve family-facing aliases for API clarity.

10. CC51 should own the provider-only slice and CC50 should explicitly depend on it. Add files, validation, serialization compatibility, type-checking, providers_api export, descriptor loader, and cross-component architecture tests to CC51 before implementation.

## Conclusion

Recommended provider design: centralize runtime mode validation in the existing family catalogue; share three narrow Literal aliases rather than one widened enum; consolidate only the true provider-isolation concept; keep MCP launch isolation separate; delete the stale authority alias rather than merging different vocabularies; and name observer timing distinctly from session-surface installation. StrEnum remains optional and should be used only with explicit boundary parsing.
