# Pre-implementation review: paths package collision, import surface, and slice ordering

## Notes

Pre-implementation validation against current codebase state.

## Findings

1. P1 - `foundation/paths/` already exists as a package with 5 modules (resolution.py, package.py, names.py, component_paths.py). Step 4 assumes creating the package from scratch; it should describe merging symbols from the flat `audiagentic.paths` module into the existing package.

2. P1 - Import surface is 56+ sites across CLI, runtime, foundation sub-packages, and components. Current items:
   - `cli_io`: 23 consumers (including 3 in foundation/contracts/, 1 in foundation/logging/config.py)
   - `foundation.home`: 21 consumers
   - `paths`: 12 consumers + paths package collision from finding #1
   Priority P2 and complexity "mid" underestimate the atomic update scope.

3. P2 - Slice ordering: cli_io move (step 3) should precede paths/home work within Slice A because foundation/contracts/ and foundation/logging/ import from cli_io. Any later slice touching those sub-packages would see stale imports if paths moves first.

4. P2 - launcher.py public entrypoint risk: Step 2 extracts commands but doesn't explicitly call out verifying `pyproject.toml` console script survives intact. Validation section covers this, but the step itself should include an in-slice check.

## Conclusion

Plan is well-structured and standards-aligned. Requires corrections to step 4 (existing paths package), complexity bump from mid to complex, and minor slice reordering before implementation should begin.
