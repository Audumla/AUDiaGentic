# Slice 2 corrections: output schemas are a safety net, not a committed surface; config-driven payloads cannot be closed

## Notes

Self-review of the CC61 rewrite. Three defects found by testing the item's own code sample against the real API rather than re-reading it.

## Findings

1. **The regression guard would have forced a §2 violation.** The guard as written asserts `not schema.get("additionalProperties")`. Planning payload keys are config-driven: `FRONTMATTER_FIELDS`, `ITEM_SECTION_HEADING`, and `METADATA_KEYS` are loaded from `planning.yaml` at import time (`components/planning/item_store.py:83-111`), and `build_item_body` accepts `custom_headings`, so items carry arbitrary sections (CC47 returns `new_yaml_schema`, `file_rename_plan`; CC50 returns `architecture_constrained_enum_design`). Satisfying the guard would require enumerating a config-owned vocabulary in Python — exactly what §2 forbids.

2. **Wrong invariant.** The distinguishing property of a blob is not openness, it is an *empty* schema. Verified: `dict[str, Any]` yields `properties: {}` / no `required`; a model with a declared core plus `extra='allow'` yields typed properties, a populated `required` list, *and* `additionalProperties: true`. The latter is a real contract. The guard should assert a non-empty `required`, nothing more.

3. **The TypedDict sample was unusable.** It used `class` syntax, which cannot express the hyphenated keys these payloads actually use (`created-by`, `created-at`, `review-of`, `reviewed-by`). It also omitted `created-by`/`created-at` entirely and marked `work`/`skill` `NotRequired` when both are always present as empty strings — an error in the breaking direction, since a wrongly-required field turns a working tool into a boundary failure.

4. Minor: the `tool_boundary` sample elides the async arm with a comment.

## Conclusion

Fold in as a slim correction — no tier taxonomy. Output schemas are a safety mechanism, not a committed foundational surface, so one rule covers every tool: **declare the invariant core as required; leave the rest open.** Where a payload is wholly code-owned the core happens to be the whole shape; where it is config- or content-derived the core is the identity fields and the remainder stays open. Guard becomes a non-empty `required` check. Fix the sample to functional TypedDict syntax with verified fields, and add the open-core variant. No versioning, migration, or per-tier ceremony — the schema exists to catch a tool silently returning the wrong shape, not to freeze a public contract.
