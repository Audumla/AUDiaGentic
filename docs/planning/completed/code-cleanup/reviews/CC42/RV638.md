# Reuse migration validation exposed one stale ledger assertion and unrelated LSP state regression

## Notes

Focused validation after migrating to foundation primitives.

## Findings

The migrated ledger idempotency test retained an obsolete expectation that a second sync would re-count fragments already purged by the first sync; it was corrected to expect fragment_count=0 while proving the ledger remains byte-equivalent. The combined run also exposed test_active_dependency_ids_no_enabled_features_returns_empty, but an isolated check shows that failure is in active-feature selection and is unrelated to coding_lsp's atomic JSON writer migration; it is not incorporated into CC42.

## Conclusion

CC42 is valid and complete. Foundation StartupLock, atomic_write_json, and now_iso_z replace the duplicate implementations without adding abstraction. The stale ledger assertion was corrected. The unrelated LSP feature-state regression remains outside CC42 and must be handled by its owning workstream if still reproducible after concurrent changes settle.
