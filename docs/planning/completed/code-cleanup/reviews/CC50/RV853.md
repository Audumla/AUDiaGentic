# Scope and dependency review

## Notes



## Findings

1. CC50 duplicates the provider-vocabulary work owned by CC51. Make CC50 an audit/umbrella item and delegate provider work to CC51; do not let both edit provider contracts.

2. CC50 assumes every closed string vocabulary should become StrEnum. That is not a safe general rule. Many values are wire/config/durable schema strings accepted from mappings and persisted as plain strings. Replacing Literal[str] with StrEnum changes the static contract to require enum instances, while dataclasses and from_mapping methods do not coerce automatically. Adopt a boundary rule: Literal for plain-string wire/config contracts; StrEnum only for runtime domain values that are parsed at ingress and intentionally represented as enum instances internally.

3. Workflow states (gateway requests/sessions, agent jobs, planning) are declared by workflows.yaml and enforced by TransitionEngine. Hand-authored enums would be a second authority. Prefer strings validated through the workflow engine. If static enum symbols are required, generate checked-in modules from YAML and enforce freshness in CI; do not hand-maintain both.

4. Agent-job stage-result and next-stage-recommendation are already canonical in JSON Schema. Do not introduce independent StageStatus/Recommendation enums. If generated types are wanted, generate StageResult and NextStageRecommendation from the schema. The proposed short name Recommendation is actively ambiguous because review reports have a separate recommendation vocabulary.

5. The proposed LifecycleInstallation is a semantic/name collision. foundation.transports.session_surface.LifecycleInstallation already means none/managed-hook/managed-plugin/structured-output. The harness observer field means installation timing (session-open/first-turn/lazy). Use ObserverInstallationTiming (or ObserverActivationTiming), not LifecycleInstallation.

6. Capability authority was misclassified. descriptors.base defines an apparently unused automation/operational/evidence-only alias, while capability_catalogue owns provisioned/operational/evidence-only. “automation” and “provisioned” are not interchangeable. Delete the unused alias if confirmed; define the canonical catalogue type at its owner.

7. CC50 should be split by authority/source, not simply by enum count: provider contracts (CC51), YAML workflow states, JSON-schema vocabularies, foundation wire contracts, and internal runtime projections/reasons. Each slice needs a file/caller/serialization/test matrix.

8. Grep-based “zero raw completed strings” validation is invalid because identical strings belong to unrelated domains. Validate owner-scoped references and source-of-truth alignment instead.

## Conclusion

Retain CC50 as the taxonomy audit and migration umbrella, but remove direct provider implementation and make CC51 its provider-owned child/dependency. Do not mandate StrEnum globally. Use source-derived validation for YAML/JSON-schema vocabularies, Literal aliases for plain-string boundaries, and StrEnum only after explicit parsing into an internal runtime representation. Split implementation into owner/source-specific items before coding.
