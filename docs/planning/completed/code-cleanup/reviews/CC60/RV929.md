# Native mcp/lsp discovery findings block the .lsp.json and .mcp.json moves as scoped

## Notes

Verified against installed package source, not just docs. Qwen: grepped installed @qwen-code/qwen-code/cli.js bundle -> LspConfigLoader.loadUserConfigs() resolves `path.join(this.workspaceRoot, ".lsp.json")`, hardcoded, no settings.json field/env var/CLI flag override exists (`qwen --help` has no --lsp-config/--config). Root .lsp.json is Qwen's own native LSP discovery file, not AUDiaGentic cache -- moving it under .audiagentic/config/ silently breaks Qwen's LSP feature entirely. Pi: read installed pi-mcp-adapter/config.ts getConfigSources() directly -- 4 merge sources when --mcp-exclusive isn't set: shared-global (~/.config/mcp/mcp.json), pi-global (Pi's own agent-dir mcp.json -- the ONLY redirectable slot, already used by --mcp-config), shared-project (<cwd>/.mcp.json), pi-project (<cwd>/.pi/mcp.json). AUDiaGentic-orchestrated launches (execute/interactive/acp) never read config_path at all -- they write a request-owned launch.json and pass --mcp-config/--mcp-exclusive explicitly, so moving config_path doesn't affect gateway launches. But a bare/manual `pi` invocation outside AUDiaGentic relies on native discovery of project-root .mcp.json as one of the adapter's built-in sources.

## Findings

1) .lsp.json move to .audiagentic/config/lsp.json must be dropped -- hard break for Qwen, confirmed by decompiled source, no workaround exists. 2) Pi's .mcp.json move to .audiagentic/config/mcp.json should be retargeted to .pi/mcp.json instead -- that's an already-natively-scanned project source (pi-project, has its own writePath) so bare/manual pi launches keep discovering AUDiaGentic-registered servers, while root-level .mcp.json still goes away (declutter goal met without discovery loss). .pi/ is already Pi's own managed runtime dir per pi.yaml agent-files.

## Conclusion

Correct CC60's target-state tree and steps: drop the .lsp.json move; replace the .mcp.json move with a config_path retarget from ".mcp.json" to ".pi/mcp.json" in pi.yaml. .coding-lsp/ -> .audiagentic/runtime/cache/ move is unaffected and stays in scope.
