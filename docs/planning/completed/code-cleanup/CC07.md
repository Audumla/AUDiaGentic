# A21 — State machine unification

## Description

Two independent state-machine implementations exist with duplicated transition-validation logic:

1. `foundation/workflow/state_machine.py` — `StateMachine` class. Config-driven (reads transitions from `WorkflowConfig.workflow_for()`), protocol-based via `WorkflowContext`, supports lifecycle action metadata, event publishing, and cascades. Validation lives inline in `state()` at lines 45-48: checks `new_state in wf['values']` then `new_state in wf['transitions'].get(old, [])`. Raises `WFSM`-coded errors.

2. `components/agent_jobs/state_machine.py` — module-level functions. Hardcoded `LEGAL_TRANSITIONS` dict + `TERMINAL_STATES` set, direct file I/O via `runtime.state.jobs_store`, no events/cascade. Validation lives in `ensure_transition()` (lines 30-45). Raises `VAL-STATE-001` / `CON-STATE-001` errors.

The duplicated concept is: given (current_state, new_state, transitions_map), is the transition legal, and is a state terminal. Everything else (persistence, events, cascade, config-loading) is host-specific and stays put.

SCOPE CORRECTION vs original draft: the original 4-phase plan assumed deep coupling. In reality the shared surface is tiny (~2 predicate functions). agent_jobs SM is consumed by only 5 files: control.py, prompt_launch.py, packet_runner.py, approvals.py, and tests/deferred/jobs/test_state_machine.py. Foundation SM is consumed via the WorkflowContext protocol. The realistic effort is LOW.

## Steps

**Phase 1 — Create shared engine (no behavior change).**
Create `src/audiagentic/foundation/workflow/transition_engine.py` with a pure, dependency-free core:

```python
from __future__ import annotations
from dataclasses import dataclass, field
from collections.abc import Mapping, Set

@dataclass(frozen=True)
class TransitionConfig:
    # state -> set of states reachable from it
    transitions: Mapping[str, frozenset[str]]
    terminal_states: frozenset[str] = field(default_factory=frozenset)
    # optional: full universe of valid state names; if None, derived from transitions keys+values
    values: frozenset[str] | None = None

    def known_states(self) -> frozenset[str]:
        if self.values is not None:
            return self.values
        out = set(self.transitions)
        for dests in self.transitions.values():
            out |= set(dests)
        return frozenset(out)

class TransitionEngine:
    def __init__(self, config: TransitionConfig):
        self.config = config
    def is_known_state(self, state: str) -> bool: ...
    def is_legal(self, current: str, new: str) -> bool:
        # current unknown -> False; new not in allowed -> False
        ...
    def is_terminal(self, state: str | None) -> bool: ...
    def check(self, current: str, new: str) -> str | None:
        # returns None if legal, else a machine-readable reason code:
        #   'unknown-current' | 'unknown-target' | 'illegal-transition'
        ...
```

The engine NEVER touches files, config objects, or events — it only answers predicate questions. Write `tests/unit/foundation/test_transition_engine.py` covering: legal transition, illegal transition, unknown current state, unknown target state, terminal detection, `values` override vs derived, empty terminal set.

**Phase 2 — Adopt in agent_jobs (backward-compatible).**
In `components/agent_jobs/state_machine.py`:
- Build a module-level `_ENGINE = TransitionEngine(TransitionConfig(transitions={k: frozenset(v) for k,v in LEGAL_TRANSITIONS.items()}, terminal_states=frozenset(TERMINAL_STATES)))`.
- Rewrite `ensure_transition()` to delegate to `_ENGINE.check()`, mapping the returned reason code to the EXISTING error codes/messages — do NOT change error codes or details shape (consumers/tests depend on `VAL-STATE-001` for unknown state and `CON-STATE-001` for illegal transition).
- Keep `LEGAL_TRANSITIONS` and `TERMINAL_STATES` as the source-of-truth data (the engine wraps them). Keep `transition_job` / `transition_and_persist` signatures unchanged.
- Add a `is_terminal_state(state)` helper delegating to `_ENGINE` only if a consumer needs it; otherwise skip.

**Phase 3 — Adopt in foundation StateMachine.**
In `foundation/workflow/state_machine.py` `state()`:
- Construct a `TransitionConfig` per-call from the resolved workflow: `transitions={s: frozenset(d) for s,d in wf['transitions'].items()}`, `values=frozenset(wf['values'])`.
- Replace inline checks at lines 45-48 with `engine.check(old, new_state)` and map reason codes to the existing `_state_error(1, ...)` (unknown state) and `_state_error(2, ...)` (invalid transition) so `WFSM` codes and messages are preserved byte-for-byte.
- `is_terminal()` (lines 111-118) stays as-is — it uses config `state_in_set(..., 'terminal', ...)` which is richer than the engine's flat terminal set; do NOT force it through the engine. (Document this divergence in a code comment.)

**Phase 4 — Cleanup.**
- Remove any now-dead local validation helpers.
- Confirm no remaining inline transition-legality checks elsewhere (grep `transitions.get(` and `not in.*transitions`).
- No deprecation warnings needed — public signatures unchanged.
