# Replace complexity with work (S/M/L) and skill (1/2/3)

## Description

Replace the single `complexity` field with two orthogonal metrics:

- **work** (S/M/L) — volume of work, how broad the change is (files, lines, scope). Default: S. Plan creator can estimate this at creation time.
- **skill** (1/2/3) — cognitive difficulty, how much thought and judgment is required per unit of work. **Optional** — the plan creator may not be able to determine this until someone starts working on it. Can be set later via `plan_update_item`.

Skill level drives agent routing: S1 items go to any capable agent; L3 items need strong reasoning models. When unspecified, the system should not assume a skill level — it's better to leave it unset than to route incorrectly.

The old `complexity` values map approximately as:
- simple → work: S (skill left unset unless known)
- mid → work: M (skill left unset unless known)
- complex → work: L, skill: 3 (complex implies deep thinking is needed)

However, the two dimensions enable new distinctions that complexity could not express, such as large-but-straightforward (L,1) or small-but-deep (S,3).

Agent instruction files (AGENTS.md etc.) are auto-injected from the component config — updating planning.yaml propagates the change automatically.
