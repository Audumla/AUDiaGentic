# RIG-001 — Consolidate runtime rig error factories and platform constants

## Description

7 duplicate error factories in `runtime/rig/` (`models.py`, `http.py`, `resolution.py`, `process.py`, `launch.py`, `config.py`, `binaries.py`) plus duplicate platform/binary name mappings in 3 files and scattered env var name constants.

## Steps

1. Create `runtime/rig/errors.py` with shared `make_rig_error(prefix, component, number, message, **details)` factory
2. Replace all 7 local `_xxx_error()` functions with imports from `rig/errors.py`
3. Fix `http.py:23` typo: `"RIGHTTP"` → correct component code
4. Create `runtime/rig/constants.py` with centralized env var names, `DEFAULT_HOST`, `DEFAULT_PORT`, platform-to-directory mapping, binary name patterns
5. Replace hardcoded platform checks in `resolution.py:92-97`, `process.py:32-36`, `binaries.py:216-221` with shared `_platform_dir_name()` and `_binary_names()`

## Files

New: `runtime/rig/errors.py`, `runtime/rig/constants.py`
Modified: `models.py`, `http.py`, `resolution.py`, `process.py`, `launch.py`, `config.py`, `binaries.py`, `cli.py`

## Validation

All rig modules use shared error factory, no duplicate platform mappings remain, env var names centralized in constants module, `http.py` typo fixed

## Architecture Standards Assessment

**Standard #3 (Logic Containment):** 7 duplicate error factories, 3 duplicate platform mappings, env vars scattered across 6 files.

## Resolution Assessment

**Complexity: Mid.** Mechanical error factory replacement + new constants module + platform mapping consolidation.

**Why mid:** Constants module needs careful design to avoid import cycles. Error factory replacement is straightforward.

## Effort & Risk

Medium — additive new files, mechanical replacements.

## Notes

Error code numbering across 7 files is uncoordinated — consider a shared error code registry later.
