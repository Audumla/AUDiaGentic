# Consolidate stragglers onto foundation primitives: StartupLock, atomic JSON writes, now_iso_z

## Description

Codebase reuse sweep (2026-07-18) found three small classes of foundation duplication left behind by earlier migrations. Each has an existing foundation owner; no new abstraction is needed — this is pure caller migration.

## Steps

1. components/ledger/sync.py _acquire_lock/_release_lock hand-roll a cross-process PID-liveness/stale-age lock file — exactly what foundation.system.process.StartupLock provides (and PR06 hardened for same-process thread serialization and Windows reader-handle unlink). Replace with StartupLock; keep the ledger-specific stale-age policy only if StartupLock's timeout semantics cannot express it, and say why in the item notes if so. PR05 step 9's planned architecture test (no ad-hoc process/lock lifecycle outside foundation) should then catch regressions.
2. Migrate non-atomic config/state JSON writes to foundation.io.atomic_write_json (which also carries the Windows antivirus-retry behaviour these sites lack): providers/adapters/pi/model_config.py:49,64; coding_lsp/coding_lsp_config.py:72; release/github_auth.py:118; source_control/git_commits.py:71. Leave deliberate non-atomic writes (e.g. the ledger lock sentinel once step 1 lands) alone.
3. Replace inline UTC-ISO timestamp construction with foundation.time.now_iso_z: agent_jobs/prompt_parser.py:57 (byte-identical reimplementation), agent_jobs/prompt_context.py:436 (currently omits the Z normalization — verify no consumer depends on '+00:00' before changing), ledger/fragments.py:53.
4. Run the focused suites for ledger, providers adapters, coding_lsp config, release auth, and agent_jobs; ruff on touched files.
