# FND-001 — Consolidate duplicate error factory functions across 20 files

## Description

Every module that raises errors defines its own `_xxx_error()` helper calling `make_error()` with the same signature pattern, differing only in `prefix` and `component` values. 13 foundation modules + 7 runtime/rig modules = 20 nearly-identical functions.

## Steps

1. Extend `foundation/contracts/errors.py` with `make_error_code(prefix, kind)` that returns a bound factory function
2. Each module replaces its local `_xxx_error` with `_xxx_error = make_error_code("PREFIX", "kind")`
3. Fix `runtime/rig/` typo: `"RIGHTTP"` → `"RIGHTTP"` in `http.py:23`
4. Verify all error codes use canonical `PREFIX-COMPONENT-NNN` format

## Files

Modified: `foundation/contracts/errors.py` — add `make_error_code()` factory
Modified (20 files): `config.py`, `io.py`, `components/loader.py`, `dependencies.py`, `features/registry.py`, `features/options.py`, `workflow/state_machine.py`, `workflow/actions.py`, `workflow/propagation/engine.py`, `workflow/propagation/propagation_config.py`, `system/process.py`, `paths/resolution.py`, `runtime/rig/models.py`, `http.py`, `resolution.py`, `process.py`, `launch.py`, `config.py`, `binaries.py`

## Validation

All 20 files use `make_error_code()` pattern, no local `_xxx_error` defs remain, error codes follow `PREFIX-COMPONENT-NNN` convention, `http.py` typo fixed

## Architecture Standards Assessment

**Standard #8 (Error Handling):** Direct violation — each module reinvented error construction. Consolidation aligns with the standard's intent for canonical error construction.

## Resolution Assessment

**Complexity: Simple.** Additive change — new factory function, mechanical replacement in each module. No behavior change.

**Why simple:** Each replacement is a one-line substitution. No API surface changes.

## Effort & Risk

Low — 20 mechanical replacements, no behavioral change.
