# Consolidate provider automation vocabulary and validation without widening family contracts

## Description

Consolidate genuinely shared provider vocabulary ownership and validation while preserving the distinct public mode sets of provider automation families. This item owns only the provider slice of CC50's vocabulary policy.

## Steps

- Phase 1 (safe deletions, no behavior change): remove the dead `CapabilityAuthority` alias from descriptors/base.py; delete the stale duplicate services/contracts/model-sources.schema.json and services/contracts/model-source-catalog.schema.json; collapse the duplicate `AUTOMATION_MODES` frozenset (descriptors/automation_capabilities.py vs services/capabilities/recipe_definitions.py) to one export; fix the 2 export-surface call sites in agents/gateway/profiles.py and agents/gateway/session/sessions.py to import SurfaceHint from providers_api
- Phase 2 (new shared types, same accepted values): add providers/contracts/automation_vocabulary.py with ProviderAutomationMode/ProviderReconcileMode/ProviderApplyStatusMode; re-point ManagedMcpMode, ManagedHooksMode, LanguageServerProjectionMode, PluginEntryMode, ModelProjectionMode, GeneratedSurfaceMode, SelfProvidedLspMode at the shared aliases (GeneratedSurfaceMode goes from bare `str` to a real Literal); add ObserverInstallationTiming (session-open/first-turn/lazy) with real membership validation in harness_status_observer.py; add SelfProvidedLspResult.state validation against the confirmed 3-value set {provisioned, needs-action, unknown}, mirroring CliLifecycleResult's existing __post_init__ pattern
- Phase 3 (behavior-affecting, needs full test run + sign-off): switch managed_mcp_family.py, language_server_family.py, model_projection_handler.py, plugin_entries.py from hardcoded _SUPPORTED_MODES to catalogue-backed `family.supported_modes` validation (the pattern already used by managed_hooks_family.py and recipe_definitions.py); derive lifecycle_modes.py's _VALID_CLI_MODES from CliLifecycleMode instead of a hand-copied 4-value subset (restores MCP-level reachability of the already-implemented upgrade/upgrade-status CLI lifecycle modes); fix services/mcp/mcp.py's "no mcp_config defined" reason string to "no mcp_config"; add StreamValidationPolicy (warn/fail/normalize) shared by provider_streaming.py's sink-error-policy and control-validation-policy only
- Phase 4 (cross-component, revised during implementation — see Notes): consolidate ProviderIsolationTier so descriptors/base.py imports the one definition from providers/contracts/provider_execution.py; agents/contracts/execution_context.py keeps a local runtime Literal (cannot import from providers at runtime — see Notes) but imports the real type under TYPE_CHECKING for static drift-checking. McpLaunchIsolationTier stays a separate type throughout
- Deferred out of this item: the "centralize model-source validation" half of the original step 10 — PC12 (provider-capability-model plan, pending) already owns providers_api.py, model_source_config.py, source_catalog.py, and model-sources.schema.json for a larger restructure; CC51's model-source touch is scoped to the two PC12-independent fixes only (stale schema-file deletion, done in Phase 1; and documentation correction that `none` discovery is a descriptor-side sentinel outside the persisted-catalog schema's scope, not a schema enum gap)
- Export only the finalized public types through providers_api; the 2 known bypass call sites fixed in Phase 1

## Detailed Solution & Technical Design

### Current State Assessment (verified against the tree at 2026-08-10)

**1. Mode vocabulary** — four distinct value-sets duplicated across files: `{apply,prune,status}` in managed_mcp.py/managed_hooks.py/language_server_projection.py/plugin_entry.py; `{plan,apply,prune,status}` in model_projection.py (real Literal) and generated_surface.py (bare `str`, unvalidated); `{apply,status}` in self_provided_lsp.py; 6-value superset `{plan,apply,prune,status,upgrade-status,upgrade}` in cli_lifecycle.py's CliLifecycleMode plus a verbatim-duplicate `AUTOMATION_MODES` frozenset independently defined in both descriptors/automation_capabilities.py and services/capabilities/recipe_definitions.py.

**2. Handler-local mode sets** duplicated the contract Literal a second time — 2 of 6 family handlers (managed_hooks_family.py, recipe_definitions.py) were already catalogue-backed; 4 (managed_mcp_family.py, language_server_family.py, model_projection_handler.py, plugin_entries.py) hardcoded their own `_SUPPORTED_MODES`/inline sets.

**3. Real, live functional bug found and fixed**: lifecycle_modes.py's `_VALID_CLI_MODES` was a hand-copied 4-value subset omitting `upgrade`/`upgrade-status`, even though CliLifecycleMode declares them and cli_lifecycle_handler.py fully implements `_do_upgrade_status`/`_do_upgrade`. The MCP tool `manage_cli_lifecycle` called `normalize_provider_cli_mode` first, so upgrade/upgrade-status were unreachable through MCP despite being fully implemented. Fixed by deriving `_VALID_CLI_MODES` from `CliLifecycleMode` instead of hand-copying it.

**4. `ProviderIsolationTier`** had three independent definitions of the identical 3-value Literal: contracts/provider_execution.py, descriptors/base.py (as local `IsolationTier`), and agents/contracts/execution_context.py (with a redundant `_ISOLATION_TIERS` set duplicated a second time in the same file).

**5. `CapabilityAuthority`** (descriptors/base.py) was confirmed dead code — zero references anywhere in src/, and semantically stale (its first value `"automation"` didn't even match the real catalogue-owned vocabulary's `"provisioned"`).

**6. `ObserverInstallationTiming`** didn't exist — harness_status_observer.py's `lifecycle_installation` was a bare string whose `__post_init__` only checked non-empty, never membership. Confirmed distinct from foundation's `LifecycleInstallation` StrEnum (installation *mechanism*, not *timing*) — no unification risk there.

**7. CLI-lifecycle vs self-provided-LSP result states** — CliLifecycleResult already validated `state` in `__post_init__`; SelfProvidedLspResult had no such validation. Grepped every construction site (self_provided_lsp_handler.py, providers_api.py): only `{"provisioned", "needs-action", "unknown"}` are ever used.

**8. Managed-MCP status reason drift**: services/mcp/mcp.py documented `reason` as one of `'no mcp_config'/'read failed'/'absent'/'stale'/'match'` but actually emitted `"no mcp_config defined"` — a sixth, undocumented spelling. Fixed to the documented `"no mcp_config"`; confirmed no test was pinned to the old exact string (only a substring check that holds either way).

**9. Streaming policy inventory** (corrected — broader than the original description): sink-error-policy and control-validation-policy share an identical `{warn,fail,normalize}` set and role — genuine unification candidate. termination-policy (`{graceful-kill,warn-only}`), overflow_policy (`{fail,truncate-head,truncate-tail,warn-only}` — not mentioned in the original description at all), invalid_event_policy (`{fail,quarantine,warn}`), and event_write_policy (locked-append vs. implicit unlocked fallback) all have distinct membership and stay independently spelled.

**10. Model source catalog**: found and deleted two confirmed-stale, unreferenced duplicate schema files (services/contracts/model-sources.schema.json — already diverged from its contracts/ counterpart, missing AS105/AS101 resource-id/concurrency fields; services/contracts/model-source-catalog.schema.json — byte-identical but still dead). Both `model_source_config.py` and `source_catalog.py` resolve to the `contracts/` copies. The "centralize source validation" work is deferred — PC12 (provider-capability-model, pending) owns the same files for a larger restructure.

**11. Export-surface leakage**: 2 call sites (agents/gateway/profiles.py, agents/gateway/session/sessions.py) imported SurfaceHint directly from providers.contracts.session_surface instead of providers_api (which already re-exports it) — both are deferred/local imports inside function bodies, so fixing them carried no import-time risk.

### Architecture Assessment

The CC50-vs-CC51 conflict on `IsolationTier` ownership (foundation vs providers_api) was resolved by the user in favor of providers_api — reasoning: `foundation.providers.isolation` would be the first foundation subpackage named after a consuming component, contradicting CC50's own "provider-specific types stay with providers" rule; and providers_api is expected to become the injected interface once the codebase's DI/IoC direction lands, so building on it now is forward-compatible.

**That resolution held for descriptors/base.py (same component) but not for agents/contracts/execution_context.py — discovered only by running the real test suite.** worker_protocol.py imports `IsolationTier` from execution_context.py at module level; worker_host.py (the gateway's disposable subprocess entry point) imports worker_protocol at its own top level, before `main()`'s `redirect_stdout(sys.stderr)` guard. That guard exists specifically so provider-package import-time prints can't corrupt the worker's stdout-framed IPC protocol. Importing anything from `audiagentic.components.providers.*` in execution_context.py — providers_api or the lighter contracts.provider_execution, it makes no difference — triggers providers/__init__.py's eager `from . import adapters` (69 modules) unprotected on real stdout, breaking the protocol. Confirmed via tests/unit/agents/test_sh21_gateway_pi_smoke.py failing with a corrupted frame count, and fixed via `is` no longer available at runtime: TYPE_CHECKING-only import for static drift-checking, plain runtime Literal duplicate for execution_context.py specifically, documented inline. See Notes for full detail — this is the one place this item's implementation deviated from its own plan, and it was a necessary, verified deviation, not a shortcut.

### Proposed Design (as implemented)

`providers/contracts/automation_vocabulary.py` (new): `ProviderAutomationMode = Literal["plan","apply","prune","status"]`, `ProviderReconcileMode = Literal["apply","prune","status"]`, `ProviderApplyStatusMode = Literal["apply","status"]`. Family contracts re-point at these via `from .automation_vocabulary import ProviderReconcileMode as ManagedMcpMode` (etc per file) instead of restating the values. `CliLifecycleMode` stays its own 6-value type — never folded into `ProviderAutomationMode`. `AUTOMATION_MODES` collapsed to one definition (descriptors/automation_capabilities.py; recipe_definitions.py imports it). `lifecycle_modes.py`'s `_VALID_CLI_MODES` derived via `set(get_args(CliLifecycleMode))`.

Catalogue-backed handler validation: each of the 4 handlers gained a `_family_declaration()` helper (`get_catalogue().families[FAMILY_ID]`) and switched `if mode not in _SUPPORTED_MODES` to `if mode not in _family_declaration().supported_modes` — the pattern already proven in managed_hooks_family.py.

`ObserverInstallationTiming = Literal["session-open","first-turn","lazy"]` in harness_status_observer.py, with `__post_init__` checking `get_args()` membership instead of bare non-empty-string.

`SelfProvidedLspResult.__post_init__` validates `state` against the grep-confirmed `{"provisioned","needs-action","unknown"}`.

`StreamValidationPolicy = Literal["warn","fail","normalize"]` in provider_streaming.py, used to type `validate_stream_controls`'s `policy` parameter and derive `valid_policies` via `get_args()` instead of a hardcoded set literal.

`ProviderIsolationTier`: sole definition in contracts/provider_execution.py; descriptors/base.py imports it directly (`from ..contracts.provider_execution import ProviderIsolationTier as IsolationTier`) — confirmed single identity via `is` comparison. agents/contracts/execution_context.py: `if TYPE_CHECKING: from ...provider_execution import ProviderIsolationTier as IsolationTier` / `else: IsolationTier = Literal[...]` — the runtime duplicate is intentional and documented inline, not an oversight.

## Code Samples & Guidance

**automation_vocabulary.py (new, providers/contracts/):**
```python
from typing import Literal

ProviderAutomationMode = Literal["plan", "apply", "prune", "status"]
ProviderReconcileMode = Literal["apply", "prune", "status"]
ProviderApplyStatusMode = Literal["apply", "status"]
```

**Catalogue-backed handler validation (managed_mcp_family.py, language_server_family.py, model_projection_handler.py, plugin_entries.py):**
```python
def _family_declaration():
    from audiagentic.components.providers.descriptors.capability_catalogue import get_catalogue
    return get_catalogue().families[FAMILY_ID]

# replace: if mode not in _SUPPORTED_MODES:
# with:    if mode not in _family_declaration().supported_modes:
```

**_VALID_CLI_MODES derived instead of hand-copied (lifecycle_modes.py — fixes the upgrade/upgrade-status MCP-unreachability bug):**
```python
from typing import get_args
from audiagentic.components.providers.contracts.cli_lifecycle import CliLifecycleMode

_VALID_CLI_MODES: set[str] = set(get_args(CliLifecycleMode))
```

**ProviderIsolationTier in descriptors/base.py (same-component, safe):**
```python
from ..contracts.provider_execution import ProviderIsolationTier as IsolationTier
```

**ProviderIsolationTier in agents/contracts/execution_context.py (cross-component, worker-protocol-constrained — the actual shipped pattern, NOT a plain import):**
```python
from typing import TYPE_CHECKING, Literal

if TYPE_CHECKING:
    # Type-check-only: worker_host.py imports this module (via worker_protocol.py)
    # at its own top level, before main()'s redirect_stdout(sys.stderr) guard —
    # importing anything under audiagentic.components.providers here would trigger
    # the providers package's eager adapter-loading __init__.py unprotected,
    # corrupting the worker's stdout-framed IPC protocol.
    from audiagentic.components.providers.contracts.provider_execution import (
        ProviderIsolationTier as IsolationTier,
    )
else:
    IsolationTier = Literal["full-isolation", "partial-isolation", "no-isolation"]

_ISOLATION_TIERS = {"full-isolation", "partial-isolation", "no-isolation"}
```

## Effort & Risk

Implemented as `work: M` across 4 phases in one session. Actual effort matched the plan's own "larger than M" warning — the Phase 4 cross-component step required a real architecture discovery (the worker-protocol stdout constraint) not visible from static analysis alone, found only by running the real test suite. That's the key lesson: this class of change (adding an import to a low-level contract file) needs the full test suite run, not just import-sanity checks, before being considered safe — a partial validation would have shipped a broken subprocess protocol. Streaming/mode/schema changes (Phases 1-3) were low-risk and validated exactly as predicted.

## Standards

- One owner, not one spelling: only unified value-sets genuinely identical in membership and role (sink-error-policy/control-validation-policy; the {apply,prune,status} and {plan,apply,prune,status} family-mode sets). termination-policy, overflow_policy, invalid_event_policy stayed separate — distinct membership.
- Plain-string wire/config values kept as narrow Literal aliases plus validation; no StrEnum introduced anywhere in this item.
- Preserved existing serialized values except the one intentional mcp.py reason-string fix.
- Component boundary: providers_api is the sanctioned surface for cross-component provider-type consumption — held for the export-surface fix and for descriptors/base.py's same-component consolidation. Where that boundary conflicted with a lower-level operational constraint (the worker subprocess's stdout protocol), the operational constraint won and the deviation is documented, not silently absorbed.
