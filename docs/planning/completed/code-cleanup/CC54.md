# Consolidate duplicated _emit(on_progress-or-push_status) helper across providers services

## Description

Four near-identical private `_emit` helpers exist in the providers component, each implementing 'call the injected ComponentOutputSink if given, else fall back to something': reconcile.py:43, lifecycle.py:43, catalog.py:18, surfaces/manager.py:38. Only two of them (reconcile.py, lifecycle.py) actually fall back to the global `foundation.interaction.push_status` when no callback is supplied — catalog.py and surfaces/manager.py silently drop the message instead. That's a real behavioral inconsistency (messages vanish for callers of catalog refresh / surface apply that don't wire an on_progress callback), found while designing the reconciliation-policy plan's analogous ask_fn injectable-callback pattern (see plan 'onboarding-policy', ON03) and noticing the codebase already has this exact idiom duplicated four times with drift between copies.

## Steps

1. Extract one shared helper, e.g. `emit_or_push_status(output: ComponentOutputSink | None, component: str, message: str, *, level: str = 'info', **data) -> None` in a foundation-level module (candidates: foundation/contracts/output.py, next to ComponentOutputSink itself, or a new small module in foundation/interaction/ since it calls push_status) that always falls back to `push_status(component, message, level=level, details=data)` when output is None.
2. Replace all four component-local `_emit` definitions with calls to the shared helper, passing each caller's own component name ('providers' in all four current cases, but the helper should not hardcode that).
3. Preserve each call site's existing extra fields where they differ (e.g. surfaces/manager.py's `kind='log'` on the ComponentOutputEvent) by keeping those as parameters/kwargs on the shared helper rather than dropping functionality during the merge.
