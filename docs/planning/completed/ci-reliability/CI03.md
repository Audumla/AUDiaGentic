# Rotate gateway journals daily with protected five-day trace retention

## Description

User-authorized daily UTC append-only trace segments, byte-based rollover, gzip of closed segments and configurable five-day background deletion. Preserve active, unresolved, recovery-required and pinned request evidence; keep request state/results and 100-request history policy independent.

## Steps

Reuse current indexed journal writers/readers; add rotation-aware streaming readers and stable sequence pagination. Move compression/expiry to bounded background maintenance. Add validated policy fields, safeguards, docs and regression tests.

## Detailed Solution & Technical Design

Per-resource canonical NDJSON head with daily UTC/size rollover into immutable numbered segments, plain or gzip. Durable segment counter orders archives even across wall-clock rollback. Current-head indexed reads are fenced; retained segments stream with bounded head snapshots. Background compression copies outside lifecycle and append locks; short atomic publication is fenced. Hourly/startup and terminal-triggered sweeps reuse one coalesced retention worker. Trace expiry defaults to5elapsed days from last append; configuration is rechecked under request->retention->session fences. Active/unresolved/recovery-required/pinned or unreadable records are protected. Unmatched/unresolved recovery intent also protects timeline/DOM traces. Recovery-action journals enforce budgets/idempotency and are durable control state: rotate/compress but never age-expire. Request records/results/runtime are not expiry targets. Both explicit purge paths and late maintenance observations share external resource maintenance fences. A stamped256-entry metadata cache reduces append overhead without ignoring atomic replacement/external edits.
