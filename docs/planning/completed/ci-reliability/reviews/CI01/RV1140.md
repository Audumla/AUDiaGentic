# Main fast validation exposes cross-process StartupLock PID-publication race

## Notes



## Findings

Main run 40050894693 failed cross-process session append regression: 11 of 12 successful child appends persisted. StartupLock atomically creates its PID file, then writes PID; another process seeing an empty file treats it as malformed/stale and unlinks a live claim. Stale reaping can also race a replacement claim. Serialize claim publication/reaping/release using existing stable OS-backed AdvisoryLock companion, retaining PID-file semantics and a single timeout budget. Add deterministic process regression pausing PID publication while a contender must time out rather than enter.

## Conclusion

Hold v0.4.1. Repair exclusion instead of rerunning away lost-update evidence.
