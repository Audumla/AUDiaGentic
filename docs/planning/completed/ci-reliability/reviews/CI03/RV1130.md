# Keep recovery authority and purge fencing safe during journal expiry

## Notes



## Findings

Recovery journals contain durable action intent, not merely debug text. A terminal request with an unmatched intent or unresolved result must remain protected even if its record lacks a recovery-required flag. Maintenance must use request -> retention -> session lock order. A separate external request-maintenance fence must serialize late maintenance observations with both session purge and archive purge, without recreating request directories.

## Conclusion

Check pending recovery intent under mutation fence before deletion; preserve all evidence on uncertainty. Use the shared external maintenance fence for late writer/purge serialization. Add adversarial tests and operator documentation.
