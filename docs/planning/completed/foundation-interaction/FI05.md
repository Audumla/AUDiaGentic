# Wire the harness's own reload decision through foundation.interaction instead of a dead CLI advisory field

## Description

CORRECTED (2026-07-05): originally scoped as foundation/lifecycle/components.py (_component_result) calling foundation.interaction.ask on the harness's behalf after looking up the harness.runtime-sync capability. That capability is being deleted entirely by the expanded EV01 (harness subscribes to lifecycle.component.* directly and computes its own reload/refresh action inline, synchronously, before _component_result even runs -- no capability round trip needed). So this item's real scope is: once EV01's harness lifecycle-subscriber exists and decides an action is needed, and FI01/FI02 exist, wire THAT subscriber (in runtime/harness, not foundation/lifecycle/components.py) to call foundation.interaction.ask() directly and act on the answer. foundation/lifecycle/components.py needs no changes at all beyond what EV01 already does (deleting the dead 'sync' field).

This preserves the principle that runtime owns its own runtime decisions."]
