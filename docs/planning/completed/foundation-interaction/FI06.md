# Fix MCP elicitation: async-native ask path, Literal choice schema, per-request ctx wiring, error taxonomy

## Description

Fixes RV121: foundation/interaction.py's MCP ask path cannot work today. Verified defects (2026-07-06, current file): (1) _elicit_sync (interaction.py:127-142) calls loop.run_until_complete() on an already-running loop -- inside a FastMCP tool handler (always a running loop) this raises RuntimeError('This event loop is already running') unconditionally, which the over-broad `except (asyncio.TimeoutError, Exception)` swallows into a TIMED_OUT response, so elicitation fails 100% of the time in the only environment it exists for, silently. (2) _build_elicit_schema (interaction.py:100-124) constrains choices by raising pydantic ValidationError from __init__ via `ValidationError(_ChoiceSchema, msg)` -- not a valid constructor in pydantic v2 (raises TypeError), and the generated model is a bare `value: str` field, so the elicitation requestedSchema carries no enum and the client never sees the valid options. (3) Nothing constructs McpAskBackend anywhere -- foundation/mcp/component_server.py has no elicitation wiring, so even a correct backend is unreachable. DECIDED SOLUTION: (a) Add an async-native path: `async def ask_async(title, description='', choices=None, default_choice=None, timeout_seconds=30, *, ctx=None) -> AskResponse` -- when ctx is provided it awaits ctx.elicit(message, schema) directly under asyncio.wait_for(timeout); the MCP fast path takes ctx per-request (mirroring how run_blocking_with_output/McpOutputBridge are ctx-scoped in component_server.py:309-331), NOT via the global set_backend() -- the global backend remains for CLI/push only. Keep sync ask() for non-async callers; when called with no running loop it may wrap ask_async via asyncio.run(); when called from inside a running loop without ctx it must NOT attempt elicitation (return TIMED_OUT with a debug log) rather than deadlock. (b) Build the choice schema with pydantic.create_model('ElicitChoice', value=(Literal[*choices], ...)) so the enum is carried in the requestedSchema; freeform stays `value: str`. Delete the __init__-raising validator entirely. (c) Error taxonomy per the FI02 risk note: client-does-not-support-elicitation (capability probe or McpError with method-not-found) -> debug log + TIMED_OUT; transport/protocol failure -> logger.warning(exc_info=True) per ARCHITECTURE_STANDARDS section 8 + TIMED_OUT; decline/cancel remain REJECTED-with-elicit_action (already correct, keep). Narrow `except (asyncio.TimeoutError, Exception)` to the specific exception types. (d) In foundation/mcp/component_server.py, expose a helper (e.g. ask_via_ctx(ctx, ...)) so MCP tool handlers have one sanctioned entry point, following the McpOutputBridge shape.

## Effort & Risk

Mid-high: async API design must not break the sync callers (harness handler). The per-request-ctx decision avoids global-state races between concurrent MCP requests -- do not revisit it toward a global backend without a review. Interim behavior: until FI07 lands, a failed/timed-out elicitation still just returns TIMED_OUT (caller treats as deferral); no durable fallback yet.
