# Build the durable interaction store: persisted request/respond/get_response with TTL, schema, and bus events

## Description

Fixes the core of RV120: FI01's actual deliverable -- a durable, file-backed ask/answer store -- was never built; foundation/interaction.py is in-memory only, get_response(ask_id) just re-asks (interaction.py:282-297), push_status never touches the event bus, and no schema exists. DECIDED SOLUTION (adopts the original FI01 spec onto the now-existing module, keeping the backend abstraction from the redesign): (1) Store layout: <project_root>/.audiagentic/runtime/interactions/{request_id}.json, path composed via foundation/paths/names.py helpers (project_marker_path(project_root) / 'runtime' / 'interactions') -- never a hardcoded '.audiagentic' literal (CP01). Record shape generalizes agent_jobs/approvals.py's proven pattern (approvals.py:20-60: requested_at ISO-Z, state pending/answered/expired, DEFAULT_TTL): fields request_id, kind, title, description, choices, state ('pending'|'answered'|'expired'), answer (choice + details), source_kind, source_id, requested_at, answered_at, ttl_seconds (default 28800 = approvals' 8h). (2) Schema: foundation-owned interaction-request.schema.json under foundation/contracts/ (registered with the existing schema_registry used by approvals.py:19 validate_with_schema), a superset covering binary approvals and open questions. Do NOT touch components/agent_jobs/contracts/approval-request.schema.json -- that retires in FI08, not here (RV112 atomic-migration rule). (3) API: request(kind, title, ..., project_root) -> request_id persists a pending record and publishes 'interaction.requested' on get_bus(); respond(request_id, choice, *, details=None, project_root) writes the answer and publishes 'interaction.answered'; get_response(request_id, *, project_root) -> AskResponse|None becomes a REAL poll reading the record (rename the current re-ask wrapper out of the way -- its semantics were misleading, RV120 point 4); expiry evaluated lazily on read like approvals.py _is_expired (approvals.py:156). (4) push_status additionally publishes 'interaction.status' on get_bus() (keeping the existing backend/log delivery). (5) ask() integration: when no live backend/ctx answers (TIMED_OUT), ask() with persist=True and a project_root persists a pending durable request and returns TIMED_OUT carrying the request_id in details -- callers that can poll later (job service) use it; fire-and-forget callers ignore it. Event-type names are domain-neutral per EV04 ('interaction.*').
