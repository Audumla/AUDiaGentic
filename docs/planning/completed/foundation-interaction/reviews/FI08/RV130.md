# CliBackend status-semantics fix is misplaced in FI08 — it belongs in FI06, which owns the response model

## Notes



## Findings

FI08's Part B step 7 fixes CliBackend's status conflation (interaction.py:204 branches on the magic string 'rejected' to derive APPROVED/REJECTED). But FI06 lands first and writes the tests that assert on AskResponse semantics — if the status model changes afterward in FI08, FI06's tests and the harness handler assertions churn twice. The response-model decision (status = transport outcome: answered/declined/timed_out; the selected option lives only in .choice) is a foundation.interaction API concern and should be settled in the item that owns the module's API rework (FI06), not in the migration item that merely consumes it.

## Conclusion

Move the status-semantics decision and the CliBackend fix into FI06's scope; FI08 keeps only the call-site migration. Update both items.
