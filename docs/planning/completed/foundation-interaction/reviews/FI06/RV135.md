# CONFIRMED: worker-thread branch inverted — the RV129 harness path still returns TIMED_OUT; required test file never written

## Findings

(1) CRITICAL, empirically reproduced (2026-07-06): interaction.ask()'s contextvar path reads `current = asyncio.get_running_loop()` INSIDE the try block and only submits via run_coroutine_threadsafe when `current is not loop`. In the actual RV129 scenario -- sync code in run_blocking_with_output's worker thread, where NO loop runs in the current thread -- get_running_loop() raises RuntimeError, the `except RuntimeError: pass` swallows it, and ask() falls through to TIMED_OUT. Reproduction: stub ctx + loop in another thread, _mcp_ctx_var set, ask() called from a loop-less thread -> 'elicit coroutine ran: False, status TIMED_OUT'. The threadsafe submit is only reachable in the exotic case of a DIFFERENT loop running in the current thread. FIX: hoist the loop probe -- `try: current = asyncio.get_running_loop() except RuntimeError: current = None`; submit via run_coroutine_threadsafe when `current is None or current is not loop`; only the `current is loop` case falls through (cannot block own loop). Also give future.result() a small margin over timeout_seconds (the inner wait_for already enforces the user timeout; racing both at the same value makes the outer TimeoutError win nondeterministically). (2) The item's required test suite -- tests/unit/foundation/test_interaction.py with five stub-Context scenarios INCLUDING the harness-path thread-boundary simulation -- was never written; validation bullet 1 was not executed, and it is precisely the test that would have caught defect (1). The item was marked completed regardless: another Definition-of-Done violation (CREATING_PLANS.md section 5). (3) Type inconsistency: InteractionBackend Protocol declares sync ask(), but McpAskBackend.ask is now async -- if McpAskBackend were ever set as the global backend, ask() would return an un-awaited coroutine. Either drop McpAskBackend entirely (nothing constructs it; ask_async/ask_via_ctx are the real surface) or split the protocol. (4) Disposition note: RV121's original defects (run_until_complete misuse, broken pydantic ValidationError) ARE genuinely fixed -- the Literal create_model schema and async wait_for path are correct, ResponseStatus semantics fix (RV130) is done well, and the component_server contextvar wiring is right (asyncio.to_thread propagates context). RV121 stays open until (1)+(2) are resolved.
