# Durable store — the item's core deliverable — was never built; the interaction module is in-memory only and dead in production

## Notes



## Findings

foundation/interaction.py implements an in-memory global _backend with ask/push_status/respond dataclasses. Missing relative to FI01's spec: (1) NO durable file-backed store — no .audiagentic/runtime/interactions/{id}.json, no TTL/expiry, nothing persists; (2) NO schema — the generalized interaction-request schema (the approvals.py generalization that was the item's reason to exist) was never created; (3) NO event-bus integration — push_status never publishes 'interaction.status' via get_bus(), request/respond/'interaction.requested'/'interaction.answered' events don't exist; (4) get_response(ask_id) is not a poll for a prior request's resolution — it just calls ask() again with the id as the title, a misleading name with different semantics than specified; (5) no unit tests for the module at all (no test file references foundation.interaction). Compounding: nothing in src/ ever calls set_backend(), and foundation/mcp/component_server.py is untouched — so in every production process _backend is None, ask() always returns TIMED_OUT, and the entire FI01/FI02/FI05 chain is dead code (the harness reload ask can never fire). Also §9: CliBackend uses print() with noqa:T201 inside a foundation library module — print belongs in CLI entry points; a foundation-owned backend should route through cli_io or the caller should inject the sink. Positive: the no-backend fallback is at least non-blocking, so headless installs don't hang.

## Conclusion

This item should not be in completed/. Either build the specified durable store + schema + event publishing (and real get_response polling), or get an explicit user decision that the redesigned in-memory-backend shape replaces the spec — in which case FI03's premise (migrating approvals.py onto the durable primitive) collapses and FI03/FI04's status must be revisited too. Either way, something must call set_backend() for the feature to exist at runtime, and the module needs tests.
