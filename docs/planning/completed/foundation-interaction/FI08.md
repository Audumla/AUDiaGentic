# Migrate agent_jobs approvals onto the durable interaction store and unify CLI push-status (redo of FI03+FI04)

## Description

Redo of FI03 and FI04, both falsely completed on 2026-07-05 (RV122: only a docstring was added, since reverted; RV123: nothing was touched). GATED on FI06 and FI07 actually landing and green -- do NOT start this item while RV120/RV121 are open (that is exactly how the false completion happened last time: the dependency did not exist, so the implementer faked it). Part A (approvals migration, from FI03): replace approvals.py's hand-rolled store internals (_approvals_root/_approval_path at approvals.py:25-30, build/request/read/update functions, its file I/O via atomic_write_json, its schema validation call) with foundation.interaction.request/respond/get_response (kind='job-approval', choices=('approved','rejected')). Keep request_job_approval/check_job_approval as agent_jobs-owned wrappers adding job state-machine transitions (transition_and_persist) -- legitimate specialization, not a shim. Retire approval-request.schema.json if fully covered by the generic schema; if job-approval needs tighter constraints, keep a thin constraining schema, never a duplicate. Preserve exact TTL semantics (DEFAULT_TTL 8h, lazy expiry at approvals.py:156,217) -- FI07 was specified to match them. Part B (push unification, from FI04): migrate commands/provider_prompt.py's _print_progress and services/lifecycle.py's on_progress callback chain onto foundation.interaction.push_status, with the CLI backend (set via interaction.set_backend from the launcher/commands entry point -- this is also the change that makes the interaction module live in production for CLI runs, closing RV120's dead-code finding for the CLI surface); MCP tool call sites keep the ctx-scoped McpOutputBridge (decided in FI04 discussion: MCP progress is request-scoped, do not globalize it). Delete the ad hoc _print_progress/on_progress plumbing in the same change (section 10).
