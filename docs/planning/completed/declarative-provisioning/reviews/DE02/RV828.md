# DE02 delete-path: binary-file compensate and uninstall scope

## Notes



## Findings

D1 (minor, verified): single-file compensate captures self._prior_content via target.read_text(encoding='utf-8') and restores with atomic_write_text. This raises UnicodeDecodeError on a binary file. The codex hook scripts are UTF-8 text so the immediate DE02/codex use is safe, but the step is generic. Fix options: (a) capture bytes (target.read_bytes()) and restore via write_bytes for robustness; or (b) document delete-path single-file restore as text-only. Recommend (a). StepResult(status/outputs/reason) signature is confirmed correct.

D2 (scope confirmation): the codex uninstall delete-path removes ~/.hindsight/codex/scripts (recursive) but leaves ~/.hindsight/codex/settings.json (the download optional-file, written only when absent, potentially user-customised) and ~/.hindsight/codex.json (keys handled by config-remove; the file may remain as {} or with foreign keys). This matches 'remove downloaded scripts' and preserves user-owned settings — confirm that is the intended scope (likely yes; do NOT recursively delete ~/.hindsight/codex wholesale).

D3 (registration completeness): a new BUILTIN needs FOUR touch points under the current registry design — add the fragment to _BUILTIN_STEP_SCHEMAS, _REGISTRY.register in _register_builtins, an entry in the _builders dict literal, and add 'delete-path' to _params_accepting_types (path may contain {KEY}). The sample lists these; make all four explicit so none is missed.

## Conclusion

DE02 is sound. Apply D1 (bytes-based single-file restore) and make D3 explicit; D2 is a confirm-intent note. Incorporate and close.
