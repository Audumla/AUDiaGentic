# DE03: family result fields are hidden behind RecipeResult after DE01; verified describe_provider/deprecation shapes

## Notes



## Findings

E1 (design gap, important): DE03 says to read the managed family's 'changed' flag and collision signals, but AFTER DE01 reconcile receives a foundation RecipeResult (success/status/state) from execute_recipe_mode — NOT the ManagedMcpResult. The rich fields (verified present: changed, collision_ids, removed_ids, auto_refreshed, action_needed, error_code) are produced inside the managed-mcp step and currently dropped. DE03 MUST define how they reach reconcile. Recommended mechanism (reuses the existing context seam): the managed-* step writes result.to_mapping() into a mutable context bucket, e.g. context.setdefault('managed_results', {})[managed_id] = result.to_mapping(); reconcile passes a context dict into execute_recipe_mode and reads it back after the run. Then _refresh/collision/deprecation hints are computed from managed_results, not re-derived. NOTE ManagedMcpResult.auto_refreshed already encodes the refresh signal — prefer it over re-reading descriptor refresh_mode where available (fall back to refresh_mode for hooks/plugin results that lack it).

E2 (accuracy — remove hedge): describe_provider output is now verified — config_surfaces is a list of {kind, format, refresh_mode, capabilities:list, ...}; the mcp surface is kind=='mcp'. Drop the 'confirm exact key names' caveat in the sample; the keys are real.

E3 (accuracy — deprecation source): read deprecation from the descriptor, not an assumed describe_provider field. get_descriptor(pid).deprecated (bool) exists (descriptors/base.py:253); the human message + replacement live in the descriptor 'deprecated' block (gemini.yaml: replacement_provider: antigravity, message: '...'). _is_deprecated/_deprecation_message should read get_descriptor(pid).deprecated and that block, not guess a summary-row field.

## Conclusion

DE03 is viable but its central mechanism (surfacing family results) is under-specified for the post-DE01 recipe path — E1 must be added or DE03 cannot report collisions/changed. E2/E3 are accuracy fixes. This also reinforces sequencing DE03 AFTER DE01 and defining the context result-bucket as part of DE01's managed-* step contract. Incorporate and close.
