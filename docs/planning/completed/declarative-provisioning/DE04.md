# Correct Hindsight installation routes per canonical INSTALL_MAP audit

## Description

The INSTALL_MAP was rewritten based on the canonical documented Hindsight integration methods. The current implementation uses a fixed family preference order (managed-hooks > managed-mcp > plugin-entry) which selects wrong families for several providers.

Key corrections:
- Claude Code: should use plugin-entry (marketplace plugin), not managed-mcp
- OpenCode: should use plugin-entry, not managed-mcp 
- Cline: should use managed-hooks, not managed-mcp
- Aider: should use cli-lifecycle (pip install hindsight-aider) + config-set, not guidance-only
- Copilot, Roo, OpenHands: compound recipes (MCP + generated-surfaces rule)
- Goose, Qwen, Gemini CLI: wrong config paths in provider YAML

All corrections use existing families — no new families needed. Toolchains already updated with pip.

## Steps

- Fix _resolve_family routing: plugin-entry must beat managed-mcp for providers that support both (Claude, OpenCode)
- Add plugin-entry to claude.yaml automation_capabilities
- Add managed-hooks to cline.yaml automation_capabilities
- Create Aider recipe: hindsight-aider.yaml using cli-lifecycle (pip install) + config-set for ~/.hindsight/aider.json
- Add Aider to _ARTIFACT_RECIPES mapping
- Fix Goose mcp_config path from .goose/config.yaml to ~/.config/goose/config.yaml
- Fix Qwen mcp_config path from project .mcp.json to ~/.qwen/settings.json
- Fix Gemini CLI mcp_config path (use .gemini/settings.json for project scope)
- Fix Copilot mcp_config path from .mcp.json to .vscode/mcp.json; add generated-surfaces step for .github/copilot-instructions.md
- Fix Roo mcp_config path from .mcp.json to .roo/mcp.json; add generated-surfaces step for .roo/rules/hindsight-memory.md
- Add generated-surfaces step for OpenHands AGENTS.md rule
- Update _ARTIFACT_RECIPES and _resolve_recipe as needed
