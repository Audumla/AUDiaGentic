# Missing coverage: fragments.py, lifecycle/provision entry-points, and spec duplication

## Notes

Validated against current code. Incorporated into RS00 inventory and cross-linked to RS12/RS19 guard work.

## Findings

RS00's description mentions 'recipe codebase and dependants' but the inventory map must explicitly cover:

1. **fragments.py** (foundation/toolchains/fragments.py:162) — generic reconciler used by MCP sync but not mentioned in any RS item. It's a shared primitive that recipes interact with via managed-block steps.

2. **CompensatingSequence** (sequence.py:122) — step execution engine. RS05 mentions shell.py/sequence.py for redaction, but the inventory must document Sequence's `run()` output propagation (`per_step` list at line 42-70), which is how stdout leaks to RecipeResult.details.

3. **lifecycle.py** (hindsight/lifecycle.py:175) and **provision.py** (hindsight/provision.py:135) — the recipe orchestration entry-points. These call registry.install()/uninstall() but also construct `ProviderRecipeResult` directly as fallback (lines 109, 116). RS items don't mention this impact.

4. **status.py** (hindsight/status.py) — builds status reports by invoking probe(). Not mentioned in any item.

5. **_NO_BACKEND_GUIDANCE_SPEC** duplication: lifecycle.py:28-39 defines the same RecipeSpec as strategies._GUIDANCE_SPEC. Any spec change must be applied to both locations, but no RS item flags this.

6. **resolve_ref** usage (plugin_recipes.py:471-474) — `_PluginArrayRecipe` imports `resolve_ref` for dynamic reader/writer/remover dispatch. This is a foundation import used in component-layer recipes; the inventory should note it as a seam.

**Recommendation**: Update RS00 description to include these 6 areas explicitly, or add them as sub-bullets when the inventory document is created.
