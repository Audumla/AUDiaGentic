# Redaction scope must extend to run_steps and DeclaredStepRecipe probe

## Notes

Validated propagation through sequence, `run_steps()`, and declared-step probes. Incorporated into RS05, RS15, and RS16.

## Findings

RS05 correctly identifies that ShellProvisionStep captures raw stdout/stderr into StepResult.outputs (shell.py:89-96, 138-144).

**Gap: Redaction scope must extend beyond shell.py and sequence.py**

The plan's file list covers:
- provision_steps/shell.py
- provision_steps/sequence.py

But the leakage path is wider:

1. **recipe_contract.py:126** — `run_steps()` captures `seq_result.outputs.get("steps", [])` into RecipeResult.details on failure. This propagates all per-step outputs (including stdout) up to the recipe result, which is then exposed through ProviderRecipeResult.

2. **sequence.py:53-57** — CompensatingSequence.run() captures `result.outputs` for every step, including non-shell steps (config-set, write-file). For shell steps this includes raw stdout.

3. **recipe_patterns.py:124** — DeclaredStepRecipe.probe() uses `substitute_params` + `CommandProbe` which may fail with unredacted command strings in the exception message (line 127).

4. **env variable exposure**: ShellProvisionStep._run_argv() at lines 68-72 merges `self.env` into subprocess environment. If `self.env` contains secrets (e.g., API keys), these are passed to child processes but not surfaced in outputs. However, if the child process echoes its environment or logs the command line, they could appear in stdout.

**Recommendation**: Expand RS05 file list to include `recipe_contract.py` (run_steps output capture) and `recipe_patterns.py` (probe failure messages). Add validation: "Tests prove recipe_contract.run_steps() does not propagate raw shell outputs into RecipeResult.details on failure."
