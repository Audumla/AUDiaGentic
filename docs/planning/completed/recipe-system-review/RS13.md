# Characterize provisioning step substitution and path behavior

## Description

Small execution slice for RS04. Add tests that document current substitution and path behavior before changing any provisioning step implementation.

Dependency: none (characterize phase — must complete before RS14).

## Steps

1. In `tests/unit/foundation/toolchains/test_provision_step.py` (existing file, corrected path per RV228), add:
   a. `test_substitute_is_strict_at_definition_time`: call `_shell_from_dict({"command": "echo {UNKNOWN}"}, {}, None, None)` (or the equivalent `config-set`/`write-file`/`managed-block` `_*_from_dict` factory) and assert it raises the `VAL-PSTEP-002` error (import `_pstep_error`'s code prefix or catch `AudiaGenticError` and check `.code`).
   b. `test_substitute_params_is_lenient`: call `substitute_params("echo {UNKNOWN}", {})` from `provision_steps/factory.py` (or wherever it's re-exported) and assert it returns `"echo {UNKNOWN}"` unchanged (no raise).
   c. `test_shell_step_applies_two_substitution_passes`: build a `ShellProvisionStep` with `command=["echo", "{PARAM}-{context_key}"]` where `{PARAM}` was already resolved to a literal by `_substitute` at construction time (simulate by passing the already-substituted list directly to the constructor, not through `_shell_from_dict`, since that's how the real pipeline works) and `context={"context_key": "value"}` — call `step.run(context)` and assert the executed command reflects the run-time substitution. Document in the test docstring that this is intentional two-stage substitution, not a bug.
2. Add `test_foundation_path_steps_do_not_anchor_to_project_root`: construct a `WriteFileStep`/`ManagedBlockStep` with a relative path and confirm it resolves via `Path(...).expanduser()` relative to CWD, not to any injected project root (there is no project-root parameter on these classes — the test should assert the class signature has no such parameter, e.g. via `inspect.signature(WriteFileStep.__init__)`, to lock the boundary so a future change doesn't quietly add capability-specific vocabulary to foundation).
3. Add `test_hindsight_absolute_project_path_anchors_relative_paths` to `tests/unit/memory/test_hindsight_recipe.py`: call `_absolute_project_path("relative/path", project_root=Path("/tmp/proj"))` and assert it returns `Path("/tmp/proj/relative/path")`; call it with an absolute path and assert `project_root` is ignored.
4. Add `test_shell_render_has_no_second_consumer` (documentation-as-test): grep `src/audiagentic/foundation/toolchains/provision_steps/*.py` for `.format(**context)` or equivalent runtime-templating calls (use `ast` or a simple string search within the test) and assert exactly one match, in `shell.py` — this is the precondition RS14 must re-check before extracting anything; if this test starts failing (a 2nd consumer appeared), that is the signal RS14's extraction becomes valid.
5. Run `python -m pytest tests/unit/foundation/toolchains/test_provision_step.py tests/unit/memory/test_hindsight_recipe.py -v`.
