# Consolidate Hindsight recipe patterns and plugin recipe duplication

## Description

Consolidate repeated Hindsight recipe mechanics while preserving provider-specific integration policy. Hindsight already moved guidance-only and declared-step recipes into `RecipeSpec` assembly. Remaining plugin recipes still duplicate source-gated step execution, plugin install/uninstall handling, probe→verify patterns, dry-run strings, and managed MCP status/sync logic.

## Steps

This is the parent/analysis item; execution happens in RS11 (characterize) then RS12 (consolidate). Do not implement fixes directly under this ID.

1. Confirmed root cause (RV228/RV229 audit) in `src/audiagentic/components/memory/hindsight/plugin_recipes.py`:
   a. `_should_run_plugin_command()` (checks `self._row.audia_action == "call_official_installer"`) is defined identically in both `PluginConfigRecipe` (line ~87) and `_PluginUrlConfigRecipe` (line ~360).
   b. The gated-step-execution block (`if self._row.source_status != "verified": return self._stamp(ProviderRecipeResult.fail(...refusing to execute..., action_needed=...)); ... steps = steps_from_defs(...); seq = run_steps(...); if not seq.success: return self._stamp(seq)`) is repeated near-verbatim 4 times: `PluginConfigRecipe.install`, `PluginConfigRecipe.uninstall`, `_PluginUrlConfigRecipe.install`, `_PluginUrlConfigRecipe.uninstall`.
   c. This is the *same* gate-then-run-steps pattern that `foundation/toolchains/recipe_patterns.py::DeclaredStepRecipe` already implements generically (its `install()`/`uninstall()` check `self._m.verified`, run `steps_from_defs` + `run_steps`, with `gate_action`/`source_label` messaging) — the plugin recipes hand-rolled a parallel implementation instead of reusing `DeclaredStepRecipe`/`InstallManifest`.
2. RS11 must characterize current behavior of all 4 duplicated blocks plus `_should_run_plugin_command` before RS12 extracts a shared helper.
3. RS12's extraction target: a small shared method/function (e.g. `_run_gated_steps(row, params, step_defs, *, fail_prefix, subject) -> ProviderRecipeResult`) used by all 4 call sites, OR reuse `DeclaredStepRecipe`'s gate logic directly if RS11's characterization shows the semantics are identical (same `source_status`/`verified` gate, same message shape). Do not resurrect `ManagedEntryRecipe`/`ConfigEntryTarget` (SL13 — confirmed still absent, docstring-only reference in recipe_patterns.py).
4. Once RS11/RS12 land, update this item's Notes with the final extraction summary.
