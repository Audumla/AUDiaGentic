# Remove dependant duplication of managed config and artifact primitives

## Description

Audit recipe dependants for direct reimplementation of primitives already provided by foundation or providers. Hindsight/plugin recipes currently mix provider managed MCP sync, direct JSON writes, direct file deletion, source-gated step execution, plugin array reader/writer/remover dispatch, and custom Windows repair. Keep genuinely component-specific logic, but route common file/config ownership, managed config, and lifecycle concerns through shared primitives.

## Steps

This is the parent/analysis item; execution happens in RS17 (classify) then RS18 (replace/document). Do not implement fixes directly under this ID.

1. Confirmed direct mutations (RV228/RV229 audit), all in `src/audiagentic/components/memory/hindsight/plugin_recipes.py`:
   a. `_PluginUrlConfigRecipe.configure()` (~line 410-414): `self._url_config_path.parent.mkdir(...)` + `self._url_config_path.write_text(json.dumps(self._expected_config(), indent=2), encoding="utf-8")` — direct write, not registered with `ArtifactRegistry`, not routed through `WriteFileStep`.
   b. `_PluginUrlConfigRecipe.prune()` (~line 446): `self._url_config_path.unlink(missing_ok=True)` — direct delete, no registry lookup, no dry-run-safe pattern (unlike `ArtifactRegistry.prune()` which reports `skipped` for already-missing files instead of silently no-op'ing via `missing_ok`).
   c. `_repair_windows_plugin_mcp()` (~line 203-280): direct `json.loads(mcp_path.read_text())` / `mcp_path.write_text(json.dumps(content, indent=2))` on a Windows-only plugin-owned `.mcp.json` file discovered via `glob.glob()`.
   d. `_PluginArrayRecipe` uses `resolve_ref()` on matrix-row-configured reader/writer/remover callables (Std §2-compliant, config-driven — NOT a violation, do not touch).
2. Preliminary classification for RS17 to confirm/refute with its own grep (do not treat this as final — RS17 must independently verify):
   - (a) configure/write: likely "shared-primitive-available" — the JSON content is already fully built by `_build_plugin_url_config()` before the write; it could be handed to a `WriteFileStep` instance (which auto-registers with `ArtifactRegistry` when given one) instead of a raw `Path.write_text`.
   - (b) prune/unlink: likely "shared-primitive-available" for the same reason — once (a) routes through `WriteFileStep`/`ArtifactRegistry`, prune should go through `ArtifactRegistry.prune()` instead of a bare `unlink(missing_ok=True)`.
   - (c) Windows repair: likely "intentional one-off" — it patches a file this recipe does not own/create (the plugin's own generated `.mcp.json`), discovered via glob rather than a known path, so it is not expressible as an owned artifact for prune purposes. Document, do not replace.
3. Once RS17/RS18 land, update this item's Notes with the final classification table and confirm no unauthorized reimplementation of `ArtifactRegistry`/`WriteFileStep` semantics remains.
