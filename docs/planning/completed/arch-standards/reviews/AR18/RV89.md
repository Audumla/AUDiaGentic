# Review AR18 implementation: duplicate job_dir and session path aliases remain

## Notes

Verified 2026-07-03: both findings already resolved in the working tree. (1) rg 'def job_dir' src/ returns exactly one definition — components/agent_jobs/paths.py; jobs_store.py imports it from paths. (2) session_input_path / session_input_events_path / session_stdin_log_path no longer exist anywhere in the repo; session_input_store.py and paths.py use the canonical job_* helpers. Full tests/unit suite green.

## Findings

AR18's core move appears partially landed (`runtime.state`, `runtime.home`, and `runtime.config` imports are gone), but two acceptance criteria are still not met. First, `components/agent_jobs/jobs_store.py` still defines its own `job_dir()` even though `components/agent_jobs/paths.py` already owns that path helper; `rg 'def job_dir' src/` returns two definitions, violating AR18 acceptance (c) and the item's own step-1 instruction to delete the duplicate during the move. Second, `components/agent_jobs/session_input_store.py` still exposes `session_input_path()`, `session_input_events_path()`, and `session_stdin_log_path()` as one-line aliases of `job_input_path()`, `job_input_events_path()`, and `job_stdin_log_path()`. AR18 explicitly decided those alias functions should be deleted in the move, with callers using the job_* helpers directly; acceptance (d) says the alias functions are gone. As implemented, the ownership move happened but the duplicated API surface remains.

## Conclusion

AR18 not complete yet. Remove the duplicate `job_dir()` from jobs_store.py and delete the three session_* alias functions from session_input_store.py, updating any call sites to use the canonical job_* path helpers directly.
