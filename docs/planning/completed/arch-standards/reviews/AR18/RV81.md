# Review AR18: state dissolution and shim deletion

## Notes



## Findings

Well-specified with import evidence — reduces cross-cutting risk by moving domain state to its owner.

Concerns:

1. **Session→agent_jobs coupling (step 3)** — session_input_store needs job path functions. If session component is expected to operate without agent_jobs (e.g. session status before jobs subsystem loads), this creates a circular import or new dependency. Resolution: verify the three session-specific paths are genuinely session-owned lifecycle, not orphaned job artifacts; if so, keep them in session rather than deferring to agent_jobs.

2. **runtime/config consumers include runtime/lifecycle modules** — step 6 says "includes runtime/lifecycle modules" in the consumer list. AR19 depends on AR18 landing before lifecycle moves. If runtime/config is deleted now and lifecycle still lives in runtime/, those intra-runtime imports break until AR19 lands, violating atomic migration (std 10). Resolution: if lifecycle consumes runtime.config, defer shim deletion to AR19's move window, or do the re-pointing of runtime/lifecycle→foundation.io before deleting runtime/config.

3. **ndjson helpers scope** — _append_ndjson/_append_text are described as "genuinely shared mechanics". Verify no other modules outside session_input_store use them today; if only session stores need them, embedding in the moved session module may be simpler than promoting to foundation/io.py (which already has atomic_write_json).
