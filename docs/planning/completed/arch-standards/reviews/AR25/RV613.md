# AR25 standard landed and gateway enforced; the automated check generalizes to only one component

## Notes

T3 post-completion review. Verified: ARCHITECTURE_STANDARDS.md §8 'Protocol Adapter Boundaries' exists and states the full rule; tests/unit/foundation/test_protocol_adapter_boundaries.py enforces API-modules-never-import-MCP generically (all *_api.py) and the adapter→internals direction for the agents gateway MCP/HTTP adapters; the MCP timeout constant is gone from agents_gateway_api.py.

## Findings

1) ENFORCEMENT NARROWER THAN THE RULE: §8 forbids every adapter from importing its component's store/queue/dispatch/service internals, and AR25's validation claims 'architecture checks fail when an MCP module imports owning-component internals' — but the adapter→internals check is hardcoded to agents_gateway_mcp.py and the gateway HTTP transport only. A survey of all 17 *_mcp.py modules shows they currently import their package root or public API (no live violation found — jobs_mcp's event_overview and providers_mcp's contracts.lifecycle_modes are contract/read-only modules), so generalizing now is cheap: extend the existing AST helper to iterate every components/**/*_mcp.py and forbid imports matching its own component's (store|queue|dispatch|service|adapters|internal) modules, with an explicit exception list per step 4's inventory. Without this, a regression in any other component's MCP module passes CI and §8 depends on review vigilance. 2) MINOR: 'Unrelated existing Ruff findings remain in tests/unit/release/test_ledger_api.py' is noted but unowned — same pattern as the Coding-LSP suite timeout flagged in RV604; small persistent validation noise should get an owner rather than be re-cited by future completions.

## Conclusion

Duplicate confirmation incorporated into RV595. The check is now generalized across every component MCP module and the two live non-boundary imports found by that inventory were migrated. Close this duplicate review.
