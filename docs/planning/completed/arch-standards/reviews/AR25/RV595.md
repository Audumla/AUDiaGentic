# Protocol-adapter enforcement is gateway-specific despite a repository-wide completion claim

## Notes

Post-completion implementation audit against Architecture Standards, Architecture Guidelines, Observability Standards, plan intent, and reuse-before-build doctrine.

## Findings

HIGH — AR25's original enforcement covered only the agents gateway MCP/HTTP pair. A repository-wide inventory found two live deviations from the stated thin-adapter rule: providers MCP loaded internal surface contributions to construct a default request, and agent-jobs MCP imported the event overview implementation directly because no jobs API boundary existed.

## Conclusion

Resolved with contained reuse. Providers MCP delegates default contribution selection to the existing `providers_api.operate_provider_surfaces` operation; agent-jobs exposes its existing read-only overview through a small `jobs_api` application boundary. The architecture test now inventories every `*_mcp.py` and allows same-component dependencies only through API, client, or contract modules. Focused boundary/jobs/providers validation passes (22 tests).
