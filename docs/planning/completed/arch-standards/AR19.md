# Relayer: move runtime/lifecycle to foundation/lifecycle; invert the single harness seam

## Description

Doctrine realignment (Standard 1 v2): runtime/lifecycle is the component-lifecycle capability, not process orchestration. Evidence: it is consumed by six components (coding_lsp, ledger, memory, project, providers, release) plus launcher; its outbound imports are foundation (components machinery, events, errors, probe), intra-package, and exactly one orchestration dependency — build_runtime_sync from runtime.harness (runtime/lifecycle/components.py:27). The component machinery it operates (loader, registry, hooks, dependencies) already lives in foundation/components/ — the current split places half the component-system capability in foundation and its operations (install/detect/sync/uninstall) in runtime, which is the naming misalignment this item fixes.

After this move, runtime/ contains only genuinely runtime things: system (environment), harness, rig, update — packages that execute or observe live processes.
