# Phase 2: Hoist shared runner helpers across pi and opencode harness runners

## Description

Follow-up to AR08 (Phase 1: AgentContext unification). Confirmed duplicated runner logic beyond the dataclass: startup-info banner block (Project/Provider/Model/Endpoint/Server/MCP/Log lines), timestamped log-path construction, the agent_run_started/agent_run_finished JSON log envelope, the smoke-check flow (models-endpoint check + CLI version probe), _build_run_env env assembly, and the supervised_run + rig-teardown invocation — all appear in both pi/runner/agent_run.py and opencode/runner/__init__.py with only cosmetic differences. Hoist these into shared runtime/harness modules; each harness keeps only its command construction and genuinely harness-specific steps (pi direct-MCP smoke, opencode version probe). Depends on AR08 landing first since these helpers consume the unified AgentContext.

## Steps

1. PREREQUISITE (hard gate): AR08 is in planning state 'completed' — not merely merged/tested — before this item starts. Verify with plan_get_item(AR08).
2. GOLDEN FILE FIRST: before touching runner code, capture today's agent_run_started/agent_run_finished JSON envelopes from both runners as golden fixtures; the extracted helpers must reproduce them byte-for-byte.
3. Create src/audiagentic/runtime/harness/run_common.py with fixed signatures: build_base_run_env(ctx: AgentContext) -> dict[str, str] (the AUDIAGENTIC_*/OPENAI_* assembly common to both; harness-specific extras layered by each caller); make_log_path(ctx, mode: str) -> Path (timestamped '<mode>-<stamp>.log' under ctx.agent_log_dir, creating dirs); write_run_started(log_path, ctx, agent_args) / append_run_finished(log_path, returncode); print_startup_info(ctx, log_path, *, title: str, extra_lines: list[str] = ()) (honoring ui.show_startup_info); run_supervised(command, cwd, env, log_path) -> int (supervised_run + run-finished envelope only).
4. SCOPE EXCLUSIONS (verified against the code, RV76): (a) Rig teardown is NOT shared — opencode kills the managed rig in its run finally-block (opencode/runner/__init__.py:233-235); pi has no rig teardown in its run path (its only kill_process_tree at pi/runner/agent_run.py:123 is the smoke-timeout kill of the agent process). Unifying would change pi behavior; teardown stays in the opencode caller. (b) Smoke flows are NOT shared — the only common piece is require_models_endpoint(ctx.endpoint, timeout=15), which both already import from runtime.rig.http; pi's direct-MCP smoke + sentinel check and opencode's --version probe remain per-harness.
5. Migrate pi/runner/agent_run.py + pi/runner/command.py (_build_run_env common core) and opencode/runner/__init__.py to the helpers, deleting the duplicated blocks in the same change. Harness-specific logic stays put: pi's tools banner lines (pass via extra_lines), each harness's command construction, opencode's rig teardown.
6. MODULE-SIZE GUARD: if run_common.py exceeds ~350 lines (std 3), split into run_logging.py (log path + envelopes) and keep env/banner/supervised in run_common.py.
7. Golden-fixture tests pass; both harness launch paths end-to-end including smoke mode.
