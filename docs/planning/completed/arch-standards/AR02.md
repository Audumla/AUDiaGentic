# Split provider-internals inversion by capability seam: surface rendering, MCP projection, provider config/descriptors

## Description

Standard 1 violations: foundation/components/loader.py:264 imports components.providers.surfaces.base; runtime/lifecycle/component_mcp.py:33 imports components.providers.services.mcp_projection; runtime/lifecycle/provider_recipes.py imports components.providers.services.provider_config and components.providers.descriptors.registry. Runtime/foundation must never import a specific optional component — use registered callbacks, events, or contribution registries.

Codex review (RV60): this bundles three distinct inversion seams with different risk and bootstrap-ordering characteristics. Treat as three sequenced sub-efforts under this item rather than one atomic change, so one registry migration cannot block the others.

## Steps

1. PREREQUISITE (read-only): for each of the three lazy-import sites, determine two things and record them in the PR: (a) whether a real import cycle forced the deferral or it only guards optional-component absence; (b) whether the call needs a synchronous RETURN VALUE or only triggers an effect. The answer to (b) picks the seam: effect-only → use the existing event bus (the providers surfaces observer already subscribes to lifecycle.component.* — check whether the lazy call duplicates an event path that already fires); return-value → capability registry.
2. ONE MECHANISM, NOT THREE: add a single generic capability registry primitive in foundation, src/audiagentic/foundation/capabilities.py. SPEC (decided per RV83): module-level _REGISTRY: dict[str, Callable]; register_capability(key: str, fn: Callable) — registering an already-present key with the SAME function object is an idempotent no-op (re-import safety), with a DIFFERENT function raises make_error(prefix='VAL', component='CAP', number=1) so early imports can never silently win; get_capability(key: str) -> Callable | None. Registered keys documented in the module docstring. This is the only new registry this item introduces — do NOT create per-seam register_X/get_X modules.
3. REGISTRATION TIMING (decided per RV83): providers registers its capabilities at lifecycle-observer module import time — the same descriptor-driven mechanism (register_all_components imports modules declared as lifecycle-observer) that already wires the surfaces observer. This guarantees population before any lifecycle operation because register_all_components runs during bootstrap ahead of lifecycle ops; the bootstrap-order test in step 7 proves it.
4. Seam A — surface rendering (foundation/components/loader.py:264): providers registers under 'providers.surface-validator' from components/providers/surfaces/observer.py; loader.py resolves via get_capability and no-ops when nothing is registered.
5. Seam B — MCP projection (runtime/lifecycle/component_mcp.py:33): apply step-1(b) first — if the surfaces observer's existing lifecycle.component.* / lifecycle.component.mcp.sync subscriptions already cover the effect, delete the lazy import in favor of emitting the event and remove the duplicate path; only if a synchronous result is required, use capability key 'providers.mcp-projector'.
6. Seam C — provider config/descriptors (runtime/lifecycle/provider_recipes.py): capability keys 'providers.provider-config' and 'providers.descriptors'; migrate the existing bespoke register_provider_recipe_reconciler onto the shared registry too if it fits without contortion.
7. Each seam is one atomic commit: register from providers + replace deferred import + remove old path. Never leave both paths alive.
8. Tests: each seam with providers absent (graceful no-op) and present (registered path executes); bootstrap-order test asserting registration precedes first consumption; duplicate-key test asserting same-fn no-op and different-fn VAL-CAP-001.
