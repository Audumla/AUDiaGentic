# Per-provider surface.py boilerplate — replace with descriptor-driven renderer factory

## Description

Standards 2+3 violation: the ~11 adapters' surface.py modules are copy-paste identical except for provider name and instruction file (gemini/surface.py and qwen/surface.py differ only in the strings 'gemini'/'GEMINI.md' vs 'qwen'/'QWEN.md'). Adding a provider currently requires a new Python file. Surfaces should be produced by one parameterized factory driven by the provider descriptor (instruction-file name, launch-example template, path template), with register_renderer called during descriptor loading. Adapters with genuinely custom rendering (claude, codex, cline, opencode, aider) keep custom code only for the parts that differ.

## Steps

1. CLASSIFICATION (verify, then treat as the deletion list): pure-template surfaces expected — gemini, qwen, copilot, roo, plandex, openhands, goose, local_openai; custom — claude, codex, cline, opencode, aider. Verify by diffing each surface.py against gemini/surface.py with provider-name normalization (same technique as the AR12 adapter diff); any file whose normalized diff is empty is pure-template. Record the final classification in the PR.
2. SCHEMA (coordinate with AR12 — one descriptor-schema pass): add a `surfaces:` block to the provider descriptor YAML with fields: instruction-file (e.g. GEMINI.md), launch-example-template (e.g. "@{tag}-{provider_id}"), contribution-file (single-file contribution target, usually same as instruction-file). Document the block in the descriptor schema alongside AR12's execution block.
3. Implement make_standard_surface_renderer(descriptor) in components/providers/surfaces/base.py returning the render function currently duplicated per adapter; call register_renderer/register_contribution_renderer for every descriptor that carries a surfaces: block during descriptor loading (module-import-time safe, matching the existing registration pattern at the bottom of each surface.py).
4. BEFORE structural changes: capture golden files — render all providers' surfaces for a fixture project and store the outputs as test fixtures.
5. Delete the pure-template surface.py files per the step-1 classification; reduce the five custom files to only their divergent logic (they may still call make_standard_surface_renderer for their standard parts).
6. Assert golden-file byte-equality for every provider; run providers test suite.

## Validation

ACCEPTANCE: (a) golden-file test proves byte-identical rendered surfaces for every provider before/after; (b) the pure-template surface.py files are deleted; (c) a new provider with only a YAML descriptor (containing a surfaces: block) gets working surface rendering with zero Python — demonstrated by a test fixture provider; (d) providers test suite passes.

## Effort & Risk

Removes ~400+ lines of duplicated Python. Risk: subtle per-provider differences hidden in the boilerplate — golden-file diff mitigates.
