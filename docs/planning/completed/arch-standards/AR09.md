# VS Code coupling in providers services/surfaces — abstract to config-driven host adapter

## Description

Standard 4 violation: editor-specific paths and concepts are hardcoded across the providers component — .vscode/extensions.json and ~/.vscode/extensions in surfaces/extensions_json.py (:27,:81,:100,:127), services/host_capabilities.py (:23,:46,:74), services/status.py (:90 'vscode_project'), services/reconcile.py, plus a vscode_extensions descriptor field consumed in providers_api.py and descriptors/registry.py. Host-specific behavior (extension installation, workspace detection) must resolve through a pluggable, config-driven host adapter so a second editor host is a config drop, not a code change.

## Steps

1. Create the host-adapter seam at src/audiagentic/components/providers/services/host_adapter.py: a HostAdapter protocol with detect_workspace(project_root) -> bool, extensions_manifest_path(project_root) -> Path, installed_extension_ids() -> list[str] | None, extension_dir() -> Path; plus get_host_adapter(host_id: str) and a registry populated from host descriptor YAML.
2. Create the host descriptor config at src/audiagentic/config/components/providers/hosts.yaml declaring the vscode host: workspace-marker (.vscode), extensions-manifest (.vscode/extensions.json), extensions-dir (~/.vscode/extensions), host-id (vscode). The adapter implementation reads these values from the descriptor — zero path literals in Python.
3. Rewrite extensions_json.py and host_capabilities.py to route every filesystem touch through the adapter; status.py's 'vscode_project' key becomes a hosts: {<host-id>: {workspace: bool}} sub-dict; reconcile.py consumes the adapter.
4. Descriptor field migration (one-shot, atomic): rename vscode_extensions → host-extensions: {vscode: [...]} in the ProviderDescriptor dataclass, descriptors/registry.py, providers_api.py, AND every provider YAML under src/audiagentic/config/components/providers/ that carries the old field (enumerate first: rg 'vscode.extensions' src/audiagentic/config). No back-compat alias; the same commit updates schema + all configs + all consumers.
5. Update tests including status-shape assertions; run providers test suite.

## Files

src/audiagentic/components/providers/surfaces/extensions_json.py; src/audiagentic/components/providers/services/host_capabilities.py; src/audiagentic/components/providers/services/status.py; src/audiagentic/components/providers/services/reconcile.py; src/audiagentic/components/providers/descriptors/registry.py; src/audiagentic/components/providers/providers_api.py

## Validation

ACCEPTANCE: (a) rg -i '\.vscode' src/audiagentic --glob '!config/**' returns zero Python matches (paths live only in hosts.yaml); (b) rg 'vscode_extensions' src/ returns zero matches; (c) status payload reports per-host capability dict; (d) providers/reconcile/status tests pass; (e) adding a second host = adding a hosts.yaml entry + one adapter registration, demonstrated by a test fixture host.

## Effort & Risk

Medium: descriptor field rename touches provider YAML configs — coordinate with descriptor doctrine (SL01).
