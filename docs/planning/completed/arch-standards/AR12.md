# Provider execution adapters: shared run pipeline + YAML-declared command construction

## Description

Standards 2+3: the per-provider execution adapters (adapters/*/adapter.py, ~8 substantial ones totalling ~1,700 lines) are structural clones. Normalizing provider names, qwen vs copilot differ by ~15 lines — only the executable name and CLI argument construction; the EventExtractor subclass, _build_prompt, _parse_*_completion, and run() scaffolding are copy-pasted. The whole run pipeline (resolve executable → build prompt → stream command → parse completion → normalize result) belongs in one shared runner in providers/services/execution.py or a new adapters/base module. Command construction is declarative: executable, args template with {model}/{prompt} placeholders, and an approval-mode→flag map can live in the provider descriptor YAML. Adapters keep Python only for genuinely custom behavior (codex packet-doc excerpts, gemini prompt tags, claude/local_openai streaming specifics).

## Steps

1. GOLDEN TESTS FIRST: before any structural change, add tests that capture for every provider adapter (a) the exact command list produced for a fixture packet/provider-config and (b) the parsed completion payload for fixture stdout samples. These fixtures are the acceptance oracle for the whole item.
2. VARIANCE INVENTORY: diff each adapter.py against qwen/adapter.py with provider-name normalization; record per provider: command construction (all differ), custom prompt handling (codex: packet-doc excerpt; gemini: prompt tags; others: none expected), custom completion parsing (verify per diff), event-extractor field mappings.
3. SCHEMA (one pass with AR03's surfaces block): add an `execution:` block to the provider descriptor YAML: executable (name resolved via require_executable), args-template (list with {model}, {prompt} placeholders), approval-mode-flags (map of permission-mode value → CLI flags, e.g. yolo: ['--yolo']), model-flag (e.g. '-m'), extractor-fields (the per-provider event-extractor mappings if they reduce to field names — verify in step 2).
4. Implement the shared pipeline in components/providers/adapters/base_runner.py (or extend services/execution.py): resolve executable → build prompt → build command from descriptor execution block → run_streaming_command → parse completion → normalize_provider_result. Hook points: build_prompt(packet_ctx, provider_cfg) and parse_completion(...) overridable per adapter; default implementations cover the common case.
5. Migrate provider by provider (each a working state): adapters with zero custom logic lose adapter.py entirely (execution.py falls back to the generic runner when no adapter module exists — update _load_runner accordingly); codex/gemini keep only their hook overrides; claude/local_openai assessed separately per their streaming specifics (they may retain full custom runners — record the decision in the PR).
6. After each provider migration, its golden tests from step 1 must pass unchanged.
