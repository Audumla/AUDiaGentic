# §11 transparency: component/feature registry accessors self-populate; delete ~25 caller-side register_all_components() priming calls; fix ledger_events.register() caller-side wiring

## Description

The rewritten §11 (Lazy Initialization: 'Transparency is mandatory... Callers never invoke a separate ensure-loaded step') and the new §12 row ('Call site must invoke a loader or check load state before using a value -> Hide laziness inside the accessor') make the codebase's dominant registry-access pattern a standards violation. Audit (2026-07-06, grep 'register_all_components()', 30 hits): production call sites explicitly prime the component/feature registries before using get_descriptor()/all_descriptors()/feature getters -- commands/component.py:24,62,97, commands/provider_prompt.py:40,77, launcher.py (agent-jobs + ledger presence checks added by CP00, plus the :48 auto-install bootstrap), runtime/harness/system_prompt.py:51, runtime/harness/mcp_collector.py:35 (both found via AR20's parallel audit, RV134), coding_lsp/language_registry.py:164, coding_lsp/runtime_resolver.py:48, ledger/ledger_bootstrap.py:27, memory/memory_mcp.py:22, project/project_mcp.py:28, providers/providers_mcp.py:24, providers/services/mcp_sync.py:29, providers/surfaces/base.py:276, providers/surfaces/contributions.py:169, providers/tags/loader.py:247, session/session_mcp.py:31, foundation/lifecycle/baseline_sync.py:43, fresh_install.py:27, uninstall.py:23, foundation/mcp/component_server.py:215,246, plus tests. DECIDED SOLUTION: (1) Make the accessors self-populating: foundation/components/registry.py get_descriptor/resolve_component_id/all_descriptors (and the features-registry getters that depend on descriptor loading) internally invoke the default-config loader on first access -- the CP02 cache guard already makes repeated invocation a cheap no-op, satisfying §11's idempotent-and-cheap rule. (2) REENTRANCY GUARD is the hard part: register_all_components() itself triggers code that calls these same accessors mid-load (observer imports subscribe and register descriptors; loader validation reads them; register_from_yaml calls register()). The self-population hook must use an in-progress flag: while loading is underway, accessors return current (partial) state without re-triggering the loader -- same-thread reentrancy only, no locking needed (registries are per-process, one profile per process per CP05). (3) Delete every caller-side register_all_components() priming call in src/ whose only purpose is populating the default registries. KEEP: explicit calls that pass config_dirs overrides (tests), and composition-root eager bootstrap where ordering is semantically load-bearing (launcher.py:48 auto-install path calls it immediately before install_component -- verify whether accessor self-population makes even that redundant; if yes, delete it too). register_all_components() remains public as the explicit-override/bootstrap entry point -- §11 bans REQUIRING callers to prime, not the existence of a bootstrap API for composition roots and tests; document this exemption in the loader docstring (composition roots may prime at boot, never defensively before individual accesses). (4) Fix the second violation class: components/release/release_api.py:74-76 explicitly calls ledger_events.register() before publishing, with an error message admitting the fragility ('ledger archive event was not handled -- ledger_events.register() may not have been called'). Move the subscription to the ledger component's lifecycle-observer self-registration path (module imported by register_all_components via its descriptor's lifecycle-observer declaration, same as memory_observer/surfaces observer), delete the caller-side register() and the apologetic error branch. Audit the sibling subscribe-once modules (agents_gateway_events.py:113, coding_lsp_bootstrap.py:105, external_mcp_probe.py:47) the same way: any register() invoked by product code at use-time is a violation; register() invoked at observer-module import time is compliant internal wiring. (5) After the sweep, verify no DOUBLE-LOADING remains in any call chain (per AR20's check): e.g. a tags accessor whose internal loader triggers register_all_components while its caller previously also primed -- with priming lines gone and the cache guard warm this should be a no-op chain, but assert it (the reentrancy test covers the pathological case).

## Effort & Risk

Complex and wide (~25 call sites + reentrancy semantics). The reentrancy guard is the risk concentrate: get too clever (locking, thread-locals) and it breaks the simple one-profile-per-process model; too naive and observer imports recurse. The in-progress-flag design above is deliberately minimal -- do not add thread synchronization without evidence it is needed. Interim state between batches is safe: accessors self-populate whether or not a caller still primes (priming becomes a redundant cheap no-op, so batches can land incrementally per §10 atomic-migration).
