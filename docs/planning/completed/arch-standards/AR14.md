# Shared implementation-status payload builder for component status hooks

## Description

Standard 3: memory_status (memory_api.py:54) and planning_status (planning_api.py:54) are ~80% identical — both do is_enabled + active-implementation resolution + implementation_config_status + the same missing_required list-comp + the same details.implementation dict; agents_api.py:238 and coding_lsp_bootstrap.py:150 are variations. Extract a foundation.features helper, e.g. implementation_status_payload(project_root, component_id, extra_details=None), so each component's status hook reduces to the helper call plus its component-specific details (item counts, gateway stats). Coordinate with CC23 (ComponentStatusPayload contract rigidity) — doing both together avoids reshaping the payload twice.

## Steps

1. DECIDED: implement together with CC23 (plan-code-cleanup) as one change — CC23 defines the typed ComponentStatusPayload contract (enabled, configured, active_implementation, missing_required, details — snake_case) in foundation/components/hooks.py and this item supplies the shared builder that makes the per-component migration mechanical. If CC23 has already landed, build against its shipped contract as-is.
2. Add to foundation/features/config_status.py: implementation_status_payload(project_root: Path, component_id: str, *, extra_details: dict[str, Any] | None = None) -> ComponentStatusPayload — encapsulating: is_enabled check, active-implementation resolution (use AR15's resolve_active_implementation if landed, else inline the precedence once here), implementation_config_status call, missing_required mapping ([{option, description}]), and details.implementation = {enabled, is_default}; extra_details merged into details.
3. Migrate the hooks: memory_api.memory_status (no extras), planning_api.planning_status (extra_details = pending/completed item counts), agents_api.agent_status, coding_lsp_bootstrap.status_payload (extra_details = missing-dependencies offer per CC23's shape), source_control_bootstrap.status_payload. Delete each hook's hand-rolled assembly in the same change.
4. Snapshot tests: capture each hook's payload before the change; after, payloads must be identical except for changes CC23 itself mandates (key renames/casing).
5. Each migrated hook body ≤ 15 lines.
