# Make MCP adapters thin, framework-isolated, and architecture-enforced

## Description

Promote the existing CREATING_A_COMPONENT guidance into a non-negotiable architecture rule: MCP modules are inbound protocol adapters only. They may translate MCP parameters/context, apply MCP transport concerns such as progress and bounded call waits, invoke the owning component's public API, and serialize the result. Domain decisions, validation policy, persistence, state transitions, dispatch, retries, provider selection, worker/service lifecycle, discovery, resource arbitration, and reusable orchestration belong behind framework-neutral API/application layers. Conversely, core/API modules must not import MCP/FastMCP or own MCP-specific constants and behavior.

## Steps

1. Add an explicit Protocol Adapter / MCP Boundary section to ARCHITECTURE_STANDARDS.md and align ARCHITECTURE_GUIDELINES.md §2 plus CREATING_A_COMPONENT.md §2/§6. 2. Define allowed adapter responsibilities: parameter/schema translation, authenticated caller/context extraction, transport timeout/progress/logging, API invocation, and result/error serialization. 3. Define forbidden responsibilities and dependency direction: *_mcp.py -> owning public *_api.py/application contract; never *_api.py/core -> MCP, and never MCP -> store/queue/dispatch/adapters/service internals. 4. Inventory current MCP modules and classify exceptions before enforcement; record bounded migrations rather than weakening the rule. 5. Add AST/import architecture checks and representative behavioral tests proving the same API is callable from MCP, CLI, events, service transport, and tests. 6. Migrate the agents gateway MCP timeout constant out of agents_gateway_api.py to the MCP/client transport boundary and remove obsolete compatibility aliases unless an approved external obligation exists.

## Validation

Architecture checks fail when an MCP module imports owning-component internals instead of its public API, when core/API imports MCP/FastMCP, or when MCP owns domain state/dispatch policy detectable by the approved rules. Existing compliant thin wrappers remain valid. Gateway timeout behavior remains covered at the transport adapter and unrestricted API callers are unaffected.

## Effort & Risk

Mid. Static import checks are straightforward; detecting logic ownership needs carefully scoped AST/rule checks plus review guidance to avoid false confidence or false positives.
