# provision_step.py: registry-based step-type factory and module split

## Description

Standards 2+3: foundation/toolchains/provision_step.py (715 lines) holds five step classes plus provision_step_from_dict, which branches if step_type == 'shell' / 'config-set' / 'managed-block' / 'write-file' — an entity-name if-chain the standards prohibit. A (step_type, constructor) registry lets components register new step types without editing foundation, and splitting the step classes into a package keeps each module focused.

## Steps

1. Create package src/audiagentic/foundation/toolchains/provision_steps/ with modules: base.py (ProvisionStep protocol, _substitute, the step-type registry: register_step_type(kind: str, from_dict: Callable[[dict, dict, ArtifactRegistry | None, str | None], ProvisionStep])), shell.py (ShellProvisionStep), config_set.py (ConfigSetStep), managed_block.py (ManagedBlockStep), write_file.py (WriteFileStep), sequence.py (CompensatingSequence), factory.py (provision_step_from_dict as pure registry lookup).
2. Each step module calls register_step_type(...) at module scope; the package __init__ imports all step modules (so import of the package populates the registry deterministically) and re-exports every name currently importable from foundation.toolchains.provision_step.
3. factory.provision_step_from_dict: keep existing behavior exactly — missing 'type' → VAL-PSTEP-001, unknown type → VAL-PSTEP-001, missing required field → VAL-PSTEP-002; per-type required-field validation moves into each step's from_dict.
4. Delete foundation/toolchains/provision_step.py in the same change; update all importers (rg 'provision_step import|from .provision_step' src/ tests/).
5. Add an extensibility test in tests/: register a dummy step type from test code, round-trip it through provision_step_from_dict, assert it constructs — proving new step kinds need no foundation edits.
6. Run toolchain/provision test suite.
