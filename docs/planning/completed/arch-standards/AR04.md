# Decompose planning_api.py (996 lines) and reuse foundation frontmatter parsing

## Description

Standard 3 violations: planning_api.py is a god object mixing (a) markdown item storage — frontmatter parse/render (_parse_frontmatter, _parse_sections, _build_body, _render_item), ID allocation, directory management/cleanup; (b) item CRUD + state transitions; (c) review CRUD + state transitions. It also re-implements frontmatter parsing that already exists in foundation/workflow/frontmatter.py, and duplicates item/review guard patterns (_ensure_not_review/_ensure_review, near-identical CRUD shapes). State-transition elif chains (planning_api.py:531, :820) should route through foundation/workflow/transitions.py.

## Steps

1. CONTRACT FREEZE: planning_mcp.py and planning_manage_mcp.py import from planning_api — those imported names and signatures are the frozen public contract. List them (rg 'from .*planning_api import' src/) before moving anything; planning_api.py remains as a facade re-exporting exactly that set.
2. Coverage check: compare planning_api._parse_frontmatter/_parse_sections/_build_body/_render_item against foundation/workflow/frontmatter.py. Extend the foundation module with any missing capability (section parsing/rendering) rather than keeping a planning-local copy; then delete the planning-local implementations.
3. Create components/planning/item_store.py: _find_item/_require_item/_next_item_id/_next_review_id/_dir_item_prefix/_check_prefix_collision/_state_dir/_remove_empty_ancestors/_remove_empty_descendants/_cleanup_empty_plan_dirs plus the frontmatter round-trip helpers (now thin wrappers over foundation.workflow.frontmatter).
4. Create components/planning/items.py (create_item/list_items/get_item/set_state/update_item/delete_item/list_items_grouped) and components/planning/reviews.py (create_review/list_reviews/get_review/set_review_state/update_review/delete_review), both consuming item_store.
5. planning_api.py shrinks to: status/config functions + facade re-exports of the frozen contract. Target: every module in components/planning under 350 lines (std 3 threshold).
6. DEFERRED (out of scope for this item): routing state validation through foundation/workflow/transitions.py — the inline _check_transition stays as-is; CC07 (state machine unification) owns that consolidation.
7. If AR05/AR15 have not landed, also extract _active_implementation_id per AR15's spec as part of this change (single resolve_active_implementation in foundation/features) and mark AR15 accordingly.
