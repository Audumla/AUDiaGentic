# Lifecycle-observer boilerplate — foundation subscription helper for component observers

## Description

Standard 3: every component lifecycle observer (memory_observer.py, providers/surfaces/observer.py, coding_lsp_bootstrap.py, source_control/ledger equivalents) re-implements the same pattern: subscribe to lifecycle.component.*, unpack project_root/component_id from payload with isinstance checks, filter to own component, then dispatch on event type via if/elif. Extract a foundation helper that owns payload validation and event dispatch.

DOCTRINE UPDATE (§1 v2) + AR19 coordination: the original rationale for moving the event-name constants out of runtime.lifecycle.observers ('components shouldn't reach into runtime internals') no longer applies — components importing runtime is legal, and AR19 moves the whole lifecycle package into foundation/lifecycle anyway. The constants move is now purely about cohesion: event names are bus vocabulary and belong in foundation/event beside the bus, regardless of where lifecycle lands.

## Steps

1. DESIGN DECISION (resolved): the event bus subscribes by event-type pattern only — topics do not encode component IDs — so component filtering cannot move into the subscription pattern. The helper therefore centralizes the filtering: subscribe_component_lifecycle(component_id: str | None, *, on_installed=None, on_enabled=None, on_disabled=None, on_uninstalled=None, on_config_changed=None) subscribes once to 'lifecycle.component.*', validates payload types (project_root: Path, component_id: str), filters to the given component_id (None = all components, for the providers surface observer), and dispatches to the matching callback with (project_root, payload, metadata).
2. DESTINATION FROZEN (per RV84 — no execution-time discovery): both the helper AND the event-name constants (COMPONENT_INSTALLED/ENABLED/DISABLED/UNINSTALLED/CONFIG_CHANGED) land in src/audiagentic/foundation/event/lifecycle_observer.py, regardless of where the lifecycle package lives when this executes. AR13 owns the constants move; AR19 must not re-move them (its observers.py move takes whatever remains). Move is no-reexport: delete the constants at their old location (runtime/lifecycle/observers.py, or foundation/lifecycle/observers.py if AR19 landed first) and re-point every importer in the same change.
3. Migrate the observers: components/memory/memory_observer.py, components/providers/surfaces/observer.py (component_id=None variant — keep the mcp.sync subscription separate since it's a different topic), components/coding_lsp/coding_lsp_bootstrap.py (_on_lifecycle_event), and any source_control/ledger equivalents found by rg "subscribe\('lifecycle" src/.
4. Delete each observer's hand-rolled unpack/filter/dispatch in the same change; handler bodies (_on_installed/_on_enabled/...) stay in their components.
5. Run lifecycle integration tests covering: surface apply/prune on install/uninstall, LSP sync on enable, hindsight reconcile on config change.
