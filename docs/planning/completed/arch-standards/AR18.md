# Relayer: dissolve runtime/state into agent_jobs; delete runtime shim modules (home.py, config/)

## Description

Doctrine realignment (Standard 1 v2) + ownership evidence: runtime/state is not a generic capability. Import graph: jobs_store.py and paths.py are consumed ONLY by the agent_jobs component (approvals, control, packet_runner, prompt_launch, records, review_launch, state_machine) plus the launcher (composition root); session_input_store.py is consumed ONLY by the launcher.

OWNERSHIP DECIDED (per RV81/RV85, settled by code inspection 2026-07-03): ALL THREE modules move to components/agent_jobs — including session_input_store, which is job-scoped through and through: persist_session_input requires a job-id (VAL-SESSION-001 without one), every file it writes lives inside the job directory (.audiagentic/runtime/jobs/<job_id>/), and build_and_persist_session_input takes a job_store parameter defaulting to jobs_store.read_job_record. Creation, retention, and cleanup of these files all belong to the job-directory lifecycle, which agent_jobs owns. Nothing moves to components/session; no cross-component coupling is created.

Also fixes intra-package duplication: jobs_store.job_dir re-implements paths.job_dir; session_input_store's session_*_path functions are pure one-line aliases of paths.py's job_* functions — both deleted in the move.

Also deletes the pure re-export shims (Standard 10): runtime/home.py (→ foundation.home), runtime/config/files.py (→ foundation.io), runtime/config/layered.py (→ foundation.config). The entire runtime/config package goes if nothing substantive remains.

## Steps

1. Move runtime/state/{paths.py, jobs_store.py, session_input_store.py} → components/agent_jobs/ (e.g. job_paths.py, job_store.py, session_input_store.py; folding job_store into the existing records.py — which already wraps validate_job_record — is acceptable if tighter). During the move: delete the duplicate job_dir in jobs_store (keep the paths.py definition) and delete the three session_*_path alias functions (callers use the job_* path functions directly — same component now).
2. _append_ndjson/_append_text stay local to the moved session_input_store module — verified 2026-07-03 they have no other consumers; do NOT promote to foundation/io (RV81#3).
3. Re-point all consumers in the same commit: the 7 agent_jobs modules (become intra-component imports), launcher.py (composition root — importing components is legal). Delete runtime/state/ entirely; no shim.
4. Delete runtime/home.py; re-point its consumers (rg -l 'runtime\.home' src/ tests/) to audiagentic.foundation.home in the same commit.
5. runtime/config deletion (ATOMIC per RV81#2): inspect runtime/config/__init__.py; enumerate ALL consumers first (rg -l 'runtime\.config' src/ tests/ — this includes runtime/lifecycle modules, which at this point still live under runtime/). Re-point every consumer — including the intra-runtime lifecycle imports — to foundation.io / foundation.config in the SAME commit that deletes the package. No commit may leave an importer pointing at a deleted module.
6. Update docs/standards/ARCHITECTURE_STANDARDS.md §1: remove runtime/state (and runtime/config if deleted) from the runtime-orchestration namespace list in the same change.
7. Full test suite.
