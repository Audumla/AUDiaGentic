# Standards reconciliation: §10 forbids the proposed compat shims; §15 redaction and §8 error-code registration missing

## Notes

Cross-checked UN01 against ARCHITECTURE_STANDARDS.md after initial authoring.

## Findings

1. §10 Migration Doctrine CONTRADICTION (must fix): UN01 as written proposes 'compat shims during migration' and turning provision_steps/ into 'deprecation re-exports'. §10 states: 'No compatibility shims, deprecations, legacy paths... unless explicitly required. Remove old code with replacement.' The migration must instead be atomic per step: each rewire lands with the old import path deleted and the full suite green, not a shim maintained across steps. §10 also mandates: on any move/rename/delete, grep the WHOLE repo including tests/ for the old dotted path as a string (patches, importlib, decorators, config/YAML); proof of completion is a green `python -m pytest tests/unit`, not grep or a partial suite.
2. §15 Output Redaction (must add): the merged ShellStep captures subprocess stdout/stderr (steps.py:181-222 and provision_steps shell.py). §15 requires redact_text() from foundation/logging/redaction.py at the structured-return boundary. Confirmed neither current shell step redacts. The unified ShellStep is the single correct chokepoint to enforce this — do it once here so every downstream recipe/dict inherits it. Use DEFAULT_REDACT_PATTERNS only; never a local regex list.
3. §8 Error Handling (must add): any new AudiaGenticError raised from the unified step/runner needs a stable PREFIX-COMPONENT-NNN code registered in the owning config/components/*/error-resolutions.yaml BEFORE use, via make_error()/make_error_factory(). Foundation-layer errors are audited too.
4. §1 Layer Boundaries (verify, not assume): the home-package decision must be validated against the architecture boundary tests for intra-foundation import direction (does foundation/toolchains importing foundation/workflow, or vice versa, violate a finer-grained test?). The step module must stay domain-neutral (no component vocabulary) — already true, keep it.
5. §3 Logic Containment: watch the 350-line / 3-responsibility limit when merging ShellStep; if the merged file exceeds it, split by concern (shell exec vs param substitution vs planning).

## Conclusion

Incorporate all five into UN01 description/steps/validation. Item 1 is a correctness fix to the migration approach, not an addition.
