# Codebase review — 1 integration gap + 1 bug found

## Notes

LSP23 is ~90% implemented but two issues remain before it can be considered complete.

### Gap: `remove_language` does not call `_sync_hook_for_language`
`lsp_config_api.remove_language()` (line 402) disables the feature, regenerates cache, shuts down sessions, and prunes provider configs — but never removes the pre-commit hook block for that language. The hook stays installed.

**Fix:** Add `_sync_hook_for_language(project_root, language, install=False)` after line 416 (before `prune_language_servers_from_providers`).

### Bug: Closing managed-block marker uses literal string instead of f-string
`git_hooks_sync._hook_body_for_language()` line 58:
```python
lines.append("# <<< audiagentic:_HOOK_BLOCK_ID:language-hooks <<<")
```
Should be:
```python
lines.append(f"# <<< audiagentic:{_HOOK_BLOCK_ID}:language-hooks <<<")
```
The opening marker on line 54 correctly uses f-string with `_HOOK_BLOCK_ID`; the closing marker does not. This breaks the managed-block mechanism — `remove_managed_block()` won't match boundaries and falls through to the manual fallback on line 203 (which also has the same literal-string issue).

Both lines 58 and 203 need f-string interpolation.
