# Two local redaction variants outside OU01 scope: component_server and prompt_context

## Notes



## Findings

Repo check 2026-07-13: foundation/mcp/component_server.py defines its own _SENSITIVE_* key set, _SECRET_PATTERNS regex, and _redact_string() for MCP tool-arg logging; components/agent_jobs/prompt_context.py defines a local _REDACTION_DENYLIST frozenset. Both duplicate the matcher/pattern role that foundation/logging/redaction.py declares it solely owns ('consumers must not define local variants'), and neither module is in OU01's file list — OU01 covers subprocess output-capture boundaries only, so this duplication is currently tracked nowhere.

## Conclusion

Extend OU01 Phase 1 with a consolidation step: migrate component_server's _redact_string/_SECRET_PATTERNS onto redact_text()/is_sensitive_key() (folding any patterns redaction.py lacks — e.g. its key-name list including stdout/stderr/input — into the shared module, not kept locally), and replace prompt_context's _REDACTION_DENYLIST membership test with is_sensitive_key() plus any prompt-specific additions contributed to SENSITIVE_KEY_PATTERN. Validation 7 ('pattern set lives in exactly one place') then genuinely holds repo-wide.
