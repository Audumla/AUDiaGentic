# OU01's fan-out landed on in-flight sites not egress boundaries, and RV328's key fold made stdout/stderr/output/input 'sensitive' — blanking diagnostics everywhere

## Notes

INCORPORATED 2026-07-16 — OU01 has been rewritten around this review and reopened; closing.

OU01's description, steps, validation, effort_risk and notes are all replaced. The new shape:
  0 baseline + inventory the ~66 sites (must name the destination each protects; most protect none)
  1 un-fold the matcher: SECRET_KEYS blanket-replaced, BULK_KEYS (stdout|stderr|output|input|prompt) content-redacted + truncated — undoes the RV328 fold
  2 make the content matcher key-preserving ('token: [REDACTED]', not '[REDACTED]')
  3 DELETE the ~60 in-flight calls OU01 v1 itself added (base_runner.finalize_run, ShellStep, CallableStep, probes, hooks, rig, agent_run, lsp_diagnostics) — the 'clear the rubbish' step
  4 enforce at the few real egress boundaries, AT THE WRITER, copying the fail-closed operational-record model
  5 close the git-managed gap (surfaces/manager.py, managed_block.py, artifact_registry.py) — new scope, highest value
  6 explicit non-goal: never redact the config-write path; comment it so nobody 'fixes' it
  7 fix the 2 stale tests to the new contract rather than to current behaviour
  8 validate, and re-run the inventory — the count must go DOWN

What OU01 v1 got RIGHT is preserved and called out: the RawLogSink disk write (v1 correctly called it 'the most impactful fix'), the local_release error paths, and the single-shared-pattern-set rule. The error was not the rule ('sole matcher / no local variants') — it was concluding that a narrow consumer's key list must therefore become universal. The fix splits the matcher by MEANING rather than forking it per consumer, which honours both v1's instinct and EDJ24's.

OU01 v1's own effort_risk note is quoted in the revision as evidence the intent was always right: 'touching only the boundary where output is persisted/surfaced, not execution logic'.

## Conclusion

Reopen OU01 with a corrected target: FEWER enforced boundaries, not more scattered calls. Four changes.\n\n1. UN-FOLD THE KEY SET (undo the RV328 over-reach). Split SENSITIVE_KEY_PATTERN in two: SECRET_KEYS (key|token|secret|password|authorization|auth) stay blanket-replaced — their values are secrets by definition. BULK_KEYS (stdout|stderr|output|input|prompt) get content-redaction via redact_text plus truncation instead of blanking. redact_text already scrubs secrets inside stdout — verified it leaves 'npm ERR! 404 Not Found: @walodayeet/hindsight-pi' completely untouched and reduces 'https://user:pw@host/api' to 'https://[REDACTED]@host/api' — so the safety property holds while diagnostics return. Keep component_server.py's tool-arg logging on the SECRET_KEYS+content path; that call site can pass BULK keys explicitly if it truly needs arg blanking.\n\n2. REDUCE TO EGRESS BOUNDARIES. Remove the ~60 in-flight redact_text calls (base_runner finalize_run, ShellStep, CallableStep, probes, hooks, rig, agent_run, lsp_diagnostics) and let values flow untouched in memory. Enforce at the destinations that actually persist or publish: RawLogSink/NormalizedEventSink disk writes (OU01 step 2 — already correctly identified as the highest-impact fix), audit log, dead-letter, operational records (done), MCP responses. Prefer REJECT-or-sanitise AT THE WRITER over redact-at-the-caller so a new caller cannot forget. Target: 66 opt-in sites -> a handful of enforced boundaries.\n\n3. CLOSE THE GIT-MANAGED GAP (new scope, highest value). Give surface/managed-block writes the same fail-closed sensitive-key check operational records already have. Durable AND shareable AND currently unguarded.\n\n4. EXPLICIT NON-GOAL: never redact the config-write path. Add a comment at the writer saying so, with the reason (config is the secret's source), or it will be 'fixed' later.\n\nTHEN fix the 2 stale tests to whatever contract 1 lands on, and make the content matcher key-preserving so 'token: sk-abc' becomes 'token: [REDACTED]' rather than losing that it was a token. Do NOT simply update those tests to current behaviour — that ratifies blanking diagnostics.\n\nOU01 validation 1 and 7 should be restated: 'every HIGH/MEDIUM-HIGH site has redaction applied' becomes 'every EGRESS boundary enforces sanitisation, and no in-flight site redacts'.
