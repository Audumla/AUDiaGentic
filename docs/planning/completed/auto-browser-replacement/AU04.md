# Monitor live multi-stage ChatGPT DOM transitions and tune evidence policies

## Description

Observe a real multi-turn SH plan review through the Agent Gateway with an independent read-only CDP monitor. Identify definitive and noisy DOM triggers for response start, active phases, completion, continuation readiness, and visible failures, then tune configured evidence policies where supported by observed evidence.

## Steps

- Capture state-transition and mutation evidence over three turns in one provider conversation.
- Compare observed signals against configured start/active/complete/failure policies and legacy state detection.
- Separate definitive, supporting, and noisy signals.
- Tune only evidence-supported policy configuration and deterministic fixtures.
- Rerun live and automated validation; record remaining unknown failure modes.

## Detailed Solution & Technical Design

A read-only CDP monitor sampled the configured gpt-auto DOM signals every 250 ms while three SH10 review prompts ran through AgentTaskFactory and the production Agent Gateway in one provider conversation. Both monitored follow-ups showed the same sequence: the prior latest-turn completion control remains during submission while stop-control appears and busy-indicator is transient; a fresh assistant turn then appears with stop-control plus streaming-indicator while text grows; completion removes all active indicators and adds completion-control within the new latest assistant turn. The existing all-of/none-of evidence policy and turn-relative assistant-fresh fact correctly prevent the previous copy control from causing a false completion. Composer editability remained true throughout and is not evidence. The completion selector was made localization-safe by relying on its latest-turn-scoped data-testid rather than an English aria-label. A separate stalled run exposed a possible sustained empty-assistant pattern but not enough evidence to promote it to an immediate failure trigger.
