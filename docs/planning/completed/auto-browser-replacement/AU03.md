# Add policy-driven DOM evidence workflows for long-running gpt-auto turns

## Description

Replace fixed gpt-auto DOM conditionals and mismatched hard ceilings with configuration-driven evidence policies for response start, activity, completion, and failure. Support hour-long responses and multi-day persistent sessions without conflating session lifetime with turn lifetime.

## Steps

- Audit the generic workflow engine for reusable policy/evidence composition capabilities.
- Inventory legacy and live ChatGPT DOM signals for accepting, active, complete, and failed response states.
- Define provider-owned configurable signal groups and conjunction/quorum policies.
- Separate response-start, activity-stall, total-response, and session-lifetime policies.
- Integrate policy evaluations as explicit workflow transitions and observations.
- Add deterministic policy/state/failure tests and live monitoring acceptance.
- Validate through the Agent Gateway and synchronize the ledger.

## Detailed Solution & Technical Design

Added a pure Foundation EvidencePolicy evaluator supporting all-of, any-of, and none-of with matched/missing/blocked diagnostics. GPT Auto owns configured DOM signal definitions (scope, selectors, visibility, optional text fragments) and four named policies: response-started, response-active, response-complete, response-failed. The turn workflow evaluates facts from atomic snapshots and uses policy results to transition, emit activity, fail closed, or begin completion stability verification. Timing is separated into submission, response-start, optional activity stall, and total response policies. Gateway outer blocking timeout now derives from the configured session-turn policy rather than a fixed 50-minute ceiling.
