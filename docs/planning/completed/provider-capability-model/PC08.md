# Refactor provider management MCP and model-source availability

## Description

Redesign the providers management MCP surface so provider activation, installation/support availability, runtime status, capabilities, catalog refresh, provider configuration refresh, and model-source management have clear ownership and consistent names. Replace overloaded mode-based tools with explicit operations and preserve provider-specific model availability.

## Steps

- Audit and rename the provider MCP tools into functional groups with consistent group_operation naming.
- Replace reconciliation terminology with provider activation policy terminology and make individual provider enable/disable first-class operations.
- Combine provider runtime, installation, update, catalog, execution, configuration, and projection state into provider_status; expose static declared support through provider_capabilities.
- Remove descriptor-list, generic repair, and direct projection mode tools from the public MCP surface while retaining internal APIs.
- Add provider_refresh(provider_id=None) to reapply managed provider configuration for one or all enabled providers without changing activation state.
- Expose provider_catalog_refresh(provider_id=None) for one/all provider catalog refreshes.
- Refactor model tools without a provider prefix: model_source desired state, model_source_catalog_refresh, model_list(provider_id, source_id=None), model_inventory, model_projection_apply, and model_vendor operations.
- Model remote-account sources as vendor/account catalogs, preserve multiple sources per vendor, and resolve effective model availability per provider rather than unioning models globally.
- Support optional apply behavior on model-source and vendor desired-state mutations while keeping desired-state-only behavior by default.
- Update MCP declarations, descriptions, generated instructions, public API wrappers, and tests.

## Detailed Solution & Technical Design

Provider activation is independent from provider installation/support availability. Activation policy is evaluated during startup/post-install reconciliation and may be used by internal maintenance flows; it does not install providers. provider_enable/provider_disable are transactional over provider feature state and provider-owned projections/managed MCP entries. provider_install/provider_uninstall/provider_update operate support availability. provider_status is the sole operational status tool and includes activation, installation, update, catalog, execution, configuration, and projection sections. provider_capabilities exposes static/declared execution modes, launch channels, automation families, connectors, host integrations, config surfaces, and limitations without secrets. provider_refresh(provider_id=None) reapplies only enabled providers and preserves unrelated user configuration. Provider catalog refresh and model-source catalog refresh are distinct. A remote-account model source is a concrete vendor/account catalog with source_id, vendor_id, connector, credentials/reference, discovery mode, filters, enabled state, and cached catalog. The same vendor can have multiple sources. model_list resolves the effective models through a target provider, preserving provider-specific subsets and reasons such as unsupported connector, credential missing, filtered, stale, or projected.

## Code Samples & Guidance

Proposed provider tools: provider_status(provider_id); provider_capabilities(provider_id); provider_enable(provider_id); provider_disable(provider_id); provider_install(provider_id); provider_uninstall(provider_id); provider_update(provider_id); provider_refresh(provider_id=None); provider_catalog_models_list(provider_id); provider_catalog_refresh(provider_id=None). ## Validation

- MCP registration contains only the revised public tool names; removed names are absent.
- provider_status returns separate activation, installation, update, catalog, execution, configuration, and projection sections.
- provider_capabilities returns declared capability data without secrets or resolved credentials.
- provider_enable/provider_disable apply and prune only provider-owned projections and managed MCP/model entries.
- provider_refresh works for one enabled provider and all enabled providers and skips disabled providers.
- provider_catalog_refresh refreshes one provider or all supported providers.
- Model-source CRUD validates model-sources.yaml and optional apply projects/prunes owned entries.
- Remote source catalogs use static/list-api/none discovery and cached data during ordinary projection.
- model_list returns provider-specific subsets for the same vendor/source; inventory does not imply universal vendor availability.
- Full provider unit and MCP contract tests pass, including generated SYSTEM/tool metadata checks.

## Effort & Risk

Large public-interface refactor touching MCP declarations, generated instructions, lifecycle orchestration, model catalog/source resolution, managed configuration, and broad tests. Main risks are breaking existing MCP callers, conflating activation with installation, and incorrectly unioning vendor models across providers. Use a breaking rename as previously selected and update all generated metadata atomically.

## Standards

Preserve provider prompt/provenance doctrine. Keep provider activation, installation/support availability, model-source desired state, catalog retrieval, and provider projection as separate concerns. Preserve managed-config ownership boundaries and never overwrite unrelated user configuration. Use the ag-planning and ag-ledger workflows for implementation and release recording.
