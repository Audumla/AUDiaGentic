# Code review: provider-resolved model availability

## Notes

Static audit of list_model_inventory(), catalog overview, provider catalogs, descriptor connectors, and model projection handlers.

## Findings

1. Current list_model_inventory() unions models by vendor across provider catalogs and only records provider-level harness presence; it cannot produce the proposed provider×source×model availability matrix.
2. No provider-source availability resolver module exists. PC13 needs a new pure/read-only resolver boundary rather than placing compatibility logic in overview.py.
3. Native provider catalogs and source catalogs have different identity/ownership semantics. Native models come from provider catalog entries; source models come from materialized source entries and provider connector renderers. The result must preserve origin and avoid deduplication by model ID alone.
4. Credential availability is currently checked through descriptor vendor_key_injection and has_ambient_value in inventory, while source api-key-ref and connector availability follow different paths. These checks need one redacted availability contract.
5. model_list(provider_id, source_id=None) has no existing public implementation and must define whether it includes native provider models, projected custom entries, disabled sources, stale caches, and unsupported entries.

## Conclusion

PC13 is the largest model refactor and needs a dedicated availability resolver/data contract plus explicit inclusion rules; the current plan is not yet code-complete.
