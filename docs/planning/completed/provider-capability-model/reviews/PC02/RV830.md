# ROI: PC01 may be sufficient; the full merge (PC02-04) is cohesion, not function — gate it

## Notes

Stepping back from the mechanics: what actually hurts today is capability_facts — the open, unenforced, mirror-prone bucket. The OTHER three 'concepts' (mcp_config, permissions, host_capabilities) are already strongly typed, already have dedicated readers/writers, and are NOT disorganized — they just happen to be separate keys. PC01 alone (executable catalogue + VAL-PCAP-009 enforcement + mirror-fact pruning in place) fixes ~80% of the original complaint: it closes the namespace, kills the dumping-ground, and gives a canonical dictionary. It does so with ZERO descriptor churn and ZERO consumer risk.

PC02-04 then spends an L-skill-3 loader rewrite + a 16-file migration + a retirement pass to buy COHESION (one block instead of four) — an aesthetic/consistency win, not a functional one. No runtime behaviour changes; no capability becomes possible that wasn't. That is real work against a soft payoff, in a multi-agent tree where the descriptor loader is high-traffic (managed-config-consistency and declarative-provisioning both touch providers/descriptors concurrently).

## Findings

Insert an explicit GO/NO-GO gate between PC01 and PC02. Ship PC01, live with it for a beat, then re-decide whether the four-into-one merge is still worth the loader rewrite + migration, or whether 'canonical catalogue + enforced ids + pruned mirrors, keeping the typed fields where they are' is the better resting point. Concretely: (1) demote PC02-04 to 'pending, gated on PC01 retro'; (2) capture the decision criteria now — e.g. proceed only if, post-PC01, there is a CONCRETE consumer that benefits from uniform iteration over capabilities (a generic capability report, a UI, a cross-provider audit) that the typed fields make awkward. If no such consumer exists, PC02-04 is polish and should not preempt higher-value work. This is not an argument to cancel the merge — it is an argument to not pre-commit to it before PC01 proves the catalogue and the real cohesion pain is measured.

## Conclusion

Recommend gating PC02-04 behind a post-PC01 go/no-go. PC01 delivers most of the value at a fraction of the risk; the merge is cohesion polish that should earn its way past a concrete consumer justification, not proceed by default.
