# SA02 — Harden `.gitignore` and tracked-file audit — COMPLETED

## Description

Cover conventional local secret and state files in `.gitignore` and identify already tracked exceptions. Based on SEC-02 from the security audit.

### Implementation summary

1. **Consolidated duplicate entries**: Removed repeated `/agent/`, `/.claude/`, `dist`, and `opencode.json` entries. Reorganized into clearly commented sections (IDE, agent working dirs, generated config, runtime state, Python build, Docker logs, node modules, archive).

2. **Added general sensitive-file protection**:
   - Environment/local: `.env`, `.env.*` (with `!.env.example`), `*.local`, `*.local.*`
   - Credentials/keys: `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, `*.crt`, `*.cer`, `credentials*.json`, `service-account*.json`, `secrets*.json/yaml/yml`, `auth.json/yaml/yml/toml`, `.netrc`, `.npmrc`, `.pypirc`
   - Local databases: `*.sqlite`, `*.sqlite3`, `*.db`, `*.db-journal`, `*.db-wal`, `*.db-shm`
   - Logs/dumps: `*.log`, `*.trace`, `*.dump`, `*.dmp`, `crash-*.txt`
   - Missing entries: `/.idea/`, `*.swp`, `*.swo`, `*~`, `*.egg`

3. **Verified patterns** — confirmed via `git check-ignore` that all sensitive patterns correctly reject test files.
4. **Tracked-file audit** — scanned 2,604 tracked files matching new patterns. Results:
   - `tests/docker/provider-lifecycle.env.example` — legitimate example file (passes via `!.env.example`)
   - `tests/docker/Dockerfile.test.local` — legitimate test fixture

### Validation criteria

- [x] Representative local-secret filenames (`.env`, `*.pem`, `*.key`, `*.sqlite`) are ignored by `git check-ignore`
- [x] No required package source is accidentally ignored (verified 2,604 tracked files)
- [x] Already tracked sensitive-looking files are classified (both are legitimate)
- [x] Duplicate entries consolidated (confirmed each pattern appears once)
- [x] `!.env.example` negation works correctly (`provider-lifecycle.env.example` still tracked)
