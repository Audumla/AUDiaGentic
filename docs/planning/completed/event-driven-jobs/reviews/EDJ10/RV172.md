# Context layer coupled to single event domain

## Notes



## Findings

Step 3 hardcodes `planning.item.*` events and `{plan_item.id}` aliases into the generic EventJobPromptContext. This tightens a generic abstraction to one event type, creating rework when other event domains (e.g. code review, release) arrive.

Keep per-event-type key injection out-of-band: EDJ01 trigger config could declare `payload_aliases` per trigger, or EDJ02 observer injects event-specific fields before context construction.

## Conclusion

Defer per-event-type specializations. Keep EventJobPromptContext generic; let trigger config or the observer layer handle domain-specific key injection.
