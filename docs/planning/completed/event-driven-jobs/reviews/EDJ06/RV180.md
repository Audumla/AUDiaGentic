# Strict missing-placeholder rejection is too aggressive for polymorphic event payloads

## Notes

Recommended: default to 'warn and skip' for missing placeholders, with an opt-in strict mode. Event payloads are inherently polymorphic across event types.

## Findings

EDJ06 step 3: 'Reject missing placeholders with AudiaGenticError.'

This means any prompt template that references `{payload.some_optional_field}` will fail if the event payload doesn't include that field. Event payloads vary by event type — `planning.item.created` may not carry the same keys as `planning.item.updated`. A trigger configured for a wildcard pattern like `planning.item.*` would need all placeholders to be present in every matching event.

The existing `workflow/actions.py` render() implementation uses typed value passthrough and does NOT reject missing placeholders — it falls back to str.format() which will raise KeyError. The new dotted-path renderer is meant to be an additive improvement, not a regression.

Options:
1. Allow `{key:default}` syntax for optional placeholders with fallback values
2. Support `{key?}` syntax that renders empty string on missing key
3. Make strict rejection opt-in (e.g., trigger-level `strict-rendering: true` flag)
4. Silently skip missing keys and log a warning

## Conclusion

SHOULD-FIX: 'Reject missing placeholders' (step 3) is too strict for event payloads where optional fields may be absent. Allow configurable fallback values or partial rendering with warnings — many event types won't carry all context keys.
