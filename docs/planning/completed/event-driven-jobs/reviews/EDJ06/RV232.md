# Renderer should become shared core, not parallel render implementation

## Notes



## Findings

EDJ06 correctly avoids changing `foundation.workflow.actions.render` semantics up front, but it still risks leaving two independent renderers with overlapping typed whole-placeholder/mixed-string/list/dict behavior. Current `workflow.actions.render` is small but established; EDJ06's new `foundation/templates.py` should be designed so `workflow.actions.render` can later delegate to it under compatibility tests.

Also avoid confusing this with `foundation.refs.resolve_ref`: refs resolves `module:object` config references, while EDJ06 resolves mapping data paths inside prompt templates. Naming/tests should make that distinction explicit.

## Conclusion

Create a follow-up consolidation item after EDJ06: migrate `workflow.actions.render` onto the shared template core only if compatibility tests stay green. This preserves safety while preventing long-term duplicate renderer behavior.
