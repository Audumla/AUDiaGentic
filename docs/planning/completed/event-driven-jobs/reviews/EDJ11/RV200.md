# Schema sync, path containment implementation, and template chain integration

## Notes



## Findings

1. **Missing touchpoint: Schema registry synchronization** — Like EDJ03 review, both `event-trigger.schema.json` (EDJ01) and `prompt-launch-request.schema.json` exist in mirror locations. EDJ11 extends both schemas with `prompt-template-file` but only lists the agent_jobs copies. The foundation copies at `foundation/contracts/schemas/` must be updated identically, or the schema registry validation will reject new fields.

2. **Missing touched file: managed defaults directory** — Step 2 defines `.audiagentic/prompts/jobs/` and `.audiagentic/prompts/jobs/events/` as managed default locations. The plan should include a step to create these directories with a `.gitkeep` file so they appear in the repository structure for discoverability.

3. **Missing impacted code: Path containment implementation** — Step 3 says 'reject resolved paths that escape project root' but does not specify the containment algorithm. Foundation may already have path utilities (check `foundation/paths.py` or similar). If not, EDJ11 must implement this with proper handling of:
   - Symlink resolution (`os.path.realpath()`)
   - Case-insensitive drive matching on Windows
   - Unicode normalization
   Add a file: `src/audiagentic/foundation/path_safety.py` or reuse from existing utility.

4. **Missing touched file: prompt_templates.py loader** — The files list includes `prompt_templates.py` but steps don't detail changes. This module currently handles inline template syntax. EDJ11 must add file loading logic alongside existing inline handling. Add explicit step to refactor `prompt_templates.py` to support both modes.

5. **Missing validation test: Template rendering integration** — EDJ11 loads templates and EDJ06 renders them. The plan should include an integration test that exercises the full chain: file load -> context build (EDJ10) -> dotted-path render (EDJ06). This ensures the three items work together correctly.

6. **Missing impacted component: Config schema versioning** — The event trigger schema has `contract-version` (const "v1"). Adding `prompt-template-file` is an additive change but changes the mutual-exclusion constraint with `prompt-template`. Ensure the schema's oneOf/dependencies constraint is updated correctly and that existing v1 configs without either field still fail as expected.

## Conclusion

Handled: schema mirror/registry sync, managed prompt dirs, path containment algorithm/utility, prompt_templates loader details, full-chain integration test, and v1 mutual-exclusion schema constraints folded into EDJ11.
