# Schema registry integration and foundation touchpoints validation

## Notes



## Findings

1. **Missing touchpoint: Schema registry integration** — The plan adds `event-trigger.schema.json` under `components/agent_jobs/contracts/` but does not mention registering the schema with `foundation/contracts/schema_registry.py`. Existing schemas (job-record, prompt-launch-request, agent-llm-record) use canonical IDs in the registry for runtime validation. Without registry integration, `validate_with_schema()` cannot be called on event-trigger payloads.

2. **Missing touchpoint: Component descriptor update** — The plan adds new files under `agent_jobs/` but does not note that `src/audiagentic/config/components/agent-jobs.yaml` must list the new module in its entry-points/members so the component lifecycle system loads event_triggers.py on initialization.

3. **Missing foundation code group: Event pattern vocabulary** — The plan references 'existing event-bus pattern vocabulary' for `event-pattern` but does not identify the defining file. Foundation's `foundation/event/lifecycle_observer.py` and `foundation/event/event_bus.py` contain the wildcard subscription logic. The trigger config should validate that its `event-pattern` conforms to the bus's accepted syntax (e.g., trailing `*` or exact match). Add `foundation/event/event_bus.py` to the files list as a read-only dependency.

4. **Missing impacted component: Ledger** — Event-triggered job launches create new job records. The ledger (`ag-ledger`) tracks change events for releases but does not record runtime job state. This is not an EDJ concern, but the plan should clarify that event-driven jobs are a new operational surface distinct from release tracking.

5. **Validation gap: `context` field shape** — Step 2 defines `context` as 'object' with no internal schema. Because EDJ10's `AgentJobPromptContext` will consume this data, the trigger config should at minimum specify that `context` values are opaque key-value pairs (no nested event dispatch). Suggest constraining to flat key-value or documented depth limit.

## Conclusion

Handled: schema registry, component descriptor, event bus syntax, context constraints folded into EDJ01. Ledger finding assessed no-action: runtime job state is distinct from release ledger.
