# Schema ownership/mirror drift not governed for event-trigger schema

## Notes



## Findings

EDJ01 creates `components/agent_jobs/contracts/event-trigger.schema.json` while also editing `foundation.contracts.schema_registry` / `canonical_ids`, whose registry loads from `foundation/contracts/schemas`. EDJ03 and EDJ11 already require component and foundation schema copies to stay synchronized for existing contracts. The plan lacks a standard or guard that states which copy is authoritative and how mirror drift is detected.

Risk: EDJ01 may add only the component schema or later schema edits may change one copy but not the other, causing runtime validation and documentation/tests to disagree.

## Conclusion

Create a separate plan item to codify schema ownership/mirror synchronization and add drift tests before EDJ01/EDJ11 expand the duplicated schema surface.
