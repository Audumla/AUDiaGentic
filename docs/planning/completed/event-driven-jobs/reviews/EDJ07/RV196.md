# Timeline ordering dependency and lifecycle event vocabulary

## Notes



## Findings

1. **Critical ordering issue: EDJ07 depends on EDJ03 but lands after** — EDJ03 (order 60) writes timeline entries via 'EDJ07's job_timeline_path helper'. EDJ07 (order 90) creates that helper. This is a backward dependency. Either:
   - Lower EDJ07 to order 50-55, before EDJ03
   - Accept that EDJ03 ships with an inline timeline path that's refactored post-EDJ07
   The current ordering means the first live timeline writes will be non-canonical.

2. **Missing touched file: agent_jobs/events.py** — Step 3 says 'publish job lifecycle events' and the files list includes `events.py`. This is a new module that must follow the pattern from `components/planning/events.py` (best-effort async publish via `get_bus().publish()`). Add step: define event topic constants (e.g., `agent.job.state.created`, `agent.job.state.completed`) in this module.

3. **Missing impacted component: Foundation observability contract** — Step 4 lists prompt assembly milestones (template-loaded, context-built, etc.) but these are not in the existing timeline event vocabulary. The `foundation/observability.py` `record_timeline_event()` accepts arbitrary event names, but should the plan define a canonical set of milestone event types? Suggest adding an enum or constant dict in the new `events.py`.

4. **Missing touched file: state_machine.py** — The files list includes `state_machine.py` but the steps don't detail what changes there. Does EDJ07 add timeline recording calls inside transition functions? If so, this affects EDJ05's outcome handler (which also transitions states and records timeline). Clarify the split: who owns timeline recording -- the state machine or the caller?

5. **Missing impacted code: control.py compatibility** — Step 5 says 'keep existing control-events compatibility if needed'. The `control.py` module currently handles job approvals and cancellation. Does it write its own log events? If so, EDJ07 should migrate those to timeline entries. Add an explicit audit step for control.py's current logging behavior.

6. **Missing validation test: Timeline file permissions** — The shared observability helper uses per-path threading locks. If multiple agent-jobs processes write to the same timeline directory (e.g., VSCode extension + CLI), file-level locking may be needed. Suggest noting this as an assumption (single-writer per job directory) in the plan.

## Conclusion

Handled: EDJ07 order moved to 55 before EDJ03; lifecycle constants, event publish pattern, state-machine timeline ownership, control.py audit, and writer assumption folded into EDJ07.
