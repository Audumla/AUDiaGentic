# metadata.job-id round-trip through gateway store to lifecycle events requires explicit cross-component contract verification

## Notes

Recommended: add an explicit integration test in EDJ04 or EDJ05 that verifies the full round-trip: publish request with metadata={job-id: 'X'} -> assert gateway lifecycle events carry metadata.correlation_id and any custom keys from the request metadata. This is an architectural boundary test across two components.

## Findings

The metadata flow required for job correlation is:

1. EDJ04 step 3: publish `agents.llm.gateway.requested` with `metadata={job-id, trigger-id, correlation_id, subject}`
2. agents_gateway_events._on_llm_requested receives the event and calls `store.create_record(..., metadata=metadata)` — line 95 in current code
3. Gateway record persists metadata (agents_gateway_store.py line 182: `"metadata": dict(metadata or {})`)
4. agents_gateway_queue publishes lifecycle events with `metadata=record.get("metadata", {})` — line 58
5. EDJ05 step 2 matches on `metadata.job-id`

The chain exists in the current codebase. However:
- EDJ04's metadata includes `job-id` which is NOT currently a field in the gateway request event contract. The existing _REQUESTED_TOPIC normalization (agents_gateway_events.py lines 63-95) extracts project-root, prompt-body, agent-profile-id, etc. — but passes remaining payload keys as-is.
- EDJ04's step 3 specifies `metadata` as a separate payload key. The event bus's publish() method has a distinct `metadata=` parameter that flows into EventEnvelope.metadata (not payload). The current _on_llm_requested handler conflates envelope metadata with payload — it reads both and merges them into the gateway record.

The risk: if the agent-jobs component publishes `job-id` in the event's `metadata` parameter but the gateway handler stores it differently than how the queue publishes lifecycle events, EDJ05 won't find `metadata.job-id` on the outcome event.

## Conclusion

MUST-FIX before EDJ04/EDJ05 implementation: metadata must round-trip through gateway store to lifecycle events, but no item verifies the contract. The chain works IF agents_gateway_events passes metadata to store.create_record and agents_gateway_queue publishes it back — confirm this contract is explicit.
