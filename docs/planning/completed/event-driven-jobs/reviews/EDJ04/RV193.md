# Gateway event contract validation and dispatch error handling

## Notes



## Findings

1. **Missing touchpoint: Gateway event payload contract** — Step 3 specifies the `agents.llm.gateway.requested` payload fields but does not cross-reference the actual subscriber in `components/agents/agents_gateway_events.py`. That module's subscription handler parses the incoming event dict into a gateway request. The plan must validate that EDJ04's published payload fields match what `agents_gateway_events` expects for normalization (e.g., does it expect `prompt-body` or `prompt_body`? What keys are required vs optional in the existing subscriber?).

2. **Missing touched file: agents_gateway_events.py subscription handler** — The files list includes `agents_gateway_events.py` but EDJ04 should NOT modify this file; it only publishes to its topic. Clarify that agents_gateway_events.py is a read-only dependency for payload contract validation, not an implementation target.

3. **Missing impacted code: Dispatch error handling** — The plan says 'job transitioned ready->running on dispatch' (step 2) but does not cover what happens if event publication itself fails (e.g., bus unavailable, no subscribers). Options:
   - Job stays `ready` and retries later
   - Job transitions to `failed` with a dispatch-failed error
   The plan should define this edge case explicitly.

4. **Missing touched file: EDJ03 job record update** — Step 4 says 'Recover the gateway request id from async lifecycle events' but the actual persistence happens in EDJ05's outcome handler, not EDJ04. EDJ04 needs to ensure the metadata.job-id is present so EDJ05 can correlate. Add validation that published event's `metadata` dict includes `job-id`.

5. **Missing validation detail: Architecture boundary test** — The validation section says 'Assert NO direct call/import of agents_gateway_api' but does not specify HOW to enforce this. Options:
   - Import graph analysis in CI
   - Monkey-patch assertion in tests
   - Architectural lint rule (e.g., import-linter)
   Suggest specifying the enforcement mechanism.

6. **Missing impacted component: Event bus async delivery** — The plan publishes `agents.llm.gateway.requested` as an event but doesn't specify delivery mode (SYNC vs ASYNC). Foundation's event bus defaults to one or the other. If ASYNC, the dispatch function returns before gateway processing begins; if SYNC, it blocks. This affects step 4 (recovering gateway request id).

## Conclusion

Handled: gateway payload contract validation, read-only agents dependency scope, publish failure behavior, metadata correlation, architecture test mechanism, and async delivery semantics folded into EDJ04.
