# Gateway event completeness and state machine integration

## Notes



## Findings

1. **Missing touchpoint: Gateway lifecycle events completeness** — Step 1 subscribes to `agents.llm.completed`, `.failed`, `.rejected`, `.cancelled` but does NOT subscribe to `agents.llm.queued` or `agents.llm.started`. The gateway publishes all six (per `agents_gateway_queue.py`). Should EDJ05 also record `queued` and `started` as timeline milestones? These are informational but useful for observability.

2. **Missing touched file: state_machine.py transition validation** — Step 3 applies transitions against the job workflow but does not specify whether to use the existing `state_machine.transition_and_persist()` or a direct state mutation. The plan says 'foundation.workflow primitives' in standards, which implies using `transition_and_persist()`. However, this function also persists to disk and writes timeline — if EDJ07's helper isn't landed yet (dependency issue from EDJ03 review), there could be duplication.

3. **Missing impacted code: Event correlation fallback** — Step 2 describes matching by `metadata.job-id` (primary) or gateway-request artifact request-id (fallback). The plan does not specify where the job-id lookup index is stored. Options:
   - In-memory dict mapping job-id -> JobRecord
   - File-based index query in jobs_store
   - Query all jobs and filter
   For performance, suggest `jobs_store.py` provides a `find_by_job_id()` or similar.

4. **Missing touched file: events.py** — EDJ07's files list includes `agent_jobs/events.py` for lifecycle event publishing. EDJ05 should also publish timeline events via the same module/helper. Clarify whether `events.py` is new (EDJ07 creates it) or existing. If new, EDJ05 depends on EDJ07 landing first.

5. **Missing validation test: Race condition handling** — The plan describes idempotency for terminal states but not for in-progress race conditions: what if two gateway events arrive simultaneously for the same job? Suggest adding a test for concurrent event processing on a single job (e.g., completed + failed arriving near-simultaneously).

6. **Missing touched component: Foundation observability** — Step 6 references 'shared observability helper' but should explicitly call out `foundation/observability.py` `record_timeline_event()` as the file to import.

## Conclusion

Handled: queued/started milestones, transition_and_persist use, lookup helpers, EDJ07 timeline dependency, concurrent outcome race handling, and observability dependency folded into EDJ05.
