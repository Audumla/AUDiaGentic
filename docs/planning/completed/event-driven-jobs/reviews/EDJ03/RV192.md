# Schema registry sync and timeline dependency sequencing

## Notes



## Findings

1. **Missing touchpoint: Schema registry synchronization** — The job-record.schema.json exists in both `src/audiagentic/foundation/contracts/schemas/` and `src/audiagentic/components/agent_jobs/contracts/`. EDJ03 extends the schema but only lists the agent_jobs copy. Plan must explicitly update the foundation copy as well, or document the mirroring strategy. Schema canonical IDs are defined in `foundation/contracts/canonical_ids.py` — any new fields require registry consistency.

2. **Missing dependency sequence: EDJ07 timeline helper** — The plan says 'adopt EDJ07's job_timeline_path helper/format' and 'EDJ03's timeline writes should adopt that helper once it lands'. This creates a build-order dependency: EDJ07 (order 90) is scheduled AFTER EDJ03 (order 60). If EDJ03 ships first, its timeline writes use an ad-hoc format. Suggest either:
   - Lower EDJ07's order to before EDJ03 (e.g., order 55), or
   - Accept a two-phase approach where EDJ03 uses a minimal inline helper then refactors post-EDJ07

3. **Missing impacted code: records.py builder extension** — The steps mention 'trigger-origin job builder (or extend prompt_launch build path)' but `records.py` has an existing `build_job_record()` factory that populates all JobRecord fields. EDJ03 must either extend this builder or create a parallel factory. If extending, the plan should list specific new kwargs: `event_source`, `launch_source.surface='event'`. The builder's type signature (`JobRecord` frozen dataclass) may need changes.

4. **Missing touchpoint: Gateway request record ownership** — The plan correctly states 'gateway request record stays in agents' but does not identify the correlation mechanism. How does EDJ04 (dispatch) return the gateway-request ID to EDJ03's artifact store? The plan says 'Store downstream gateway request id(s) as the gateway-request artifact once dispatch returns/correlates them' — this implies an async callback (EDJ05 lifecycle events), but step 5 is about timeline and step 6 is about storing. Clarify that artifact storage of gateway-request ID happens in EDJ05's outcome handler, not in EDJ03's creation path.

5. **Missing impacted component: Event envelope serialization** — The `event-source` object captures `received-at` (iso string) from the inbound event. Foundation's `EventEnvelope` has an `occurred_at` field — confirm whether `received-at` should map to `occurred_at` or represent a separate timestamp (e.g., processing latency).

## Conclusion

Handled: schema mirroring/registry sync, EDJ07 dependency sequencing, records.py builder extension, EventEnvelope timestamp mapping, and gateway artifact ownership folded into EDJ03.
