# created->ready transition is a gap between EDJ03 (sets 'created') and EDJ04 (expects 'ready')

## Notes

Simplest fix: EDJ03 sets state to 'ready' if the trigger config has everything needed for immediate dispatch. Keep 'created' only when there's a materialization gap (e.g., template not rendered yet). Alternatively, EDJ04 step 1 explicitly handles created->ready before ready->running.

## Findings

EDJ03 step 2: job is created with 'state created'.
EDJ04 step 2: 'Transition the job ready -> running at dispatch time.'

The workflows.yaml defines `created: [ready]` as the only exit from created. EDJ04 assumes the job is already in `ready` state when it attempts to transition to `running`. No item in the plan specifies who performs the `created -> ready` transition.

Possible owners:
- EDJ03 step 2 could set initial state to 'ready' instead of 'created'
- EDJ04 step 1 (render prompt) could include a created->ready transition before dispatch
- A new implicit transition in the trigger handler that creates the job and immediately moves it to ready

## Conclusion

MUST-FIX before EDJ04: EDJ03 creates jobs in 'created' state, but EDJ04's dispatch expects 'ready' state (transition: ready->running). No item specifies the created->ready transition. Add this transition to EDJ03 or EDJ04.
