# job_timeline_path defined in EDJ07 (order 90) but consumed by EDJ03 (order 60) — inverted dependency

## Notes

Recommended resolution: extract the job_timeline_path helper definition from EDJ07 into EDJ03 step 4, with EDJ07 then referencing EDJ03's canonical implementation. Alternatively, promote the helper definition to a separate lightweight item (e.g., EDJ12) ordered between EDJ03 and EDJ05.

## Findings

EDJ03 step 4 says: 'Record the first job timeline entries via foundation.observability.record_timeline_event (adopt EDJ07's job_timeline_path helper/format — do not define a second writer).'

EDJ05 step 6 similarly references the shared observability helper for timeline entries.

EDJ07 is ordered at 90, after both EDJ03 (60) and EDJ05 (80). Its notes say 'This item owns the canonical job_timeline_path helper and lifecycle-event set; EDJ03 should consume that helper rather than defining its own path/format.'

The ordering is inverted: consumers precede the definition. The implementing agent working on EDJ03 has two bad choices:
1. Block on EDJ07 (which is P2 and not a blocker per its notes)
2. Define an ad-hoc timeline path here, then refactor when EDJ07 lands — which creates exactly the duplicate writer EDJ03 says to avoid

EDJ07's own notes acknowledge: 'Overlaps EDJ03 step 3 (which writes the first job timeline entries). This item owns the canonical job_timeline_path helper...'

This is a structural ordering conflict. The job_timeline_path helper (a simple function in paths.py) does not require the broader EDJ07 observability work to be complete.

## Conclusion

MUST-FIX before EDJ03 implementation: timeline_path helper defined too late (order 90) but consumed by EDJ03 (order 60) and EDJ05 (order 80). Either move the helper definition into EDJ03 or split EDJ07's helper into its own P1 item ordered before EDJ03.
