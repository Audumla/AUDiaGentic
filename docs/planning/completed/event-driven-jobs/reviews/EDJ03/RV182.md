# No inbound event payload validation strategy — malformed events produce invalid job records

## Notes

Recommended: add a payload validation step to EDJ02 step 3 — before passing event data to the dispatcher, verify that required fields (or their defaults) are present. Log and reject events with missing provenance data rather than creating corrupt job records.

## Findings

EDJ02 step 4 says 'malformed payload handling' is in scope for validation tests, but EDJ03's job builder (step 2-3) consumes event-type, trigger-id, correlation-id, subject, and source-component from the inbound event without any validation contract.

The current event bus delivers whatever payload the publisher emits. If `planning.item.created` events carry `{subject: {kind, id}}` but another component publishes `planning.item.updated` with a flat subject string, EDJ03's job builder will silently produce invalid provenance or crash on serialization.

No EDJ item specifies:
1. What event payload shape is expected for each trigger pattern
2. Whether the observer should validate payload structure before creating a job
3. What happens when required provenance fields (correlation-id, subject) are missing from metadata

The validation tests in EDJ03 mention 'existing job fixtures still validate' but not 'malformed event data is rejected before job creation'.

## Conclusion

MUST-FIX before EDJ03 implementation: no inbound event payload validation strategy specified. If a malformed event (missing subject, corrupt metadata) triggers job creation, the downstream records and dispatch will carry invalid data. Define validation scope at observer boundary.
