# Observer lifecycle management and error handling touchpoints

## Notes



## Findings

1. **Missing touchpoint: Component descriptor lifecycle** — EDJ02 mentions 'registered through the component descriptor lifecycle observer mechanism' but does not specify which file defines the registration. The file list includes `config/components/agent-jobs.yaml` but the steps don't detail what YAML fields change (e.g., adding a new `lifecycle-observer` entry). Add explicit step: update `agent-jobs.yaml` to register the observer class in the component lifecycle.

2. **Missing impacted code group: Event bus subscription management** — The plan says 'subscribe to enabled patterns' but does not address subscription lifecycle. If event triggers are reloaded (hot-reload, restart), are stale subscriptions cleaned up? Foundation's `event_bus.py` exposes `unsubscribe()` — the observer should manage subscription handles and clean up on re-registration.

3. **Missing touchpoint: Error handling and logging** — Step 4 says 'handler failures should log and publish/record rejection outcomes' but does not specify:
   - Which structured log to use (`foundation/event/event_log.py` `StructuredLog` vs `logging` module)
   - What event topic to publish for a rejected trigger (new topic needed: `agent.job.trigger.rejected`?)
   - Whether the failure is recorded in the job timeline (EDJ03/EDJ07) or only in logs

4. **Missing validation test: Idempotency on duplicate registration** — The validation section mentions 'idempotent registration' but does not specify what idempotency means here: same subscriptions not doubled? No-op second call? Suggest testing that calling the observer's register method twice results in the same subscription count as a single call.

5. **Missing impacted component: Planning events payload shape** — EDJ02's observer will receive `planning.item.created` events from `components/planning/events.py`. The plan should verify the event envelope structure against the real published shape: `EventEnvelope.from_dict()` produces the dict format that planning emits, and the observer must map `payload`, `metadata.correlation_id`, `metadata.subject` correctly.

## Conclusion

Handled: lifecycle descriptor registration, subscription cleanup, envelope mapping, error/log/rejection behavior, and idempotency validation folded into EDJ02.
