# Operational append helper does not fsync

## Notes



## Findings

EDJ20 step 1 requires true O(1) append with flush/fsync. src/audiagentic/foundation/observability/operational_records.py:71-76 opens in append mode and flushes twice, but never calls os.fsync(handle.fileno()). The docstring at line 41 claims flushes/fsyncs, so the implementation and standard-facing contract disagree.

Reliability impact: a process crash or OS crash after write can lose acknowledged operational sidecar records, including dead-letter entries EDJ12 relies on as durable failure evidence.

## Conclusion

Call os.fsync after flush inside the per-path lock, and add a unit test/mocked assertion so future edits cannot regress durability semantics.
