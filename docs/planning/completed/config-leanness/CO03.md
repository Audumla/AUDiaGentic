# Migrate jobs + planning state to config-driven shared workflow primitives

## Description

Move hardcoded transition tables out of agent-jobs and planning into component-local workflow YAML config files, validated through slim shared primitives in foundation/workflow. Keep components segregated (own error contracts, own storage/file moves); only the transition-table semantics live in shared foundation code. No full StateMachine/WorkflowContext ceremony for these hosts.

## Steps

1. foundation/workflow/transitions.py: load_workflow(path,kind,name) + is_known_state/transition_allowed/states_in_set/in_state_set predicates. Export from __init__.
2. Refactor StateMachine.state to reuse the predicates (dedup the inline check).
3. agent_jobs/workflows.yaml + rewrite state_machine.py to derive LEGAL_TRANSITIONS/TERMINAL_STATES from config and validate via shared predicates, preserving public API + agent-jobs error kind.
4. planning/workflows.yaml (item: pending<->completed; review: created->considered->closed) + route set_state/set_review_state validation through shared predicates, keeping file-move logic in planning.
5. Tests for foundation + jobs + planning; ledger.
