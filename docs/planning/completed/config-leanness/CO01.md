# Dedup MCP tooling config: kill central catalog, component-owned tool definitions

## Description

Optimize component YAML configs so MCP tooling definitions are lean, component-owned, and do not increase agent context unnecessarily. Eliminate the only cross-component aggregation (the auto-derived `## MCP tools` system-prompt block) and remove dead/duplicated catalogs. tool-descriptions become the single source of truth for per-tool info; server `instructions` carry only cross-tool doctrine; operating-rules doctrine moves to component contributions.

## Steps

1. Remove central catalog: derive_harness_instructions + `## MCP tools` injection in runtime/harness/system_prompt.py; drop `## MCP tools` section from pi SYSTEM.md template. Keep `## Available components`.
2. Update tests: remove derivation/drift tests in test_component_loader_ids.py; drop `MCP tools` assertion in test_dynamic_agent_config.py.
3. planning/agents/memory: delete `harness-instructions: What you can do` catalogs; trim server `instructions` to doctrine only.
4. agent-ledger/release: trim server `instructions` per-tool enumeration; keep tool-descriptions + guardrails.
5. source-control: drop `Official MCP servers` catalog; move operating-rules doctrine to contributions.
6. coding-lsp: optionally move `LSP operating rules` to contributions so it reaches agents.
7. Run unit tests; record ledger event.
