# MD-001 — Add markdown language feature descriptor + server dependency

## Description

Add Markdown as a `language` feature of the coding-lsp component. Languages are declared purely as data: a feature descriptor at src/audiagentic/config/components/coding-lsp/markdown.yaml (kind: language), mirroring the existing rust.yaml / typescript.yaml / python.yaml shape. This item covers ONLY the feature descriptor + its language-server dependency declaration. Bindings to the two implementations are MD02; tests/surfaces are MD03.

Server choice: recommend `marksman` (the de-facto standalone Markdown LSP — single binary, supports hover, document symbols, references, rename across wiki-links/headings). The implementer should confirm marksman is the right pick; the VS Code markdown language server is not cleanly distributable as a standalone binary, so it is a poor fit for the dependency model. Document the decision in the item before coding (validate_first).

## Steps

1. Confirm server choice: marksman. Verify probe + install channels exist before writing the descriptor (marksman is distributed via GitHub releases; brew `marksman`, scoop `marksman`; winget availability must be checked). If a channel is missing, use the `via:` + `platform-fallback:` pattern from agent-lsp.yaml (GitHub release download script) rather than inventing a package name.
2. Create src/audiagentic/config/components/coding-lsp/markdown.yaml:
   type: feature / contract-version: v1 / parent: coding-lsp / kind: language / id: markdown
   display-name: Markdown (marksman)
   language-id: markdown
   server: command: [marksman, server]  (confirm the exact stdio invocation marksman expects)
   server.file-extensions: [.md, .markdown]
   server.workspace-config-files: []  (marksman uses .marksman.toml — include if applicable)
   detection-markers: []  (markdown has no canonical project marker; leave empty or use README.md cautiously — decide and document, since a too-broad marker would auto-suggest the language in every repo)
   dependencies.marksman: display-name, probe: binary:marksman (or command:marksman --version), toolchain/package or via/platform-fallback per step 1
   options-schema.server-settings: {type: object, default: {}}  (match siblings)
3. Cross-check field names against rust.yaml/typescript.yaml so the loader (foundation/features/loader.py load_feature_from_yaml) parses it without VAL-FDESC errors.
4. Do NOT add bindings here — without a binding for the active implementation the language is declared but not wired; that is MD02. Note this in the item so the feature is not expected to work standalone yet.

## Validation

1. register_all_components() loads with no VAL-FDESC-* errors; the markdown FeatureDescriptor appears in the feature registry under key (coding-lsp, language, markdown).
2. Decision on detection-markers + server command is written into the item notes/description before implementation.
3. Dependency probe resolves correctly when marksman is/ isn't installed (probe returns false when absent). Validate install path in the Docker image, not the host.

## Effort & Risk

Low. Risk: wrong marksman stdio invocation or install channel — mitigate by confirming against marksman docs in step 1. Risk: over-broad detection-marker auto-enabling markdown everywhere — mitigate by leaving detection-markers empty unless justified.
