# MD-003 — Tests, management-surface, and docs for markdown LSP

## Description

Close out markdown LSP support: verify it surfaces through the management tools (lsp_list_languages, lsp_config_status, lsp_add_language), add regression coverage, and update any language inventory in tests/fixtures and docs. Ensures markdown behaves like a first-class language end-to-end rather than just being declared.

## Steps

1. Run lsp_list_languages (ag-lsp-mgmt) and confirm markdown appears with its default server command. Run lsp_config_status to confirm it reports installed/missing based on the marksman probe.
2. Exercise lsp_add_language('markdown') on a scratch project: confirm it enables the markdown language feature and that lsp_install_dependencies can install marksman (validate install in the Docker image, never the host).
3. Search tests/ and any fixtures for an enumerated list of supported/expected languages (e.g. parametrized language tests, snapshot of lsp.json, language_registry expectations) and add markdown so existing assertions don't go stale or, conversely, so coverage includes it.
4. Add a focused regression test: markdown feature + both bindings register; projection includes marksman when markdown enabled under ag-lsp.
5. If MD02 omitted the agent-lsp binding, assert that markdown is NOT offered under agent-lsp (mirror how python-ruff/agent-lsp absence is handled).
6. Docs: if any user-facing list enumerates supported languages (README, docs/), add markdown. The ARCHITECTURE / CREATING_A_COMPONENT doc needs no change (it already uses coding-lsp languages as the feature example).

## Files

tests/ — language enumeration + new regression test
tests/fixtures or snapshots — lsp.json / language list updates
src/audiagentic/components/coding_lsp/language_registry.py — verify (likely no change; data-driven)
docs/ — supported-language lists, if any

## Validation

1. lsp_list_languages includes markdown; lsp_config_status reflects marksman presence/absence.
2. Full test suite green including the new regression test.
3. lsp_add_language('markdown') + lsp_install_dependencies path validated in Docker.
4. No stale assertions referencing the prior language set.

## Effort & Risk

Low. Mostly verification + test additions. Risk: a hardcoded language list somewhere that silently excludes markdown — the test-search step (3) surfaces it. Depends on MD01 + MD02.
