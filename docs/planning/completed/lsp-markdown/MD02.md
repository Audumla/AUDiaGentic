# MD-002 — Bind markdown to ag-lsp and agent-lsp implementations

## Description

Wire the markdown feature (from MD01) to the coding-lsp implementations via binding descriptors. A language is only usable under an implementation that has a binding for it. Existing languages have a binding per implementation: ag-lsp.<lang>.yaml (writer-key coding-lsp.lsp-json) and agent-lsp.<lang>.yaml (writer-key agent-lsp.mcp-args). Add the markdown equivalents so markdown works under both the native ag-lsp bridge and the external agent-lsp runtime.

Note python-ruff has an ag-lsp binding but NO agent-lsp binding — confirming bindings are per-pairing and intentional. For markdown, add both unless agent-lsp cannot drive marksman (verify).

## Steps

1. Create src/audiagentic/config/components/coding-lsp/ag-lsp.markdown.yaml:
   type: binding / contract-version: v1 / parent: coding-lsp / implementation: ag-lsp / feature-kind: language / feature: markdown
   uses-dependencies: [marksman]
   projection.writer-key: coding-lsp.lsp-json
   (mirror ag-lsp.rust.yaml / ag-lsp.python.yaml exactly.)
2. Create src/audiagentic/config/components/coding-lsp/agent-lsp.markdown.yaml:
   type: binding / implementation: agent-lsp / feature-kind: language / feature: markdown
   uses-dependencies: [agent-lsp, marksman]
   projection.writer-key: agent-lsp.mcp-args
   (mirror agent-lsp.rust.yaml.)
3. Verify agent-lsp can actually launch marksman as a runtime server (its projection uses args-from-runtime-servers). If agent-lsp cannot drive marksman, omit the agent-lsp binding and document why (as python-ruff does for agent-lsp).
4. Confirm the projection writer-keys (coding-lsp.lsp-json, agent-lsp.mcp-args) are registered generators — grep for the writer-key registration so the binding doesn't reference a non-existent writer.

## Files

src/audiagentic/config/components/coding-lsp/ag-lsp.markdown.yaml — NEW binding
src/audiagentic/config/components/coding-lsp/agent-lsp.markdown.yaml — NEW binding (if agent-lsp supports marksman)
reference: ag-lsp.rust.yaml, agent-lsp.rust.yaml (shape + writer-keys)

## Validation

1. register_all_components() loads both bindings with no VAL-FDESC-* errors; BindingDescriptor keys (coding-lsp, ag-lsp, language, markdown) and (coding-lsp, agent-lsp, language, markdown) present in the feature registry.
2. With ag-lsp active + markdown enabled, the generated projection (.coding-lsp/lsp.json) includes the marksman server entry. Snapshot before/after.
3. With agent-lsp active, the mcp-args projection includes marksman (or binding intentionally absent + documented).
4. uses-dependencies names match dependency keys declared in MD01's markdown.yaml and agent-lsp.yaml (loader validates references).

## Effort & Risk

Low. Risk: referencing a writer-key or dependency name that doesn't exist — mitigate by grepping writer-key registrations and matching dependency keys to MD01. Depends on MD01 (feature + marksman dependency must exist first).
