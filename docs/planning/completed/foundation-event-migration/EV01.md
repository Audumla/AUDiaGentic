# Delete harness.config-refresh AND harness.runtime-sync capabilities; harness subscribes to lifecycle.component.* directly and self-decides reload/refresh

## Description

foundation/lifecycle/component_mcp.py:_refresh_mcp_config_if_needed pulls get_capability('harness.config-refresh') and calls it with the return value discarded, at the exact same call sites (components.py:180,236,268) where fire_post_install/uninstall/enable/disable already publish lifecycle.component.installed/uninstalled/enabled/disabled on the generic event bus (observers.py). This is the same 'something happened, an optional listener reacts' problem solved twice for the identical transition -- once via a genuinely decoupled event (which components/providers/surfaces/observer.py already consumes) and once via a capability-lookup workaround. SCOPE EXPANDED (2026-07-05): the same reasoning eliminates harness.runtime-sync too. foundation/lifecycle/components.py:_component_result (100-110) pulls get_capability('harness.runtime-sync') to compute a reload/refresh advisory and embeds it in the CLI JSON response under 'sync' -- but nothing ever reads that field back (confirmed by tracing every caller), so it was never a real synchronous need, just dead output. Once the harness subscribes to lifecycle.component.* directly (this item), its subscriber handler runs synchronously (SYNC dispatch mode) inside fire_post_install/etc, before _component_result even executes -- meaning the harness already has everything (reason, component_id, its own target-specific pi/opencode logic, its own MCP-server declarations) to decide the reload/refresh action itself, with no need for foundation to ask and relay the answer back. Once plan foundation-interaction/FI01-FI02 land, the harness's own subscriber can call foundation.interaction.ask(...) directly to surface/answer the question and trigger request_runtime_reload on its own -- entirely self-contained inside runtime/harness, matching the surfaces/observer.py pattern. This removes the last of the six original foundation capabilities that looked legitimate -- none of them were.
