# Interim behavior between EV01 and FI05 unspecified; subscription registration point must preserve import-time parity

## Notes



## Findings

Two gaps. (1) EV01 lands well before FI01/FI02/FI05 (per agreed ordering: EV01 is 5th in its plan; FI05 is last overall). Step 2 says the harness subscriber 'computes the reload/refresh action directly', but no step says what the subscriber DOES with the computed action until FI05 wires foundation.interaction.ask() — the item deletes the old advisory output ('sync' field) without stating the replacement interim contract. An implementing agent could invent a blocking prompt, drop the information silently, or leave dead code. Since the old field was confirmed dead output, the correct interim behavior is presumably 'log the computed action (and perform the config refresh), take no reload action' — but that must be stated. (2) Related: validation bullet 2 ('correct reload/refresh action determination') is unobservable unless the interim behavior produces something assertable (a log record or a return value on the subscriber) — specify the observable. (3) Today's capabilities are registered at runtime/harness/__init__.py module import time (lines 209-216, deliberately at EOF); the replacement lifecycle.component.* subscription must likewise happen at import time of runtime/harness — not inside a harness-launch path — or headless/CLI installs that import the harness module but never launch it will lose the config-refresh behavior that capability lookup provides today. Worth an explicit step so the parity constraint isn't lost. Verified: fire_post_install (components.py:179) does run before _component_result (181) and the event bus defaults to SYNC dispatch, so the item's synchronous-ordering claim holds.

## Conclusion

Add a step stating the interim contract (subscriber performs refresh + logs the computed reload/refresh action; no user-facing ask until FI05), make validation bullet 2 assert on that observable, and add a step pinning subscription registration at module import time to match the current capability-registration activation semantics.
