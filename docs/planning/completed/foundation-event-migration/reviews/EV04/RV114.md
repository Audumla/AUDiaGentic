# Anti-pattern-table-only fix wasn't durable; needed general Rules bullets instead

## Notes



## Findings

The prior version of this item fixed the 'registered callbacks' removal by (a) striking the phrase from the sanctioned-mechanisms list and (b) adding a row to the section 12 Anti-Pattern Quick Reference table naming the specific deleted pattern (get_capability/register_capability-shaped lookups). That's under-durable: a table row keyed to this migration's specific shape would not by itself catch a future reinvention of the same trick under a different name (e.g. a new hand-rolled string-keyed service-locator module that isn't literally foundation/capabilities.py). The fix needed to be a general, positively-stated principle in section 1's normative Rules list, not just a reference-table entry describing today's instance.

## Conclusion

Rewrote as two tight, one-sentence Rules bullets: (1) prohibiting string-keyed lookup as an import-avoidance workaround, stated generally (not naming get_capability), with the events/contribution-registries/composition-root-direct-import alternatives; (2) domain-neutral naming for foundation module/function/event/registry-key names. Anti-pattern table keeps two one-line rows pointing back to these rules, per the standard's existing terse style. Also reset EV04's state from an unexplained 'completed' back to 'pending' since no actual doc edit had been made yet.
