# Backward-compat shim violates Migration Doctrine §10

## Notes

Standard reference: Section 10 'Migration Doctrine' — 'No backward compatibility shims'. Per standard, recommend either migrating all handlers in one change or dropping this item entirely.

## Findings

1. **Backward-compat shim violation**: Step 2 says 'Keep backward compat: untyped handlers still accepted'. This directly contradicts Architecture Standards Section 10 'Migration Doctrine': 'No backward compatibility shims — unless explicitly stated, we do not maintain backward compatibility.' The item should either: (a) migrate all callers simultaneously and remove untyped paths in the same change, or (b) defer entirely if the caller set is too large.

2. **Generic EventHandler complexity**: Adding `EventHandler[T]` with TypedDict per domain introduces runtime generic type checking challenges. Python's `isinstance()` doesn't support generics well. The typing benefits are compile-time only — which is fine for mypy but may surprise implementers expecting runtime enforcement.

3. **Missing scope boundary**: 'Define TypedDict per event domain' — how many domains? Lifecycle events, agents events, memory events, release events, ledger events... This could be a significant undertaking if every payload variant gets its own TypedDict. Recommend scoping to 1-2 high-value domains and leaving the rest as `dict[str, Any]`.

## Conclusion

EV12's backward-compat approach violates the Migration Doctrine §10. Should either commit to typed payloads or defer entirely.
