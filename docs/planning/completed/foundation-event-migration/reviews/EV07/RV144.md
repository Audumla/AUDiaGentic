# Missing cross-reference, config-missing behavior, and validation criteria

## Notes

Standard reference: Section 2 'Config Over Code' — if config loading is advisory with silent defaults, that contradicts the spirit of the standard. Recommend fail-fast on missing required keys.

## Findings

1. **Wrong cross-reference**: Step 2 says 'Add double-checked locking... (see EV16)' but the thread-safety item is EV10, not EV16. This is a stale reference that will mislead implementers.

2. **Config-missing behavior unspecified**: The item does not state what happens when `.audiagentic/event/config.yaml` is missing or contains invalid values. Under the 'config over code' standard, should `EventBus.__init__()` fail-fast with `AudiaGenticError`, or fall back to defaults? This determines whether config is required or advisory.

3. **Reset_bus dispatcher re-subscription is incomplete**: Step 3 mentions draining `_DISPATCHERS` before re-subscription, but doesn't specify how `_DISPATCHERS` tracks which dispatchers are already registered — a list-based tracker with `append()` and `clear()` is error-prone if subscription fails mid-way. Consider using a set or a try/finally pattern.

4. **Missing validation section**: No acceptance criteria to verify the wiring is correct.

## Conclusion

EV07 needs clarification on config-missing behavior (fail-fast vs default), correction of cross-reference, and a concrete dispatcher re-subscription strategy before it's implementable.
