# Missing unsubscribe_all(), close-after-publish semantics, and validation

## Notes

Standard reference: Section 8 'Error Handling' — a post-close publish should raise AudiaGenticError rather than silently dropping events.

## Findings

1. **Missing unsubscribe_all()**: The concrete EventBus likely has a way to remove all subscriptions for clean shutdown, but it's not on the protocol. External MQ implementations won't know this is expected. Recommend adding `unsubscribe_all()` as an optional abstract method.

2. **close() semantics unclear**: Should `close()` be idempotent? What happens if `publish()` is called after `close()`? Should it raise, silently drop, or drain the queue?

3. **Missing validation criteria**: No acceptance tests specified.

## Conclusion

EV08 is implementable as-is but would benefit from adding unsubscribe_all() and close-after-publish semantics. Validation criteria should be added.
