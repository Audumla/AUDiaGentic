# Inline validate_config_reference into loader.py; delete providers.surface-validator capability

## Description

foundation/components/loader.py:_validate_descriptors_contributions reaches validate_config_reference via get_capability('providers.surface-validator') registered in components/providers/surfaces/observer.py:32, sourced from components/providers/surfaces/base.py:44-62. The function's actual logic (config_base = _COMPONENTS_CONFIG_DIR.parent; candidate = config_base / config_path; candidate.exists()) uses only a foundation-owned constant and generic path logic -- component_id is used solely to format the warning string. It has no dependency on providers-specific knowledge and does not need to be a capability at all; it was parked in the providers component's surfaces/base.py for no structural reason and then had to be capability-wired back into foundation to be reachable from the shared bootstrap loop. This is the third instance (after EV01/EV03) of unnecessary indirection built to route around the import-direction rule for logic that was never actually component-specific. It also has a real functional bug as a side effect of being capability-gated: when providers is not installed, get_capability returns None and _validate_descriptors_contributions no-ops entirely -- silently skipping config-reference validation for EVERY component's descriptor, not just providers', since the validation loop in loader.py scans all descriptors generically for a contributions/surface-contributions:[{config:...}] shape.

## Steps

["Move validate_config_reference's body (or an equivalent plain function) directly into foundation/components/loader.py as a private helper, e.g. _validate_config_reference(config_path, component_id) -> str | None", "Replace the get_capability('providers.surface-validator') lookup and None-check in _validate_descriptors_contributions with a direct call to the new local helper", 'Delete the providers.surface-validator capability registration in components/providers/surfaces/observer.py:32', 'Delete validate_config_reference from components/providers/surfaces/base.py if nothing else in the providers component calls it directly; if something does, keep the function there but stop registering it as a foundation capability and have loader.py own its own copy/equivalent instead', "Confirm the fixed behavior: config-reference validation now runs for every component's descriptor regardless of whether the providers component is installed"]
