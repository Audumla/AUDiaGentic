# Add contained CLI MCP installation and configuration for explicitly selected harnesses

## Description

Design and implement the approved keyword CLI for listing/help and installing a declared MCP to explicitly selected existing harnesses. Current deliverable is the reviewed implementation design with concrete contracts, ownership, migration and acceptance gates; child implementation remains pending. No implicit chat launch, harness binary installation or false slim-packaging claim.

## Steps

1. MP04 pure descriptor catalogs and owner help projections.
2. MP08 syntax/help vertical slice with one existing root parser and shipped external obligations.
3. MP06 Project-owned explicit selection and full broadcast-caller migration.
4. MP07 shared reconciliation correctness plus provider-owned guarded native apply/recovery and project install orchestration.
5. MP05 actual owner configuration requirements, no speculative framework.
6. MP09 installed-wheel/protocol/native/lifecycle/architecture qualification; only then complete parent.

MP10 cross-surface rollout runs alongside these slices: tools/signatures/metadata before exposure, short generated instructions from owner contributions, native-fragment/schema/package migrations with the functional change, and installed protocol/docs parity as the final gate.

## Detailed Solution & Technical Design

Containment agreement from code-level Dev GPT review: CLI adapters translate syntax/input/results and call owning Project public API (same existing component-command pattern) or approved providers_api for provider queries. Project owns onboarding/catalog/request DTOs, project-config selection and install workflow; it may import providers_api only, never provider services/adapters/registries/serializers. Providers owns native formats/paths/capabilities/reload/ownership and native recovery, accepts data requests, and never imports requester Project or receives requester callbacks. Project is not promoted to cross-component platform API. Existing composition root wires narrow startup/lifecycle public surfaces directly; no synthetic configurable binding for a single implementation and no new service locator. Generic foundation changes limited to pure descriptor parsing and correctness of existing neutral fragment mechanisms used by MCP/hooks/plugins/models. No MCP onboarding DTO/secret-store/help framework/profile selector in foundation.

One Project-owned project-scoped desired binding model is durably committed before component lifecycle. Project subscriber and typed provider-state event converge every native exposure refresh into that resolver; old broadcast helpers/callers are removed. Bounded ownership-evidenced migration normalizes old state once; no perpetual compatibility mode. Process component-profile remains its existing single authority; no active-profile field or profile selection map. Different native payload under a profile change requires explicit reconciliation rather than silent replacement. Internal AUDiaGentic management and independent LSP ownership remain separate scopes. Existing provider-owned writes are hardened for full preflight, unowned/cross-scope collisions, raw-entry modification detection, ordered locks/revisions, byte-identical no-op and per-target recovery. Move only authoritative MCP ownership out of purgeable runtime via bounded migration; do not add a second registry or expand unrelated retention work. Shared file atomic writes do not imply cross-harness transactions.

Reuse installed application MCP entrypoints. MCP ID, managed ownership ID, component ID and module/package name remain distinct. Native installation is project-only MVP. MP02 slim/co-installable packaging remains separate. Detailed code samples and acceptance evidence live in MP04-MP09.

## Code Samples & Guidance

User-approved syntax and reviewed grammar (proposed, not implemented):
```text
audiagentic help
audiagentic mcp help
audiagentic mcp list
audiagentic harness list
audiagentic mcp install help
audiagentic mcp install ag-planning harness pi,opencode
audiagentic mcp ag-planning help
audiagentic harness pi help
audiagentic mcp -- MODULE MODULE_ARGS
```
Optional install clauses, each once after mandatory operands: project PATH, component-profile NAME, config FILE, dry-run, non-interactive, output json. A keyword consumed as a value remains a value. No describe verb, root install aliases or new single-dash flags. Preserve shipped root flags and provider passthrough. Bare management names and the item trailing-help form have explicit precedence; affected literal modules use mcp -- MODULE. One argparse root plus a single MCP REMAINDER preserves that escape; semantic validation belongs to owner APIs. See MP08 for exact parse/error gates.

## Acceptance Criteria

All approved CLI commands and contextual help implemented through owner APIs; no launcher entity-specific branches, provider-to-project dependency, product internals imports or foundation domain bleed. Help/list outside a project has no writes/network/subprocess/adapter/runtime bootstrap. Explicit MCP/harness selections persist across every native lifecycle/refresh/restart path; obsolete broadcast routes deleted. All targets preflight before mutation, true no-op bytes, foreign/user ownership safe, crash/partial recovery truthful, component profiles single-authority. Existing shipped stdio/module/flag/provider passthrough obligation documented and tested, with literal-module escape for reserved names. Installed application wheel passes real MCP protocol/planning/ledger and supported native-format qualification with exact proof levels.
