# Persist the selected process profile in generated MCP launch environment

## Notes



## Findings

Generated component MCP entries carried the project root but omitted the active component profile. A native client launched later would start its MCP under a different process profile than the explicit installation that authored its declaration. Reuse the canonical active-profile resolver in the shared component-entry builder and include the environment variable only when selected; keep base-profile output unchanged.

## Conclusion

Implement profile propagation and test that background refresh cannot switch it silently while an explicit install can update a proven owned entry.
