# Release live GPT turn after operator capture before same-session reuse

## Description

A manual terminal capture can mark a request completed while its in-memory GPT turn remains unresolved. A later request then fails preflight despite the request-owned terminal response and durable session checkpoint being cleared. Define a safe, request-correlated handoff that lets the live turn consume the exact terminal proof or safely detaches/resumes the same conversation before another prompt is admitted.

## Steps

- Trace operator completion from provider capture through request finalization, transport turn state, session memory and subsequent queue admission.
- Select a provider-neutral terminal acknowledgement or successor-session recovery that does not click Stop on an already terminal response and cannot clear a newer turn.
- Persist/observe a bounded handoff event identifying the captured request and live turn owner.
- Add same-session multi-turn regression: manual capture of terminal response, then a follow-up prompt is admitted exactly once.
- Add negative tests for stale capture, different turn, active generation and concurrent successor ownership.

## Detailed Solution & Technical Design

Accepted GPT design review req_example_231a6c6c81a2 requires both phases. Phase1: snapshot exact pre-clear checkpoint and session binding under capture CAS; persist in terminal-finalization; compare-and-clear atomically with cleared/already-cleared/superseded dispositions. Keep marker through runtime reconciliation; do not discard it when store clear returns false. Notify runtime only after releasing request/session locks. Phase2: request-scoped provider-neutral externally-captured acknowledgment validates durable operator completion, exact request/attempt/owner/checkpoint and releases only local observation (never Stop/cancel generation). Observer finally releases current_request/FIFO, then existing exact checkpoint synchronization clears matching idle memory. Skip normal provider terminal writes/retries. Durable terminal-state observation/IPC must support owner in another process. Missing runtime retains replay information; successor mismatch must never mutate newer turn. Late worker output remains CAS-fenced.
