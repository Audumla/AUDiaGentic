# Trace finding: watchdog captured a predecessor turn for a queued request

## Notes



## Findings

- - **Severity**: high
    - **Evidence**: BigCherry request req_example_06178dc57433 trace: request had unresolved-turn-pending=true, submission-proven=false, no provider binding, zero DOM signals, and no terminal response identity. CDP target DA0E1D34C17690F4A43AF01C56269B8E was on the exact BigCherry project route, not Audiagentic-v2. The separate GPT reviewer trace showed the analogous stale-response completion: req_example_6c8bf3fb5f24 was completed from operator-provider-capture using a previous turn's response.
    - **Finding**: Automatic watchdog capture treated any session-level unresolved turn as eligible evidence for the currently running request, even when unresolved-turn-id named a predecessor. Capture could therefore complete a waiting request with stale provider output.
    - **Recommendation**: Require request/turn ownership before automatic provider capture and reject capture API calls when durable unresolved-turn-id is a different request. Emit a compact trace event when watchdog capture is skipped for a foreign turn.

## Conclusion

Accepted; implementation and regression coverage added. Focused validation and exact-head review remain required.
