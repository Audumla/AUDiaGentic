# Initial provider binding writes an incomplete submission checkpoint

## Notes

Resolved by boundary filtering, exhaustive regression coverage, and two live same-session turns. Trace details are recorded on the request-owned observation journal; the finalizer's later `already-cleared` record is consistent with terminal cleanup after durable completion and is tracked separately under RV1092.

## Findings

- - **Severity**: P1
    - **Summary**: Initial provider binding accepts turn checkpoint fields before the owner-fenced prepared stage exists
    - **Evidence**: req_audiagentic_d81beed27b47 observations 1-5; fresh session ses_241aae3bd9a342bc; exact CDP page 94335CC23577E793CE63F3938ABC232C. `_publish_message_ids(strict=True)` sends scalar unresolved metadata through binding_sink before `persist_unresolved_checkpoint`; install_initial_provider_binding merges it into session metadata, so the later `prepared` update sees pending=true with no matching turn/stage and rejects CON-AGW-125.
    - **Required Change**: At the session store boundary, strip `_RECOVERY_CHECKPOINT_KEYS` from initial provider binding metadata while preserving provider identity fields. Add regression proving binding updates cannot mutate an existing checkpoint or create an incomplete one, plus live first-turn test showing prepared->dispatching->proven transitions and terminal cleanup.

## Conclusion

RESOLVED. Initial provider binding now strips every `_RECOVERY_CHECKPOINT_KEYS` field while preserving provider identity metadata, preventing binding publication from creating or mutating a partial turn checkpoint. Regression test exhaustively checks the recovery-key set. Live req_audiagentic_1e227511839f on successor session ses_ca0856bbf07c4ef3 exercised a first prompt after resume; it reached completed/success with submission-proven and a fresh, bound terminal response. A second same-session prompt req_audiagentic_0433887f6151 also reached completed/success. The exact AUDiaGentic CDP page shows the corresponding final READY review response.
