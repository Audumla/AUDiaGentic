# GPT design review: reconcile before terminal failure

## Notes



## Findings

- Existing strict two-snapshot provider capture can safely promote a failed request only when prompt/assistant identity and completion DOM evidence correlate.
- The primary integration point is _dispatch_session_request failure handling before _transition_owned_attempt(..., 'failed').
- Status reads must remain non-blocking and only expose reconciliation state/evidence.
- Safe retry requires positive proof that submission never occurred; ambiguous submissions must not replay.
- Use CAS/attempt fencing and retain reconciliation deadline/evidence across restart.

## Conclusion

Implement reconciliation before durable terminal failure; do not perform synchronous CDP work from status polling. Reuse complete_execution_from_provider with passive capture, preserve ambiguous submissions, and keep synthetic activity separate from evidence.
