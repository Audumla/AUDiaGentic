# GPT review of gateway observability, causal recovery, and compact MCP plan

## Notes

GPT review request req_cd59c5cb46d8435c completed successfully. No implementation has started.

## Findings

- P1 GA03 durability: do not reuse best-effort timeline append unchanged; lifecycle decision/action/terminal evidence must share request/session mutation fencing, with event-seq, attempt-epoch, poll-seq, monotonic elapsed, build/schema/policy digests.
- P1 GA03 dedup/privacy: coalesce unchanged polls with first/last/repeat/gap fields; use request-owned or project-keyed artifacts, cap compressed and decompressed sizes, redact prompts/responses, never capture cookies/storage/headers/tokens/network bodies, and purge artifacts with request/session data.
- P1 GA04 correlation: provenance keys are not ownership proof; retain immutable project/session binding, prompt identity, ordered prompt-assistant boundary, assistant pin/remount proof, error occurrence delta, and terminal witness correlation. CDP target replacement alone is insufficient.
- P1 GA04 continuation: distinguish provider-native retry/continue from a linked child turn; persist action intent and retry budget before side effects, and require reconciliation after crash windows. Stop disappearance remains non-terminal and inactivity is not permission to continue.
- P1 GA05 compatibility: status polling default can move to include_response=false only as a versioned compatibility change; retain explicit opt-in and canonical response retrieval. Add finite store-level pagination/cursors, preserving existing bounded diagnostics semantics.
- P1 live validation: test multiple projects concurrently through the shared CDP runtime with duplicate tabs, target replacement, virtualization, remounts, sticky controls, errors, restart, and crash windows; observation capture must not mutate focus/navigation/tabs.
- P2 analytics: define ground-truth outcome classes before measuring missed completion or false failure; use derived SQLite/Parquet for fleet analysis, not lifecycle truth.

## Conclusion

CHANGES_REQUESTED: The GA03-GA05 direction is sound, but implementation must first make durability/CAS ordering, strong request-turn correlation, continuation idempotency, privacy/purge, MCP compatibility/versioning, pagination, and shared-CDP validation explicit.
