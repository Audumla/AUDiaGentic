# Persist compact request-owned DOM and activity observation journals

## Description

Capture enough provider and gateway evidence to explain why a request progressed, stalled, failed, or completed without detection. Persist an append-only request-owned journal keyed to session, request, turn, and CDP target. Record normalized DOM signals, activity labels, state derivation inputs, error occurrences, response identity/digests, controls, and action outcomes without secrets or unbounded raw DOM.

## Steps

- Define a versioned NDJSON observation envelope with wall/monotonic timestamps, project/session/request/turn correlation, CDP target identity, poll sequence, previous/current digests, changed-field summary, DOM signals, activity labels/groups, generation/composer/stop/regenerate state, error identity, decision, action, and causal parent event.
- Instrument the CDP snapshot and GPT-auto turn/recovery boundaries so every meaningful change, error, action, terminal decision, and bounded periodic sample is recorded; deduplicate unchanged polls and separate provider activity from synthetic lease heartbeats.
- Persist optional compressed/redacted DOM or accessibility snapshots as content-addressed debug artifacts behind an explicit capture policy with size limits, retention, and redaction.
- Expose operator-only export/replay bundles joining request record, session timeline, journal, diagnostics, and provider artifacts chronologically.

## Detailed Solution & Technical Design

Use append-only NDJSON for the hot journal and content-addressed compressed blobs for opt-in detailed DOM artifacts. The envelope should carry schema_version, event_id, observed_at, monotonic_ms, project_hash, session_id, request_id, turn_id, conversation/url hash, CDP target hash, source, poll_seq, previous_digest, current_digest, changed_fields, dom_signals, activity label/group, page state, controls, response reference, error observation, decision, action, and causal_parent_event_id. Store bounded normalized text/digests by default; keep exact response text in the existing response artifact path.

## Code Samples & Guidance

Example event fields: schema_version=1, event=dom-observed, request_id, session_id, turn_id, poll_seq, current_digest, changed_fields, dom_signals, activity, page_state, decision.
