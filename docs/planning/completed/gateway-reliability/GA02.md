# Expose guarded gateway purge through API and MCP tooling

## Description

Provide an operator-facing purge capability for gateway session/request state without duplicating lifecycle deletion logic. Support dry-run inspection, refuse live/non-terminal work, and expose the existing guarded per-session purge through the public client and MCP boundary.

## Steps

- Add public application/client/remote-client contract for session purge.
- Add service operation validation and dispatch.
- Add MCP per-session purge and bulk terminal-session dry-run/purge tooling.
- Add focused unit and service tests; verify live dry-run against the gateway.
- Document that provider cloud conversation deletion remains a separate provider capability.

## Detailed Solution & Technical Design

Reuse purge_execution_session as the single destructive primitive. Add purge_execution_sessions(project_root, dry_run=True) to enumerate project-scoped sessions, report active/non-terminal blockers, and only invoke the primitive for explicitly eligible terminal sessions when dry_run is false. Keep active work fail-closed and return bounded counts/ids.
