# Full holistic diagnostics design proposal (see updated detailed_solution)

## Notes

Investigated who actually spawns configured MCP servers: AUDiaGentic never supervises them live. component_mcp_launch() (foundation/mcp/launch.py) only returns the (interpreter, -m, args) argv tuple written into mcp.json/OPENCODE_CONFIG_CONTENT -- the harness (pi/opencode), a third-party process, is what spawns and manages the JSON-RPC connection at session time. This means AUDiaGentic cannot instrument a live harness session's MCP calls from the outside; the generic '-32001'/'server unavailable' errors originate inside the harness and are opaque to us. The only place AUDiaGentic can produce first-party diagnostics is a self-owned preflight/health-check that spawns each configured server command itself (via the existing supervised_process.spawn_supervised, same primitive agents_gateway_worker.py already uses), speaks the MCP initialize handshake, and times/observes it directly -- this is a new capability, not an enhancement of something existing. Filled in a full proposal in detailed_solution covering module placement, data shape, phase-boundary detection, redaction split, and the CLI/tool entry point. Not implemented -- this is a design proposal for review, per explicit request to detail it out before building.
