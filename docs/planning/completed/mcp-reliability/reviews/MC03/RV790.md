# Executed minimal slice: preflight probe_mcp_server + diagnose_mcp_servers tool

## Notes

Per explicit direction (user confirmed hitting -32001 in practice; wants least-intrusive slice, extensible later, not a maintenance-heavy framework): built foundation/mcp/diagnostics.py's probe_mcp_server -- one function, no dataclass hierarchy. Spawns a configured server via the existing supervised_process.spawn_supervised, completes the MCP initialize handshake over stdio with a bounded timeout (thread+queue pattern for cross-platform safety), and returns {server_name, ok, phase, elapsed_ms, exit_status?, error?} with a stable error taxonomy (spawn-failed/initialize-timeout/initialize-rejected/crashed). Never includes argv/env in the result -- redaction is structural (the field just doesn't exist) rather than a scrubber needing maintenance. Wired as session_api.diagnose_mcp_servers(project_root), reading the harness's actual materialized mcp.json via the existing mcp_config_path/read_mcp_config facade (so it probes what's really configured, not a re-derived surface), and exposed as a new diagnose_mcp_servers tool on the existing ag-session-mgmt MCP server (session_mcp.py + session.yaml) rather than a new server or subsystem. 5 unit tests cover success/crash/timeout/malformed-response/spawn-failed paths, all passing. This deliberately does NOT cover tool-call-phase probing, stderr capture, or the proactive pre-write-to-config entry point described in the earlier full design (RV784) -- those remain candidate extensions if this slice proves insufficient in practice. Item stays open (this is the first slice, not full closure) but the core, previously-empty capability now exists and is usable.
