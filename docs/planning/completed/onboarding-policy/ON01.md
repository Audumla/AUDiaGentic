# Add provider reconciliation-policy setting (auto/allowlist/prompt)

## Description

New first-run reconciliation in `reconcile_provider`/`reconcile_all_providers` (src/audiagentic/components/providers/services/reconcile.py) currently auto-enables *any* provider whose CLI is found on PATH, with no way to scope which harnesses a project actually wants. Add a project-scoped `reconciliation-policy` setting owned by the `providers` component itself (not the `project` component — reconcile logic and enablement feature-state already live in `providers`, so keeping the policy there avoids a cross-component dependency per the layering doctrine).

Decision context: considered (A) policy on providers component, (B) policy on project component, (C) A plus a global user-home default. User explicitly chose A only, project-scoped, no global default — 'audiagentic project focused as much as possible, no global settings that confuse setup and execution.'

## Steps

1. Extend contracts/provider-config.schema.json with a new top-level property (sibling to `providers`):
   ```json
   "reconciliation-policy": {
     "type": "object",
     "properties": {
       "mode": {"type": "string", "enum": ["auto", "allowlist", "prompt"]},
       "allowed-providers": {"type": "array", "items": {"type": "string"}, "uniqueItems": true},
       "decided-providers": {"type": "array", "items": {"type": "string"}, "uniqueItems": true}
     },
     "required": ["mode"],
     "additionalProperties": false
   }
   ```
   `allowed-providers` is the enable set for `allowlist` mode and the accumulated yes-answers for `prompt` mode. `decided-providers` (superset of `allowed-providers`, includes explicit no-answers) lets ON03 distinguish 'never asked' from 'asked and declined' so a later new CLI on PATH is recognized as undecided while a previously-declined one is not re-enabled. Neither array is required — `mode: auto` needs neither; `set_reconciliation_policy` (step 2) is responsible for supplying them when the mode requires it, not the schema.
2. In services/config/provider_config.py add, next to the existing `is_provider_enabled`/`set_provider_enabled` pair:
   - `get_reconciliation_policy(project_root: Path) -> dict[str, Any]` — reads via `load_provider_config_lenient` (never raises, tolerates the marker file), returns `payload.get('reconciliation-policy')` if it's a dict, else the default `{"mode": "auto"}`.
   - `is_reconciliation_policy_configured(project_root: Path) -> bool` — returns whether `reconciliation-policy` was ever explicitly written (raw key present in the lenient payload), distinct from the defaulted read above. ON03's 'first run, never asked the mode question' branch depends on this distinction — `get_reconciliation_policy` alone can't express 'unset' vs 'explicitly set to auto'.
   - `set_reconciliation_policy(project_root: Path, *, mode: str, allowed_providers: list[str] | None = None, decided_providers: list[str] | None = None) -> dict[str, Any]` — validates `mode` is one of the three values (raise `AudiaGenticError` VAL-PCFG-002 otherwise, matching the existing VAL-PCFG-001 style at provider_config.py:171), loads the raw payload defensively (falsy/non-dict → `{"contract-version": "v1"}`, per the comment-only-file finding above), builds the policy dict (only include the array keys when the caller passed them, so `auto` mode round-trips as `{"mode": "auto"}` with no dangling stale lists), writes it under `payload['reconciliation-policy']`, validates the full payload against the updated schema before saving, then persists via the existing `_save_provider_config` (atomic YAML write already used by `patch_provider_config`). Returns the saved policy dict.
3. Document the new setting in components/providers/README.md: what `reconciliation-policy` controls, the three modes, and that it is project-scoped only (explicitly no global/user-home default, per the standing decision on this plan).

## Detailed Solution & Technical Design

**Assumptions validated against the current tree:**

- `providers.yaml` (src/audiagentic/components/providers/services/config/provider_config.py:52, `_providers_yaml_path`) is the only per-project providers config file, at `.audiagentic/config/runtime/providers.yaml`. It already mixes per-provider rich config (`providers:` map) with a `contract-version` header — a project-scoped `reconciliation-policy:` sibling key fits the existing shape without a new file.
- The schema (contracts/provider-config.schema.json) has no `additionalProperties: false` at the *top* level (only nested objects lock it down), so today an extra top-level key is silently accepted and unvalidated. This is the actual gap ON01 closes: add an explicit, validated `reconciliation-policy` schema block instead of relying on the permissive default.
- `load_provider_config_lenient` / `load_provider_config` already special-case the installer's comment-only marker file (`# Installation marker` → parses to `{}` → treated as `{"contract-version": "v1", "providers": {}}`, see tests/unit/providers/test_provider_config_loading.py). Any new read/write helper MUST preserve this — a policy write must not turn a not-yet-reconciled project's marker file into something that then fails the empty-file tolerance test.
- `patch_provider_config` (provider_config.py:81) has a latent gap for this same edge case: `load_yaml_file(path)` on a comment-only file returns `{}` (via `require_mapping(load_yaml_value(path, {}), ...)` in foundation/io.py:128-130), not `None`, and `{}.setdefault('providers', {})` silently produces a payload with no `contract-version`. The new `set_reconciliation_policy` must not copy this bug — seed `{"contract-version": "v1"}` explicitly whenever the loaded payload is falsy/non-dict, mirroring `load_provider_config_lenient`'s defensive check, rather than mirroring `patch_provider_config`'s.
- Enablement itself stays in feature state (`is_provider_enabled` / `set_provider_enabled`, provider_config.py:59-126) and is untouched by this item — `reconciliation-policy` is pure policy config, never enablement, so it belongs in providers.yaml, not features.yaml.
- `providers_mcp.py` shows the established MCP tool pattern (`@mcp.tool() @log_tool_call def ...(): return providers_api.xxx(project_root_from_env(), ...)`) that ON02's setter tool will follow — not part of ON01, but confirms the storage layer's function signatures should take `project_root: Path` first, matching every other helper in this module.

**What ON01 actually delivers:** schema + read/write storage only. No reconcile.py behavior change (ON02) and no interactive prompt (ON03) — this item must be safe to merge alone with zero observable behavior change, since nothing calls the new getter yet.

## Code Samples & Guidance

```python
# services/config/provider_config.py additions
_VALID_RECONCILIATION_MODES = ("auto", "allowlist", "prompt")
_DEFAULT_RECONCILIATION_POLICY: dict[str, Any] = {"mode": "auto"}


def get_reconciliation_policy(project_root: Path) -> dict[str, Any]:
    payload = load_provider_config_lenient(project_root)
    policy = payload.get("reconciliation-policy")
    if isinstance(policy, dict) and policy.get("mode") in _VALID_RECONCILIATION_MODES:
        return policy
    return dict(_DEFAULT_RECONCILIATION_POLICY)


def is_reconciliation_policy_configured(project_root: Path) -> bool:
    payload = load_provider_config_lenient(project_root)
    return isinstance(payload.get("reconciliation-policy"), dict)


def set_reconciliation_policy(
    project_root: Path,
    *,
    mode: str,
    allowed_providers: list[str] | None = None,
    decided_providers: list[str] | None = None,
) -> dict[str, Any]:
    if mode not in _VALID_RECONCILIATION_MODES:
        raise AudiaGenticError(
            code="VAL-PCFG-002",
            kind="providers",
            message="invalid reconciliation-policy mode",
            details={"mode": mode, "allowed": list(_VALID_RECONCILIATION_MODES)},
        )
    path = _providers_yaml_path(project_root)
    payload = load_yaml_file(path) if path.exists() else {}
    if not isinstance(payload, dict) or not payload:
        payload = {"contract-version": "v1"}
    policy: dict[str, Any] = {"mode": mode}
    if allowed_providers is not None:
        policy["allowed-providers"] = sorted(set(allowed_providers))
    if decided_providers is not None:
        policy["decided-providers"] = sorted(set(decided_providers))
    payload["reconciliation-policy"] = policy
    issues = validate_provider_config(payload)
    if issues:
        raise AudiaGenticError(
            code="VAL-PCFG-001",
            kind="providers",
            message="provider config failed validation",
            details={"issues": issues, "path": str(path)},
        )
    _save_provider_config(path, payload)
    return policy
```

## Validation

Extend tests/unit/providers/test_provider_config_loading.py (or a new sibling test module, e.g. test_reconciliation_policy.py, to keep the existing file focused on the marker-file tolerance regression):
- `get_reconciliation_policy` on a missing file, and on a comment-only marker file, both return the `auto` default (mirrors `test_missing_file_returns_default` / `test_empty_or_comment_only_file_is_the_same_as_no_file`).
- `is_reconciliation_policy_configured` is False for missing/marker files, True after any `set_reconciliation_policy` call.
- `set_reconciliation_policy(mode='allowlist', allowed_providers=['claude','codex'])` round-trips through `get_reconciliation_policy` and through a fresh `load_yaml_file` read of providers.yaml directly (proves it's actually persisted, not just cached).
- `set_reconciliation_policy` on a project whose providers.yaml is the comment-only install marker succeeds and the resulting file still has `contract-version: v1` (regression guard for the `patch_provider_config` gap identified above).
- `set_reconciliation_policy(mode='bogus')` raises `AudiaGenticError` with code `VAL-PCFG-002` and never touches the file (write-then-validate-then-save ordering, or validate-before-write — whichever the implementation picks, but the file must be provably unchanged on rejection).
- Schema-level: a `providers.yaml` fixture with `reconciliation-policy: {mode: bogus}` fails `validate_provider_config` (proves the schema enum, not just the Python-level check, rejects it) — add this as a `test_genuinely_invalid_config_still_fails`-style case.
- `set_reconciliation_policy(mode='auto')` (no lists passed) produces exactly `{"mode": "auto"}` with no `allowed-providers`/`decided-providers` keys — guards against stale-list leakage across mode switches.

## Notes

This item only adds storage/schema — nothing reads `get_reconciliation_policy` yet, so it ships with zero behavior change and can land independently.
