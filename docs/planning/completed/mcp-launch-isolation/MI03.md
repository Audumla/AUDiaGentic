# Define one provider-owned isolated launch-surface contract

## Description

Extend the approved `providers_api` execution seam so direct and session/ACP launches can receive concrete MCP entries and a unique request-runtime root. Providers compose their own command, environment, and ephemeral artifacts exactly once; callers never merge provider-specific configuration.

## Steps

1. Revise the MCP surface request to include concrete entries and a unique writable launch-runtime root. Keep project root for provider discovery only.
2. Represent the isolation outcome explicitly (`supported`, `exclusive`, safe mechanism/reason) and register provider-owned errors for malformed materialization or required-isolation failure.
3. Make preparation side-effect bounded and single-shot. The same prepared result supplies command arguments, environment, and any provider-owned ephemeral artifact references.
4. Add MCP entries and isolation requirement to `prepare_provider_session_transport`; use one private provider composition path for both session transport and any retained one-shot ACP operation.
5. Let each adapter combine overlapping native configuration channels internally. Generic code must not merge two values for the same environment key or assume arguments reach a bridge.
6. Define ephemeral artifact lifecycle: write atomically beneath the request root, never beneath shared project/default config; retain for the child lifetime; remove with request cleanup; never expose contents or secrets in logs/results.
7. Fail closed for internal jobs requiring isolation when the adapter returns additive-only or unsupported. Native terminal launch remains a separate durable/default path.
8. Update public exports, conformance helpers, fake providers, and architecture inventory tests; delete obsolete dual preparation routes unless an evidenced external obligation exists.

## Detailed Solution & Technical Design

The provider request contains data, not requester policy concepts:

```python
McpLaunchSurfaceRequest(
    project_root=...,
    runtime_root=...,
    entries=(...),
)
```

The caller states whether exclusivity is required at the public operation. The adapter reports facts; the provider service enforces the requested constraint and returns a completely prepared neutral transport. No Pi/OpenCode arguments, config paths, environment keys, or ACP types cross into `components.agents`.

Ephemeral artifacts are provider-owned implementation details. If cleanup metadata is required, keep it behind the prepared transport/request-runtime lifecycle rather than exposing a general artifact API to agents.

## Validation

- Preparation runs once per launch even when both args and env are needed.
- Two concurrent jobs receive different runtime paths and cannot observe or overwrite each other’s entries.
- Required isolation rejects additive/unsupported providers before child execution.
- Overlapping provider configuration channels are composed provider-locally.
- No provider adapter import or raw launch/config detail appears in agents/runtime callers.
- Secret environment values are absent from diagnostics and durable records.

## Effort & Risk

Large, central contract migration. Update all callers atomically; do not retain a second API route as a compatibility shortcut.
