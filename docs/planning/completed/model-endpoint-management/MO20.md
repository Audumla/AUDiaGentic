# Cross-harness model availability overview: one read-only introspection surface

## Description

Sponsor direction 2026-07-18: 'introspect the providers and then the models exposed'. Compose the reads that already exist into one coherent overview instead of forcing tool-by-tool assembly: enabled providers/harnesses, their execution + model-projection capability state, configured model sources (local endpoints and vendors) with enablement, cached catalog contents (with freshness), and which models are currently materialized into which harness configs. Strictly read-only, derived entirely from existing stores — no new persistence, no network (cached catalog data only), no scheduling logic.

## Detailed Solution & Technical Design

PURE COMPOSITION -- every read this item needs already exists in providers_api.py, confirmed by reading their signatures:
  - `list_providers(project_root) -> dict` (providers_api.py:734) -- delegates to services/status.py::build_provider_status(include_probes=False); enabled/installed providers + status.
  - `describe_provider(project_root, provider_id)` -- execution + launch capability state + model catalog + managed registries.
  - `list_provider_models(project_root, provider_id) -> dict` (providers_api.py:814) -- reads the cached catalog only; explicitly does NOT hit network.
  - `model_source_list(project_root) -> dict` (providers_api.py:1085) -- reads services/model_source_config.py::load_model_sources; per-source class/display-name/vendor-id/enabled state.
  - MO17's catalog freshness/vendor-grouping read -- reuse, do not reimplement freshness computation.
  - Managed-projection ownership registry contents -- model_ownership_registry(project_root) in services/catalog/models.py -- reuse its read path.

BLOCKED REASONS (corrected 2026-07-28): capability_facts on provider descriptors carry static action_needed/support_assessment fields, but PC01 is actively REMOVING the evidence-only tier from descriptors (model-local-state, model-config-projection, obs-* are being deleted as "the forbidden second registry"). MO20 must NOT depend on static descriptor facts for blocked reasons.

Instead: blocked/degraded state comes from two sources:
  1. Runtime probes via describe_provider's status field — is the CLI installed? Is the process running?
  2. Model projection status via manage_model_projection(mode='status') — are managed entries present or errored?
  Both are runtime evidence, not static declarations. This aligns with PC06's "declaration != authority; proof in owning subsystem" principle.

DESIGN: define one frozen dataclass shaped roughly:
  ProviderModelOverview:
    providers: list[ProviderOverviewRow]  # from list_providers + describe_provider per id
    sources: list[SourceOverviewRow]      # from model_source_list, each with its catalog freshness/count from the MO17 read
    materialized: list[MaterializedRow]   # provider_id, source_id, managed_id count, from the projection ownership registry read
  Each row is itself a frozen dataclass, not a raw dict -- follow the MA16/typed-contract discipline already enforced everywhere else in providers_api.py.

IMPLEMENTATION: one new providers_api.py function (e.g. `model_availability_overview(project_root) -> dict`) that calls the reads above and assembles the typed result; one new providers_mcp.py tool exposing it (AR25 boundary: the MCP tool only translates/serializes).
