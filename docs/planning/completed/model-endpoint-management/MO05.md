# Fix local-openai catalog schema validation

## Description

Isolated bug fix pulled out of MO02. local_openai/catalog.py emits status: "available" and context-window: None, but provider-model-catalog.schema.json requires status in {active,deprecated,experimental} and an integer context-window >= 1. Catalog refresh for this provider cannot persist valid output until fixed. Independently valuable and unblocks valid catalog persistence today, ahead of the larger model-endpoint work.

## Steps

1. Map normalized upstream status through an explicit table: active/available/ready/unknown-missing -> active, deprecated -> deprecated, experimental/preview -> experimental; unrecognized values default active.
2. Resolve context-window in fixed precedence: per-model upstream context-window/context_window when positive integer; provider config context-window when positive integer; otherwise conservative constant 4096 declared once in catalog.py. Never emit None/0 and never infer from model name.
3. Ensure supports-structured-output stays boolean.
4. Add a catalog validation test that the emitted payload passes provider-model-catalog.schema.json.

[CONTRACT] src/audiagentic/components/providers/contracts/provider-model-catalog.schema.json — reference only (no schema change expected)

## Validation

1. Unit test: fetched catalog validates against schema.
2. Unit test: missing/unknown upstream status maps to a valid enum value.
3. Unit test: absent context-window uses a positive-integer fallback.
4. Precedence tests cover per-model value, provider-config fallback, and exact 4096 default.
5. Invalid/boolean/zero context values cannot leak through as integers.

## Effort & Risk

Simple, low risk. Confined to one adapter + one test. No dependency on the consolidation or contract work.
