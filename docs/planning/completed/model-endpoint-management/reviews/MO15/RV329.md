# Redaction guarantees must consume foundation/logging/redaction.py, not new machinery

## Notes



## Findings

MO15 states redaction guarantees (resolved values never in logs/status/timelines/errors) without naming the existing shared primitive. foundation/logging/redaction.py already provides redact_text/redact_env_like/is_sensitive_key/summarize_structure as the repo's sole redaction module (§15, OU01 fan-out plan). An implementing agent could plausibly write local scrubbing code.

## Conclusion

Pin: MO15's defensive redaction (status output, error details, timeline attributes, contribution listings) uses foundation.logging.redaction primitives — redact_env_like for env mappings, is_sensitive_key for key filtering; any missing pattern extends DEFAULT_REDACT_PATTERNS in the shared module, never a local list. The primary guarantee remains structural (values are never PLACED in those surfaces); shared redaction is the second layer, and the canary test exercises both.
