# Anchor resolver on the existing auth-ref env: convention; migrate ad-hoc consumers

## Notes



## Findings

Repo check 2026-07-13: the env-reference convention ALREADY EXISTS — provider-config.schema.json defines auth-ref with pattern ^env:[A-Z0-9_]+$ (required when descriptor access_mode: env, e.g. roo), but its only consumer is services/health.py which checks PRESENCE, never resolves. Separately, adapters/local_openai/catalog.py hand-rolls key lookup across api-key/apiKey/api_key/OPENAI_API_KEY config keys — an ad-hoc partial resolver. MO15 as written could create a second, parallel ref convention for api-key-ref.

## Conclusion

MO15 must implement the resolver FOR the existing convention, not beside it: (1) reuse the ^env:[A-Z0-9_]+$ grammar as the v1 SecretRef syntax — auth-ref (provider-config) and api-key-ref (model-sources) are the same ref type resolved by the same function; (2) migrate local_openai's ad-hoc key lookup onto resolve_secret_ref in the same change (§10 — no parallel path left behind); (3) health.py's presence check stays but gains nothing new; (4) hindsight's inline api_key values are explicitly out of scope (different flow, noted for a future item only).
