# Status, dry-run, rollback, and collision handling are required model-sync surfaces

## Notes

Revalidated MO02 against the current MCP sync shape. The MCP service already returns config path, updated/removed entries, collisions, reload/no-op method, and action-needed text for restart-required providers. Model endpoint sync should expose at least the same operational signals.

## Findings

1. Model endpoint sync must report support mode, config path, managed model count, refresh mode, updated/removed entries, collisions, last sync result, and action-needed. 2. Dry-run must be implemented before user-global or destructive writes. 3. Removal must delete only entries recorded under `model-endpoints/<endpoint-id>` ownership ids. 4. Collision handling must distinguish unmanaged coexistence from blocking conflicts with another managed id. 5. Provider MCP exposure should wait until service tests cover update/remove/idempotency/collision behavior.

## Conclusion

Incorporated into the reference review gates. MO02 is valid with status/dry-run/rollback as required service surfaces rather than optional UX polish.
