# Notes codify 'registry is capability service, no new types' — contradicted by providers_api.py model_source_* functions and open RV412/RV414

## Notes

MO02 is Block C2 (after MA17). Its Notes lock it to the RV406 universal-registry framing that the open RV412/RV414 dispute and that the implemented code does not follow. Related MO-plan doc defects (MO07 missing step 8, MO14 dup '4.') noted here.

## Findings

1. MO02.md:54 (Notes, 'RV406 CODIFICATION') asserts 'the "capability service" IS `ProviderRecipeRegistry` — no new types. `ProviderRecipeKind.MODEL_CONFIG` already exists.' The delivered `src/audiagentic/components/providers/providers_api.py` instead provides concrete functions `model_source_add/update/remove/set_enabled` (lines 413-494), `sync_provider_models` (497-525), `list_provider_models_config`, `reload_provider_models` — not a registry dispatch, and `ProviderRecipeKind` is not used for model projection there. The Notes misdescribe the actual surface.

2. MO02.md:21-25 (steps 2-3) call for 'explicit register provider handlers' and 'Move sync/list/reload operations behind registered handlers,' but `providers_api.py` performs sync via direct `sync_managed_provider_models`/`materialize_local_endpoint_sources` calls, with no registration table for model projection. The 'explicit handler registration' the plan requires does not exist for models.

3. RV412/RV414 (both `created`) reject the universal-registry mandate and recommend the purpose-built API that MO02's own code already uses — so MO02's Notes argue against the design the program shipped. Open reviews are not reflected in MO02.

4. Minor: MO07.md steps skip from 7 to 9 (no step 8); MO14.md Validation duplicates the number '4.' (lines 41 and 42). These are MO-plan doc defects that should be corrected for plan reliability.

## Conclusion

DISSOLVED by RV412 ratification (2026-07-15). MO02 notes corrected: the model_source_*/sync_provider_models functions in providers_api ARE the sanctioned purpose-built surface RV412 endorses — not a universal registry, no new types.
