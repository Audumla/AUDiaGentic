# Connector rendering must be a registry (Std §2); wire error codes + redaction (§8/§9/observability)

## Notes

Std §2 Config Over Code prohibits if/elif chains branching on entity names (provider id, connector kind) — use a (key, handler) registry. §8 requires canonical PREFIX-COMPONENT-NNN error codes via make_error, resolution text in error-resolutions.yaml only. §9 + Observability: module logger, never log MCP args/api keys, emit durable timeline events with redaction.

## Findings

1. The connector-aware desired-entry builder must dispatch through a (connector -> renderer) registry, not if/elif on connector or provider id (§2). Add a connector_render registry module. 2. New error codes for model-endpoint ops (e.g. VAL-MEP-*, CON-MEP-*) constructed via make_error; remediation text in config/components/providers/error-resolutions.yaml (not the raised message). 3. Model-sync must emit observability timeline events and must never log api keys / base auth / MCP args (§9). 4. Any foundation-touching helper stays domain-neutral (§1). 5. Recipe/registry lazy-load via shared utility (§11).

## Conclusion

Incorporate into MO02 touch points + standards: connector renderer registry, error-code + error-resolutions wiring, timeline events with redaction. Annotate files by layer.
