# Model config needs an explicit recipe kind; env projection is not NoAutomation

## Notes

Revalidated MO02 against `providers/services/recipes.py` and `foundation/toolchains/recipe_patterns.py`. The current `ProviderRecipeKind` enum has no model-config kind yet, while `NoAutomationRecipe` is specifically a guidance-only no-op recipe returning `ABSENT` plus `action_needed`.

## Findings

1. MO02 must add an explicit model-config/model-endpoint recipe kind to the provider recipe enum or equivalent registry metadata. 2. `NoAutomationRecipe` is correct for manual, unsupported, and blocked providers, but not for automated env-projection providers such as OpenHands/Aider. 3. Env projection needs a real launch-env contribution recipe that can produce env/args/status/dry-run without creating fragment registry entries. 4. Structured-file model sync remains a thin wrapper over the MO06 shared sync core.

## Conclusion

Incorporated into the refreshed reference doc. MO02 remains valid, with the added review requirement that env-projection is automated through a dedicated launch-env recipe and `NoAutomationRecipe` is reserved for guidance-only cases.
