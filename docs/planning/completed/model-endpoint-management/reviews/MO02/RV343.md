# Renderer selection: descriptor dotted-ref callable, not a string-keyed registry

## Notes



## Findings

User direction during implementation (2026-07-13): the planned connector_render.py (format/connector -> renderer) runtime registry is a fuzzy layer — it hides a method call behind a string lookup and duplicates what descriptor refs already do declaratively. The codebase's established idiom for adapter-owned callables is a YAML dotted ref resolved at descriptor load into a typed callable field (reader/writer/remover, fetch_catalog_fn, on_lsp_enabled all work this way).

## Conclusion

Implemented as ProviderDescriptor.model_entry_renderer: Callable | None — declared in provider YAML (model_entry_renderer: "module:fn"), resolved by DescriptorSpec kind="ref" at load, called directly by services/models.py. §2 remains satisfied (dispatch is descriptor DATA, no provider-name branches) with one less indirection mechanism. connector_render.py deleted; VAL-MEP-002 now means 'provider declares model_config but no model_entry_renderer'. MO03/MO13/MO14 adapters declare their renderer refs in provider YAML instead of registering into a registry.
