# Do not mirror services/mcp.py — bind onto shared reconcile + capability recipes

## Notes

Validated fragments.py (reconcile_fragments payload is Any — reusable directly), mcp.py (_sync_managed_entries is a thin adapter), managed_mcp_registry.py (~40 lines, generic shape), recipes.py (ProviderCapabilityRecipe/Registry/Kind provide lifecycle+status+provenance+action_needed), recipe_patterns.py (NoAutomationRecipe exists; SL13 A6 removed the old generic ManagedEntryRecipe in favour of this fragment machinery), reconcile.py (_sync_provider_mcp is the trigger point), lsp_projection.py (_ACTION_HANDLERS dispatch is the events surface).

## Findings

1. MO02 proposes a standalone services/models.py mirroring mcp.py — this is a code mirror. Instead extract the shared reconcile/reload core (sync_managed_config / reload_provider_config) so MCP, LSP, and models are thin bindings. 2. The ownership registry should be one generalized ManagedFragmentRegistry parametrized by filename/top-key, not a second copy of managed_mcp_registry.py. 3. Model-endpoint management should register as a provider capability recipe (ProviderRecipeKind) to reuse status/dry_run/lifecycle/provenance. 4. Env-projection (OpenHands/Aider) and extension-storage (Cline/Roo) must NOT go through reconcile_fragments — env-projection is a launch-env capability recipe; extension-storage uses NoAutomationRecipe. 5. Trigger via a sibling _sync_provider_models in reconcile.py and register action handlers in the existing dispatch-table style. 6. local-openai catalog fix (step 6) is an isolated bug — pull it into its own item.

## Conclusion

Rewrite MO02 as: consolidate the managed-config machinery, then bind the model kind as a thin consumer + capability recipe. Remove the mirror framing and the bundled local-openai fix.
