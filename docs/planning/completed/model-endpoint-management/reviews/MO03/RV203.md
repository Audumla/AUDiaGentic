# Split structured-file vs env-projection; unresolved prerequisites are blockers not steps

## Notes

Validated adapter/config state and the mechanism taxonomy in the rewritten capability doc.

## Findings

1. First-wave mixes three mechanisms: structured-file reconcile (Pi, OpenCode, Goose, Codex, Qwen), env-projection (OpenHands), and AG-side catalog (local-openai). Only structured-file uses the fragment reconciler; OpenHands should be an env-contribution capability recipe. The item should make the mechanism explicit per adapter. 2. OpenCode path reconciliation (opencode.json vs config.json, provider vs providers) and OpenHands settings-file schema are unresolved prerequisites — they are validate-first blockers, not implementation steps. 3. Codex is user-global scope and must be consent-gated. 4. Each adapter contributes a reader/writer/remover trio to the consolidated ManagedConfigSpec, not a bespoke service.

## Conclusion

Incorporate: annotate each first-wave adapter with its mechanism + reuse vehicle, promote OpenCode/OpenHands unknowns to explicit validation gates, and reference the per-provider adapter spec blocks in the capability doc.
