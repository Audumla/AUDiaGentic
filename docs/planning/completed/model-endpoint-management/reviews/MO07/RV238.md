# Add projection-mode selection and native vendor key injection; align to collapsed remote-account class

## Notes



## Findings

MO07 assumed materialization (custom entries) as the only projection vehicle for external sources, with connection-only tied to discovery: none. Real agent providers frequently support vendors natively and only need a key injected (env var for Aider/OpenHands-style agents; config field for OpenCode-style agents) — in that mode the agent enables all the vendor's models and no filter is possible. Projection mode must be selected per (provider, vendor) from declared provider capabilities, preferring native key injection, falling back to custom entries where the connector is supported, else none. The 3-class materializer registry also collapses to remote-account per RV237 on MO01.

## Conclusion

Rework MO07 steps: single remote-account materializer; per-(provider, vendor) projection-mode selection from provider YAML declarations (never if/elif); env-mechanism key injection rides the existing launch-env contribution seam, config-mechanism key injection is a managed fragment (model-connections/<source-id>) through the normal reconciler; model-filter applied only on the custom-entry path. Verification of per-provider vendor support/key mechanisms is split out to MO09 (research deep dive).
