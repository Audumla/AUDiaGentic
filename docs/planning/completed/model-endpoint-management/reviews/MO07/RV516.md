# Add provider-owned routed model identity/introspection seam before agent scoring consumes backend model names

## Notes



## Findings

['`brutus/coder-quality-mid` is currently only exposed by `.audiagentic/config/agent-profiles.yaml` as the agent profile model_id. There is no `.audiagentic/config/model-sources.yaml` entry or cached source catalog that maps this routed name to an underlying checkpoint/runtime model, so the system can truthfully report the routed id but cannot yet assert the backend identity.', 'The existing ownership split should be preserved: `providers` owns model-source compatibility, source catalogs, endpoint/protocol qualification, provider status, and provider model config projection; `agents` owns profile selection and dispatch-time binding of provider_id + model_id. A new component would duplicate ownership unless model identity becomes a broader cross-provider observability product later.', 'The implementation should reuse `providers.services.source_catalog` for explicit refresh/cache/degraded results, `providers.services.models.MaterializedModelEntry` for provider-neutral model/source linkage, and `providers.providers_api`/`providers_mcp` for the public read surface. Do not put network probes or source catalog reads in `agents`.', 'Add a provider-owned model identity read that accepts provider_id + model_id, and optionally source_id/refresh/probe. The read should return routed_model_id, matched source/catalog facts, connector/wire facts, endpoint fingerprint, introspection support, underlying_model_id when evidence-backed, evidence tier/confidence, limitations, and action_needed. Unknown underlying identity is a valid result, not a failure.', 'Gateway/router-specific introspection must be capability/config driven, not provider-name or product-name branching. If LlamaSwap or another gateway exposes admin/config data, wire it through a registered introspector keyed by declared source/gateway capability or connector-options, not hard-coded `if llamaswap` logic.', 'Agents should consume this only through a thin public API join: e.g. `agent_profile_model_identity(profile_id, refresh=false)` and best-effort request/attempt snapshots in the agent gateway record/timeline. The persisted snapshot must be redacted, bounded, and should not trigger network calls unless explicitly requested.']

## Conclusion

Update MO07/MO02 design before implementation so remote-account/catalog sources produce not only materializable provider entries but also an auditable model identity/status surface. Start in providers, expose via MCP, then let agents snapshot/score it. This directly answers routed aliases such as `brutus/coder-quality-mid` while preserving existing architecture boundaries.
