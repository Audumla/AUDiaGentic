# Secret resolver seam is missing — hard blocker for key injection

## Notes

Step 3 is blocked on infrastructure that does not exist.

## FINDING: No provider auth/launch secret resolver exists in codebase
Grep for `api-key-ref`, `secret.*resolver`, and `auth.*resolver` returns zero hits across the src tree.

Step 3 says: 'Resolve api-key-ref only through the existing provider auth/launch secret resolver seam. If no reusable resolver exists, raise a prerequisite plan item; do not add local env parsing.'

The second sentence applies — a prerequisite must be created. Without it:
- MO07 cannot implement native env injection (step 4: 'Native env injection contributes env at provider launch')
- MO07 cannot implement config injection (step 4: 'config injection emits connectivity managed entry')
- The model-sources schema (`api-key-ref: env:OPENROUTER_API_KEY`) has no resolver to honor the `env:` or any other prefix
- Key value lifecycle (resolve at write/launch time only, never persist) cannot be enforced

## RECOMMENDATION
Create a new plan item (e.g., MO15) for 'provider secret resolution seam' before MO07 implementation. Minimum scope:
(a) A prefix-based resolver that handles `env:<VAR_NAME>` references at launch/write time
(b) Redaction guarantee: resolved values never enter fragments text, registries, status, timelines, logs, or error details
(c) Integration with the execution/launch seam so env keys are contributed to provider subprocesses
(d) If a different prefix scheme is preferred (e.g., `vault:`, `config:`), the resolver architecture must support extension without modifying MO07.
Until this prerequisite exists, MO07 step 3 and step 4 (native injection paths) cannot be implemented.
