# Consolidation is a foundation extraction mandated by Std §3/§1, not a providers-internal tidy

## Notes

Checked ARCHITECTURE_STANDARDS.md. §3 Logic Containment: 'Shared logic (2+ files) -> extract to foundation immediately' and 'Duplicate dataclasses (>80% field overlap) -> unify to one canonical type'. McpConfigSpec and LanguageServersConfigSpec are ~90% field overlap. §1: foundation must be domain-neutral; components may import foundation. reconcile_fragments already lives in foundation/toolchains.

## Findings

1. The consolidated ManagedConfigSpec + the generic ManagedFragmentRegistry + the sync/reload core belong in FOUNDATION (foundation/toolchains), domain-neutral names (ManagedConfigSpec not McpConfigSpec) — this is mandated by §3, not optional. ProviderDescriptor (component) holds the foundation type (components->foundation import is allowed). 2. §10 Migration: remove McpConfigSpec/LanguageServersConfigSpec in the SAME change (no shim, no parallel path); MCP+LSP rewired atomically, guarded by their tests. 3. §11: the generalized registry should use the shared registry utility's lazy-loader, not a hand-rolled _loaded guard. 4. Provider-scoped concerns (runtime file paths under .audiagentic/runtime/providers/) stay in the component as a thin instance of the foundation registry.

## Conclusion

Retarget MO06 touch points: foundation gets ManagedConfigSpec/ManagedFragmentRegistry/sync_managed_config; providers/services + descriptors become thin bindings with old types deleted. Annotate each file by layer.
