# MO20 code review — capability alignment and scope gaps

## Notes

Reviewing MO20 against live codebase, checking capability system alignment.

## Findings

FINDING 1 — `model_availability_overview` does not exist. MO20 is entirely unimplemented.

FINDING 2 — Capability system alignment: the `model` domain has 6 capabilities in _capabilities.yaml (model-config, model-catalog-refresh, model-connectors, model-local-state, model-credentials, model-config-projection). MO20's plan references 'MA19 capability facts including blocked-evidence' but `list_provider_descriptors()` does NOT return `capability_facts` — it returns `automation_capabilities`, `host_capabilities`, `permissions` etc. The raw capability_facts (with action_needed, support_assessment, limitations) are accessible only via the internal `capability_facts_payload(all_descriptors())` in capability_facts.py, which is not exposed through providers_api.

FINDING 3 — `harness_observability_inventory.py` referenced by the plan does NOT exist. The module was likely planned but never implemented. MO20 needs to find an alternative source for 'blocked reasons' — the capability_facts on provider descriptors carry `action_needed`, `support_assessment`, and `limitations` fields that can express blocked states, but they're not surfaced through any public API.

FINDING 4 — Existing reads that MO20 CAN compose:
- list_providers(project_root) — enabled/installed providers + status
- describe_provider(project_root, provider_id) — execution support, model catalog, managed-config surfaces, ownership registries
- list_provider_models(project_root, provider_id) — cached catalog with freshness/stale flag
- model_source_list(project_root) — per-source config with enabled state and filter
- apply_model_sources(project_root) — projection across all providers (write, not read-only)
- manage_model_projection(mode='status') — current managed model state
- list_provider_descriptors() — automation capabilities, permissions, host extensions

FINDING 5 — No catalog freshness read exists as a standalone function. `list_provider_models` includes `stale` flag but no source-level freshness aggregation. The source_catalog module has `SourceCatalogResult.freshness` but no public 'read all sources with freshness' API.

FINDING 6 — `model_ownership_registry(project_root)` in services/catalog/models.py provides the projection ownership data (ManagedFragmentRegistry). This is already used by `describe_provider` but not exposed as a standalone read.

## Conclusion

MO20 is unimplemented. Key correction: capability_facts are NOT the right source for blocked reasons — PC01 is actively removing the evidence-only tier from descriptors (model-local-state, model-config-projection, obs-* deleted as 'forbidden second registry'). MO20 must use runtime probes from describe_provider's status field and manage_model_projection(mode='status') instead. This aligns with PC06's 'declaration != authority; proof in owning subsystem' principle. No new PC item needed — the existing reads already provide what's required.
