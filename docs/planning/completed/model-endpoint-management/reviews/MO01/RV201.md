# Contract must target consolidated managed-config, not a new spec

## Notes

Validated against providers descriptor/loader code. McpConfigSpec and LanguageServersConfigSpec are already identical in shape (config_path/reader/writer/remover/format[/refresh_mode]) with twin builders in loader.py (_build_mcp_config, _build_language_servers_config) and twin YAML blocks (see opencode.yaml). A third ModelConfigSpec would be the third clone.

## Findings

1. MO01 step 3 proposes provider descriptor metadata for model config as if net-new; it should instead define the model kind as a consumer of a consolidated ManagedConfigSpec (fold mcp_config + language_servers_config + model kind into one dataclass/one loader builder). 2. Managed id/owner_scope mapping should be stated explicitly: owner_scope = provider id (matches MCP), managed_id = model-endpoints/<endpoint-id>. 3. Reference doc PROVIDER_MODEL_ENDPOINT_CAPABILITIES.md now carries the full contract + comprehensive matrix with FILL placeholders; MO01 should point at it rather than restate.

## Conclusion

Incorporate: retarget MO01 to the consolidated spec and reference the rewritten capability doc. Consolidation of existing specs is a prerequisite refactor (new item), sequenced before the model kind.
