# Collapse vendor-account/account-aggregator; separate discovery from projection; add model-filter

## Notes



## Findings

1) vendor-account and account-aggregator have no behavioral difference: connectivity shape, discovery modes, materialization, and rendering are all driven by connector + model-discovery, never by the class — a materializer registry keyed on the 3-class enum would hold two identical entries. The distinction with real teeth is local (declared) vs remote (connected: discovery, key semantics, degradation). 2) Discovery and projection were coupled ('discovery: none -> connectivity block'). They are separate axes: discovery is what AG knows about the source's models; projection per (agent provider, vendor) is a capability fact — native key injection (agent natively supports the vendor, key via env or config field, enables ALL models, no filter possible), custom-entry materialization (model-filter applies), or none. 3) No model-filter field existed; list-api sources (OpenRouter) return hundreds of models — unfiltered custom-entry materialization is unusable.

## Conclusion

Schema changes: source-class enum collapses to local-endpoint | remote-account (vendor vs aggregator becomes a descriptive grouping column in the mapping table only); add optional model-filter (include/exclude patterns) on remote-account sources, applied to custom-entry projection and AG-side alias exposure, explicitly NOT applicable to native key injection; provider YAML gains a vendor-key-injection declaration map ((vendor-id) -> mechanism env|config + key name/path, FILL until verified per provider, MO09).
