# Holistic AUDiaGentic model and vendor management surface

## Notes

User clarified that model management should be AUDiaGentic-centric: inspect vendor groups/models once and enable/apply them across compatible harnesses, while preserving native vendor and custom endpoint distinctions.

## Findings

The earlier MCP surface mixed AUDiaGentic source CRUD with a raw per-provider manage_model_projection tool and had no aggregate vendor/model view. OpenCode proves why this is insufficient: its catalog exposes vendor-group models natively, while Pi/Qwen use verified native env paths and custom endpoints use managed entries.

## Conclusion

Implemented one holistic MCP workflow: list_model_inventory, refresh_model_source_catalog, model_source CRUD, model_vendor_set_enabled, and apply_model_sources. Provider-specific projection remains a typed internal/public component seam but is no longer an MCP tool. Vendor groups are distinct from harness provider ids, OpenCode catalog rows carry vendor-id, native vendor groups are not duplicated into custom config, and custom catalogs reuse the existing managed-config/ownership core.
