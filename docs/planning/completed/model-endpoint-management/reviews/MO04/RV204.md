# Adopt NoAutomationRecipe for manual/unsupported/blocked tiers; separate status from priority

## Notes

Validated NoAutomationRecipe in recipe_patterns.py provides the guidance-only lifecycle (probe ABSENT + action_needed) that the manual/unsupported tiers need without new code.

## Findings

1. The four-state taxonomy (auto/manual/unsupported/blocked) is correct but should be implemented by binding NoAutomationRecipe for manual/blocked providers rather than ad hoc status text. 2. Support status and priority are orthogonal and are now separate columns in the capability matrix; MO04 should not conflate them. 3. Roo descriptor access_mode: env is misleading (forces auth-ref) and does not model extension-managed profiles — fix before any adapter. 4. Cline/Roo extension storage and Plandex/Aider config paths remain FILL in the matrix; keep them manual/blocked until validated.

## Conclusion

Incorporate: express manual/unsupported/blocked via NoAutomationRecipe, keep status/priority separate, and gate extension-storage providers behind storage validation.
