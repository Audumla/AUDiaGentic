# README capability tables will drift from the authoritative reference doc

## Notes



## Findings

Step 7 has every provider README carry its own capability table (status, config surface, sources, support status) while PROVIDER_MODEL_ENDPOINT_CAPABILITIES.md holds the same matrix. Two copies of the same running reference guarantees drift, violating the user requirement for one consistently-maintained record.

## Conclusion

Decision: PROVIDER_MODEL_ENDPOINT_CAPABILITIES.md is the single authoritative running matrix (support status, connectors, source-class participation, priorities). Provider READMEs carry only adapter-local detail (config surface specifics, verification notes, manual-mode instructions, whether manual is terminal) plus a link to the reference doc — never a duplicate matrix. Any change to support status or connector facts must update the reference doc in the same change.
