# Connect source catalogs to explicit cross-harness model projection

## Description

Provide one AUDiaGentic-centric model workflow: inspect configured sources and vendor groups with their models and verified harness paths, refresh source catalogs explicitly, enable vendor groups as desired state, and apply custom entries across compatible enabled harnesses through the existing typed projection family.

## Steps

1. Retain the normalized source catalog cache and explicit refresh boundary. 2. Add optional vendor-id to source/catalog contracts and normalize OpenCode native catalog models by vendor. 3. Inventory configured sources, cached/static source models, native provider catalog models, and verified harness modes (native vendor, native catalog, custom entries). 4. Enable/disable all configured sources for a vendor without implicit provider writes. 5. Materialize cached/static custom endpoint catalogs into the existing ModelProjectionRequest; native vendor groups are not duplicated as custom entries. 6. Fan out apply across enabled registered model-projection harnesses. 7. Keep raw per-provider projection off the MCP surface; expose inventory, refresh, desired-state CRUD/vendor toggle, and holistic apply.

## Files

[REUSE] services/source_catalog.py, services/models.py, providers_api.py, providers_mcp.py, model projection family, Pi descriptor/adapter. [TEST] explicit refresh/read, no-network reconcile, filter/materialization, stale ownership, Pi roundtrip.

## Validation

Completed 2026-07-18: 183 focused provider/schema/catalog/MCP/adapter tests passed, followed by the full providers unit suite (630 passed). Inventory and refresh are separate; ordinary projection performs no network call; OpenCode catalogs carry vendor ids; Pi/Qwen verified native vendor paths are descriptor data; native vendor groups do not duplicate custom entries; filtered catalog entries retain source-scoped ownership; MCP descriptor exactly matches implemented holistic tools and does not expose manage_model_projection.

## Notes

User-facing model management is AUDiaGentic-centric, not harness-centric. Vendor groups such as Anthropic/Google/OpenAI may be native in some harnesses and explicit custom entries in others. model_vendor_set_enabled changes desired state only; apply_model_sources is the explicit cross-harness projection step.
