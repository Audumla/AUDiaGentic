# Provider ACP capability and config override analysis

## Description

Pre-work investigation into two provider capability dimensions:

1. **ACP (Agent Client Protocol) support** — which providers natively implement ACP vs rely on adapter packages, and what that means for AUDiaGentic's execution transport.
2. **Config location override at startup** — can a provider be started with an entirely different config file path (MCP, models, LSP) to enable isolated launch without mutating user config.

Key findings:
- 8 providers support ACP (OpenCode, Kilo, Qwen, Gemini native; Claude Code, Codex, Pi via adapter). OpenHands is an ACP host, not agent.
- Only OpenCode and Kilo Code support inline config via env var (`OPENCODE_CONFIG_CONTENT`/`KILO_CONFIG_CONTENT`).
- Four providers in Tier 1 allow full config isolation (OpenCode, Kilo, Qwen, Codex).
- Six providers in Tier 3 have no config isolation at all.

These findings inform provider descriptor design, execution transport selection, and projection mode decisions.
