# Cross-platform MCP launcher path resolution

## Description

MCP config entries embed sys.executable as absolute command path. Works on originating machine but breaks if same JSON is read on another OS.

Current: mcp_interpreter() returns sys.executable — resolved at write time, written verbatim to mcp_config.json. Read back as-is with no cross-platform translation.

## Steps

['1. Inventory all MCP config write paths: json_format, component_mcp_launch, mcp_interpreter\n2. Determine whether cross-OS portability is required or if machine-local config is acceptable\n3. If required, implement resolution strategy (placeholder, relative ref, or OS-aware rewrite)\n4. Add unit tests for cross-platform path resolution']

## Files

['src/audiagentic/foundation/mcp/launch.py', 'src/audiagentic/foundation/mcp/json_format.py', 'src/audiagentic/components/providers/services/mcp.py']

## Validation

- Write `sys.executable` with audiagentic args -> placeholder on disk
- Read placeholder back -> resolved to current `sys.executable`
- 393 provider tests pass with no regression
- Non-audiagentic commands (e.g., `hindsight-mcp`) pass through unchanged

## Effort & Risk

Low risk — foundation-level change affects all json_format consumers automatically. All existing tests pass.

## Notes

Implemented placeholder mechanism in `json_format.py` at foundation level:
- `_sanitize_command()` replaces absolute python path with `__AUDIAGENTIC_PYTHON__` on write for audiagentic-owned entries
- `_resolve_command()` resolves placeholder back to `sys.executable` on read
- pi/mcp_format.py and opencode/mcp_format.py updated to use same sanitization
- Hindsight MCP recipe uses 'hindsight-mcp' command (PATH-resolved) — not affected by this issue
