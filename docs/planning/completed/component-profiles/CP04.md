# Layer base + profile component config dirs via existing 3-layer merge

## Description

Reuse the existing project_local > user_global > package_default merge pattern already implemented in foundation/paths/resolution.py for config value merging, applied instead to component descriptor discovery: a profile's component set should layer on top of (not replace) the base 'audiagentic' component set, so profiles can leverage base functionality (workflow, events, job state machine, etc.) without redeclaring it. BLOCKING conflict (found in deep-dive 2026-07-04): foundation/components/loader.py:241-258 _validate_descriptors_data() currently raises a hard error on any duplicate component id across config dirs - this directly conflicts with the 'profile wins on collision' rule and must be resolved by design, not just implementation.

## Steps

['Extend register_all_components() (or its caller in loader.py) to accept and merge multiple config dirs in priority order: profile dir first, base package dir second, matching the existing resolution.py layering semantics', "Resolve the loader.py:253-258 hard-fail: either (a) tag each descriptor with its source layer and skip the duplicate-id error specifically for cross-layer collisions (keeping last/profile), or (b) pre-filter duplicates by id before calling _validate_descriptors_data, mirroring resolution.py's _MERGE_ORDER (package_default -> user_global -> project_local, last wins) - do not silently change today's same-layer duplicate-id error, only the cross-layer case", "Align foundation/contracts/error_resolutions.py's directory iteration (see CP02) with whatever layer-ordering abstraction is introduced here, so descriptors and error resolutions cannot drift into reversed precedence relative to each other", 'Ensure install/enable/disable lifecycle operations and event-based lifecycle reactions (foundation/lifecycle, event bus subscribers) treat layered components identically to single-source components - no special-casing needed given foundation/ never imports components/', 'Add integration test: profile with one custom component + base layer confirms both the custom component and a known base component (e.g. ledger or workflow-dependent component) are registered and functional together, plus a test that a profile-layer descriptor sharing an id with a base descriptor wins per the chosen collision rule']
