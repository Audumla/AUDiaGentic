# Replace commands/ hardcoded optional-component imports with component-registry presence checks + direct import (not capability lookups)

## Description

commands/ is the correct composition-root layer per docs/standards/ARCHITECTURE_STANDARDS.md:13 (it is explicitly the one layer permitted to import specific optional components) - the earlier idea of moving commands/ under runtime/ was wrong and has been dropped. The real defect found while tracing commands/'s imports: six call sites hardcode a direct import of a specific optional component (components.providers.*, components.project.project_api, components.agent_jobs.control, components.ledger.ledger_bootstrap) wrapped in an ad hoc try/except ImportError, and treat a caught ImportError as proof the component is absent -- which is not a reliable absence signal (a real bug inside the imported module surfaces identically to 'not installed', silently masking failures). REVISED (2026-07-05): the original plan for this item proposed fixing that via get_capability()/register_capability() lookups. That direction is now rejected -- ARCHITECTURE_STANDARDS.md's 'registered callbacks' sanction is being struck entirely (see foundation-event-migration/EV04) after an audit found every real and planned use of that mechanism in the codebase was a misapplication, these six included: since commands/ and launcher.py are ALREADY exempt from the import-direction rule (ARCHITECTURE_STANDARDS.md:13), they never needed capability indirection to avoid a forbidden import in the first place -- there was no layering problem to solve here, only an absence-detection problem. The correct fix is simpler and requires no new infrastructure: check the existing component registry (get_descriptor(component_id) / is_installed(...), already populated by register_all_components()) BEFORE attempting the import. If the component isn't registered/installed, report 'not available' without ever importing. If it is, import directly and let a genuine ImportError propagate as a real bug rather than being silently swallowed as absence. This avoids inventing brand-new lifecycle-observer modules for project/agent_jobs (which the capability-based plan required purely to host register_capability() calls) and avoids six new capability-key registrations entirely.
