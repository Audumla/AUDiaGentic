# Cache guard will fight test-isolation fixtures that clear registries

## Notes



## Findings

The planned short-circuit cache guard in register_all_components() is keyed on the resolved targets list, but test-isolation fixtures (the snapshot/clear/restore precedent at tests/unit/foundation/conftest.py cited by CP05/CP10, and CP10's planned shared reset fixture) clear the underlying registries WITHOUT the loader knowing. After a fixture clears descriptor/feature/capability state, a subsequent register_all_components() call with unchanged targets would short-circuit and leave the registries empty - silently breaking any test that relies on lazy re-population, and mirroring the exact staleness bug CP01 flags for module-level register_all_components() calls.

## Conclusion

Add a step: expose a loader-cache reset hook and wire it into the same fixtures that clear registry state (CP10's shared reset fixture should call it), or key the guard on registry population as well as targets. Verified meanwhile: no caching exists today (loader.py:180-238 re-globs per call), error_resolutions is called with the same targets at loader.py:236, and ARCHITECTURE_STANDARDS.md section 11 already codifies the cache-inside-loader rule as this item's notes claim.
