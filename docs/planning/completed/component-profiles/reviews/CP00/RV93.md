# MUST-FIX: get_capability() conversion breaks paths that never bootstrap the registry

## Notes



## Findings

get_capability() only returns non-None after register_all_components() has imported lifecycle observers (loader.py:218-226), which is where register_capability() calls run. Of the six call sites CP00 converts, only commands/component.py is safe - it calls register_all_components() before its lookups (component.py:23,63,98). The other paths never populate the registry: provider_prompt.py's _try_provider_prompt is dispatched at launcher.py:348 with no bootstrap on the path, and launcher's _cmd_job_control (launcher.py:131) and _cmd_release_bootstrap (launcher.py:177) are dispatched directly from _main (launcher.py:337-339) - only _cmd_install ever calls register_all_components(). Implementing CP00's steps as written turns working commands into unconditional 'component not available' failures even when the component is installed.

## Conclusion

Add an explicit step: every converted call site must lazily call register_all_components() before get_capability(), per ARCHITECTURE_STANDARDS.md section 11 (lazy self-bootstrap). This makes CP02's cache guard a soft prerequisite (23+ call sites gain a re-glob each without it) - note the sequencing interaction. The regression test step must cover the launcher-dispatch paths specifically, asserting a capability RESOLVES (not just degrades gracefully) when the component is present.
