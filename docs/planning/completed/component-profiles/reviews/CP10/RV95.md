# Alias behavior of components/registry.py mischaracterized; surfaces/registry needs two instances

## Notes



## Findings

Two spec corrections. (1) CP10 (and CP08) describe foundation/components/registry.py register() as 'destructively strips aliases from the previous owner on collision - the most destructive pattern found'. The code (registry.py:17-23) strips only aliases owned by the SAME incoming component_id - that is correct cleanup for idempotent re-registration, not destruction of another descriptor's aliases. The real latent defects are different: cross-component alias collisions are silently last-wins (_aliases[alias] = id with no conflict check), and an alias can silently shadow-collide with a real component id in _registry. The Registry utility's alias spec should target those two, not a nonexistent stripping bug. (2) surfaces/registry.py holds TWO dicts (_renderer_registry, _contribution_renderer_registry) behind ONE _providers_imported lazy flag - the migration needs two Registry instances sharing a single loader callable (or a loader that populates both), not a 1:1 mapping like the other five. All six registries otherwise verified structurally as claimed.

## Conclusion

Update CP10's design step to specify alias semantics against the real behavior (raise or warn on cross-component alias conflict and alias-vs-primary-key shadowing; same-owner re-registration stays a silent no-op), and note the surfaces/registry two-dicts-one-loader shape. Propagate the same correction to CP08's description of the 'destructive pattern'.
