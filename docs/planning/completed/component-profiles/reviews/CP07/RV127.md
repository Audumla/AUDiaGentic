# Subprocess-level CLI test missing; profile tests bake in the cwd dependence instead of catching it

## Notes



## Findings

tests/unit/foundation/test_component_profiles.py covers the four in-process scenarios reasonably (layering, base-only, VAL-COMP-010 guard, idempotent re-register, override-wins). But: (1) the item's explicitly-added step ('ADD 2026-07-05, closing a gap from the architectural review: add at least one subprocess-level test that invokes the actual CLI … asserts on real stdout/exit code') was not implemented — no test anywhere invokes the audiagentic entrypoint with --component-profile; the flag added to launcher.py (including its env-var propagation ordering relative to module imports) is completely untested. (2) Every profile test does monkeypatch.chdir(tmp_path) before registering — which is precisely what hides the os.getcwd() profile-resolution bug (RV117); a test with cwd ≠ project root would have caught it. (3) CP00's own step 7 required regression tests per converted presence-check call site (launcher agent-jobs/ledger, provider_prompt, component.py) — none were added anywhere, so the 'present-but-broken component propagates ImportError instead of reporting not-available' behavior is unverified.

## Conclusion

Add the subprocess CLI test (real entrypoint, fixture profile dir, assert stdout/exit code), a cwd-independent profile test (chdir elsewhere, pass project root explicitly) once RV117 is fixed, and the CP00 presence-check regression tests. Until the first exists, the feature has never been exercised the way a user invokes it.
