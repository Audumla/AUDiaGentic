# components/registry.register() pops before registering — collision detection the migration existed to gain is bypassed

## Notes



## Findings

foundation/components/registry.py now constructs Registry(aliases=True), but register() calls _registry.pop(descriptor.component_id) before every _registry.register(...). This unconditionally deletes any existing entry first, so the Registry's primary-key collision policy (raise on different-value re-registration) can never trigger — silent last-wins is fully preserved, which is the exact latent defect CP08 was narrowed to fix. The alias cross-conflict and shadow checks do remain active (they run in _add_aliases), so partial value was delivered, but the primary-key half of the adoption is a no-op wrapped in extra indirection. There IS a real tension here — CP04's cross-layer 'profile wins' layering requires overwrite — but the implementation resolved it by silently disabling detection for ALL cases (including genuine same-layer accidental collisions, which loader-level validation only catches within one register_all_components pass, not across independent register() calls). Also: reset()'s docstring contains a stale TODO claiming CP02 hasn't landed (see RV115).

## Conclusion

Make the overwrite explicit and scoped: e.g. register(descriptor, *, replace=False) where only the loader's cross-layer path passes replace=True, letting direct re-registration of a different descriptor under an existing id raise as the Registry intends; or at minimum log a warning on silent replacement. Clean up the stale TODO.
