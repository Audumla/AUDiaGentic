# Make component descriptor discovery directory genuinely overridable

## Description

Pre-cleanup groundwork for profile support. register_all_components() in foundation/components/loader.py always resolves _ALL_COMPONENT_CONFIG_DIRS from the installed package's own config/components/ directory. The function accepts a config_dirs override parameter but nothing in the running application ever passes one - only a unit test does. Before profiles can point discovery at a different folder, this override path needs to be real: driven by actual config/env, not just a theoretical parameter.

## Steps

['Trace every call site of register_all_components() (loader.py:180-238, ~23 real call sites found via grep, not just the ~15 originally estimated)', "Add a short-circuit cache guard inside register_all_components() itself, keyed on the resolved targets list: today it has NO caching at all (loader.py:180-238) - every one of the 23 call sites re-globs and re-parses every YAML file from disk on every call, relying only on 'idempotent = safe to re-register the same descriptor', not 'cheap to call repeatedly'. This same cached-targets state is what CP05 needs anyway to detect 'a different profile was requested in this process' - implement it once, shared by both purposes", "MUST FIX (per review RV96, verified 2026-07-05): a cache keyed purely on 'have I seen this targets list before' will fight test-isolation fixtures that clear the underlying registries (component/feature/capability registries) without the loader's cache knowing - after a fixture clears state, a subsequent register_all_components() call with unchanged targets would short-circuit and leave registries empty, silently breaking any test relying on lazy re-population (the same staleness class CP01 flags for module-level calls, just triggered by test teardown instead of import time). Expose an explicit cache-invalidation hook (e.g. _reset_registration_cache() or similar) and wire it into the same fixtures that clear registry state - specifically CP10's planned shared reset fixture and CP05's guard test - so clearing state also invalidates this loader-level cache", "Do NOT centralize or reduce the scattered call sites - lazy self-bootstrap from wherever a module needs the registry populated is the intended pattern in this codebase, confirmed as a deliberate preference, not something to clean up. The cache guard's job is to make that lazy pattern cheap, not to reduce how many places call it", 'Introduce a real override source (env var and/or resolved config value) that feeds config_dirs, distinct from the hardcoded _ALL_COMPONENT_CONFIG_DIRS default', 'Ensure all call sites pick up the override consistently rather than only some of them threading it through', "Align foundation/contracts/error_resolutions.py:47-65 load_all_error_resolutions(config_dirs) with the same override source - it is a second, independent 'iterate multiple component-config directories' implementation called from loader.py:236 with the same targets list, and will silently diverge from descriptor discovery if not updated together", "Verify the new cache guard does not break any call site's correctness on first call in its process - it only skips redundant re-parsing on subsequent calls with unchanged targets, never skips the first real load, and never survives an explicit cache-invalidation call"]
