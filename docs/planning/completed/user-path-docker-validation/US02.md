# Validate component enable and disable mutations in Docker

## Description

From each applicable installed harness, enable and disable every supported component through public CLI workflows and prove the documented artifacts, registrations, and managed surface changes appear and are subsequently removed.

## Steps

1. Derive the component/capability matrix from descriptors and docs. 2. Reuse foundation-owned path and surface inspection helpers. 3. Validate enable, repeat-enable, disable, repeat-disable, and mixed-component isolation. 4. Check generated-file ownership and preservation of unrelated user content. 5. Raise review items for failures.

## Files

tests/docker; component descriptors; surface/path documentation

## Validation

All mutable mutations run in disposable containers; assertions cover exit contracts, files, configuration, and negative preservation checks.

## Effort & Risk

Platform-specific integrations may require explicit capability skips with evidence; silent coverage gaps are not acceptable.
