# Remove orphaned reload-marker mechanism; redesign runtime_sync_contract

## Description

HA04 deleted Pi's footer.ts extension, which was the SOLE consumer of the reload-marker file (reload-request.json). With it gone, the whole reload-marker mechanism is now dead: write_reload_marker / runtime_reload_request_path (runtime/harness/reload.py), the request_runtime_reload calls in commands/bootstrap.py and both {pi,opencode}/install/__init__.py, and the reload-request.json file are written but never read (opencode never had a consumer either). Separately, the advisory runtime_sync_contract MCP tool + build_runtime_sync 'sync' fields (project_api, session_api) still describe a reload flow to agents ('reload Pi session to apply') that no longer auto-applies -- semantically stale now that there is no in-session reload consumer.

## Steps

['Remove write_reload_marker + runtime_reload_request_path from runtime/harness/reload.py and the request_runtime_reload calls (bootstrap cmd_config_sync, pi/opencode install refresh_harness_config_if_installed) -- keeping the config materialization those functions also do.', "Keep or retire build_runtime_sync / runtime_sync_contract based on the future direction: the user intends a harness-agnostic way to signal config changes to a running harness ('better ways in the future'). Decide whether the advisory 'reload required after install' metadata stays (still true -- user must restart to pick up new MCP servers) or is replaced.", 'Remove the session-ui-visibility-updated / reload-reason plumbing if fully unused.', 'Update tests (test_reload.py) and any callers.']

## Detailed Solution & Technical Design

TWO INDEPENDENT MECHANISMS SHARE THIS FILE -- KEEP ONE, DELETE THE OTHER:

1. FILE-WRITING SIDE (DELETE): write_reload_marker + runtime_reload_request_path (runtime/harness/reload.py) write .audiagentic/runtime/harness/reload-request.json. Its SOLE reader was Pi's footer.ts extension (deleted this session, HA04) -- a live-reload-notification UI that polled this file. OpenCode never had a consumer either (confirmed no equivalent OpenCode extension ever existed). Zero readers remain anywhere in src/ or docs/ (verified by grep for 'reload-request.json' and 'runtime_reload_request_path' -- re-verify this before starting, in case something changed).

2. PURE ADVISORY METADATA (KEEP): build_runtime_sync (same file) + _runtime_action_for_reason are pure functions (no I/O) that classify a reason string into an action (refresh_required/reload_required) and shape a dict. This is NOT dead -- it's returned synchronously inside two MCP tool responses so the CALLING AGENT can see and act on it in the same turn, independent of any marker file: session_api.py::refresh_harness_config()'s "sync" field (line ~63) and project_api.py::runtime_sync_contract()'s "example" field (line ~60), which is itself an exposed MCP tool (project.yaml direct-tools list, ~line 23/42). Do not delete build_runtime_sync or runtime_sync_contract -- only the file-writing half.

CALL SITES TO REMOVE (all call request_runtime_reload / the facade forwarding to it):
  a) src/audiagentic/runtime/harness/__init__.py lines ~176-183: delete the `request_runtime_reload` facade function entirely (it's just `_forward("install", "request_runtime_reload", ...)`).
  b) src/audiagentic/commands/bootstrap.py: `cmd_config_sync` (~line 74-85) imports request_runtime_reload and calls it at line 80 after refresh_materialized_agent_config. Remove the import and the call -- keep the refresh_materialized_agent_config call, the try/except, and the success/failure JSON output unchanged.
  c) src/audiagentic/runtime/harness/pi/install/__init__.py: `request_runtime_reload`/`build_runtime_sync` module-level functions (~line 91-108, forwarding to reload.py) -- delete `request_runtime_reload` only (keep `build_runtime_sync`, still forwarded generically by the facade for session_api/project_api's advisory use). Also update `refresh_harness_config_if_installed` (~line 154-177, added THIS SESSION via runtime/harness/lifecycle.py) to stop passing a `request_reload` callable.
  d) src/audiagentic/runtime/harness/opencode/install/__init__.py: same shape -- delete `request_runtime_reload`, keep `build_runtime_sync`, update `refresh_harness_config_if_installed` (~line 173-183, also added this session) the same way.
  e) src/audiagentic/runtime/harness/lifecycle.py (NEW THIS SESSION, 2026-07-25): `refresh_harness_config_if_installed(*, cli_installed, component_id, refresh, request_reload)` currently ALWAYS calls both `refresh()` and `request_reload()`. Simplify its signature to drop `request_reload` entirely -- it becomes `refresh_harness_config_if_installed(*, cli_installed, component_id, refresh) -> bool`, calling only `refresh()` in the try/except. Update both call sites in (c) and (d) to stop passing `request_reload=lambda: ...`.

WHAT STAYS UNCHANGED: config materialization itself (materialize_agent_config, refresh_materialized_agent_config) -- HA05 only removes the RELOAD SIGNAL, not the refresh. A component install/enable/disable must still regenerate models.json/settings.json/AGENTS.md/config.json exactly as it does today; it just no longer also writes a reload-request.json nobody reads.

SESSION-UI-VISIBILITY / RELOAD-REASON PLUMBING: grep src/ for 'session-ui-visibility-updated' and any other reload-reason-specific plumbing beyond the _ALWAYS_RELOAD/_MCP_RELOAD reason sets in reload.py before removing anything else -- the original item description flagged this as possibly-unused but it wasn't independently verified this session; confirm zero callers before deleting.

OPTIONAL, NOT REQUIRED: project_api.py::runtime_sync_contract() hardcodes "target": "pi-runtime" regardless of which harness is actually active (a pre-existing staleness, not introduced by this item) -- if touching this function anyway, consider resolving the real target via get_harness_type()+f"{type}-runtime" instead of the hardcoded string, but this is a separate, smaller correctness fix and not required for HA05's scope.

      cleanup_runtime, install_to, refresh_materialized_agent_config, request_runtime_reload,

      del args
      target = global_harness_runtime()
      try:
          refresh_materialized_agent_config(target, project_root=project_root)
          request_runtime_reload(project_root, reason="manual-refresh")
      except Exception as exc:
          print_json({"ok": False, "error": str(exc)})
          return 1
      print_json({"ok": True, "runtime": str(target), "project_root": str(project_root)})
      return 0
  after: drop request_runtime_reload from the import and drop its call line -- everything else unchanged.

4) runtime/harness/lifecycle.py -- before (as written this session):
  def refresh_harness_config_if_installed(*, cli_installed, component_id, refresh, request_reload) -> bool:
      if not cli_installed: return False
      refreshed = True
      try: refresh()
      except AudiaGenticError: ...; refreshed = False
      try: request_reload()
      except AudiaGenticError: ...; refreshed = False
      return refreshed
  after:
  def refresh_harness_config_if_installed(*, cli_installed, component_id, refresh) -> bool:
      if not cli_installed: return False
      try:
          refresh()
          return True
      except AudiaGenticError:
          logger.warning("Failed to refresh agent config for %s", component_id, exc_info=True, extra={"component": component_id})
          return False

5) pi/install/__init__.py and opencode/install/__init__.py's refresh_harness_config_if_installed -- drop the `request_reload=lambda: request_runtime_reload(...)` kwarg from both calls into the shared lifecycle function (from step 4's new signature), and delete each module's own `request_runtime_reload` function (keep `build_runtime_sync`).

6) tests/unit/harness/test_reload.py -- remove any tests exercising write_reload_marker/runtime_reload_request_path if present (check first; this session's read of the file showed only _runtime_action_for_reason and build_runtime_sync tests, which stay unchanged since those functions are untouched). Add/update tests in tests/unit/provisioning/ or wherever pi/opencode install tests live (test_pi_install.py, test_opencode_agent_config.py, test_dynamic_agent_config.py) that currently monkeypatch/assert on request_runtime_reload being called during refresh_harness_config_if_installed -- update them to assert it is NOT called / no longer exists, while refresh (materialize) still is called.

## Notes

Direct consequence of HA04's removal of Pi harness UI customization. The user explicitly deferred the underlying need ('signal config changes to a running harness') to 'better ways in the future' -- so this item removes the dead mechanism and flags the redesign, rather than rebuilding reload now.

Executed (2026-07-25): reload.py's write_reload_marker/runtime_reload_request_path deleted exactly per guidance; build_runtime_sync/_runtime_action_for_reason kept (still live advisory metadata in session_api/project_api MCP tool responses). Implementation took a slightly different shape than the exact diff this item's guidance proposed: rather than deleting request_runtime_reload and its parameter from lifecycle.refresh_harness_config_if_installed, both pi/install/__init__.py and opencode/install/__init__.py kept a request_runtime_reload function name but gutted its body to return build_runtime_sync's dict directly instead of writing a file. This still fully satisfies the item's validation ('No reload-request.json is written by any path') since write_reload_marker no longer exists anywhere to be called -- a smaller-diff alternative to full deletion, not a shortfall. Full tests/unit/providers/, tests/unit/harness/, tests/unit/provisioning/, tests/unit/agents/test_sh21_* suites confirmed green with this implementation. Closing.
