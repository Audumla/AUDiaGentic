# Provider-to-runtime boundary violation after harness extraction

## Notes

User-reported failing boundary test after HA11 working-tree changes.

## Findings

Pi and OpenCode provider materializers imported runtime.harness.system_prompt for an unused dynamic injection mechanism. The provider materialization service also imported runtime.harness.config solely for rig-port validation. Provider boundary test correctly rejected all three imports. No current component config declares harness-instructions, so prompt injection had no active consumer; provider managed surfaces are the durable instruction path.

## Conclusion

Deleted the unused injection path, retained provider templates/managed surfaces, and moved shared harness rig-port validation to foundation configuration.
