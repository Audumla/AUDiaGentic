# Converge hindsight provider integration onto managed-fragment sync; recipes only for real installers

## Description

hindsight built a parallel vertical instead of reusing the provider fragment machinery. Validated findings (2026-07-06):
1. DUAL MCP WRITERS (correctness hazard, not just duplication): HindsightMcpRecipe (mcp_recipe.py:98) writes provider MCP config either via target.writer_fn or raw ConfigPatcher (configure(), lines 169-193) — in BOTH paths it bypasses providers/services/mcp.py, which owns managed MCP entries for these same files (add/remove/list + _sync_managed_entries with managed-id ownership markers and reconciliation). Hindsight entries are invisible to the managed-entry sync, and two independent writers touch the same provider config files.
2. RULES FRAGMENT BYPASS: RulesOnlyRecipe (recipes.py:824) drives apply_managed_block directly with its own path resolution (_resolve_rule_path, _resolve_harness_config_path, recipes.py:1288-1328), parallel to the provider surfaces machinery (surfaces/base.py, surfaces/manager.py, skill_surfaces.py) that already manages instruction-file blocks per provider descriptor (instruction_file/agent_files fields).
3. WRONG SEMANTICS DRIVE THE BLOAT: config fragments (MCP entry, rule block) have desired-state SYNC semantics (idempotent reconcile, ownership, prune) — exactly what sync_managed and surface-apply implement. Forcing them through the 8-method install lifecycle (probe/install/configure/verify/uninstall/prune/dry_run/provision) produced seven recipe classes whose methods are mostly stamped no-ops (_McpConfigAdapter has 8 one-line delegations at recipes.py:1492-1513; GuidanceOnlyRecipe/PluginConfigRecipe similar).
4. Only installer-kind integrations (official hook installers, wrapper CLIs, plugin installers — rows with install_steps + verified-source gating) genuinely need the lifecycle contract.
Goal: hindsight's MCP + rules fragments flow through the SAME managed-fragment mechanisms as ag-* servers and provider surfaces (enhancing those core features: URL-form MCP entries, capability-scoped rule blocks become generally available); the recipe lifecycle remains only for installer rows; recipes.py drops from ~1700 to roughly 400-600 lines; the strategy matrix (verified-source gating, platform constraints, fallback precedence resolve_hindsight_strategy/_external_fallback_row) is preserved unchanged as the selector.
