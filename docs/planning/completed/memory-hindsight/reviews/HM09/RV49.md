Finding 3 corrects this review's own earlier assessment — the standards doc (§4) is explicit and wins. Flakiness mitigation (split gates from network) already addresses the item's stated risk.

## Findings

1) MISSING DEPENDENCY — HM07: effort_risk lists HM10 and HM11 as dependencies (HM12 recommended), but the backend-switch test and the global-teardown test ('disable memory → reconcile removes every owned artifact') exercise lifecycle wiring that only exists after HM07 lands. HM07 is pending and not listed. Add it — the full execution order is HM10 → HM11 → HM07 → (HM12) → HM09 — or those two tests are unimplementable as written.
2) INHERITED OPEN QUESTIONS NOT IN SCOPE: HM05 left unresolved whether Copilot reads `.vscode/mcp.json` vs the adapter's `.mcp.json`, and gemini Cloud's OAuth-proxy gap. HM09 asserts 'config file contains expected remote entry' — which passes even if it's the wrong file for the running harness. Add an explicit validation deciding/documenting the copilot target, or the live test proves file-writing, not integration.
3) STANDARDS §4 VIOLATION IN THE ITEM AS WRITTEN (supersedes this review's earlier 'acceptable' verdict): the item directs a code default of `http://10.10.100.10:8888/mcp` for local/dev. ARCHITECTURE_STANDARDS §4 prohibits embedding local network details in code — they must live in non-committed config or env files. DIRECTIVE: the fixture reads `HINDSIGHT_TEST_MCP_URL` from the environment (optionally via a git-ignored `.env`/local config file); when unset, network-dependent tests SKIP with a clear reason. No IP literal appears anywhere in committed code or committed config. The refusal to skip architecture/source gates on unavailability stays — that part of the design is right.
4) COVERAGE DEBT CONCENTRATION: this item is now the proof point for validations claimed by completed items HM04 (Docker installer flows) and HM06 (disable-prune). Its completion criteria should explicitly enumerate which completed-item validations it discharges, so nothing is silently dropped if scope is trimmed under time pressure.
5) ADDITIONAL GATE TO INCLUDE (cheap, from RV48 finding 2): a matrix-freshness assertion — flag rows whose source_date exceeds a configured max age (with an explicit allowlist for stable rows) — belongs in this item's architecture/source gate group, since it is the only place source provenance is systematically checked.

## Conclusion

Right test architecture, wrong dependency list, and one directive in the item text must be overridden: add HM07 as a hard dependency; replace the committed IP-literal default with env/non-committed config per Standards §4 (skip network tests when unset); fold the copilot config-target question into validation; add the source_date freshness gate. Everything else in the item stands as written.
