# Review: de-duplicate Hindsight MCP config provisioning (pending)

## Notes

All line numbers verified 2026-07-03 against the working tree; re-verify with Grep before editing since HM11/HM12 touch the same files. Standards references: docs/standards/ARCHITECTURE_STANDARDS.md §2 (config over code), §8 (error handling), §9 (logging), §10 (atomic migration).

## Findings

1) CLAIMS VERIFIED IN CODE TODAY: the unreachable duplicate `prune()` block is real — mcp_recipe.py lines 234–247 sit after an unconditional return at line 230 and duplicate lines 220–233 verbatim. `sync_managed_provider_mcp_subset` exists in providers/services/mcp.py. The item's premise is accurate, not speculative.
2) ADDITIONAL DUPLICATION: `build_hindsight_entry` builds a raw dict and `_desired_mcp_entry()` re-parses that dict back into a McpServerEntry (mcp_recipe.py:128-142). DIRECTIVE: build `McpServerEntry` directly from `HindsightBackendConfig` (one function returning McpServerEntry; derive the raw-dict form only where a JSON payload is required) and delete `_desired_mcp_entry`. Do not preserve the dict→entry round-trip during the refactor.
3) SCOPE: the arbitrary `config_path + container` direct-config capability is load-bearing for HindsightTarget consumers; keep it as an explicit fallback for non-provider targets only — never as a parallel path for providers that have a descriptor `McpConfigSpec`. Providers with a spec MUST go through `sync_managed_provider_mcp_subset`. ADD a stdio round-trip test: `build_hindsight_entry` supports transport=="stdio" (command `hindsight-mcp`) and that shape must survive the move to the sync path; the item's validation list currently omits it.
4) SEQUENCING: must land before HM07 (which routes backend-switch reconciliation through this sync path) and before HM11 touches the same files. This is the correct first pending item to execute.
5) PLACEHOLDER SYSTEM UNIFICATION — DELETE `_parameterize_command` (recipes.py:858-884). There are two placeholder mechanisms: `_hindsight_params()` (dict of URL/MCP_URL/TOKEN/KEY/ID consumed by `provision_step_from_dict` for install/uninstall/configure steps) and `_parameterize_command()` (raw `str.replace` of the BARE tokens URL/TOKEN/KEY/ID inside `status_command`). The raw replace is a latent bug: it substitutes those letter sequences anywhere in the string, so any status command containing a word with "ID", "KEY", or "URL" in it is silently corrupted. DIRECTIVE: (a) in `config/components/memory/hindsight_matrix.yaml`, write status_command placeholders brace-delimited exactly like step defs: `{URL}`, `{MCP_URL}`, `{TOKEN}`, `{KEY}`, `{ID}`; (b) substitute by replacing only `{NAME}` tokens using the `_hindsight_params()` dict; (c) delete `_parameterize_command`. One placeholder system, brace-delimited, one source of values. Migrate the YAML in the same change (Standards §10 atomic migration). Add a unit test: a status_command containing the literal word "IDENT" is not corrupted.
6) PARALLEL ENUM MAP — DELETE `_RECIPE_KIND_MAP` (matrix.py:54-65). `ProviderRecipeKind` is a str-Enum whose values equal the YAML strings, so the map is a hardcoded parallel list (Standards §2 / §11 anti-pattern). DIRECTIVE: parse with `try: kind = ProviderRecipeKind(kind_str) except ValueError: kind = ProviderRecipeKind.GUIDANCE_ONLY` and delete the map.
7) STANDARDS FIXES IN THE SAME FILES (§8/§9): mcp_recipe.py has no module-level logger and `probe()` (line 154) swallows `except Exception` silently — add `logger = logging.getLogger(__name__)` at module scope and log the exception with `logger.warning(..., exc_info=True)` before returning ABSENT. Also `provision_steps()` gates on the identity check `writer is not _write_mcp_json` (line 111) — fragile; after the move to `sync_managed_provider_mcp_subset` this check must be deleted, not carried over.

## Conclusion

Accurate, well-scoped, and the highest-leverage pending item — execute first among pending HM items. Expanded scope for the implementer, all in the two files this item already owns: delete the dead prune block, delete `_desired_mcp_entry` (build McpServerEntry directly), delete `_parameterize_command` (brace-delimited placeholders in YAML, single params source), delete `_RECIPE_KIND_MAP` (use the str-Enum constructor), add module logger + exc_info logging in mcp_recipe.py, add stdio round-trip and placeholder-corruption tests. Every deletion here shrinks what HM11/HM12 must touch.
