# Code review: config changes can still reconcile twice

## Notes

Review of latest config-change wiring after switching event publish to ASYNC.

## Findings

['`memory_set_config()` now publishes `lifecycle.component.config_changed` asynchronously from `memory_api.py`.', '`memory_mcp.py` still consumes `needs_provider_recipe_refresh` by calling `refresh_provider_recipes()` synchronously for MCP callers.', 'That leaves two reconcile paths for MCP config updates: immediate bridge refresh plus later observer event. This can duplicate config mutation / installer work and introduce ordering races.']

## Conclusion

Choose one authoritative reconcile path per config update. Current hybrid approach is fragile and can double-run provider integration work.
