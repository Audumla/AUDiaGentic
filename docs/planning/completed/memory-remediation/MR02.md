# Stage 2 — Rehome provider adaptation into provider-owned surfaces

## Description

Move any Hindsight-to-provider mapping out of the `memory` component and into provider-owned adapters, registries, or generic capability-projection infrastructure. Providers decide how a memory capability is surfaced; memory does not decide how providers work.

## Steps

1. Define a provider-owned integration contract for memory-capable backends: either a provider surface registry keyed by capability/backend, or provider adapter hooks that consume generic memory payload from the active implementation.
2. If the memory backend must expose provider-consumable data, define one provider-agnostic export shape from `memory` (for example: backend id, endpoint, auth metadata, capability flags). No provider IDs in this export.
3. Implement provider-side rendering in `src/audiagentic/components/providers/` or provider adapter packages, not in `src/audiagentic/components/memory/`.
4. Ensure provider-specific file paths, managed block IDs, and prompt/config syntax live only in provider-owned code.
5. Rework refresh/reconcile flow so provider component pulls current memory export during surface generation, rather than memory pushing changes into provider surfaces.
6. Add at least one test that proves a provider adapter can consume memory export without memory importing provider modules or naming provider IDs.

## Files

src/audiagentic/components/providers/
src/audiagentic/components/providers/adapters/*/surface.py
optional generic projection registry under provider services
src/audiagentic/components/memory/ only for provider-agnostic export contract, if needed

## Validation

- Provider-specific file paths and syntax live only under provider component code.
- `memory` package does not import provider adapter modules or provider surface managers.
- Reconcile/apply flow still updates provider surfaces from active memory config, but data flow direction is provider pull, not memory push.
- Adding a new provider requires only provider-side changes unless the backend export contract itself changes.

## Effort & Risk

Risk is replacing one coupling with another hidden coupling. Mitigation: make the boundary explicit and test import direction plus data-shape contract.

## Notes

Architecture target: `memory` owns backend state; `providers` owns downstream representation. Hindsight-specific provider docs inform provider adapters, not the memory component core.
