# Stage 1 — Remove provider-specific logic from memory component

## Description

Refactor the `memory` component back to a generic capability/implementation owner. Delete provider-ID knowledge, provider target file mappings, provider branching, and provider-specific rendering from `src/audiagentic/components/memory/`.

## Steps

1. Audit `src/audiagentic/components/memory/` for any references to concrete provider IDs, provider file paths, provider surface modes, or provider reconcile APIs.
2. Remove `memory_projection.py` or reduce it to provider-agnostic payload generation only; no hard-coded provider IDs or output file paths may remain.
3. Strip `memory_api.py` of provider enumeration, provider support summaries, and direct `apply_provider_surfaces` / provider reconcile orchestration.
4. Keep `memory` focused on implementation selection, implementation config validation/persistence, and generic status for the active backend.
5. Update `memory_status` contract so it reports memory-owned facts only: active implementation, configured state, implementation options health, and generic projection/export state if needed.
6. Remove or rewrite README sections that describe provider matrices or provider-specific modes as memory-component responsibilities.

## Files

src/audiagentic/components/memory/memory_api.py
src/audiagentic/components/memory/memory_projection.py
src/audiagentic/components/memory/README.md
src/audiagentic/components/memory/memory_mcp.py

## Validation

- No file under `src/audiagentic/components/memory/` contains concrete provider IDs such as `claude`, `codex`, `copilot`, etc.
- No file under `src/audiagentic/components/memory/` contains provider target paths like `CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md`, etc.
- `memory_status` and related management tools still work, but report only memory-owned state.
- Memory implementation switching/config updates no longer directly call provider surface APIs.

## Effort & Risk

Main risk is breaking current projected behavior while removing the leak. Mitigation: move provider adaptation responsibility in Stage 2 before reintroducing any provider-facing integration.

## Notes

This item is architecture correction first, feature preservation second. Prefer deleting wrong-layer behavior over preserving bad abstractions.
