# Consolidate Pi's independent MCP materializer onto the shared foundation projection

## Description

OpenCode's runtime/harness/opencode/mcp_format.py already delegates to the shared foundation/mcp/json_format.py (read_mcp_json/write_mcp_json/remove_mcp_json) -- that half of the original duplication is resolved.

What remains: runtime/harness/pi/mcp_format.py still carries a fully independent serializer (_entry_to_pi_cfg, read_pi_mcp_json, write_pi_mcp_json) with Pi-specific lifecycle/settings fields, instead of delegating to the shared foundation projection the way OpenCode does. Both runtime/harness/{pi,opencode}/install/__init__.py also each carry a second, smaller layer of local mcp_config_path/read_mcp_config/write_mcp_config/remove_mcp_config wrapper functions around their mcp_format modules -- consolidate these too.

One generic foundation projection should select entries. Pi should have one serializer/materializer implementation, matching OpenCode's pattern. Runtime should not carry a second version of provider config formatting, and should not carry a second layer of path/read/write wrappers per provider.

## Steps

['Port Pi mcp_format.py serialization (lifecycle/settings fields) onto the shared foundation/mcp/json_format.py projection, matching the OpenCode pattern', 'Remove the now-redundant install/__init__.py local mcp_config_path/read/write/remove wrappers in both pi and opencode, calling the consolidated mcp_format functions directly', 'Verify no behavior change after consolidation (existing isolation tests must still pass)']
