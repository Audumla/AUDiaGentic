# Architectural validation and regression testing

## Description

Comprehensive validation to ensure we're not bleeding logic or cross-contaminating components.

Architectural constraints from ARCHITECTURE_STANDARDS.md:
1. Layer Boundaries (Rule 1):
   - Foundation must never import from runtime or components
   - Runtime must never import from optional components
   - Components may import runtime and foundation
   
2. Config Over Code (Rule 2):
   - Lists of entities must be declared in YAML/JSON, never hardcoded in Python
   - No if/elif chains on entity names - use registry of (key, handler) pairs
   
3. Logic Containment (Rule 3):
   - Shared logic (2+ files) → extract to foundation immediately
   - Duplicate dataclasses (>80% field overlap) → unify to one canonical type
   
4. Platform Independence (Rule 4):
   - Never reference specific editor's CLI, binary, or filesystem paths
   - Host-specific behavior → resolved at runtime through config-driven adapter
   
5. Component Discovery (Rule 5):
   - Never maintain Python import list or __all__ that enumerates pluggable modules
   - Use pkgutil.iter_modules() or config-driven discovery
   
6. Error Handling (Rule 8):
   - AudiaGenticError is the only domain exception
   - Every error must carry canonical code: PREFIX-COMPONENT-NNN
   
7. Logging (Rule 9):
   - Module-level logger only: logger = logging.getLogger(__name__)
   - No print() in library code
