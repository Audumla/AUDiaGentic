## Locked decisions (2026-06-26) — supersede earlier open questions

**D1. Dotpath syntax = colon `module:attr`.** One canonical resolver, `foundation/descriptors/resolver.py:resolve_ref()`. The existing `_resolve_probe_custom` (dependencies.py:82) is PATCHED to delegate to it (it currently uses dot `rsplit('.',1)`). No second dotpath implementation may be added — this is the consolidation point.

**D2. Scope = consolidate the MECHANISM, not the registries.** The recurring, duplicated pattern is 'YAML → resolve dotpath hooks → build step tree → construct typed descriptor', plus dotpath resolution itself. That becomes shared `foundation/descriptors/{resolver,steps,loader,registry}.py`. Specialized registries stay: the feature registry keeps its 5 multi-key dicts (no remap); the provider registry keeps its simple id-keyed dict + `_register_feature_implementation` coupling. `DescriptorRegistry[T]` is a reusable id-keyed store that registries MAY compose (providers do; feature registry does not — no friction). Migrate ONLY providers to YAML now; components/features adopt the mechanism opportunistically later.

**D3. Provider probe model is already declarative — do not route it through `_resolve_probe`.** Providers use `cli_probe: list[str]` (pure data) consumed by `_probe_cli` (registry.py:70, returns a structured availability dict). Keep both as-is. The only provider callable probe is `CliInstallRecipe.probe_fn`, which becomes a colon dotpath ref. There is NO new `cli` probe type. The `_resolve_probe` prefix model (binary:/command:/custom:) stays the COMPONENT-DEPENDENCY family's concern, untouched except the D1 patch.

**D4. Step-from-YAML builder is registry-dispatched (Rule 2).** `foundation/descriptors/steps.py:build_step_from_spec(spec)` dispatches on `spec['type']`: toolchain|shell|callable|sequence|select. `toolchain` delegates to `foundation/toolchains/loader.build_step`; `callable` does `CallableStep(fn=resolve_ref(ref))`; `select`/`sequence` recurse. No if/elif chain on type — a {type: handler} dict.

**D5. Foundation purity.** `foundation/descriptors/*` imports nothing from components/runtime. The pre-existing loader.py:147/281/290 violations are a separate prerequisite (PD06 gate), not introduced here.

**D6. Provider descriptors stay generic.** Provider YAML migration must not
absorb backend-specific implementation matrices. Hindsight-specific provider
setup remains contained in `config/components/memory/hindsight_matrix.yaml` and
`components/memory/hindsight/`. Provider descriptors expose generic seams only
(`mcp-config`, `cli-install`, `language-servers-config`, hooks refs). This
prevents the provider component from becoming a repository of memory/Hindsight
knowledge while still allowing implementation packages to consume generic
provider descriptor data.
