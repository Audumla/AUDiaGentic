# Build a config-driven role capability resolver and immutable launch manifest

## Description

Implement resolution from an agent-role-id plus project/component/provider evidence into a validated immutable capability/launch manifest. The resolver selects and configures only the components, features, MCP surfaces, permissions, and execution capabilities required for the job, recording provenance and explicit degraded/unsupported outcomes.

## Steps

1. Add typed role and capability models/loaders under the owning component/public API. 2. Resolve required/optional capabilities against component descriptors, feature declarations, MCP contributions, provider capability facts/probes, and policy. 3. Produce a stable manifest and fingerprint consumable by SH02/SH06; do not mutate process-global registries during resolution. 4. Enforce dependency closure, conflicts, permission boundaries, and unknown-capability failures. 5. Add explain/status output showing why each capability was selected or rejected without exposing secrets. 6. Add fixtures for minimal reviewer, implementer, research, and unrestricted compatibility roles as tests rather than permanent product presets unless approved.

## Validation

Resolver is deterministic; required capabilities are complete; unrelated components/MCPs are absent; missing evidence defaults to unknown/unsupported; manifests are stable across processes and contain no secrets.

## Effort & Risk

Complex cross-domain resolution. Component/provider owners must expose narrow typed facts; the resolver must not import their internals.
