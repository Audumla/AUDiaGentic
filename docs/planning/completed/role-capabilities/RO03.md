# Integrate role selection into job submission and shared-gateway execution

## Description

Allow MCP and event-triggered jobs to specify agent-role-id through thin protocol adapters. Resolve the role into the immutable launch manifest through the framework-neutral agents public API before dispatch, persist its identity/provenance with the request, and make context-isolated workers materialize that manifest. Preserve explicit agent-profile selection and existing workflow-profile semantics; MCP/event modules do not resolve roles or inspect component/provider internals.

## Steps

1. Extend submission contracts/events with optional agent-role-id and clear precedence rules. 2. Resolve and validate role intent at the authoritative boundary; carry the resolved manifest/fingerprint through SH02 rather than re-reading publisher process state. 3. Make SH06 workers enable only the declared components/features/MCPs and permissions. 4. Include safe role/capability identity in lifecycle events and timelines. 5. Add compatibility behavior for callers without a role during migration. 6. Test MCP, event, retry/resume, session, and cross-project paths.
