# Define agent-role and capability contracts distinct from agent profiles

## Description

Introduce the architectural concept of an agent role as execution intent and required/optional capabilities, separate from agent profiles (provider+model), workflow profiles (stage policy), and component profiles (process configuration overlay). Define ownership, configuration schema, naming, composition rules, inheritance constraints, and failure semantics before runtime integration.

## Steps

1. Inventory current all-or-nothing component/MCP exposure and any implicit roles in workflows, agent profiles, prompts, and job packets. 2. Define a typed capability vocabulary that can reference AUDiaGentic components, features, MCP tools/servers, provider execution capabilities, permissions, and resource needs without provider-name conditionals. 3. Define project-scoped role declarations and explicit required vs optional capabilities; prefer composition over deep inheritance. 4. Specify how roles combine with agent-profile-id, workflow-profile, and component-profile, including precedence and conflict errors. 5. Define safe defaults and least-capability behavior. 6. Review schema and architecture before implementation.
