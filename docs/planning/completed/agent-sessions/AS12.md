# Session lifecycle event publication (agents.session.* topics)

## Description

Publish session lifecycle notifications on the foundation event bus, mirroring the request lifecycle events (agents.llm.*) published by the queue manager. Decided during RV513 triage: the event bus is for OBSERVABILITY, not turn control flow — turn queuing stays in the SessionRuntime (per-session asyncio.Lock, ordered, request/response); events let listeners (status surfaces, future remote-channeling clients, automations) react to session state without polling the store.

## Steps

1. Register topics in agents events.yaml: agents.session.opened, agents.session.turn-finished, agents.session.closed, agents.session.expired, agents.session.failed (single owning component — CON-EVT-011).
2. Publish from SessionRuntime at the store-write points (open, turn finish, close/expire/fail) with payload {session-id, agent-profile-id, provider-id, state, close-reason, turn-count}; never raise from a publish failure (mirror _publish_lifecycle_event's RV38 swallow).
3. Tests: subscriber sees the full lifecycle; publish failure does not break the session loop.

## Files

src/audiagentic/components/agents/events.yaml (or equivalent topic registry); agents_gateway_sessions.py; tests/unit/agents/test_agents_gateway_sessions.py

## Validation

Unit tests with a bus subscriber; existing event-topic registry validation passes.

## Effort & Risk

Simple. Only risk is topic-registry conventions — mirror the agents.llm.* registration exactly.
