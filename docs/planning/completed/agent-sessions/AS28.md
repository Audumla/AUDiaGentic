## Description

Replace ACP as the gateway-facing live-session control model with a foundation-owned agent-session transport contract. ACP, Codex App Server, future native RPC, and process-only/CLI execution become provider-declared surfaces that implement the same narrow seam. Agents owns session queueing, durable session records, lifecycle projection, and control requests; providers own surface/version capability resolution, transport construction, protocol mapping, and native control mechanics. Hooks/plugins are observation producers only and never execute a control action.

## Steps

0. Freeze ownership and import direction. Add protocol-neutral types under `foundation/transports/agent_session.py` (or an existing foundation contract module) with no `components.agents` or `components.providers` import. `agents_gateway_sessions.py` may import only these foundation types and `providers_api`; providers may import foundation types and provider-local adapters. `AcpEvent`, `AcpLaunch`, ACP method names, raw IDs, and ACP error codes must not cross `providers_api`.
1. Define the exact foundation contracts:
```python
class SessionControlAction(StrEnum):
    CANCEL_TURN = 'cancel-turn'
    INTERRUPT_TURN = 'interrupt-turn'
    STEER_TURN = 'steer-turn'
    RESPOND_PERMISSION = 'respond-permission'
    CLOSE_SESSION = 'close-session'

class ControlDisposition(StrEnum):
    ACCEPTED = 'accepted'
    UNSUPPORTED = 'unsupported'
    ALREADY_TERMINAL = 'already-terminal'
    REJECTED = 'rejected'
    UNCERTAIN = 'uncertain'

@dataclass(frozen=True)
class TransportObservation:
    session_ref: str | None
    turn_ref: str | None
    sequence: int | None
    kind: TransportObservationKind
    observed_at: str
    correlation_quality: CorrelationQuality
    attributes: Mapping[str, Scalar]

class AgentSessionTransport(Protocol):
    async def open(self) -> SessionOpenResult: ...
    async def prompt(self, request: SessionPrompt, sink: ObservationSink) -> SessionTurnResult: ...
    async def control(self, request: SessionControlRequest) -> SessionControlResult: ...
    async def close(self) -> None: ...
    def is_alive(self) -> bool: ...
```
`SessionPrompt` contains only gateway turn id, prompt body, and deadline/cancellation token. `SessionControlRequest` contains the AUDiaGentic session id, turn/request id, action, and canonical payload (`permission: allow|deny`, `steer_text`, or empty); it has no provider-native command/payload escape hatch. `SessionControlResult` reports only `ControlDisposition`, observed correlation, and a stable error code—never an inferred session state.
2. Define the neutral observation vocabulary. `TransportObservationKind` is intentionally lower-level than the canonical status enum: `turn-accepted`, `activity`, `tool-requested`, `tool-finished`, `permission-requested`, `terminal`, `transport-error`, `transport-closed`. It carries bounded safe scalar attributes only (`tool_call_id`, `tool_status`, `reason`, `model_activity` where proven), no prompt text, output, tool arguments, native event name, raw payload, or secrets. Providers map native protocol frames to this vocabulary. The AS19 observer adapter then maps `TransportObservation` plus hook/native evidence to canonical `StatusEvidence`; AS21 alone maps evidence to state/decision flags.
3. Define provider capability declarations in `ProviderDescriptor.session_control_surfaces`, keyed by `(surface_id, version_constraint)`. Each entry declares `transport_factory_ref`, `controls`, `observation_source`, correlation guarantees, event ordering, resume support, and CapabilityEvidence. Example:
```yaml
session_control_surfaces:
  - surface_id: opencode-acp
    version_constraint: '==<probed>'
    transport_factory_ref: audiagentic.components.providers.adapters.opencode.session_control:build_transport
    controls: {cancel-turn: cooperative, interrupt-turn: unsupported, steer-turn: unsupported, respond-permission: default-deny, close-session: supported}
    observation_source: transport-callback
    correlation: {session: native, turn: request-scoped, sequence: ordered-per-turn}
```
No broad code branches on `surface_id`; absent/mismatched/unproven resolves to `unsupported` with process-only fallback.
4. Add provider public contracts in `providers/contracts/session_control.py`: `PreparedSessionTransport`, `SessionSurfaceCapability`, and a factory result that carries only a foundation `AgentSessionTransport`, resolved capability snapshot, and effective provider/session references. Add `providers_api.prepare_provider_session_transport(project_root, provider_id, model_id, surface_hint, session_context)` and `providers_api.get_session_surface_capability(...)`. The factory resolves provider enablement, exact version, descriptor declaration, and adapter registration before constructing the transport. `prepare_provider_acp_launch` becomes provider-internal or an explicitly temporary adapter helper; callers outside providers must migrate to the neutral operation.
5. Implement `providers/services/session_control_resolution.py` plus adapter registration. Each provider-local `session_control.py` implements the factory; no adapter is imported by agents. The resolver validates its declaration against the registered factory and returns `unsupported` rather than falling back to a different protocol. It must expose a capability snapshot before opening so the gateway can reject an impossible control request locally without pretending the native operation happened.
6. Implement the ACP adapter in `foundation/transports/acp.py` and provider adapters. Wrap `AcpSessionTransport` in `AcpAgentSessionTransport`: `open` delegates to ACP open; `prompt` translates bounded `AcpEvent` values to `TransportObservation` before invoking the sink; `control(CANCEL_TURN)` races/uses the existing ACP cancel path and returns `ACCEPTED` only when the protocol accepts it; unsupported interrupt/steer return `UNSUPPORTED`; permission uses the existing default-deny policy until an ACP permission response has versioned proof; `close` delegates idempotently. Keep ACP raw event payloads/private IDs inside the adapter. Preserve the one-shot `run_acp_prompt` compatibility wrapper during migration.
7. Refactor agents session runtime. Replace `AcpLaunch`, `AcpSessionTransport`, `AcpResult`, `AcpEvent`, `TransportFactory`, and `_make_on_event_callback` dependencies in `agents_gateway_sessions.py` with `PreparedSessionTransport`, `AgentSessionTransport`, `SessionTurnResult`, and `ObservationSink`. On open it obtains the prepared transport through providers_api; on prompt it forwards a neutral sink to AS19's observer lease; on cancel it issues `SessionControlAction.CANCEL_TURN`; on close it issues `CLOSE_SESSION`/transport close. Queue locks, deadlines, owner finally blocks, persisted session records, and current cancellation semantics stay agents-owned. Do not let `SessionControlResult` directly transition records.
8. Define control semantics precisely. A request is idempotent by `(session-id, turn-id, action, client-control-id)`. Repeating an accepted request returns the original disposition. `UNSUPPORTED` is not an error/state change; `ALREADY_TERMINAL` is a successful no-op; `REJECTED` means the provider refused a known request; `UNCERTAIN` means transport loss after submission and forces AS21/SH07 conservative reconciliation. Only a correlated terminal observation or established process-death evidence can release the turn; a control acknowledgement never does. `STEER_TURN` is append-only and exactly-once at the provider adapter; it must be unavailable until a native surface proves it. `RESPOND_PERMISSION` defaults to deny, requires a correlated outstanding request, and never accepts arbitrary provider-native payload.
9. Materialize non-ACP surfaces through the same factory: Codex App Server (AS14) declares native `interrupt-turn` and `steer-turn` only after its loopback protocol probe; CLI/process-only surfaces implement a `ProcessOnlyAgentSessionTransport` with `close-session` and at most cooperative cancellation, observation source `process-exit`, and no false session reuse; hooks/plugins augment AS19 observations but cannot implement `control`. This gives a future harness an additive control capability without changing agents.

## Validation

No executable gateway/session module imports `AcpEvent`, `AcpLaunch`, `AcpResult`, or `AcpSessionTransport`; it compiles against foundation `AgentSessionTransport` only. OpenCode ACP preserves current session open/two-turn/FIFO/cancel/close behavior through the neutral seam. A control action is capability-gated, idempotent, correlated, redacted, and never releases work on acknowledgement alone. Unsupported and unproven native controls return a stable disposition without fallback; a lost transport produces `UNCERTAIN` and conservative AS21/SH07 behavior. A fake native transport can add steer/interrupt support and pass the identical gateway suite without an agents code change. Docker proves each real surface/version before its capability declaration exceeds documentation tier. Additionally, static grep/AST gates enforce that agents has no Acp* imports, ACP callback argument names, public ACP launch APIs, or raw ACP extension parsing; the old OpenCode behavioral characterization passes through the neutral seam; and no obsolete ACP-session production import remains before a second harness is enabled.

## Effort & Risk

Complex cross-cutting migration with active AS13/AS14/AS19 work. The principal risks are accidental ACP leakage through public types, treating a hook as a control channel, dual transport paths, and control acknowledgements falsely terminalizing a turn. The staged migration, foundation-only protocol types, provider capability gates, idempotency keys, and AS21/SH07 state authority are non-negotiable.

## Standards

- Public provider API boundary: agents calls only `providers_api`; provider adapters and descriptor types never cross into agents.
- Foundation neutrality: `foundation/transports/agent_session.py` may depend only on foundation modules and scalar/frozen contract types.
- One declaration owner: AS29 `session_surfaces` is the sole runtime surface declaration; AS28 must not add `session_control_surfaces`.
- Explicit migration/deletion: retain one-shot ACP compatibility only outside SessionRuntime; remove ACP-shaped session imports, callbacks, launch results, and raw extension parsing from agents with AST/grep gates.
- Redaction and authority: raw provider IDs/payloads stay in adapters; transport observations do not transition durable session state.
- Reuse: extend existing foundation transport exports, providers_api, session runtime queue/ownership paths, and AS17 process supervision rather than duplicating them.
