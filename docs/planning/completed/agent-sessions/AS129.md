# Harden GPT-auto recovery ownership and proven terminal completion

## Description

Implement the narrow, repository-specific corrections identified by the live GPT reassessment of the pushed AS122/AS123/AS126 recovery slice. Preserve the existing nested response-recovery flow and avoid introducing the rejected recovery-state/helper abstraction.

## Steps

- Seed interruption_was_present from the pre-submit baseline DOM signals.
- Allow independent response-failed evidence to win when provider-interruption is co-present, while preserving completion-first ordering and auth handling.
- Remove active-turn page refresh from GptAutoSessionTransport.reconcile_activity_gap; retain binding revalidation and leave active-turn refresh authority in GptAutoTurn._await_response.
- Reorder proven terminal completion to non-strict final identity projection, durable unresolved-clear, conditional in-memory fence clear, COMPLETE transition, and best-effort terminal observation with dropped-observation accounting.
- Add focused regressions for stale interruption, compound provider failure, watchdog revalidation, checkpoint persistence failure, and terminal observation sink failure.
- Run focused GPT-auto tests, the full GPT-auto suite, gateway regression tests, then ask GPT to review the committed implementation and run a live gateway test.

## Detailed Solution & Technical Design

The existing GptAutoTurn._await_response nested recovery closure remains the only active-turn recovery authority. The pre-submit baseline is the edge detector baseline. Provider-interruption is a recovery signal and synthetic activity source, not a terminal failure; independent error-page/error-alert/auth-required policy evidence must not be hidden by it. The watchdog may validate/rebind the page but must not call PersistentChat._refresh_for_reconciliation while an active turn owns recovery timing and refresh budget. After terminal response proof, strict identity persistence is no longer required because correlation was already durably established; clear the unresolved checkpoint before clearing the in-memory marker. If that durable clear fails, retain the unresolved fence and put the chat in RECOVERING but return the already-proven answer successfully. Terminal event delivery is telemetry and must not downgrade the answer; count failed delivery.
