# Add bounded redacted metadata event polling for active sessions

## Description

Add an authenticated, project-scoped, cursor-based read surface over a bounded in-memory stream of provider-neutral session metadata. Remote prompt submission continues to use the existing `session-id` request path. This plan adds observation only: it creates no durable replay store, push stream, steering path, cancellation path, content channel, runtime owner, or second request/session state authority.

## Steps

1. Inspect the existing agents event/timeline/public-read seams and reuse an equivalent bounded buffer if one already exists. Otherwise add `src/audiagentic/components/agents/agents_session_event_polling.py` as the single owner.
2. Define immutable cursor/page values:

```python
@dataclass(frozen=True)
class SessionEventCursor:
    session_id: str
    next_sequence: int
    issued_at: str
    generation: str

@dataclass(frozen=True)
class SessionEventPage:
    events: list[dict[str, Any]]
    next_cursor: str
    gap: dict[str, Any] | None
    has_more: bool
```

3. Use opaque integrity-checked cursor tokens through an existing project helper. If no approved signing/integrity helper exists, keep the first slice internal and expose no remotely forgeable cursor until one is added through the appropriate foundation seam.
4. Implement one bounded per-project/per-session buffer with defaults: 256 retained events per session, 50 maximum page size, 25 default page size, and a per-process generation identifier. Restart or expiry returns a deterministic gap:

```json
{
  "reason": "expired-or-restarted",
  "from-sequence": 42,
  "next-available-sequence": 88
}
```

5. Accept only already-redacted AS19 `StatusEvidence`, AS21 lifecycle decisions/state changes, and registered bounded public diagnostic records. Normalize to: `sequence`, `timestamp`, `session-id`, `turn-id`, `kind`, `coarse-state`, `flags`, `source`, `correlation-id`, and bounded diagnostic code/message.
6. Reject or strip prompt text, assistant output, hidden reasoning, tool arguments/results, native protocol payloads, opaque provider refs, identity fingerprints, credentials, raw exceptions, command lines, paths containing protected refs, and stack traces.
7. Implement `poll_session_events(project_root, session_id, cursor=None, page_size=None, *, requester_context)` as a side-effect-free application helper. It validates authorization and project/session scope, clamps page size, returns ordered non-duplicated pages, and reports deterministic cursor gaps.
8. After the pure helper and authorization tests pass, add one shared gateway application/client/MCP read operation, `poll_agent_session_events` in the application/client and `agent_session_events_poll` in MCP. The public schema accepts `session_id`, optional `cursor`, and optional `page_size` and returns the public page shape.
9. Polling must not create or attach a runtime, acquire a session turn lock, renew execution ownership, alter queue state, keep a session alive, or mutate lifecycle/request records.
10. Prove that a second standalone client can poll while another client submits a later turn and that existing FIFO behavior is unchanged.

## Files

- `src/audiagentic/components/agents/agents_session_event_polling.py` or the equivalent existing owner.

Do not modify provider adapters, raw protocol parsers, `FileEventStore`, request persistence, AS31 content persistence, or execution lifetime for this plan.

## Validation

- ordered pages and cursor continuation without duplicates;
- page-size clamping and bounded retention;
- deterministic gap on restart generation mismatch and expired sequence;
- malformed/tampered cursor rejection;
- cross-project, unauthorized, and wrong-session rejection;
- content/protected-field redaction;
- poll is side-effect free and does not acquire the turn lock;
- concurrent poll plus later prompt preserves FIFO;
- process restart never claims durable replay.

## Effort & Risk

Mid. The main risks are cursor integrity, accidental content disclosure, and a read path acquiring execution ownership.

## Standards

Use existing authorization, public projection, bounded event, redaction, and shared-gateway seams. Unknown or untrusted fields are excluded by default.

## Acceptance Criteria

- The stream is bounded, redacted, in-memory, cursor based, project authorized, and content free.
- Restart/expiry returns a deterministic gap and never implies durable history.
- Polling does not create a runtime, change execution lifetime, advance queue state, or mutate status.
- AS31 output remains a separate lane; AS57 may combine authorized reads only at the external presentation layer.
