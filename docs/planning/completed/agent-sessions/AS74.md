# Make the unit suite parallel-safe and cut local run time ~9x

## Description

The suite already has full parallel infrastructure — pytest-xdist 3.8 installed, a `no_parallel` marker, and a `tests/conftest.py` hook that pins stateful modules to a single xdist worker via `--dist loadgroup`. CI uses it: `pytest tests/unit tests/integration tests/e2e -n auto --dist loadgroup -m "not docker"`.

Measured on this machine (32 CPUs):

| Run | Time |
|---|---|
| `pytest tests/unit` (serial) | 417-490s |
| `pytest tests/unit -n auto --dist loadgroup` | **50s** |

So the ~8 minute unit-suite cost recorded in AS71 is not inherent — it is the cost of running serially. Every local run in the AS71/AS72 work was serial.

**But the parallel run is not green.** Ten tests fail under `-n auto` that pass serially, from two distinct global-state leaks. Both are cross-*module* leaks, so the existing per-module `no_parallel` pinning does not address them, and neither is visible to a serial run — AS71 concluded the suite was order-independent on the strength of two serial runs, which cannot see this class of defect.

## Steps

1. ~~Switch distribution mode.~~ **Done** — `--dist loadfile`, not `loadgroup`. Biggest single win, independent of the rest.
2. ~~Make `no_parallel` actually isolate.~~ **Done** — deselection under `-n` plus a terminal warning, and a partitioned runner (`tools/run_unit_suite.py`).
3. **Open, and the real work: fix the global-registry churn.** The root `tests/conftest.py` autouse `_reset_test_registries` resets the feature, component, provider-descriptor and language registries before *every* unit test, and repopulation is not reliable — pi's import-time custom `surface.py` registration is never restored. Either make reset-and-repopulate exact, or stop resetting global registries per test and give the few tests that need a clean registry an explicit fixture. Until this lands the suite cannot be reliably parallel, and marking victims will not converge.
4. **Open. Fix the event-bus leak.** `reset_bus()` closes the process singleton; `tests/unit/{agents,jobs}` and `tests/unit/foundation/test_interaction_store.py` call it. Any test sharing that worker afterwards gets `VAL-EVT-002: event bus is closed`. Give callers a fixture that restores an open bus in teardown.
5. **Open. Verify CI.** CI still runs `--dist loadgroup`, which this work shows is the wrong mode. Not checkable from here — no source-control MCP is connected and CLAUDE.md forbids invoking `gh` directly. Because `docker-tests` has `needs: tests`, a red host suite silently skips the entire 15-image Docker matrix, so this is worth resolving before anything else.
6. **Open.** Once step 3 lands and repeated runs are green, switch CI to the partitioned runner and document it as the local default in `tests/TESTING.md` and `CREATING_PLANS.md` §5.
7. **Open.** Only then look at fixture-level savings (shared setup, session-scoped installs). Parallelism is the order-of-magnitude win already banked; deduplicating setup is second-order.

## What Was Implemented 2026 08 02

### 1. `--dist loadgroup` was the wrong distribution mode

`loadgroup` distributes **individual tests**, so a module is split across workers and any test relying on module-level setup from an earlier test in its own file breaks. `--dist loadfile` keeps each file on one worker.

Full unit suite, single command: **10 failures under `loadgroup` → 1 under `loadfile`**, same 65s. This is the single highest-value change here and is independent of everything else.

### 2. `no_parallel` did not actually isolate anything

The marker only added an `xdist_group`, pinning a module to one worker. That worker still runs unrelated tests, so a test that reads or mutates process-global state could still be poisoned by whatever landed beside it. The marker's own docstring described a guarantee it did not provide.

`tests/conftest.py` now **deselects** `no_parallel` tests from any run with `-n`, and `pytest_terminal_summary` reports how many were held back and how to run them — so a green parallel run can never be mistaken for a complete one. `AUDIAGENTIC_SERIAL_PHASE=1` opts back in for the serial pass. Detection checks both `config.option.numprocesses` (controller) and `config.workerinput` (workers); checking only the former silently fails because the hook also runs inside each worker.

### 3. Partitioned runner

`tools/run_unit_suite.py` runs five phases: non-foundation parallel, foundation parallel, serial `no_parallel`, then two files each in their own process (they register components against synthetic config trees, which replaces the live registries and error catalogue for the rest of that process, so they poison each other and everything after them).

**Result: all phases green in 84s, versus 417-490s serial.**

## Why This Is Not Sufficient

Three consecutive full runs of the partitioned suite: one clean, then two with a *different* failure each time — `test_generated_surface_contract`, `test_interaction_store`, `test_component_server_errors`. Marking cannot converge, because the set of parallel-unsafe tests is not a fixed list to enumerate; it is emergent from shared global state and changes with worker packing.

**The real cause is broader than first recorded.** It is not only `tests/unit/foundation/conftest.py`. The *root* `tests/conftest.py` has an autouse `_reset_test_registries` fixture that runs before **every** unit test in the repository, clearing the feature registry and resetting the component, provider-descriptor and language registries. The entire suite therefore depends on lazy repopulation being perfectly reliable on every access. It is not: pi's contribution renderer, registered from a custom `surface.py` at import time, is not restored by the post-reset repopulation path at all. Serially this is masked because one fixed module order happens to warm what is needed; in parallel, each worker sees a different order.

So the fix is not more markers. It is to make registry reset-and-repopulate correct — or to stop resetting global registries before every test.
