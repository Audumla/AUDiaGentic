# Session persistence: session records, schema, timeline + request-record session fields

## Description

Durable, observable session state following the exact agents_gateway_store conventions: atomic JSON records, schema validation via schema_registry, workflow-driven state transitions, NDJSON timeline. Live handles are in-memory (AS02); these records are the audit/observability layer and the future resume anchor (they persist the provider session reference, e.g. the ACP session id).

## Steps

1. New schema agent-llm-session.schema.json: contract-version, session-id, agent-profile-id, provider-id, model-id, provider-session-ref (ACP session id), state (active|closing|closed|expired|failed), created-at/updated-at/last-activity-at/closed-at, close-reason, idle-timeout-seconds, max-lifetime-seconds, request-ids[] (requests served in this session), turn-count. NO prompt/output content in the session record — content lives on request records which already have redaction discipline (Standard 8).
2. workflows.yaml: add 'gateway-session' workflow (active→closing→closed; active→expired; active/closing→failed; terminal set).
3. agents_paths.py: gateway_session_path/gateway_sessions_root/gateway_session_timeline_path beside the request equivalents.
4. Store functions in agents_gateway_sessions_store.py (or a section of a new store module — keep request store untouched): build_session_record, write/read/list, transition_session_record with per-session threading.Lock (mirror _request_lock), record_session_timeline.
5. Request record schema (agent-llm-record.schema.json) additions: optional 'session-id' (attach to existing session), 'session' object {keep-alive: bool, idle-timeout-seconds: number|null}. build_record validates: session-id and session.keep-alive are mutually exclusive with fallback-profile-ids (a sessionful request cannot fall back to a different profile mid-conversation — registered VAL code); keep-alive creates a session, session-id joins one.
6. Timeline events: session.opened, session.turn.started/finished, session.idle-expired, session.max-lifetime-expired, session.closed, session.failed.

## Files

src/audiagentic/components/agents/agents_gateway_sessions_store.py (new); src/audiagentic/components/agents/schemas or config schema dir (agent-llm-session.schema.json); src/audiagentic/components/agents/workflows.yaml; src/audiagentic/components/agents/agents_paths.py; agent-llm-record.schema.json; agents_gateway_store.py build_record validation

## Validation

Schema round-trip tests; illegal transition raises CON code; request record with both session-id and fallback-profile-ids rejected; existing request-record tests unchanged.

## Effort & Risk

Mid. Risk: schema additions breaking existing stored records — all new fields optional with defaults; validate against existing fixture records in tests.
