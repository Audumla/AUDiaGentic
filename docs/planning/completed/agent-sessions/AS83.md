# Seed real Agent Definition, Role and Execution Profile content

## Description

Turn the composition mechanism into populated, usable content. The CRUD and resolution path works and is tested, but the only instances in this repo are the deliberate minimal smoke fixtures (`rig-tester` profile, `placeholder` role with empty instructions, `rig-tester-agent`).

Content only — this item does not reopen the composition architecture (field shape, do-not-add list, resolution semantics), which is settled.

## Steps

1. Choose the candidates. The strongest source is the existing `agent_jobs` `@tag` prompt content (ag-implement / ag-plan / ag-review), which already encodes real behavioural instructions and is slated for rework — an Agent Definition is a natural home for it.
2. For each candidate create a real Role with actual instructions, a suitable Execution Profile, and an Agent Definition composing them — through the CRUD API/MCP tools, not by hand-editing YAML.
3. Set publication flags per definition from actual intended exposure, not defaults.
4. Add one regression test per definition following `tests/unit/agents/test_project_rig_tester_agent.py` (real project config, read-only assertions, no runtime writes).
5. State explicitly whether `placeholder`/`rig-tester-agent` are retired or deliberately kept as minimal smoke fixtures.

## Codebase Verification 2026 08 05

**Verified against the tree. Step 1's named candidate source exists but at a different path than expected — corrected here.**

The `@tag` prompt content lives in `src/audiagentic/config/components/agent-jobs/`, **not** `config/components/agent-jobs/tags/` (the path the generated CLAUDE.md doctrine cites — that reference is itself stale). The real files:

- `ag-implement.yaml`, `ag-plan.yaml`, `ag-review.yaml` — each a `kind: action` feature carrying `content.body` (the actual behavioural doctrine), `tag-id`, `display-name`, `description`, `aliases` and a `directives` list.
- `ag-implement-skill.md`, `ag-plan-skill.md`, `ag-review-skill.md` — the surfaced skill text.
- a `skills/` subdirectory.

**This is genuinely good Role material.** `ag-implement.yaml`'s `content.body` is already exactly the shape a Role's `instructions` field wants — behavioural guidance with no provider or model binding: "carry out the requested implementation work within the stated scope. Do not broaden scope... Run verification steps." The same holds for plan and review. Three real Roles are essentially already written; this item is largely a transcription plus choosing their Execution Profiles and publication flags.

**Two things to decide, not assume:**

1. The `directives` list (`profile`, `model`, `model-alias`, ...) is *job-request* vocabulary, not Role vocabulary. Do not carry it into the Role — provider/model selection belongs to the Execution Profile, and a Role carrying model directives would reintroduce exactly the separation this whole model exists to enforce.
2. These tags are consumed by the `@tag` prompt-launch mechanism, which is separately slated for rework. Seeding Roles from their content is safe and additive; **rewiring the tag mechanism to resolve through Agent Definitions is not this item's scope** and should not be attempted here.

## Implemented 2026 08 07
