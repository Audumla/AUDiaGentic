# Reassessment blocks parallel refresh authorities

## Notes

Dependency-order reassessment received from the user-pasted DevB GPT design on 2026-09-12.

## Findings

- The current slice adds a new response refresh path but leaves AS119 initial one-shot refresh, reconciliation refresh, correlation-conflict refresh, and activity-gap refresh authorities live.
- Refresh success is currently treated as part of the turn flow without the required recovery_anchor_at versus last_real_activity_at distinction; refresh must not count as validated activity.
- Real activity detection is too broad and currently includes global message/count and DOM/generating transitions; foreign or advisory changes must not reset the recovery episode.
- The refresh operation lacks the required serialized physical-page ownership, binding, generation, URL, and request-owner validation and post-refresh adoption boundary.

## Conclusion

Block current AS122 implementation pending consolidation with AS119 into one canonical refresh and reconciliation authority. Do not add further recovery behavior until AS123 is fully corrected and AS128 establishes reliable dispatch predicates.
