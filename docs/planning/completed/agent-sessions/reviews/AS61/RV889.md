# Instruction-handling step conflicts with agent_jobs rework direction

## Notes



## Findings

AS61 step 1 ("Characterize existing instruction handling and reuse its owner") and its §3 standards bullet ("instruction handling has an existing owner; reuse it rather than adding a second instruction store") both point at `agent_jobs/prompt_templates.py` -- the `@tag`-keyed prompt template system, characterized during the earlier AS61-reassessment investigation this session as the closest thing to a de-facto Role today.

The user has since stated (2026-08-04) that `agent_jobs`'s `@tag` prompt-launch mechanism is a dangling feature likely to be rewritten, superseded by harness-native Skill discovery (a harness matches on `trigger`/`description`, not literal `@tag` text in the prompt). See project memory `project_agent_jobs_rework_pending.md`. Deep-characterizing and reusing `prompt_templates.py` as Role's instruction owner right now means building against a component whose shape is expected to change, and re-litigating the integration once agent_jobs' actual rework lands.

## Conclusion

Revise AS61 step 1 and its §3 standards bullet to not direct a deep characterize-and-reuse dependency on agent_jobs/prompt_templates.py. Role's `instructions` field should stay minimal and content-agnostic (plain string or opaque reference) for now, deferring the reuse-vs-second-store question until agent_jobs' rework is actually scoped. This narrows step 1's evidence-led justification rather than removing it -- reuse is still the right instinct if/when there is a stable owner to reuse.
