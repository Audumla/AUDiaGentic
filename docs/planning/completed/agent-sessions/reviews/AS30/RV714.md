# AS30 landed binding code: rollback ghost records, rebuild race, identity gates (external review 2026-07-18, verified)

## Notes

Source: external plan/code review dated 2026-07-18; every finding re-verified against main on 2026-07-19. Already FIXED in tree 2026-07-19 (do not re-raise): record_session_turn is now idempotent (C2); v1 migration is deterministic via bindings.build_migrated_v1_binding (C3); transition_session_record rejects identity-field updates with VAL-AGW-097 (C6); ProviderSessionRef repr/str redacted (C7); provider_ref_key uses length-prefixed encoding (C8).

## Findings

1) OPEN ROLLBACK GHOST (High, C4): SessionRuntime._open_session writes the session record BEFORE binding_store.register_open_binding. On registration failure (e.g. CON-AGW-096 duplicate) the transport is closed but the written record remains durable-active — a reusable ghost visible to list/recovery. Required: on any failure after provider open but before handle exposure, transition the unexposed record to a terminal failed state with a stable reason (or delete under an approved no-audit policy), ensure no active index entry remains, record cleanup failure separately if the external session cannot be deleted. Add tests: duplicate binding, index write failure, record write failure, crash between record and index — assert no active reusable ghost, transport closed.
2) REBUILD INDEX RACE (Critical, C5): rebuild_index scans all records WITHOUT the binding lock and only locks the final write; a concurrent open registering after the scan is silently overwritten. Also reads raw JSON (bypasses validation/migration), silently skips unreadable records, does not re-read protected records for exact-ref collision validation, and unreadable-index reads (IO-AGW-096) do not trigger rebuild. Required: hold StartupLock for the full scan/validate/build/write; rebuild through the validated session-record reader; define legacy-migration stabilization before index admission; refuse rebuild (or record a recovery incident) when an apparently active record cannot be accounted for; re-read protected records on hash-key collision; rebuild under the same lock on unreadable index. Add process-race and crash tests.
3) UNKNOWN IDENTITY FINGERPRINTS (High, C9): open bindings default surface/identity/execution context to 'unknown'. Acceptable only for the transitional open-only slice. Required: complete AS08/AS29 context resolution before attach/resume/discovery; REFUSE attach/resume while either fingerprint is unknown; consider refusing new persistent bindings without an exact identity namespace post-migration. Two accounts/profiles returning the same provider-local ref currently collide.
4) NULLABLE BINDING INVARIANT (High, C10): schema requires the binding key but allows null; build_session_record returns null when the provider returns no ref. Decide explicitly: either every persistent session surface must return a stable ref, or an unbound live session is a distinct legacy/open-only state with no advanced operations. Do not leave this accidental.
5) INTEGRATION RULE (P16): AS08 durable schema/context fields, AS10 resume, and AS14 Codex App Server must implement their session identity through this item's binding/record work — no parallel binding implementations or second schema migrations.

## Conclusion

AS30's design holds; the landed transitional code needs the four repairs above before any attach/resume or second session surface is added. Sequence: rollback + rebuild locking first, then identity-gate enforcement.
