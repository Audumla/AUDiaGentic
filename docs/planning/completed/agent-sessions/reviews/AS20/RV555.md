# AS20 event-driven LLM slot re-acquisition deadlock risk

## Notes



## Findings

The AS20 notes say that when model.started fires without an available LLM slot, the turn should block until a slot is acquired. AS18 callbacks run inside the blocking transport prompt path; waiting synchronously in that callback can prevent the harness that owns the released tool slot from emitting its completion event, causing a deadlock. Re-acquisition needs a queue-level reservation/async handoff or a non-blocking state transition with bounded cancellation—not a blocking callback wait. The validation must prove no callback-thread deadlock and define behavior when the model phase arrives while capacity is unavailable.

The evidence gate is also inconsistent across items: AS18 notes allow AS20 at verification_tier >= installed-artifact, while AS19 describes verified signals as round-trip/installed-version evidence. Releasing scarce LLM capacity should require at least round-trip validation of the exact event mapping in the installed harness, with installed-artifact evidence remaining conservative.

## Conclusion

Keep AS20 pending. Redesign re-acquisition mechanics before implementation and require round-trip validation for the optimization signal; preserve conservative fallback on observer or event-loop failure.
