# Reaper must not kill busy sessions; queue turns instead of rejecting; lifetime/idle caps overridable incl. no-cap

## Notes

Sponsor feedback 2026-07-16 after the slim slice landed: (1) the 4h hard max-lifetime is problematic for planned remote-control sessions — must be overridable per request, including disabling it; (2) a session that is processing must never be shut down by the reaper — forced mid-turn close was too aggressive; (3) concurrent prompts should QUEUE per session (FIFO) rather than reject with CON-AGW-003.

## Findings

Design: per-session asyncio.Lock provides ordered turn queuing on the existing session loop (no new machinery); pending-counter with a queue cap (default 8) keeps back-pressure visible — CON-AGW-003 repurposed to 'turn queue full'. Reaper closes only quiescent sessions (no held lock, no waiters); past max-lifetime, new turns are rejected (new CON-AGW-004) so the session drains then closes. 0 = disabled for both idle-timeout and max-lifetime (request field session-max-lifetime-seconds added, VAL-AGW-061). Event bus deliberately NOT used for turn queuing (sync fire-and-forget, no per-session ordering or request/response semantics); lifecycle event publication deferred to a new plan item (AS12).

## Conclusion

Implement in agents_gateway_sessions.py + store/schema/dispatch/API/MCP plumbing; close when landed with tests.
