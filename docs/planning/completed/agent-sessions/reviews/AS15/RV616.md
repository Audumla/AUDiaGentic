## Notes

T3 verification pass prompted by open RV592, which rates AS15 CRITICAL/incomplete. The tree has moved since that review was written.

## Findings

1) STALE CLAIMS IN RV592: agents_gateway_queue.py now has a pq.compute_slots semaphore as the real compute gate — _on_turn_starting blocks acquiring a slot before removing the idle marker (line 407-412), _on_turn_done releases the slot, re-marks idle, and triggers _drain (line 414-422), and notify_turn_done IS called from agents_gateway_sessions.py:539 at the turn boundary. The specific failure modes RV592 describes (idle never drains; turn_starting takes no capacity; turn_done never called) do not match current code. RV592 should be re-triaged against the tree before anyone acts on its 'treat AS15 as incomplete' conclusion. 2) TEST GAP CONFIRMED: no test in tests/ references compute_slots, active_running, or a two-session max_concurrency=1 scenario — the concurrency gate that now exists is unproven. The race worth pinning: session A idle, session B running, A's turn_starting blocks on the semaphore in a worker thread while B completes — assert A proceeds, and assert concurrent compute never exceeds max_concurrency with two live sessions plus one non-session request interleaved. 3) DESIGN NOTE: there are two coupled accounting mechanisms — active_running() (running minus idle) gating thread spawn in _drain, and compute_slots gating actual compute. RV592's suggestion to remove the idle-set accounting if the semaphore makes it redundant is right in spirit but the sets also feed status() reporting; if both stay, add one comment stating which is authoritative (the semaphore) so they don't drift.

## Conclusion

Resolved by the corrected AS15 implementation and deterministic contention test. The bounded semaphore is documented as the actual compute gate; idle/running sets remain observability and drain bookkeeping.
