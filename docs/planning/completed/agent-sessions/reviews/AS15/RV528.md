# Concurrency slot release/re-acquire atomicity and callback design

## Notes

Architecture review required before P0 implementation begins. The concurrency model change is fundamental — a mistake here would cause deadlocks or slot leaks.

## Findings

## Architecture Standards Review — AS15

### Strengths
- Addresses the exact gap identified in the gateway analysis: profile concurrency held by idle sessions
- Two-phase model (hold slot only during actual transport compute) is correct
- Observable through gateway overview extension

### Concerns to resolve before implementation

**1. Atomicity of release/re-acquire (§3: no race conditions)**
The item says "release pq.running slot when session is quiescent" — but _drain reads len(pq.running) under pq.lock. The release/re-acquire must happen atomically with turn_lock transitions. Specifically:
- Worker enters dispatch → acquires pq.running slot
- If session turn_lock is held by another turn → worker should NOT hold pq.running while waiting
- When turn_lock acquired → re-acquire pq.running
- When turn completes → release pq.running, release turn_lock

This requires restructuring the _run_one/dispatch flow so that the pq.running add happens at turn_start, not at dispatch_start. Consider a callback from SessionRuntime to the queue manager: "my turn is about to start" → acquire slot; "my turn is done" → release slot.

**2. Back-compat with non-session requests (§1: no behavioral regression)**
Direct requests (no session_id, no keep_alive) go through a different path — they create a transient session, do one turn, and close. Ensure the two-phase model doesn't break this flow.

**3. Concurrency slot accounting during transport execution (§7: liveness)**
When a request is "on the transport" (actively computing), it MUST hold pq.running. The re-acquire must succeed — if max_concurrency is 1 and another request somehow acquired the slot during our session-level wait, we'd deadlock. The model needs: "a session's active turn has priority to re-acquire its slot." This means _drain should not fill slots that are reserved for pending session-level requests.

**4. SessionRuntime callback design (§5: no framework coupling)**
The callback from SessionRuntime to the queue manager must use a foundation-level interface, not import agents_gateway_queue internally. Consider having SessionRuntime publish an event (agents.session.turn-starting, agents.session.turn-done) and the queue subscribes.

**5. Test coverage (§6: testability)**
The item needs AS06-style tests: fake ACP agent with controllable turn timing. Test scenario: two sessions, max_concurrency=1, Session A finishes turn, Session B's request starts while A is idle.
