# Session-aware concurrency does not implement a safe release/re-acquire gate

## Notes

Post-completion implementation audit against Architecture Standards, Architecture Guidelines, Observability Standards, plan intent, and reuse-before-build doctrine.

## Findings

CRITICAL — AS15's `pq.idle` bookkeeping did not enforce concurrency. Marking a session request idle did not trigger `_drain`; `turn_starting` simply removed the idle marker without waiting for capacity; `turn_done` was never called. Depending on timing, requests either remained unnecessarily queued or multiple session turns could compute above `max_concurrency`. No two-session/max=1 contention test existed, and SessionRuntime imported the queue's private `_TURNCB` object.

## Conclusion

Resolved with one queue-owned bounded compute gate reused by session and non-session work. Session turns asynchronously acquire the gate without blocking the shared event loop, always release it after the transport phase, and trigger draining when quiescent. SessionRuntime now calls public notification functions and guarantees turn-lock release. A deterministic two-session contention test proves both workers reach the gate while measured compute never exceeds one; focused queue/session/integration validation passes (43 tests).
