# AS25 correlation query surface review

## Notes



## Findings

1. **FileEventStore as query source is correct** — Events are persisted with correlation_id, occurred_at, and component annotation. No new infrastructure needed.

2. **Do NOT build a dashboard** — A query API (agent_llm_correlated_status) is the right scope. Visualization is a separate surface.

3. **Missing correlation_id handling** — The requirement to exclude events without correlation_id is conservative and correct; provider events that don't carry correlation_id are genuinely uncorrelatable.

## Conclusion

No blockers; confirm FileEventStore is sufficient
