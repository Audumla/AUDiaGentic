# Swallowed-error follow-up completed; AS71's premise about RES-PIACP-001 was wrong

## Notes



## Findings

AS71 Finding 1 recorded that `public_execution.py` discarded "a registered, perfectly descriptive `RES-PIACP-001`". Two corrections:

1. **`RES-PIACP-001` is not registered.** It is constructed by `make_error(prefix="RES", component="PIACP", number=1)`, and constructing it raises `ValueError: Error code 'RES-PIACP-001' is not registered` once resolutions are loaded. What the bare `except Exception` actually swallowed was that ValueError — a failure of the error framework itself, not a well-formed provider error.

2. **The gap is systemic, not local to pi.** An AST sweep of every `make_error` call site found 38 of 70 statically-resolvable codes unregistered, plus 22 sites computing `number=` dynamically that cannot be checked statically at all. `test_error_resolutions.py` regexes for quoted code literals, so `make_error`-built codes are invisible to it. Recorded as AS72.

Also corrected: AS71's second follow-up framed the AS41 test decision as "(b) is likely correct — the assertion is about wiring, not about pi". Reshaping all four tests to fake builders would have made `test_opencode_never_gets_a_hook` tautological, since a fake builder trivially lacks the kwarg. The module docstring's original rationale — real adapters exercise the signature guard honestly — was right.

## Conclusion

Both AS71 follow-ups are now closed in the tree.

**Swallowed error.** `prepare_provider_session_transport` now splits the bare handler into a classified `AudiaGenticError` branch and an unclassified branch, logs both (details only at the failure site, since they may carry paths), and carries `unavailable_code`/`unavailable_message` scalars on `PreparedSessionTransport`. The builder-contract-violation return got the same treatment. Two new codes registered: `EXT-PROVEXEC-901`, `EXT-PROVEXEC-902`.

**AS41 external dependency.** Resolved as (a)+(b), per the user's note that pi is the current canary and other harnesses arrive soon: the four real-adapter tests are marked `requires_npm` with an npx skipif and remain the pi-canary proof; a new provider-neutral `TestSignatureGuardWithFakeBuilders` class covers the same branch logic with fake builders plus the three new failure-reporting paths, so CI always exercises the mechanism and the coverage survives the move beyond pi.

The AS28 field-set guard was updated to admit the two new scalars, with an added test asserting they stay scalar so the reason field cannot become a route for native payloads.

No change to AS71's completed state — its Definition of Done was already met by the two green runs; these were its recorded carry-outs.
