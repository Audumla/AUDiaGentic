# Two-session concurrency proof + Docker E2E transcript-fixture scaffold (increment 4)

## Notes

Extended test_pi_rpc_tap_real_binaries.py with a second real-binary test proving the required_concurrency_proof acceptance criterion, and set up a Docker E2E suite for the remaining exact-version transcript-fixture validate-first requirement (full prompt turn, not just the session/new handshake).

## Findings

Concurrency proof: two real pi-acp+pi sessions launched simultaneously (interleaved session/new calls) via _RealTappedSession, asserting distinct tap addresses/authkeys/runtime roots/pi-acp PIDs, and -- the real cross-contamination check -- that each tap's captured get_state frames carry only that session's own sessionId, disjoint from the other's. Both pass locally. Also found (not fixed, out of AS40 scope): pi-acp's own CLI parses only --terminal-login; the --cwd/--session-dir/--model flags build_acp_launch appends to pi-acp's argv are silently ignored by pi-acp itself (cwd instead comes from session/new's ACP params, which pi-acp does use). Relevant for the Docker E2E transcript test, which instead relies on patch_provider_config's default-model to make the embedded rig pi's own default regardless of CLI flags.

## Conclusion

New Dockerfile.pi-rpc-tap-e2e + test_pi_rpc_tap_transcript_e2e.py (opt_in, Docker-gated via AUDIAGENTIC_PI_RPC_TAP_E2E_DOCKER=1) provisions a real npm Pi CLI + real embedded llama-server rig (same provisioning as Dockerfile.gateway-pi-smoke, no external API key), drives a full ACP session/new + session/prompt turn through the tee shim, and asserts the tapped frames span agent_start -> message_update/turn_end -> agent_end. Build was started; per this repo's Docker-test doctrine the image build/run is how this suite gets validated, not a host-side override of its gate.
