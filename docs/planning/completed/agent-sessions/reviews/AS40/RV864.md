# Assert AS40 tee-shim design against ARCHITECTURE_STANDARDS/CREATING_A_HARNESS.md

## Notes

User flagged AS40's plan text uses the word 'shim' and asked whether that's architecturally correct. Verified against docs/standards.

## Findings

The forbidden 'shim' in ARCHITECTURE_STANDARDS.md SS4 and ARCHITECTURE_GUIDELINES.md SS9 (Migration Validation) is scoped to migration compatibility shims -- keeping an old API/route alive instead of updating all callers. AS40's 'tee shim' is a different category: a runtime process-tee/proxy executable substituted at the existing PI_ACP_PI_COMMAND hook, precedented in-tree by acp.py's existing _materialize_pi_command_wrapper wrapper-script mechanism. Checked against the rules that do apply: (1) location -- shim + rpc_tap.py both stay under components/providers/adapters/pi/, never import runtime.harness, matching CREATING_A_HARNESS.md's dependency-boundary split; (2) single-owner lifecycle (SS3) -- tap/socket lifetime tied to the existing session lifecycle, no new AS30 binding shape; (3) requester-blind/no dual authority (SS6) -- tap is read-only, pi-acp remains sole command driver, no second AgentSessionTransport, already stated as an AS40 acceptance criterion; (4) Gate D (CREATING_A_HARNESS.md SS5) -- AS40's validate-first section already requires per-bridge byte-transparency proof. Conclusion: AS40's shim usage does not violate any standard; the term collision with the forbidden migration-shim concept is coincidental, not substantive. Separately (unrelated to AS40, not actioned here): test_provider_runtime_boundary.py::test_provider_platform_has_no_runtime_harness_imports is currently failing for real -- adapters/pi/install.py and adapters/opencode/install.py import runtime.harness.system_prompt, a live violation of the exact rule CREATING_A_HARNESS.md names. Uncommitted working-tree edits from the concurrent HA11 refactor; left untouched per standing instruction not to fix/revert concurrent-workstream in-flight changes without being asked.

## Conclusion

No design change required. AS40's tee-shim mechanism is standards-compliant as specified.
