# Real pi-acp + real pi byte-transparency proof (increment 3)

## Notes

Ran the tee shim against the actually-installed pi-acp 0.0.32 bridge (via npx, cached) and pi 0.82.1 binary -- the load-bearing proof flagged as the most critical remaining gap after increments 1-2 (which only used fake/echo children).

## Findings

Found a real bug: _pump_stdin/_pump_stdout used BufferedReader.read(n), which blocks trying to fill the full chunk before returning -- fatal for interactive small-message RPC framing (pi-acp writes one small JSON line, waits for a response). The fake-child unit tests never caught this because they pre-seed the full response in one shot. First real-binary run reproduced it exactly: pi-acp's session/new hung after the first getState() call and Node eventually threw 'Cannot call write after a stream was destroyed' once the underlying process tree had gone away. Isolated the cause by first proving the pre-existing (already-shipped) MCP-isolation-only wrapper path works fine end-to-end against the real binaries (ruling out a Windows .cmd-wrapper/shell:true issue), which narrowed it to the shim's own stdio pumping. Also adopted the real pi child into a Windows kill-on-close Job Object via foundation.system.supervised_process.adopt_pid_into_kill_job (flagged by the user mid-session after I had to manually taskkill an orphaned real pi process left over from a hung manual probe) so the tee shim can't leak the real pi process if the shim itself is hard-killed.

## Conclusion

Fixed by replacing the buffered .read(n) calls with a fileno()-based os.read(fd, n) helper (_read_available) that returns as soon as any data is available, falling back to the test doubles' own .read() when no real fd exists (io.BytesIO etc. in unit tests). Re-ran the real-binary probe: pi-acp's session/new now completes its full real RPC round trip through the tee shim (get_state x3, get_available_models) with output identical to the unshimmed path, and the tap independently captured all real frames in transit. New permanent regression test: tests/integration/providers/test_pi_rpc_tap_real_binaries.py (marked requires_npm, skipif npx/pi missing). All 32 existing AS40 unit tests plus the new integration test pass; wider tests/unit/providers suite shows the same 8 pre-existing unrelated failures, no new regressions.
