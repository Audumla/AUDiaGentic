# Expand status-observer rollout from Gemini-only to per-harness recipes

## Notes



## Findings

The user requires AS27 to contain the actual implementation recipes for every harness, not only the initial Gemini hook investigation. The harness reference differentiates attach-only ACP, potential managed hooks, structured output, and unsupported surfaces, so a single Gemini-only item no longer represents the requested rollout. Recipes must state exact code/config action where evidence exists and otherwise prescribe the concrete probe plus conservative unsupported result.

## Conclusion

Replace AS27 with a per-harness status-observer recipe catalogue and rollout item. Keep AS19 as the shared implementation prerequisite; preserve the one-harness-per-probe execution gate inside AS27 so individual harnesses are not implemented speculatively or in one gateway change.
