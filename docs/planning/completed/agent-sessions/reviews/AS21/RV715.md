# Turn finalization races the session lock; AS21 must own commit-before-AVAILABLE and the live snapshot owner (verified)

## Notes

Source: external plan/code review 2026-07-18; verified against agents_gateway_sessions.py on 2026-07-19.

## Findings

1) LOCK-ORDER RACE (Critical, C1): SessionRuntime._prompt releases handle.turn_lock (and calls notify_turn_done) BEFORE record_session_turn, the session.turn.finished timeline write, and the SESSION_TURN_FINISHED event (agents_gateway_sessions.py ~775-806). A second queued turn can acquire the lock and reach the transport while the first turn's request-id, turn-count, timeline, and final event are uncommitted — durable request order can diverge from transport FIFO order, and a future AVAILABLE projection would release the session too early. Required: separate the profile/model compute slot from the session serialization boundary — release the compute slot on trusted terminal transport evidence, but hold the session turn lock until required durable finalization succeeds (idempotent turn record, final request output commit, required timeline facts, in-memory lifecycle decision update); only then make the session reusable. Best-effort timeline/EventBus enrichment may happen later only where explicitly non-authoritative. If required finalization fails, project UNKNOWN/FAILED, never AVAILABLE. Required test: block first-turn persistence after transport return, prove the second turn cannot enter the transport until finalization commits, then prove durable order matches transport FIFO.
2) LIVE DECISION OWNER (P8): AS21 is a pure projector with no durable store, but AS30 needs the current reusability decision between turns. Required plan addition: the SessionRuntime handle owns the current immutable projected lifecycle snapshot for a live session; AS21 stays a pure reducer/projector; required terminal facts live in existing session/request timelines/records; after gateway restart no live handle exists, same-generation continuation is impossible, and AS30 resume rules apply.
3) TERMINAL-EVIDENCE vs AVAILABILITY BOUNDARY (P9): a terminal protocol event is not 'session reusable'. AS21 must model the ladder explicitly: terminal evidence accepted → required AG finalization committed → no blocking foreground/background work → session projected AVAILABLE. This is the durable fix for finding 1.

## Conclusion

Add the state-owner and commit-before-AVAILABLE requirements to AS21, and treat the current lock-ordering race as a Stage-0 repair on main that AS21's implementation must land or depend on.
