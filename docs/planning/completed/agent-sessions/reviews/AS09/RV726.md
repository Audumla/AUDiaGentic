# Rebase the remote status API onto AS19/AS21 outputs; define in-memory gap semantics

## Notes

Source: external plan/code review 2026-07-18; assessed 2026-07-19.

## Findings

P18: AS09 currently depends on AS18's minimal ACP-derived event sequence. The remote status API must instead consume AS19 normalized StatusEvidence, AS21 projected decisions/state changes, and AS16 diagnostics where appropriate — the old event sequence is not the final remote lifecycle contract. Content-lane data stays in AS31, separate from this API.
