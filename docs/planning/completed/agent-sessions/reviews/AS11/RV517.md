# Graduate overseer R&D through agents session/gateway MCP, not a standalone component yet

## Notes



## Findings

['The reusable controller/worker pattern already has two strong owners: `agents` owns agent profiles, gateway request/session records, ACP session runtime, request/session MCP tools, and event publication; `providers` owns ACP launch builders and provider/model capability evidence. A new component would currently split the same lifecycle across another owner without enough distinct domain semantics.', 'The current `.audiagentic/research/agent-overseer/overseer_trial.py` is valuable as a trial harness, but its production seams should be harvested into the agents component: plan preflight, session-per-plan-item submit, sparse progress summary, terminal/stall classification, bump policy, review handoff, and cleanup verification. The script should remain the proving ground until AS11/AS06 evidence is strong enough.', 'The existing agents gateway/session code is the leverage point: request records, session records, timelines, lifecycle events, `agent_llm_*` MCP tools, and `SessionRuntime` already provide most primitives needed for a controller to avoid per-action inspection. Add summary/status reads rather than requiring an overseer to stream every ACP event.', 'AS08 is the correct owner for cross-process durability, heartbeat, and orphan adoption/termination once the pattern graduates. The current `SessionRuntime` is still process-local and daemon-thread based; any promise that long worker tasks survive MCP host death belongs to AS08, not AS11.', 'RE01 is a related consumer pattern but not the general overseer. It proves event-driven reviewer jobs and planning MCP propagation; AS11 should reuse its prompt-template/correlation discipline but keep implementation delegation/revision loops separate.', 'Provider/model identity and capability scoring should not be embedded in the overseer. AS11 should consume provider-owned identity/capability reads from MO07/MA19 and record model/profile performance evidence in the capability log or future agents status records.']

## Conclusion

Keep AS11 as the R&D/proving lane, then graduate reusable control surfaces into the existing agents component: sessionful plan-item delegation, summarized progress/status MCP, continuation/bump control, terminal/cleanup classification, and review handoff. Use AS08 for the durable supervisor/daemon. Do not create a new component unless the controller becomes a distinct workflow engine with multiple non-agent backends or independent durable policy ownership.
