# Split proven-death evidence from silence policy; retire the second recovery authority (verified)

## Notes

Source: external plan/code review 2026-07-18; verified 2026-07-19: agents_gateway_api.reconcile_gateway_state still derives orphans from this process's live IDs and calls get_session_runtime() (starting a runtime as a read side effect), while agents_gateway_recovery.py holds the SH07 owner-epoch-aware path. Also verified: the reaper's silence watchdog comment calls declared-cadence silence 'proven-stalled evidence'.

## Findings

1) SILENCE IS POLICY, NOT PROOF (P15): an inactivity timeout is a valid operator policy but must be described and recorded as a configured watchdog expiration (TIMED_OUT / policy-stalled, conservative forced failure) — not 'proven-stalled evidence' and not part of the proven-dead orphan logic. The orphan path acts only on strong process/protocol death evidence. Silence must never produce AVAILABLE or successful completion. Reword the RV680 reaper comment/timeline facts accordingly.
2) TWO RECOVERY AUTHORITIES (High, C14): the old process-local reconcile_gateway_state path remains publicly reachable alongside SH07's owner-epoch-aware recovery module. It makes decisions from process-local live IDs rather than the shared-service owner generation and starts a runtime as a side effect. Required: prove it dead/internal-only and delete it, or route it through the SH07 recovery authority; add an architecture/dead-code gate preventing two recovery authorities.

## Conclusion

Scope split required: AS26 keeps proven orphan recovery only; the silence watchdog stays a separately-labelled timeout policy; the legacy reconciliation path is removed or subordinated to SH07 recovery.
