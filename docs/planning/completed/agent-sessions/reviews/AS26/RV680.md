# Live-but-wedged harness is undetectable: no turn deadline, reaper skips busy sessions, cancel never reaches a running turn

## Notes



## Findings

Verified in tree (2026-07-18). AS26 covers proven-dead children; the larger operational hole is a child that stays alive but stops responding — nothing in the current design can ever detect or recover that, and it is the likeliest cause of 'we cannot tell what state the agent is in'.

1. Session turns have no deadline. `_dispatch_session_request` calls `runtime.prompt_in_session(...)` without timeout_seconds → `_call(coro, timeout=None)` → `Future.result(timeout=None)` blocks the gateway worker thread forever. Non-session dispatch has worker_timeout_seconds; the session path has no equivalent. A wedged harness leaves the request durably 'running' forever, holds the profile compute slot (max-concurrency default 1 ⇒ the whole profile is dead), and the FIFO backlog fills to CON-AGW-003.

2. Liveness detection is exit-code-only and quiescent-only. `AcpSessionTransport.is_alive()` checks proc.returncode; `_reap_once` explicitly skips non-quiescent handles (RV513). So a session stuck mid-turn is never inspected by the reaper, and a live-but-hung child passes is_alive anyway. There is no no-event watchdog (e.g. 'no AcpEvent for N seconds during an active turn') even though the on_event stream already provides the heartbeat signal for free.

3. Cancellation cannot reach a running session turn. `AcpSessionTransport.prompt` supports cancel_signal with protocol-level session/cancel, but SessionRuntime._prompt never passes one (agents_gateway_sessions.py:565). agent_llm_cancel on a running session request only sets the durable cancel-requested flag, which `_dispatch_session_request` checks once, before the prompt starts. So the one interruption mechanism the ACP protocol actually offers is wired but unused — an operator watching a wedged turn has no remediation short of killing the gateway.

Implementation-ready direction (fits AS26's turn-ownership model): (a) per-turn deadline resolved from profile params (turn-timeout-seconds, generous default) enforced inside the loop-side _prompt via asyncio.timeout so the finally-based lock/slot release paths fire; (b) an in-turn activity watchdog: last_event clock updated by the on_event callback, reaper allowed to inspect non-quiescent handles read-only and to flag/close a turn whose event silence exceeds a bound — this is exactly AS26's 'reaper may inspect non-quiescent handles' step, extended from proven-dead to proven-silent with conservative unknown; (c) plumb an asyncio.Event per turn from the cancel path into transport.prompt(cancel_signal=...) so cancel-requested interrupts via protocol cancel, with AS09's caveat that semantics stay provider-verified. All three land in the seams AS26 already names (turn task ownership, reaper, queue idempotent finalization).

## Conclusion

Recovering proven-dead children (AS26 as written) still leaves the dominant failure mode — alive-but-silent — permanently invisible; add turn deadline, event-silence watchdog, and cancel_signal wiring to AS26's scope or a sibling item.
