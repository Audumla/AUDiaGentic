# Make harness status-observer plan implementation-ready

## Notes



## Findings

AS19 states the target architecture but leaves the code path underspecified: it has no typed descriptor/request/result names, no exact lifecycle owner for provider enable/disable, no per-session hook-to-gateway delivery mechanism, no stable ownership keys, and no explicit modules/tests. The existing code proves the available implementation patterns: ProviderAutomationRegistry plus typed contracts, ManagedFragmentRegistry ownership reconciliation, component lifecycle observers, providers_api as the sole requester seam, AcpLaunch environment injection, and bounded ACP callbacks. The current canonical status vocabulary must be shared through a neutral contract; providers must not import an agents-only enum.

## Conclusion

Amend AS19 and its Gemini child AS27 with concrete types, modules, lifecycle events, request flow, authenticated loopback ingress, ownership keys, state boundaries, and test cases. This is a planning correction only; no runtime contract is implemented by this review.
