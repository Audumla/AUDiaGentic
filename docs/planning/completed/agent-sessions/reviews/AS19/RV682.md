# Define generic managed harness-status observer lifecycle and bounded rollout

## Notes



## Findings

AS19 correctly owns conservative, surface/version-specific observability declarations and the first OpenCode ACP proof, but it does not make harness-side observer enablement/removal an explicit provider capability. The current runtime has a hard-coded ACP callback projector labelled unknown, while provider descriptors already offer the relevant architecture patterns: capability evidence, explicit automation families, managed ownership reconciliation, and non-mutating status probes. Without an explicit lifecycle, future hook/plugin/config integrations risk leaking provider-native mechanics into gateway code or leaving injected artifacts behind when a provider/component is disabled.

## Conclusion

Refactor AS19 to establish a generic provider-owned harness-status-observer capability family and resolver, with apply/prune/status semantics, owned-artifact reconciliation, canonical status-event contract, and OpenCode ACP as its first no-injection attachment proof. Create a separate, evidence-gated Gemini CLI hook item rather than generalizing from documentation alone.
