# ACP turn-event normalization is broken: model.completed never publishes, canonical vocabulary bypassed, duplicate tool.started

## Notes



## Findings

Verified in tree (2026-07-18), all agents+transport unit/integration tests green — these are design defects the tests encode rather than catch.

1. `agents.turn.model.completed` can never be published from a live turn. `_ACP_KIND_TO_TURN_TOPIC` in agents_gateway_sessions.py maps kind 'result' → TURN_MODEL_COMPLETED_TOPIC, but the only producer of 'result' events is `_TurnPipeline.emit_terminal` (foundation/transports/acp.py:329), which never invokes `_emit_callback` — unlike `emit`/`emit_error`. The on_event callback therefore never sees the terminal event. The AS18 test (test_agents_gateway_sessions.py:475 `test_intra_turn_events_wired_to_eventbus`) masks this by hand-injecting only non-terminal kinds. Any observer (AS09 polling, AS21 projector) waiting on model.completed will wait forever; turn completion is only observable via the synchronous prompt return.

2. The 'closed canonical vocabulary' is bypassed by every real harness event. `_RAW_TO_CANONICAL` (acp.py:71) contains keys that are not real ACP sessionUpdate values ('thought', 'status', 'usage', 'file_change', 'terminal_output') while the real values 'agent_thought_chunk' and 'tool_call_update' are absent, so they pass through `_map_kind` raw. Downstream, `_resolve_turn_topic` keys on exactly those *unmapped raw* kinds ('agent_thought_chunk', 'tool_call_update') — i.e. turn-state detection depends on the normalization layer failing to normalize. Consequences: `_extract_text` never extracts thought text (kind is 'agent_thought_chunk', not 'thought'); any harness that spells a kind differently silently produces no state signal and no error; the frozen-contract vocabulary in AGENT_TRANSPORTS.md does not describe actual behavior. test_acp_session_subprocess.py:162 asserts the leak ('agent_thought_chunk' expected verbatim) — the leak is load-bearing.

3. `tool_call_update` with status 'pending' then 'in_progress' publishes agents.turn.tool.started twice per tool call; status 'failed' publishes nothing, so tool failure is invisible to observers. `_resolve_turn_topic` should be status-transition-aware (started once, terminal for completed|failed).

4. Confirms the AS19 step-4 premise with evidence: `_TURN_EVENT_SEMANTIC_STRENGTH='precise'` / `_TURN_EVENT_VERIFICATION_TIER='execution'` (agents_gateway_sessions.py:62) stamp every event of every harness as execution-tier, self-attested, with no per-surface declaration or capability evidence — precisely the runtime self-attestation AS19 removes.

Implementation-ready direction: (a) make emit_terminal async-emit through _emit_callback (or emit a distinct terminal notification hook) so the callback sees exactly one terminal event per turn; (b) correct _RAW_TO_CANONICAL to the real ACP sessionUpdate vocabulary (agent_message_chunk, agent_thought_chunk, tool_call, tool_call_update, plan, available_commands_update, current_mode_update), map turn topics from canonical kinds only, and make an unknown raw kind an observable 'unknown' event rather than silent passthrough — this is a frozen-contract change and needs the MA18-successor review trail; (c) dedupe tool.started per tool-call id and add a tool terminal for failed; (d) fold into AS19's declaration-driven strength/tier resolution.

## Conclusion

AS18's projection must be corrected before AS19/AS21 build on it; today the event stream cannot signal turn completion or tool failure and its normalization contract is fictional.
