# gpt-auto review of AS87 - correct intent but significant contract holes

## Notes



## Findings

**Verdict:** Intent sound, architecture good (one public final-output decision + one internal durable read primitive). **Not implementation-ready.** M/intermediate is reasonable if Detailed Solution filled in.

**After discussion with reviewer, revised findings:**

1. **Selector input contract undefined (HIGH):** "Bounded relay state" is not sufficient. Must consume AS86's OutputStore authority — no inspecting event files or index independently. Hidden issue: no common "neutral turn result" exists — queue path deals in provider result dicts, session path receives typed SessionTurnResult.final_summary. Needs small gateway-owned normalization (TurnFinalizationFacts) before selector can serve both paths.

2. **AS86 dependency implicit but real (HIGH):** AS86 literally says "AS87 remains blocked." Selector assumes production relay wiring, coalescing, final flush, durable ordinals, gap state, recovery, single-reader store — all AS86 work. Must be explicit `blocked_by: AS86`.

3. **Selector output type undefined (HIGH):** Durable record has only output/completion fields; no durable output-selection/degradation field. If selector returns "degraded/unknown" internally but terminalization persists only output=None, distinction disappears. Needs concrete type:
   FinalOutputSelection(text: str | None, disposition: selected | no-output | degraded | conflicting, reason: closed enum)
   Specify where non-text disposition survives durably.

4. **Cursor read uses wrong identity after AS86 (HIGH):** Step 5 says after_sequence — wrong after AS86 replaces optional source sequence with durable event ordinal. API should be:
   read_request_output(project_root, request_id, after_ordinal, limit)
   Not after_sequence. Verification note about "20-digit zero-padded" filenames is actively dangerous — current code writes f"{event.sequence}.json" and lexically sorts (10.json before 2.json).

5. **Selector ordering relative to terminal transition (HIGH):** Required order must be explicit:
   transport/provider finishes → relay final flush/close → obtain frozen OutputStore finalization state → run pure selector → exactly one fenced terminal request transition
   Terminalization can precede relay close unless plans restructure boundary — makes selector inherently racy. Crash window between relay close and request transition needs defined policy.

6. **Bounded final output missing from steps (HIGH):** dispatch.py reads result.get("output") directly with no bound. Caps in AS86 protect only sidecar, not authoritative field. Must have explicit byte bound derived from frozen output policy; define what happens when candidate final exceeds it (truncate with explicit state, reject and degrade, etc.).

7. **ASSISTANT_FINAL semantics undefined (HIGH):** AgentOutputEvent has ASSISTANT_TEXT_DELTA and ASSISTANT_FINAL plus separate is_final boolean, but contract never says whether ASSISTANT_FINAL.text means complete final answer, final delta, or terminal summary. Cannot handle "coalesced streaming text plus explicit final" deterministically until normalized. Concatenating full final snapshot duplicates output; replacing deltas with final tail loses content.

8. **Reconciliation precedence unspecified (HIGH):** Cases enumerated but no expected results defined:
   - Coalesced relay text says A and neutral final says B
   - Relay truncated but neutral result contains complete final
   - Deltas but no final
   - Explicit final exists but transport reports failure
   - Final event and is_final contradict one another
   Need deterministic source-of-truth algorithm.

9. **Retry-attempt contamination (HIGH — AS86 blocker):** Queue dispatch can execute several provider attempts for single request. Without attempt provenance, AS87 sees both sets of events under one request/turn and cannot know which content is eligible for authoritative final output. Clean split:
   - AS86: Every stored output event carries attempt_epoch in StoredOutputEvent and OutputStore/index identity. Recovery preserves attempt boundaries; output from one attempt never adopted into another.
   - AS87: Final-output selection consumes relay state for owned terminal attempt only. Prior failed/retried attempts never eligible for durable public final output.

10. **Timeout and interrupted scenarios (HIGH):** Timeout not actually a request state (completed/failed/cancelled/rejected/interrupted exist). Both concepts needed:
   - Session turn deadline expiry → TO-AGW-090 → failed with reason turn-timeout
   - Isolated worker watchdog → TO-AGW-076 → transient, can cause retry; exhausted retries → failed
   - Interrupted = real gateway terminal state for execution unable to continue/recover cleanly
   Gateway terminal state alone insufficient (failed could mean timeout after partial output, config failure with no output, transport loss, etc.). Needs gateway-owned normalized finalization input:
   TurnFinalizationFacts containing terminal_state + termination_reason (NORMAL, CANCELLED, TIMEOUT, TRANSPORT_FAILURE, EXECUTION_FAILURE, INTERRUPTED)

11. **"Retention gap" ahead of storage contract (MEDIUM/HIGH):** AS87 promises distinguishable retention-loss outcome but AS86 doesn't define retention/compaction policy or durable retained-floor metadata. Either add retained-range semantics to AS86 or remove "retention" as separately knowable condition.

12. **Cursor semantics incomplete after ordinal change (MEDIUM):** Specify after_ordinal exclusive, initial cursor value, next_ordinal for empty page, has_more while source still open, hard maximum page limit. Retain project_root in API — current read takes project_root; proposed signature silently drops it even though AS94 isolation boundary is project scope.

13. **Step 4 "do not duplicate final text" wording needs tightening (MEDIUM):** Genuine provider ASSISTANT_FINAL event belongs in sidecar; AS86 explicitly intends adapters to map assistant/final content into output events. Should say: do not synthesize additional sidecar event from selected durable request output.

14. **Keep selector separate from terminal-quality classification (MEDIUM):** Selector owns structural reconciliation and evidence sufficiency, not "does this answer look suspicious/incomplete?" heuristics.

**Downgraded from original concerns:**
- Multi-turn sessions: Mostly misses the mark — each subsequent prompt is new gateway request with existing session_id. API explicitly describes continuing conversation by submitting later request. AS86 scopes relay per turn and index by request/session/turn.

**Converged responsibility split:**
- AS86 tells AS87 exactly what durable output evidence belongs to which attempt
- Gateway finalization tells AS87 why execution ended
- AS87 only reconciles those facts into authoritative final output
- AS94 composes AS87's cursor read with metadata poll; must translate reported source-state, not re-derive gap/corruption facts

**Implementation-ready: NO.** Multiple HIGH blockers beyond simply waiting for AS86. Once Detailed Solution written and AS86 explicit blocker added, item becomes much tighter.
