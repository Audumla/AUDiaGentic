# Paged output read must expose typed source-state, and only that half blocks AS94

## Notes

External adversarial review 2026-08-09. Two findings. (1) Contract mismatch with AS94: AS94 requires deterministic output gaps for truncation/retention loss, corrupt indexed events and missing indexed events, but AS87's new paged reader as specified only promises ordered non-duplicated pages plus a limit. If the source does not surface gap/corruption information, AS94 would have to inspect relay files and the index itself — exactly what AS94's own composition rules forbid. (2) Dependency is over-broad: AS87 contains two independently useful pieces — the final durable-output selector (normal/partial/tool-only/cancel/timeout/conflicting selection) and the paged relay-output reader. Only the paged reader blocks AS94; the final-output selector is independent of it. AS94's current Blocked-by: AS93, AS87 is therefore safe but broader than the real dependency.

## Conclusion

Edit AS87 so its paged output reader returns a typed page/source-state contract covering next position, has-more, truncation/retention gap, and corrupt/missing indexed events — AS94 then merely translates those source outcomes rather than deriving them. This is the strongest technical reason AS87 must precede AS94. Optionally split AS87 into final-output-selection vs paged-relay-read if the dependency graph should reflect true implementation order; keep together only if minimizing item count matters more than parallelism, accepting that AS94 then waits unnecessarily on the selector.
