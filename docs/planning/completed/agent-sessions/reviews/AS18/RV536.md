# AS18 semantic_strength and event taxonomy review

## Notes



## Findings

1. **semantic_strength vs verification_tier conflation** — Step 4 says "Record semantic_strength separately from CapabilityEvidence verification_tier" but the description doesn't explain what semantic_strength is or where it comes from. This is a new concept not present in the existing CapabilityEvidence model (which uses verification_tier: unverified, documentation, installed-artifact, round-trip, execution). Either define semantic_strength explicitly or use only the existing verification_tier vocabulary.

2. **Good discipline on inventorying actual events** — Step 1's requirement to inventory real AcpEvent kinds is correct; prevents inventing mappings.

3. **Non-controlling observation** — The requirement that callback/timeline failure doesn't alter control flow is the right design.

## Conclusion

Major finding on semantic_strength; no blockers for implementation
