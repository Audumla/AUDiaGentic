# POSIX hard-parent-death guarantee has no named mechanism — name one or narrow the acceptance

## Notes

Source: external plan/code review 2026-07-18; assessed 2026-07-19. Windows Job Object adoption is implemented; the gap is POSIX only.

## Findings

P14: an in-process adopter cannot guarantee child-tree death after the gateway is SIGKILLed on POSIX — process groups and atexit do not provide it. The Linux Docker acceptance currently demands a property the proposed seam cannot deliver. Required decision, one of: (a) implement and NAME a real mechanism — wrapper/shim setting parent-death behavior (e.g. PR_SET_PDEATHSIG in an exec shim), an external watcher/supervisor, or cgroup/service-manager ownership; or (b) narrow the guarantee to graceful/exception cleanup plus identity-safe next-start orphan reconciliation, with an explicit statement that immediate descendant death after a hard gateway kill is NOT claimed. Related tests (with AS26): distinguish process-dead from process-unobservable; external processes are never signaled; owner-task finalization releases lock/slot exactly once.

## Conclusion

Holds with acceptance correction — pick mechanism (a) or narrowed guarantee (b) explicitly before implementation; do not leave the dishonest acceptance criterion in place.
