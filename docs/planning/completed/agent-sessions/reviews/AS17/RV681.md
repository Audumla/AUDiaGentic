# Foundation process evidence is one-signal in practice; ACP children have no hard-death supervision; Windows pid_alive conflates access-denied with dead

## Notes



## Findings

Verified in tree (2026-07-18), foundation/system unit tests green.

1. `ownership_matches` (managed_process.py:128) advertises 'PID plus at least one non-PID proof' across three comparisons, but `observe_process` only ever populates creation_identity — observed.command_fingerprint and observed.group_identity are always None, so those two comparisons are structurally dead. In effect ownership proof is exactly one signal, and when creation identity is unreadable (POSIX /proc denied → `ps lstart` fallback with 1-second resolution; Windows OpenProcess denied → None) stop/adopt degrades to refusal. AS17's adopt/observe/stop contract should either populate all declared comparisons or shrink the contract to what is actually observable per OS — the current shape claims redundancy it does not have.

2. ACP session children have no OS-enforced death-with-owner today. `spawn_agent_process` is SDK-owned; the gateway never assigns the child to a Job Object (Windows) or its own process group (POSIX). supervised_process.py has exactly the needed machinery but is unused on this path. Cleanup relies on transport.close()/atexit — which never runs on hard kill — so a hard-killed or crashed gateway orphans every live harness child tree on both platforms. This is AS17's core scope; flagging that the gap is present-tense and observable, not hypothetical: `AcpSessionTransport.open` exposes proc but SessionRuntime records no ProcessEvidence for it, so AS16 diagnostics and AS26 reaping have no process facts to consume either.

3. `pid_alive` on Windows (process.py:125) returns False whenever OpenProcess fails, conflating ERROR_ACCESS_DENIED (process alive, other user/elevated) with dead. Consumers that stale-break on 'holder dead' — StartupLock.__enter__ unlinks and steals the lock; managed-service owner logic that trusts pid_alive — will treat a live elevated process as dead. Low likelihood in single-user dev, real in shared/service contexts the shared-gateway plan is heading toward. Distinguish 'dead' from 'unknown' (check GetLastError; treat ERROR_ACCESS_DENIED as alive-unknown and stay conservative).

Implementation-ready direction: in the AS17 adopt seam, capture creation identity + group/job identity at adoption time from the live proc handle (not later by PID lookup), assign adopted children to a gateway-owned kill-on-close Job Object where nesting allows (reusing _assign_to_kill_job) / setpgid where the SDK spawn permits, and surface the resulting ProcessEvidence through the session record so AS16/AS26 have real facts. Make pid_alive tri-state or add pid_alive_strict for lock-stealing call sites.

## Conclusion

The supervision primitives are sound but unwired for the interactive-child path, and two of three ownership proofs plus Windows liveness have honesty gaps AS17 should close explicitly.
