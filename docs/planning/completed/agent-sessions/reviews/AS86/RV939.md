# gpt-auto review of AS86 - correct architecture but not implementation-ready

## Notes



## Findings

**Verdict:** Architecture correct, scope correct (L/advanced), AS87 should remain blocked. Not implementation-ready — contract details need tightening before starting.

**HIGH findings (blockers):**

1. **Step 1 should reuse existing OutputSink contract, not add new one.** foundation/transports/agent_output.py already defines OutputSink, ASSISTANT_TEXT_DELTA, ASSISTANT_FINAL, and is_final. Rewrite Step 1 as: Thread the existing foundation OutputSink through AgentSessionTransport.prompt().

2. **Final-output semantics undefined.** AgentOutputEvent.text must be non-empty, but providers may stream deltas then expose final response. Persisting both duplicates the answer. Specify whether ASSISTANT_FINAL is content or classification; prohibit re-emitting accumulated final after deltas.

3. **Durable ordinal change essential — current code has real defects.** Event with sequence=None not written at all. _persist_event() writes index before _index_state.update(), so durable index can lag the event just written. OutputStore.append() must allocate its own ordinal under request lock, write event, then advance index.

4. **open/closed/truncated/degraded are not mutually exclusive.** A relay can be closed+truncated or closed+degraded. Use orthogonal flags, not a single 4-value enum.

5. **"Storage failure persists degraded state" is impossible as unconditional guarantee.** If store failed, it may be impossible to persist the fact that it failed. Change to: marks relay degraded in memory and best-effort persists degradation metadata; never terminalizes agent execution.

6. **Timer coalescing underspecified.** OutputPolicy has only enabled/max_fragment_bytes/max_turn_bytes — no flush-delay setting or clock/timer seam. Add frozen setting (coalesce-max-delay-ms), define monotonic clock/timer abstraction, specify cancellation on close.

7. **Timer+provider writes+close introduce undefined concurrency.** Timer can race provider write or close(), causing duplicate/lost flushes. Relay mutation/flush/close must be serialized; close() idempotent; timer callbacks cannot persist after close.

**MEDIUM findings:**

1. Recovery's "adopts exactly once" too narrow — recover entire contiguous valid ordinal suffix or establish invariant that no further writes occur after index-advance failure.
2. Step 7 names identity fields not in AgentOutputEvent (no request_id/channel). Coalescing is within one relay already scoped to request/session/turn.
3. Source-sequence "range" {start:2, end:8} doesn't show gaps. Split coalescing on discontinuity or persist explicit gap indication.
4. Count/byte cap semantics need exact definitions (durable records vs incoming fragments, UTF-8 content bytes vs JSON bytes).
5. Strict config rules incomplete — explicitly reject non-boolean booleans, non-integers, zero/negative bounds, invalid kinds, inconsistent bounds.
6. On-disk compatibility policy unspecified for legacy unversioned index.json artifacts.
7. Crash model undeclared — process crash only or power-loss? File/fsync ordering matters for the latter.

**Positive findings:**
- Store consolidation (Step 4) well justified — current code has 3 independent readers/writers, one treats index.json as NDJSON then comments it's ordinary JSON.
- Step 9 fixes real behavioral bug — _accept_event() conflates rejected input with failed storage via outer exception handler.

**Recommended step amendments:**
- Step 1: Thread existing OutputSink through prompt()
- Step 2: Define delta/final normalization rule for non-duplication
- Step 3: Idempotent close in finally, faults never mask primary exception
- Step 6: Store allocates ordinal under lock; index carries lifecycle+truncated+degraded+gaps; define legacy handling and crash model
- Step 7: Coalesce consecutive compatible events; add timer policy and fake-time seam explicitly
- Step 9: Validation rejection is rejection; caps set truncated without terminalizing; persistence faults mark degraded in-memory
- Step 10: Add tests for delta+final non-dup, timer/write/close races, idempotent close, sequence=None, gaps, exact boundaries, recovery scenarios
