# Adversarial review of gpt-auto AS92 implementation design (req_b64740ac69804fb2)

## Notes

Adversarially reviewed the gpt-auto design (req_b64740ac69804fb2, outcome success) against the local tree. All structural claims the design got RIGHT were verified first (listed in conclusion); then every concrete schema/semantic detail was checked against the actual transport and transition paths. Findings A1–A8 below. A1 and A2 are critical: followed literally they produce a schema that cannot validate real snapshots and a test that asserts an impossible timestamp.

## Findings

A1 CRITICAL — schema draft vocabulary is fabricated vs local transport. The design's agent-status-snapshot draft uses decisions {interruptible, pausable, cancelable, retryable, progress-disposition}, lifecycle [queued, active, waiting, paused, terminal, unknown], scope [request], outcome [unknown, success, failed, cancelled, rejected, interrupted]. NONE of these match the actual transport (src/audiagentic/foundation/transports/agent_status.py, verified). Real vocabulary: decisions = {accepts-new-turn, session-reusable, turn-terminal, dependent-work-releasable, evidence-confidence [validated/candidate/contradictory/insufficient/rejected], reason} (serialized by snapshot_to_mapping status_projection.py:55-66; AgentStatusDecisions agent_status.py:105-119); lifecycle = [pending, active, waiting, completing, available, terminal, unknown] (agent_status.py:46-55); scope = [execution-request, session, turn, workflow] (agent_status.py:37-43) — the request snapshot serializes scope as 'execution-request', not 'request'; outcome = [success, failed, cancelled, interrupted, rejected, timed-out, expired, abandoned, superseded] (agent_status.py:58-69) — 'unknown' is not an outcome (outcome is None when non-terminal), and timed-out/expired/abandoned/superseded exist. The design's progress-disposition/interruptibility vocabulary exists only in queue/progress.py:295-308 (request_runtime_status progress dict), NOT in the agent-status snapshot — the design conflated two different surfaces. Fix: pin the schema to the verified transport vocabulary and add a transport↔schema parity test. A2 CRITICAL — rejected observed-at claim is impossible. Design (sec 7 and test matrix) asserts 'finished timestamp used as observed-at' for rejected. But rejected transitions (queue.py:431,475,552) call transition_record with updates={error:{...}} only; transition_record (store/_transitions.py:82-148) writes state/updated-at/revision + provided updates — it never writes finished-at. So rejected records have finished-at=None and observed_at falls back to updated-at via the existing terminal branch (status_projection.py:113). The generic 'use existing fallback order' advice is right; the specific test expectation is wrong. Either pin observed-at=updated-at for rejected (current behavior) or extend the rejected transition paths to write finished-at (bigger, separate change). A3 HIGH — snapshot_for_request signature mismatch. Design's internal sequence calls snapshot_for_request(record, session=..., lifecycle_decision=..., projected_at=...). Actual signature: snapshot_for_request(record, *, decision=None) (status_projection.py:77-81) — no session, no projected_at, param is named decision. The design's deterministic-test approach depends on a projected_at override that does not exist today. Fix: explicitly ADD a projected_at override to snapshot_for_request (small, additive) as part of AS92, or normalize timestamps in tests. A4 HIGH — session_record plumbing is speculative. The decision lookup only needs session-id string: latest_lifecycle_decision(session_id, request_id) (sessions.py:693-697) reads an in-memory evidence map by key; the current status path never reads a durable session record (api.py:563-583; _attach_agent_status api.py:216-235). snapshot_for_request has no session param. The design's _find_session_for_request + session_record param + list session-index is over-specified for V3. Fix: drop session_record from the V3 signature; keep the option only if GP14/V4 needs session facts. A5 HIGH — envelope decision supersedes design's metadata-in-schema. The design treats metadata as an optional field INSIDE the V3 response schema (routed via AS102). The 2026-08-17 envelope decision (GP14) places harness/deeper metadata in a sibling `metadata` sidecar, NOT inside the canonical `result` schema. Fix: AS92's V3 `result` schema declares NO metadata slot; AS102 owns the sidecar. A6 MEDIUM — now_iso_z consolidation incomplete. Design covers status_projection.py's private _now_iso (3 uses, status_projection.py:37/118/146/162). But snapshot_from_decision (session_lifecycle_projection.py:744) has an inline datetime.datetime.now(...).isoformat() duplicate. Fix: extend the consolidation or explicitly scope it out. A7 MEDIUM — list/get provider-turn-pending asymmetry breaks structural-equivalence test. get reconciles session provider-turn-pending via read_public_status (api.py:572-587), list uses project_public_status directly with only request-side provider-metadata. A running item with unresolved session turn would differ across surfaces. Fix: scope the equivalence test to the request-status portion (as the design partially does) and exclude session-reconciled provider-turn-pending until GP14/AS102 unify it. A8 MEDIUM — work-size rescope. Design recommends S→M-small/M. Defensible given added deliverables (2 schemas, version registry, consumer migration, golden fixtures), but code volume is small. Recommend M with a note, or keep S+ and split AS92a (projector fixes+shared projection) / AS92b (schema/version authority) as one coordinated train. VERIFIED CORRECT (design got right): rejected absent from _DURABLE_OUTCOME_MAP (status_projection.py:29-34) while workflows.yaml terminal includes rejected; AgentOutcome.REJECTED exists; _now_iso private copy 3 uses; _attach_agent_status:216 + get_execution_request:563 duplicate peek+decision; async submit returns raw record (api.py:555) without agent-status; list uses project_public_status without agent-status (api.py:739-747); project_public_status leaks metadata (visible list includes 'metadata', _records.py:536); peek_session_runtime no-side-effect (sessions.py:2679-2686); latest_lifecycle_decision read-only (sessions.py:693-697); _PUBLIC_RESPONSE_VERSION=3 (api.py:560); _public_session_projection copies record wholesale incl. provider.metadata (api.py:750-758); durable record schema contract-version const v5 + no agent-status + additionalProperties:false (agent-execution-record.schema.json); don't add agent-status to durable schema; no-fallback unsupported versions; V3 not composed from durable V5; read path creates no runtime; no AS92-owned sanitizer; get-first migration ordering; Phase-0 V3 inventory/golden fixtures.

## Conclusion

APPROVE WITH CORRECTIONS. The design's architecture is sound and its structural facts are accurate — but its concrete schema draft (A1) and rejected-timestamp expectation (A2) are factually wrong against the local transport and must be corrected before any implementation. A3–A5 are reconciliation fixes (projected_at override, drop session_record, envelope boundary). A6–A8 are scoping decisions. Incorporate A1–A8 into AS92; the corrected schema must be pinned to the verified transport vocabulary with a parity test. The design remains gated: incorporate findings, then implement per its 20-step sequence.
