# Current ChatGPT conversation-load error bypasses failure policy

## Notes

Added both current and legacy punctuation variants to the conversation-load-failed signal and added regression coverage for the production configuration plus both text forms in the snapshot harness.

## Findings

Live CDP validation showed the provider page text "Could not load this ChatGPT conversation" without a trailing period. The packaged workflow matched only the punctuated variant, so response-failed did not trigger. The request emitted response-observing heartbeats every 30 seconds, renewed the gateway activity lease, and remained running on an unchanged error page. This is a confirmed provider-DOM regression and a false-progress risk.
