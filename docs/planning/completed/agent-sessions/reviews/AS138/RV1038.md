# Generic ChatGPT request-error alerts need bounded same-session continuation

## Notes



## Findings

- Current dispatch only follows up the exact network-error-alert signal; generic request-error-alert is terminalized even when the durable session remains non-terminal.
- The provider already records request-scoped DOM/error evidence and can release the unresolved-turn fence, but no workflow-configured continuation policy exists for this alert class.
- Recovery must remain conservative: reconcile/observe any completed assistant response first, preserve the failed attempt and failure evidence, and allow at most one same-session continuation only when durable session disposition is non-terminal.

## Conclusion

Implement a separate provider-error-followup policy and reuse the existing same-session recovery machinery with explicit reason/timeline evidence.
