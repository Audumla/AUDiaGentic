# gpt-auto review of AS85 - correct architecture but significant runtime gaps

## Notes



## Findings

**Verdict:** Architecture direction correct, description/defect statement good. **Not implementation-ready.**

**After discussion with reviewer, revised findings:**

1. **Admission ownership (HIGH — biggest blocker):** AgentTaskFactory currently resolves Agent Definition itself and drops the role entirely — only execution-profile ID reaches gateway. Step 1 must be rewritten: Move Agent Definition selection to authoritative gateway admission boundary. Add optional `agent-id` and `agent-role-id` to canonical submission contract. AgentTaskFactory, MCP and event adapters pass selectors through unchanged and perform no Agent Definition, Role, or manifest resolution.

2. **Admission compatibility mechanism (HIGH):** AS84 owns *what* a capability requirement means and how evidence satisfies it. AS85 must own *when* and *against what resolved execution context* the AS84 resolver is invoked, plus fail-closed semantics: any unmet requirement = typed admission rejection; no warning, partial-success manifest, profile override, role override, or dispatch-time retry.

3. **Session reuse violates least-capability (HIGH):** Sessions open long-lived transports/processes reused across requests. Turn 1 under Role A with MCP X cannot serve continuation under Role B without X. Role-manifest fingerprint must be part of session binding identity; different manifest requires rejection/new session.

4. **Resume has no durable source for role manifest (HIGH):** Current resume recomputes from live config. Must persist versioned typed role-manifest, agent-role-id, and role-manifest-fingerprint in session binding or request record; make resolvable forever.

5. **Role behavioural content snapshot story (HIGH):** Role instructions/output_guidance have no immutable admission-time snapshot — same "resolve twice → drift" defect applies. Either include in scope or explicitly exclude with owning item named.

6. **Execution-profile precedence with agent-id (HIGH):** Once agent-id reaches admission it brings both role AND execution profile. Complete precedence matrix needed:
   - Role axis: 1) explicit agent-role-id, 2) role from agent-id, 3) temporary role-less default
   - Execution axis: 1) explicit execution-profile-id, 2) explicit provider/model, 3) execution profile from agent-id, 4) default execution profile
   - Both selections composed and compatibility-checked in same admission operation

7. **Naming invariant automated assertion (MEDIUM):** Public submission/event contracts must use `agent-role-id` exclusively for role selection. No `role-id`, `role_id`, or alternate public alias accepted/emitted; asserted from registered schemas. Scope: gateway submission, durable request-event, lifecycle-event, and public task submission schemas only.

8. **Worker enforcement model (MEDIUM):** Both disposable-worker and session-launch paths must consume same immutable contract. Default-deny role-controlled baseline defined.

9. **Terminology collision with ExecutionManifest (MEDIUM):** Use `agent-role-id`, `role-manifest`, `role-manifest-fingerprint` consistently — never generic manifest/fingerprint.

10. **Idempotent redelivery after Role deletion (MEDIUM):** Must return already-admitted request without re-derivation.

11. **Free-instance dispatch compatibility (MEDIUM):** AS101 permits multiple eligible model instances per Execution Profile. If AS84 defines requirements that differ between instances, AS85 must either prove all eligible instances satisfy the requirement or persist a narrowed eligible-instance set at admission.

**Downgraded from original concerns:**
- Manifest internal shape is AS84's problem (not AS85's)
- Bespoke conflict classes in AS85 would duplicate AS84's vocabulary (wrong fix)
- Deleted/renamed roles are what resolve-once makes irrelevant by design (mostly an anti-drift test)

**Converged responsibility split:**
- AS84: defines capability meaning, evidence predicates, and pure resolution
- AS85: owns selector precedence, authoritative admission invocation, persistence, transport, fail-closed composition, enforcement of frozen result
- AS104: role-less compatibility policy gates
- AS101: free-instance dispatch (compatibility with role requirements)

**Implementation-ready: NO.** Once boundary/session points written into Detailed Solution and Step 1 rewritten to move Agent Definition selection to gateway admission, item becomes much tighter — doesn't need to grow beyond M/advanced.
