# Session lifecycle publication drops correlation metadata

## Notes

Post-completion implementation audit against Architecture Standards, Architecture Guidelines, Observability Standards, plan intent, and reuse-before-build doctrine.

## Findings

HIGH — AS12 published session lifecycle events with `get_bus().publish(topic, payload)` and discarded the request correlation chain. The session and AS18 turn topic registrations also declared no correlation metadata, so EventEnvelope/timeline consumers could not join session activity to the originating request. The event transport and timeline primitives already support this metadata.

## Conclusion

Resolved by threading the existing request `correlation-id` through session open and prompt calls, publishing it as canonical EventBus metadata, and recording it on session/turn timelines. Session close/failure retain the opening correlation on the live handle. Topic declarations now advertise correlation metadata, and AS18 declarations include the already-required semantic/verification fields. No new event path was added. Focused session, queue, gateway integration, and event-topic validation passes (57 tests).
