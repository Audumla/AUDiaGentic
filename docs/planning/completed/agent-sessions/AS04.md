# Sessionful dispatch routing + provider ACP-launch capability seam

## Description

Route session-flagged gateway requests to the SessionRuntime instead of the one-shot execute_provider path, through a provider-neutral capability seam. No provider-specific branches in dispatch (AG10 rule stays intact).

## Steps

1. Capability seam: providers.services.execution grows _load_acp_launch_builder(provider_id) mirroring _load_runner — an adapter that supports live ACP sessions exposes module attribute build_acp_launch(project_root, *, model_id) -> AcpLaunch (opencode already has this in adapters/opencode/acp.py). A session request against a provider without the attribute fails terminal with a registered UNS code ('provider does not support live sessions').
2. dispatch_request: if record has session-id or session.keep-alive → dispatch_session_request (new function, same module): resolve profile/provider/model exactly like _dispatch_one_attempt, then (a) keep-alive without session-id: SessionRuntime.open_session then prompt_in_session; result includes the new session-id; (b) session-id present: validate the session exists, is active, and its agent-profile-id matches the request's (registered VAL code on mismatch — a conversation cannot silently switch models); prompt_in_session.
3. NO retry/fallback on the session path: a failed turn fails the request (retrying inside a stateful conversation is not idempotent; fallback to another profile would silently drop context). Document in the dispatch docstring beside the AG10 rules.
4. Session turn results flow into the normal terminal transition (completed/failed) with provider-id/model-id/output/completion/usage populated from the AcpResult events (assistant-message text concatenation for output; stop_reason recorded); record['session-id'] persisted on the request record; session record's request-ids appended.
5. Queue interaction: sessionful requests still go through GatewayQueueManager (per-profile concurrency respected); per-session serialization is enforced by the runtime (AS02) — a busy-session rejection surfaces as the registered CON code, terminal.
6. Cancellation: cooperative pre-turn check as today; an in-flight turn is cancelled via the transport cancel_signal (protocol cancel then bounded termination) — note this kills the session (state failed, close-reason 'cancelled-turn'); document.

## Files

src/audiagentic/components/agents/agents_gateway_dispatch.py; src/audiagentic/components/providers/services/execution.py (capability loader only); error catalogues (UNS/VAL/CON codes)

## Validation

Unit tests with fake runtime + fake launch builder: keep-alive creates and reuses session across two requests with context (fake transport echoes turn count); profile mismatch rejected; unsupported provider terminal UNS; no fallback attempted on session path; cancel during turn closes session and fails request.

## Effort & Risk

Mid. Risk: result normalization from AcpResult events differs from CLI adapter's finalize_run shape — keep the gateway record contract identical (output/completion/usage keys), test explicitly.
