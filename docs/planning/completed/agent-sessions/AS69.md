## Validation

- every post-AS64 persistent generation freezes composition identity/digests;
- changed incompatible Agent Definition, Role, Execution Profile or effective
  capability cannot silently continue or resume a generation;
- unknown (pre-migration) composition context rejects exact-compatibility
  operations rather than defaulting to permitted;
- composition-context separation is covered by the same Windows/Linux direct
  matrix that already covers identity-context separation;
- external ACP/A2A IDs remain mappings above the binding and expose no provider
  ref or composition internals;
- redacted events carry digest prefixes only;
- no new store, index or context authority is introduced.

## Goal

Freeze the agent-composition identity of an Interaction Session generation on
its AS30 binding record, and reject continuation, resume and attach when that
composition has changed incompatibly.

Store public IDs and digests only. Never store raw Role instructions, tool
policy, model secrets, provider credentials or Agent Card content.

## Fields

Persisted on the AS30 binding record, using the repository's actual naming
convention:

```text
agent-definition-id
agent-definition-generation-or-digest
role-id
role-generation-or-digest
execution-profile-id
execution-profile-generation-or-digest
effective-capability-digest
```

These are authorization/compatibility evidence only. AS69 does not load,
resolve, merge or mutate Agent Definitions, Roles, Execution Profiles or
capability sources — it records what AS60/AS61/AS62/AS64 already resolved.

The existing SH02 execution-context fingerprint remains authoritative for
workspace/provider/model/component/runtime context. Composition digests
supplement it; they do not create a competing execution-context record.

## Work

1. Evolve the existing session schema in place — one schema version that adds
   the composition block to the existing protected `binding` object. Do not add
   a parallel record or alias fields.
2. Extend the SessionRuntime open transaction: resolve the AS60/AS62
   composition snapshot alongside the AS29 surface, then persist the immutable
   composition context with the binding in the same transaction. Rollback
   behavior is unchanged — a failed persist still closes the provisional owned
   transport and leaves no index entry.
3. Extend collision checks to compare composition context alongside provider,
   surface, identity context and exact opaque ref.
4. Extend the forbidden-fallback list with: changed Execution Profile, changed
   Role, changed Agent Definition, and skill-name substitution.
5. Bounded read migration: records created before AS60-AS64 have unknown
   composition context. Unknown context **rejects** continuation, resume and
   attach wherever exact compatibility is required, unless a one-time migration
   can derive the immutable values without re-resolving changed configuration.
6. Extend redacted binding lifecycle facts with composition digest **prefixes**
   only — never Role instructions, tool policy or raw Agent Card data.
7. Feed the frozen values to AS47 (same-generation continuation) and AS49
   (explicit resume) through the existing AS30 read seam. Neither gets its own
   composition lookup.

## Do not add

- an AgentDefinition, Role, ExecutionProfile, AgentTask, A2A task, external ACP
  session or runtime-instance store;
- a second execution-context record or fingerprint;
- definition versioning infrastructure or snapshot trees — IDs and digests only;
- composition resolution inside AS30/AS47/AS49.
