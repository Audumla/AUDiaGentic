## Public model

Expose two logically separate channels through one client-facing read surface:

- metadata/status events from AS48/AS19/AS21;
- user assistant output from AS31.

They may share an outer turn envelope/cursor response, but must retain separate event kinds, retention/gap states, redaction policy, and source sequence. Never merge assistant text into lifecycle evidence or metadata events.

Define a bounded public envelope containing only:

- request/AgentTask compatibility ID, Interaction Session ID and turn ID;
- public sequence/cursor;
- timestamp;
- channel (`status|output`);
- canonical redacted status event or assistant text fragment;
- next cursor, has-more, gap, truncated, and delivery state.

No provider ref, native event name, raw protocol payload, prompt, hidden reasoning, tool arguments/results, auth token, stack trace, Role instructions, Agent Definition internals, raw Agent Card, or control capability is present.

## Authorization and side effects

Use existing shared gateway canonical project-root validation, authenticated active client lease, and AS30 session/binding context. A reader must be authorized for the exact project/session/request-or-task.

Reads must not:

- create/open a runtime or provider transport;
- take the session turn/FIFO lock;
- renew execution lifetime or a process lease;
- advance queue/request/task state;
- cancel, steer, follow up, respond permission, delegate, resume, attach, or close;
- mark evidence consumed in a way that changes lifecycle;
- resolve a changed current Agent Definition/Role/Execution Profile into the session.

## Cursor, gaps, and reconnect

Use opaque/integrity-checked cursor semantics grounded in the AS48 metadata generation and AS31 output relay/index. Support bounded page reads and reconnect after client disconnect.

Return deterministic gaps for:

- metadata buffer expiry/service restart;
- output truncation/retention;
- corrupt/missing indexed output event;
- cursor generation/request/task/turn mismatch.

Do not claim durable replay for in-memory metadata. Output durability is only what AS31 proves. A client can always retrieve the final durable request/task status/output after terminalization through existing APIs.

Protocol adapters map their reconnect semantics onto this cursor; they do not invent stronger replay guarantees.

## Service/client/MCP surface

Add closed application/client/service operations and an MCP read tool only after pure read helpers and authorization tests pass. Prefer one operation with explicit channel selection or one combined ordered page; do not create SSE/WebSocket/push in this item unless the existing shared service already has a safe reusable streaming primitive.

AS65 may expose ACP session updates and AS66 may expose A2A task/status/artifact progress by polling, long-polling or adapting an existing safe stream. Neither may alter AS57 storage or cursor truth.

Polling/tailing cannot block prompt execution or hold global/session locks while waiting. Use bounded wait/long-poll only if it reuses an existing cancellation-aware service primitive.
