# Transport session lifecycle: AcpSessionTransport (open / prompt* / close)

## Description

Refactor foundation/transports/acp.py so the spawn→initialize→new_session→prompt→teardown pipeline is reusable across multiple prompts on one live child process, instead of being welded into the one-shot run_acp_prompt. This is the foundation for gateway-held persistent agent sessions (back-and-forth context retention) and later remote channeling. The neutral event contract (AGENT_TRANSPORTS.md, frozen per MA18) is NOT changed — only the lifecycle is extended; a review has been recorded on MA18 covering this extension.

## Steps

1. Introduce class AcpSessionTransport with async lifecycle: open() spawns the child (spawn_agent_process entered via AsyncExitStack, NOT async-with, so the process outlives a single call), runs connection.initialize + connection.new_session, stores session_id. prompt(text, *, on_event=None, cancel_signal=None) runs one turn and returns an AcpResult (same shape as today, per-turn event buffers). close() performs protocol-polite shutdown then bounded child termination: terminate → wait CANCEL_GRACE_SECONDS → kill; idempotent; never raises on double-close.
2. Per-turn bounded delivery: event buffer, byte budget, callback-failure isolation reset per prompt() call (extract today's emit/emit_error/emit_terminal closures into a per-turn _TurnPipeline so run-once semantics are preserved).
3. GatewayClient (permission default-deny, session_update forwarding) becomes session-scoped: constructed once at open(), routes updates to the CURRENT turn pipeline; updates arriving between turns are buffered into the next turn (or dropped with a counter — decide and document).
4. run_acp_prompt() is preserved verbatim in behavior as open→prompt→close over AcpSessionTransport — all existing semantics (default-deny permissions, malformed-update normalization, exactly-one-terminal-event, child-exit error codes) must hold.
5. Failure model: any child death mid-session marks the transport dead (is_alive() false); subsequent prompt() raises EXT-ACP-003-derived AudiaGenticError; close() still safe. New error code for prompt-on-closed-session (CON-ACP-00x) registered in error catalogues.
6. Keep this module provider-neutral and prompt-in/events-out only — no gateway, persistence, or coding-specific concepts (this transport will be reused for non-coding agent activities).

## Files

src/audiagentic/foundation/transports/acp.py; src/audiagentic/foundation/transports/__init__.py (export AcpSessionTransport); error catalogue YAML for new CON-ACP code

## Validation

Existing transport unit tests pass unchanged; new tests: two prompt() calls on one open transport reuse the same session_id and child process; close() terminates the child within grace; prompt() after close raises the registered code; run_acp_prompt equivalence (event sequence, terminal event, error normalization).

## Effort & Risk

Complex. Risk: subtle asyncio lifetime bugs (exit-stack vs async-with); mitigated by keeping run_acp_prompt as a thin wrapper so the one-shot path exercises the same code.
