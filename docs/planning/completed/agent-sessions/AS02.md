# Gateway SessionRuntime: registry, event-loop owner, idle/max-lifetime reaper, guaranteed cleanup

## Description

New module src/audiagentic/components/agents/agents_gateway_sessions.py owning live agent sessions inside the gateway process. Mirrors the GatewayQueueManager singleton pattern (module-level instance, process-lifetime). Non-negotiable requirement from the sponsor: process management must be tight — no leftover child processes under any exit path (explicit close, idle timeout, max lifetime, runtime shutdown, interpreter exit).

## Steps

1. SessionRuntime class: lazily starts ONE daemon thread running an asyncio event loop; all AcpSessionTransport objects live on that loop; sync gateway code interacts via asyncio.run_coroutine_threadsafe(...).result(timeout).
2. Registry: dict session-id → SessionHandle {transport, provider-id, agent-profile-id, launch, created-at (monotonic + wall), last-activity-at, idle-timeout-seconds, per-session asyncio.Lock (turns on one session are strictly serialized — a second prompt while one is in flight waits or is rejected with a registered CON code; decide: reject, to keep back-pressure visible)}.
3. Lifecycle API (sync-facing): open_session(project_root, agent_profile_id, *, idle_timeout_seconds=None) -> session record; prompt_in_session(session_id, prompt, ...) -> result dict + refreshes last-activity; close_session(session_id, reason: 'client-request'|'idle-timeout'|'max-lifetime'|'shutdown'|'failed'); list_sessions().
4. Reaper: a single periodic asyncio task (every ~30s) on the session loop; closes sessions idle past their idle-timeout (request-supplied, else gateway default DEFAULT_SESSION_IDLE_TIMEOUT_SECONDS = 900) and any session older than DEFAULT_SESSION_MAX_LIFETIME_SECONDS = 14400 (4h) regardless of activity. Both defaults module-level constants, overridable via agent-profile params (session-idle-timeout-seconds / session-max-lifetime-seconds) — config over code.
5. Cleanup guarantees: atexit hook + SessionRuntime.shutdown() close every registered transport with bounded termination; transport close is idempotent so double-paths are safe; a session whose child died is transitioned 'failed' and removed from the registry on next touch or reaper pass (no zombie registry entries).
6. Every open/close/expire/prompt writes a session store record + timeline event (AS03) so state is observable after the fact even though live handles are in-memory only.
7. Keep this generic: SessionRuntime knows nothing about coding, opencode, or planning — only AcpLaunch + transport. Provider resolution stays in dispatch (AS04).

## Files

src/audiagentic/components/agents/agents_gateway_sessions.py (new); src/audiagentic/components/agents/agents_gateway_api.py (module singleton accessor, shutdown wiring); error catalogue for new VAL/CON/RES session codes

## Validation

Unit tests with a fake transport: idle reaper closes at deadline; max-lifetime closes an active session; concurrent prompt on busy session rejected with registered code; shutdown closes all and is idempotent; registry empty after close; no thread leak (single loop thread).

## Effort & Risk

Complex. Risks: sync/async boundary deadlocks (never block the loop thread on sync store I/O — do store writes on the calling thread, not inside loop coroutines, or use run_in_executor); reaper racing an in-flight prompt (reaper must respect the per-session lock — never terminate a child mid-turn except on max-lifetime breach, which is documented as forced).

## Notes

IMPLEMENTED 2026-07-16 (Claude). agents_gateway_sessions.py: SessionRuntime with one daemon event-loop thread; all registry mutations loop-side (no registry locks); injectable clock + reap interval + transport factory. Defaults: idle 900s, max lifetime 14400s, reap every 30s (module constants; per-profile params session-idle-timeout-seconds/session-max-lifetime-seconds honoured via dispatch). Dead child → failed + deregistered (RES-AGW-003 on touch); shutdown + atexit close-all; failed open never leaks. get_session_runtime() module singleton.

REVISED per RV513 (sponsor feedback, same day): (1) turns now QUEUE FIFO per session on an asyncio.Lock instead of rejecting when busy — CON-AGW-003 repurposed to 'turn queue full' (waiter cap, default 8, SessionRuntime(session_queue_max=...)); queued turns re-validate liveness/lifetime after the wait; (2) the reaper closes QUIESCENT sessions only — a processing session or one with queued turns is never reaped; past max-lifetime a session stops accepting turns (CON-AGW-004), drains, then closes on the next sweep; (3) both bounds are overridable per request (session-idle-timeout-seconds / session-max-lifetime-seconds) and 0 DISABLES a bound (remote-control sessions). Tests: test_agents_gateway_sessions.py (16 tests incl. FIFO ordering, queue-full, zero-bound opt-out, drain-then-expire). OUTSTANDING for AS06/AS07: real-subprocess no-orphan proof.
