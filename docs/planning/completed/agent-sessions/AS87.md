# Final-output selector and internal output read

## Description

Reconcile the two disconnected output writes into one authoritative final result, and add the internal cursor read over the relay's event stream.

Today the durable request-record `output` field (written at terminal transition) and the `OutputRelay` sidecar stream are two independent writes with nothing reconciling them. There is no selector deciding what the public final output actually is when a turn is partial, cancelled, timed out, or produced malformed content.

## Steps

1. Build the final-output selector. It consumes bounded relay state, lifecycle/finalization facts, and the neutral turn result, and handles: normal assistant final; coalesced streaming text plus explicit final; partial text with transport failure; tool-only turn with no assistant text; cancellation; timeout; missing terminal output; malformed or conflicting content events.
2. Insufficient evidence returns a typed degraded/unknown result. Never fabricate success.
3. Transports and adapters cannot choose or persist the public final output directly — only the selector/AS86 OutputStore seam can. The authoritative terminal result is the request-owned final artifact plus a bounded record preview; the durable record never becomes a second full-response store.
4. The durable request-record `output` field remains the authoritative public result. Do not duplicate final text into sidecar events merely because a final request output exists.
5. Add `read_request_output(request_id, after_sequence, limit)` — a cursor read with a page limit over the relay's events, returning a typed page/source-state result: next position, has-more, and explicit truncation/retention-gap and corrupt/missing-indexed-event outcomes (RV925). Today's `read_request_output(project_root, request_id)` has neither the cursor nor the typed state. AS94 composes this surface and must translate the reported source-state rather than re-deriving gap/corruption facts by inspecting the relay files or index itself.

**Critical gaps requiring Detailed Solution sections:**

1. **Selector input contract must consume AS86's OutputStore authority.** No inspecting event files or index independently. Hidden issue: no common "neutral turn result" exists — queue path deals in provider result dicts, session path receives typed SessionTurnResult.final_summary. Needs small gateway-owned normalization (TurnFinalizationFacts) before selector can serve both paths.

2. **AS86 explicit blocker required.** Selector assumes production relay wiring, coalescing, final flush, durable ordinals, gap state, recovery, single-reader store — all AS86 work. Must be `blocked_by: AS86`.

3. **Selector output type needs concrete shape:** FinalOutputSelection(text: str | None, disposition: selected | no-output | degraded | conflicting, reason: closed enum). Specify where non-text disposition survives durably — dedicated record field or bounded completion metadata.

4. **Cursor read must use durable ordinal, not after_sequence.** API:
   read_request_output(project_root, request_id, after_ordinal, limit)
   Delete stale verification note about "20-digit zero-padded" filenames — current code writes f"{event.sequence}.json" and lexically sorts (10.json before 2.json). Retain project_root in API — AS94 isolation boundary is project scope.

5. **Selector ordering relative to terminal transition must be explicit:**
   transport/provider finishes → relay final flush/close → obtain frozen OutputStore finalization state → run pure selector → exactly one fenced terminal request transition
   Crash window between relay close and request transition needs defined policy.

6. **Bounded final output required in steps.** dispatch.py reads result.get("output") directly with no bound. Caps in AS86 protect only sidecar, not authoritative field. Must have explicit byte bound derived from frozen output policy; define what happens when candidate final exceeds it (truncate with explicit state, reject and degrade, etc.).

7. **ASSISTANT_FINAL semantics undefined.** Contract never says whether ASSISTANT_FINAL.text means complete final answer, final delta, or terminal summary. Cannot handle "coalesced streaming text plus explicit final" deterministically until normalized.

8. **Reconciliation precedence needs deterministic algorithm.** Cases enumerated (relay text A vs neutral B, truncated relay but complete neutral, deltas without final, etc.) but no expected results defined.

9. **Retry-attempt contamination (AS86 blocker with AS87 rule):** Queue dispatch can execute several provider attempts for single request.
   - AS86: Every stored output event carries attempt_epoch in StoredOutputEvent and OutputStore/index identity. Recovery preserves attempt boundaries; output from one attempt never adopted into another.
   - AS87: Final-output selection consumes relay state for owned terminal attempt only. Prior failed/retried attempts never eligible for durable public final output.

10. **Timeout and interrupted scenarios need gateway-owned normalized finalization input:** TurnFinalizationFacts containing terminal_state + termination_reason (NORMAL, CANCELLED, TIMEOUT, TRANSPORT_FAILURE, EXECUTION_FAILURE, INTERRUPTED). Gateway terminal state alone insufficient; raw provider stop reason too low-level.

**MEDIUM findings:** "Retention gap" ahead of storage contract (add retained-range semantics to AS86 or remove as separately knowable), cursor semantics incomplete after ordinal change (after_ordinal exclusive, initial cursor, next_ordinal for empty page, has_more while source still open, hard maximum page limit), Step 4 wording needs tightening (don't synthesize sidecar event from selected durable output), keep selector separate from terminal-quality classification.

**Converged responsibility split:**
- AS86 tells AS87 exactly what durable output evidence belongs to which attempt
- Gateway finalization tells AS87 why execution ended
- AS87 only reconciles those facts into authoritative final output
- AS94 composes AS87's cursor read with metadata poll; must translate reported source-state, not re-derive gap/corruption facts

**Implementation-ready: NO.** Multiple HIGH blockers beyond simply waiting for AS86. Once Detailed Solution written and AS86 explicit blocker added, item becomes much tighter — doesn't need to grow beyond M/intermediate.

## Codebase Verification 2026 08 05

**Verified against the tree. The "two disconnected writes" premise is confirmed, and the disconnection is total.**

The durable write: `gateway/queue/dispatch.py:299-305` takes `output_text = result.get("output")` straight from the provider result and returns it for the terminal record transition. It consults no relay state whatsoever.

The relay write: `gateway/output.py`'s `OutputRelay` persists per-event files and an index under `<request-dir>/output/`.

**Nothing joins them.** A repo-wide scan for callers of `read_request_output` or `get_turn_summary` outside `output.py` itself returns **zero hits** — the relay's persisted stream is written and never read by any production path. So the selector this item builds is genuinely absent, not merely incomplete, and `OutputRelay.get_turn_summary()` (line 494) is currently dead code awaiting exactly this consumer.

**Implementation note for step 5:** the existing `read_request_output(project_root, request_id)` (line 548) reads *all* events by listing and sorting the events directory. Adding `after_sequence`/`limit` is a natural extension of that listing rather than a rewrite — event filenames are 20-digit zero-padded sequences, so a cursor filter is a filename comparison, not a full parse of every file.

**Terminal-result decision (AS86/AS87/AS94):** the gateway now persists the exact final response at `request/output/final-response.txt` before the fenced terminal transition. The request record carries only `{response-artifact, output-preview, output-truncated}`; the artifact is the authoritative full result and the public status remains bounded and stable.
