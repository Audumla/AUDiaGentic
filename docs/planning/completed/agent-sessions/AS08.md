## Description

Complete only the agents-owned session integration that remains after SH04 moved GatewayApplication and SessionRuntime into the standalone shared service. Bind every live/durable session generation to its immutable SH02 execution context so a second authorized client can continue it without silently changing provider, model, component profile, runtime digest, or project. Shared-gateway/foundation retain service, lease, discovery, request, worker, and lifecycle ownership.

## Steps

1. Reuse ExecutionManifest/context-fingerprint as the session context identity; do not invent another identity model. 2. Persist the manifest/fingerprint linkage and project identity on session creation. 3. Require an exact match on every continuation and reject mismatches with a stable registered error. 4. Keep per-session FIFO and owned/external cleanup unchanged. 5. Consume SH06 worker isolation, SH07 recovery, and SH10 drain/lease behavior; do not duplicate them. 6. Correct provider launch access through providers_api under the existing AS04 boundary review. 7. Add standalone two-client, changed-context, project-isolation, concurrent FIFO, service-failure, and no-orphan tests.

## Files

Agents session store/runtime/dispatch and SH04 public application/client seams only; existing SH02 execution-context contracts; targeted unit/integration/Docker tests. No new daemon, discovery, PID journal, startup lock, generic service store, or worker framework.

## Validation

Client A opens a keep-alive fake-ACP session through the standalone service and exits; Client B continues the same generation with the exact context and FIFO semantics. Changed profile/model/component profile/runtime digest and Project B are rejected. Service/worker failure resolves deterministically through SH owners and leaves no owned child orphaned.
