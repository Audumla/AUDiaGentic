# Classify suspicious terminal agent outputs without LLM review

## Description

Add deterministic terminal-output quality classification for live agent/session requests so the gateway can distinguish clean completion from suspicious premature halt, partial final response, repetition loop, or content-capture anomaly without requiring human or LLM interpretation. This is diagnostic metadata only: do not change request terminal state, do not auto-resubmit, and do not read raw prompt/tool payloads. The motivating incident is SH07 C2 correction request req_03fdae3e068d46ad: the provider returned completed/end_turn with dropped-events=0 after substantial tool work, but the final request output ended mid-progress sentence and lacked the requested summary/self-review.

## Steps

1. Add a pure agents-local classifier module, suggested path `src/audiagentic/components/agents/agents_terminal_quality.py`.

Required frozen dataclasses/enums:
```python
class TerminalQualityLabel(StrEnum):
    CLEAN = "clean"
    SUSPICIOUS = "suspicious"
    PREMATURE_HALT_SUSPECTED = "premature-halt-suspected"
    REPETITION_SUSPECTED = "repetition-suspected"
    CONTENT_CAPTURE_SUSPECTED = "content-capture-suspected"
    UNKNOWN = "unknown"

@dataclass(frozen=True)
class TerminalQualitySignal:
    code: str              # closed vocabulary, e.g. "TQ-MISSING-SUMMARY"
    severity: str          # "info" | "warning" | "critical"
    message: str           # short operator text, no raw prompt/tool payload
    evidence: Mapping[str, Any]  # bounded scalar/redacted evidence only

@dataclass(frozen=True)
class TerminalQualityReport:
    label: TerminalQualityLabel
    confidence: float      # 0.0..1.0 deterministic heuristic confidence
    signals: tuple[TerminalQualitySignal, ...]
    classifier_version: str
```

Primary function:
```python
def classify_terminal_output(
    *,
    record: Mapping[str, Any],
    latest_turn: Mapping[str, Any] | None = None,
    session_event_summary: Mapping[str, Any] | None = None,
) -> TerminalQualityReport: ...
```
Do not import provider adapters, event bus internals, or planning code. The function must be pure and deterministic.

2. Classification inputs and boundaries:
- Allowed inputs: public request record fields (`state`, `output`, `completion.stop-reason`, `completion.dropped-events`, `completion.total-events`, `attempts`, `error`, `created-at`, `started-at`, `finished-at`, `session-id`, metadata keys), redacted latest turn projection, and a bounded session event summary if already available.
- Forbidden inputs: raw prompt body, tool arguments/results, provider refs, raw ACP payloads, hidden reasoning, raw transcript, full timeline content.
- If raw evidence is absent, return `UNKNOWN` or low-confidence signals rather than reading private files.

3. Implement deterministic signals:
- `TQ-NO-OUTPUT`: terminal completed with no output or output shorter than a small threshold after nontrivial event/tool count.
- `TQ-ENDS-WITH-PREAMBLE`: last non-empty output line ends with progress/preamble patterns such as `:`, `Now let me`, `Let me`, `Next`, `First,`, `I will`, `I'll`, `Updating`, `Now update`, `Now add`, `Now run`; match case-insensitively after stripping markdown punctuation.
- `TQ-MISSING-EXPECTED-CLOSEOUT`: request metadata or prompt-derived flags are not available, so implement only deterministic generic closeout checks: if output contains multiple progress markers (`Now`, `Let me`, `First`, `Next`, `run tests`) but no closeout markers (`Summary`, `Tests`, `Validation`, `Done`, `Self-review`, `Findings`, `Result`) then warning.
- `TQ-UNTERMINATED-MARKDOWN`: odd number of fenced code blocks, table header without row, or bullet/list line ending with an unfinished colon.
- `TQ-REPETITION`: repeated identical or near-identical lines above threshold, or repeated same progress phrase at least N times with little intervening substantive text.
- `TQ-DROPPED-EVENTS`: completion has `dropped-events > 0`; classify as `CONTENT_CAPTURE_SUSPECTED` unless output also has a clear closeout.
- `TQ-HIGH-EVENT-LOW-OUTPUT`: `total-events` above threshold (e.g. >500) and output below threshold (e.g. <500 chars), especially after tool events in `latest_turn`/summary.
- `TQ-STOP-REASON`: non-`end_turn` stop reasons (`max_tokens`, `cancelled`, `error`, unknown provider stop) produce warning/critical according to terminal state.
- `TQ-TOOL-AFTER-LAST-TEXT` only if the supplied event summary includes `last-assistant-event-sequence` and `last-tool-event-sequence`; do not parse raw timeline files in the classifier.

4. Add a small event-summary helper where existing session timeline projection already lives, likely `agents_gateway_sessions_store.py` or `agents_gateway_progress.py`:
```python
def latest_turn_quality_summary(project_root: Path, session_id: str, request_id: str) -> dict[str, Any] | None: ...
```
It must read only persisted redacted session timeline attributes and return bounded scalar fields: event-count, last-event-kind, last-event-sequence, last-event-at, last-assistant-event-sequence, last-tool-event-sequence, result-sequence, finished-at, stop-reason. No text, provider refs, tool names, args, outputs, or raw payloads.

5. Wire report projection into public diagnostics:
- In `agents_gateway_api.request_runtime_status()`, add `terminal-quality` only for terminal request records, using the pure classifier and the latest redacted turn/quality summary when a session id is present.
- In `wait_llm_request()`, when the returned record is terminal, add `terminal-quality` to the shallow response copy. Preserve existing behavior for non-terminal wait timeouts.
- In `project_public_status()` or a narrowly named projection helper, include only the report dict, not raw evidence. Evidence values must be scalar/bounded and redacted.
- Do not mutate persisted request records in this slice unless the existing public status contract already persists derived diagnostics. Prefer projection-only.

6. Add tests before/with implementation:
- Unit tests for the pure classifier in `tests/unit/agents/test_agents_terminal_quality.py` covering clean summary, empty output, progress-line ending, missing closeout, unterminated code fence, repetition, dropped events, high event/low output, non-end_turn stop reason, and the SH07 C2 incident shape.
- API/status tests proving terminal-quality appears for terminal status/wait responses and is absent for running/queued unless explicitly requested.
- Redaction tests: prompt body, provider-session-ref, provider-ref-key, tool args/results, raw payload keys, and long output excerpts must not appear in signal evidence.
- Session summary tests proving only bounded scalar sequence/kind/time fields are returned.

7. Add an integration-style fake ACP/session test if existing fake harness makes this cheap: a fake session emits many tool events, returns `end_turn`, and final output ending in `Now update ...:`. Assert request state remains `completed` but diagnostics label `premature-halt-suspected` or `suspicious`.

8. Do not implement automatic bump/resubmit. The output of this item is diagnostic evidence that a controller or future AS item may use to decide whether to ask a follow-up.

## Effort & Risk

Mid. The main risk is overclaiming semantic correctness from heuristics. Keep labels diagnostic, confidence-scored, and deterministic. False positives are acceptable if evidence is bounded and the request state remains completed; false negatives are acceptable for cases needing future provider-native stop signals. Do not make this an LLM judge and do not persist or expose raw content evidence.
