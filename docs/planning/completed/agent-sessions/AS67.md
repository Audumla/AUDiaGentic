# Simplify AS29 surface validation evidence to reference + validated flag

## Description

AS29's session-surface validation model is over-specified relative to what's actually used. `SurfaceValidationState` (5 states: declared/probe-required/validated/blocked/unsupported) and `EffectiveObservationLevel` (O0-O4, an undocumented 5-level ordinal ladder) both exist in `foundation/transports/session_surface.py`, but in practice ~20 of ~22 entries in `harness_observability_inventory.py` sit at `effective_production_level=O0`, nothing reaches O2/O3/O4, and the only real gating logic anywhere is two threshold checks (`effective_level.numeric >= 1` and `>= 2`). No code or comment documents what distinguishes O2 from O3 from O4. This is exactly the kind of evidence-tier/ceremony-field complexity [[feedback_keep_it_slim]] already rejected once for the provider capability model (PC06/RV865) -- it was never re-examined for AS29's own model, and user feedback in this session (2026-07-29) confirmed it was built without a grounded requirement.

User's actual original intent, stated directly: a reference (URL preferred, internal doc/test path acceptable) where the validation can be proven if queried, plus a simple indication that validation happened -- nothing more. Not an ordinal maturity ladder.

## Steps

1. Replace `SurfaceValidationState` + `EffectiveObservationLevel` with a single frozen `ValidationEvidence` type:

```python
@dataclass(frozen=True)
class ValidationEvidence:
    validated: bool
    reference: str  # URL preferred; internal doc/test path acceptable
```

2. Keep per-platform granularity (the one part of the current model that IS genuinely used -- Windows/Linux/macOS really do differ in what's been proven, confirmed concretely this session by AS40's real Windows binary-proof vs real Linux Docker E2E proof being genuinely different evidence). Each `PlatformEvidence` row becomes `{platform: str, evidence: ValidationEvidence}` instead of carrying its own `tool_version`/`validation_state`/`effective_level` triple.
3. Update `SessionSurfaceDeclaration` (`descriptors/session_surface_declarations.py`) to carry one top-level `ValidationEvidence` (surface-level) plus the simplified `platforms: tuple[PlatformEvidence, ...]`.
4. Update `validate_session_surface_declarations()`'s 5 rules (`session_surface_declarations.py:138-190`) to the simplified model: replace the O2+-requires-validated ceiling rule with just 'controls/content channels beyond basic open/close require `validated=True` at the relevant platform row'; keep the duplicate-key and content-channel-bounds rules as-is (unaffected by this change).
5. Update `resolve_session_surface()`'s ceiling checks (`session_surface_resolution.py:233-235,491,529`) to branch on `evidence.validated` instead of `effective_level.numeric` thresholds.
6. Update all ~22 entries in `harness_observability_inventory.py` -- collapse `declared_capability`/`effective_production_level`/`validation_state` triples to one `ValidationEvidence(validated=..., reference=...)` per entry, using real references where they exist (e.g. opencode's entry should reference `tests/e2e/agents/test_opencode_acp_e2e.py`) and honest `validated=False` with a `reference` pointing at the relevant probe doc (e.g. `docs/reference/PROVIDER_CAPABILITY_REFERENCE/harnesses/profiles/pi-acp-bridge-probe.md`) for anything not yet proven -- do not invent URLs.
7. Bump `agent-llm-session.schema.json`'s affected shape if `ValidationEvidence`/`PlatformEvidence` are schema-validated anywhere (check `foundation/contracts/schemas/` for a session-surface schema file, not just the session/binding one already found this session).
8. Update the `opencode.yaml`/`pi.yaml` (once AS29's pi-community-acp entry lands, see AS29's own notes) declarations to the simplified shape.
9. Update this session's AS29/AS30/AS41 guidance (plan items) that assumed the old shape -- specifically AS29's step 3 (platform evidence rows) and AS41's step 1 (inventory validation_state/effective_production_level assignment) reference the old fields by name and need rewriting once this lands.
