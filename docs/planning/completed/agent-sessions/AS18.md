# Wire ACP on_event callback: real-time intra-turn visibility into model phase and tool lifecycle

## Description

Wire AcpSessionTransport.prompt(on_event=...) into SessionRuntime so the gateway gains a first usable intra-turn observation slice. Normalize only the installed ACP adapter events needed to distinguish model activity and tool execution, preserving native provenance and correlation. Publish through the existing EventBus/topic registry and write best-effort per-turn timeline events. Events remain observational and cannot complete a turn, release a slot, or change session reuse policy in this item.

## Steps

1. Inventory the actual AcpEvent kinds emitted by the installed OpenCode ACP path; do not invent mappings.
2. Register the smallest normalized topic set needed by AS20: agents.turn.model.started, agents.turn.model.completed, agents.turn.tool.started, agents.turn.tool.completed. Add permission/output topics only if the installed adapter emits them and a targeted test needs them.
3. Pass on_event from SessionRuntime._prompt to transport.prompt and map events into a redacted evidence envelope containing request/session/turn correlation plus native kind/id.
4. Record semantic_strength separately from CapabilityEvidence verification_tier.
5. Publish through EventBus and record a best-effort per-turn timeline event; callback/timeline failure must not alter prompt control flow.
6. Ensure callback observation occurs before compact_events drops retained result events.
7. Add a fake-transport test for model→tool→model ordering, correlation, provenance, redaction, and non-controlling failure behavior.

## Files

src/audiagentic/components/agents/agents_gateway_sessions.py (_prompt method, pass on_event callback); foundation/transports/acp.py (verify callback semantics); new agents_gateway_observability.py or integration into existing events; tests/unit/agents/

## Validation

A fake transport emits model/tool events during a blocking prompt; subscribers receive the minimal normalized sequence with exact request/session/turn correlation and native provenance. Compact result mode does not suppress callbacks. Observer and timeline failures do not fail or complete the prompt. No prompt text, assistant output, tool arguments, or secrets enter events.

## Effort & Risk

Mid. Narrow wiring change. Risks are event-loop/thread boundaries, duplicate delivery, and accidentally coupling observation to turn control; all require targeted tests.

## Standards

Architecture Standards §§1,3,5; Observability Standards.

## Notes

Staged per RV532. AS18 enables visibility only. Completion arbitration, full event taxonomy, scheduler control, and O4 replay are follow-on work.

Per RV536: semantic_strength is a separate dimension from CapabilityEvidence verification_tier. Verification_tier rates the evidence source reliability (unverified→execution). Semantic_strength rates how precisely the event maps to model/tool activity: "precise" = explicit ACP protocol signal (e.g., tool_call function), "approximate" = inferred from token stream position, "coarse" = stdout-parse heuristic. Both dimensions are recorded independently; AS20 requires verification_tier >= installed-artifact AND semantic_strength != coarse for conservative optimization.
