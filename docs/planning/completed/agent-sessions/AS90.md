# Fix the Windows close() child-process orphan race

## Description

Harden Windows ACP shutdown so close returns after a bounded terminate/wait/kill/final-reap sequence. The cited real failure passed 10/10 now, so use a deterministic contract test rather than a reproducibility claim.

## Steps

1. Target AcpSessionTransport.close(), not AcpAgentSessionTransport.close().
2. Fake-process test: first wait times out, kill occurs, second bounded wait completes before close returns.
3. Reuse one private terminate-wait-kill-final-wait helper only where process ownership matches.
4. Keep stream/task close bounded; close Windows kill-job handle after direct child reap.
5. On final timeout emit a redacted diagnostic and preserve never-raises close; no polling/sleeps.
6. Repeat real Windows subprocess confirmation; update only an active baseline artifact if one exists.

## Detailed Solution & Technical Design

The helper is idempotent: terminate if live, bounded wait, kill if still live, bounded final wait, return reaped boolean. Tolerate already-exited processes and avoid sharing across wrappers that do not own the child or use different tree-kill semantics.
