# Robust host-process teardown — kill MCP/LSP child trees on exit

## Description

Harness host subprocesses (pi node, opencode) are spawned with plain subprocess.run and no OS-enforced teardown. When the python launcher exits abnormally (crash, kill, terminal close) the host and its stdio MCP/LSP grandchildren orphan and accumulate. Observed: 3 stale opencode.exe + 3 orphaned yaml-language-server, week-old pi node host. pi real-run path has NO tree teardown; opencode finally kills only rig_pid, not the host tree.

## Steps

1. Add foundation/system/supervised_process.py: a supervised_run() / supervised_popen() helper.
   - Windows: create a Job Object with JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE (ctypes), spawn host CREATE_SUSPENDED, AssignProcessToJobObject, resume. Kernel kills whole tree when the launcher dies/closes the handle — survives crash/kill.
   - POSIX: start_new_session=True (new process group); finally killpg(SIGTERM) then SIGKILL.
   - Always belt-and-suspenders kill_process_tree(pid) in finally.
   - Forward SIGINT/SIGTERM to child while running.
2. Wire pi runner real-run (agent_run.py:150) through supervised_run.
3. Wire opencode runner real-run (__init__.py:222) through supervised_run; keep rig_pid kill.
4. Fix _cmd_launch SIGTERM/atexit so host tree is reaped on signal, not just the rig.
5. Make kill_process_tree handle taskkill on the host plus stale-orphan sweep is out of scope here.

## Validation

Run pi/opencode host; Ctrl+C and hard-kill the launcher; assert no orphaned `audiagentic mcp`, yaml-language-server, or host processes remain. Add unit test for supervised_run teardown on POSIX (process group) and Windows job-object close.

## Effort & Risk

Mid. ctypes Job Object is the only robust Windows path; must spawn CREATE_SUSPENDED to avoid assignment race. Low blast radius — isolated helper, two call sites.
