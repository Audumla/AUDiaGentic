# Reassess rig lifecycle against managed-service foundation and generic harness

## Notes

Review triggered by the generic harness/model-projection refactor and completed PR05–PR07 managed-service foundation.

## Findings

PR04's remaining implementation direction would create a second lifecycle island. The current generic harness already owns only rig policy and calls runtime/rig/registry.py; however that registry still implements a parallel rig.json + PID-file client counter, image-name reaper, and destructive read_rig_state(expected_model=...). PR05–PR07 now provide the required generic authority: atomic start-or-attach, ownership proof, renewable leases, guarded drain/stop, stale-record recovery, and platform-tested detached-process handling. Retain the operational requirements (single machine rig, no cross-harness kill, model compatibility, decoy safety, hard-kill cleanup), but replace steps 3–6 and the registry design with an adapter over ManagedServiceLifecycle. HA07 changes model discovery/projection only; they do not change rig process lifecycle ownership.

## Conclusion

Update PR04 to a foundation-consuming migration. Do not extend PID files, registry-local locks, reapers, or watchdogs; remove that island once the rig adapter is verified.
