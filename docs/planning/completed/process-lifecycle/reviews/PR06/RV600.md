# PR06 store review: heartbeat revision-CAS conflicts with lease traffic; lease-expiry logic triplicated

## Notes

T3 review of src/audiagentic/foundation/system/managed_service.py and managed_service_contracts.py. Overall: reuse discipline is genuinely good (StartupLock, TransitionEngine, atomic_write_json, timelines, redaction denylist all reused, none reinvented); records are typed/versioned; epoch+revision CAS is correctly enforced on transitions.

## Findings

1) ManagedServiceStore.heartbeat (managed_service.py:153) requires expected_revision, but every client lease acquire/renew/release/expire also bumps revision. A real owner heartbeating on a timer will hit CON-MSVC-014 'stale managed-service writer' whenever any lease op interleaves, forcing a read-retry loop in every consumer. heartbeat mutates only health_facts and updated_at — epoch gating alone is sufficient to reject a deposed owner; revision CAS adds conflicts without protecting anything. Recommend: drop expected_revision from heartbeat (epoch-only, like renew_lease), and record the decision in the PR05 contract (see RV599). 2) Active-lease expiry-by-deadline is now implemented three times: ManagedServiceStore.expire_leases (managed_service.py:286), ManagedServiceShutdown._expire_due_unlocked (managed_service_shutdown.py:94), and the expire-all variant _expire_old_leases (managed_service_start.py:47) plus a fourth inline copy in ManagedServiceOwner.claim (managed_service_owner.py:60). Extract one pure helper in managed_service_contracts (e.g. expire_leases(leases, now=None) returning tuple+changed flag) and reuse it from all four sites so expiry semantics cannot drift. 3) Minor: acquire_lease rejects when state != 'running' with conflict 18 'service does not accept leases' — same error number as heartbeat's 'service does not accept heartbeats'; harmless but distinct messages under one code make error-resolution lookup ambiguous; consider distinct codes.

## Conclusion

Valid and implemented. Heartbeats are epoch-gated, lease expiry/history normalization is centralized and bounded, restart/claim reuse one canonical record helper, active lease authorization uses the same store authority, and heartbeat state rejection has distinct CON-MSVC-036 resolution. Host and Docker multiprocess tests pass.
