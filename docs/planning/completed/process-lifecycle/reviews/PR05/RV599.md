# PR05 contract gaps surfaced by PR06/PR07 implementation: heartbeat CAS semantics, lock-hold duration policy, Windows job-breakaway policy

## Notes

Post-completion T3 review of the ManagedProcess/ManagedService contract (docs/design/managed-process-service-lifecycle.md) read against the shipped PR06/PR07 implementation.

## Findings

1) The contract specifies one lock/transition authority but is silent on how long that lock may be held: the shipped start-or-attach holds the per-service StartupLock for the full launch + readiness handshake window (readiness_timeout default 15s, consumer-tunable) while the store lock timeout defaults to 30s. The contract should state the policy (bounded lock-hold with classified busy outcome for waiters, or explicit coupling rule readiness_timeout < lock_timeout). 2) Heartbeat concurrency semantics are unspecified: the contract lists heartbeat facts but not whether refreshing health facts participates in revision CAS. The PR06 implementation chose revision+epoch CAS, which makes owner heartbeats spuriously conflict with unrelated client lease acquire/renew traffic (every lease op bumps revision). The contract should state that health-fact refresh is epoch-gated only, or define the retry obligation. 3) Windows Job Object breakaway policy is not addressed anywhere in the design (grep for breakaway/Job Object finds nothing beyond lock-held launch proof), yet detached shared-service launch on Windows depends on CREATE_BREAKAWAY_FROM_JOB, and PR07's own validation shows real hosts deny it. The contract needs a declared degraded mode (service dies with starter; classified outcome) or a preflight rule. 4) No operator recovery operation is defined for a record whose live process can never be ownership-proven (e.g. OpenProcess denied across user sessions): attach raises permanently, stop returns ownership-unverified permanently. Define a guarded reset/adopt escape hatch (candidate owner: SH10 diagnostics).

## Conclusion

Valid and handled. The design now specifies epoch-only heartbeat semantics, the readiness/lock budget (readiness plus one-second margin must fit the lock timeout), and observable Windows Job Object degradation. A denied breakaway retries job-bound and records process scope=session-child rather than claiming full detachment. The live-but-unprovable owner recovery is incorporated into SH10 as an explicit record-only operator action that never signals the PID.
