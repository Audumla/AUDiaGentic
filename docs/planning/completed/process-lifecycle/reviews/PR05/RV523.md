# Elevate managed shared services to a first-class foundation lifecycle capability

## Notes



## Findings

PR05 identifies shared singleton services and lock-held leases, but treats them as one item among generic child-process concerns. The approved shared-gateway requirement needs a concrete reusable foundation abstraction for services that several harnesses connect to: durable service identity and state, owner-proofed process attachment, client leases, readiness/heartbeat, atomic start-or-attach, drain/stop sequencing, and safe observability. If gateway code implements those itself, the same lifecycle bugs will reappear in shared rig and future services.

## Conclusion

Retain PR05 as the architecture/contract item, explicitly define a foundation ManagedService capability, then create sequenced implementation items for (1) durable service records and client leases and (2) race-safe discovery/start-or-attach and guarded shutdown. Components retain domain admission/drain policy; foundation owns generic lifecycle mechanics.
