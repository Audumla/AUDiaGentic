# Explicitly started service owner registration gap found during SH04 integration

## Notes

SH04 is intentionally manual/explicit before SH05 automatic discovery. Its already-running host must publish current-process evidence and become the ManagedService owner without pretending to be a client-launched process.

## Findings

Confirmed and corrected. Added current_process_evidence for credential-free current-process identity and ManagedServiceOwner as the generic atomic claim/retire authority. Claim rejects a live proven owner, refuses an unprovable live process, recovers only dead/stale records with a fresh epoch, expires prior leases, verifies caller-supplied evidence, and publishes running endpoint/health state under the existing service lock. Retire requires matching epoch, a running/draining owner, zero active leases, and fresh ownership proof. No gateway concepts enter foundation.

## Conclusion

Implemented and validated with explicit owner, competing live owner, dead-owner recovery, lease-guarded retirement, and live current-process evidence tests. The SH04 host can now reuse foundation owner adoption rather than duplicating it.
