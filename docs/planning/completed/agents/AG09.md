# Gateway queue and profile concurrency

## Description

Implement simple in-process Agent LLM Gateway queueing with per-profile concurrency, minimal gateway param validation, and clear best-effort cancellation semantics. V1 is not a durable worker system; queued/running work is owned by the current process, with persisted state for visibility and later status/wait calls.

## Steps

['Add agents_gateway_queue.py with GatewayQueueManager, per-profile FIFO queues, per-profile semaphore/capacity, request handles, and worker startup on demand.', 'Add small gateway params resolver for known keys only: max_concurrency integer >=1, queue_max_size integer >=1, timeout_seconds positive number, retry_count integer >=0, fallback_profile_ids list[str]. If a known key is present with invalid type/range, raise AudiaGenticError. Do not reject unrelated params keys.', 'Resolve max_concurrency from profile params.max_concurrency, default 1.', 'Resolve queue_max_size from profile params.queue_max_size, default max(8, max_concurrency * 2).', 'On manager startup, do not attempt durable recovery. If persisted non-terminal records from a prior process are discovered during status/startup, mark them stale/abandoned or return a clear stale state; do not silently re-enqueue old work in v1.', 'On submit: persist accepted/queued state, enqueue if capacity exists, otherwise reject with state rejected and AudiaGenticError code.', 'On worker start: transition queued to running only after semaphore acquired.', 'Support cancel: remove queued item when possible and mark cancelled.
