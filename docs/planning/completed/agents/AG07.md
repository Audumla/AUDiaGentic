# Agent LLM gateway design overview

## Description

Concrete v1 design umbrella for adding an isolated Agent LLM Gateway to the existing agents component. The gateway accepts asynchronous submit/poll requests, blocking run/wait requests, and event-triggered requests. It should stay easy to remove: new gateway files, audiagentic-scoped MCP tools, optional event observer, and descriptor entries only. Inspect agent-jobs for reusable ideas/helpers, but do not generalize or refactor agent-jobs unless reuse is trivial and keeps rollback simple. V1 uses prompt-body because current provider adapters consume packet_ctx['prompt-body']; raw messages support is out of scope.

## Effort & Risk

Complex. Main architectural risk is duplicate state/store behavior with agent-jobs. Mitigation: explicit AG07 decision gate before AG08; prefer reuse/generalization if overlap is substantial. Process lifetime remains a risk: in-process workers are fine for MCP/server processes but not durable across one-shot CLI exits. Persisted queued/running/terminal state makes this visible; durable external worker remains later process-lifecycle enhancement.
