# Gateway provider dispatch and fallbacks

## Description

Wire queued gateway requests to provider execution through the providers component, merging agent profile provider/model/params into a neutral packet context. Keep v1 conservative: use current adapter contract, simple retry/fallback, no broad provider catalog enforcement unless existing model resolution already provides it.

## Steps

['Resolve profile with agents_api.resolve_profile or resolve_default_profile.', 'Validate provider enabled via providers provider_config.is_provider_enabled before dispatch.', 'Resolve model selection via providers.services.models.resolve_model_selection where applicable. Do not add new provider catalog refresh/availability machinery in v1.', 'Build neutral packet_ctx containing request-id, agent-profile-id, provider-id, model-id, model-alias, prompt-body, params, source, and metadata. Do not include messages in v1.', 'Call providers.services.execution.execute_provider(provider_id=provider_id, packet_ctx=packet_ctx, provider_cfg=provider_cfg).', 'Normalize provider result from actual fields: output, completion, status, model, stdout, stderr, returncode, usage optional.', 'Classify AudiaGenticError by code/kind families where practical: network/timeout/capacity/transient provider failures may retry; validation/config/missing profile/disabled provider/model resolution errors do not.', 'Catch unexpected non-AudiaGenticError exceptions at the gateway dispatch boundary, log exc_info=True, and record terminal failure without raw prompt/provider output leakage.', 'Implement retry_count for transient failures only, default 0 or 1 per agreed profile params.', 'Before each retry/fallback attempt, check cancel_requested; if set, stop retry/fallback and preserve best-effort cancel_requested state.', 'Implement fallback_profile_ids from request override or profile params.fallback_profile_ids, preserving attempts list.', 'Never fallback on unknown profile, disabled provider, invalid request, model resolution error, or safety/config validation failures unless future explicit policy says so.', "Set source='event-bus' for event-triggered requests when no source is provided.", 'Add tests using injected fake execute_provider to prove context shape, keyword call, retry, fallback order, result normalization, unexpected exception handling, cancel during retry, and terminal failure behavior.']

## Notes

Implemented agents_gateway_dispatch.py: dispatch_request(project_root, record) is the RequestRunner used by AG09's queue manager. Per-profile flow: resolve_profile -> is_provider_enabled check (VAL-AGW-031 if disabled, terminal) -> load_provider_config()['providers'][provider_id] -> resolve_model_selection -> execute_provider(provider_id=..., packet_ctx=..., provider_cfg=...) using KEYWORD args (RV13 fixed the positional-call error in the plan text). packet_ctx built from confirmed real fields (request-id, agent-profile-id, provider-id, model-id, model-alias, prompt-body [not messages, per RV12], params, source, metadata). Result normalized from confirmed adapter fields: output, completion, usage, model, provider-id.

Failure classification (RV13's 'pin the taxonomy to real adapter codes' finding) is driven by the canonical PREFIX-COMPONENT-NNN prefix from foundation.contracts.errors.ERROR_CODE_PREFIXES (the exhaustive, enforced set) rather than string matching: VAL/RES/CON/CFG/VER/UNS = terminal (no retry, no fallback); NET/TO/EXT/INT/IO = transient (retry then fallback). Retry: resolve_retry_count from profile params.retry-count (default 1, i.e. up to 2 tries), validated (VAL-AGW-030) rather than silently defaulted, same pattern as AG09's params validation. Fallback: candidates = [agent-profile-id, *fallback-profile-ids]; only advances to the next candidate after the current profile's retries are exhausted on a TRANSIENT failure; a terminal (validation_config) failure at any point returns immediately with exactly one attempt recorded — no fallback profiles tried, matching AG10's explicit 'never fallback on validation/config' rule and its own validation criterion.

Every attempt (success or failure) is recorded via agents_gateway_store.append_attempt, preserving per-profile provenance in the final record's attempts list.

Known limitation documented in the module: RES covers both 'not found' and 'rate limited' per its official description: 'Resource: not found, quota exceeded, rate limited, empty result' — classified terminal here because AG10 explicitly calls out unknown-profile (RES-AGP-001) as a no-fallback case; a future rate-limit-flavored RES code would currently misclassify as terminal too. No adapter emits one today (rate limits surface as NET-*/TO-*/EXT-* in the existing adapters) so this is not yet a live issue.

7 unit tests in tests/unit/agents/test_agents_gateway_dispatch.py: classification across all 11 canonical prefixes, packet_ctx shape assertion against a fake execute_provider, retry-then-succeed, fallback-after-retries-exhausted, no-fallback-on-validation-error (exactly one attempt), disabled-provider-is-terminal-no-fallback (fake execute_provider never called), and retry-count param validation. All passing; full tests/unit/agents suite (52 tests) green.
