# Gateway event trigger and lifecycle events

## Description

Add minimal event-driven Agent LLM Gateway integration. Event callers publish a request event and receive queued/started/completed/failed/cancelled/rejected lifecycle events using request-id and correlation_id for matching. Follow existing component observer pattern: descriptor imports observer module; module self-registers safely and idempotently.

## Notes

Two pieces: (1) generic lifecycle events fired by agents_gateway_queue.py itself (_publish_lifecycle_event helper) at every transition point — queued, rejected (queue full), started, and completed/failed/cancelled (read off whatever terminal state the runner/dispatch actually produced, including a mid-dispatch cancel) — for EVERY request regardless of origin (MCP-submitted or event-triggered), since this is the single choke point all requests pass through. metadata is carried straight from record['metadata'], so EventEnvelope auto-extracts correlation_id/subject per AG12 spec with no extra plumbing. (2) agents_gateway_events.py: the INBOUND trigger only — subscribes to agents.llm.requested, normalizes payload (project-root/prompt-body required; agent-profile-id/fallback-profile-ids/source optional; blocking flag opts into mode='blocking', default async) into agents_gateway_api.submit_llm_request, and republishes agents.llm.rejected (with no request-id, since no record exists yet) for a malformed payload instead of silently swallowing it via the bus's generic subscriber-error catch.

RV18 finding on deferred registration: investigated and NOT adopted. get_bus() is a plain lazy singleton (foundation/event/event_bus.py get_bus()) with no initialization-order dependency, and import-time self-registration via a register()+_REGISTERED-flag guard is the codebase's own established, working pattern (audiagentic.components.memory.memory_observer, audiagentic.components.coding_lsp.coding_lsp_bootstrap both do exactly this). Followed that convention rather than RV18's speculative caution; documented the reasoning in the module docstring.

RV18 payload-validation finding applied: missing prompt-body or project-root rejects cleanly via agents.llm.rejected rather than crashing/silently dropping.

During testing, found and fixed two real test-isolation bugs (not production bugs): (1) the process-global event bus leaks subscriptions across tests — added an autouse _fresh_event_bus fixture (reset_bus() + re-register) in test_agents_gateway_events.py; (2) agents_gateway_api._QUEUE_MANAGER is a true process-global singleton (by design — one per hosting process) that was shared across ALL agents tests, so two tests using the same default agent_profile_id could have a worker thread bound to one test's project_root dequeue and process a different test's (already-deleted) tmp_path, causing FileNotFoundError races. Added tests/unit/agents/conftest.py with an autouse fixture that installs a fresh GatewayQueueManager per test.

6 unit tests in tests/unit/agents/test_agents_gateway_events.py: idempotent registration (without corrupting global state — the first draft of this test leaked a real duplicate subscription and had to be fixed), event creates and completes a request, async-by-default (returns without waiting for a held long-running request), missing-prompt-body rejection, missing-project-root rejection, correlation_id/subject preservation through to the completed lifecycle event. Full tests/unit/agents suite (149 tests) green with zero warnings.
