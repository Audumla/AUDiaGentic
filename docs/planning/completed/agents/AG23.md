# Replace source-control context Git subprocesses with Dulwich

## Description

Replace the source-control component's per-admission git.exe queries with read-only in-process Dulwich repository metadata. This removes child-process overhead and console-window risk without changing the generic runtime component-context collector.

## Steps

- Add `dulwich>=0.24,<0.26` as an explicit bounded project dependency and ensure supported environments package it.
- Replace `_git_value()` and all subprocess calls in `source_control.context()` with `Repo.discover(project_root)`, worktree-aware metadata, `repo.head()`, and the refs container.
- Return the existing safe-null projection for non-repositories, unborn HEAD, detached HEAD, corrupt metadata, and all read errors; never make gateway admission fail because source-control facts are unavailable.
- Cover normal repositories, nested directories, detached HEAD, unborn repositories, packed refs, and linked worktrees.
- Remove source-control-specific Windows launch suppression after no subprocesses remain; retain generic `CREATE_NO_WINDOW` treatment for other legitimate background subprocesses.

## Detailed Solution & Technical Design

Dulwich remains entirely owned by the source-control component. Runtime continues to know only that it invokes a component context hook; it has no Git/Dulwich dependency. `source_control.context()` discovers the repository in process, resolves its worktree through Dulwich's worktree-aware API, gets the resolved HEAD commit through `repo.head()`, and reads raw HEAD only to determine whether it is a symbolic `refs/heads/...` branch. Do not reconstruct `.git` paths manually. Preserve the current mapping keys and safe-null semantics. No raw repository configuration, remotes, credentials, or large Git objects enter prompt context.
