# README references non-existent observability tools; missing provider CLI-session vs API-completion caveat

## Notes

Implementation review of README.md + agents.yaml direct-tools. AG13 validation criteria: 'provider CLI-session vs API-completion output caveat' and 'observability surfaces: agent_llm_status, agent_llm_list_requests, agent_llm_gateway_overview.'

## Findings

MEDIUM — README references `agent_llm_list_requests` and `agent_llm_gateway_overview` in the observability list but neither tool exists. MCP direct-tools (agents.yaml lines 57-61) only expose: submit, status, wait, cancel, run. No list or overview endpoint.

The AG13 validation checklist says 'structured logs/lifecycle events/request list expose state transitions' — request list is not implemented as an API or MCP tool. The gateway_status() function returns per-profile queue depths (pending/running counts) which is a partial observability surface but doesn't provide the ability to list individual requests.

MEDIUM — README does NOT document the provider CLI-session vs API-completion output caveat from AG07/RV11: 'Gateway output for most providers is provider CLI/session output, not raw chat completion; only API-style providers behave like direct chat completion.' This was a HIGH finding in RV11 and explicitly called out in AG07 notes. It's critical UX guidance — callers expect `result['output']` to be a chat completion, but for most adapters it's the full CLI session output including system prompts.

LOW — README line 99 links to AG14 (startup reconciliation) which doesn't exist yet. This is a minor doc issue — either create AG14 or remove the link.

## Conclusion

MEDIUM (README references agent_llm_list_requests/agent_llm_gateway_overview that don't exist): those tools now exist (see RV33). Note for the record: at the time this review ran, the README did NOT actually reference those tool names at the cited line numbers — verified by grep against the live file; this finding's specific citation was inaccurate, but the underlying ask (build the tools) was legitimate and is now done regardless. MEDIUM (missing CLI-session vs API-completion caveat): this was a real, correctly-identified gap — added an explicit paragraph to README's Agent LLM Gateway section explaining that for CLI-based providers 'output' is full session/CLI output, not a raw completion, and only API-style providers (local-openai) behave like a direct chat completion. LOW (AG14 link broken): AG14 already existed (created earlier this session as the RV15/RV25 follow-up) — link was already valid, not stale.
