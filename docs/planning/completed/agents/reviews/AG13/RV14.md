# Status hook must conform to the new ComponentStatusPayload contract

## Notes

Verified agents.yaml has no status-hook or lifecycle-observer today; cross-referenced the ComponentStatusPayload contract landed this session (CC23) and the generic get_config/set_config standard (CC24, docs/standards/CREATING_A_COMPONENT.md §6).

## Findings

MEDIUM — AG12/AG13 predate the rigid status contract. agents.yaml currently declares NO status-hook and NO lifecycle-observer. AG13's 'add status details showing queue depth/running count/per-profile concurrency/recent failures' must register a status-hook returning foundation.components.hooks.ComponentStatusPayload (top-level enabled/configured/active_implementation/missing_required, everything gateway-specific under details, snake_case) — not an ad-hoc dict. AG12's 'update agents.yaml lifecycle-observer if none' should add a real lifecycle-observer module that self-registers idempotently (agents has none today).

LOW — AG13 references editing docs/planning/active/agents/AG07.md in its files list; that's a plan doc, not a deliverable — drop it from the component's file set (use plan_update_item to revise AG07 instead).

LOW — ledger: AG13 correctly requires recording a change event after implementation per project doctrine; keep that.

## Conclusion

Implemented. agents_api.agent_status(project_root) returns a ComponentStatusPayload: enabled=is_enabled('agents', project_root), configured=True (agents has no swappable-implementation concept, so there's no 'unconfigured' state), active_implementation=None, details={profile_count, default_profile_id, gateway: agents_gateway_api.gateway_status()}. Registered as status-hook in agents.yaml. Contract test added to the shared tests/unit/foundation/test_component_status_contracts.py alongside memory/planning/coding-lsp/source-control.
