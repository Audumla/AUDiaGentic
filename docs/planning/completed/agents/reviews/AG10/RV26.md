# Missing model capability validation before dispatch; retry count 0 edge case in fallback path

## Notes

Implementation review of agents_gateway_dispatch.py. Reviewed against providers/services/models.py and local_openai adapter.

## Findings

MEDIUM — no model capability check before dispatch: _dispatch_one_attempt resolves the model via resolve_model_selection, which returns a default or matching model from provider config. But if the profile specifies model_id='nonexistent-model', resolve_model_selection will either return 'nonexistent-model' (if present in provider config) or fall back to the provider's default. In neither case is there an explicit validation that the requested model is actually usable by this specific provider instance. A future adapter might raise an obscure error instead of a clean 'model not supported'. Consider adding: assert model['resolved'] in provider_config.get('models', []), or use resolve_model_selection's own failure mode.

LOW — retry-count=0 edge case: _try_profile_with_retries sets max_attempts = retry_count + 1, so retry_count=0 yields exactly 1 attempt. This is correct per the docstring ('additional attempts after the first'). But in the fallback path inside dispatch_request(), a failure on profile A with retry_count=0 will immediately try profile B — which also has its own retry_count. So profile B could have retry_count=2 (3 attempts) while profile A had only 1. This is intentional but worth documenting: per-profile retry policy applies independently to each fallback candidate.

LOW — _TerminalFailure preserves the original exception via self.original, and dispatch_request extracts it for transition_record updates with error=exc.original. The redaction in store.transition_record will handle this correctly since exc.original is an AudiaGenticError.

## Conclusion

No code change for this slice. Model-catalog pre-validation (resolve_model_selection already supports it via its optional catalog= param, just not wired here) is a real but non-blocking improvement — deferred; AG10's own validation criteria never required it, and wiring it means loading/caching a live provider catalog inline in the dispatch hot path, which is more scope than this slice needs. retry-count=0 edge case and per-profile-independent retry policy across fallback candidates confirmed correct and intentional by the reviewer's own trace. _TerminalFailure redaction confirmed correct.
