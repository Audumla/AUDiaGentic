# Event trigger topic is broad and lifecycle payload is underspecified

## Notes



## Findings

MEDIUM — src/audiagentic/components/agents/agents_gateway_events.py:L29-L31 subscribes to agents.llm.requested, and README.md:L57 documents the same broad topic. The final plan had moved toward a gateway-specific trigger (agents.llm.gateway.requested) to avoid any generic LLM request event accidentally launching provider work. Consider renaming the inbound topic to agents.llm.gateway.requested, or explicitly document/accept that agents.llm.requested is reserved for this gateway and no other component should publish it casually.

MEDIUM — src/audiagentic/components/agents/agents_gateway_events.py:L93-L97 catches AudiaGenticError only. Unexpected exceptions from submit normalization/API will be swallowed by EventBus subscriber isolation and no agents.llm.rejected event will be published. Catch Exception at this external boundary, log exc_info=True, and publish a redacted rejected event.

LOW — README.md:L87-L93 says lifecycle payload is only {request-id, agent-profile-id, state}; this is too little for event-only callers to observe provider/model/error without polling record.json. Align with the observability review in AG09 by adding safe terminal metadata.

## Conclusion

Both MEDIUM findings fixed. Renamed the inbound trigger topic from agents.llm.requested to agents.llm.gateway.requested throughout (module, tests, README) — avoids the exact accidental-trigger risk named (a future unrelated publisher assuming 'agents.llm.requested' is a neutral marker). Outbound lifecycle events (agents.llm.completed/failed/etc.) were left as-is — no other component would have a reason to publish TO those topics, so there's no equivalent collision risk on the output side. _on_llm_requested now also catches bare Exception (not just AudiaGenticError) at this external boundary, logs exc_info=True, and publishes agents.llm.rejected — previously an unexpected exception would have been silently swallowed by EventBus's per-subscriber isolation with zero trace. Added test_requested_event_unexpected_exception_publishes_rejected_not_swallowed. LOW (thin lifecycle payload): resolved via RV31's terminal-event enrichment (provider-id/model-id/error/attempt_count).
