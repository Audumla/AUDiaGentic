# lifecycle-observer path resolves to submodule not a callable; agents.yaml misconfigured

## Notes

Implementation review of agents.yaml + foundation/components/hooks.py _resolve_hook. The lifecycle observer hook path must resolve to a callable with (event_type, payload, metadata) signature per LifecycleHook.

## Findings

HIGH — `lifecycle-observer` in agents.yaml line 10 resolves incorrectly: `_resolve_hook()` does `hook_path.rpartition('.')`, giving module=`...agents_gateway` and fn_name=`events`. It then does `getattr(module, 'events')` which returns the submodule object (not callable). The lifecycle hook dispatch will silently skip it — logs show 'could not resolve' warning at hooks.py:93. Agents.gateway events has NO lifecycle-observer registered.

The agents_gateway_events module self-registers at import time via `register()` which subscribes to `agents.llm.requested` directly on the event bus — this is NOT a lifecycle observer. The two mechanisms serve different purposes: lifecycle observers receive all component lifecycle events (lifecycle.component.*); direct event subscriptions are topic-specific.

ACTION: Either (a) remove `lifecycle-observer` from agents.yaml since the module already self-subscribes at import time, OR (b) add a proper hook function in agents_gateway_events with signature `(event_type, payload, metadata) -> None` and point lifecycle-observer to that function.

Note: RV18 already flagged 'deferred subscription at first request vs import time' — the current implementation chose import-time registration based on an established convention (memory_observer, coding_lsp_bootstrap). This is acceptable but means the component cannot be disabled without process restart.

## Conclusion

REFUTED — verified against source, no code change. loader.py:216-220 handles lifecycle-observer via a PLAIN MODULE IMPORT (`__import__(descriptor.lifecycle_observer)`), never through _resolve_hook's rpartition-based function resolution (that's only used for lifecycle-hook and status-hook, which are separate YAML fields pointing at actual functions). agents.yaml's `lifecycle-observer: audiagentic.components.agents.agents_gateway_events` is imported as a whole module, exactly matching the established pattern (memory_observer.py, coding_lsp_bootstrap.py) — the module's own register() call at the bottom is what does the real work. This review applied _resolve_hook's function-resolution logic (correct for lifecycle-hook/status-hook) to a field that uses a completely different mechanism. Also: removing lifecycle-observer as suggested would be wrong, not just unnecessary — agents_gateway_mcp.py (the gateway MCP server entrypoint) never imports agents_gateway_events, so without the lifecycle-observer declaration forcing the import during register_all_components(), a process that only ever loads the MCP server would never self-register the event subscription at all. Already implicitly proven working by tests/unit/agents/test_agents_gateway_events.py and tests/integration/agents/test_agents_gateway_flow.py's event-triggered flow test, both passing.
