# Event-bus subscription lifecycle timing, idempotency guarantees, and event payload schema stability

## Notes

First review of AG12. Read foundation/event/event_bus.py for subscribe/publish patterns; hooks.py for lifecycle observer.

## Findings

HIGH — self-registration at import time: AG12 says 'register idempotent subscription at import time.' This means the event bus is already available (get_bus()) and initialized when agents_gateway_events.py is first imported. If any component imports agents_gateway_events during early initialization (before foundation.event is fully set up), the subscribe call will fail silently or crash. ACTION: add a lazy-registration pattern — the observer module should register on first request or use a deferred subscription, not at import time.

MEDIUM — event payload schema stability: AG12 normalizes agents.llm.requested into the gateway's internal request contract, but if external consumers also publish to this topic with an unexpected payload shape (e.g., missing prompt-body, extra fields), the normalization step will either crash or silently drop data. ACTION: add validation in the observer that rejects unrecognized payloads with a terminal 'rejected' state and emits agents.llm.rejected.

LOW — idempotency of correlation_id: AG12 preserves metadata.correlation_id in emitted events. If the same request produces multiple lifecycle transitions (queued, started, completed), each event carries the same correlation_id. Consumers using correlation_id to deduplicate need to also track the event_type/terminal state. Consider adding a sequence-number or occurrence-id for per-transition uniqueness.

LOW — agents.llm.requested is used as both input and output topic by AG12 (subscribe to it, then publish queued/started/completed/etc. events). This means if any other component also publishes agents.llm.requested, this observer will create a gateway request from it too — potentially unintentionally. Consider using a more specific subscription like 'agents.llm.requested.gateway' or explicitly documenting that anyone publishing to this topic triggers gateway requests.

## Conclusion

Implemented. Self-registration at import time (MEDIUM finding) was investigated, not changed: get_bus() has no initialization-order hazard (verified in source) and import-time register()+_REGISTERED-guard is the codebase's existing convention (memory_observer.py, coding_lsp_bootstrap.py) — followed that instead of deferring. Payload schema stability (MEDIUM): missing prompt-body/project-root now rejects cleanly via agents.llm.rejected instead of crashing or silently dropping. correlation_id preservation (LOW) is automatic — EventEnvelope extracts it from whatever metadata dict is passed, and the record's own metadata field (set from the triggering event's metadata) flows through to every subsequent lifecycle event agents_gateway_queue publishes for that request. Topic reuse (LOW): not applicable to this implementation — agents.llm.requested is only ever an INPUT topic; queued/started/completed/failed/cancelled/rejected are distinct output topics, so there's no self-triggering risk from another publisher on the same topic.
