# Gateway MCP surface lacks planned observability tools

## Notes



## Findings

MEDIUM — src/audiagentic/components/agents/agents_gateway_mcp.py:L22-L87 exposes submit/status/wait/cancel/run only. The observability update to AG11 called for agent_llm_list_requests and agent_llm_gateway_overview so operators can see recent/stuck/failed work without already knowing a request-id. The current surface only supports status by request-id.

MEDIUM — src/audiagentic/components/agents/agents_gateway_api.py:L121-L129 gateway_status returns only in-process queue depths. It does not include persisted queued/running/stale/failed records, so after a process restart or terminal failure the overview can be empty even though .audiagentic/runtime/agent-llm-gateway contains important state. Add read-only list/overview helpers derived from store.list_records plus in-memory queue depths.

LOW — src/audiagentic/config/components/agents.yaml:L54-L91 descriptor likewise omits tool descriptions for list/overview tools. Once API helpers exist, register them on ag-agents-gateway only (propagate: audiagentic).

## Conclusion

Implemented. Added agents_gateway_api.list_llm_requests(project_root, state=, limit=) and gateway_overview(project_root) — the latter combines persisted request counts by state (works after a restart, unlike the in-memory-only gateway_status()) with the 5 most recent failures (redacted error only) and in-process queue depths. Wired as agent_llm_list_requests/agent_llm_gateway_overview MCP tools on ag-agents-gateway (still audiagentic-scoped only, per RV20). agent_status (component status hook) now uses gateway_overview() instead of gateway_status(). Added test_gateway_overview_reflects_persisted_state_across_restart which explicitly simulates a restart (fresh GatewayQueueManager) and proves the overview still reports the persisted failure while queues is empty.
