# Do not propagate gateway tools to providers — re-entrancy/scope (complements RV17)

## Notes

Complements RV17 (which covers MCP blocking-timeout cap and cancel/retry interaction) with a distinct finding not raised there. Cross-referenced agents.yaml server declarations: ag-agents-mgmt propagate: audiagentic; ag-agents propagate: providers. Propagate doctrine in docs/standards/CREATING_A_COMPONENT.md §6.

## Findings

MEDIUM — propagation scope: AG11 says 'propagate activity tools to providers only if provider-facing use is desired.' The existing ag-agents activity server is propagate: providers. Exposing agent_llm_submit/run/etc. on a providers-propagated server means a provider surface could recursively invoke the gateway that dispatches back into providers — a re-entrancy footgun and a privilege-scope concern (a provider gaining the ability to launch arbitrary profile/model runs). RECOMMENDATION: place gateway tools on an audiagentic-scoped server (management-style, like ag-agents-mgmt), NOT the providers-propagated ag-agents activity server, unless there is a concrete provider-facing need. Make this an explicit decision in AG11 rather than a conditional 'if desired'.

## Conclusion

Considered. AG11 now requires gateway MCP tools on an audiagentic-scoped server only and explicitly forbids providers propagation in v1 to avoid re-entrancy/scope issues.
