# Gateway record contract allows invalid direct requests

## Notes



## Findings

HIGH — src/audiagentic/components/agents/agents_gateway_store.py:L74-L118 and src/audiagentic/foundation/contracts/schemas/agent-llm-record.schema.json:L28-L40 allow prompt-body=null and timeout-seconds to be any number. Event submissions reject missing prompt-body, but direct API/MCP submissions can create runnable records with no prompt and negative/zero timeout values. Add validation for non-empty prompt-body for submitted requests and positive timeout-seconds when provided.

MEDIUM — src/audiagentic/components/agents/agents_gateway_api.py:L52-L66 passes explicit fallback_profile_ids straight to build_record, whose L101 uses list(fallback_profile_ids or []). If a caller passes a string (common JSON mistake), it becomes a list of characters and passes the current schema. Validate explicit fallback_profile_ids is list[str] before build_record, matching profile-param validation.

MEDIUM — tests/unit/agents cover invalid mode and schema extra fields, but not missing/empty prompt-body, negative timeout_seconds, or string fallback_profile_ids. Add regression tests for all three public input paths: API, MCP wrapper if feasible, and event payload.

## Conclusion

Fixed. build_record() (the single choke point for record construction) now rejects: empty/whitespace-only prompt_body (VAL-AGW-007), non-positive timeout_seconds (VAL-AGW-008), and fallback_profile_ids that isn't a list[str] (VAL-AGW-009) — catches the exact 'backup' string -> ['b','a','c',...] footgun the review named. Validated at the lowest layer (agents_gateway_store.build_record), not just agents_gateway_api, so it protects every current and future caller. 4 regression tests added in tests/unit/agents/test_agents_gateway_store.py.
