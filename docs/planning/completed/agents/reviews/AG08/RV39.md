# Architecture standards: gateway state paths belong in agents, not runtime

## Notes



## Findings

HIGH: `src/audiagentic/runtime/state/paths.py` now exposes agent-gateway-specific helpers (`gateway_root`, `gateway_request_dir`, `gateway_request_path`). `docs/standards/ARCHITECTURE_STANDARDS.md` says runtime must not reference optional component internals and component work should stay isolated. Move these helpers into the agents component (`agents_gateway_store.py` or a small agents-local paths module) and keep runtime as a generic state primitive only.

## Conclusion

Fixed. Moved gateway_root/gateway_request_dir/gateway_request_path from runtime/state/paths.py into a component-owned module (agents_paths.py, which already existed for agent_profiles_path) and updated agents_gateway_store.py's import. Note on the standard's precise scope: runtime/state/paths.py never actually IMPORTED agents component code (Standard 1's literal text is 'runtime must never import a specific optional component'), and the file already carried agent-jobs-specific path knowledge (job_dir, job_stages_dir, etc.) for the same optional component pattern — so this wasn't a strict layering-direction violation. But the file's own docstring scopes it to '.audiagentic/runtime/jobs' specifically, and cross-component path knowledge belongs with the component that owns it (Logic Containment) rather than accumulating in a nominally single-component-scoped runtime file. Fixed for that reason, and to keep the pattern consistent with agents_paths.py's existing role. runtime/state/paths.py is back to job-only scope. Full agents+jobs test suite (185+27 tests) green after the move.
