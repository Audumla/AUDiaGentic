# Gateway store review — schema and redaction gaps

## Notes



## Findings

HIGH — src/audiagentic/components/agents/agents_gateway_store.py:L62-L64: non-AudiaGenticError redaction persists str(error), which can contain prompt text, stdout, stderr, URLs, or tokens. Store only error type plus generic message for unexpected exceptions, or explicitly sanitize before persistence.

MEDIUM — src/audiagentic/foundation/contracts/schemas/agent-llm-record.schema.json lacks top-level additionalProperties:false. A record containing messages would pass validation even though v1 contract says prompt-body only. Add additionalProperties:false and a regression test.

LOW — Schema was added to foundation/contracts/schemas, not component-local contracts. This may be acceptable because schema_registry only reads canonical schemas, but note this as intentional since it broadens rollback scope slightly.

## Conclusion

Fixed. _redact_error no longer persists str(exception) for non-AudiaGenticError exceptions — replaced with a generic 'unexpected error (see server logs)' message; only .kind (exception type name) is kept. AudiaGenticError's own .message is still trusted (it's already required to be free of raw stdout/stderr/tokens per Standard 8 at construction). Added test_transition_record_redacts_generic_exception_message. Schema now has additionalProperties: false at the top level (plus cancel-requested added to required); added test_schema_rejects_additional_properties regression test. LOW note on schema location acknowledged as intentional (matches job-record precedent, not component-local).
