# Gateway design overview — agent-jobs overlap must gate the work

## Notes

Reviewed against actual codebase (agent_jobs/packet_runner.py, providers/services/execution.py, provider adapters). Integration points named across the plan verified to exist: agents_api.resolve_profile/resolve_default_profile, providers.services.execution.execute_provider, providers.services.models.resolve_model_selection, provider_config.is_provider_enabled, event bus subscribe/publish/wait_idle.

## Findings

HIGH — agent-jobs overlap is the central architectural risk, not 'secondary' as AG07 states. agent_jobs/packet_runner.py already implements job-id generation, a persisted record store (store.write_job_record/read_job_record), a state machine (state_machine.transition_and_persist: created->ready->running->completed/failed), profile resolution, and a packet_ctx dispatch. The packet_ctx built at packet_runner.py:136 is nearly identical to the neutral packet_ctx AG10 specifies. Building a parallel agents_gateway_store + second state machine + second dispatch collides with Standard 3 (unify >80%-overlap types) and Standard 1 (layering). ACTION: add an explicit up-front decision step to AG07 — evaluate building the gateway ON agent-jobs' existing store/state_machine primitives, adding only the genuinely new layer (per-profile queue, concurrency, retry/fallback, async/blocking/event surfaces). The real differentiator worth building is queue+concurrency+one-shot-vs-multistage; a duplicate record/state store is not.

MEDIUM — 'Direct LLM completion' mischaracterizes the path for 13 of 14 providers. Through the CLI adapters a request is a coding-agent CLI session in a working directory, not a raw chat completion. The claude adapter injects 'Use the packet document excerpt as the task definition' and looks up docs/implementation/packets/<PACKET>.md. Only local_openai is a true API completion. AG07/AG13 docs must state gateway output is provider-CLI-session output wrapped in AUDiaGentic execution framing, or explicitly target API-style providers for the direct-completion use case.

LOW (acknowledged, keep explicit) — in-process thread workers + blocking subprocess/urlopen calls suit MCP/server lifetime but a one-shot CLI submit exits before the worker drains. AG07/AG09's mitigation (persist accepted/queued state now, durable external worker later) is the right call.

## Conclusion

Considered. AG07 updated with an explicit pre-implementation decision gate for agent-jobs store/state reuse, prompt-body-only v1 contract, and provider CLI-session output caveat.
