# Concurrency knobs live in unvalidated free-form profile params (complements RV15)

## Notes

Complements RV15 (which covers restart-orphan recovery, cancel-running semantics, worker cleanup) with a distinct source-verified finding not raised there. Verified: agents/models.py AgentProfile.params is dict[str, Any] validated only as 'must be a mapping' (models.py:20,43-45); resolve_profile returns params verbatim (agents_api.py:206-212); profile CRUD accepts arbitrary params keys.

## Findings

MEDIUM — AG09 reads max_concurrency and queue_max_size from profile params.*, and AG10 reads params.fallback_profile_ids, but params is a free-form unvalidated dict. Consequences: (a) a typo like 'max_concurency' silently falls back to default 1 with no error; (b) these gateway-critical knobs have no schema, no discoverability, and no CRUD guardrail. ACTION: validate the gateway params keys at read time in the queue manager (explicit AudiaGenticError on wrong type / out-of-range) instead of silently defaulting, and document the exact keys/types in AG13 docs. Optionally define a typed sub-schema for gateway params so agent_create_profile/agent_update_profile can reject bad values at write time.

## Conclusion

Considered. AG09 now requires gateway params resolver/validator for max_concurrency, queue_max_size, timeout_seconds, retry_count, and fallback_profile_ids with AudiaGenticError on invalid values instead of silent defaults; AG13 docs already cover param documentation.
