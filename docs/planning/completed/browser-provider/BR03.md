# Plan-item-driven review prompts + random selection (no reuse)

## Description

The prompt pool uses itertools.cycle which reinitializes on each process start, so consecutive runs always send the same first two prompts — exactly the bot-detection pattern we are trying to avoid, and the user does not want the same prompt reused for a new conversation. Replace cycle with random selection, and add a plan-item-driven prompt generator: pick a random plan item from docs/planning/ and ask ChatGPT to review its content.

## Steps

- Replace itertools.cycle with random selection in pick_prompt
- Add pick_plan_review_prompt() reading docs/planning plan items
- Wire the test to use a plan-review prompt for turn 1 and a random pool prompt for the follow-up
- Validate two runs produce different prompts (no repeat)
- Run ruff and py_compile on changed files

## Detailed Solution & Technical Design

prompt_pool.pick_prompt uses random.choice (drop the module-level itertools.cycle). Add pick_plan_review_prompt(planning_root) that globs docs/planning/active/**/*.md and docs/planning/completed/**/*.md, skips templates/README, picks one at random, parses its title+description frontmatter, and returns a prompt of the form: 'Review the following plan item for technical soundness, risks, and missing validation: {title}\n\n{description}'. Fall back to the curated pool if no plan items exist. Test uses plan-review prompt for the first turn and a different random pool prompt for the follow-up so consecutive runs never repeat.
