# Execute multi-project jobs through context-isolated workers

## Description

Ensure one shared control plane can safely execute jobs for projects with different roots, startup directories, component profiles, MCP sets, provider configs, and credentials. Because component profiles are one-per-process and several providers have fixed or partial config isolation, use context-isolated worker/provider processes instead of attempting to switch global process state inside the gateway service.

## Steps

1. Implement one disposable worker per one-shot attempt; do not pool while reuse safety is unproven. 2. Start each worker with canonical project CWD, the manifest-frozen component profile before component/provider imports, and an explicit replacement environment. 3. Invoke provider-owned public execution/materialization only; never branch on provider id in agents and never mutate fixed user configuration as an isolation workaround. 4. Use a versioned private pipe contract carrying worker/attempt/manifest/fingerprint identity and the MA17 runtime-only execution request/result; prohibit env, config blobs, secrets, persistence, and logging of raw prompt/output. 5. Verify handshake PID/creation evidence, accepted tier/root/profile, bounded completion, and ownership-safe descendant teardown. 6. Fail closed with an explicit policy outcome for partial/no-isolation or any full-isolation provider lacking a proven materializer. 7. Add adversarial Docker tests for concurrent conflicting projects, distinct worker PIDs/CWD/profiles/config, canary non-bleed, crash cleanup, and unsupported tiers. Defer pooling and durable cancel/recovery semantics to SH07/SH08/SH10.

## Files

gateway worker wire contract, process host and supervisor; MA17 provider public execution/materialization contract; foundation supervised child-process handle; manifest/dispatch integration; focused host and mutable Docker tests

## Validation

Validated 2026-07-18 in Docker: concurrent conflicting project roots/profile values use distinct disposable worker processes; private worker pipe redacts secrets/config/env and rejects partial/no tier with UNS-AGW-076; worker timeout reaps provider descendants; three different gateway profiles launch three worker OS processes without a gateway-wide compute gate. Clean Docker image build succeeds while excluding live .audiagentic/runtime state. Focused coordinated slice passes.

## Effort & Risk

Highest execution risk. Fixed-config providers may require serialized access, disposable homes/config roots, or an explicit unsupported mode rather than unsafe reconciliation.

## Standards
