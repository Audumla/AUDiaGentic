# Add race-safe gateway discovery and self-managed startup

## Description

Implemented opt-in self-managed gateway startup through the framework-neutral gateway client. Automatic mode delegates discovery record ownership, atomic start-or-attach, detached launch, stale-owner recovery, readiness, process verification, and initial lease issuance to foundation ManagedServiceLifecycle; gateway code contributes only its fixed loopback declaration, authenticated health compatibility handshake, and HTTP client lease adoption.

## Steps

1. Declare the gateway's service kind/scope, launch declaration, health/identity handshake, and gateway-specific compatibility rules for PR07; do not create a gateway-local discovery record format. 2. Use PR07 start-or-attach, ownership verification, and atomic lease registration for single-winner startup across concurrent harnesses. 3. Declare detached lifetime requirements to PR07 so the service outlives the starting harness and its process group/job object safely. 4. Add gateway-specific bounded connect/start/retry behavior and clear errors for incompatible or unhealthy gateway protocols. 5. Handle gateway upgrade/version skew without killing an unrelated active service. 6. Add concurrent cold-start, stale-record, PID reuse, starter-crash, and reconnect tests on Windows and POSIX.

## Files

shared gateway public client/bootstrap integration; PR06/PR07 foundation public APIs; thin CLI/MCP wiring that calls the public client; tests

## Validation

Completed and post-review corrected 2026-07-18. Windows host: 62 automatic/standalone/client/foundation/error-contract tests pass. Linux Docker: clean image rebuild and 63 cross-platform cases pass with one correct Windows-only skip. Concurrent real clients start exactly one owner and share one epoch/leases. Health and the automatic client publish foundation process lifetime scope: shared-service-host for full detachment or session-child when a Windows supervisor denies Job Object breakaway. Stale-record, ownership, protocol mismatch, readiness cleanup, timeout/disconnect, and no-adapter-policy behavior are covered.

## Effort & Risk

Complex due to cross-process races and Windows lifetime semantics.

## Standards

AR25; Architecture Standards §§1,3,4,6,7.

## Notes

Complete. Reuses ManagedServiceLifecycle, ManagedServiceStore, DetachedLaunch, process ownership evidence, and the SH04 host/client. No gateway-local PID, lock, discovery record, process killer, or retry engine exists. Automatic mode uses AUDIAGENTIC_GATEWAY_MODE=automatic with optional AUDIAGENTIC_GATEWAY_PORT (default 8765) and does not silently fall back. Windows job-bound degradation is explicitly reported as lifetime-scope=session-child in health/client evidence and logs; it is not represented as fully detached. Default cutover remains SH11. RV648 incorporated.
