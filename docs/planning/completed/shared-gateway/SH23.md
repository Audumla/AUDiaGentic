# Route no-isolation one-shot dispatch through ephemeral session transport

## Description

agent_task_submit's one-shot (non-session) path unconditionally routes through the SH06 disposable-subprocess worker model (worker_host.py), which hard-requires full-isolation and fails closed (UNS-AGW-076) for anything else. 12 of 20 configured providers declare no-isolation (gpt-auto, claude, cline, copilot, crush, gemini, kilo, openhands, plandex, roo, zed, antigravity) and are therefore currently unable to serve a plain one-shot agent_task_submit call at all -- even though most of them already implement a working AgentSessionTransport (open/prompt/close) that the live-session path exercises successfully today. Fold one-shot dispatch for no-isolation providers into the existing, already-tested ephemeral-session pattern _dispatch_session_request already implements (session_id=None + keep-alive=false opens a session, runs one turn, then auto-closes via its existing post-turn cleanup) instead of leaving them permanently blocked. Full-isolation and partial-isolation dispatch behavior, worker_host.py's isolation gate, and SH06's Docker-validated disposable-subprocess model are all left completely unchanged -- this only adds a new reachable branch for the no-isolation tier.

## Steps

1. In queue/dispatch.py's dispatch_request, extend the routing condition so a request with provider_isolation_tier == "no-isolation" also routes to _dispatch_session_request even when it has no explicit session_id/session_keep_alive -- reusing the function's existing session_id=None ephemeral-open/one-turn/auto-close behavior unchanged. 2. Accept that this path carries no per-profile retry-count, matching the session path's existing documented "no retry on a stateful conversation" behavior -- record this as a deliberate, accepted behavior difference from the full-isolation one-shot retry loop, not a defect to fix. 3. Rewrite the UNS-AGW-076 resolution text in error-resolutions.yaml so it no longer implies there is no alternative -- it now only fires for partial-isolation or an unproven full-isolation materializer, and should say so plainly. 4. Add a unit test in test_agents_gateway_dispatch.py: a no-isolation provider dispatched via dispatch_request with no session fields calls _dispatch_session_request (mock the session runtime), never _dispatch_one_attempt/execute_isolated_provider_turn. 5. Add/confirm coverage that full-isolation and partial-isolation one-shot routing is unchanged (still _dispatch_one_attempt; partial-isolation still hits UNS-AGW-076 via worker_host, per test_sh06_worker_isolation.py). 6. Where a live logged-in browser is available, validate one real gpt-auto agent_task_submit call with no session_keep_alive against tests/gpt_auto/test_micro_steps.py's existing ladder; otherwise validate with mocks only and say so explicitly rather than claiming live verification.

## Detailed Solution & Technical Design

queue/dispatch.py:dispatch_request currently branches purely on _is_session_request(record) (session-id or session-keep-alive present). Change the condition to `_is_session_request(record) or provider_isolation_tier == "no-isolation"`, passing the same dispatch_prompt/preallocated_session_id/context_fingerprint through to _dispatch_session_request unchanged. Inside _dispatch_session_request, session_id=None already triggers the is_new_session branch (opens a session bound to the resolved profile via SessionRuntime.open_session -> providers_api.prepare_provider_session_transport), runs exactly one prompt_in_session turn, and -- because record["session-keep-alive"] is falsy for a plain one-shot submit -- the existing post-turn block (record.get("session-id") is not None and not record.get("session-keep-alive")) already closes the session via _post_turn_close_continued_session_if_quiescent and cleans up the request runtime dir. No new session-runtime code is needed; this is a routing-only change. worker_host.py's `provider_isolation_tier != "full-isolation"` gate (UNS-AGW-076) stays exactly as-is and remains reachable for partial-isolation and any full-isolation provider whose materializer proves unsafe -- it simply becomes unreachable for the no-isolation case because dispatch_request no longer sends no-isolation requests down that path at all.

## Effort & Risk

Medium blast radius, low structural risk: reuses an already-exercised code path (_dispatch_session_request) rather than adding new session-runtime logic, and does not touch worker_host.py or SH06's Docker-validated subprocess isolation model at all. The real risk is behavioral, not structural: the ~12 no-isolation providers' one-shot calls lose per-profile retry-count (session turns are intentionally not retried), and a no-isolation provider that has no working session/ACP transport will now fail with a session-surface error (e.g. CON-AGW-095 / RES-AGW-103) instead of UNS-AGW-076 -- a different, more specific failure, not a worse one.

## Notes

Motivated by a live agent_task_submit test against gpt-auto that failed immediately with UNS-AGW-076, despite gpt-auto's session transport (GptAutoSessionTransport in providers/adapters/gpt_auto/session_transport.py) already working correctly through the live-session path (see tests/gpt_auto/test_micro_steps.py, which calls SessionRuntime.open_session() directly). Root cause: dispatch_request's routing only ever checked for an explicit session_id/session_keep_alive, never the provider's isolation tier -- so a no-isolation provider had no route into the one-shot path (worker_host.py categorically rejects anything but full-isolation) and no route out of it either (nothing sent it down the session path instead). Deliberately out of scope here: worker_host.py's UNS-AGW-076 gate itself, SH06's disposable-subprocess model for full/partial-isolation providers, and partial-isolation's currently-undefined "needs serialized access" case, which SH06 explicitly punted on and which this item does not attempt to resolve.

Implemented 2026-08-09: dispatch_request's routing condition extended to `_is_session_request(record) or provider_isolation_tier == "no-isolation"`; UNS-AGW-076 resolution text rewritten in error-resolutions.yaml. Added test_no_isolation_plain_record_routes_through_ephemeral_session (test_agents_gateway_dispatch_sessions.py) proving the new route never touches execute_isolated_provider_turn and that the ephemeral session opens, runs one turn, and auto-closes. tests/unit/agents (full suite, 656 tests) green; tests/integration/agents/test_sh06_worker_isolation.py's directly relevant case (test_non_full_tiers_return_explicit_policy_outcome, partial-isolation via worker_host) still passes unchanged -- the other 3 failures in that file are pre-existing, environment-related (Windows host running a Docker-gated real-subprocess suite; unrelated files, hardcoded full-isolation tier, not touched by this change), not caused by this item. No live gpt-auto browser session was available in this session to exercise the real end-to-end call -- validation here is mock-only, per the item's own accepted fallback; a live confirmation is still worth doing when a logged-in browser is available.
