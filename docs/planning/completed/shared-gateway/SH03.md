# Introduce an in-process gateway client/control-plane seam without changing behavior

## Description

Refactor the current module-level gateway API and queue manager behind a framework-neutral public client/application/control-plane protocol while retaining the current in-process implementation as the only backend. MCP, event, CLI, and future service transports remain thin inbound adapters: translate protocol context and transport-only constraints, call the public API, and serialize results. They do not own gateway decisions or import backend internals.

## Steps

1. Characterize submit/status/wait/cancel/run, event-triggered submission, sessions, reconciliation, errors, and lifecycle events. 2. Define requester-blind public gateway client and application/control-plane contracts using SH02; neither imports MCP/FastMCP or another inbound framework. 3. Move singleton access behind composition-root registration/factory wiring; do not add provider-name branching or dual state owners. 4. Keep MCP/event surfaces behaviorally stable through thin adapters importing only the public API. Move MCP_BLOCKING_TIMEOUT_SECONDS and its obsolete compatibility alias out of agents_gateway_api.py to the MCP/client transport boundary, preserving unrestricted non-MCP wait semantics. 5. Add conformance and architecture tests runnable against the in-process backend. 6. Delete direct internal callers and protocol adapters that bypass the public seam.

## Files

src/audiagentic/components/agents/agents_gateway_api.py and new public/application contracts; agents_gateway_mcp.py transport-only timeout handling; composition-root wiring; event/CLI adapters; focused and architecture tests

## Validation

Existing gateway and session suites pass at the public boundary; one control-plane owner exists; contract tests cover all operations/events; core/API imports no MCP/FastMCP; MCP/event/CLI modules import only approved public APIs plus protocol scaffolding and contain no store, queue, dispatch, discovery, worker, or lifecycle policy.

## Effort & Risk

Mid. The risk is accidentally maintaining two active paths or freezing process-specific concepts into the remote contract.

## Standards

AR25; Architecture Standards §§1,3,4,6,7; CREATING_A_COMPONENT §2 and §6.
