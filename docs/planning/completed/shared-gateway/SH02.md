# Define the versioned job execution context and resolved execution manifest

## Description

Define the smallest versioned submission envelope and resolved execution manifest the shared gateway needs now, without inheriting submitting-process state. V1 carries canonical project root, existing agent-profile/provider/model selection, per-request component profile, existing execution/session fields, idempotency/correlation identity, and a frozen runtime digest/fingerprint. Provider configuration remains the owner of MCPs, environment shaping, vendor keys, and secrets; roles and multi-root workspaces are later owned schema extensions.

## Steps

1. Inventory only the implicit context required by current submit/dispatch behavior. 2. Define the v1 envelope and immutable manifest with canonical project-root rules and the resolved runtime digest/fingerprint. 3. Resolve provider isolation tier from the MA20 capability fact; define only current safe/unsupported outcomes, not future worker policy. 4. Reject raw credentials and ambiguous roots; do not add env or secret-reference fields. 5. Specify version negotiation and only the migration support with a documented external obligation. 6. Add path, determinism, cross-project, redaction, and version-negotiation tests. SH06, SH07, and RO items add their own fields later by schema version bump when required.

## Files

docs/reference/PROVIDER_CAPABILITY_REFERENCE/configuration/provider-config-projection.md; new shared gateway contract/schema modules and schemas identified by design; agents gateway request contracts; provider public execution contracts; tests

## Validation

Round-trip/schema tests cover Windows and POSIX path forms; identical intent resolves deterministically; two projects with different roots, managed runtime configurations, and component profiles cannot bleed state; persisted records contain no raw secrets/prompts; old clients receive VAL-GWY-VERSION with the supported range. Tamper/integrity tests are SH07-owned.

## Effort & Risk

Complex because much current context is process implicit. An envelope that merely carries paths without freezing the resolved managed runtime digest will remain nondeterministic.
