# Run the gateway as an explicit standalone local control-plane service

## Description

Add a manually started standalone gateway service and local authenticated transport so multiple harness processes can share one queue/session control plane. The service transport is a thin protocol adapter over the same framework-neutral application/control-plane API proven by SH03. Gateway code supplies launch declaration, gateway health handshake, authorization, and request/session behavior; PR06/PR07 provide durable service record, client leases, start-or-attach, ownership verification, and guarded process shutdown. All gateway state transitions, dispatch, recovery, and domain lifecycle behavior remain behind the gateway API.

## Steps

1. Select and document a cross-platform local transport and gateway endpoint/authentication scheme; bind locally by default. 2. Implement the standalone service host over SH03's control-plane contract and acquire its process/service lifecycle through PR06/PR07 public APIs. The service—not an MCP caller process—owns active work, so submission, client timeout, and client exit cannot terminate a worker. 3. Make request state transitions, cancellation, waiting/status, reconciliation, and session registry gateway-service-owned; remove thread-lock assumptions at service boundaries. 4. Add gateway protocol health/version/capability endpoints and bounded client retry semantics. 5. Bound long-lived gateway state including event correlation-chain retention. 6. Add crash, restart, concurrent-client, malformed-client, and security tests. 7. Keep explicit configuration to choose in-process or standalone during this phase.
