# SH07 wait and ACP progress projection parity

## Description

Make wait, status, and diagnostics consume the same redacted live ACP/session evidence so active work is never reported as launching/stale.

## Steps

1. Extract a single bounded progress-summary helper from the live session timeline used by request diagnostics. 2. Include latest sequence/timestamp, event-kind counts, active/completed/failed tool counts, assistant/thought chunk counts and byte counts, terminal stop_reason, dropped/overflow counters, and callback/projection health; never include prompt, text, tool args, output, provider refs, or project roots. 3. Use this helper in agent_llm_wait timeout responses, request status, and diagnostics. 4. Preserve deterministic terminal-quality signals for premature halt/repetition without an LLM. 5. Add regression coverage reproducing an active ACP tool-call turn where wait currently says launching/stale, plus terminal and dropped-event cases.
