# Make all shared-gateway protocol surfaces thin adapters over framework-neutral APIs

## Notes



## Findings

SH01–SH11 correctly separate the shared control plane from agent-session and process-lifecycle ownership, but they do not uniformly state that MCP, event-bus, CLI, and local-service transport modules are inbound adapters only. SH03 mentions a client/control-plane seam, while SH05 names MCP startup integration and SH09 event ingress; without an explicit dependency rule, discovery, startup, idempotency, dispatch, or lifecycle policy could drift into those protocol modules. Existing standards guidance requires thin MCP wrappers but the non-negotiable architecture standard and automated enforcement are incomplete (AR25). The current agents gateway API also exposes MCP_BLOCKING_TIMEOUT_SECONDS despite documenting it as a transport-only concern.

## Conclusion

Amend the shared-gateway program and affected items to require a protocol-neutral public API/application layer. MCP/event/CLI/service transport adapters may translate protocol context and transport constraints, then call that API; they must not own gateway logic or import stores, queues, dispatchers, workers, discovery, or lifecycle internals. Add architecture-test validation and make SH03 remove the existing MCP timeout leak.
