# Component-profile isolation, AR25 enforcement, and security boundaries

## Notes

Program boundary review. Must be resolved before SH02 implementation begins.

## Findings

## Architecture Standards Review — SH01

### Strengths
- Clear target topology: thin clients/MCP facades -> local shared gateway control plane -> context-isolated execution workers/providers
- Phase gates with rollback points — correct migration approach
- Preserves AS ownership of session semantics and PR05 ownership of process primitives

### Concerns to resolve before SH02 implementation

**1. Component-profile isolation (§3: layering)**
The item acknowledges "process-global component-profile state and provider config limitations" — this is the hardest problem. A shared gateway serving multiple projects with different component profiles needs per-request context isolation. The SH02 execution manifest must freeze component-profile selection at request time, not process startup time.

**2. AR25 MCP boundary enforcement (§5: thin adapters)**
The item must explicitly state that MCP, event, CLI, and future service transports are inbound adapters that import ONLY the public gateway API. They do not own gateway decisions or import backend internals. This is already stated in SH03 but should be a program-level constraint from SH01.

**3. AS15 compatibility (§1: consistency)**
The session-aware concurrency model (AS15) changes how profile capacity is tracked. The shared gateway's resource arbitration (SH08) must build on AS15's active_running/idle model, not the previous flat pq.running count.

**4. PR05 dependency chain (§4: no circular deps)**
The item correctly defers to PR05 for managed process foundation. However, SH03 (in-process client/control-plane seam) should be implementable BEFORE PR05 — it's a pure refactor with no new process management. This should be explicit in the phase gates.

**5. Security boundary (§7: no secret leakage)**
The item mentions "security boundary" but doesn't define what it means. A shared gateway serving multiple projects must enforce that:
- Project A's requests cannot access Project B's files, MCP servers, or secrets
- Execution workers run in project-isolated contexts (cwd, env, file access)
- The SH02 execution manifest enforces this at the schema level
