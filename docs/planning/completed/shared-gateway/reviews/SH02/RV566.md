# Sponsor review of v0.2: envelope diverged from the working base — strip invented fields, anchor on agent profile as the source of truth

## Notes



## Findings

v0.2 carried fields with no basis in the working system: enabled_features (nothing defines or consumes features outside component profiles), role_intent (roles are future RO work; agent profile is today's source of provider/model), startup_cwd/workspace_roots (execution cwd is the project root today; no multi-root feature exists), env_allowlist/secret_refs (vendor key injection and environment shaping are provider-config capabilities materialized from managed config, not job-request fields). The agent profile (profile_id → provider_id, model_id, model_alias, params incl. retry-count/max-concurrency/stream-controls) is the existing resolution source and the envelope must mirror the existing submit_llm_request surface plus profile-doctrine precedence, not redesign it.

## Conclusion

v0.3: envelope = current submit surface (project_root, agent_profile_id or provider_id+model_id per profile doctrine precedence, component_profile name, mode, timeout, session fields, prompt, metadata) plus only schema_version, idempotency_key, correlation_id, source. Manifest identity = project_root, resolved profile/provider/model, provider_isolation_tier, component_profile, agent_runtime_digest. Execution cwd is the project root. Env/secrets stay provider-config concerns captured by provider_config_revision inside agent_runtime_digest. Future concerns (roles, multi-root workspaces) arrive via schema version bumps when their owning items land — that is what the version field is for.
