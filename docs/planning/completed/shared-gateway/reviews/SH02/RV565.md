# Sponsor review of draft v0.1: remove fallback reselection; freeze agent runtime as digest instead of first-class MCP fields

## Notes



## Findings

1) fallback_profile_ids in the envelope and 'retry/fallback that changes provider/model produces a new attempt with a new manifest' over-complicate the model: policy-driven reselection does not belong in the gateway contract. 2) mcp_set_digest and mcp_servers make MCPs first-class gateway selections, but MCP assembly is owned by AUDiaGentic provider/config management (and later by roles); the gateway must not independently choose or assemble an MCP set. 3) role_intent remains optional and opaque — roles later enhance the baseline agent profile, they are not resolved by SH02.

## Conclusion

Simplified lifecycle adopted: envelope → admission/resolution → one immutable manifest → one or more technical attempts using that same manifest. Technical retries restart the same execution context after worker crash or transient transport failure; any change to agent profile, provider, model, project context, or resolved capabilities requires a new request and new manifest (SH07 model: request_id → manifest_id → attempts). MCP fields removed from the manifest; identity instead freezes the resolved agent runtime as agent_runtime_digest (sha256 over agent-profile, provider-config, and component-profile revisions — covering attached MCPs, tools, instructions, hooks, sandbox, model settings without SH02 understanding them individually). Existing in-process fallback_profile_ids becomes a deprecated surface retired at SH11 cutover; callers wanting reselection submit a new request. Applied to docs/design/gateway-execution-context.md v0.2.
