# Sponsor review of v0.3: strip manifest to the shell — drop runtime_revisions and per-field provenance; later items define their own fields

## Notes



## Findings

The v0.3 manifest still carries day-one-unneeded machinery: the runtime_revisions diagnostics block and the per-field provenance array are heavy records with no identified consumer — scope creep with no idea of need. SH02's job is the shell of the contract: versioned envelope, resolved identity, fingerprint. When later items (SH06 worker debugging, SH07 recovery, RO roles) need more fields, it is up to those items to define and implement them via a schema version bump.

## Conclusion

v0.4: manifest reduced to schema_version, manifest_id, request_id, resolved_at, the six-field identity block, context_fingerprint, session, mode, timeout_seconds, prompt_digest. Removed: runtime_revisions, the provenance array, and gateway_protocol_version (SH04's handshake owns protocol negotiation). agent_runtime_digest stays — it is identity, and its inputs are still the three resolved configurations, just not stored as separate fields. Manifest tamper/integrity testing moves to SH07 with the admission record. Field additions are pushed to the items that need them.
