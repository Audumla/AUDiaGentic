# Provider conversation-load errors must remain observation-only

## Notes



## Findings

- gpt_auto/chat.py bounded load recovery could reach replacement or terminal readiness failure after a short local window.
- gpt_auto/turn.py treated conversation-load-failed as fresh provider failure during response observation.
- Retry clicks must not renew provider-progress activity or reset real inactivity.

## Conclusion

The provider load-error page can persist independently of request execution. Submitted or ambiguous turns must remain bound to the exact conversation and retry only its visible Retry control; proven-unsent recovery remains the only path allowed to replace and replay.
