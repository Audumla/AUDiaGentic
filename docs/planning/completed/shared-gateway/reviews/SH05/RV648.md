# Make degraded Windows lifetime and adopted-lease contract observable

## Notes

Post-completion audit after PR07 Windows breakaway correction and SH04 protocol hardening.

## Findings

1. Automatic bootstrap accepts a foundation session-child fallback but neither health nor the returned client exposes that degraded Job Object lifetime, while SH05 completion claims a detached owner. Publish process lifetime scope in health and on the client; document that automatic mode can be supervisor-bound on Windows. 2. adopted managed-lease validation reuses VAL-AGSV-020, which now means non-canonical project root, and VAL-AGSV-021 has no resolution. Allocate distinct stable codes/resolutions. 3. Bootstrap and host still import PROTOCOL_VERSION through the service application instead of the neutral service-contract module. Correct the dependency direction. 4. Add Windows/POSIX assertions covering the published lifetime scope.

## Conclusion

Implemented. Health and automatic clients expose foundation lifetime scope; Windows session-child degradation is documented and tested while shared-service-host remains distinct. Adopted-lease errors have unique resolutions, and protocol ownership imports the neutral service-contract module. Windows host and clean Linux Docker gates pass.
