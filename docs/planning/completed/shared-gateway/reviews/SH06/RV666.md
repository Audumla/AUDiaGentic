# Coordinate isolated worker implementation with MA17 public execution cutover

## Notes

Dependency audit found the current dispatch path resolves provider config/model and calls execution through providers.services internals.

## Findings

The control plane executes provider code inside queue threads and reads process-global component profile/config. A safe first implementation is one process per one-shot attempt, not pooling. The worker must start under canonical project CWD and frozen component profile before provider imports, use a replacement allowlisted environment, carry only a runtime-only typed execution request (no config/env/secret fields), and use the MA17 public provider materializer/executor. Tier evidence alone must not cause unsafe fixed-config mutation; unsupported materialization is an explicit policy result. SH07 retains durable cancellation/terminal-state semantics.

## Conclusion

Valid. Coordinate MA17 and SH06 now. Reuse foundation supervised-process ownership, require a versioned identity handshake, prohibit reuse across fingerprints, and defer pooling/live-session workers to their owning items.
