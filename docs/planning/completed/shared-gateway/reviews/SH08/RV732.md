# Landed sampler does not implement Slice A; resource identity, gate order, and policy ownership corrections (verified)

## Notes

Source: external plan/code review 2026-07-19 at commit 5bcaaaab.

## Findings

1) SAMPLER IS NOT SLICE A (R1): the landed contention sampler defines resource_key_for() but never uses it; reads resource hints from profile params instead of providers_api; groups by profile:<id>; records distinct_projects=0 permanently; cannot distinguish two projects; no per-request queued wait, no p95/starvation duration; raw NDJSON append outside the guarded operational-record path; no service-host sampler thread; tested with one profile only. No evidence it produces can justify Slice B/C. Required: complete a correct Slice A from immutable service snapshots (canonical/opaque project key, profile queue generation, resolved provider resource key, running/pending/active counts, wait distribution, ingress backlog, sample/config version) — or remove the incomplete production module until ready.
2) RESOURCE IDENTITY OWNERSHIP (R2): endpoint-host fingerprints and exclusive-local-compute claims are not user profile policy — the provider platform exposes a validated neutral resource identity from the resolved execution surface; machine policy supplies local limits for that key.
3) GATE ACQUISITION ORDER (R3): the item's statements (acquire after profile slot; profile concurrency inner; resource admission outer) contradict, and holding either scarce gate while blocked on the other wastes/deadlocks. Required: integrate resource admission at the actual compute boundary from AS15/AS28 — one coordinator or non-blocking reservation loop with a fixed order; for session requests acquire/release around actual transport execution, not around the FIFO-lock wait.
4) POLICY LOCATION (R4): max_concurrent/max_deferred are machine/deployment policy keyed by validated resource identity, not provider-descriptor facts — descriptors declare inherent identity/exclusivity characteristics only.
5) RESTART RECONSTRUCTION (R5): active-work entries carry no resource key, and re-resolving config after restart can yield a different key than admission used. Persist the resolved resource key/config generation in the immutable execution manifest or the protected active-work entry.
6) Evidence tests required: two projects sharing one resolved resource, correct distinct-project count, reproducible p95/starvation, profile IDs alone never defining a resource, sampler crash not corrupting prior evidence.

## Conclusion

Keep SH08 paused. Corrected Slice A (Stage 3) only after the SH07 queue-identity repairs land, since valid samples need the project-scoped queue keys; B/C remain gated on documented evidence thresholds.
