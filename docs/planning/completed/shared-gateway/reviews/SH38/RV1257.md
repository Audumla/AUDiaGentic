# Reconnect after explicit receipt ACK and resume timeouts

## Notes



## Findings

Parent and recipient host source audit confirmed lost ACK is currently classified terminal: sender raises registered CON-AGND-001 with receipt-ack-timeout and host treats all such errors as fatal. Resume request timeout loses typed identity as receipt-sender-failed; channel-close ordering can therefore change reconnect behavior.

## Conclusion

Preserve a bounded explicit receipt-resume-timeout only at the actual network resume await. Host may retry only typed ACK/resume timeout after complete old-channel cleanup and within the finite budget. Cursor contradictions, auth/config, custody I/O, generic sender errors and cleanup failures stay non-retriable. Test both sender/close orderings and producer preservation.
