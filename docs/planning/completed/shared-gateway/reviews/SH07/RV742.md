# C2 decision: execution profiles are gateway-owned

## Notes

Incorporated into SH07 on 2026-07-19. The plan now treats execution profiles as gateway-owned shared resources and specifies request admission, snapshot persistence, lane keying, stale-generation rejection, C6 Model B replay-required recovery, C7 work-index hardening, and C11 interrupted event/job mapping.

Key locked C2 policy: queued work with a stale gateway profile generation/config digest must fail terminally with resubmit-required semantics. Old queued generations do not silently drain. Running work that has already launched continues under its stored immutable snapshot.

## Findings

Resolved and rolled into SH07. The previous ambiguity was whether queue isolation should be keyed by project identity plus profile ID, or by gateway-owned execution profile identity. The accepted design is gateway profile authority: projects reference allowed gateway profiles, while the gateway owns provider/model/limits/config generation and queue coordination.

SH07 now requires a `GatewayProfileSnapshot`, `GatewayExecutionLaneKey`, immutable non-secret profile snapshot fields persisted on request records, `_profiles` replacement with lane-keyed queues, and redacted request-scoped status/overview behavior. It also locks stale profile behavior: queued stale-generation requests are rejected/resubmit-required rather than drained under old config.

## Conclusion

Closed. The C2 design decision and execution details are now part of SH07's implementation steps; no separate open review action remains for RV742.
