# Make all public request results projected and retire unfenced v2 mutation paths

## Notes

Follow-up from RV677 bounded correction review; intentionally separate to avoid broadening the in-flight fix.

## Findings

Most public request operations still return raw durable records: submit, wait, cancel, and run bypass the safe get/list projection. Nested `recovery`, `completion`, `usage`, and attempt error shapes are unconstrained enough to leak sensitive values to HTTP/MCP callers. Production legacy mutators (`transition_record`, `start_attempt`, `append_attempt`, `write_record`) remain callable without v2 owner/revision fences, and existing queue/reconciliation paths use them. Queue claim conflicts can drop an in-memory item leaving a durable queued record with no pending entry; after manager reset, cancel on a missing local profile previously returned unchanged without persisting intent. The immediate durable-cancel correction covers the latter, but a separate pass must apply one explicit public projection to every outward operation, close public nested shapes or exclude them, and restrict/remove bypass mutators with architecture-search gates.

## Conclusion

Valid next SH07 correction after RV677 completes. Preserve request state ownership in agents; do not add generic serialization, retries, or session recovery.
