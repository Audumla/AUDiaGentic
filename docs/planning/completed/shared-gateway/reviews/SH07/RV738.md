# Allow continued sessions to declare post-turn keep-alive policy

## Notes

Implemented and validated. Key correction after worker review: keep-alive must
be nullable at the API/record boundary so omitted continuation preserves the
existing live session, while explicit false means close after turn if
quiescent. Added/updated tests for omitted, explicit true, explicit false, and
bounds validation.

## Findings

The gateway rejects requests that specify both session-id and session_keep_alive/session_idle_timeout_seconds. That prevents the useful contract: continue an existing session for this turn and explicitly decide whether it remains alive afterward. Desired behavior: session-id selects an existing live session; session_keep_alive, when supplied, controls post-turn lifecycle for that continued session. session_keep_alive=true should leave it live after the turn, session_keep_alive=false should close it after the turn unless other pending turns exist. Session idle/max lifetime fields should be allowed only when keep-alive true and should update runtime policy for the continued session if supported, otherwise produce a clear validation error. Add tests around submit validation and runtime lifecycle.

## Conclusion

Handled in source and tests; close this review.
