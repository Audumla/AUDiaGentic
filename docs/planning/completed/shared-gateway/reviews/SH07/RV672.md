# SH07 pre-implementation review: durable service ownership, cancel acknowledgement, and ambiguity-safe recovery

## Notes

Triaged from three independent implementation/test/architecture audits before opening the SH07 block.

## Findings

Current queue/service ownership is still process-local. The next safe SH07 vertical slice is deliberately limited to v2 durable ownership and ambiguity-safe recovery: explicit dispatch owner epoch/claim timestamp/recovery fields; forward-only v1→v2 migration; an `interrupted` terminal workflow state; claim/start/append/terminal store commands fenced by owner epoch + worker id + attempt epoch; a small agents-owned machine active-work reference index; and reconciliation that interrupts old/unprovable queued/running records without re-dispatching (queued = not-dispatched, running = execution-ambiguous). Raw prompts remain absent, so recovery must never retry/resume. Cancellation acknowledgement is separate; session recovery remains AS-owned. Existing foundation StartupLock, atomic writes, ManagedService process evidence, workflow transitions and timelines are reused without placing request semantics in foundation.

## Conclusion

Valid next SH07 implementation slice. Implement only v2 owner claim/migration/reconciliation/status and its crash/race tests; defer cancellation control, worker pooling, and retry/resume to later slices.
