# Validate submission wire types and redact arbitrary metadata before persistence

## Notes

Post-implementation architecture/security review of SH07 admission.

## Findings

Two defects are reproducible in the admission boundary. First, API metadata strips only `idempotency_key`/`idempotency-key`; arbitrary metadata is persisted and published unchanged. `metadata={'prompt_body':'METADATA_SECRET_PROMPT','idempotencyKey':'RAW_KEY_ALIAS'}` leaks both values to the record and event path. Second, `SubmissionEnvelope` does not validate scalar types before execution: non-string idempotency keys reach `.encode()`, non-integer schema versions reach `int()`, and non-numeric timeouts reach comparisons. These become unclassified AttributeError/TypeError/ValueError and the standalone HTTP service reports generic 500 rather than a validation 4xx. The boundary must reject or safely redact reserved/sensitive metadata recursively, validate wire types/ranges before persistence/dispatch, preserve raw prompt only in the in-memory request field, and return canonical VAL errors.

## Conclusion

Valid. Implement immediately as an SH07 correction with direct and standalone-service regression tests. Do not add a generic metadata transport abstraction; apply the existing envelope/record error conventions.
