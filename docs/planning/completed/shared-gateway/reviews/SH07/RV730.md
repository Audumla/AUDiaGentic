# Queue identity/context substitution, unwired recovery, and replay-model decision (external review 2026-07-19, verified; partial fixes landed)

## Notes

Source: external plan/code review dated 2026-07-19 at commit 5bcaaaab; every finding re-verified against main. Complements open reviews RV639/RV672/RV678. Already FIXED in tree 2026-07-19 (do not re-raise): sessions root moved under .audiagentic with lazy legacy migration (C3); service_root threaded submit→enqueue→claim_dispatch so the standalone service now writes active-work entries (C4); GatewayServiceHost.serve_forever runs recover_gateway_requests before readiness and ingress (C5); default idempotency is now a fresh unique key per admission — dedup is explicit-key-only (C8); _intent_digest excludes source/metadata provenance (C9); acknowledge_cancel requires cancel-requested and a closed actor vocabulary {queue-worker, session-runtime, dispatch, recovery} (C10, CON-AGW-086); transition_record rejects updates outside the mutable result set with VAL-AGW-098 (C12).

## Findings

1) QUEUE CONTEXT SUBSTITUTION (Critical, C1): _ProfileQueue.pending holds only request IDs; project_root/params/runner (a functools.partial carrying the RAW PROMPT, manifest ID, context fingerprint, component profile, isolation tier, timeout) are passed into enqueue()/_drain() as arguments. When request A finishes, its finally-drain pops request B and launches B with A's runner/params/project_root — trivially triggered at max_concurrency=1. Required: replace pending with one immutable QueuedDispatch entry (request_id, project_root, profile id, queue key, params snapshot, runner, owner epoch, service root, context fingerprint); _drain accepts only the queue and pops complete entries, never receiving request state from the finishing worker. Test: two distinct runners, two prompt sentinels, two project roots — block A, enqueue B, finish A, prove B executes only B's context. Current queue tests reuse one runner and cannot detect this.
2) CROSS-PROJECT QUEUE SHARING (Critical, C2): GatewayQueueManager._profiles keys only on agent_profile_id — in the shared machine service, Project A's 'default' and Project B's 'default' share one deque/semaphore/limits, and the first project freezes max_concurrency/queue_max_size for everyone; config changes are ignored for existing queues. Required: profile execution queue key = canonical project identity + profile ID + config digest/generation; a config change creates a new queue generation and drains the old (or is rejected while old work remains). SH08 resource grouping happens by explicit resource key, never by accidental queue sharing.
3) QUEUED REPLAY MODEL (Critical, C6): the raw prompt lives only in the in-memory runner; recovery's queued path releases the stale claim, leaves state 'queued', counts 'requeued', but cannot enqueue or reconstruct the runner — the request is permanently stranded. Decide explicitly: Model A (protected work-payload sidecar: prompt body, manifest ref, no credentials, private perms, delete-on-terminal, disclosed retention) enabling real replay, or Model B (no autonomous replay: transition to 'interrupted'/replay-required terminal outcome, require explicit caller replay linking the old request). Model B better matches the current privacy contract. Never report 'requeued' without a real queue entry.
4) ACTIVE-WORK TRANSACTIONAL SAFETY (High, C7): claim writes the request claim before active-work (failure leaves a claimed-but-undiscoverable record); clear_active_work can raise after durable terminalization; queued cancellation doesn't reliably clear a claim-created entry; recovery does not validate entry owner-epoch/filename digest/canonical project-root; malformed entries are deleted not quarantined; missing-request evidence is retained forever. Required: defined ordering/rollback, idempotent non-throwing cleanup after terminalization, schema/digest/root/epoch validation, quarantine with redacted diagnostics, bounded retention, crash injection before/after every record/index write.
5) INTERRUPTED OUTCOME CONTRACT (High, C11): 'interrupted' is terminal but has no lifecycle topic (map covers completed/failed/cancelled/rejected only), recovery publishes no event, and agent_jobs maps only the four outcomes — an event-driven job stays 'running' forever after recovery interrupts its request. Required: one terminal outcome contract (prefer agents.execution.interrupted via SH12, or agents.llm.interrupted now), published exactly once with request/job correlation, mapped by every job consumer, duplicate/late-safe. SH12's rename table must include it (N2).
6) ADMISSION-BEFORE-CLAIM CRASH WINDOW (C6-adjacent): the active-work index is created at claim, not durable admission — a crash between admission and claim leaves a queued record invisible to machine recovery. The chosen replay model must resolve this window (durable-queued scan at startup or admission-time indexing).

## Conclusion

SH07's architecture holds; it cannot be closed on the present queue. Stage-0/Stage-1 order: queue entry immutability + project-scoped queue keys first, then the replay-model decision, then transactional active-work hardening and the interrupted contract. Production-path crash tests through StandaloneGatewayClient are mandatory (kill before claim / after claim / after start / after completion-before-cleanup).
