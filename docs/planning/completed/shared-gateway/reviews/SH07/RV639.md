# SH07 pre-implementation input: cross-process lost-update race on request records, and the 50ms full-revalidation wait poll

## Notes

Deep-dive findings 2026-07-18 that land squarely in SH07's scope (durable, idempotent, recoverable, remotely cancellable requests). Filed now so SH07's design starts from them rather than rediscovering them.

## Findings

1) UPDATED — CROSS-PROCESS WRITE SAFETY: the prior finding that `agents_gateway_store` used only a per-process `threading.Lock` is stale. It now uses per-request foundation `StartupLock`, monotonic revisions, worker/attempt fencing, and has a cross-process append test. SH07 still needs an end-to-end cancel + terminal race test and service/worker ownership epochs before this can be closed. 2) HANDLED — WAIT POLL: `GatewayQueueManager.wait` now makes an initial validated durable read, then uses a size/mtime/ctime change marker with 50ms→500ms bounded exponential backoff. A 500ms validated-read fallback retains correctness on coarse/unreliable filesystem timestamps; an independent Python process terminal writer is observed in Docker. No condition-variable architecture was added because cross-process durable observation remains required. 3) RETRY TAXONOMY: re-check remote error paths so unknown envelope-derived errors cannot cause a non-idempotent side effect to retry.

## Conclusion

The wait-efficiency finding is incorporated and validated. Retain this review: its end-to-end cancel/terminal race coverage and retry-taxonomy findings remain SH07 work.
