# Gateway daemon-thread execution ceiling: 300s cap, orphaned requests, missing crash recovery trigger — from MA18/RV511

## Notes

Routed from MA18/RV511. Gateway creates daemon threads for each request; caller blocks at most 300s then returns. Work exceeding 300s is abandoned mid-flight (daemon thread dies with process). Orphaned records frozen at 'running' forever. Evidence: req_928141cc9d434b24 orphaned 3 days. Three fixes identified: (1) surface timeline in status API, (2) trigger reconcile_gateway_state on startup, (3) decide execution lifetime — move worker out of process or declare gateway for short turns only. SH07's crash-safe recovery model must address this: worker_id, attempt_epoch, and durable admission/dispatch transitions are needed.

## Findings

Valid. The current in-process daemon worker and bounded caller wait can orphan a running record and cannot provide service-grade durability. SH07 step 0 now requires characterization, status visibility, and safe reconciliation wiring; steps 1-6 require schema-versioned worker/attempt identity, owner epoch/lease, ownership-aware recovery, cancellation acknowledgement, crash points, and exactly-once terminal projection without claiming exactly-once provider execution. SH04/PR07 establish the prerequisite service lifetime before these durability claims are implemented.

## Conclusion

Incorporated into the pending SH07 delivery scope. No premature thread-level patch is appropriate before SH04 service ownership; close this review while SH07 remains pending for implementation.
