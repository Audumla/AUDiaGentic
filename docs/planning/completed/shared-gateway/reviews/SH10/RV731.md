# Drain admits work, quiescence is not authoritative, stop races its own lease, signal/force gaps (verified)

## Notes

Source: external plan/code review 2026-07-19 at commit 5bcaaaab; verified against agents_gateway_service_application.invoke (lease-only validation), the host ingress poller, and the lifecycle controller.

## Findings

1) DRAIN ADMISSION GATE (L1): request_drain changes only managed-service state — invoke() validates the lease, not the service state, so existing clients can still submit; the ingress poller calls the application directly and keeps admitting offline triggers while draining. Required operation policy while draining: allow status/wait/cancel/list/overview/close-session/operator ops; reject or defer submit/run/open-session/anything creating work; pause ingress consumption leaving pending files untouched; resume restarts admission. Enforce at the framework-neutral application/lifecycle boundary, not only HTTP.
2) READINESS ORDER (L2): partially repaired 2026-07-19 — the host now runs SH07 recovery before the ready heartbeat and before ingress. Remaining: readiness should also require ingress/store root validity and a lifecycle state able to accept work, with a degraded/not-ready health state when reconciliation cannot complete.
3) AUTHORITATIVE QUIESCENCE (L3): gateway_quiescence_facts counts in-memory queue/live sessions/pending ingress files only — it misses durable queued records not in memory, active-work entries, recovery in progress, an ingress handler between spool read and admission, finalization in progress, and ambiguous owner/worker state. A restarted service can self-declare quiescent with stranded records. Required: one host-owned immutable quiescence snapshot over all queue generations, active-work/recovery state, pending AND in-flight ingress, live sessions/turns, mandatory finalization, unresolved durable records; unknown/unreconciled state counts as busy.
4) STOP/CALLER-LEASE RACE (L4): service_stop subtracts the caller lease then synchronously calls server.shutdown(); ManagedServiceOwner.retire() refuses while any active lease remains, but the caller cannot release until it gets the response — result: HTTP exits, retirement fails, durable record stuck 'draining'. Required: stop ticket/coordinator — validate, transition draining, flush the accepted response, revoke/release the operator lease under a defined rule, wait for other leases/quiescence, stop server, retire owner. The request handler must not own the whole retirement path.
5) SIGNAL HANDLING (L5/L6): calling lifecycle.request_stop from the main-thread signal handler can deadlock (HTTP shutdown must come from another thread). The handler should only set intent, record the signal, and wake one coordinator thread. SIGTERM means bounded graceful drain then force after the deadline — not immediate force.
6) FORCE-STOP CLEANUP (L7): force reports counts and shuts down HTTP but does not signal/terminalize current requests, close owned sessions, clean child trees, or record uncertain/interrupted outcomes — the item's 'no orphan' validation is not provided by the code. Coordinate force with SH07 recovery, AS26 finalization, AS17/AS28 owned shutdown, and the external-process no-signal rule.
7) ADMIN TRUST MODEL (L8): every authenticated lease can drain/resume/stop. If acceptable for a same-user loopback single-token service, state that explicitly; otherwise add an admin lease capability/separate token. Hiding the tool from one MCP surface is not a control.

## Conclusion

SH10's lifecycle goal holds; the current core slice is not complete. Sequence the drain gate + ingress pause + quiescence + stop coordinator + signal/force work as the Stage-2 block after SH07 Stage-0/1 repairs.
