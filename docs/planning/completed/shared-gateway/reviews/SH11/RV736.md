# Component identity alignment, generic implementation management reuse, machine/project option split, refuse-by-default coexistence (verified)

## Notes

Source: external plan/code review 2026-07-19 at commit 5bcaaaab. Includes automatic-mode findings A1–A6.

## Findings

1) COMPONENT IDENTITY (M1): the agents component presents as 'Agent Profiles' owning profile CRUD + gateway execution. embedded/standalone/automatic as exclusive implementations only works if the component is restated as an Agent Execution capability whose invariant core is profile management and whose swappable backend is gateway management — otherwise use a separate gateway component. Update the descriptor responsibility, define the backend contract, keep profile CRUD invariant, and let implementation selection affect only gateway client composition.
2) REUSE GENERIC IMPLEMENTATION MANAGEMENT (M2): use the repository's existing implementation descriptors, exclusive cardinality, generic config schema, get/set tools, and provenance — no gateway-specific option store, second registry, custom schema validation, or implementation-specific tools.
3) REMOVE mcp-gateway PLACEHOLDER (M3): an intentionally unsupported selectable descriptor with no concrete product violates evidence-led scope and can only fail. Keep MCP-gateway extensibility in design docs until a real plan names a backend.
4) ENVIRONMENT SANITIZATION (A1): automatic mode inherits the first starter's complete environment (os.environ.copy() minus two AUDIAGENTIC vars) — HOME/PATH/provider API keys/proxies/Python env leak into the long-lived machine service, first-starter-wins. Required: gateway-owned service environment allow-list (minimal system/runtime vars, explicit executable env, service identity/config, NO provider credentials); credentials materialize per request/worker through provider-owned APIs and the resolved manifest; machine-scope credentials, if intentional, are declared and fingerprinted.
5) MACHINE vs PROJECT OPTION SPLIT (A2): project/client selection (mode, client timeout, endpoint/token ref, coexistence policy) is project-scoped; machine service declaration (root, port, idle policy, environment, protocol/config fingerprint) is machine-scoped. Attach compares expected declaration with the live handshake and accepts the authoritative machine config or fails clearly — never first-starter-wins with later clients believing their own config applies.
6) CLIENT PROTOCOL/TIMEOUTS/CACHE (A3/A4/A5): freeze one complete framework-neutral GatewayClient protocol (currently behind StandaloneGatewayClient's ad-hoc ops); define operation-specific transport timeouts (submit/status/cancel/list short; wait/run = application bound + margin; stop = accepted/async ticket) — today run with no timeout abandons at the 30s transport default despite the 300s blocking default; make the client cache key an immutable selection fingerprint (implementation revision, options, token version, service declaration/config generation), with env aliases as a short-lived compatibility input only.
7) EMBEDDED COEXISTENCE (A6): default REFUSE when embedded mode runs beside a provable shared owner (both paths mutate the same records under separate owners); override requires explicit acknowledgement + isolated root/fixture + no shared-semantics claim.
8) DEFAULT-FLIP GATES (M4): the soak matrix must add distinct-prompt queue isolation, two projects with one profile ID, service-root active-work integration, crash-before-claim, queued replay/interruption, drain admission refusal, stop caller-lease retirement, sanitized environment, machine-config mismatch, and first-turn live-session recovery tests — otherwise a soak passes while the severe defects persist. Automatic cannot become default until SH07/SH10 correctness is repaired.

## Conclusion

Final cutover goal holds after major rebase. Sequence: Stage 6, after SH07/SH10 repairs, SH08 Slice A evidence, the AS28/AS29 neutral seam, and SH12's rename — do not stabilize descriptors/conformance/docs around names SH12 deletes.
