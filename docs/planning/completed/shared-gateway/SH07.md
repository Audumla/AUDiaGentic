# Make gateway requests durable, idempotent, recoverable, and remotely cancellable

## Description

Replace CLI-lifetime recovery assumptions with service-grade queue ownership. Define durable admission and dispatch identity, idempotent submission, ownership leases/epochs, cancellation observation, crash recovery, and terminal-result uniqueness across service and worker restarts. SH07 is the single durable job-state authority: gateway job/request state materializes only through SH07 record transitions, fed by capability-declared observation evidence — never by a parallel transport-specific state store.

## Steps

V2 fencing, C1 queue-entry immutability, RV741 progress projection, and RV739 opencode verification are LANDED. The remaining SH07 closure work is these executable slices, in order.

### Slice 0 — C2 gateway-owned execution profile lanes

Decision: execution profiles are gateway-owned shared resources. Projects reference allowed gateway profile IDs; they do not own queue limits or profile definitions. Project identity remains request/session/security context, not profile authority.

Add a gateway profile snapshot boundary before queue admission. Suggested module: `src/audiagentic/components/agents/agents_gateway_profiles.py` unless an equivalent gateway-owned profile resolver already exists.

Required public/internal types:
```python
@dataclass(frozen=True)
class GatewayProfileSnapshot:
    profile_id: str                  # caller-facing gateway profile id
    generation: str                  # opaque gateway profile generation
    config_digest: str               # stable digest of non-secret execution config
    provider_id: str
    model_id: str | None
    max_concurrency: int
    queue_max_size: int
    execution_params: Mapping[str, Any]  # redacted/non-secret params only
    admission_policy_digest: str

@dataclass(frozen=True)
class GatewayExecutionLaneKey:
    profile_id: str
    generation: str
    config_digest: str

    def public_id(self) -> str: ...   # e.g. profile_id + generation + short digest, no paths/secrets
```

At request admission:
1. Resolve `agent-profile-id` against the gateway profile registry, not the project-local profile file in shared/automatic gateway mode. Embedded compatibility may continue to use project profiles only when no shared gateway is involved.
2. Persist the immutable resolved snapshot identity on the request record:
```json
"gateway-profile-id": "lite-coder-opencode",
"gateway-profile-generation": "gen_...",
"gateway-profile-config-digest": "sha256:...",
"gateway-execution-lane-key": "lite-coder-opencode/gen_.../<12hex>",
"resolved-provider-id": "opencode",
"resolved-model-id": "...",
"resolved-queue-limits": {"max-concurrency": 1, "queue-max-size": 20},
"admission-policy-digest": "sha256:..."
```
Only persist non-secret snapshot metadata. Do not persist provider auth, raw env, API keys, tool payloads, or full profile documents.
3. Build `QueuedDispatch` from that immutable snapshot. `params` on the entry must be the resolved snapshot params, not a caller/project mutable dict.
4. Replace `GatewayQueueManager._profiles: dict[str, _ProfileQueue]` with `_lanes: dict[GatewayExecutionLaneKey, _ProfileQueue]`. `_profile_queue(...)` becomes `_execution_lane(snapshot)` and creates the queue using snapshot limits only.
5. `queue_depth`, `all_queue_depths`, and overview expose redacted lane public IDs and counts. Request-scoped status may show only the caller's own request lane identity, never other projects' request IDs or project roots.

Stale-generation policy (locked): queued work must fail and require a new submission. Do not silently drain old profile generations.
- Running work that has already launched continues under the snapshot stored on its request unless it fails normally; do not mutate it to a new profile.
- Queued/pending work whose stored snapshot no longer matches the current gateway profile generation/digest must transition to terminal `rejected` before dispatch with a redacted error such as `CON-AGW-101 gateway profile changed; resubmit required`.
- A new submission resolves the current generation and enters the new lane.
- Add a helper such as `validate_snapshot_current(snapshot) -> SnapshotCurrent | SnapshotStale`; call it before enqueue and immediately before `_run_one` claims dispatch.

Required C2 tests:
- Two projects submit to the same gateway profile; the global gateway profile limit is enforced across both, while each request still executes with its own project root/runner/session context.
- A project-local profile with the same name cannot change shared gateway queue limits in shared/automatic mode.
- First project no longer freezes limits; limits come from the gateway snapshot only.
- Profile generation changes while a request is pending: the pending request is terminal `rejected` with resubmit-required error; a new submission uses the new generation and can run.
- Running request keeps its stored snapshot after profile generation changes.
- Queue overview groups by redacted gateway lane key and leaks no project roots/secrets.
- Request status includes the resolved profile snapshot identity for that request.

### Slice 1 — C6 replay model: terminal replay-required, no autonomous replay

Decision: use Model B. SH07 must not persist prompt payload sidecars for automatic replay.

Replace the current misleading `requeued` recovery behavior. Recovery must never report `requeued` unless it has actually created an in-memory queue entry, which Model B does not do.

Required behavior:
1. Introduce a terminal replay-required outcome using existing terminal state `interrupted` plus error code, e.g. `CON-AGW-102 replay required after gateway recovery`.
2. Stale queued records found during recovery transition to `interrupted`, not back to `queued`, because the runner/prompt cannot be reconstructed.
3. Stale running records continue to transition to `interrupted` with existing stale-owner error semantics.
4. Add request linkage fields for explicit caller replay:
```json
"replay-required": true,
"replay-reason": "gateway-recovered-without-work-payload",
"replayed-by-request-id": null,
"resumed-from-request-id": null
```
A later explicit submission may set `resumed-from-request-id` / update the old request's `replayed-by-request-id` through a fenced helper. Never silently execute the old prompt.
5. Resolve admission-before-claim crash by indexing admitted work before/at durable admission, not only after claim. The control-plane index entry may be phase `admitted|claimed|running|terminal-cleanup`; it must contain no prompt body.

Required C6 tests:
- Recovery of stale queued record returns `interrupted`, `replay-required=true`, and no pending queue entry.
- Recovery report uses `interrupted` / `replay_required` count, not `requeued`.
- Crash after admission before claim is discoverable via the index and terminalizes to replay-required.
- Explicit new submission can link to old interrupted request; old request is not re-executed.

### Slice 2 — C7 transactional active-work/control-plane index safety

Harden the active/admitted work index as a references-only transactional control-plane index.

Required helpers in `agents_gateway_store.py` or a cohesive `agents_gateway_work_index.py`:
```python
def write_work_index_entry(service_root, project_root, request_id, *, phase, owner_epoch=None, lane_key=None) -> None: ...
def update_work_index_phase(service_root, request_id, *, from_phase, to_phase, owner_epoch=None) -> None: ...
def clear_work_index_entry(service_root, request_id) -> bool: ...  # never raises to terminalization caller
def quarantine_work_index_entry(service_root, path, *, reason_code) -> None: ...
def validate_work_index_entry(entry) -> WorkIndexEntry | InvalidEntry: ...
```

Entry requirements:
- request id, canonical project root, project-root digest, dispatch owner epoch when claimed, lane key, phase, claimed/admitted timestamp, schema version.
- filename or body must include/check a digest so a malformed filename/body mismatch is quarantined.
- no prompts, outputs, auth, provider refs, raw protocol payloads, or stack traces.

Ordering policy:
- Admission writes request record and index entry under the admission/request mutation discipline before the request can become invisible to recovery.
- Claim updates request claim and index phase in a defined order with rollback or conservative recovery if the second write fails.
- Terminal transition writes terminal request state first, then best-effort non-throwing index cleanup. Cleanup failure must not undo terminal state; recovery later clears/quarantines stale terminal entries.
- Malformed/unreadable/mismatched entries are quarantined with redacted diagnostics, not silently deleted.
- Missing request records referenced by index are quarantined with bounded retention.

Required C7 tests:
- Crash/fault injection before and after each record/index write: admission, claim, start, attempt append, terminal, cleanup.
- Cleanup failure after terminalization does not fail the terminal transition and is later recoverable.
- Malformed entry goes to quarantine, not delete.
- Entry with mismatched project-root digest/request id is quarantined.
- Bounded retention cleanup removes old quarantine entries without touching valid active entries.

### Slice 3 — C11 interrupted terminal event and downstream job mapping

Decision: introduce `agents.llm.interrupted` now; SH12 may later rename/map it to `agents.execution.interrupted`.

Required changes:
1. Add `LLM_INTERRUPTED_TOPIC` / `agents.llm.interrupted` to the agents event catalog and constants.
2. Include `interrupted` in `_TERMINAL_EVENT_SUFFIXES` and lifecycle topic map in `agents_gateway_queue.py`.
3. Ensure recovery-published interrupted terminals emit exactly one lifecycle event with request id, project/correlation metadata, replay-required flag if applicable, and redacted error code.
4. Update agent-jobs consumers/mappers so gateway request `interrupted` maps to a terminal job state instead of leaving jobs running. Coordinate names with SH12 N2 but do not wait for SH12 to make recovery safe.
5. Add duplicate/late safety: replayed recovery or duplicate terminal transition must not publish a second interrupted event for the same request/decision.

Required C11 tests:
- Recovery interrupted request publishes `agents.llm.interrupted` exactly once.
- Agent-jobs mapped job reaches terminal interrupted/failed-equivalent state according to existing job workflow policy.
- Duplicate recovery pass does not republish.
- Public status/progress shows interrupted without leaking raw recovery internals.

### Production crash matrix for SH07 closure

Run through `StandaloneGatewayClient` / service path, not only in-process unit tests:
- two projects sharing one gateway profile with global max_concurrency=1;
- profile generation changes while pending -> old request rejected/resubmit required;
- crash after admission before claim -> replay-required interrupted;
- crash after claim before start;
- crash after start before attempt append;
- crash after terminal before index cleanup;
- cancel raced with recovery;
- malformed active-work/control-plane entry quarantine;
- interrupted event reaches downstream job consumer.
