# Reuse GPT default sessions per client process, project and agent

## Description

Use automatically derived stdio client identity via gateway lease to retain a per-client/project/agent default GPT session. Blank selection reuses default; explicit session/new session overrides do not replace established default. First successful selection establishes default. Missing sessions attempt URL-based recovery; any recovery failure creates replacement default with bounded warning. Never replay possibly submitted prompts without reconciliation.

## Steps

1. Stabilize automatic client instance identity across lease reattachment. 2. Add atomic gateway-owned default binding and explicit new-session flag. 3. Reuse durable session resume and URL recovery, bounded fallback warnings, no ambiguous-turn replay. 4. Update MCP descriptions and compact responses. 5. Test concurrent first calls, scope isolation, first explicit/new adoption, override preservation, reopen/fallback, and async failures.

## Acceptance Criteria

- A blank selection reuses one default per client process, project and agent (scope isolation tests)
- Concurrent first selections establish one atomic binding and explicit overrides leave the default untouched (thread and two-process tests)
- Missing sessions recover by URL or produce bounded replacement warnings; terminal defaults are replaced while retaining the chat
- Ambiguous submissions never trigger a blind replay: a presubmit failure never replaces the default, a retry needs explicit same-session proof, and a late failure cannot overwrite a replacement
- The gateway-owned binding survives a process restart (fresh-interpreter test); client defaults need not survive the client process, which is the recorded design
