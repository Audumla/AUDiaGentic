# Gateway Docker tests: real provisioning, concurrency coverage, negative paths

## Description

Brought the two existing gateway Docker suites (crash-matrix, opencode) in line with the repo's established clean-room Docker test pattern (tests/TESTING.md, tests/integration/providers/harness.py) and added a third suite proving real concurrent load — a guarantee previously only tested against an in-process fake.

## Steps

1. New shared module tests/integration/agents/gateway_docker_harness.py (modeled on tests/integration/providers/harness.py): real agent-profile creation via agents_api.create_profile (not hand-written YAML), real provider CLI install via install_provider_cli, HoldableRigHandler (a local OpenAI-compatible rig with peak-concurrency tracking so tests can prove genuine overlap, not just eventual completion), and gateway-subprocess lifecycle helpers.
2. Refactored test_gateway_crash_matrix_docker.py to use the shared harness (mechanical, no behavior change) — all 4 crash/recovery scenarios still pass.
3. Refactored test_gateway_opencode_docker.py: the opencode CLI is now actually installed by the test (via the same install_provider_cli path tests/integration/providers/harness.py uses) instead of assuming shutil.which('opencode') already resolves on the host PATH — that assumption was silently host-state-dependent, not a real clean-room proof. Provider coverage is discovered DYNAMICALLY (gateway_rig_compatible_npm_provider_ids(): npm-installable AND declares the real 'model-projection' automation capability apply_model_sources itself uses) rather than hardcoded to 'opencode' — today resolves to ['opencode'], automatically covers more providers if they gain the capability. Added 2 negative tests (real cancel of an in-flight request, rejection of an unresolvable profile before touching the provider) where there were previously zero.
4. New tests/integration/agents/test_gateway_concurrency.py + Dockerfile.gateway-concurrency: 5 tests against a real gateway subprocess and a real rig — max-concurrency genuinely bounding simultaneous dispatch (peak-concurrency asserted, not assumed), two different projects sharing one gateway-owned profile lane (SH07 Slice 0 / SH13, never proven against a real subprocess before), queue-max-size rejection, reload-vs-in-flight-load races, cancel-vs-concurrent-dispatch.
5. Added agents_gateway_service_process.py --gateway-profiles-config CLI flag — previously the real subprocess entry point could never run in shared/gateway-owned-registry mode at all, only GatewayServiceHost.create() (in-process) supported it.
6. Fixed a real bug found while building this: agents_gateway_api.submit_llm_request never passed service_root into store.admit_record, so the admission-phase work-index entry (which SH07 recovery relies on to discover admitted-but-unclaimed requests after a crash) was never written in production — the crash-matrix suite's first scenario was untestable until fixed.
7. Host-side e2e wrappers (tests/e2e/agents/), Makefile targets, CI matrix entries, tests/run_all.py wiring, and a tests/TESTING.md image-layout table update — the two prior suites had none of these (never ran in CI, no Make target, undiscoverable).
