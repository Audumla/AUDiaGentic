# SH07 C2 initialize gateway-owned profile registry

## Description

Make shared gateway profile authority real at service startup. The gateway, not a project-local profile file, must construct and own the registry used by every request.

## Steps

1. Add a gateway configuration loader/registry factory beside agents_gateway_profiles.py that reads the gateway-owned profile definitions and creates an immutable GatewayProfileRegistry snapshot with generation/config_digest per profile. 2. Initialize it exactly once in GatewayServiceHost/GatewayServiceApplication startup before readiness and ingress; call set_gateway_registry(registry). 3. Add an atomic reload_profile_registry() service operation: load/validate candidate config, construct a complete new registry, swap the pointer under a short lock, and retain the previous registry on failure. 4. Publish only redacted reload outcome/generation metadata. 5. Reject shared-mode requests when the requested profile is absent or disallowed; do not fall back to project-local limits. 6. Preserve embedded compatibility only when no shared service host is active. 7. Existing running requests retain their snapshot; queued stale snapshots reject with CON-AGW-101/resubmit-required. 8. Add a production-path test with two project roots proving one global lane limit, live reload/generation rejection, and no interruption of a running request. 9. Add a self-review test for secret/path redaction in status and queue overview.

## Files

src/audiagentic/components/agents/agents_gateway_profiles.py; src/audiagentic/components/agents/agents_gateway_service_host.py; src/audiagentic/components/agents/agents_gateway_service_application.py; src/audiagentic/components/agents/agents_gateway_api.py; tests/unit/agents/test_agents_gateway_profiles.py; tests/integration/agents/test_gateway_e2e_states.py

## Validation

Focused profile/API/queue/service tests; reload success/failure/concurrency tests; standalone service-path test proving running work survives reload and queued stale work is rejected.

2026-07-19 partial progress via RV745 (closed under SH07): steps 1-2 landed. GatewayServiceHost.create now loads gateway-owned profile definitions from a machine-scoped gateway-profiles.yaml (audiagentic_home()/config/, overridable via gateway_profiles_config param) through agents_gateway_profiles.load_gateway_registry_from_config(), and calls set_gateway_registry() before the store/server are constructed — so shared mode is registry-authoritative from the first admitted request, not a manual wiring step. host.close() clears the registry. Proven with a production-path test through the real HTTP service host.

2026-07-20 steps 3-9 landed (commit 4e575c86 area). First verification pass found the production-path integration tests failing on real bugs (not test races) — all now fixed by Claude, tests green:
1. agents_gateway_service_application.py passed `_dispatch_service_root=...` into a call chain agents_gateway_api.submit_llm_request()/run_llm_request() didn't accept (TypeError). Fixed: both now accept and forward `_dispatch_service_root` into `_QUEUE_MANAGER.enqueue(dispatch_service_root=...)`.
2. Deeper, load-bearing bug found while chasing the above: `InMemoryGatewayRegistry.register()` derived `generation` from a per-instance version counter (`self._versions`), but `load_gateway_registry_from_config()` builds a fresh registry instance on every call/reload — so the counter reset to the same value every time and generation NEVER actually changed across a reload, silently defeating the entire CON-AGW-101 stale-rejection guarantee this item exists to prove. Fixed: generation is now a content digest (provider/model/limits/params), stable when config is unchanged and different when it changes.
3. `submit_llm_request` never actually resolved a snapshot from the live gateway registry at all when one was installed — it only did project-local profile resolution, so `gateway-profile-generation` etc. were never populated on new records (always None), meaning shared-mode admission was effectively unimplemented for real requests despite the registry/validation machinery existing. Fixed: submit_llm_request now resolves `get_gateway_registry().resolve_snapshot(profile_id)` when a registry is installed, uses its provider/model/params as authoritative, and persists the full snapshot identity on the record via store.build_record.
4. Several test-authoring bugs in tests/integration/agents/test_gateway_standalone_service.py fixed: a fabricated `client._acquire_lease()/_invoke()` API replaced with the real `client._call()`/typed wrapper methods (2 tests); `_start_host()` never threaded `gateway_profiles_config` through so two tests' custom gateway config was silently ignored (now an optional kwarg); an event-handler test callback had the wrong arity for the 3-arg event bus dispatch convention; `test_absent_shared_profile_rejected_not_fallback` used the `SharedApplication` fake test double (which stubs submit_llm_request and never touches the registry) instead of the real application, so it could never actually exercise rejection — switched to the real GatewayServiceHost; a reload-race test asserted stale-snapshot rejection before the running request's slot ever freed (structurally impossible under the lazy-validate-before-dispatch design) — reordered to release/complete the running request first, matching the actual guarantee (validated before dispatch, not proactively at reload time).

Full independent verification (Claude, not worker self-report): tests/unit/agents/test_agents_gateway_profiles.py (24/24), tests/integration/agents/test_gateway_standalone_service.py (25/25 after fixes), plus the full agents+jobs+foundation-boundary suite all green except 4 unrelated pre-existing e2e_states.py tests (live session-handle latest-turn-event enrichment — a distinct, separately-scoped gap, not caused by or blocking this item).
