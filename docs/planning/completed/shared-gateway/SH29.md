# Fix stale watchdog-state surviving terminal request transitions

## Description

Dashboard rows for terminal (failed/rejected/interrupted/completed) requests were showing watchdog-state: active with reason awaiting-verified-activity, contradicting the terminal state. Root cause: bind_and_start_owned_attempt sets watchdog-state=active when a request starts running, but transition_owned_terminal and transition_recovered_terminal never cleared it on terminalization, so the last value from the running phase leaked into terminal records forever. Confirmed live: 6 of the current failed rows carried stale watchdog-state=active.

## Steps

1. Add watchdog-state/watchdog-reason to _MUTABLE_RESULT_FIELDS in store/_shared.py so transition_record accepts clearing them.
2. In transition_owned_terminal (store/_transitions.py), force watchdog-state=not-started and watchdog-reason=None into terminal_updates before calling transition_record.
3. In transition_recovered_terminal, set the same two fields directly in the inline record update (this path bypasses transition_record's field fence).
4. Run gateway store/queue test suite to confirm no regression.
