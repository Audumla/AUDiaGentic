# Verify event-driven linkage end-to-end

## Description

Verify the complete event-driven linkage pipeline after PL02, PL04, and PL01 are implemented:

1. **Schema:** Confirm `ledger-events` appears as a valid section key — run `plan_update_item(CC01, {"ledger-events": "- test-chg"})`, verify it renders in the markdown file and persists through `get_item`.
2. **Ledger publish:** Record a change event with `plan-item-ids`: `record_change_event({"change-class": "feature", ..., "plan-item-ids": ["CC01"]})`. Verify ledger publishes `ledger.event.recorded` event (check logs).
3. **Planning subscribe:** After step 2, call `plan_get_item("CC01")` — the `ledger-events` section should contain `- <event-id>` from the recorded change event.
4. **Multiple events:** Record a second change event for the same item. Verify both event IDs appear in the ledger-events section (accumulation, not overwrite).
5. **Bad ID handling:** Record with non-existent plan-item-id. Verify ledger records normally, planning logs error and skips the bad ID.
6. **Instruction surface:** Run `audiagentic surface apply`, confirm AGENTS.md shows the `plan-item-ids` instruction in the ledger section only when ledger is enabled.
