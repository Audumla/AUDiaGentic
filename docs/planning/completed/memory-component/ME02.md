# Stage 2 — Hindsight implementation descriptor and state model

## Description

Add first `memory` implementation, `hindsight`, with implementation-local config and status semantics. This stage must finish with one unambiguous project config shape for Hindsight and a doc-backed mapping of which provider integrations are officially supported.

## Steps

1. Create implementation descriptor at `src/audiagentic/config/components/memory/hindsight.yaml` with `type: implementation`, `parent: memory`, `id: hindsight`, `default: true`, and implementation-scoped `options-schema`.
2. Include exact option keys in the first draft unless Hindsight docs forbid them: `base-url` (required), `api-key` (optional), `timeout-seconds` (defaulted), `enabled-providers` (optional allowlist), `transport` (enum if docs show multiple modes).
3. Create a small config/state API in `src/audiagentic/components/memory/memory_api.py` for: read active implementation, read Hindsight config, validate URL/options, and persist implementation config.
4. Record canonical config file path chosen in ME01, with example shape for selected implementation plus per-implementation options. Example must show active implementation = `hindsight` and URL field placement.
5. Before writing provider projection code, audit Hindsight docs and produce a provider integration matrix in this item notes or linked review: provider id, doc URL, official integration exists yes/no, required config shape, auth requirements, unsupported notes.
6. Define status behavior exactly: `memory_status` should report configured/not-configured, active implementation, and doc-backed provider support summary. Live network reachability check is out of scope unless it can be done without adding new infrastructure assumptions.

## Validation

- Implementation descriptor loads as `type: implementation` under parent `memory`.
- Example config/state shape is written down and internally consistent.
- Hindsight-specific options appear only in implementation config, not component root.
- Provider integration matrix exists with source links/URLs for every provider currently in scope.
- `memory_status` output contract is specified enough that another agent can code it without guessing fields.

## Effort & Risk

Main risk is implementing against assumed Hindsight config rather than official docs. Mitigation: no provider projection work starts until integration matrix with doc URLs is captured.
