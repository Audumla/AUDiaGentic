# Stage 1 — Memory component contract and implementation model

## Description

Define new `memory` component as installable AUDiaGentic capability with swappable implementations. Follow `agent-planning` pattern for exclusive backend selection, but keep provider-surface projection hooks explicit because memory configuration must flow into provider adapter files.

## Steps

1. Create component descriptor at `src/audiagentic/config/components/memory.yaml` with `type: component`, `id: memory`, `display-name`, `description`, and `implementation-cardinality: exclusive`.
2. Model management server after `src/audiagentic/config/components/planning.yaml` as `ag-memory-mgmt` with exact tools: `memory_status`, `memory_list_implementations`, `memory_select_implementation`, `memory_get_config`, `memory_set_config`.
3. Decide v1 activity-server posture in this stage and lock it: either no `ag-memory` server yet, or an empty/deferred activity server. Record decision in item notes and descriptor comments so later stages do not reopen it.
4. Create package scaffold targets for later implementation: `src/audiagentic/components/memory/__init__.py`, `memory_api.py`, `memory_mcp.py`, `memory_bootstrap.py`, `README.md`.
5. Define persisted state targets before any code is written. Use project-owned config under `.audiagentic/config/` plus generated/runtime state only if needed. Record canonical path in this item before Stage 2 begins.
6. Add harness doctrine to component descriptor only for management usage patterns; do not hand-write provider tool catalogs.

## Validation

- `memory.yaml` loads under component registry without adding import lists.
- Management tool names are fixed and documented exactly as above.
- Component contract names generic memory concepts only; no Hindsight-specific keys appear in component-level schema.
- Persisted config path for selected implementation is explicitly chosen and recorded.
- v1 decision on presence/absence of `ag-memory` activity server is closed here, not deferred implicitly.

## Effort & Risk

Risk is leaving contract half-generic, half-Hindsight-specific. Mitigation: component-level schema only stores active implementation and generic status; implementation-specific config lives in implementation-scoped state.
