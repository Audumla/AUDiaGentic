# Stage 4 — Memory management MCP tools and implementation switching

## Description

Implement the memory management MCP surface and wiring needed to switch implementations and update implementation config without manual file edits. This stage must end with stable tool contracts another agent can test directly.

## Steps

1. Implement `ag-memory-mgmt` in `src/audiagentic/components/memory/memory_mcp.py` using exact tool names fixed in ME01: `memory_status`, `memory_list_implementations`, `memory_select_implementation`, `memory_get_config`, `memory_set_config`.
2. Define exact input/output contract for each tool in descriptor tool-descriptions before coding logic:
- `memory_status()` → active implementation, configured bool, provider support summary, last projected state if tracked.
- `memory_list_implementations()` → available implementations, active flag, default flag, summary.
- `memory_select_implementation(implementation_id)` → persists selection, triggers refresh/reconcile path, returns updated status.
- `memory_get_config(implementation_id | None)` → resolved config for active or requested implementation.
- `memory_set_config(implementation_id, updates)` → validates options, persists state, triggers surface refresh, returns updated config/status.
3. Route business logic through `memory_api.py`; keep MCP layer thin like existing component servers.
4. Hook successful selection/config updates into existing refresh paths. Minimum expected side effects: provider surface apply/reconcile and harness refresh if memory descriptor contributes instructions.
5. If an `ag-memory` activity server is needed in v1, define exact reasons and tool list here. Otherwise explicitly keep activity server absent and document that provider integration is config projection only in v1.
6. Add error mapping/guidance if memory config validation introduces reusable error codes.

## Validation

- All five management tools are declared in component YAML and implemented in MCP module.
- Another agent can call each tool without guessing argument names.
- `memory_select_implementation('hindsight')` updates persisted active implementation.
- `memory_set_config('hindsight', ...)` validates and persists config, then triggers projection refresh path.
- Repeated config apply is idempotent: same input yields no extra drift in managed provider files.

## Effort & Risk

Risk is overloading management tools with provider-specific special cases. Mitigation: tools operate on implementation selection/config only; provider-specific render decisions stay in ME03 projection code.
