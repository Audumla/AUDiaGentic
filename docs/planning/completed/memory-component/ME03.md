# Stage 3 — Provider-specific Hindsight surface projection

## Description

Project Hindsight config into provider surfaces using official Hindsight integration shapes first, and descriptor-driven fallback behavior second. This stage owns exact adapter/file touchpoints and must define what happens for every in-scope provider ID.

## Steps

1. For each provider in the ME02 matrix, classify one of three modes: `official-native`, `custom-managed-block`, or `unsupported`.
2. For `official-native` providers, identify exact target adapter files under `src/audiagentic/components/providers/adapters/<provider>/` and exact rendered file(s) in project root that must receive managed blocks or config entries.
3. Implement memory projection through provider surface system, reusing existing touchpoints: `src/audiagentic/components/providers/surfaces/manager.py`, `src/audiagentic/components/providers/services/reconcile.py`, and any provider adapter `surface.py` files that own instruction/config rendering.
4. Do not branch on provider IDs in unrelated core code. Keep provider-specific memory rendering in provider adapter renderers or in a memory-specific projection service invoked from provider surface generation.
5. For unsupported providers, choose and record one exact fallback behavior now: either emit no changes plus surfaced warning in `memory_status`, or write a generic managed note block. Do not leave this undecided.
6. Add explicit reconciliation trigger path: memory config change must cause `apply_provider_surfaces` and provider MCP sync through existing flows, using `reconcile_provider` / `reconcile_all_providers` semantics where appropriate.
7. Produce and preserve an implementation matrix artifact in notes/review with columns: provider-id, mode, target file, managed block id or config key, source doc URL, expected output example.

## Validation

- Every in-scope provider ID from ME02 has an explicit mode assignment.
- For each `official-native` provider, exact source adapter file and exact generated project file/block are named.
- Re-running provider reconcile after changing Hindsight URL updates only managed blocks/config owned by the memory projection.
- Unsupported providers follow one chosen fallback policy consistently.
- No implementation depends on editing generated user files by hand.

## Effort & Risk

Highest risk remains provider sprawl. Mitigation: ship initial support only for providers with verified Hindsight docs, but still classify all others explicitly as custom or unsupported so behavior is deterministic.

## Notes

Local anchors for integration flow: `src/audiagentic/components/providers/surfaces/manager.py::apply_provider_surfaces`, `src/audiagentic/components/providers/services/reconcile.py::reconcile_provider`, and provider adapter renderers such as `adapters/codex/surface.py` and `adapters/claude/surface.py`.
