# Lock capability evidence data model and execution boundaries

## Notes



## Findings

The proposed HostCapability-only extension is too narrow: HostCapability represents editor extensions, while MA19 covers managed-config, connector, execution, transport, surface, and other provider facts. Adding evidence fields only there would misclassify or lose facts. Free-form annotations are informational and cannot be the authoritative evidence store. Evidence must remain provider-owned and must not extend foundation ManagedConfigSpec or become an executable RecipeDefinition. Existing list_provider_descriptors is a public projection, not a lossless generator.

## Conclusion

Revise MA19 to define a reusable provider-owned evidence record and a provider-level capability-facts collection keyed by stable fact id and linked to existing descriptor subjects. Preserve HostCapability semantics. Lock validation, deterministic views, and runtime/recipe separation.
