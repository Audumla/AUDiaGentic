# Memory must delegate provider-specific execution to providers

## Notes



## Findings

Current MA02 correction moved Hindsight-specific adapters into memory-owned contributions to keep providers unaware of Hindsight. That overcorrects ownership: a component should declare desired integration intent but must not directly call provider code or implement provider-specific config/plugin/hook mechanics. Providers should execute their own generic exposed capabilities without learning the requesting domain.

## Conclusion

Revise MA02/MA06/MA16/MA17: foundation defines provider-capability request/result contract and gateway; providers registers generic capability handlers per provider (MCP, plugin, config fragment, hook, instruction, external command where safe); memory declares opaque desired payload/intent and submits through gateway. Providers sees capability request, never `hindsight`; memory never imports/calls provider implementation. Provider-specific custom mechanics remain in provider adapter handlers.
