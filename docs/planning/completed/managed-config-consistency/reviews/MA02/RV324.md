# Providers must not own Hindsight integration declarations

## Notes



## Findings

MA02 proposes provider-owned declarations under config/providers and a providers-owned observer for capability id `hindsight`. This violates the required ownership boundary: providers must not know a removable memory library/capability by name. It would make a memory-library migration require edits to providers and create forbidden cross-component knowledge.

## Conclusion

Reverse ownership: memory owns its neutral backend export, refresh event, and a memory-owned capability contribution declaration. Providers exposes only neutral contribution registration, recipe execution, descriptor lookup, and managed-config primitives. Provider-specific adapter implementations may be registered through the memory contribution without providers importing memory or containing `hindsight` vocabulary.
