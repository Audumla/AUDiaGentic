# Common declarative operation schema is not explicit

## Notes



## Findings

MA10 defines a generic RecipeSpec/bindings/factory contract, MA11 defines generic steps, and MA12 retains the existing provider YAML authoring shape. Together they do not require one stable, component-neutral declaration schema for install/configure/verify/uninstall/ownership across provider CLIs, memory-library integrations, harnesses, LSP, release hooks, and future capabilities. Without an explicit schema and migration/guard, parallel dialects can persist.

## Conclusion

Create dedicated MA16 common declarative capability-operation schema. MA10 consumes MA16’s schema contract; component-specific YAML remains component-owned but maps to the same schema. Providers must remain unaware of memory integrations.
