# Approved schema and Step 2 implementation diverge on mandatory gates

## Notes



## Findings

Current implementation does not meet MA16 Block B1 gate. `docs/reference/CAPABILITY_OPERATION_SCHEMA.md` says exact approved loader shape uses kebab-case keys, extensions require `ext.<provider-id>` plus provider-schema validation, recipe refs resolve, and only execute may carry transports. `schema.py`/`loader.py` instead accept underscore keys, accept arbitrary `ext` dicts, only prefix-check recipe refs, and allow transports on any kind. The configured source directory `src/audiagentic/config/providers/capabilities/` has no declarations, so no shipped provider emits the required catalog entry or descriptor compilation output. Loader also coerces multiple types with `str()`/`list()` and leaks KeyError/TypeError for malformed required/nested data, contrary to strict canonical validation. MA16 plan's explicit every-support-state evidence rule and MA18 transport fields are not fully represented. Resolve contract/source-of-truth drift and mandatory validation before treating Step 2 or schema freeze as complete.

## Conclusion

Incorporated through RV401 re-scope. Source/loader drift is resolved by withdrawing the broad schema as runtime contract and planning its reduction; remaining implementation work stays on pending MA16.
