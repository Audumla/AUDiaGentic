# Canonical provider capability inventory must precede schema design

## Notes



## Findings

Current provider capability facts are split between descriptor YAML/runtime fields, feature mapping, adapter behavior, and the model-endpoint reference. The model matrix is explicitly authoritative but has 61 unverified/blocked cells; no single machine-readable inventory joins structural, lifecycle, projection, ownership, and evidence state. Designing MA16 before this inventory risks choosing schema fields from an incomplete or duplicate view.

## Conclusion

Add a read-only pre-schema discovery gate to MA16. It produces a generated canonical provider-capability inventory from descriptor YAML plus explicit verified evidence/status overlays, identifies every gap/legacy dialect, and is approved before the immutable MA16 schema is defined. It introduces no new runtime gateway or provider behavior.
