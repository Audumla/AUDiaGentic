# ext field type allows None but loader never returns None

## Notes



## Findings

CapabilityRecord declares `ext: dict[str, Any] | None`, but `_resolve_capability` (line 186) always sets `ext={}`
when the YAML field is absent. The loader never produces `None` for ext.

**Impact:** Type-safety gap. Code that reads from loaded records can safely iterate `record.ext.items()` without None checks. But a programmatically constructed CapabilityRecord could set `ext=None`, creating a runtime difference between loader-produced and manually-constructed records.

**Options:**
1. Change type to `dict[str, Any]` (never None) — simplest, matches loader behavior.
2. Have loader return None when ext is absent — makes the type accurate but requires MA17 to handle None.
3. Keep as-is and document that loader-produced records always have `ext={}`.

**Question:** Should the type be changed to exclude None, or should the loader return None for absent ext?

## Conclusion

Superseded by reducing/removing broad CapabilityRecord. No optional extension field is exposed in runtime unless consumed.
