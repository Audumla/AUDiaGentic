# Move capability knowledge ownership out of foundation

## Notes



## Findings

RV401 separated soft provider knowledge from runtime logic but MA16 still permits a foundation-owned catalog loader/generator. Capability matrix is provider-specific knowledge. Its config, validation, evidence linkage, catalog generation, and status/reference tooling belong to the providers component/config. Foundation may own only neutral request/result/handler/execution-port protocols proven by cross-component call sites. Foundation must never import provider config; requester components must never import providers capability modules. Composition root injects explicit provider handlers through neutral protocols.

## Conclusion

Incorporated into MA16, MA17, MA19, MA00, MA09, and superseded schema notice. Provider capability knowledge is provider-owned; foundation retains neutral protocols only.
