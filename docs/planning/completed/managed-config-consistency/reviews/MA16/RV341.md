# Capability inventory must become extensible provider capability contract

## Notes



## Findings

User requires more than a generated audit: each provider needs one canonical, extensible capability declaration covering current and future capabilities, technical invocation/constraints, and agent-facing manifestation. A report alone cannot drive discovery, validation, or future reuse.

## Conclusion

MA16 must define a provider-owned capability-catalog declaration layered over descriptor-derived facts, with neutral capability taxonomy, typed technical contract, agent-facing guidance, provenance/evidence, and explicit state. It must generate both machine and agent views without duplicate hand-maintained matrices.
