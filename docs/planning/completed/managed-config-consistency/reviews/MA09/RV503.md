# Cross-test pollution: tests/unit/coding_lsp/test_provider_lsp_provision.py leaks state that breaks 12 provider tests — reproduced and narrowed

## Notes

NARROWED 2026-07-16 by claude. The polluter is identified and the reproduction is deterministic. Handing off root-cause with the diagnosis done.

DETERMINISTIC REPRODUCTION (order matters, not randomness):
  pytest tests/unit/providers tests/unit/coding_lsp   -> 0 failures
  pytest tests/unit/coding_lsp tests/unit/providers   -> 17 failures
NOTE: pytest-randomly is already disabled repo-wide (`-p no:randomly` in pyproject.toml addopts), so this is NOT random ordering. It is plain directory order: coding-lsp tests run first and leave state behind that providers tests then read.

POLLUTER ISOLATED by per-file bisect:
  pytest tests/unit/coding_lsp/test_provider_lsp_provision.py tests/unit/providers/test_provisioning.py -> 12 failures
Every other coding_lsp file is clean against test_provisioning.

IT IS CUMULATIVE, NOT A SINGLE TEST: running each test in that file individually against test_provisioning produces ZERO failures. Only the whole file together pollutes. So this is accumulated module/global state across several tests, not one bad monkeypatch.

FAILURE MODE points at the leaked state: the provider tests die with
  RES-PREC-001: provider automation implementation is not registered {provider-id: codex, family-id: generated-surfaces}
  RES-PREC-001: ... {provider-id: claude, family-id: cli-lifecycle}
That means build_automation_registry saw a descriptor set WITHOUT the real providers -- i.e. something left the process holding a reduced/fake descriptor or feature state. test_provider_lsp_provision builds fake ProviderDescriptors ('selflsp', 'plain', 'hooked', 'nohook'), monkeypatches descriptors.registry.all_descriptors and automation_registry.all_descriptors, and calls feature_registry.clear() in setup_function/teardown_function.

PRIME SUSPECT: providers/descriptors/registry.py holds a module-level `_registry` populated once at descriptor load, and all_descriptors()/get_descriptor() call _sync_feature_implementations(), which re-registers every descriptor into the foundation feature_registry. test_provider_lsp_provision's teardown calls feature_registry.clear() unconditionally. Provider enablement (services/feature_resolution.enabled_provider_ids) reads feature state, so a cleared feature registry that is never repopulated for the real providers plausibly explains why registration/enablement then fails for codex/claude. Confirm whether _registry itself is being clobbered or only the derived feature state.

SUGGESTED FIX: add an autouse fixture that snapshots and restores BOTH the provider descriptor registry and the feature registry around each test, rather than each file hand-rolling setup_function/teardown_function clears. A shared fixture means new family tests inherit isolation by default instead of each author rediscovering this.

WHY IT MATTERS (unchanged): MA09 gate item 1 ('full suite, no regressions') cannot be honestly signed off while the suite's outcome depends on directory order. Every agent validating a change in this area currently has to diff failure sets against a baseline to separate real regressions from this noise -- I had to do exactly that three times this session.

## Findings

['tests/unit/providers/test_provisioning.py: 12 tests (reconcile_* and cli_lifecycle_*) FAIL when run as part of `pytest tests/unit/providers`, but ALL PASS when the file runs alone or with test_surface_contributions.py.', 'tests/unit/providers/test_surface_contributions.py: 4 tests fail in the combined run, pass per-file.', 'tests/unit/providers/test_lsp_enable_propagation.py::test_sync_language_servers_to_native_provider: fails in combined run, passes alone.', 'Failure set is stable at 17 and identical before and after unrelated source changes, so it is ordering/state-dependent rather than change-dependent.', 'Likely cause is shared mutable module state not reset between tests: the descriptor registry (all_descriptors), the feature registry, and provider-enablement state are process-global and are monkeypatched per test. Several tests monkeypatch `...descriptors.registry.all_descriptors` while others rely on the real registry; test_provider_lsp_provision.py uses setup_function/teardown_function to clear feature_registry, but no equivalent reset exists for the provider descriptor registry.', 'Consequence: a real regression in these 17 tests is indistinguishable from ambient noise, and CI signal depends on selection/ordering. Any agent validating a change must diff failure sets against a baseline to interpret results.']

## Conclusion

VALID AND REPRODUCED: coding-LSP provision file before provider provisioning causes 12 deterministic failures. Root cause is clear-only feature registry teardown leaving partial provider feature state. Created MA33 for shared restore/reload isolation; added to MA09 gate.
