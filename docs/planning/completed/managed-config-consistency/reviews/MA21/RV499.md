# MA21 slim slice not implemented — generated_surface_definition is dead code and providers_api imports the private _make_handler

## Notes

SLIM_IMPLEMENTATION_PATH.md lists MA21 under 'Completed plan items' as 'handler implemented, bypasses registry', but the slice it defines for MA21 (register with the registry, dispatch through it, delete the direct path) has none of its four steps done. The item should not be counted as complete. Distinct from RV475/RV477/RV485, which debate whether families must route through the registry as a design question — this review is narrower: MA21 already decided to register, the family half-declares itself, and the wiring was never finished.

## Findings

['generated_surface_family.generated_surface_definition(provider_id) exists but has no production caller. The only reference outside its own module and __all__ is tests/unit/providers/test_generated_surface_contract.py:37. It is dead production code kept alive by a test.', 'build_automation_registry imports generated_surface_family_contracts() and merges the generated-surfaces contracts into family_contracts (line 60), but never registers a handler for the family. The family is half-present: its contracts are registered, its handlers are not.', 'Because the contract map advertises generated-surfaces while no provider is registered, registry.dispatch(pid, \'generated-surfaces\', ...) raises RES-PREC-001 for every provider — the family is discoverable but not dispatchable.', 'providers_api.operate_provider_surface (lines 230-235) imports _make_handler directly from services.generated_surface_family and calls handler(mode, request, provider_id), bypassing the registry entirely — exactly the direct path the slice says to delete.', 'The imported symbol is underscore-private yet listed in generated_surface_family.__all__ (line 103). Exporting a private name is self-contradictory; it signals the seam was never meant to be crossed.', 'operate_provider_surface constructs the handler per call, so the surfaces manager import and handler closure are rebuilt on every invocation.']

## Conclusion

STALE/RESOLVED. generated-surfaces is now Pattern A registered through FamilyRegistrar; providers_api dispatches via registry; handler factory is public. Focused generated-surface tests pass.
