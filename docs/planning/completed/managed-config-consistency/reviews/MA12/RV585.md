# Keep CLI lifecycle typed through the public provider boundary

## Notes



## Findings

['The public manage_cli_lifecycle seam returned an untyped mapping even though the provider API doctrine and adjacent automation families use typed request/result contracts.', 'Install and uninstall also directly invoked generated-surfaces and managed-MCP operations, duplicating orchestration owned by provider reconciliation and causing clean-room Pi CLI validation to fail when those unrelated families were not registered.']

## Conclusion

Valid and incorporated. CliLifecycleResult now supports mapping conversion, providers_api returns the typed result, and only the MCP serialization boundary converts it to a mapping. CLI lifecycle no longer dispatches generated-surfaces or managed-MCP; reconciliation remains the single cross-family orchestrator. Validation passed 91 focused unit tests and a rebuilt Linux clean-room image with both real Codex and Pi install/uninstall tests (2 passed).
