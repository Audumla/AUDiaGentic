# Keep Hindsight integration recipes requester-owned

## Notes



## Findings

MA24 currently moves Hindsight-specific package names, commands, gates, and verification into provider handlers. That violates the locked boundary that providers remain unaware of Hindsight. Cline/Aider descriptors need not implement requester-specific automation. Hindsight should parse its config into frozen typed recipe objects and execute official integration commands through the generic foundation recipe/step runtime. Provider APIs are used only when provider-owned artifacts/config formats must be mutated.

## Conclusion

Revise MA24 from provider-integration family migration to typed requester-owned declared integration recipes. No providers_api.manage_provider_integration for Hindsight-specific installers. Keep rules in surfaces and provider config writes behind generic provider capabilities.
