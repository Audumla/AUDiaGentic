# Specify capability catalogue and generic-mechanic boundary

## Notes



## Findings

MA20 states that the family namespace is open but does not explicitly distinguish enumerated provider capability declarations from reusable generic mechanics. That leaves room for either a closed global taxonomy or arbitrary free-form executable capabilities.

## Conclusion

Amend MA20: each provider enumerates supported capability-family IDs and their typed descriptor facts; reusable generic mechanisms are independently named, schema-backed typed families selected only by explicit descriptor declaration. Free-form annotations/facts remain inert metadata and cannot select a handler or carry execution/configuration blobs.
