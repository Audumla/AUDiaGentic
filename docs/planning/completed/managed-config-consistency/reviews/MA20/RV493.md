# Allow declarative recipe mechanics behind explicit family binding

## Notes



## Findings

MA20's wording that configuration cannot enable implementation is too broad and conflicts with the intended config-managed recipe target. The real restriction is that config cannot invent public family contracts or register an unbound handler.

## Conclusion

Clarify that CC41 declarative config may define private executable lifecycle mechanics. MA20 still requires an explicit supported-family declaration and explicit family registrar/adapter binding before those mechanics are reachable through providers_api.
