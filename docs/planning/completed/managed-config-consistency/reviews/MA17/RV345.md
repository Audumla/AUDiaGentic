# String registries must not conceal component coupling

## Notes



## Findings

Current standards encourage `(key, handler)` registries for entity dispatch but do not clearly distinguish legitimate same-owner extension dispatch from string-keyed service locators used to evade dependency rules. MA16/MA17 capability work could accidentally recreate forbidden coupling through opaque keys/dotpaths.

## Conclusion

Add explicit architecture rule: registry is allowed only when owner, typed protocol, declaration source, lifecycle, and composition-root binding are explicit. A registry cannot make a forbidden import/call legal, cannot carry foreign-domain policy, and cannot replace a direct same-layer import or typed event merely to reduce visible coupling. Add graph/tests for key ownership and handler boundary.
