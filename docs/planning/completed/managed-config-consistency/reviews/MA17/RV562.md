# Reserve an optional session-reference field in the frozen execution signature before freeze

## Notes



## Findings

MA17 step 2 freezes the execution signature with worker_id, attempt_epoch, provider_isolation_tier (covering SH07's durability needs) but contains nothing about session identity. AS08's notes (RV543) state 'MA17 must reserve a session-aware execution signature', but that requirement never made it into MA17's own text. If MA17 freezes without it, live-session dispatch (AS04 seam, AS08 detached sessions, AS10 resume) either bypasses providers_api execution — creating a second execution path and a layering breach — or forces a retroactive contract change.

## Conclusion

Add a reserved optional session reference (provider-session-ref plus session/turn correlation identity) to the frozen signature and its packet-schema validation so sessionful and one-shot dispatch flow through the same providers_api execution entry. Edit applied to MA17.
