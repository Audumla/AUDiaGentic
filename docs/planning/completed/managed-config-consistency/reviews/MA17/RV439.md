# Assumes a capability gateway MA16 does not establish; §18.3 registry mandate vs concrete-call code divergence; blocked by open RV412

## Notes

MA17 is Block B2 — the public-API/handler/execution boundary item. Its definition of the boundary depends on the unresolved RV412/RV414 divergence and on an API surface MA16 does not actually establish.

## Findings

1. MA17.md:20 (step 0 INPUT GATE) assumes 'MA16 ... establishes providers public capability API' as a 'capability gateway.' MA16 delivers a sanctioned module that re-exports recipe types plus concrete functions (providers_api.py) — there is no gateway/registered-handler mechanism for model/LSP/config operations. MA17's assumption is false.

2. MA17.md:23 (step 3) says 'Implement/use providers-owned capability gateway' and MA17.md:30 (step 10) 'Provider config/LSP/job mechanics remain behind providers public capability gateway.' No such gateway exists; the code uses concrete `providers_api` functions. MA17 would build something the architecture (§18.3) already prescribes as `registry.register(recipe)` — yet the actual model-source/surfaces code bypasses that with direct service calls. MA17 must reconcile these two authorities.

3. RV414 (state `created`, on MA17) recommends the dual-API design (ProviderRecipeRegistry for CLI lifecycle + purpose-built `providers_api` sync/diff functions). RV414 is unresolved, so MA17's boundary definition is not approved. MA17 step 12 tests 'catalog non-authority' and 'explicit handler resolution' but the implemented surface has neither a catalog nor explicit handler resolution for these operations.

4. MA17.md:62-69 Ledger Events and Notes cite RV404 but not the open RV412/RV414, so MA17 presents itself as ready while its core boundary decision is under active dispute.

## Conclusion

DISSOLVED by RV412 ratification (2026-07-15). MA17 note clarifies: 'capability gateway' = providers_api purpose-built functions + explicit registration, not a universal registry; §18.3 governs automation authority and is not a 'registry mandate' and is not violated by concrete functions; Step 0 gate = 'providers_api surface exists'. No §18.3 divergence remains.
