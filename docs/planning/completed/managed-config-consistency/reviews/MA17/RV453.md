# Restore standards-mandated neutral execution port and composition injection

## Notes



## Findings

MA17 and the MA16 handoff currently propose agents→providers_api execution. Architecture Standards §18.4 and completed RV405 explicitly require the provider-neutral agent execution port in foundation/execution, providers implements it, and composition injects it into agents so agents imports zero providers modules. Current foundation/execution contains ACP transport types only; no ExecutionPort or injection/composition seam exists. Current agents gateway directly imports three provider services. A direct providers_api function would clean internals but still violate the stronger standard.

## Conclusion

REJECTED before implementation (user correction, 2026-07-15). The review over-applied stale/conflicting Architecture Standards §18.4 wording. Correct current direction restored: provider execution stays provider-owned behind the sanctioned providers public boundary; agents may depend on that public API but never provider internals; foundation retains independently neutral ACP primitives only and gains no new execution-port/composition abstraction. MA17 and handoff packet reverted. Follow-up required to correct §18.4 so standards no longer contradict settled plans.
