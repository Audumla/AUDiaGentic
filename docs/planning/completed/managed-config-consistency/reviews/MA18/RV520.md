# Bounded-delivery degradation change: dropped assistant text preserved in overflow buffer; compact payload mode for gateway sessions

## Notes

The frozen neutral-event contract's bounded-delivery budgets (MAX_EVENTS 10k / 8MiB) are UNCHANGED, but the degradation behaviour under cap pressure is extended: live evidence (MA29 implementation turn: 3997 of 13998 events dropped, the worker's final report truncated mid-sentence) showed the caps destroy exactly the artifact a controller needs — the assistant's final text — while protecting memory from tool-call payload bulk nobody consumes.

## Findings

1. When a budget drops an assistant-message event, its TEXT is now banked in a per-turn overflow buffer (bounded, MAX_OVERFLOW_TEXT_BYTES 1MiB) exposed as AcpResult.overflow_text (additive field, default None); gateway output assembly appends it, so the final report survives cap pressure intact. Drop counting and event-list caps are byte-for-byte unchanged — all pre-existing frozen-contract tests pass unmodified. 2. New opt-in compact_events mode on AcpSessionTransport: ext carries raw_kind only, never the raw update payload — used by the gateway SessionRuntime, whose consumers only ever read text/kind/counts; this removes the main byte-budget pressure at source. Default (non-compact) behaviour unchanged for any consumer that wants lossless in-memory payloads. 3. Events remain in-memory only — nothing new is persisted; overseer token cost unchanged (final record only).

## Conclusion

Implemented with tests (overflow past MAX_EVENTS preserves tail text; compact mode buffers no payloads; full transports+agents suites green). Closing as incorporated; AS06's long-run budget item remains for the checkpoint/compaction strategy if 1MiB overflow proves insufficient.
