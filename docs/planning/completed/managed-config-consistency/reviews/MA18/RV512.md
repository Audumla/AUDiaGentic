# Transport lifecycle extension for persistent sessions (agent-sessions plan AS01)

## Notes

foundation/transports/acp.py declares the neutral event and lifecycle contract frozen per AGENT_TRANSPORTS.md with deviations requiring an MA18 review. The agent-sessions plan (AS01) extends the LIFECYCLE (not the event contract): the spawn→initialize→new_session pipeline becomes reusable via AcpSessionTransport supporting multiple prompt() turns on one live child, plus an explicit close() with bounded termination. The frozen event semantics are preserved unchanged: canonical kind vocabulary untouched, per-turn bounded delivery (MAX_EVENTS/byte budgets/callback isolation) applied per prompt, exactly-one-terminal-result per turn, default-deny permissions, malformed-update normalization, child-exit error normalization (EXT-ACP-003). run_acp_prompt remains as a behaviour-identical one-shot wrapper (open→prompt→close) so existing consumers and tests are unaffected. New surface: AcpSessionTransport (open/prompt/close/is_alive), one new CON-ACP error code for prompt-after-close.

## Findings

1. Event contract: no change. 2. Lifecycle: extended from one-shot to session-scoped; process lifetime == session lifetime (stdio). 3. New error code CON-ACP-001 (prompt on closed/dead session) to be registered. 4. AGENT_TRANSPORTS.md needs a lifecycle section update describing the session extension once AS01 lands.

## Conclusion

Extension approved for implementation under plan agent-sessions AS01; close this review when acp.py and AGENT_TRANSPORTS.md are updated together.
