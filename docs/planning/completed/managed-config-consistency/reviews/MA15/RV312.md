# Isolate startup and CLI smoke from host mutation

## Notes



## Findings

Installed wheel, virtualenv, component loading, logging bootstrap, home/config discovery, and lifecycle commands can mutate or inspect host state despite temp project arguments. Existing project convention already provides `tests/docker/Dockerfile.packaging` for clean-room wheel validation and `AUDIAGENTIC_DOCKER_TESTS=1`/`mutates_host` gating.

## Conclusion

Run all real entrypoint, package-install, startup/load, and mutating CLI cases in Docker. Keep host lane limited to in-process parser/dispatch units with mocked side effects.
