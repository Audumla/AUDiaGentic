# Keep Codex and Pi Hindsight recipes requester-owned

## Notes



## Findings

MA26 currently moves Codex/Pi Hindsight paths, commands, and integration handlers into providers and reuses a provider-integration family. That violates the locked boundary: providers remain requester-blind. Codex/Pi recipe semantics and typed desired values belong to Hindsight; providers may only expose generic config capabilities where provider-native format mutation is unavoidable.

## Conclusion

Replace provider-integration family plan with two Hindsight-owned typed recipe batches. Codex uses generic provider config capability only if a provider-owned config artifact cannot be managed by Hindsight-owned file contract; Pi remains typed non-executable guidance until evidence is verified.
