# MA11 interim step substrate still duplicates behavior and has unsafe compatibility dispatch

## Notes



## Findings

Current MA11 slice introduced foundation.steps results/sequence/shell/callable but left toolchains/provision_steps concrete steps/factory and workflow control factory alive. The canonical SequenceStep accepts legacy constructor forms and retries step.run after catching TypeError; a real TypeError raised inside a step can cause a second execution. Shell/sequence behavior is therefore duplicated while APIs differ (plan/dry_run, compensate/revert, positional answers). This violates MA11's final no-shim/no-duplicate goal and adds complexity rather than consolidating.

## Conclusion

Do not build MA16/MA17 on the interim API. Complete one canonical step protocol and migrate all concrete/config/control/factory steps in one bounded MA11 closeout. Replace exception-driven dispatch with explicit adapters at construction time, delete old packages and compatibility forms, then add zero-old-import guard.
