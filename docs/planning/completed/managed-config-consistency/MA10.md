# Consolidate observed recipe execution without speculative schema

## Description

Characterize existing recipe behavior and extract only mechanics already shared by multiple implemented consumers. Do not consume MA16 catalog shape or create a universal declarative recipe object model. Prefer existing MA11 steps plus small provider/component-owned builders. A generic assembler/registry ships only if current duplication proves it simpler.

## Steps

1. Inventory current Hindsight/provider recipe behavior and actual callers. Count duplicated mechanics and record which fields each caller reads.
2. Re-open SL17 KEEP decision because its trigger was the now-withdrawn MA16 universal schema. Compare: keep component-owned builders on MA11 steps; extract small shared helper; or retain generic assembler. Choose smallest shape supported by current consumers.
3. Extract only repeated domain-neutral mechanics. No ParamBinding/constraints/outcome taxonomy unless at least two current consumers require identical behavior.
4. Keep provider/component policy and payload validation local. Foundation imports no component vocabulary.
5. Avoid arbitrary pattern-string factory registries. Explicit composition registration allowed only when multiple real implementations need runtime selection.
6. Rewire one consumer with parity, then second consumer if present. If no second consumer, keep implementation local and close extraction as unnecessary.
7. Delete only proven duplicates. Add a guard against parallel generic engines, not against legitimate small component builders.

1. Every extracted field/type has at least two implemented non-test consumers. 2. No dependency on MA16 catalog or documented capability taxonomy. 3. Behavior parity for migrated consumers. 4. No speculative registry/type scaffolding. 5. Foundation contains no component/provider vocabulary. 6. Decision record explains why extraction is smaller than local builders.
