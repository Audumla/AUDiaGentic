# Restore feature registry state between provider/LSP tests

## Description

Fix deterministic cross-test pollution caused by coding-LSP tests clearing process-global feature registry state. Restore canonical registry state through one shared test fixture/reset seam; do not add production caching or per-file cleanup layers.

## Steps

1. Reproduce the pollution by running coding-LSP tests that call feature_registry.clear() before provider provisioning tests, with the reverse order as a control.
2. Identify exactly which process-global registries are mutated. Start with foundation feature_registry and coding_lsp.language_registry; include another registry only with failing-test evidence.
3. Implement one shared test isolation seam, preferably in tests/conftest.py, that restores canonical registry state between tests by clearing loader cache and reloading component descriptors. Avoid per-file clear-only setup/teardown that leaves the suite partially registered.
4. Remove or replace file-local setup_function/teardown_function clear-only hooks in the affected coding-LSP tests when the shared fixture covers them.
5. Add a regression check that would fail if a test clears the feature registry and a later provider/LSP test observes missing language/binding descriptors.
6. Validate both orders: coding-LSP then providers, providers then coding-LSP, plus the focused affected files.

## Files

[TEST] tests/conftest.py; tests/unit/coding_lsp/test_provider_lsp_provision.py; tests/unit/coding_lsp/test_scoped_install.py; tests/unit/coding_lsp/test_runtime_resolver.py; add a narrow regression test only where it proves the cross-file ordering failure
[PRODUCTION] src/audiagentic/foundation/features/registry.py or src/audiagentic/components/coding_lsp/language_registry.py only if a minimal explicit test reset/reload hook is required; do not add production caching or a new registry abstraction
