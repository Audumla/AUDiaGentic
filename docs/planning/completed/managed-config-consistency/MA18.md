# Validate ACP as shared agent execution transport

## Description

Mid-level execution packet to characterize and close only proven gaps in the existing provider-neutral ACP transport and OpenCode launch binding. Architecture is frozen by `PROVIDER_CAPABILITY_REFERENCE/execution/agent-execution-transports.md`: preserve current public dataclasses, neutral event contract, canonical errors, one event stream, and strict foundation agnosticism. MA17—not MA18—owns requester/provider composition.

## Steps

0. BASELINE — Run `python -m pytest tests/unit/foundation/test_acp_execution.py tests/unit/providers/test_opencode_acp.py -q`. Record pass count and inspect `PROVIDER_CAPABILITY_REFERENCE/execution/agent-execution-transports.md`, `foundation/execution/acp.py`, and the two test files. Do not edit before producing a contract-versus-test gap list.
1. CLASSIFY EACH REQUIREMENT — Mark cancellation, child termination, malformed updates, callback isolation, bounds, permission default, redaction, terminal-result uniqueness, OpenCode launch isolation, and Docker packaging as `covered`, `missing-test`, or `failing`. If covered, add no implementation change. If the frozen document and existing tests disagree, stop and request MA18 review.
2. FOUNDATION BATCH A: FAILURE NORMALIZATION — In `foundation/execution/acp.py`, change only code required by a failing/missing test so malformed updates become non-terminal canonical error events, unexpected child exits use the registered ACP error, and every run retains exactly one terminal `result` event. Preserve `AcpLaunch`, `AcpEvent`, `AcpResult`, error-code values, and public function signature.
3. FOUNDATION BATCH B: CANCELLATION — Add/verify tests for cancel-before-prompt and cancel-during-prompt. Cancellation attempts protocol cancel first, waits no longer than `CANCEL_GRACE_SECONDS`, terminates the child if needed, and yields one cancelled terminal result. No duplicate terminal event or leaked task/process is allowed. Escalate if the installed ACP SDK cannot provide the frozen cancellation behavior without changing the public contract.
4. FOUNDATION BATCH C: CALLBACKS AND BOUNDS — Verify callback failures are isolated, success resets the consecutive-failure count, and the callback disables after `CALLBACK_FAILURE_LIMIT` consecutive failures without recursive callback emission. Verify `MAX_EVENTS`, `MAX_PAYLOAD_BYTES`, and `MAX_TOTAL_BYTES`: non-terminal overflow is counted/dropped, the terminal event is retained, and retained text/error/ext data is redacted and bounded. Do not change constant values without review.
5. PERMISSIONS AND REDACTION — Verify permission requests default-deny without `policy_fn`, explicit grants flow through, and policy/callback exceptions do not expose secrets. Use the shared redaction implementation; add no local secret patterns. Raw prompts, tokens, authorization values, and raw exception text must not appear in events or `AudiaGenticError.details`.
6. OPENCODE BINDING — In `providers/adapters/opencode/acp.py`, preserve `build_acp_launch(project_root, model_id)` as launch declaration only: executable `opencode`, args `("acp", "--cwd", resolved_root)`, optional model through `OPENCODE_CONFIG_CONTENT`, and zero file/config mutation. Add tests only for uncovered behavior. Do not add retries, profile selection, timeline writes, or provider dispatch.
7. PACKAGE GATE — Run focused suites again. Then run the existing Docker ACP gate using its documented project command; if no command is documented, record that as the sole packaging blocker rather than inventing a new workflow. Optional real-provider E2E stays opt-in and cannot block unit completion.
8. EVIDENCE HANDOFF — Update `PROVIDER_CAPABILITY_REFERENCE/execution/agent-execution-transports.md` and MA19-owned provider evidence only with facts directly proven by tests or installed-tool evidence. Do not create runtime fields, registrations, or code paths from evidence.
9. MA17 HANDOFF — Produce a short handoff listing the stable `AcpLaunch`/`AcpEvent`/`AcpResult` contract, cancellation behavior, OpenCode builder, test commands, and remaining provider limitations. Do not implement the agents-to-providers execution seam here.
10. FINAL VALIDATION — Run focused foundation/provider tests, foundation component-import scan, touched-file Ruff checks, Docker wheel gate when available, and optional E2E separately. Report exact tests passed/skipped and every unexecuted environmental gate.

Exactly one terminal result exists for success, malformed-update continuation, child exit, callback failure, cancel-before, and cancel-during cases. 5. Callback and bounded-delivery constants retain their values and tested semantics. 6. Permission default-deny and explicit grant behavior pass. 7. Secret canaries are absent from event text/error/ext, returned results, logs, and error details. 8. OpenCode binding performs zero durable mutation and adds no orchestration. 9. Docker wheel gate passes or is reported as a named environmental blocker; optional E2E is reported separately. 10. MA17 handoff is complete and no runtime composition is implemented in MA18.
