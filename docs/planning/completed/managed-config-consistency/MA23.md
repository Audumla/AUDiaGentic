# Migrate Hindsight managed MCP through MA20

## Description

First executable MA02 cutover. Replace Hindsight _McpConfigAdapter and matrix MCP/HYBRID dispatch with the MA20 managed-mcp family. Memory builds only serializable desired MCP entries and an opaque ownership scope; providers own paths, format adapters, reconciliation, collisions, reload, definitions, and registrations.

## Steps

1. Preflight: require MA20 substrate and completed MO06. Run current goldens before edits: test_hindsight_managed_sync.py, test_hindsight_registry_provision.py, provider MCP/managed-config tests, and architecture boundaries. Record current result fields consumed by reconcile_hindsight/build_hindsight_status_report: success/state/error only.
2. Freeze public family contract. Add providers_api.manage_mcp_entries(project_root, provider_id, *, mode, entries, ownership_scope). Supported modes are apply|prune|status; do not add plan because no current caller previews this family. entries is a tuple/list of {managed_id: str, payload: serializable mapping}; status/prune may pass an empty collection. ownership_scope is opaque and required.
3. Freeze family result keys: ok, supported, changed, managed_ids, removed_ids, collision_ids, auto_refreshed, action_needed, error_code. Do not return recipe ids/kinds, commands, paths, raw exception text, headers, tokens, or provider serializers.
4. Use MA20 definition refs provider-managed-mcp-payload/v1 and provider-managed-mcp-result/v1, family-id managed-mcp, ownership-scope-required=true, modes apply|prune|status. Add provider-owned definition declarations and load them with load_recipe_definition; declarations remain inert until explicit code registration.
5. Add explicit registrations for current behavior only: copilot, gemini, openhands, roo, continue, and cline fallback. Do not auto-register by scanning descriptor.mcp_config and do not expand Goose/local-openai/Qwen guidance into automation.
6. Implement the private family handler over services/mcp.py sync_managed_provider_mcp(_subset), list/status helpers, and MO06 ownership registry. apply reconciles desired entries; prune reconciles empty desired state for only the supplied scope; status reads. Exact-payload adoption only; collision never overwrites; reload only after change.
7. Keep memory/hindsight/mcp_recipe.py as a pure desired-entry builder. Remove provider service/descriptor imports from that builder. Replace _McpConfigAdapter and _build_mcp_config_recipe/_build_mcp_recipe calls with providers_api.manage_mcp_entries. Use one stable scope such as memory/hindsight/<server_name>; never put provider paths in Memory.
8. Preserve generic fallback without provider-id branching: MA27 orchestration queries family status; a platform-blocked provider-integration may fall through to managed-mcp only when this family reports supported.
9. Delete migrated _McpConfigAdapter, _sync_hindsight_mcp_entry, harness-path resolution used only by MCP, MCP/HYBRID factory branches, obsolete patch seams, and compatibility tests in the same change. Do not retain adapters for old signatures.
10. Validate apply/prune/status, missing descriptor, stdio vs remote capability, exact adoption, collisions, scoped removal, reload/no-op, secret redaction, and all six explicit registrations. Run focused Memory+provider suites, ruff, architecture boundary tests, and rg for migrated symbols.
