# Unify compensating step execution in foundation

## Description

Block A1. Finish—not extend—the in-progress consolidation of workflow and provisioning steps into one component-neutral `foundation.steps` substrate. Lesser-agent rule: characterize first, migrate one consumer slice at a time, fix every encountered failure, and do not start MA16. Final state has one protocol, one result model, one shell/callable/sequence/control/managed-mutation implementation, one typed factory, and zero legacy aliases/paths.

## Steps

0. READ FIRST: Architecture Standards §§1, 1.1, 2, 3, 8, 10, 15, 16; this item; RV344. Inspect current files with `rg --files src/audiagentic/foundation/steps src/audiagentic/foundation/toolchains/provision_steps src/audiagentic/foundation/workflow/invocation` and inventory imports with `rg -n "workflow\.invocation\.steps|toolchains\.provision_steps|foundation\.steps" src tests`. Do not edit before recording exact remaining callers.
1. VALIDATE BASELINE: run `python -m pytest tests/unit/foundation/steps tests/unit/foundation/workflow tests/unit/foundation/toolchains tests/unit/memory tests/unit/providers -q`. Record failures before edits; no known failure may be ignored. Current expected state is green with one Windows-only echo skip.
2. Freeze/extend characterization tests before moving each behavior: shell argv and explicit shell mode; platform override; timeout/cwd/env; progress callback; command plan; redaction; callable output/error; confirm/select/conditional; sequence fail-fast/non-fail-fast/waiting; reverse compensation preserving primary error; config-set/write-file/managed-block adoption/revert; construction binding versus runtime substitution; custom factory registration.
3. Pin final API in `foundation/steps/protocol.py`: `Step.run(context)->StepResult`, `Step.plan(context)->StepResult`, optional `CompensableStep.compensate(context)->StepResult`. Interactive answers live in one reserved neutral context field populated by workflow runner; remove positional/keyword answer overloads. Do not introduce a service locator or requester-selected handler string.
4. Pin final results in `foundation/steps/results.py`: neutral typed progress/question records, `StepResult`, `SequenceResult`; status vocabulary documented and closed. Preserve public workflow result payload through `WorkflowInvocationResult` adapter. Redact at producing step boundary and again defensively at public adapter.
5. Finalize `SequenceStep`: canonical constructor `SequenceStep(steps, *, id, fail_fast, compensate_on_failure)` only; one invocation per child; explicit context propagation of prior outputs/status; explicit compensation policy; reverse only committed steps; failed compensation recorded without replacing primary failure. Delete `legacy_steps`, signature inspection, `revert`/`dry_run` fallbacks after callers migrate.
6. Finalize one `ShellStep`: support argv tuple OR explicit shell string via a `shell` flag; construction-time parameter binding is performed by factory, runtime context rendering by shell step; optional empty values are removed by factory, not executor; platform override, timeout, cwd, env, progress streaming, compensation command, command plan, redaction. Shell mode must never be inferred from metacharacters.
7. Move `ConfirmStep`, `SelectStep`, `ConditionalStep`, and `planned_commands` to `foundation/steps/control.py`. Move `ConfigSetStep`, `WriteFileStep`, `ManagedBlockStep` to `foundation/steps/structured.py`. Reuse `ConfigPatcher`, `atomic_write_text`, `managed_block`, and `ArtifactRegistry`; do not duplicate ownership or IO logic.
8. Build one `foundation/steps/factory.py`: typed `StepFactory` protocol and §1.1-compliant registry owned by foundation steps. Built-ins register directly/idempotently—no importlib module-name string table. Declaration `type` selects only a step constructor; dotpath/callable resolution happens at descriptor/config boundary, not as hidden cross-component lookup. Unknown/duplicate type uses canonical registered errors. Preserve strict construction placeholders and separate lenient free-text substitution only where a real consumer requires it.
9. Migrate workflow slice: `workflow/invocation/from_spec.py`, runner, `foundation/components/dependencies.py`, source-control/coding-LSP callers, workflow tests. Workflow package retains orchestration/result adapter only. Run workflow/dependency tests.
10. Migrate toolchain slice: loader, recipe_contract, recipe_patterns, `toolchains.__init__`, provision tests. Replace `CompensatingSequence` with `SequenceStep(...compensate_on_failure=True)` and `ShellProvisionStep` with canonical shell/factory. Run toolchain tests.
11. Migrate provider slice: provider descriptor CLI types/loader, provider_cli workflow/lifecycle, adapter descriptors, tests. Preserve CLI result shapes and progress. Run provider descriptor/CLI/provision tests.
12. Migrate memory slice: Hindsight recipes/plugin/codex imports and declared-step construction. Keep Hindsight intent in memory; only generic step construction changes. Run memory tests. Any provider-boundary issue belongs MA02/MA06—do not solve it with a new registry.
13. Delete `foundation/toolchains/provision_steps/` and concrete definitions from `workflow/invocation/steps.py`; delete aliases/re-exports/compatibility constructors, old tests/import strings, and stale docs claiming deliberate duplication. Keep no deprecation shim.
14. Add architecture guards: exactly one class definition for each canonical step type/result/factory; zero old path strings/imports; zero `except TypeError` retry; no component imports/vocabulary in `foundation.steps`; registry satisfies §1.1; raw managed writes absent from step implementations; **assert every `__all__` entry in a re-exporting `__init__.py` actually imports successfully** (broken by commit 4e6198c9 removing WorkflowAnswer without updating consumer).
15. FINAL VALIDATION: rerun focused suites, then `python -m pytest tests/unit -q`; run formatting/lint used by repository. Record exact commands/results and ledger event. Mark MA11 complete only if zero old imports/classes/shims and zero new failures. Then stop—do not implement MA15/MA16 until review.
