# Harden component-owned workflow and hook mutations

## Description

Make release workflow and source-control hook mutations atomic and ownership-safe using existing descriptor, managed-block, WriteFileStep, and ArtifactRegistry primitives.

## Steps

1. Characterize exact bytes, mode bits, ownership, and behavior for release-please install/update/ensure_baseline and source-control post-commit hook install/remove. Fixtures: absent file, exact generated file, user-owned file, file containing old AG block, malformed markers.
2. Release workflow classification per path: descriptor-owned generated-managed file uses component descriptor/virtual asset; recipe-owned optional file uses WriteFileStep + ArtifactRegistry. Do not register a pre-existing user-owned whole file as owned.
3. Adoption: pre-existing file is adopted only when bytes equal canonical generated content or contains a uniquely identified existing AUDiaGentic managed block. Otherwise report collision/action_needed; never overwrite.
4. All release writes use atomic_write_text. On failure original bytes remain. Remove/prune touches only registered whole file or managed block.
5. Source-control hook uses existing managed-block primitive with stable block id. Preserve shebang, unmanaged commands, LF/newline policy, and executable bits. If hook absent, create whole owned file and register it; if pre-existing, own block only.
6. Hook removal: remove owned block; delete file only if registry proves AUDiaGentic created whole file and remaining content is empty/installation marker only. Preserve mode bits on rewritten user file.
7. Dry-run returns path, ownership mode (whole-file|block|collision), byte-change summary, and planned permission changes; zero writes/registry changes.
8. Update MA01 audit rows to keep after tests and add architecture regression against raw write_text in these symbols.
9. After MA11, express release-please probe/install/verify sequencing with the foundation recipe/step engine only where it removes local orchestration. File mutation remains MA05-owned writer/artifact logic; GitHub API/auth/release finalization stay outside recipe steps.

## Validation

1. Matrix covers absent/exact/user-owned/old-block/malformed cases for both features.
2. Exact generated files adopt; user-owned differing files collide and remain byte-identical.
3. Atomic failure leaves original bytes and artifact registry unchanged.
4. Hook shebang, unmanaged commands, LF policy, and executable bit preserved across install/remove.
5. Whole-owned file deletes only with registry proof; block-owned file never deleted.
6. Dry-run changes no file, mode, or registry mtime.
7. MA01 inventory exact; relevant actions become keep only after green tests.
