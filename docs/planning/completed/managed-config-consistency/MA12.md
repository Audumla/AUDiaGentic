# Migrate provider CLI automation to semantic operation

## Description

Implement the CLI automation family using the MA20 RecipeDefinition schema. Derive one CLI-specific public payload from providers-MCP and runtime callers. Public modes are supported members of plan|apply|prune|status; lifecycle mechanics remain private.

## Steps

1. Inventory every caller and consumed result for install_provider, uninstall_provider, repair_provider, CLI planning/status, and provision-all orchestration.
2. Freeze one CLI-family signature from those callers. Payload may describe CLI desired state and CLI-specific options, but must not expose repair, recipe methods, recipe kinds, or fields borrowed by other families.
3. Implement one providers_api CLI operation using existing recipes and foundation.steps; add no recipe abstraction.
4. Apply probes and internally selects install, repair, configure/PATH settle, verify, or no-op. Prune removes only owned CLI state. Plan/status do not mutate.
5. Migrate providers MCP and every runtime/composition caller atomically. Provision-all remains orchestration over family calls, not a public reconcile mode.
6. Delete old lifecycle functions, MCP compatibility routes, aliases, shims, dual dispatch, obsolete tests, and private workflow state machine after parity.
7. Preserve only caller-consumed results and canonical errors; redact command/stdout/stderr.
8. Run focused unit/integration tests and Docker-only real-install smoke.

## Files

[PUBLIC] providers_api CLI family operation
[CALLERS] providers MCP and runtime/composition
[INTERNAL] services/cli_recipes.py, lifecycle.py, foundation.steps
[DELETE] lifecycle/reconcile public routes, wrappers, provider_cli.py when unused
[TEST] caller goldens, modes, ownership, redaction, Docker smoke

## Validation

1. All old callers use one CLI family operation. 2. Public payload has no repair flag or recipe mechanic. 3. Apply handles absent, broken, configured, and healthy states internally. 4. Plan/status do not mutate; prune removes only owned state. 5. No compatibility alias, dual route, or mechanic-named public function remains. 6. Current callers retain consumed behavior and errors. 7. No provider-id dispatch branch. 8. Focused tests and Docker smoke pass.

## Effort & Risk

Complex public contract migration. Completed MA11 substrate and existing recipe infrastructure are available; no prerequisite remains. Goldens and call-order spies protect behavior.
