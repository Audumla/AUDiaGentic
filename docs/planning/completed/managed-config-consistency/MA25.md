# Migrate Hindsight provider plugin automation

## Description

Migrate Claude/OpenCode plugin paths to frozen Hindsight-owned plugin recipe definitions. Hindsight owns plugin package identity, endpoint/auth values, repair decisions, and lifecycle semantics. Providers remain Hindsight-blind and expose only generic config/plugin storage capabilities where a provider-owned format must be read or written.

## Steps

1. Consolidate private plugin recipe classes: rename _PluginRecipe → PluginRecipe, _PluginUrlConfigRecipe → PluginUrlConfigRecipe, _PluginArrayRecipe → PluginArrayRecipe; update __all__ to export all four.
2. Migrate strategies.py plugin builders: _build_plugin_url_config_recipe and _build_plugin_config_recipe already convert row → HindsightPluginDefinition via from_row(). No change needed to the conversion path; only update imports to use renamed public classes.
3. Migrate test imports: update test_hindsight_stamping_golden.py and test_hindsight_recipe.py to import the renamed public classes instead of private _PluginUrlConfigRecipe and _PluginArrayRecipe.
4. Remove raw-row compatibility seam in plugin_definition.py: delete HindsightPluginDefinition.from_row() method. The from_row() call path exists only in strategies.py (step 2) and tests (step 3). Replace with direct HindsightPluginDefinition construction from row fields at each call site. This makes the matrix→definition conversion explicit at the boundary.
5. Remove HindsightRecipeRow import from plugin_recipes.py. The module docstring says "The raw HindsightRecipeRow exists only in the matrix-to-definition parser" — after step 4, no HindsightRecipeRow should appear in plugin_recipes.py or plugin_definition.py.
6. Add parity tests: verify that HindsightPluginDefinition constructed from row fields matches the previous from_row() output. Verify plugin recipe probe/install/configure/verify/uninstall/prune produce identical results with typed definition as with raw row.
7. Run full Memory/provider/architecture suite and Ruff. Verify no HindsightRecipeRow appears in plugin_recipes.py, plugin_definition.py, or the public plugin-entry API.

## Files

[MEMORY] typed Hindsight plugin definitions/recipes and orchestration\n[SCHEMA] Hindsight plugin definition/request/result schemas\n[PROVIDERS] generic config capability APIs/adapters only; no Hindsight handler, registration, command, or identity\n[TEST] plugin lifecycle, repair/restoration, ownership, redaction, provider-blind boundary

## Validation

DONE when Claude/OpenCode production plugins use frozen Hindsight recipe objects; serialized schemas validate; providers have no Hindsight imports/registrations/commands; generic provider config mechanics preserve existing ownership/collision behavior; repair/restoration and redaction pass; focused/full suites green.

## Effort & Risk

Complex Windows repair and ownership work. Stop if a provider-specific config writer cannot be used through a generic capability boundary, or repair ownership is ambiguous. Do not solve by moving Hindsight behavior into providers.
