# Harden Pi exact-isolation support in pi-mcp-adapter

## Description

pi-mcp-adapter is an upstream third-party package, not AUDiaGentic code. The --mcp-exclusive behavior is an AUDiaGentic patch applied to that package. Exact isolation currently depends on patch anchors in upstream TypeScript.

Keep:

- Version checks
- Both-file atomic patching
- Idempotency
- Fail-closed behavior when either anchor changes
- Tests against every supported adapter version

Prefer contributing a native exclusive-config option upstream eventually.

## Detailed Solution & Technical Design

### Current architecture

- `pi-mcp-adapter` is an **upstream third-party package** — not AUDiaGentic code
- The `--mcp-exclusive` behavior is an **AUDiaGentic patch** applied to that package
- Exact isolation currently depends on **patch anchors in upstream TypeScript**
- If upstream changes those anchors, the patch silently fails (or worse, misapplies)

### Patch safety requirements

1. **Version checks**: before applying, verify the adapter version matches the expected version range for this patch. Reject if version is outside range.
2. **Both-file atomic patching**: both files must be patched atomically — either both succeed or neither changes. Partial patches leave the adapter in an inconsistent state.
3. **Idempotency**: applying the same patch multiple times should produce the same result as applying it once. No cumulative changes.
4. **Fail-closed behavior**: if **either** anchor text is not found in the target file, abort and fail — don't silently skip or apply a partial patch.
5. **Tests against every supported adapter version**: maintain a matrix of tested adapter versions and verify patches apply correctly to each.

### Anchor change detection

The patch should:

- Search for exact anchor text before applying
- If anchor is not found, report which file and which anchor was missing
- Include the expected anchor text in the error message for debugging
- NOT attempt fuzzy matching or best-effort application

### Long-term: upstream contribution

Prefer contributing a native `--exclusive-config` option to `pi-mcp-adapter` upstream. This eliminates the need for patching entirely. Until then, maintain the patch with full safety guarantees.
