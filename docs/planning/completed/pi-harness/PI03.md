# Remove or regenerate the static Pi MCP template

## Description

mcp.json is a fixed template while current launches materialize request-owned MCP documents dynamically.

Determine whether the template still has a legitimate bootstrap/native-default consumer.
If retained, generate it from the same projection/materializer contract.
If unused, delete it rather than allowing it to drift.

## Steps

['Audit whether mcp.json template is used by any bootstrap/native-default consumer', 'If retained, generate from projection/materializer contract', 'If unused, delete the file']

## Detailed Solution & Technical Design

### Current state

- `src/audiagentic/runtime/harness/pi/templates/home/agent/mcp.json` is a **fixed/static template**
- Current launches materialize **request-owned MCP documents dynamically** — they don't use this template
- The template is at risk of drifting out of sync with the actual projection contract

### Decision tree

1. **Does anything consume this template?** Audit:
   - Is it copied during Pi bootstrap (first-time setup)?
   - Is it used as a native-default fallback when no request-owned MCP document exists?
   - Is it referenced by documentation or examples?
2. **If yes** — generate it from the same projection/materializer contract that produces request-owned documents. This ensures single source of truth.
3. **If no** — delete it entirely. A stale template is worse than no template (it misleads developers and users).

### Generation approach (if retained)

The template should be generated at build/install time from the projection contract, not maintained manually:

```
# At install time, generate template from projection:
projected_mcp = projection.select_entries(native_default_role)
template_path.write_text(json.dumps(projected_mcp.to_dict()))
```
