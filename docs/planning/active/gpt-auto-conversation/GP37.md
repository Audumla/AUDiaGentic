# Design a browsable chat-history index for human-interrupted conversation review

## Description

Distinct from and larger than GP36 (last-exchange recovery). A real, persistent, content-retaining index of a conversation's request/response history -- useful specifically for reviewing what happened in a session a human has been directly interacting with/interrupting (out-of-sequence injection scenarios, GP04/GP05's human-interference territory), not just recovering the single most recent exchange.

## Steps

- This is a design-stage item, not yet scoped to concrete steps. Needs an explicit decision on: what triggers a write (every observed turn? only on request completion? only on ambiguous/recovered states?), retention policy and lifetime, and where it lives (a new store, or an extension of the gateway request record).
- Must explicitly reconcile with GP24's deliberate design stance: GP24's provider-correlation record NEVER persists ChatMessageRef.text specifically to avoid retaining ChatGPT conversation content in gateway-owned storage. This item's whole purpose is the opposite (retaining real content for later browsing), so the two must not be conflated or accidentally merged -- GP24 stays correlation-only; this item needs its own explicit data-handling decision, made deliberately rather than by accretion.
- Needs a redaction/sensitivity policy before implementation: this is real conversation content that may include working code, credentials-adjacent context, or other sensitive material passed through a shared, multi-project gateway (see project deployment/threat-model memory -- local/internal, non-hostile users, but still a shared surface).
