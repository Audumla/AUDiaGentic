# Implement shared PromptFingerprint/match_prompt() primitive, migrate 4 call sites off exact-text matching

## Description

The deferred third piece of GP19 (see GP19's notes for the two fixes already landed and the two independent live incidents confirming this gap). The actual root-cause fix for the recurring submission-proof/reconciliation text-matching failures: ChatGPT's renderer strips Markdown presentation syntax (backticks, emphasis, link syntax) from displayed text relative to the originally-submitted source, so exact-string comparison against the DOM-observed text intermittently and unpredictably fails on long/formatted prompts -- confirmed live twice (a bigcherry incident and this project's own GP10 re-consultation, both with small but nonzero char-count deltas between typed and expected prompt length).

## Steps

- Design a versioned PromptFingerprint format tolerant of Markdown-stripping/whitespace-normalization, replacing the three currently-inconsistent equality definitions: _matches()/_normal() in turn.py, _same_prompt() and _prompt_text_digest() in chat.py.
- Migrate all four call sites onto the shared primitive: _await_submission_proof(), _capture_provider_identity_after_ambiguous_submission(), find_prompt_snapshot(), _unresolved_prompt_match_diagnostics().
- Use the two real incident deltas already captured (bigcherry's incident; this project's req_1250368b8f2f4477: typed-text-length 2324 vs expected-prompt-length 2306) as concrete test fixtures rather than synthesizing prompt text by hand.
- The consultation that originally scoped this specified 15+ documented validation cases -- carry those forward into the implementation rather than re-deriving them.
