# Fail closed when a GPT conversation reaches maximum length

## Description

Detect ChatGPT's provider conversation-capacity terminal page when the fresh current-turn assistant region shows the full maximum-length banner together with the enabled Start new chat control. Fail the current gateway request with an actionable provider-terminal classification, mark the durable binding non-resumable, and require the next request to create a new provider conversation.

## Steps

1. Add a provider-private exhausted-conversation DOM signal requiring the normalized full banner text and a visible enabled Start new chat button in the same current-turn/page snapshot.
2. Add case/whitespace/punctuation normalization and correlation guards so historical text, user prompts, generic navigation controls, or partial phrases do not qualify.
3. Classify the signal before generic response-complete persistence; emit a stable provider-terminal error and bounded evidence, and ensure the banner is not stored as a successful response artifact.
4. Mark the durable GPT provider binding/session as exhausted or otherwise non-resumable without inventing a remote-delete claim; make retry disposition do-not-retry-current-binding.
5. Ensure explicit resume, automatic continuation, and same-session admission reject the exhausted binding; normal next admission creates a new provider conversation.
6. Add unit/snapshot, provider-turn, gateway-store, and integration tests for positive detection, every false-positive guard, error projection, artifact behavior, and fresh-session follow-up.

## Detailed Solution & Technical Design

Treat conversation exhaustion as a dedicated GPT-auto provider terminal error, distinct from generic completion, transport failure, and watchdog stall. Positive evidence requires all of: (a) fresh request-correlated assistant/message content in the current page region normalizes to the complete sentence "You've reached the maximum length for this conversation, but you can keep talking by starting a new chat."; (b) an enabled visible button or role=button in the same terminal context whose normalized accessible/visible label is exactly "Start new chat"; and (c) the page is not busy and has no active Stop control. Normalize case, horizontal/line whitespace, and surrounding punctuation only; do not substring-match "maximum length" or "start a new chat" independently.

The detection belongs in provider-private gpt_auto snapshot/turn/config code and should record only bounded booleans/normalized hashes in evidence. Banner-without-button, button-without-banner, historical banner, user-supplied banner text, unrelated global navigation, or a busy page remain ordinary classification paths. The provider must never click Start new chat or silently switch conversations during the failing request.

Use a stable provider error code such as GPT-CONVERSATION-EXHAUSTED with semantic class provider-conversation-capacity-exhausted and actionable resolution "start a new provider conversation." The gateway terminal request state is failed, with provider-terminal classification conversation-exhausted and retry disposition do-not-retry-current-binding. Do not persist the exhaustion banner as a successful assistant response artifact.

Persist a bounded exhausted/non-resumable marker in the provider binding/session metadata using an explicit provider-neutral capability/terminal fact; do not claim the remote ChatGPT conversation was deleted. Resume and same-session admission must reject this binding. The next normal request follows fresh-session admission and creates a new provider conversation; no MCP caller-controlled session reset is needed.

## Code Samples & Guidance

Provider-private signal configuration should be dedicated rather than folded into generic error-alert matching:
```yaml
conversation-exhausted:
  scope: document
  banner-text: "You've reached the maximum length for this conversation, but you can keep talking by starting a new chat."
  new-chat-control-label: "Start new chat"
  require-not-busy: true
```

Public failure projection:
```json
{
  "code": "GPT-CONVERSATION-EXHAUSTED",
  "message": "ChatGPT conversation reached its maximum length; start a new provider conversation.",
  "classification": "conversation-exhausted",
  "retry": "do-not-retry-current-binding"
}
```

## Validation

Positive DOM fixtures require the fresh current-turn banner, exact Start new chat control, and non-busy/no-stop state. Negative fixtures cover banner without control, control without banner, partial text, case/line-whitespace variants, historical banner, user prompt containing the sentence, generic navigation button, and busy/stop-control contradiction. Provider-turn tests prove the exhausted outcome is selected before generic completion and does not persist the banner as a successful final response artifact. Gateway tests prove failed terminal state, stable error/classification/retry disposition, bounded diagnostics, and durable non-resumable binding. Resume/continuation tests prove no provider resume or same-binding retry after exhaustion; next request creates a fresh provider conversation. No remote provider deletion call or claim is allowed.
