# Fail closed when a GPT conversation reaches maximum length

## Description

Detect ChatGPT's provider conversation-capacity terminal page when the fresh current-turn assistant region shows the full maximum-length banner together with the enabled Start new chat control. Fail the current gateway request with an actionable provider-terminal classification, mark the durable binding non-resumable, and require the next request to create a new provider conversation.

## Steps

1. Extend the provider-private snapshot extraction with a conversation-exhausted observation that is correlated to the current submitted turn and captures only bounded booleans, normalized text hash, and message identifier.
2. Require the normalized full banner and exact enabled/visible Start new chat control, with no busy/Stop signal, before classifying exhaustion; preserve all false-positive guards.
3. In gpt_auto/turn.py, evaluate exhaustion before response-complete acceptance and before constructing a successful SessionTurnResult/final_summary. Raise a registered terminal provider error with bounded evidence.
4. Register EXT-GPTAUTO-006 in the providers error-resolutions configuration and add an explicit queue retry classification override so this code is terminal/no-retry despite the generic EXT-* transient default.
5. Persist the failed request through the existing failure path without writing the banner as a successful final-response artifact. Persist a bounded session/provider non-resumable exhaustion fact using existing error/close-reason or provider-metadata seams; add schema support only where required.
6. Make explicit resume, automatic continuation, and same-session admission reject exhausted bindings with an actionable new-session disposition. An independent request without that exhausted binding follows ordinary fresh-session admission.
7. Add focused snapshot, turn, queue, gateway session/resume, diagnostics, error-registry, and integration tests; do not click Start new chat or silently migrate the request.

## Detailed Solution & Technical Design

Treat conversation exhaustion as a distinct GPT-auto provider terminal failure, not normal response completion, generic transport failure, or watchdog stall. The stable repository-compatible code is EXT-GPTAUTO-006 (registered in src/audiagentic/config/components/providers/error-resolutions.yaml). Because dispatch.py classifies EXT-* as transient by default, classify_failure() must special-case EXT-GPTAUTO-006 as terminal/validation_config so retries and profile fallback do not replay the exhausted turn.

Positive evidence must come from one fresh observation of the current submitted turn: the correlated fresh assistant/message region normalizes to the complete sentence "You've reached the maximum length for this conversation, but you can keep talking by starting a new chat."; an enabled visible button or role=button in the same terminal context has normalized accessible/visible label exactly "Start new chat"; and the page is not busy with no visible Stop control. Normalize case, horizontal/line whitespace, and surrounding punctuation only. Do not substring-match partial phrases.

The snapshot layer should expose provider-private evidence (conversation-exhausted, banner-match, start-new-chat-visible, start-new-chat-enabled, page-busy, stop-control-visible, matched message id/hash) without raw DOM or banner content crossing the gateway contract. Banner without control, control without banner, historical assistant text, user prompt text, generic navigation, disabled/hidden control, or busy/Stop contradiction remain non-exhaustion paths.

turn.py must evaluate this signal before response-complete acceptance and before _result()/final_summary generation. Raise AudiaGenticError EXT-GPTAUTO-006 with bounded failure-reason/provider-terminal-classification/retry-disposition details. The request transitions to failed through the existing gateway failure path; the banner and any partial assistant text are diagnostic evidence only and must not be persisted as a successful response artifact. Existing failure diagnostics may retain bounded lengths/hashes and the provider evidence.

Mark the durable provider binding/session non-resumable using the existing session error/close-reason or provider metadata mechanism, without introducing a broad lifecycle redesign or claiming remote deletion. Resume/continuation and same-session admission must reject an exhausted binding. An independent later request with no exhausted binding uses normal fresh-session admission; no autonomous Start new chat click and no silent same-request conversation migration.

## Code Samples & Guidance

Provider error registration:
```yaml
EXT-GPTAUTO-006: "ChatGPT conversation reached its maximum length. Start a new provider conversation; the exhausted conversation will not be retried."
```

Bounded error details:
```json
{
  "failure-reason": "conversation-exhausted",
  "provider-terminal-classification": "conversation-exhausted",
  "retry-disposition": "do-not-retry-current-binding",
  "exhaustion-banner-match": true,
  "start-new-chat-visible": true,
  "start-new-chat-enabled": true
}
```

```yaml
conversation-exhausted:
  scope: document

  new-chat-control-label: "Start new chat"
  require-not-busy: true
```

## Validation

Positive fixture: fresh correlated banner + exact enabled visible Start new chat + idle/no Stop yields EXT-GPTAUTO-006, failed request, no successful output artifact, and bounded diagnostic evidence.

Negative fixtures: banner without control; control without banner; partial/substring text; case and line-whitespace normalization; historical banner; user prompt containing banner; generic navigation button; hidden/disabled control; busy or Stop visible; unrelated page context. Exhaustion must win over generic response-complete only when all positive conditions hold.

Turn/queue tests prove the signal is classified before completion/result construction, the failure is terminal/no-retry despite the EXT prefix, no fallback/profile retry occurs, and partial/banner text is not stored as a successful final-response artifact. Gateway tests prove stable public error mapping, bounded diagnostics, and no null/path/DOM leakage.

Session tests prove the exhausted binding cannot be resumed or used for same-session continuation, no provider resume/new-chat click occurs, the current request is not replayed, and a later independent request creates a distinct provider conversation. Existing generic error, artifact, resume, and terminal-state suites remain green; no remote provider deletion is invoked.

## Effort & Risk

Medium: DOM shape and text normalization can drift, and the binding transition must not accidentally trigger generic retry or successful artifact persistence. Scope is provider-local detection plus existing gateway error/session seams.

## Standards

GP17/GP19/GP24/GP46 terminal evidence and correlation; SH22 activity-vs-failure classification; AS30/AS49/AS89 session binding and resume; AS86 output ordering; provider-neutral public error/redaction rules

## Acceptance Criteria

- Exhaustion is a dedicated GPT-auto provider-terminal failure using registered code EXT-GPTAUTO-006.
- Detection requires the fresh current-turn full banner, exact enabled visible Start new chat control in the same context, and idle/no Stop state.
- Case/whitespace/surrounding-punctuation normalization works without substring false positives.
- Historical assistant text, user prompt text, generic navigation, missing/disabled control, or busy/Stop state never classifies exhaustion.
- Exhaustion is evaluated before generic response completion and successful SessionTurnResult/final-response artifact persistence.
- The request ends failed with bounded classification conversation-exhausted and retry disposition do-not-retry-current-binding.
- Queue retry/fallback logic treats EXT-GPTAUTO-006 as terminal and performs no same-binding replay.
- The exhaustion banner and partial assistant text are never promoted to a successful exact response artifact.
- Durable session/binding facts make transparent resume and same-session continuation reject the exhausted provider conversation.
- A later independent request follows normal fresh-session admission and obtains a distinct provider conversation.
- No autonomous Start new chat click, silent same-request migration, remote deletion claim, raw DOM, or filesystem path is exposed.
- Existing GPT-auto terminal, artifact, session, and error-projection tests remain compatible.
