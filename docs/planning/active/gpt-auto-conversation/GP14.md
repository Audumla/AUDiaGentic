# Slim canonical gateway status contract

## Description

The status/state payloads returned by the gateway (agent_task_status, agent_task_gateway_overview, agent_task_session_list, etc.) have grown organically and are messy: odd/inconsistent field naming (mixed hyphen-case and terms that don't clearly convey meaning), duplicated information appearing under multiple keys, and poor functional grouping (related fields scattered rather than nested together by concern -- e.g. timing, provider metadata, watchdog/diagnostics, correlation identifiers). This makes the schema harder to consume correctly and easier to misread during live debugging, which this session did repeatedly tonight.

## Steps

- Make agent_task_status and request status/list projections use one compact V4 projector with no response-version negotiation.
- Keep routine status limited to task_id, lifecycle, activity, activity_seq, activity_at, and outcome; diagnostics are explicit and bounded, full response is server-side artifact dereference.
- Reject the retired response-version argument at service/API boundaries; do not emit V3 or dual shapes.
- Add payload-budget, no-preview, no-diagnostics, and endpoint-convergence tests.
- Keep session/overview/control surfaces purpose-specific and migrate callers in the same change.

## Detailed Solution & Technical Design

Current target (2026-08-25): public request polling has one fixed V4 projection. The gateway computes the provider-neutral AS92 snapshot internally, then projects only task_id, lifecycle, activity, activity_seq, activity_at, and outcome. agent_task_status, get_execution_request, list_execution_requests, and timeout status all use this projector. There is no response_version parameter, no V3 fallback, and no dual payload.

Diagnostics are owned by GP48/AS102 and exposed only through the bounded diagnostics operation. Full terminal text is owned by the request artifact store and exposed only through agent_task_response; no path, URI, preview, or artifact locator crosses MCP. Blocking in-process APIs may retain their terminal control record for internal orchestration, but that is not the polling contract.

Durable/session contract versions named v3 are separate persistence protocols and are not public task-status versions. Do not remove them without a storage migration plan.

### 2026-10-06 implementation addendum — canonical rich responses + terminal status payload

This addendum supersedes GP14's earlier statement that full terminal text is available only through `agent_task_response`. The fixed V4 lifecycle projector remains compact and unchanged; the MCP status tool becomes a convenience composition that can include the verified terminal response after completion without adding response content to `task_status_v4` itself.

This is the implementation contract. Do not redesign it during execution.

#### Final decisions

1. **No submit/request-level `response_format` option.** Output representation is a provider/output property, not execution policy.
2. **Canonical response format is provider-derived.**
   - `gpt-auto`: canonical terminal response is Markdown reconstructed from the request-owned assistant DOM.
   - providers already returning plain assistant text stay `text/plain; charset=utf-8`.
   - if GPT Markdown reconstruction is unavailable for an otherwise valid terminal response, fall back to the already-proven plain assistant text and label it plain text. Formatting failure must not downgrade a proven successful turn.
3. **Markdown never participates in correlation, completion, freshness, recovery, or prompt matching.** Existing plain `latest_assistant_text`, exact message IDs, terminal controls, fingerprints and stability gates remain authoritative.
4. **Do not change `task_status_v4.py` or `task-status-v4.schema.json`.** V4 remains the compact lifecycle/status contract.
5. **MCP status defaults to terminal response inclusion:** `agent_task_status(request_id, include_response=True)`.
6. **Gateway/Python compatibility stays compact by default:** `get_execution_request(..., include_response=False)`; MCP explicitly passes true.
7. **One gateway RPC per MCP read.** Status composition happens server-side. `agent_task_response` also stops issuing a second diagnostics RPC solely to recover state/error-code.
8. **Failure-response artifacts remain diagnostic-only.** Never promote `failure-response-artifact` to normal `response`. A failed/cancelled attempt that already owns a legitimate `response-artifact` may still return that artifact, preserving existing semantics.
9. **No artifact paths/URIs/hashes cross MCP.** Inline content plus bounded representation/state/error metadata only.

#### GPT DOM -> Markdown serializer

Inside `_SNAPSHOT_FN`, keep `assistantText()` untouched and add `assistantMarkdown()`. Assistant refs become:

Serializer requirements, bounded to the existing 200000-character sanity ceiling:

- remove `h4.sr-only`, buttons, `[role=button]`, `[data-markdown-copy="exclude"]`, and provider-owned hidden ellipsis nodes;
- text nodes preserve content with NBSP -> normal space;
- `br` -> newline;
- `p` -> paragraph with one blank line after it;
- `h1..h6` -> Markdown heading with one blank line after it;
- `strong/b` -> `**content**`;
- `em/i` -> `*content*`;
- `del/s` -> `~~content~~`;
- inline `code`: choose a backtick delimiter longer than the longest backtick run in the content;
- `pre`: fenced block; derive language from descendant `code[data-language]`, `data-language`, or `language-*` class; choose a fence longer than the longest backtick run in code;
- `a[href]`: `[label](href)`; empty label uses href; `javascript:` and `data:` emit label text only;
- nested `ul/ol/li`: preserve indentation/order;
- `blockquote`: prefix every non-empty output line with `> `;
- `hr` -> `---`;
- `table`: GFM pipe table; `thead` row when present, otherwise first row as header; escape literal `|`; embedded cell newlines become spaces;
- unknown containers recurse into children without inventing markup;
- trim trailing whitespace per line, collapse more than two consecutive blank lines to two, strip outer blank lines;
- any serializer exception returns `null` and must not fail the snapshot.

Do not serialize tool/progress/status chrome as assistant prose.
