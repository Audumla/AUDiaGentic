# Review and clean up the gateway status/state response schema

## Description

The status/state payloads returned by the gateway (agent_task_status, agent_task_gateway_overview, agent_task_session_list, etc.) have grown organically and are messy: odd/inconsistent field naming (mixed hyphen-case and terms that don't clearly convey meaning), duplicated information appearing under multiple keys, and poor functional grouping (related fields scattered rather than nested together by concern -- e.g. timing, provider metadata, watchdog/diagnostics, correlation identifiers). This makes the schema harder to consume correctly and easier to misread during live debugging, which this session did repeatedly tonight.

## Steps

- Inventory the actual current response shapes for agent_task_status, agent_task_gateway_overview, agent_task_session_list, agent_task_list_requests, and agent_task_session_close/control -- collect real examples (this session has several in its transcript/GP04 notes) rather than working from documentation alone.
- Identify duplication (the same fact exposed under two different keys/paths) and inconsistent naming (hyphen-case vs different terminology for the same concept across endpoints).
- Propose a cleaner grouping by functional concern (e.g. identity/correlation, lifecycle/state, timing, provider metadata, watchdog/diagnostics, error) and a consistent naming convention.
- This is a public/consumer-facing contract (MCP tool responses) -- any change needs a compatibility plan (versioned response, deprecation window, or a documented breaking-change contract-version bump) rather than silently changing field shapes under existing callers.
