# Durable gateway/provider evidence, semantic failure classification, and safe GPT-auto recovery

## Description

Make gateway and gpt-auto failures diagnosable and recoverable without misclassifying adapter/gateway proof failures as ChatGPT failures. Persist bounded provider evidence from pre-submit through reconciliation, derive a gateway-owned semantic classification and recovery disposition, expose the same projection through request/session status, dashboard, and MCP, and add explicit reconcile/adopt/abandon-and-retire operations. Remove session-capacity as a configurable capacity dimension; persistent sessions are capacity-neutral and only active provider tasks consume per-project execution capacity.

## Steps

- Validate target state and implementation boundaries with GPT against the current agent-surface-refactor branch; incorporate review findings before coding.
- Define versioned bounded DiagnosticEvidence and request/session diagnostic rollups: failure class, observation phase, side-effect state, certainty, correlation status, recovery disposition, provider signals, bounded evidence IDs and timestamps.
- Add the write-ahead submit-intent boundary and durable milestone/coalesced evidence capture across gpt-auto pre-submit, submission proof, activity, terminal observation, cancellation, and reconciliation.
- Persist structured cancellation provenance and unresolved-turn state with compare-and-swap revisioning; preserve evidence across restart without storing prompts, raw DOM/CDP, credentials, or full responses.
- Implement gateway-owned semantic classification and recovery policy; retain provider error codes as adapter evidence, not as proof of provider failure.
- Add explicit read/recovery APIs and MCP/admin surfaces for diagnostics, reconcile, adopt, abandon-and-retire, and safe non-submission clearing; enforce zero-send adoption and idempotency.
- Expose one bounded diagnostic projection through request status, session status, timeline, dashboard, and MCP; add project active-task capacity reporting.
- Remove the configurable session-capacity overlay from capacity resolution and queue scope keys; retain per-session single-flight as a correctness invariant and enforce active provider-task limits per canonical project.
- Add migration handling, incident-shaped tests, integration tests, and live GPT validation; update documentation and schemas.

## Detailed Solution & Technical Design

Use existing layers only: gpt_auto snapshot/turn/observation_engine produce provider evidence; the harness-status observer and agents/status terminal_quality/status_projection normalize and interpret it; gateway request/session stores and NDJSON timelines persist bounded rollups; API/service/MCP/dashboard consume the same projection. Introduce four orthogonal axes: FailureClass (provider-rejected, provider-error, browser-adapter-error, gateway-ownership-queue-error, cancelled, timeout, ambiguous-side-effect, unknown), ObservationPhase (admission, ownership, capacity-wait, pre-submit, submit-intent, submission-proof, in-progress, terminal-observation, reconciliation, cancellation, finalization), SideEffectState (not-started -> may-have-started -> submission-proven -> terminal-evidence-seen), EvidenceCertainty, and RecoveryDisposition. Persist a pre_submit snapshot, then submit_intent before any browser mutation. Never move side-effect state backwards. Coalesce repeated activity observations into bounded rollups (default 25 milestones, hard maximum 100). Store structured unresolved-turn state in the session record with revision, originating request/attempt, prompt digest/id, correlation status, candidate fingerprint, last evidence and recovery disposition. Add cancellation provenance with source/actor/reason/timestamp. Recovery mutations use unresolved-turn-id plus expected revision, candidate fingerprint where applicable, and idempotency key. adopt performs zero sends and persists the verified response through the existing OutputStore; abandon-and-retire quarantines/retires the provider conversation before a new turn; clear-not-submitted is permitted only when side_effect_state is definitively not-started. Persistent sessions consume no task capacity; queued work consumes no token; active provider turns consume a project capacity lease; reconciliation consumes a project task slot; unresolved idle sessions release the task slot while remaining recovery-blocked. Keep physical provider/model-source capacity independent from project policy.

## Effort & Risk

Large cross-layer change. Main risks are accidentally treating DOM terminal signals as provider truth, allowing duplicate sends during recovery, leaking sensitive evidence, changing existing request lifecycle semantics, or confusing session single-flight with capacity. Mitigate with a write-ahead side-effect boundary, monotonic state, CAS recovery, bounded redacted evidence, existing status projection ownership, and incident-shaped tests before live validation.
