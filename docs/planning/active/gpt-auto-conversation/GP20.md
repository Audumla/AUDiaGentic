# Add three-tier gpt-auto config loader (packaged defaults / machine override / project overlay)

## Description

Slice 1 of GP09 (see GP09's notes for the full live design consultation). Introduces the layered config resolution GP09 recommends: packaged defaults at src/audiagentic/components/providers/adapters/gpt_auto/defaults.yaml, an optional machine override at ~/.audiagentic/config/providers/gpt-auto.yaml, and project config becomes a sparse overlay specifying only overrides. Configuration flow: load defaults -> load optional machine override -> deep_merge(defaults, machine, project) -> strict GptAutoConfig.from_dict(). This is the foundational piece the other GP09 slices (schema migration, drift detection) build on.

## Steps

- Add defaults.yaml with the full current schema populated from today's typical project config values.
- Implement deep_merge() and the three-tier load order in config.py or a new loader module.
- Update project gpt-auto.yaml/gpt-auto-t1.yaml/gpt-auto-t2.yaml to become sparse overlays (only actual overrides).
- Add a provider-level config resolver hook so gateway fingerprinting and session creation see the same effective merged config (per GP09's get_provider_runtime_config_state() note).
- Test fixtures: add load_packaged_gpt_auto_defaults() + patch-only-needed-values helper; stop maintaining separate full valid_config() copies across test files.
