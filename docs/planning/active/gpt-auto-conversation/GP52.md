# Capture request-owned structural DOM progress beyond lexical activity labels

## Description

Close the confirmed GPT-auto monitoring blind spots where visible request-owned work is missed because its text is non-English/unknown or its progress is structural/non-text. Preserve fail-closed ownership and transition-only liveness renewal.

## Steps

- Add structural selector and fallback-kind extraction to the CDP snapshot while retaining known lexical labels.
- Add bounded semantic and structural digest material and new accepted progress kinds.
- Make turn scoping explicit for pre-assistant owned blocks and matching assistant ownership; keep global tool counts non-authoritative.
- Add browser DOM, snapshot parsing, scoping, and transition-only regressions.
- Run focused GPT-auto and gateway test suites; request GPT validation against the pushed exact head.

- Filter semantic descendants to visible/rendered nodes before digesting.
- Replace concatenation-plus-truncation hashing with bounded per-node material tokens so both root and head/tail state always influence the final digest.
- Scan newest agent turns first and stop at the bounded progress-block output budget; avoid repeated full-history/layout-heavy reads.
- Add browser fixtures for all structural kinds, hidden-state immunity, late descendant mutation, foreign ownership, pre-assistant ownership, wrong assistant ownership, and unchanged/remounted transitions.
- Run focused GPT-auto tests and request exact-head GPT reassessment.

## Detailed Solution & Technical Design

Extend the CDP snapshot's existing .agent-turn progress extraction with structural fallback kinds for status, progress, tool-result, connector, citation, table, and materialization regions. Include bounded semantic attributes (role, test id, aria busy/expanded/value fields, data state/status/phase/progress) and a bounded head/tail child/text signature in the digest. Continue emitting only kind plus a bounded digest across CDP. Extend ChatSnapshot accepted kinds, explicitly scope progress blocks to the submitted prompt and matching assistant (or pre-assistant owned progress), and keep _progress_activity_labels transition-only. Do not treat persistent region presence, generating=true, global tool counts, or foreign/virtualized DOM as request activity.

## Code Samples & Guidance

Structural fallback kinds: dom-status, dom-progress, dom-tool-result, dom-connector, dom-citation, dom-table, dom-materialization. Digest only bounded semantic state and child signatures; never export raw tool arguments, URLs, or full result bodies.
