# Split gateway-client cache invalidation from RPC replay-safety on NET-AGSV-002

## Description

Slice 4 of GP06 (see GP06's notes for full design), independent of the other GP06 slices -- can land in any order relative to them. NET-AGSV-002 (URLError/TimeoutError/OSError) currently only needs cache invalidation confirmed correct via code inspection, but conflates 'reacquire a live gateway client' (always safe) with 'is it safe to replay the RPC that failed' (not always safe -- a timeout doesn't prove the RPC never reached the server).

## Steps

- Keep automatic dead-client-cache invalidation + reacquire/bootstrap unconditional (already correct, no change needed there).
- Add a separate retry policy deciding whether the original failed RPC is replay-safe: reads/status/list calls may retry freely; mutating operations (submit, resume, control, close) need proven idempotency for that specific request identity, or transport-level proof the failure occurred before server acceptance, before being replayed.
- Consider reusing StandaloneGatewayClient._call()'s existing bounded reattach precedent for CON-AGSV-018 as a pattern, even though it's a less exact semantic match.
