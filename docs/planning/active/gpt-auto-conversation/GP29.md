# Add unified ordered DOM message sequence to gpt-auto ChatSnapshot

## Description

Slice 1 of GP08 (see GP08's notes for the full live design consultation) -- the smallest, most concrete, lowest-risk GP08 slice, and the foundation the other GP08 slices (GP24, GP29) depend on. Fixes a real already-merged-code gap: ChatSnapshot's user_message_ids/texts and assistant_message_ids/texts are two separate per-role arrays, not one true DOM total order, so it's currently impossible to distinguish 'A-A then U-human' from 'U-human then A-A' when both appear in the same poll -- exactly the ordering GP08's boundary rule depends on. Also fixes a related latent bug: IDs and text are currently collected via separately-filtered passes, so an empty/transient text node can desync the id/text array pairing.

## Steps

- Walk user+assistant DOM nodes together in one pass in _SNAPSHOT_FN (gpt_auto_cdp.py), producing a single ChatMessageRef{role, message_id, text, sequence} ordered sequence.
- Add ChatSnapshot.message_refs: tuple[ChatMessageRef,...]; derive the existing four arrays from it for compatibility so no other call site needs to change yet.
- Additive only -- does not change turn.py's resolution logic (that's the later _await_response() rewrite slice).
