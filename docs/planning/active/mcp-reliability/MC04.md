# Add bounded E2E test for management server read operations

## Description

Add a bounded canonical-launcher E2E test for at least one read operation from every management server (ag-planning, ag-ledger, project_status). Tests must use the canonical launcher, not bypass it with direct-module execution.

## Steps

['Write E2E test for ag-planning read operation via canonical launcher', 'Write E2E test for ag-ledger read operation via canonical launcher', 'Verify project_status test uses canonical launcher (already done per completed items)', 'Add timing assertions to verify bounded execution']

## Detailed Solution & Technical Design

### Background

- Project MCP E2E was already fixed to use the canonical launcher (completed item)
- But no bounded E2E test exists for **every** management server through the canonical launcher
- Direct-module execution bypasses launcher issues (working directory, env vars, PATH) that only manifest through the real launch path

### Servers to cover

1. **ag-planning**: `plan_list_items` or equivalent read-only operation
2. **ag-ledger**: `get_current_summary` or equivalent read-only operation
3. **project_status**: already covered (returns ~1.8s per completed items)

### Test requirements

- Use `audiagentic.launcher mcp ... stdio` — the exact path Pi uses
- Assert on **semantic success** (e.g., result contains expected fields), not just "tool returned content"
- Error envelopes (MCP error responses) must fail the test unless explicitly expected
- Timing assertions: each server completes within a bounded window (target: <5 seconds total)

### Test pattern

```
1. Launch server via canonical launcher with timeout
2. Send JSON-RPC initialize request
3. Wait for initialized response
4. Send tool call (plan_list_items / get_current_summary)
5. Assert result contains expected structure (not just content)
6. Assert total elapsed time within bound
7. Clean up process
```
