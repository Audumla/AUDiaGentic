# Diagnose planning and ledger MCP transport failures

## Description

ag-planning and ag-ledger fail before tool execution with 'Transport closed'. This is distinct from the fixed project_status timeout. It prevents authoritative plan reviews, plan state transitions, and ledger events.

Test each server through:

- Direct Python server construction
- Canonical audiagentic.launcher mcp ... stdio
- Pi direct tools
- The connected Codex MCP transport

Capture server stderr, process exit status, initialization response, and first tool call.

## Steps

['Test ag-planning via direct Python server construction', 'Test ag-planning via canonical launcher stdio', 'Test ag-ledger via both paths', 'Capture stderr, exit status, init response, first tool call for each', 'Identify root cause of Transport closed', 'Fix the transport failure', 'Verify planning and ledger operations work end-to-end']

## Detailed Solution & Technical Design

### Failure symptoms

- `ag-planning` and `ag-ledger` fail **before tool execution** with `Transport closed`
- This is **distinct** from the `project_status` timeout that was already fixed
- The failure prevents: plan reviews, plan state transitions, ledger event recording, and all operations through these MCP servers

### Diagnostic approach — four paths to test

1. **Direct Python server construction**: import and construct the server module directly, capture any ImportError or initialization exceptions
2. **Canonical `audiagentic.launcher mcp ... stdio`**: launch through the same mechanism Pi uses, capturing process lifecycle
3. **Pi direct tools**: call through Pi's tool resolution path (the actual user-facing path)
4. **Connected Codex MCP transport**: test through Codex's MCP connection if available

### Data to capture per server

- Server stderr (full output, including Python tracebacks)
- Process exit status (0 = success, non-zero indicates what failed)
- Initialization response (JSON-RPC initialize/result or failure)
- First tool call result (e.g., `plan_list_items` for planning, `get_current_summary` for ledger)

### Likely root causes to investigate

- Module resolution: server entry point not on PYTHONPATH
- Working directory: server requires specific cwd for config discovery
- Environment variables: missing required env vars for MCP transport
- Transport incompatibility: stdio buffering or JSON-RPC version mismatch
- Dependency conflicts: conflicting package versions in the same venv
