# Improve MCP startup and timeout diagnostics

## Description

Pi currently reports generic server-unavailable or MCP -32001 timeout results. Improve diagnostics to identify:

- Server name
- Command and module identity without secrets
- Initialization versus tool-call phase
- Elapsed time
- Process exit status
- Whether stderr was captured

Diagnostics must remain out of the model-visible result when they could expose paths or credentials.

## Steps

['Add server-name identification to error diagnostics', 'Include command/module identity (redacted) in safe diagnostics', 'Distinguish initialization vs tool-call phase failures', 'Add elapsed time and process exit status to diagnostics', 'Capture stderr in diagnostics log (not model-visible)', 'Verify no path or credential leakage in user-facing output']

## Detailed Solution & Technical Design

### Current state

- Pi reports **generic** errors: "server unavailable" or MCP error code `-32001` (internal error/timeout)
- No indication of which server failed, why it failed, or at what phase
- Debugging requires manual reproduction with `audiagentic.launcher`

### Diagnostics to include

```
{
  "server_name": "ag-planning",
  "command": ["python", "-m", "audiagentic.mcp.planning.server"],
  "module_identity": "audiagentic.mcp.planning.server",
  "phase": "initialization",       // or "tool-call"
  "elapsed_ms": 15230,
  "process_exit_status": -9,        // -9 = killed, 0 = success
  "stderr_captured": true,
  "stderr_lines": ["...last N lines..."],
  "error_code": "MCP-32001",       // original error code preserved
}
```

### Redaction rules — what goes where

- **Model-visible result**: server name, phase, elapsed time, generic error class. NO paths, NO credentials, NO stderr content.
- **Internal diagnostics log**: full command, module identity, stderr capture, process exit status, all details needed for debugging.
- **Safe command rendering**: strip secrets from arguments (e.g., `--api-key=sk-...` becomes `--api-key=[redacted]`)

### Phase distinction

1. **Initialization phase**: server process started but didn't complete JSON-RPC `initialize`. Includes: module not found, ImportError, early crash.
2. **Tool-call phase**: server initialized successfully but a specific tool call failed. Includes: timeout during execution, unexpected error response.
