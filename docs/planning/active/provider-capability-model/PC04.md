# Retire legacy capability blocks + dual-read shim; regenerate taxonomy doc

## Description

Once all 16 descriptors are on the unified `capabilities:` map (PC03), remove the legacy read path and the flat top-level blocks. Delete the dual-read branch in the loader, drop the standalone automation_capabilities/capability_facts/host_capabilities/permissions parsing, and make `capabilities:` the sole descriptor surface. Retire or regenerate capability-id-taxonomy.md from the code/YAML catalogue so it can never drift again. Tighten validation to reject the legacy keys outright.

## Steps



## Detailed Solution & Technical Design

GOAL: after all 16 providers are on `capabilities:` (PC03), delete the legacy read path so the four disparate blocks cannot return, and make the taxonomy doc a generated artifact that cannot drift.

1. Remove dual-read. In descriptors/loader.py delete the legacy-block parsing branch and the projection-from-flat-keys code added in PC02. `capabilities:` becomes the sole parse path. The Capability normalization + catalogue-driven mechanism loader stay.

2. Reject legacy keys (VAL-PCAP-013, new). The loader fails if a descriptor still declares any retired top-level capability key: automation_capabilities, capability_facts, host_capabilities, permissions, mcp_config, model_config, plugin_config, hooks_config, language_servers_config, cli_install, surfaces, on_lsp_enabled, lsp_support_probe, fetch_catalog_fn, skill_surface_path, instruction_file, agent_files, supported_connectors, vendor_key_injection, deprecated — whichever were folded into capabilities. (Keep genuinely orthogonal fields that are NOT capabilities: provider_id, display_name, url, description, execution_isolation_tier, mcp_launch_isolation_tier, launches, execution/interactive/acp, access_mode, annotations, session_surfaces — confirm the final folded set during PC02/PC03 and pin it here.)

3. ProviderDescriptor cleanup. Remove the now-dead flat fields from the dataclass (base.py) once nothing constructs them; keep only `capabilities` + the orthogonal fields. Accessors (automation_capability/host_extensions/permissions) remain, still projecting from `capabilities`.

4. Taxonomy doc regeneration. Replace hand-maintained capability-id-taxonomy.md content with a generator that renders the kind table + per-provider matrix FROM config/providers/_capabilities.yaml + the descriptors (same spirit as render_capability_facts_markdown). Add a test/CI check that the committed doc equals the generated output so it can never drift again. The PROVIDER_CAPABILITY_REFERENCE README's runtime-authority boundary note stays accurate (catalogue is declarative; families code-owned).

5. Ledger + docs. Record the retirement; update any INSTALL_MAP / standards references that named the old blocks.
