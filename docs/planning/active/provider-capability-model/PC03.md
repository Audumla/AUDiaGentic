# Migrate all 16 provider descriptors to the unified capabilities: map

## Description

With the dual-read loader (PC02) in place, migrate every provider YAML under src/audiagentic/config/providers/ from the legacy flat blocks to the unified `capabilities:` map, one provider at a time (each independently shippable and green). Prune redundant mirror facts during migration: a former capability_facts entry whose only content re-asserts 'mechanism field present' (installed-artifact tier, empty constraints/limitations) carries no information over the mechanism itself and is dropped — keep only facts adding provenance, constraints, uncertainty, or verification history. Providers: aider, antigravity, claude, cline, codex, continue, copilot, gemini, goose, local_openai, opencode, openhands, pi, plandex, qwen, roo.

## Detailed Solution & Technical Design

GOAL: convert every provider YAML from legacy flat blocks to the unified `capabilities:` map, one provider per change, each shippable and green under the PC02 dual-read loader. Mechanical but must preserve exact normalized output.

1. Per-provider procedure (repeat 16x):
   a. Read current descriptor; enumerate its legacy blocks: automation_capabilities, capability_facts, host_capabilities, permissions, and the config-spec/callable fields (cli_install, mcp_config, model_config, plugin_config, hooks_config, language_servers_config, on_lsp_enabled/lsp_support_probe, surfaces, fetch_catalog_fn, skill_surface_path, instruction_file, agent_files, deprecated, supported_connectors, vendor_key_injection).
   b. Map each to its catalogue kind (PC01). Write one `capabilities:` entry per kind: mechanism = the moved sub-fields; modes = the family's supported_modes (drop if identical to catalogue default); evidence = the matching former capability_fact's evidence.
   c. Delete the now-migrated legacy top-level keys for that provider.
   d. Run the PC02 normalization-equivalence test: normalized descriptor BEFORE (git HEAD) must equal AFTER for everything EXCEPT deliberately-pruned mirror facts.

2. Mirror-fact pruning (the cleanup dividend). Drop any former capability_fact whose only content re-asserts 'mechanism field present': evidence_tier installed-artifact, review verified, empty constraints AND empty limitations AND null action_needed, mechanism string merely restating the field. These add nothing over the mechanism entry. KEEP facts that carry a real constraint, limitation, action_needed, sub-'verified' evidence, or 'external:'/evidence-only provenance (e.g. pi's execution-tier vendor-key/model-config facts with tool_version 0.79.8 and constraints). Record each prune in the item change log so it's auditable.

3. Off-taxonomy id resolution. Ids PC01 flagged (pi 'vendor-key-injection' -> kind 'model-vendor-injection' evidence-only; 'model-config-surface' -> 'model-config' evidence or a dedicated evidence-only kind) get their final catalogue kind here.

4. Migration order (smallest first to prove the shape, heaviest last): aider (3), local_openai (3), plandex (4), antigravity (5), goose (5), continue (6), roo (6), claude (7), gemini (7), openhands (7), pi (7 + off-taxonomy), cline (8), copilot (8), qwen (10), codex (12), opencode (17).
