# Provider catalog operations

## Description

Unify provider catalog refresh into one optional-provider tool. Provider activation reconciliation is owned by PC10; this item must not duplicate provider_reconcile or projection repair.

## Steps

- Replace refresh_provider_catalog and refresh_all_catalogs with provider_catalog_refresh(provider_id=None).
- With provider_id supplied, refresh one provider catalog; when omitted, refresh every descriptor with a supported catalog-fetch capability.
- Keep catalog refresh network/cache semantics separate from provider_reconcile and provider configuration projection.
- Update provider status/catalog metadata and tests.

## Detailed Solution & Technical Design

provider_catalog_refresh(provider_id=None) is the explicit provider model-catalog data operation. It calls the existing async single/all catalog services, performs network access only when explicitly requested, persists runtime catalog results, and returns per-provider outcomes for batch calls. It does not install, update, enable, disable, reconcile, or project provider configuration. provider_reconcile and provider-owned projection repair are specified only in PC10.

## Code Samples & Guidance

async provider_catalog_refresh(provider_id: str | None = None) -> dict[str, Any]. MCP name: provider_catalog_refresh.

## Validation

- One-provider refresh calls only that provider's catalog fetch path.\n- Omitted provider ID refreshes all supported providers and returns per-provider results.\n- Unsupported/no-fetch providers are reported as skipped, not failures.\n- Catalog refresh remains the only explicit provider catalog network operation.\n- No public provider_refresh or operate_provider_surface(s) tools remain after PC10.

## Effort & Risk

Medium: behavior is mostly composition, but stale managed entries and provider-specific reload semantics need regression coverage.

## Standards

Managed-config writers preserve unknown user entries and ownership registries. Explicit refresh is the only network boundary.

## Acceptance Criteria

- One catalog refresh operation handles a named provider or all supported providers with typed per-provider results.
- Unsupported/no-fetch providers report skipped rather than failed.
- Catalog refresh is the only explicit provider-catalog network boundary and does not perform activation reconcile/projection repair.
- Retired refresh/surface-operation aliases are absent.
- Focused one/all/no-fetch/network-boundary tests pass.

## Notes

PC10 owns provider_reconcile; this item owns catalog data refresh only.
