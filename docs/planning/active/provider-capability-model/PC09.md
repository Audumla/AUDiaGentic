# Provider MCP status and capabilities surface

## Description

Replace the ambiguous provider status/describe/descriptor MCP tools with one operational provider_status tool and one static provider_capabilities tool. Keep runtime state separate from declared capability metadata.

## Steps

- Define the status response sections and compatibility mapping from existing get_provider_status and describe_provider reads.
- Implement provider_status(provider_id) as a composition of activation, installation probe, update applicability, catalog summary, execution/configuration state, and managed projection state.
- Implement provider_capabilities(provider_id) from descriptor and capability registries without secrets or raw callable/ownership internals.
- Remove public describe_provider, list_provider_descriptors, and duplicate status registrations from providers_mcp.py/providers.yaml.
- Update generated tool descriptions and contract tests.

## Detailed Solution & Technical Design

Use providers_api as the public composition boundary. provider_status must not perform network refreshes or mutate files; reuse build_provider_status/get_provider_status, probe_provider_cli, list_provider_models, update-recipe applicability, describe_execution_support, and managed-config status readers. Return stable nested sections: activation {enabled}, installation {available,state,probe}, update {supported,action_needed}, catalog {model_count,stale}, execution, configuration, projection. provider_capabilities should serialize static descriptor fields: supported connectors, automation families and modes, launch/session channels, host capabilities, config-surface declarations, installation/support metadata, limitations, and supported connectors. Exclude api-key values, callable reprs, raw ownership IDs, and duplicated runtime status. Keep internal list_provider_descriptors/describe_provider helpers only where existing Python consumers/tests require them.

## Code Samples & Guidance

provider_status(provider_id: str) -> dict[str, Any]; provider_capabilities(provider_id: str) -> dict[str, Any]. MCP names: provider_status, provider_capabilities. Unknown provider returns the existing structured unknown-provider result. No network calls.

## Validation

- MCP exposes exactly provider_status and provider_capabilities for these concerns.
- provider_status has stable activation/installation/update/catalog/execution/configuration/projection sections and is read-only.
- provider_capabilities contains declared support but no secrets/callable representations.
- Old public describe_provider/list_provider_descriptors/status aliases are absent from generated declarations.
- Existing provider status and describe composition tests are migrated and pass.

## Effort & Risk

Medium/high: response-shape compatibility and sensitive metadata redaction are the main risks. Do not remove internal helpers until all Python callers are migrated.

## Standards

Read-only MCP tools must not mutate or fetch mutable upstream state. Preserve provider capability ownership and secret-reference redaction.
