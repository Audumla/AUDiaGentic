# Derive foundation features from capability instances; retire feature_mapping._CAPABILITIES table

## Description

feature_mapping.py is a THIRD parallel enumeration of provider capabilities (after capability_facts and automation_capabilities): its _CAPABILITIES table re-derives mcp/lsp-support/surface/skills from RAW descriptor fields (d.mcp_config, d.language_servers_config, d.skill_surface_path, d.agent_files/instruction_file) and projects them into foundation FeatureDescriptors (the enable/disable layer). After the capabilities: migration these are the same capabilities the catalogue already declares. Retire the hand-maintained field->kind table and derive impl-scoped features DIRECTLY from the provider's capability instances — each feature-bearing capability kind emits one FeatureDescriptor. This makes capabilities the single source (declaration) and features a thin enable-gated projection.

HARD DEPENDENCY on PC04: feature_mapping reads the raw fields (mcp_config/language_servers_config/skill_surface_path/agent_files/instruction_file) that PC04 deletes. If feature_mapping is not converted in the same coordinated cut, it breaks when the fields are removed. Sequence with / inside PC04's field-removal.

## Steps



## Detailed Solution & Technical Design

1. Mark feature-bearing kinds in the catalogue. The current feature kinds (KIND_MCP='mcp', KIND_LSP_SUPPORT='lsp-support', KIND_SURFACE='surface', KIND_SKILLS='skills') map to catalogue kinds mcp, language-servers, surfaces/instructions, surface(-skill). Add a catalogue attribute (e.g. feature_kind, or derive: any provisioned kind + surfaces/skills) so the catalogue knows which capabilities project to features. Keep feature kind ids stable for the foundation features system (FEATURE_SCOPE_IMPLEMENTATION) unless a rename is coordinated with feature_resolution/manager/registry consumers.
2. Rewrite impl_features_for(descriptor) to iterate descriptor.capabilities (the normalized instances from PC02) and emit one FeatureDescriptor per feature-bearing capability, using the catalogue's feature_kind + the capability's target ids (surface files come from the capability mechanism/derived ownership, NOT the removed agent_files field). Delete the _CAPABILITIES table and the raw-field lambdas.
3. Verify the enable/disable gating in surfaces/manager.py (_active_feature_providers KIND_SURFACE/KIND_SKILLS), feature_resolution.py, and registry.py produces identical feature sets before/after (equivalence test over all_descriptors()).

# AFTER — derive from capability instances (single source)
def impl_features_for(descriptor):
    features = []
    for cap in descriptor.capabilities:            # normalized instances (PC02)
        kind = catalogue[cap.kind]
        if kind.feature_kind is None:              # not feature-projected
            continue
        for fid in feature_ids_for(cap, kind):     # target ids from the mechanism, not raw fields
            features.append(FeatureDescriptor(parent='providers', kind=kind.feature_kind,
                                              feature_id=fid, scope=FEATURE_SCOPE_IMPLEMENTATION,
                                              implementation=descriptor.provider_id))
    return features
