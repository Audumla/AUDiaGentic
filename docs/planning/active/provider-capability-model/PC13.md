# Provider-resolved model availability and listing

## Description

Make model listing and inventory provider-resolved so the same vendor/source can expose different model subsets per provider.

## Steps

- Add model_list(provider_id, source_id=None) as the primary effective-model query.
- Resolve source models through provider supported connectors, vendor-native capability, credential state, filters, provider catalogs, and projection ownership.
- Revise model_inventory to return a source/vendor/model/provider availability matrix instead of vendor-wide model unions.
- Include actionable availability reasons such as unsupported-provider, unsupported-connector, credential-missing, filtered, stale, and not-projected.
- Keep provider-native catalogs separate from source catalogs and preserve per-provider model configuration status.

## Detailed Solution & Technical Design

Introduce a dedicated pure/read-only availability resolver (recommended new services/catalog/availability.py) that composes source catalogs, provider native catalogs, descriptor supported_connectors/vendor_key_injection, source filters/enabled state, credential-reference availability, provider activation, and managed model ownership. model_list(provider_id, source_id=None) returns effective provider-resolved rows with origin=native|source, source_id/vendor_id/model_id, availability, action_needed, stale, and projected flags. Native rows come only from provider runtime catalogs; source rows come from materialized source entries and are filtered by provider connector/capability rules. model_inventory composes the same resolver across providers and sources without network calls; it must not union models solely by vendor or model_id. Unsupported/credential-missing/filtered/stale/not-projected reasons are explicit and redacted.

## Code Samples & Guidance

model_list(provider_id: str, source_id: str | None = None) -> dict[str, Any]; model_inventory() -> dict[str, Any]. Suggested row: {provider_id, source_id, vendor_id, model_id, origin, availability, action_needed, stale, projected}.

## Validation

- Same source/vendor returns provider-specific subsets for different providers.
- Native provider catalog availability is not confused with source catalog availability.
- Inventory reports per-provider reasons instead of a universal vendor model union.
- Disabled providers are not reported as active projection targets.
- Credential/filter/stale/unsupported cases are covered without network calls.

## Effort & Risk

Large: current inventory intentionally aggregates vendor models and needs a compatibility-resolution layer without duplicating provider adapter logic.

## Standards

Use descriptor-declared connector/capability facts and existing provider catalog reads. Keep inventory read-only and avoid network calls.

## Acceptance Criteria

- The same vendor/source can resolve different model subsets per provider without a universal union.
- Native provider catalog evidence remains distinct from source catalog evidence.
- Inventory reports typed per-provider reasons for credential/filter/stale/unsupported cases without network calls.
- Disabled providers are excluded as active projection targets.
- Resolution reuses PC09 descriptor facts and PC12 catalog/source contracts; no adapter logic is duplicated.

## Notes

Depends on PC12 source/catalog contracts and provider descriptor capability data from PC09. Do not duplicate provider adapter logic; use descriptor connectors, provider catalog reads, and managed model ownership.
