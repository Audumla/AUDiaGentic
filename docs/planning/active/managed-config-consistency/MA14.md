# Extract generic desired-set reconciliation coordinator

## Description

Promote the repeated desired/observed membership orchestration used by Hindsight, LSP synchronization, and similar capability reconciliation into a domain-neutral foundation coordinator. It sequences callbacks but never owns durable mutations.

## Steps

1. Characterize desired-set loops in coding_lsp/language_servers_sync.py, memory/hindsight/provision.py, and providers/services/reconcile.py. Tabulate common operations and semantic differences; require at least two exact consumers.
2. Define domain-neutral `reconcile_membership(desired_ids, managed_ids, apply_fn, remove_fn, *, plan=False, continue_on_error=True)` and result containing planned/applied/removed/unchanged/failures. Deterministic sorted ordering; ids opaque strings.
3. Coordinator owns membership calculation, ordering, callback isolation, dry-run planning, and aggregate result only. ManagedConfigSpec/ArtifactRegistry/component stores retain mutation ownership. No path/config/provider/component knowledge.
4. Support optional teardown callback only if two characterized consumers share distinct remove vs teardown semantics; otherwise keep separate to avoid speculative modes.
5. Rewire Hindsight and LSP high-level loops after MA02/MA08 owner APIs stabilize. Providers reconcile adopts only common cohesive portion; do not force enable/probe/surface state machine into set abstraction.
6. Release orchestration remains MA05 + MA11 recipe sequencing. Harness install exemptions/ownership notes fold into HA01/HA02 (plan harness-runtime-ownership, ex-MA03/MA07); MA14 does not touch them.
7. Add callback trace goldens, failure continuation, dry-run, empty sets, idempotence, and fixture third consumer tests.
8. Update Architecture Standards/docs and delete duplicated loop helpers only after parity.
