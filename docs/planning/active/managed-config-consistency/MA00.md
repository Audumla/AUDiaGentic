## Effort & Risk

BREADTH — High, but bounded. This is not a foundation/catalog rewrite. It changes one public facade plus four migration fronts: (1) providers_api export/semantic adapter surface; (2) agents execution dispatch (one direct module); (3) coding-LSP projection (five calls, four reverse type imports); (4) Hindsight provider-mechanics extraction (ten modules, factory/recipe ownership inversion). HA01/HA02 are deferred composition consumers, not current implementation scope. Shared managed-config core/MO06 and foundation.steps are reused.

CHANGE SHAPE — Cross-component API migration with behavioral parity requirements. Highest code volume/risk: MA02. Highest interface-design risk: MA16/MA17. Highest ownership/adoption/collision risk: MA08/MA02. Do not parallel-edit the public providers_api surface and downstream callers without a frozen compatibility contract.

REQUIRED AGENT SKILLS — Senior Python refactoring across package boundaries; import-graph/static analysis; API compatibility/versioning; pytest golden/monkeypatch migration; managed-config atomic write/adoption/collision/prune semantics; async execution, retries, cancellation, event/timeline preservation; provider CLI/config integrations; secrets/redaction review. Must distinguish soft provider research from executable registration and resist creating universal request/result/taxonomy abstractions.

EXECUTION CAPACITY — Use one architectural owner for MA16 public contract and MA17 execution seam. MA08 may proceed after MA16 contract freeze. MA02 should be isolated, incremental, and golden-gated; it is unsuitable for blind bulk moves. Review every family before deletion. MA09 independently verifies import/export graph and behavioral guarantees.
