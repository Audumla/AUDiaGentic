# Validate ACP as shared agent execution transport

## Description

Harden and validate ACP as one concrete provider execution implementation and preserve neutral execution events. Deeply interrogate provider transports and store all findings in provider capability knowledge config/evidence. Runtime composition uses explicit provider execution adapters through MA17; it does not select from a generic transport taxonomy or full catalog record.

## Steps

0. Preserve validated baseline in AGENT_EXECUTION_TRANSPORTS.md and existing ACP implementation; no second transport/event/session abstraction.
1. Preserve completed characterization and exact provider/version evidence; add all observed capabilities/limits to MA19-owned provider knowledge config.
2. Harden foundation ACP port only for current execution requirements: cancellation, process termination, malformed update/exit normalization, bounded delivery, callback isolation.
3. Keep canonical neutral event fields actually consumed by timeline/callers. Do not add event/state fields only because protocols expose them.
4. Test ordering, currently mapped event kinds, permission behavior, errors, cancellation, bounds, and redaction.
5. Keep OpenCode adapter limited to launch/config differences; Pi remains documented unverified until proven.
6. Preserve clean-wheel Docker protocol gate and optional real-provider smoke.
7. SOFT HANDOFF: update provider knowledge/evidence with protocol, session, event, cancellation, permission, launch, and limitation facts. These facts do not create runtime types or select code paths.
8. RUNTIME HANDOFF: MA17 explicitly composes OpenCode ACP/CLI execution adapters behind minimal ExecutionPort. No catalog binding/dotpath or generic manifestation selection.
9. Project neutral events into existing timeline; no ACP-only store.
10. Final validation: focused tests, boundaries, explicit CLI fallback, cancellation, Docker wheel, optional E2E, docs/evidence/ledger.

## Effort & Risk

High architectural leverage. Main risk is implementing against wrong ACP meaning/version or replacing useful AUDiaGentic orchestration with transport semantics. Evidence and mapping review precede code; one-provider proof limits scope.

## Standards

- arch-standards — foundation neutral; explicit composition; no hidden string/dotpath registry; canonical errors/redaction; no duplicate execution/store.
- component-creation — provider launch mechanics stay provider-owned.
- observability — one bounded redacted timeline.
