# Validate ACP as shared agent execution transport

## Description

Architecture checkpoint before MA16 schema freeze. Correct the existing ACP scaffold's terminology and ownership, validate the official Agent Client Protocol against current provider streaming/session/gateway behavior, identify duplication, and prove one transport-neutral ACP vertical slice only if a shipped provider has verified ACP support. ACP is an optional execution transport capability, not a provider identity, requester-facing provider API, replacement for MCP, or parallel orchestration system.

## Steps

0. CHECKPOINT—DO NOT REPEAT: read `docs/reference/AGENT_EXECUTION_TRANSPORTS.md` and ledger event `chg_20260713_120627_added-working-opencode-deep-co_8918`. Existing validated baseline: `foundation.execution.acp` uses official SDK 0.11.0/protocol 1; `AcpLaunch`, `AcpEvent`, `AcpResult`, `run_acp_prompt`; thin `adapters/opencode/acp.py`; OpenCode 1.17.18 + `brutus/deep-coder` real E2E; authoritative gateway working-root/stream-controls; stale provider ACP scaffold deleted. Do not recreate, relocate, or add a second transport/event/session abstraction.
1. CHARACTERIZE CURRENT CONTRACT: run focused unit tests and opt-in real E2E before edits. Record current SDK process/cancel API, event variants observed, `AcpResult` terminal behavior, and existing gateway timeline schema. Stop if installed SDK differs from pinned 0.11.0.
2. FOUNDATION HARDENING ONLY: extend `foundation/execution/acp.py` through typed, provider-neutral ports. Add explicit cancellation input/process termination semantics, malformed-update/process-exit normalization, bounded event delivery, and callback failure behavior. No provider IDs, profiles, gateway store, MCP, or component imports.
3. CANONICAL EVENT CONTRACT INPUT: define neutral event fields required by all transports: sequence, kind, timestamp, session id, safe payload/core text, terminal/error state, source transport metadata under namespaced extension. Reuse existing foundation contract/schema loader; do not create string event registry. ACP mapping remains lossless but redaction occurs before any durable consumer.
4. TEST FOUNDATION: exact tests in `tests/unit/foundation/test_acp_execution.py`: ordering; assistant/thought/status/usage/tool/file/terminal/plan mapping; default permission denial; explicit policy callback; malformed update; child exit; callback error; cancel before prompt; cancel in flight; bounded event count/bytes; secret canary absent from normalized errors. Mock official SDK boundary, not provider internals.
5. PROVIDER BINDING: keep `components/providers/adapters/opencode/acp.py` limited to executable, args, cwd/config/auth/model override and namespaced extensions. Add binding tests proving no orchestration/store imports and no config-file mutation. Pi stays unverified; no Pi binding unless separate version-matched evidence proves adapter contract.
6. DOCKER PACKAGE GATE: add clean-wheel Docker smoke that installs package with `[acp]`, imports transport, runs protocol fixture/echo agent, and leaves host untouched. Real OpenCode/deep-coder smoke remains opt-in because it needs installed executable/network; document exact command and expected exact output.
7. HANDOFF TO MA16: update transport evidence record with verified states/features/limits. MA18 does NOT implement transport selection or capability catalog. At this point MA16 may proceed even while gateway composition remains pending.
8. HANDOFF TO MA17: after MA16 declaration exists, MA17 resolves execution capability to provider-owned binding and returns neutral execution port. Only then connect gateway orchestration to `run_acp_prompt` through that port. No `if provider_id`, `if transport == acp`, executable lookup, ACP method, or protocol version in agents gateway.
9. EVENT PERSISTENCE/DELIVERY: MA17-owned composition projects neutral events into existing gateway timeline/event storage after redaction and bounded retention. MCP cursor polling reads same persisted sequence; progress notification is optional projection. No ACP-only store or raw stdout persistence.
10. FINAL VALIDATION: focused units; boundary/import guards; non-ACP CLI fallback; cancellation; clean Docker wheel; opt-in OpenCode E2E; architecture grep for provider/component imports in foundation and ACP/provider branches in gateway. Update evidence/docs/ledger. Complete MA18 only when transport hardening plus MA16/MA17 gateway composition gates pass.
