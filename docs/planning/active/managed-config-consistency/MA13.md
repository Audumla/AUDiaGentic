# Unify declarative probes in foundation

## Description

Unify only currently duplicated probe parsing/execution in existing foundation/toolchains/probes.py. Capability catalog documentation may reference probes, but MA13 does not serve future catalog declarations and creates no capability/probe taxonomy beyond observed prefixes.

## Steps

1. Inventory every current probe declaration: binary, all-binaries, path, command, provider CLI probes. Freeze timeout/detail/boolean semantics.
2. Extend existing `foundation/toolchains/probes.py` in place. Its public probe result remains `ProbeResult`; completed `foundation.steps.StepResult` is execution-internal and is not MA13's public result. Do not create another probe home or result type.
3. Add `probe_from_spec(spec)` for observed prefixes only. Prefer smallest dispatch shape; registerable prefix handlers only if more than one current extension owner needs registration.
4. Preserve path expansion, all-binary semantics, safe command parsing, and 10s dependency timeout.
5. Unknown/malformed specs use canonical error. Redact surfaced detail; exit-code-only probes discard output.
6. Replace dependencies.py private probe resolvers and equivalent duplicate parsing. Adapt `ProbeResult.available` at existing bool-only boundary rather than creating another result vocabulary.
7. Do not promote dependencies to full recipes without real lifecycle.
8. Delete duplicate resolvers/parsers and update docs.

## Files

[FOUNDATION] existing toolchains/probes.py and error resolutions
[CONSUMERS] foundation/components/dependencies.py; equivalent provider/recipe probe builders
[CONFIG] component YAML unchanged
[TEST] observed-prefix, parity, timeout, redaction, bool-boundary tests

## Validation

1. One test per observed prefix plus malformed/unknown/timeout/missing cases.
2. Dependency planned commands and bootstrap behavior byte/semantically equal to baseline.
3. Command secret canary redacted only when detail surfaced; exit-code-only result has no captured output.
4. Fixture probe kind registers without core edit; duplicate prefix rejected.
5. Old `_resolve_probe_*` and duplicate parsers absent.
6. Full unit zero new failures; real installation tests Docker-only.

## Effort & Risk

Mid-low internal refactor. Main risk timeout and command parsing drift; inventory/goldens pin both.
