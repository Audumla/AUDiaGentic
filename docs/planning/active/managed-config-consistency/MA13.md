# Unify declarative probes in foundation

## Description

Mid-level execution packet to replace duplicated dependency probe parsing with the existing provider-neutral probe primitives in `foundation/toolchains/probes.py`. Architecture is frozen: keep `ProbeResult` as the structured result, keep dependency consumers on `Callable[[], bool]`, support only currently observed spec prefixes, and add no capability/probe taxonomy.

## Steps

0. BASELINE — Run `python -m pytest tests/unit/foundation/toolchains/test_probes.py tests/unit/foundation/test_dependencies.py -q`. Inventory probe strings with `rg -n "probe:" src/audiagentic/config .audiagentic --glob "*.yaml" --glob "*.yml"`; record every observed prefix and any shell metacharacter before editing. Stop and request review if a prefix is not one of `binary:`, `all-binaries:`, `path:`, `command:`, `custom:`, or exact `toolchain:uv`.
1. ADD ONE PARSER — In `foundation/toolchains/probes.py`, add `probe_from_spec(spec: str) -> Probe`. Add the smallest private predicate wrapper needed to adapt an existing zero-argument bool callable to `Probe.check() -> ProbeResult`; do not add a public registry or new result type.
2. FREEZE PREFIX MAPPING — `binary:<name>` checks one executable with `tool_available`; `all-binaries:<a,b>` strips empty entries and requires every executable; `path:<path>` uses the existing path expansion semantics; `command:<argv>` uses non-shell argv parsing, a 10-second timeout, UTF-8 replacement decoding, and exit code zero; exact `toolchain:uv` calls `uv_available`; `custom:<module>:<dotpath>` resolves through `foundation.refs.resolve_ref` and wraps the returned zero-argument callable. Empty payload, malformed command/ref, or unknown syntax raises the existing canonical dependency validation error.
3. PRESERVE SAFETY — Commands run with `shell=False`, capture output, and never include stdout/stderr in the returned detail. Redact any surfaced exception detail with the shared redaction helper. If baseline config contains compound shell syntax or relies on output text, stop for review rather than changing semantics silently.
4. ADAPT DEPENDENCIES — In `foundation/components/dependencies.py`, replace `_resolve_probe_binary`, `_resolve_probe_all_binaries`, `_resolve_probe_path`, `_resolve_probe_command`, `_resolve_probe_custom`, and `_PROBE_RESOLVERS` with one `_resolve_probe(spec)` adapter that constructs `probe_from_spec(spec)` once and returns `lambda: probe.check().passed`.
5. PRESERVE CALLERS — Do not change `build_dependency_probes`, `load_dependency_probes`, `_guarded`, dependency YAML, `SelectStep`, or public return shapes. They continue receiving `Callable[[], bool]`.
6. TEST PARSER — Extend `tests/unit/foundation/toolchains/test_probes.py` for every supported prefix, tilde expansion, all-binaries empty-item trimming, command success/failure/timeout/invalid argv, custom callable, `toolchain:uv`, malformed/empty/unknown specs, and redacted failure detail.
7. TEST ADAPTER PARITY — Update `tests/unit/foundation/test_dependencies.py` so existing binary/all-binaries/command and install-skip/install-run behavior remains unchanged through the new parser. Keep the UTF-8 replacement regression test.
8. DELETE DUPLICATION — Confirm removed helper names and resolver table are absent with `rg -n "_resolve_probe_(binary|all_binaries|path|command|custom)|_PROBE_RESOLVERS" src tests`.
9. VALIDATE — Run both focused test files, then `python -m pytest tests/unit/foundation -q`. Run `python -m ruff check` only on touched Python files.
10. HANDOFF — Report supported-prefix inventory, files changed, test counts, and any unchanged custom-probe call sites. Do not broaden scope to provider catalogs, recipes, or runtime dispatch.
