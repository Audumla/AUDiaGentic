# Unify declarative probes in foundation

## Description

Replace component dependency probe mini-language with one foundation probe specification registry and result vocabulary, reused by recipes, dependency planning, provider CLI verification, and future capability declarations.

## Steps

1. Inventory every probe declaration in config/components/**/*.yaml and code: binary, all-binaries, path, command, provider cli probes. Freeze timeout/detail/boolean semantics.
2. Add Probe protocol `check(context)->ProbeResult` and `ProbeResult(available, detail, error_code, duration)` in foundation/toolchains/probes or foundation/probes if boundary analysis favors a neutral home. Use MA11 StepResult only for execution internals, not as public probe result.
3. Add `probe_from_spec(spec)` using registered prefix handlers, supporting only observed binary:, all-binaries:, path:, command:. New prefix registers handler; no if/elif dispatch.
4. Preserve path `~` expansion, comma/all semantics, safe command parsing, and dependency command timeout 10s. Provider/recipe callers may specify timeout explicitly.
5. Unknown/malformed spec raises registered canonical error. Surfaced command output/detail redacted; exit-code-only probes discard output and remain exempt.
6. Replace dependencies.py private `_resolve_probe_*` functions and recipe/provider duplicate parsing with the registry. YAML unchanged.
7. Evaluate dependency-as-full-recipe only by architecture, not LOC alone: keep dependencies as step plans if no teardown/ownership lifecycle. Do not invent recipe lifecycle.
8. Delete private resolvers/duplicate probe parsers with whole-repo grep; update docs.

## Files

[FOUNDATION] toolchains/probes.py or foundation/probes package + error resolutions
[CONSUMERS] foundation/components/dependencies.py; recipe/provider probe builders where equivalent
[CONFIG] component YAML read-only
[TEST] prefix registry/parser/parity/timeout/redaction/dependency plan tests

## Validation

1. One test per observed prefix plus malformed/unknown/timeout/missing cases.
2. Dependency planned commands and bootstrap behavior byte/semantically equal to baseline.
3. Command secret canary redacted only when detail surfaced; exit-code-only result has no captured output.
4. Fixture probe kind registers without core edit; duplicate prefix rejected.
5. Old `_resolve_probe_*` and duplicate parsers absent.
6. Full unit zero new failures; real installation tests Docker-only.
