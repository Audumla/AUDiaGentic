# Migrate provider CLI lifecycle to recipe registry

## Description

Replace provider CLI private state-machine/workflow using completed `foundation.steps` and existing provider recipe infrastructure while preserving public API payloads and provider-owned side effects. Provider capability config documents CLI facts but does not define runtime schema or dispatch.

## Steps

1. Snapshot provider CLI plan/install/uninstall/repair results and actual consumers.
2. Keep provider CLI authoring in provider config using natural CLI fields; normalize only runtime-read fields.
3. Build provider-owned CLI lifecycle from completed `audiagentic.foundation.steps` and existing `components.providers.services.recipes` infrastructure. Add no new recipe abstraction.
4. Preserve probe, Windows PATH settle, timeout+post-probe, and repair semantics.
5. Preserve public result dict through thin adapter; map only consumed statuses.
6. Redact command/stdout/stderr.
7. Rewire install/uninstall/repair/plan/provision-all; retain provider-owned config/surface reconciliation.
8. Remove old state machine/compatibility code after provider config migration; update capability knowledge separately.
9. Preserve operational events only if consumer inventory proves use.
10. Docker-only real install smoke.
