# Complete Hindsight family cutover and delete legacy recipes

## Description

Final MA02/MA20 cutover. Replace matrix/factory/ephemeral-registry orchestration with explicit family status and calls, retain only Memory desired-value builders, then delete the legacy provider recipe registry/types/module and obsolete lifecycle tests when repo-wide use reaches zero.

## Steps

1. Preflight requires MA23-MA26 completed. Run full Memory/provider baseline. Inventory all remaining imports/usages of ProviderRecipeRegistry, ProviderCapabilityRecipe, ProviderRecipeKind, ProviderRecipeResult, LaunchEnvContributionRecipe, matrix.py, strategies.py, recipe_spec.py, lifecycle registry construction, and status registry calls.
2. Freeze Memory orchestration without provider-id branches. For each enabled provider, query family status in fixed order: provider-integration, provider-plugin, managed-mcp. Select first supported family; if none, return guidance from provider resource/status evidence. A platform/version unsupported provider-integration may fall through to managed-mcp. Do not add a universal provider reconcile/gateway or expose recipe definitions.
3. Rewrite reconcile_hindsight/build_hindsight_status_report to call only providers_api family functions. Preserve external summary shape currently consumed: top-level action; providers[id].success/state/role/error; configured/providers status report. Map family-specific results locally in Memory; do not create universal result type.
4. Move retained backend builders/desired values only: HindsightBackendConfig, build_hindsight_entry/build_hindsight_mcp_entry, endpoint/auth/bank data, and stable ownership scope. Move mechanism evidence/guidance to MA19 facts where applicable. Remove provider discovery internal import by using providers_api query.
5. Delete Memory matrix/factory layer when unused: config/components/memory/hindsight_matrix.yaml, matrix.py, strategies.py, recipe_spec.py, register_hindsight_recipes, _reconcile legacy operation strings, legacy status registry path, and migrated recipe modules/classes. Keep no alias, shim, dual route, or compatibility test.
6. Final provider legacy deletion: require rg to show zero production consumers, then delete components/providers/services/recipes.py including ProviderRecipeRegistry, ProviderCapabilityRecipe, ProviderRecipeKind, ProviderRecipeResult, and LaunchEnvContributionRecipe. LaunchEnvContributionRecipe has no production caller today; delete its recipe-only tests. If MO02 needs launch-env behavior, it must use private model-projection/launch_env service mechanics, never retain the legacy recipe class.
7. Delete/rewrite test_provider_recipes.py, test_recipe_lifecycle.py, test_launch_env.py recipe-class cases, Memory recipe/matrix/strategy/stamping/registry tests, and integration tests tied to old construction. Preserve behavior coverage at providers_api family and Memory orchestration boundaries.
8. Preserve foundation/toolchains/recipe_contract.py unless a separate repo-wide audit proves it has no nonlegacy consumers; MA27 does not broaden into foundation cleanup.
9. Add hard stale guards: no production import of providers.services.recipes; no legacy symbols; no hindsight_matrix; no recipe-kind/factory dispatch; providers_api exports no recipe types; config/facts cannot dispatch; every retained automation registration validates through MA20.
10. Run ruff; unit providers; unit memory; focused integration memory/provider-file tests; architecture boundaries; package-structure tests; and stale searches. Record exact commands/results. Mark MA27 complete only after deletions and parity; then MA02/MA20 remain pending until owner closure review confirms all other automation families use MA20.
