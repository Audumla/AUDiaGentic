# Lock provider public API families and semantic modes

## Description

Authoritative provider-boundary umbrella. All provider automation implementations conform to one internal declarative RecipeDefinition schema and private recipe lifecycle. Public callers use family-specific providers_api functions, payloads, and results with supported modes from plan|apply|prune|status. Resource APIs and agent execution are excluded from recipes.

## Steps

1. Maintain a named export classification in Notes; category changes require review. Never gate on a historical count.
2. MA31 keeps queries mutation-free and catalog refresh explicit.
3. MO02 separates model-source resources from model projection and deletes legacy model automation exports.
4. Freeze family-specific signatures from callers; no universal public request/result.
5. MA20 owns internal RecipeDefinition and explicit Pattern A registration.
6. Keep mechanics private; resources and MA17 execution cannot register recipes.
7. Execute migrations through MA12, MA21, MA23-MA30, and MO02; migrate callers and delete old routes atomically.
8. MA22 removes reconcile after required families land.
9. Explicit registration enables Pattern A; descriptor-declared generic mechanics enable Pattern B only through typed public APIs.
10. Close after downstream items pass MA09.

## Validation

1. Every providers_api export has a named category and target disposition. 2. Cross-component imports resolve only through exported names. 3. Queries do not mutate. 4. Resources use CRUD/refresh semantics. 5. Automation uses typed family operations. 6. Reconcile exports are deleted. 7. Execution remains separate. 8. No universal public request/result, public recipe type, alias, shim, or compatibility route. 9. Strict layering and foundation agnosticism pass.

## Effort & Risk

High-impact migration. Freeze one family signature from caller evidence, migrate every caller of that family atomically, validate, then delete its old route. Do not batch unrelated families or invent fields for future callers.
