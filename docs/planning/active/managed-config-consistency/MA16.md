# Lock provider public API families and semantic modes

## Description

Authoritative provider-boundary umbrella. All provider automation implementations conform to one internal declarative RecipeDefinition schema and private recipe lifecycle. Public callers use family-specific providers_api functions, payloads, and results with supported modes from plan|apply|prune|status. Resource APIs and agent execution are excluded from recipes.

## Steps

1. Use the frozen 22-export classification in Notes; category changes require a new MA16 review.
2. MA31 makes six queries mutation-free and keeps two catalog refresh functions as explicit resource commands.
3. MO02 splits four model-source resource commands from model projection and migrates three model automation exports.
4. Freeze every family-specific signature from current callers. No universal public request/result or closed family taxonomy.
5. MA20 implements one provider-owned RecipeDefinition schema, typed loader, mode adapter, provider+family registration identity, and duplicate failure.
6. Keep recipe mechanics private; resources and MA17 execution cannot register recipes.
7. Execute automation migrations through MA12, MA21, MA23-MA30, and MO02; migrate all callers and delete old routes atomically.
8. MA22 removes both public reconcile wrappers after required families land.
9. Explicit registration alone enables automation; declarations and facts cannot execute.
10. Close after MA20-MA31 and dependent umbrellas pass MA09.
