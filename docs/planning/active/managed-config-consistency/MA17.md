# Standardize allowed component integration ports and events

## Description

Document and enforce honest component dependency direction. Provider operations use providers-owned public semantic modes (`plan|apply|prune|status`) through `providers_api`; family-specific payloads remain allowed, recipe methods remain private. Approved requesters depend only on that public API; providers remain requester-domain blind. Agent execution is separate and derived from actual call sites, never capability catalog data.

## Steps

0. INPUT GATE: MA16 establishes semantic providers_api operation surface; MA18 supplies proven execution/event requirements.
1. Generate import/resolved-binding graph and classify allowed providers_api operation/execution calls, explicit composition bindings, events, data consumption, and forbidden internal/reverse dependencies.
2. Inventory agents_gateway_dispatch imports and tests. Preserve agents ownership of profile selection, retry/fallback decision, cancellation, packet correlation, and timeline persistence.
3. Add narrow providers_api execution-invocation entry. It receives project root, provider id, agent-selected model id/alias, and existing provider-neutral packet data; inside providers it checks enablement, loads provider config, resolves model selection, and calls adapter execution. It returns existing normalized result/errors. Do not create foundation port, transport taxonomy, or catalog selection.
4. Rewire `_dispatch_one_attempt` to the public execution entry; delete imports of providers.services.execution/models/provider_config. Repoint monkeypatches to providers_api execution seam and preserve retry/fallback tests.
5. Implement/use providers-owned public operation adapters/functions for non-execution callers. Each exposes only caller modes `plan|apply|prune|status`; payload remains operation-family-specific and minimal.
6. Keep recipe mechanics private. Providers map modes to mechanics/MO06 reconciliation; no caller selects those methods.
7. Pin plan/status non-mutation, idempotent apply where supported, and scoped prune ownership. Surface collision/reload/changed outcomes only when caller consumes them.
8. Compose OpenCode ACP/CLI execution adapters explicitly inside providers; no catalog selection. Keep profiles/retry/queue in agents.
9. Project redacted bounded events into existing timeline and cursor/progress sequence; execution entry cannot write agent timeline directly.
10. Tests: public imports; forbidden internals/reverse imports; execution input/result goldens; retry/fallback/cancel event parity; explicit registration; catalog non-authority; semantic mode guarantees.
11. Revise reference docs and generated architecture guards.

## Files

[COMPONENT:providers public] execution invocation function plus semantic operation functions
[COMPONENT:providers internal] provider config/model resolution/execution adapters/registrations
[COMPONENT:agents] profile resolution, packet construction, retry/fallback/cancel/timeline only
[TEST] execution seam goldens, monkeypatch migration, import graph, events
[FORBIDDEN] agents imports of providers.services, foundation capability ports, catalog dispatch, public recipe methods

## Validation

1. agents_gateway_dispatch imports no providers.services module. 2. Provider execution public entry has no agents-domain/profile/timeline imports. 3. Existing packet/result/error/retry/fallback/cancel behavior is golden-tested. 4. Provider-operation callers use only providers public API and only plan/apply/prune/status semantic modes. 5. Family payloads stay minimal. 6. Recipe mechanics do not cross public boundary. 7. Explicit registration enables behavior; config cannot. 8. One ordered redacted event store.

## Effort & Risk

Mid. Do not remove provider integration merely for graph purity. Refactor only foreign-domain leakage and event coupling; preserve provider-specific adaptation where it is real.
