# Standardize allowed component integration ports and events

## Description

Document and enforce honest component dependency direction. Provider capability operations use a narrow providers-owned public gateway; approved requester components may depend on that public API, never provider internals. Providers remain requester-domain blind. Agent execution stays separate and uses the smallest boundary proven by agents/providers call sites; no capability catalog abstraction is used to hide dependencies. Preserve generic event delivery and explicit composition.

## Steps

0. INPUT GATE: MA16 deletes foundation capability package and establishes providers public capability API. Read MA18 proven execution/event requirements. Reopen prior generic foundation-port assumptions.
1. Generate import and resolved-binding graph. Classify approved providers public API dependency, explicit composition binding, event, data consumption, or forbidden internal/reverse dependency.
2. Audit registries and service locators. No dotpath/catalog loading. Explicit composition owns provider handler registration.
3. Implement/use providers-owned capability gateway: current requesters call narrow public API; gateway resolves explicit provider handlers and returns provider-owned neutral-enough result. No foundation capability types.
4. Keep agent execution distinct. Derive boundary from agents caller and providers implementations. Prefer consumer-owned protocol or existing public providers execution API; do not invent foundation/ports merely to avoid explicit dependency.
5. Provider execution adapters choose implemented concrete transports. Shared orchestration checks only current caller requirements.
6. Connect OpenCode ACP/CLI through explicit providers composition; no catalog selection.
7. Connect agents gateway through approved execution boundary; preserve profiles/retry/queue.
8. Project redacted bounded events into existing timeline.
9. Expose cursor/progress from same sequence.
10. Provider config/LSP/job mechanics remain behind providers public capability gateway; requesters never import internals.
11. Release→ledger uses typed event only if BU permits.
12. Tests: allowed public imports, forbidden internals/reverse imports, explicit handler resolution, catalog non-authority, execution boundary, events/cursor/cancel/fallback.
13. Revise reference docs and remove false-neutral foundation capability language.

## Validation

1. Foundation contains no capability package/type/protocol. 2. Provider capability callers use only providers public API. 3. Dependency graph documents each allowed requester→providers edge. 4. Providers have zero reverse requester-domain imports/branches. 5. Explicit registration enables handlers; config cannot. 6. Agent execution boundary contains only current requirements and remains separate. 7. No dotpath/service-locator hiding. 8. One ordered redacted event store.

## Effort & Risk

Mid. Do not remove provider integration merely for graph purity. Refactor only foreign-domain leakage and event coupling; preserve provider-specific adaptation where it is real.

## Standards

- arch-standards — explicit typed boundaries; registry edges remain visible; config-driven selection; no service locator; foundation neutrality.
- component-creation — provider mechanics/bindings provider-owned; agents orchestrate only.
- observability-standards — one ordered redacted timeline; bounded cursor/progress projections.
