# Add packaged startup and public CLI smoke suite

## Description

Prove AUDiaGentic can be imported, started, and exercised through its installed public `audiagentic` console entry point. Run real subprocess/package/startup/load cases inside disposable Docker because launcher bootstrap, package installation, home discovery, logging, and component commands may mutate environment. Host lane contains only mocked, non-mutating parser/dispatch units.

## Steps

1. Inventory public launcher contract from `pyproject.toml` and `audiagentic.launcher`; classify each test as pure unit or environment-mutating integration. Default uncertain cases to Docker.
2. Extend existing `tests/docker/Dockerfile.packaging` clean-room image and runner rather than create parallel packaging machinery. Set disposable HOME, `AUDIAGENTIC_HOME`, project root, config/cache roots, locale/encoding, and provider environment. Never mount host home/config; use ephemeral container/filesystems.
3. Add shared subprocess CLI fixture inside Docker. Capture command, rc, stdout, stderr, timeout diagnostics, and before/after filesystem snapshots. Do not add checkout `PYTHONPATH` to installed-package assertions.
4. Add clean-container import smoke: `python -c "import audiagentic; import audiagentic.launcher"`; assert rc 0 and no unexpected import-time mutation/provider launch.
5. Build wheel, install into isolated environment inside packaging image, invoke generated `audiagentic --help`; assert console-script metadata resolves and package import graph loads outside source checkout.
6. Run installed `audiagentic --project <empty-temp-project> component list`; assert rc 0, valid JSON/component rows, foundational descriptors/package data load, and no repository cwd/PYTHONPATH dependency.
7. Add Docker negative cases: unknown option/command and missing required subcommand arguments return defined argparse failure with actionable stderr and no traceback. Add one handled `AudiaGenticError` path asserting rc 1 and stable error channel.
8. Add selected Docker lifecycle CLI checks only where needed to prove load/dispatch. Mark `mutates_host`; verify every write stays within container temp HOME/project and container is disposable. Reuse existing component CLI tests where they already cover behavior; no duplicate matrix.
9. Keep host tests limited to `_main` parser/dispatch units with filesystem, logging, provider launch, and handlers mocked. No real console script, install, component apply, global home, or subprocess startup on host.
10. Register packaging/startup smoke in `tests/run_all.py` and CI packaging image. Document local Docker command, expected image cleanup, and link suite from MA09.

## Validation

1. No real startup/package/CLI lifecycle test runs on host; mutation-capable tests carry `mutates_host`/Docker gating.
2. Packaging Docker image builds wheel and installs it without network or checkout `PYTHONPATH` dependence.
3. Clean-container import and installed `audiagentic --help` succeed.
4. Installed `audiagentic --project <temp> component list` loads package descriptors and returns valid JSON.
5. Negative invocations return specified nonzero codes, useful stderr, and no traceback.
6. Filesystem snapshot proves writes remain inside disposable container HOME/project; no host home/config mounts.
7. `tests/run_all.py` and CI packaging job execute suite; supported Windows development invokes same Docker recipe.
8. Host mocked unit lane remains green and performs no external/provider/filesystem mutation.

## Effort & Risk

Mid. Docker startup adds build time but matches existing clean-room packaging convention. Reuse `Dockerfile.packaging`; avoid duplicate images. Container must build/install local artifact without network and never bind-mount host home/config.
