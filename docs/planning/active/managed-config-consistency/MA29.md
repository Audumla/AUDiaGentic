# Consolidate LSP MCP projection into managed MCP

## Description

Replace duplicate lsp-mcp-projection family with canonical descriptor-backed managed-mcp operation. Coding-LSP supplies typed MCP entries plus stable ownership_scope; providers retain path, merge, collision, reload, and prune mechanics.

## Steps

1. Characterize current LSP caller result fields and ownership behavior against managed-MCP result.
2. Map Coding-LSP entries to ManagedMcpEntry/ManagedMcpRequest with stable scope (for example coding-lsp/ag-lsp); keep disabled-provider prune semantics in provider-owned fan-out.
3. Add or reuse one managed-MCP all-provider fan-out without exposing descriptor/enablement internals to Coding-LSP.
4. Migrate callers and tests to manage_mcp_entries canonical contract.
5. Delete LspMcpProjectionEntry/Request/Result/BatchResult, schemas, service module, providers_api routes, 13 lsp-mcp-projection descriptor declarations, and CON-PLMC duplicate namespace.
6. Validate apply/status/prune, enabled/disabled fan-out, ownership collision, unmanaged preservation, import boundaries, and stale symbols.

## Files

[CODING-LSP] one named caller family
[PROVIDERS] one family definition/registration/adapter
[TEST] caller parity, ownership, import and stale-route guards

## Validation

One managed-MCP family owns MCP-entry projection. Coding-LSP imports providers_api only. Stable scope preserves scoped prune and collision behavior. No lsp-mcp-projection contracts, schemas, routes, service, descriptor declarations, or compatibility aliases remain. Focused suites and both directory orders pass.

## Effort & Risk

Bounded MA08 slice suitable for a strong mid-level agent after architecture owner freezes payload/result.

- Architecture Guidelines: Provider Platform API; Writing External Artifacts; Migration Validation.
