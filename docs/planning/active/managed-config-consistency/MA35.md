# Add prompt-delivery: stdin to the launch recipe so Pi one-shot can retire adapter.py

## Description

Reduced scope (HA04 delivered the rest). The declarative recipe system is fully in place: base_runner's build_launch_spec vocabulary (HA04) builds a ProviderLaunch from an execution: recipe, and the dead qwen/copilot adapter.py duplicates are already deleted (HA04, byte-identical to their recipes; tests rewritten to the recipe path).

The ONE remaining piece: Pi's execute (one-shot) path still uses a hand-written adapters/pi/adapter.py because Pi's --print mode drops embedded newlines when the prompt is a CLI argument (SH21); the real fix pipes the prompt via stdin (run_streaming_command input_text=). Pi's execution: recipe puts {prompt} in args-template, which would reintroduce SH21 if adapter.py were removed. Add a prompt-delivery: argv | stdin option to the build_launch_spec / make_cli_runner path (default argv, preserving every other provider) so Pi can declare prompt-delivery: stdin and retire adapter.py.

## Steps
