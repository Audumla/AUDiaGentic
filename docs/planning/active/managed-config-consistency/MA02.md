# Delegate memory integration intent to provider capability gateway

## Description

Move memory integration intent through providers-owned public capability gateway. Memory explicitly depends on narrow providers public API for provider operations, while importing no provider adapters, serializers, config loaders, matrices, or internal services. Providers own mechanics and remain unaware of Hindsight/memory.

## Steps

1. Freeze current provider effects/mechanisms/gates/fallback/artifacts.
2. Use smallest providers-owned request/result fields required by memory call sites; do not create foundation types or future taxonomy.
3. Call providers public capability gateway; it resolves explicit registered handler. No catalog lookup/dotpath.
4. Use stable provider-owned capability ids required by current routing; payload validation stays handler-owned.
5. Provider handlers own paths/serializers/reload/adoption/mutations and receive no requester-domain identity.
6. Move Hindsight desired values into memory intent config; provider knowledge config separately documents provider facts.
7. Permit import of providers public capability API only. Forbid provider internals and reverse providers→memory imports.
8. Move custom mechanics behind provider handlers.
9. Remove old matrix dispatch after parity.
10. Test allowed public edge, forbidden internals/reverse edge, explicit registration, lifecycle, and catalog non-authority.

## Files

[COMPONENT:providers public] capability request/result/gateway API
[COMPONENT:providers internal] explicit handlers/adapters/registrations
[COMPONENT:memory] Hindsight intent config and calls to providers public API only
[CONFIG:memory] desired provider-operation requests
[CONFIG:providers] capability knowledge/evidence, not dispatch
[TEST] parity, public-boundary imports, reverse-domain guards

## Validation

1. Behavior parity. 2. Memory imports only providers public capability API; no internals/paths/serializers/matrix. 3. Providers have zero memory/Hindsight imports/branches. 4. Explicit registration only. 5. Request/result fields have current consumers. 6. Lifecycle ownership safe. 7. Provider docs change without gateway code change. 8. Secrets redacted.

## Effort & Risk

Complex boundary migration. Preserve behavior with frozen per-provider table and migrate one recipe kind at a time: guidance/MCP, plugin, then hooks/custom.

## Standards

- Architecture Standards §1 component ownership, §2 config-over-code, §3 reuse, §16 generic orchestration/custom adapters.
- component-creation provider rendering/matrix boundary.
- observability/redaction for neutral refresh event.
