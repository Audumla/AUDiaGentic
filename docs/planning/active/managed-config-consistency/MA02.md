# Move Hindsight integration to memory-owned capability contributions

## Description

Remove provider ids, provider config paths, recipe selection, and provider-service imports from memory/Hindsight generic strategy code while preserving strict component ownership: memory owns Hindsight integration declarations and neutral lifecycle events; providers supplies only capability-neutral execution/registration infrastructure. Providers must contain no `hindsight` vocabulary, declarations, imports, observer, or policy.

## Steps

1. Characterize current matrix resolution for every provider: selected recipe kind, source gate, platform gate, fallback, action_needed, and artifact list. Freeze as parameterized behavior table before moving ownership.
2. Add a neutral foundation/component contribution contract with no memory/provider/capability vocabulary: contribution id, implementation ref, constraints, config/artifact metadata, and optional adapter ref. The registry accepts any contributing component; it never imports or enumerates contributors.
3. Move rows from `config/components/memory/hindsight_matrix.yaml` into memory-owned declarations under the memory component. Use a component-private capability contribution directory/schema if descriptor overlay needs it. `hindsight` remains exclusively in memory files/config.
4. Memory registers its contribution through the neutral registry at component composition/activation. Registry validates unknown kind/ref with canonical config error, dispatches generic recipe kind/adapter ref, and has zero Hindsight-specific symbols or provider-name branches.
5. Memory/Hindsight retains backend config, integration declarations, and narrow neutral export containing base_url, bank_id, transport, and secret reference—not resolved secret. It emits a neutral refresh event when its state changes.
6. A composition-root event bridge invokes registered contributions without importing memory internals or naming Hindsight. Providers may consume generic execution requests only; provider core never imports memory and memory never imports provider descriptors/services.
7. Keep Codex/Pi/plugin custom recipe classes in memory-owned adapter contribution packages, or relocate them to a neutral integration package owned by memory. Provider facts are passed as generic descriptor/context input; no provider package owns memory implementation.
8. Remove HINDSIGHT_RECIPE_MATRIX and strategy provider dispatch after parity tests. Whole-repo grep provider ids/matrix paths/imports from generic memory modules; whole-repo grep `hindsight` from providers/foundation execution modules.
9. Strengthen architecture tests: providers contains no memory-library/capability names or imports; non-provider components cannot contain provider-id matrices, provider config paths, or provider-service imports; new integrations register declaratively through the neutral contribution contract.

## Files

[FOUNDATION/GENERIC CONTRACT] capability-neutral contribution registry/contract with no memory/provider vocabulary
[COMPONENT:memory] Hindsight declarations, neutral export/event, and memory-owned adapter contributions
[COMPONENT:providers] generic provider descriptor/context input and capability-neutral execution only
[CONFIG:memory] memory-owned integration contribution declarations
[TEST] parameterized recipe parity + bidirectional architecture boundaries

## Validation

1. Pre/post table identical for every shipped provider: recipe kind, gates, fallback, status/action_needed.
2. Adding a fixture memory library/integration requires its own config and optional adapter ref only; no providers/foundation generic Python edit.
3. `components/providers/` has zero `hindsight` strings, imports, config paths, declarations, tests, or capability branches.
4. Memory generic core has zero provider ids, provider paths, provider-service imports, or provider recipe matrices; only memory-owned integration adapter boundary may receive opaque provider descriptor/context input.
5. Foundation contribution/recipe/step modules have zero Hindsight/provider/MCP/LSP/model/plugin vocabulary or component imports.
6. Refresh event contains no resolved key/token; redaction canary absent from event/log/result.
7. Missing/invalid contribution adapter ref fails at descriptor load with registered canonical error.
8. Existing provider recipe and Hindsight tests pass; known Pi source-gate failure corrected from moved authoritative data.

## Effort & Risk

Complex boundary migration. Preserve behavior with frozen per-provider table and migrate one recipe kind at a time: guidance/MCP, plugin, then hooks/custom.
