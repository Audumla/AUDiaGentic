# Migrate Hindsight provider plugin automation

## Description

Migrate Claude/OpenCode plugin paths to frozen Hindsight-owned plugin recipe definitions. Hindsight owns plugin package identity, endpoint/auth values, repair decisions, and lifecycle semantics. Providers remain Hindsight-blind and expose only generic config/plugin storage capabilities where a provider-owned format must be read or written.

## Steps

1. Preflight plugin suites; capture Claude/OpenCode apply, status, prune, collision, and repair/restoration behavior.\n2. Define frozen Hindsight plugin definition/desired/result objects and concrete JSON schemas. Parse Hindsight config once; no Any or nested dict execution payload.\n3. Keep Hindsight-specific package names, plugin URLs, commands, Windows repair decisions, source gates, and redaction in Hindsight.\n4. Where Claude/OpenCode config formats require mutation, invoke only generic provider config capability APIs; providers never receive Hindsight identity or recipe semantics.\n5. Preserve unmanaged plugins, exact adoption, scoped removal, repair backup/restore, non-mutating status, idempotence, and secret redaction.\n6. Replace production PluginConfigRecipe/_PluginUrlConfigRecipe/_PluginArrayRecipe paths after parity; defer generic provider-config adapter cleanup to MA27 only if still shared.\n7. Add typed parsing/schema, repair success/failure, ownership, collision, and provider-blind boundary tests; then remove obsolete compatibility tests.

## Files

[MEMORY] typed Hindsight plugin definitions/recipes and orchestration\n[SCHEMA] Hindsight plugin definition/request/result schemas\n[PROVIDERS] generic config capability APIs/adapters only; no Hindsight handler, registration, command, or identity\n[TEST] plugin lifecycle, repair/restoration, ownership, redaction, provider-blind boundary

## Validation

DONE when Claude/OpenCode production plugins use frozen Hindsight recipe objects; serialized schemas validate; providers have no Hindsight imports/registrations/commands; generic provider config mechanics preserve existing ownership/collision behavior; repair/restoration and redaction pass; focused/full suites green.

## Effort & Risk

Complex Windows repair and ownership work. Stop if a provider-specific config writer cannot be used through a generic capability boundary, or repair ownership is ambiguous. Do not solve by moving Hindsight behavior into providers.

## Standards

- Architecture Standards: Dependency Boundaries; Approved cross-component APIs; Ownership and Abstraction; Enforcement.
- Architecture Guidelines: Provider Platform API; Writing External Artifacts; Migration Validation.
