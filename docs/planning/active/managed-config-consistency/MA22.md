# Remove universal provider reconcile API

## Description

Replace public reconcile_provider/reconcile_all_providers with explicit composition of completed provider automation families. Migrate providers MCP and other callers atomically; retain no universal gateway, alias, or compatibility route.

## Steps

1. Record current caller fact: providers_mcp.py is the sole production caller of providers_api.reconcile_provider and reconcile_all_providers; tests are validation callers. Inventory separate direct callers of internal lifecycle/reconcile services.
2. Freeze current sequencing and partial-failure outcomes across catalog resource refresh, CLI, model, MCP, surface, and status.
3. Map every action to MA31 resource command or MA16 automation family. Do not create reconcile recipe/mode.
4. Replace or remove both MCP reconcile tools. MCP exposes explicit resource/family tools and is not an alternate API.
5. Migrate direct internal callers after family items land.
6. Delete both public exports and dead internal orchestration; no alias, shim, fallback, or compatibility test.
7. Add call-order, partial-failure, export, and stale-name tests.

## Files

[CALLERS] providers MCP, commands/runtime/composition callers
[PUBLIC] providers_api export cleanup
[INTERNAL DELETE] services reconcile/lifecycle orchestration when unused
[TEST] sequencing, partial failure, export/stale-name guards

## Validation

1. Sole public-wrapper production caller migrated. 2. Internal callers classified separately. 3. Every action maps to resource command or family. 4. No universal reconcile or reconcile recipe/mode. 5. Old exports/services/aliases absent when dead. 6. Tests pass.
