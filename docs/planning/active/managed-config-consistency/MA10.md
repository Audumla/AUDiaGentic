# Extract declarative recipe engine into foundation

## Description

Promote domain-neutral recipe specification, binding, constraints, factory dispatch, and assembly from Hindsight into discoverable foundation toolchain APIs. MA10 consumes MA16 common declarative capability-operation schema; components own declarations/policy/custom implementations only.

## Steps

1. Characterize memory/hindsight/recipe_spec.py and strategy helpers: RecipeSpec, ParamBinding, StatusOverride, assembly, pattern dispatch, source/platform/Python gates. Mark each field/mechanic generic versus component intent versus provider handler behavior. RESOLVE SL17 HERE (RV368): decide with evidence whether config-driven RecipeSpec assembly earns its keep versus two concrete subclasses — count real declaration variance across current consumers; if variance does not justify the assembler, extract the simpler shape instead and record SL17's disposition. Do not foundationize an abstraction this step fails to justify.
2. Consume MA16 canonical declaration shape and add only domain-neutral recipe types in foundation/toolchains/recipe_spec.py: ParamBinding, MethodOutcomeOverride, RecipeSpec, RecipeConstraints. Do not duplicate MA16 operation/request schema or MA17 gateway/result contract.
3. Add RecipeFactoryRegistry keyed by pattern string using shared Registry lazy-loader. API: register(pattern,factory), build(spec,declaration,context), keys(). Duplicate pattern rejected except explicit composition-root replacement for tests/plugins.
4. Add assemble_recipe resolving declaration fields, validating bindings, evaluating constraints, invoking registered factory, and applying outcome overrides. Unknown pattern/field/ref raises canonical error. It produces MA11 steps or MA16 intent; it never dispatches provider handlers directly.
5. SINGLE PUBLIC ENTRY (RV368): the recipe/step machinery is internal infrastructure with one public entry point (assemble+run seam). Components interact only with declarations and gateway requests; no component constructs RecipeSpec/steps/factories directly outside its own declaration/handler registration. Add an architecture guard for direct step/recipe construction outside foundation/providers composition.
6. Component implementation refs resolve at component/config boundary. Foundation receives callable/factory only; it imports no component module or interprets capability/requester ids. Provider-specific custom execution is registered by providers under MA17 gateway, not from a requester recipe.
7. Move generic no-automation and declared-step assembly to foundation. Keep provider result stamping in providers, backend construction in memory, and gateway transport in MA17.
8. Rewire Hindsight first with parity, then delete moved generic classes/helpers/import paths—no shims. MA02 later moves integration intent to MA16/MA17.
9. Add exports/docs, standards, and guard rejecting duplicate component RecipeSpec/factory registry classes.
