# Adopt managed ownership for provider LSP entries

## Description

Migrate coding-LSP desired state to providers_api using semantic modes `plan|apply|prune|status` and MO06 managed-config core. Coding-LSP imports no provider internals. Providers own mutation/adoption/collision/reload; recipe mechanics remain private.

## Steps

1. Characterize five projection paths and consumed results: language-server apply/prune, generic LSP-MCP apply/prune, and self-provided support.
2. Remove providers-to-coding_lsp types. Coding-LSP supplies serializable mappings and opaque scopes; providers validates its own payloads.
3. Implement MA16 language-server, generic LSP-MCP, and self-provided LSP families with only supported modes.
4. Replace action-string dispatch with explicit provider+family registration where indirection is required. Catalog strings never select behavior.
5. Migrate all coding-LSP callers/tests to providers_api, preserving consumed behavior rather than old signatures.
6. Delegate managed diff, adoption, collision, reload, and scoped prune to MO06.
7. Delete direct/reverse imports, old entry points, action handlers, patch seams, aliases, and compatibility tests after each family migration.

## Files

[COMPONENT:coding_lsp] desired mappings/managed scopes and providers_api calls only
[COMPONENT:providers public] LSP family functions with semantic modes and mapping validation
[COMPONENT:providers internal] lsp projection/config adapters; no coding_lsp imports; no action-string dispatch
[FOUNDATION reuse] MO06 shared managed-config core only
[TEST] five path goldens, adoption/collision/disable/plan-status, public-boundary/reverse-import guards

## Validation

1. No coding_lsp-to-provider-internal or providers-to-coding_lsp import. 2. Five paths retain consumed behavior. 3. Adoption, collision preservation, disabled-first-run, scoped prune, and non-mutation are proven. 4. Only MA16 family modes are exposed. 5. No action-string/catalog dispatch, old alias, or compatibility route remains. 6. Focused tests pass.

## Effort & Risk

Mid. Biggest risk is claiming pre-existing user entries. Exact payload equality and disabled-first-run rule prevent destructive adoption.
