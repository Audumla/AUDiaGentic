# Adopt managed ownership for provider LSP entries

## Description

Migrate provider LSP projection from direct writer/remover calls to MO06 managed-config core with exact-match first-run adoption, collision safety, and stable managed ids.

## Steps

1. Characterize current sync/prune behavior for each LSP-capable provider and capture result shapes, file bytes/structures, enabled/disabled behavior, and failures.
2. Define stable managed id `coding-lsp/language-server/<language-id>` and owner_scope=<provider-id>. Registry instance: `.audiagentic/runtime/providers/managed-language-servers.json`, contract v1, top-level `providers`.
3. Build desired entries as managed_id→(visible language id, LanguageServerEntry). `lsp_projection.py` owns conversion; MO06 core remains Any/domain-neutral.
4. First-run adoption transaction per provider: read current entries; exact visible-name + payload equality adopts registry ownership without rewriting config; absent entry writes desired and owns it; same-name differing payload is collision/user-owned and is not overwritten; unrelated entries ignored.
5. Adoption marker is registry presence for provider scope—no separate flag. Empty desired on first disabled-provider reconcile must not adopt or remove anything.
6. Subsequent enabled sync updates/removes only owned ids. Disabled provider sends empty desired set for coding-lsp managed ids, pruning owned entries only.
7. Rewire sync_language_servers_to_provider_configs and prune_language_servers_from_provider_configs through sync_managed_config/subset. Remove all direct `spec.writer`/`spec.remover` calls and MA08 allowlist.
8. Define result compatibility mapping: top-level ok/synced/skipped/servers/details retained; per-provider detail adds adopted, updated, removed, collisions, config_path. Collision makes provider detail ok=false and aggregate ok=false while other providers continue.
9. refresh_mode remains none for existing LSP specs; no reload behavior invented. Errors use canonical providers/coding-lsp owning codes and log with provider/language context.
10. Update status/describe_provider managed LSP count from registry. Update MA01 inventory/guard and whole-repo direct writer scan.

## Validation

1. Exact existing entries adopt without config byte change; registry records stable ids.
2. Same-name differing entry remains byte-identical and reports collision; no ownership recorded.
3. Disabled first run preserves all entries; disabled after ownership removes owned only.
4. Rename/update/remove and subset isolation preserve unrelated/unmanaged entries.
5. Public aggregate/result keys remain compatible; collision aggregate semantics pinned.
6. Registry corrupt/atomic-failure behavior inherited and tested through LSP caller.
7. Zero direct `.writer`/`.remover` calls outside MO06 core; MA08 temporary allowlist removed.
8. All coding-LSP/provider LSP tests green; full unit zero new failures.

## Effort & Risk

Mid. Biggest risk is claiming pre-existing user entries. Exact payload equality and disabled-first-run rule prevent destructive adoption.
