# Adopt managed ownership for provider LSP entries

## Description

Migrate coding-LSP desired state to providers_api using semantic modes `plan|apply|prune|status` and MO06 managed-config core. Coding-LSP imports no provider internals. Providers own mutation/adoption/collision/reload; recipe mechanics remain private.

## Steps

1. Characterize five current coding-LSP→providers projection paths and response keys: language-server sync, generic LSP-MCP sync, self-provided support, language-server prune, generic-MCP prune. Freeze tests before changing seams.
2. Remove providers→coding_lsp type imports first: providers_api accepts serializable desired-entry mappings and opaque managed ids/scopes; providers normalizes/validates its own internal input. Do not move coding-LSP LanguageServerEntry into foundation or expose it from providers.
3. Add providers_api LSP family functions with semantic operation mode: language-server desired entries map `apply`/`plan`/`status`/`prune`; generic MCP desired entries do same; self-provided support is an `apply`/`status` capability. Keep payloads distinct rather than an action-string handler map.
4. Replace lsp_projection `_ACTION_HANDLERS` string dispatch with explicit internal functions/registration only if a current provider-internal caller needs indirection. Catalog/action strings cannot select behavior.
5. Coding-LSP calls providers_api only; no writer/remover/serializer/internal-service imports. Repoint test monkeypatches from lsp_projection internals to public seam.
6. Provider adapter maps `apply` to managed entry reconciliation and `prune` to scoped owned removal; MO06 owns diff/collision/reload. Preserve disabled-provider behavior.
7. `plan`/`status` are durable-mutation-free. Disabled first run does nothing; later disable prunes owned coding-LSP entries only.
8. Preserve aggregate result keys through thin adapter; add structured collision/reload only after consumer inventory. Delete direct/reverse imports and stale test seams. Keep high-level loops local (RV411).
