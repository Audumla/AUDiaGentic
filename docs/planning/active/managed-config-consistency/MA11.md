# Unify compensating step execution in foundation

## Description

Replace parallel workflow invocation and toolchain provision step systems with one discoverable foundation/steps substrate supporting execution, compensation, planning, declarative construction, and redacted results.

## Steps

1. Capture full behavioral inventory/goldens for workflow invocation steps/runner and toolchains/provision_steps: step types, context substitution, platform overrides, timeout/cwd/progress, sequence/select/conditional/confirm/callable, compensation, declarative factory, result shapes, planned commands.
2. Use new canonical `foundation/steps/` package so workflow and toolchains both depend inward without choosing an arbitrary intra-foundation direction. Define Step protocol: run(context)->StepResult; optional compensate(context)->StepResult; plan(context)->list[list[str]].
3. Define one StepResult and SequenceResult with status, reason, outputs, error, command plan, compensation outcomes. No provider/component vocabulary.
4. Merge shell implementations: runtime context substitution and construction-time parameter binding remain distinct explicit phases; carry platform overrides, timeout, cwd, progress callback, shell mode, compensation command.
5. Redact captured stdout/stderr/command at ShellStep result boundary with canonical redaction authority. Direct streaming remains exempt.
6. Port ConfigSetStep, WriteFileStep, ManagedBlockStep, CallableStep, SequenceStep, SelectStep, ConditionalStep, ConfirmStep. CompensatingSequence becomes SequenceStep policy/mode with reverse successful-step compensation.
7. Move declarative step registry/factory (`register_step_type`, `steps_from_defs`, substitution) into foundation/steps. Lazy registration is explicit/idempotent; no import-side-effect dependency.
8. Rewire recipe_contract, recipe patterns, MA10 recipe engine, toolchains loader, component dependencies, provider descriptor CLI recipes, and tests in bounded slices. Each slice updates imports and runs focused/full baseline.
9. Delete workflow/invocation duplicate step implementations and toolchains/provision_steps package after zero callers. No re-export/deprecation shim. Keep workflow runner public API only if it contains real orchestration beyond steps; otherwise migrate/delete.
10. Register any new error codes before use; split shell execution/planning/substitution if module exceeds cohesion limits.
11. Update foundation docs and Architecture Standards with canonical step package.

## Validation

1. Full pre/post golden parity for every step type and planned command fixture.
2. Shell secret canary absent from StepResult and derived dict/log; streaming behavior unchanged.
3. Reverse compensation exact order; failed compensation reported without masking primary error.
4. Both substitution phases independently tested; literal braces remain literal when not declared placeholders.
5. Declarative registry supports fixture custom step without engine edit; duplicate/unknown type canonical errors.
6. Whole-repo zero old package imports/strings/shims.
7. Foundation/steps contains no component/provider/Hindsight/MCP/LSP/model vocabulary/imports.
8. Full unit suite zero new failures against baseline.

## Effort & Risk

Complex execution substrate. Migrate per consumer slice with goldens; final deletion only after zero imports. New neutral package avoids layering ambiguity.
