# Migrate Hindsight config and artifact ownership

## Description

After MA02 moves provider integration declarations to provider ownership, replace Codex/Pi/plugin direct mutations with ConfigPatcher, WriteFileStep, ArtifactRegistry, and managed-config core while preserving user-home state.

## Steps

1. Freeze golden fixtures for Codex config.toml/features, hooks.json, user config, downloaded scripts; Pi hindsight config with existing user keys; plugin URL/array configs; Windows dynamic repair.
2. Define stable recipe ids per capability/provider and one ArtifactRegistry rooted at project root while supporting absolute user-home artifact paths already supported by registry.
3. Adoption helper: register a whole file only when created in current run or bytes exactly equal canonical expected content; register nested key only when absent then set, or current value exactly equals desired legacy value. Differing pre-existing value is collision/user-owned and must not be overwritten without explicit apply policy.
4. Pi keys use ConfigPatcher for baseUrl, bankId, bankStrategy, host.pi. Register OwnedChange entries. On prune, remove/restore only recorded keys; preserve other host/top-level data. Brace values remain literal.
5. Codex features.codex_hooks uses ConfigPatcher. hooks.json/user config/downloaded scripts use WriteFileStep/download step with registered whole-file ownership. Preserve pre-existing differing files as collisions.
6. Plugin URL whole file uses WriteFileStep/registry. Plugin array named entry uses MO06 managed core with capability-scoped managed id, not direct writer lifecycle.
7. Existing MCP integration remains through generic managed MCP/core and uses stable managed id; no duplicate registry.
8. Windows dynamic plugin .mcp.json repair: characterize ownership. If truly third-party/unowned, retain bounded custom adapter using atomic write, backup-free preservation, redaction, and exact MA01 exemption comment. Otherwise migrate to generic primitive.
9. Dry-run builds planned changes/collisions without registry, network, subprocess, or file mutation. Prune result reports removed/restored/skipped/collisions.
10. Update MA01 audit actions/allowlists after each migration; remove obsolete RS18 exemption comments.

## Validation

1. Golden probe/configure/verify/prune outputs preserved except normalized collision/action fields.
2. Pre-existing differing user values/files remain byte-identical and report collision.
3. Exact legacy generated values adopt and prune safely; new values restore prior state according to OwnedChange contract.
4. Pi/Codex/plugin user config retains unrelated keys/tables.
5. Dry-run changes no file/registry mtime and performs no network/subprocess call.
6. Secret canary absent from registry/results/logs; intentional credential file contains it only at provisioning boundary.
7. Windows repair either passes all exemption tests or is removed.
8. Two recorded Hindsight baseline failures fixed; zero new failures.

Complex user-home adoption. Implement per integration with isolated fixtures; never bulk-adopt based only on filename.
