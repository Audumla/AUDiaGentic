# Validate no regression from removed Pi source patches (OAuth port-bind, update nag)

## Description

Commit e649112d (PI01) deleted runtime/harness/pi/install/patches.py, patches_mcp_progress.py, patches_mcp_register.py -- ad-hoc patches to the Pi npm package's own source, in favor of config-driven resolution (no more third-party harness source patching, by design going forward). Two of the removed patches suppressed real problems rather than just adding cosmetic behavior, and now have no replacement:

1. _patch_mcp_oauth_suppress made pi-mcp-adapter's initializeOAuth() a no-op. Its own docstring recorded a real observed bug: 'On Windows, port 19876 can fall in an excluded/reserved range and the bind fails with EACCES ... producing noisy startup errors.' All AUDiaGentic MCP servers are stdio-based so the OAuth callback server was never actually needed -- but nothing currently suppresses its startup attempt.
2. _patch_update_notification suppressed Pi's own native update-check/notification UI (AUDiaGentic has its own 'audiagentic update' flow). Now gone -- Pi's native update nag may show again, potentially confusing alongside AUDiaGentic's own update prompts.

Also silently downgraded (UX only, not correctness): _patch_mcp_direct_tools_live_register used to make newly-installed MCP servers usable immediately without a session restart; upstream's default 'available after restart' behavior now applies (the existing reload-request.json/footer.ts notification still tells the user to reload, just without the immediate live-register). _patch_mcp_direct_tools_progress used to render the runtime sync/reload hint inline during a tool call; footer.ts's independent ~1.5s poller still catches it, just slightly slower.

Decision (explicit, 2026-07-24): do not re-add source patches. AUDiaGentic will not patch third-party harness source going forward -- if OAuth-suppression or update-nag-suppression is still needed, it must come from Pi's own native config/CLI surface (matching how no_skills/no_prompt_templates/no_context_files already work as real Pi flags), not a regex patch into node_modules.
