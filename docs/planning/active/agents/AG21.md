# Expose enabled component context in agent prompt templates

## Description

Expose enabled component-owned facts to prompt templates through one narrow foundation seam. A component descriptor may declare a context hook; foundation collects, namespaces, sanitizes, and returns an immutable plain mapping. Gateway consumes that mapping at its existing prompt-build boundary. No generic context logic is added to the defunct agent-jobs component, provider adapters, or component implementations outside their own hook.

## Steps

- Add `context_hook: str | None` to ComponentDescriptor and load `context-hook` from descriptor YAML; validate optional explicit `context-namespace` or derive a normalized namespace from component ID.
- Implement `foundation.components.context.collect_component_context(project_root)` as the sole generic collector. It may import descriptor/registry/ref-resolution facilities only.
- Enforce one direction: component hook -> foundation mapping -> gateway packet -> renderer. Foundation does not import gateway/providers/agent_jobs; gateway does not inspect components or resolve hook references; providers receive only the completed packet/rendered prompt.
- Implement three component-local hook functions: project facts, bounded local Git facts from source-control, and public/provider-neutral session facts.
- Extend the closed gateway request-record schema and record builder with a bounded, redacted `template-context` mapping. Capture it once at admission before queuing; retries, recovery, and session dispatch reuse that stored snapshot.
- Update `_build_packet_ctx()` to carry only the record's stored `template-context`. Update `default_build_prompt()` to merge it with its existing scalar context before calling `render_template`.
- Migrate any remaining supported prompt-launch caller from the defunct agent-jobs context module, then remove that legacy module only after its consumers are gone.

## Detailed Solution & Technical Design

The seam is intentionally small. Foundation adds descriptor metadata plus `collect_component_context(Path) -> Mapping[str, Mapping[str, JSONValue]]`; it handles enabled/installed filtering, trusted hook reference resolution, normalized namespace uniqueness, redaction, and bounded JSON-compatible output. Each hook has the narrow signature `(project_root: Path) -> dict[str, Any] | None` and may use only its owning component’s public/read-only APIs. Gateway calls foundation once during admission, persists the result in an explicit `template-context` field on the schema-closed execution record, and dispatch builds its packet only from that frozen field. `default_build_prompt` reads it and calls the existing dotted single-brace `render_template`; no adapter gets component discovery code. Context-hook failures are fail-closed for a declared enabled hook in the MVP, ensuring a template never silently runs with misleading data. The generic foundation code must not import agent_jobs; job/event context is legacy and remains outside this feature.

## Code Samples & Guidance

Descriptor:\n```yaml\ncontext-hook: audiagentic.components.source_control.source_control_api:context\ncontext-namespace: source_control\n```\n\nFoundation API:\n```python\ndef collect_component_context(project_root: Path) -> Mapping[str, Mapping[str, JSONValue]]: ...\n```\n\nGateway handoff:\n```python\npacket_ctx['template-context'] = collect_component_context(project_root)\n```\n\nTemplate:\n```text\nRepository: {source_control.repository}\nBranch: {source_control.branch}\nProject: {project.name}\n```

## Validation

Unit tests must prove: (1) descriptor loader reads hook/namespace; (2) collector filters to enabled/installed components and namespaces exactly once; (3) duplicate namespace, bad hook reference, non-mapping result, unsafe/oversized value fail closed; (4) project/source-control/session hooks return only public bounded facts; (5) schema-valid request records persist `template-context`; (6) `{project.name}`, `{source_control.branch}`, and `{session.model}` render through gateway prompt construction; (7) retry/recovery uses the exact stored snapshot after component/Git state changes. Add architecture/import tests: foundation/components/context.py must not import `components.agents`, `components.providers`, or `components.agent_jobs`; gateway/provider adapter modules must not import component-specific hook modules; no new production imports of agent_jobs.prompt_context are allowed.

## Effort & Risk

Medium. Valid design with a narrow seam. The schema-closed record is the necessary durability boundary; omitting it would create retry drift. Main risk is accidental code bleed between foundation, gateway, and legacy agent_jobs, controlled with explicit import/architecture tests and one collector call site.

## Standards

One-way dependency: component hook -> foundation collector -> gateway packet -> renderer. Descriptor-configured trusted hooks only. Foundation is generic and component-agnostic. Dotted single-brace renderer remains the only renderer. Immutable admission snapshot; no provider-specific or legacy job/event context in foundation.
