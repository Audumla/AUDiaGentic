# Finalize global Agents catalog wire schema and migration

## Description

Own the operational cutover of the machine-global .audiagentic/config/agents.yaml wire contract. Canonical v2 is the target: explicit contract-version, canonical collection keys, strict top-level shape, global-only hosted authority, and an explicit one-time legacy split-file migration seam.

## Steps

1. Enforce the explicit canonical v2 wire schema and reject missing, unknown, obsolete, or unsupported contract versions.\n2. Keep the one-time migration from legacy project split files as an explicit input-only seam; write only the machine-global v2 catalog and prove idempotence.\n3. Keep repository load/save/replace and CAS digest handling on canonical serialization.\n4. Remove gateway-profiles.yaml, project-local agent authority, embedded fallback, and reload operations from production and obsolete integration coverage.\n5. Update management/configuration surfaces and architecture scans so the global catalog is the only hosted authority.

## Detailed Solution & Technical Design

The global agents catalog is the sole runtime authority. AgentsConfigDocument v2 is the only accepted persisted wire format: it requires contract-version v2, permits only the canonical collection keys, and serializes collections deterministically as id-keyed mappings. Missing files are tolerated only by non-hosted management helpers as an in-memory empty v2 document; hosted gateway composition uses a required global catalog and fails closed. Legacy roles.yaml, execution-profiles.yaml, and agent-definitions.yaml are read only by migrate_legacy_config, which writes global agents.yaml and is idempotent. The removed gateway-profiles loader/reload and embedded compatibility path cannot reappear as runtime fallbacks.
