# Run vendor free-tier models as gateway agent profiles across harnesses

## Description

Sponsor direction 2026-07-18: once OpenRouter free models are materialized into harness configs (MO18) with connectivity injected (MO19), make them usable as agents — agent profiles binding a verified harness provider to a free vendor model, dispatchable through the existing gateway (submit/run/sessions) with zero gateway changes expected. This item is profiles + validation, not new execution machinery.

## Steps

1. Define agent profiles in .audiagentic/config/agent-profiles.yaml binding provider=pi (first verified MO19 harness) to one or two OpenRouter free models (e.g. a strong free coder model chosen at implementation time from the live catalog). Use existing profile schema — no schema change unless a real gap appears; if one does, open a review before extending.
2. Verify profile resolution precedence and concurrency defaults behave for a remote free model (rate-limited vendor: set conservative profile max-concurrency; free tiers throttle hard).
3. End-to-end gate: agent_llm_run through the gateway on the free-model profile completes a real prompt; a keep-alive session two-turn retention check (AS07 pattern) if the harness supports sessions on that path.
4. Failure classification: exercise a rate-limit (429) response and confirm the gateway's retry/error classification reports a classified, actionable outcome rather than a generic failure — this is the first provider where 429s are the NORMAL case; file a review on the dispatch retry policy if free-tier throttling is misclassified.
5. As additional harnesses pass MO19's evidence gate, add one profile per harness — each addition is config only.

## Files

[CONFIG] .audiagentic/config/agent-profiles.yaml. [REUSE] gateway submit/run/session paths, profile resolution, MO18/MO19 outputs. [TEST] live/Docker free-model run gate, 429 classification check.

## Validation

1. A gateway run on a free-model profile succeeds end-to-end using only projected config. 2. Rate-limit failures are classified and visible in the record/timeline. 3. No gateway code change was needed (or its necessity is review-documented). 4. Profile concurrency respects free-tier throttling.

## Effort & Risk

Mid, mostly validation. Risk: free-tier instability making the live gate flaky — keep the gate explicit/manual like AS07 rather than wiring it into CI.
