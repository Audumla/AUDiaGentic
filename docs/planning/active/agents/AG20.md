# Collapse gateway profiles into global Agents catalog

## Description

Make the machine-global agents.yaml execution_profiles collection the sole declarative authority for hosted gateway admission. gateway-profiles.yaml must no longer be read, required, or used to resolve provider/model/instance bindings.

## Steps

- Compile an immutable gateway registry from the required machine-global agents.yaml execution_profiles collection.
- Wire hosted gateway composition and reload to the global Agents catalog; missing or malformed global authority fails closed.
- Preserve admission generation/config-digest snapshots and ensure dispatch uses the admitted snapshot.
- Remove gateway-profiles.yaml from hosted configuration and retire its CLI/config path as a declarative input.
- Run focused registry/composition/configuration tests and a local admission/status test without restarting the live gateway.

## Detailed Solution & Technical Design

Add a loader beside the existing registry implementation that reads global_agents_config_path() through AgentsConfigRepository(required=True), validates each execution profile's profile_id, provider_id, non-empty instances, and mapping params, then registers redacted immutable definitions. Hosted composition always invokes this loader and records agents.yaml as the reload source. A missing global catalog or invalid execution_profiles collection is a startup/reload error; there is no embedded fallback in hosted composition. Keep test-only registry injection explicit and separate from production configuration.
