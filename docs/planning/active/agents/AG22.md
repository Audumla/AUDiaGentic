# Inject admitted agent prompts and roles into gateway templates

## Description

Make agent definitions behavioral at gateway admission. Resolve an agent's prompt and roles, render/sanitize them against the frozen template context, persist an immutable instruction snapshot, and expose it to the provider execution template without replacing the caller's required task body.

## Steps

- Resolve ResolvedAgentComposition when agent_id is supplied, rather than only extracting its execution_profile_id.
- Build an agent instruction block from the configured prompt content plus role instructions; render it against the admitted template context and retain source/config digests.
- Add explicit immutable instruction snapshot and identity/digest fields to the schema-closed gateway request record.
- Expose a stable agent namespace to the provider prompt renderer for all requests; direct-profile requests receive an empty instruction block.
- Update global templates to place the agent instruction block before the execution request and prompt body.
- Add admission/retry/adapter tests proving gpt-auto-agent's read-only prompt and roles are sent, direct requests remain unchanged, and post-admission config edits cannot alter an admitted request.

## Detailed Solution & Technical Design

At admission, resolve_global agent composition already supplies the AgentDefinition, PromptDefinition, Roles, ExecutionProfile, and configuration fingerprint. Convert prompt content to text, combine it deterministically with ordered role instructions, and render this instruction template using the same frozen component template-context plus ordinary request fields. Persist the rendered block, its SHA-256 digest, agent-definition digest/fingerprint, prompt ID, and ordered role IDs as request-owned immutable data. The generic provider template receives `{agent.instructions}` for every request: populated for agent-id submission, empty for direct profile submission. Do not concatenate instruction text into `prompt_body`; keep caller task body and control metadata separate. Dispatch reads only the admitted record fields, so retries/recovery cannot reread mutable global agents.yaml.

## Effort & Risk

Medium. The main correctness boundary is immutable admission state: no role/prompt/global-catalog reread is allowed after admission.

## Standards

Agent definitions are behavioral only when their admitted content is frozen. Caller prompt_body remains mandatory and distinct. Component context is rendered through existing dotted templates. No provider-specific assembly and no gateway reads of mutable global agent config during dispatch.
