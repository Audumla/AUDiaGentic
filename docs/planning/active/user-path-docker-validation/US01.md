# Build isolated Docker CLI harness lifecycle matrix

## Description

Exercise AUDiaGentic from the packaged command line as a user in clean mutable containers. Install every supported harness, verify observable installed state and generated artifacts, uninstall it, and prove owned artifacts are removed without damaging unrelated state.

## Steps

1. Inventory documented harness install/uninstall commands and capabilities. 2. Extend reusable Docker scenario helpers. 3. Run every harness lifecycle in clean images and repeat for idempotency. 4. Capture command, exit status, stdout/stderr, filesystem manifest, and ownership-safe removal evidence. 5. Create review findings for reproducible product failures.

## Files

tests/docker; tests/integration; CLI/harness docs discovered during implementation

## Validation

Docker image rebuild from clean context; parametrized install/status/uninstall/reinstall matrix; host checks only for immutable test logic; no mutable host execution.

## Effort & Risk

Keep scenarios data-driven and isolated. Do not duplicate CLI behavior in the tests or assert undocumented implementation details.
