# Persist selective MCP-to-harness bindings through existing reconciliation

## Description

MP03 slice 3. Prevent component install and later refresh from broadcasting MCP entries beyond explicit targets.

## Steps



## Detailed Solution & Technical Design

Extend the existing managed MCP ownership system with an explicit desired-binding model keyed by project scope, canonical MCP ID and provider ID. Distinguish no binding metadata (legacy behavior) from explicit empty selection (no target); define one-time legacy adoption using managed ownership evidence only, never silently claim user entries. Desired bindings represent user intent; existing ownership registry records what was actually written. Reuse provider-owned subset synchronization rather than introducing another writer. Make target selection available before component lifecycle hooks or defer projection until after preflight. Audit install/enable/disable/uninstall, config sync/refresh, startup/materialization and curated launch surface collection so no path expands selection. Installing a component for one server must not auto-expose sibling/management MCPs. Dependencies activate required owner functionality but their MCP exposure remains explicit. Preserve nonselected providers, manually configured entries and propagation/isolation contracts.
