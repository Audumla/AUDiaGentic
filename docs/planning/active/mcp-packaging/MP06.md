# Persist selective MCP-to-harness bindings through existing reconciliation

## Description

MP03 slice 3. Prevent component install and later refresh from broadcasting MCP entries beyond explicit targets.

## Steps

1. Add Project-owned explicit bindings to the authoritative project-config schema and mirror byte-identically only where the existing schema registry requires it.
2. Perform bounded ownership-evidenced migration on first mutation; bootstrap new projects with explicit empty bindings.
3. Replace provider broadcast with Project-owned lifecycle reconciliation through providers_api; migrate every caller and delete obsolete helpers.
4. Wire provider-state changes through an owner-declared event and Project subscriber; preserve internal management and independent LSP ownership.
5. Qualify profile changes, missing migration, lifecycle refresh/restart and sibling exclusion.

## Detailed Solution & Technical Design

One canonical desired-state model lives in Project-owned .audiagentic/config/project.yaml, mcp-onboarding contract-version v1 with bindings keyed by MCP ID and explicit harness ID lists. Missing ID and empty list both select no provider once the section exists; absence of the entire section requires bounded migration, never broadcast fallback. Selection is project-scoped, not another per-profile selector/map: current process get_active_profile() and existing component loader remain authoritative for descriptor overrides. Identical native payload after profile change is no-op; a divergent profile-derived payload for an owned shared native target is surfaced as a conflict requiring explicit owner reconciliation authorization. No implicit replacement and no blanket prohibition on profile changes. Migration uses only demonstrable existing MCP ownership plus native evidence, preserves proven component exposure and refuses ambiguous adoption; read-only help/list never migrates. New bootstrap creates explicit empty bindings. Desired intent is committed under project revision lock BEFORE component installation/hooks; release that lock before synchronous lifecycle hooks to prevent deadlock, then repeat idempotent guarded reconciliation. No cross-resource lock held over arbitrary lifecycle callbacks.

Project public onboarding API owns normalization, selection and reconciliation. Project calls only approved providers_api with data requests; Providers never imports Project or receives project callbacks. Project-owned lifecycle subscriber handles component install/enable/disable/uninstall and owner-declared provider-state-changed events; composition root wires startup reconciliation directly without a fake single-implementation binding or service-locator registry. Providers exposes native preflight/apply/recover; it does not read Project configuration or construct desired project policy. Replace provider observer MCP broadcast and migrate callers in providers/services/reconcile.py, commands/bootstrap.py and provider global MCP sync. Delete obsolete broadcast helpers/routes after caller audit; do not retain legacy-frozen or permissive absent-metadata mode. Generic provider-owned non-MCP reconciliation continues normally.

Internal propagate:audiagentic management collection remains a separate internal projection with its existing authority; targeted native registration must not hide AUDiaGentic management tools. Coding LSP retains independent ownership and owner policy; shared native collision protection applies, but onboarding must not adopt or erase its entries. Selecting one MCP never enables sibling/management MCP exposure. Component dependencies activate functionality only; dependency MCP exposure remains explicit. Project-only native targets required; canonical path/native section identity fences aliases, shared files and unsupported global locations.

Profile authorization is an operation rule, not a new selector or CLI flag: background lifecycle/refresh may not replace a proven owned payload merely because process-profile resolution changed. An explicit install request using the already selected process profile is the authorization to reconcile that profile-derived change, after preflight verifies unchanged owned native evidence and exposes the proposed change in dry-run. Foreign edits or ambiguous ownership still block both paths. Do not require an unimplemented profile-switch command for normal explicit installation.

MP10 specifies install selection semantics: the supplied nonempty harness list is the complete desired target set for that MCP, preserving all other MCP bindings. Previously selected omitted targets are affected removals and must preflight too; never-selected targets remain untouched. Build a full-scope provider request from ALL remaining desired component MCP entries at that native target, not only the MCP in this command, so replacement cannot erase unrelated MCPs. Preserve independent LSP/memory ownership and instruction contribution visibility; the one new instruction block does not grant MCP exposure.
