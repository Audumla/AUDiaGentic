# Expose descriptor-driven MCP and harness catalogs through public APIs

## Description

MP03 slice 1. Add typed read-only catalog APIs without constructing launch sessions or importing adapter implementations.

## Steps

1. Extract metadata parsing from registration without changing canonical profile overlay resolution.
2. Add owner public catalog/item-help queries returning stable typed declaration facts.
3. Validate unique MCP identity and installation eligibility behind the owner API.
4. Exercise purity from an installed executable outside a project.

## Detailed Solution & Technical Design

Present trigger: list canonical MCP IDs and harness targets and explain setup without starting chat. Refactor foundation/components/loader.py descriptor parsing away from register_from_yaml lifecycle registration. Provider static metadata loading must not call resolve_ref, adapters.load_providers, launch preparation or probes. Project-owned catalog DTOs contain MCP ID, owning component, managed ID, description, propagation eligibility and declared requirements; provider-owned target DTOs contain provider ID, durable project registration capability, transports, refresh semantics and limitations. Protocol adapters receive owner help projections; do not introduce a foundation HelpDescriptor framework or duplicate metadata registry. Existing component and provider YAML remain entity authorities. Internal management servers remain discoverable but explicitly ineligible for provider installation. Runtime installed/configured/reachable state is an explicit separate query, never implied by static declaration support. Use canonical MCP declaration name; no speculative alias layer. Existing component aliases do not automatically become MCP aliases. Reject reserved management MCP names and duplicate public/managed identities before mutation.
