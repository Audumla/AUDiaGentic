## Detailed Solution & Technical Design

Qualification must prove both containment and user-visible functionality. Architecture gates reject CLI imports of stores/services/provider internals, provider imports of requester project modules, and foundation imports of components or onboarding policy; dynamic registry/resolve_ref dependency edges count too. Use existing foundation/toolchains architecture and protocol-adapter suites, extending coverage for new files. Build/install actual application wheel in fresh venv, invoke installed executable outside checkout, verify imports originate in installed site-packages and generated server argv uses absolute interpreter paths. Use disposable HOME/XDG/project/native configs only. Perform real MCP initialize/tools/list and planning CRUD plus ledger record/query on isolated data. Validate two native formats (JSON/TOML), unsupported provider surfaces, strict no-op bytes, preserved unrelated logical content on actual TOML mutation, all refresh/lifecycle paths, profile collision handling and crash recovery. Real native client recognition is separate proof: absent optional binary is unavailable/skipped, never verified. Windows and Linux lock/path-with-spaces/process-cleanup checks are required. Document minimal migration, explicit external compatibility obligations, owner scopes, partial results, no implicit binary/auth/network operations and configured versus verified states. MP02 slim/co-installable packaging remains independently pending.

MP10 is part of installed-package acceptance: assert package asset closure, source-to-wire descriptions/signatures, structured response client compatibility, managed instruction regeneration/no duplicates/user-content preservation, native-fragment identity/removal/refresh and updated docs in the same qualification. Reference metadata and packaging must not be validated only from checkout.
