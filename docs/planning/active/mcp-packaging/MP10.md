## Description

Inventory source-to-consumer mappings, preserve unrelated scopes, and coordinate implementation slices MP04-MP09. Planning only; no generated agent file or runtime configuration edits.

1. Freeze an explicit surface inventory: owner source -> public API/tool -> installed metadata -> generated asset -> acceptance test. Review with Dev GPT before implementation.

### Public MCP contract — three additions only

Keep ag-project-mgmt internal (propagate:audiagentic) and preserve its existing 19 tool names. Add exactly:
- list_mcp_catalog(mcp_id: str | None = None): compact declared catalog when omitted; owner metadata/help and eligible target capabilities for one canonical MCP when supplied. Pure metadata, no installed/reachable inference.
- install_mcp(mcp_id: str, harness_ids: list[str], dry_run: bool = False): explicit targeted configuration; dry-run is preflight, repeat is journal-aware safe recovery. MCP never prompts, uses server-scoped project and the one active process profile. Missing owner config returns key names and action_needed; no secret input or implicit CLI config-file parameter.
- get_mcp_install_status(operation_id: str | None = None): one requested operation or latest unresolved operation; bounded read-only receipt/recovery guidance, no retry/probe/history dump. When none exists return explicit no-unresolved state, not a fabricated successful operation.

No new preflight/recover/verify/list-harness MCP tools or CLI verbs. Harness queries stay behind providers_api for CLI/catalog composition. No new Providers MCP tool and no low-level managed-fragment tool exposed to agents. Existing owner configuration APIs/lifecycle remain authoritative. MP07 owns the installation receipt/status implementation; MP10 owns its adapter/signature/metadata parity.

Selection semantics must be explicit in metadata: install sets the complete target set for this one MCP; preserve other MCP bindings. Omitted previously selected targets are deliberate removals, not unrelated-file mutations. Full-scope native apply aggregates all remaining desired component MCP entries per provider target; never build it from only the just-installed MCP. Never-selected native targets and unrelated ownership remain untouched. Bounded migration preserves proven existing exposures before applying this explicit per-MCP change.

### Structured results and compatibility

Use one existing structured machine-result channel for the three new tools. Reuse the existing _structured_output_only_wrapper/_as_structured_only support through a neutral structured_output_tool_names factory option; do not flip Project or Providers server-wide mode and silently change existing tools. The factory accepts an explicit frozenset of tool names; _AutoDescFastMCP.add_tool wraps only those names or the existing server-wide opt-in. Exact implementation must preserve signature, generated outputSchema, decorated error behavior, async/sync support and pass-through CallToolResult. No new serializer, generic output protocol or second success text representation. Old Project tools retain their existing wire format unless a separately explicit, tested migration changes all affected clients. Existing tests/e2e/cli/test_mcp_project_server.py:_call currently parses content text only; keep old calls working and add separate structured assertions for new tools.

Owner installation DTO is shared by CLI JSON and MCP. Receipt includes MCP ID, operation ID when persisted, ok/dry_run, and per-target phase/planned action/actual changed/configured/restart/action-needed fields. Availability of the component is distinct from harness binary availability. Unattempted reachable/verified and absent errors/operation IDs are omitted, never implied true. Preserve meaningful false, zero and semantically significant empty lists. Dry-run never marks a target configured merely because it is planned. Removals report the intentional target/action so omission cannot be mistaken for failure.

Status reads only one operation and includes its current per-target outcome and safe next action. No full native paths/payloads, fingerprints, credential references, prompts, stack traces, history or redundant catalog in default output. Detailed errors use existing owning registered safe codes; no additional diagnostics tool is justified by this MVP. Proposed fixture regression budgets: compact representative catalog <=8 KiB, ordinary two-target receipt <=4 KiB, one-target status <=2 KiB. Measure serialized bytes and scaling on fixtures; these are regression checks, not permission to silently truncate a real catalog or omit outcomes.

### Final contract decisions from terminal GPT discussion

No architecture blocker remains. Exactly three new internal Project tools and no new Provider tools/CLI verbs are approved. Install preserves input order after deduplication and chooses deterministic operation ordering. Every affected target, including prunes, preflights before any mutation. The current approved CLI cannot express an explicit empty CSV selection: install requires a nonempty target list in BOTH CLI and MCP. Reject missing/empty harness operands rather than accidentally interpreting them as prune-all. Persisted empty bindings and owner disable/uninstall remain valid; adding an explicit clear-selection grammar is outside this delivery, not a hidden MCP-only behavior.

Receipt fields: operation_id only when persisted; desired_harness_ids records the requested complete set; changed reports actual mutation and is false for dry-run. planned_changes is dry-run-only. applied_changes includes only successful actual operations; removed_harness_ids if reported contains completed removals only. targets gives bounded per-target outcome/error/phase, including partial failures without mislabeling planned work as done. get_mcp_install_status(None) with no unresolved operation returns has_unresolved_operation:false; explicit missing operation_id returns the registered owning not-found error. No unattempted reachable/verified facts or absent errors emitted. Budgets are fixture regression guards, never runtime truncation.

ManagedMcpRequest adding required managed_ids changes its payload contract to provider-managed-mcp-payload/v2; update builder, emitted schema and _capabilities.yaml together, delete obsolete internal contract references after migrating callers. Result contract stays at its current version unless its own shape changes. No MCP changes bleed into managed-hooks contract. LSP/memory/recipe callers supply full/subset semantics explicitly. Bounded old ownership migration is separate from wire compatibility; no broad internal compatibility shim.

Shared transport factory adds structured_output_tool_names: frozenset[str] with default empty. Only the three named Project wrappers opt in, using the existing conversion. No server-wide Project/Providers flag change and no new mcp.tool SDK keyword. Actual tools/list outputSchema must match structuredContent result envelope; preserving annotations alone is insufficient. Add a structured-result test helper alongside the existing text helper. Existing 19 Project and all current Provider tools keep their current wire contract in this slice.

### Native request schema semantics

```json
{
  "managed_ids": {
    "oneOf": [
      {"type": "null"},
      {"type": "array", "uniqueItems": true,
       "items": {"type": "string", "minLength": 1}}
    ]
  }
}
```

The request REQUIRES managed_ids. null means whole owned scope, [] means touch no IDs, a nonempty array means subset. Do not apply output sparsification to remove a request null: its presence has control meaning. Change authoritative MCP schema builder then emit artifacts; hooks schema remains byte-identical.
