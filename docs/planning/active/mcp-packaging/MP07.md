# Implement preflighted idempotent onboarding with recoverable per-target outcomes

## Description

MP03 slice 4. Generic orchestration composes existing owner APIs and emits truthful install results.

## Steps



## Detailed Solution & Technical Design

Public project API builds an immutable operation plan: validate canonical MCP and all harness IDs, scope, component/dependency changes, entrypoint and package availability, config requirements, propagation eligibility, target paths/conflicts and configuration revisions before writes. dry-run emits redacted proposed changes without prompts that write state or remote probes. Explicit install is configure/register, not automatic harness/toolchain installation or arbitrary package execution. Prefer current installed application entrypoint with absolute interpreter argv and canonical ID resolution; external requirements must be declared/trusted. Persist a bounded redacted operation journal with intent, target revision/hash and completed phases. Atomic per-file writes plus revision checks and rollback of owned fragments where safe; no claim of cross-client transactional atomicity. On partial failure show each target's applied/failed/not-attempted/verification state, nonzero exit, and retry only unfinished steps. Never erase external user edits during rollback or retry. Bounded stdio initialize/tools/list after apply verifies identity; HTTP auth/services separately optional. Reload notifications use provider APIs and do not force-start interactive harnesses.
