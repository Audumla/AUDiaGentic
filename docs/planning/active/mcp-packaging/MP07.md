# Implement preflighted idempotent onboarding with recoverable per-target outcomes

## Description

MP03 slice 4. Generic orchestration composes existing owner APIs and emits truthful install results.

## Steps

1. Harden existing generic reconciliation preflight/no-op/collision correctness and qualify its existing independent consumers.
2. Expose provider-owned preflight/apply/recover operations through providers_api with safe typed results.
3. Build project-owned install plan that validates every selected target before committing any intent or triggering component lifecycle.
4. Persist intent before lifecycle refresh and perform guarded per-target apply; keep successful targets if another fails.
5. Verify explicitly and report configured/reachable/verified separately; qualify interruption and retry.

## Detailed Solution & Technical Design

Present defects: reconcile_fragments accepts unowned same-name entries, removes entries before validating all desired collisions, unconditionally writes unchanged values and always saves registry. Fix the existing neutral FragmentStore/reconcile_fragments/ManagedFragmentRegistry machinery, used independently by provider MCP, managed hooks, plugin entries and model projection. Foundation uses only opaque ownership keys, target identities, payload equality/fingerprints and revision fences; it must not understand MCP IDs, profiles, providers or onboarding phases. Provider code resolves native paths/sections, adapters, ownership policy and safe reload and exposes operations via approved providers_api; project never imports serializers, recipes, registries or adapter objects. Provider operations accept data and opaque correlation/ownership context, not requester callbacks. Project-owned operation DTOs and journal remain project-owned, not foundation. Full preflight precedes removal/write, including cross-scope ownership at canonical physical target+section, foreign name collision even for equal payload, prior raw-entry fingerprint, rename destinations and malformed registry. Reuse AdvisoryLock with bounded acquisition, canonical lock ordering, re-read under lock and target+registry revision checks. A no-op performs no native writer, registry save or reload. A real mutation preserves unrelated logical content using existing provider-native writers; current Codex TOML whole-file serialization cannot promise comment/format preservation. No invented second writer or ownership registry. Per-file atomicity is not global client transactional atomicity. Do not perform destructive rollback through external edits. Persist safe intent/revisions/target phase evidence, not native snapshots or credential-bearing argv. Project operation journal tracks requested targets/outcomes; provider-owned reconciliation evidence owns native-write/ownership recovery. On retry inspect actual target+ownership+operation evidence: unchanged retry is safe; proven native-write-before-registry completion may repair ownership; divergent/ambiguous evidence returns needs-reconciliation and cannot claim/adopt. Keep unresolved evidence until explicitly resolved; terminal evidence bounded by owner retention. Register errors with owning component before public use. Installed/configured success does not imply live reachability; explicit verification failure is nonzero without removing valid configuration.

Final code-level review corrections: move the existing MCP ownership registry from .audiagentic/runtime/providers/managed-mcp-servers.json to .audiagentic/state/providers/managed-mcp-servers.json, gitignored and locally protected. config/components/providers.yaml currently declares runtime provider state runtime-only and lifecycle cleanup removes runtime, so authoritative MCP ownership cannot stay there. Bounded v1-to-v2 migration validates old evidence, writes one authoritative destination, updates all callers, and removes the obsolete route; ambiguous dual-present records require reconciliation, not precedence guessing. No duplicate registry and no migration of other families. Extend current ManagedMcpRequest with REQUIRED managed_ids: frozenset[str] | None: None replaces this ownership scope; a set means subset. Current managed_ids=set(desired) otherwise leaves omitted old selections installed. Update every constructor explicitly, no undocumented default compatibility shim. Minimal operation states prepared, intent_committed, applying, completed, needs_reconciliation; successful targets retained. Release project lock before component lifecycle and reacquire/revalidate before project operation updates; native/registry locks use fixed order without cross-owner callbacks. Recovery metadata is bounded content-free local state, not tracked config.

MP10 defines the minimal public adapters: list_mcp_catalog(mcp_id=None), install_mcp(mcp_id,harness_ids,dry_run=False), get_mcp_install_status(operation_id=None). Reuse this item's single owner receipt/status DTO for CLI JSON and new MCP results. Dry-run is preflight; matching repeated install is journal-aware recovery, not a second provider submission route. Status is strictly read-only and bounded, with one requested operation/latest unresolved and an explicit no-unresolved state. Do not add separate recovery/preflight/verification MCP tools or a new CLI verb. New MCP result-channel opt-in is per-tool; old Project/Provider wire formats do not silently change.
