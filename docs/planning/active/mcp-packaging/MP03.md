# Add contained CLI MCP installation and configuration for explicitly selected harnesses

## Description

Planning only. Support audiagentic mcp install <mcp-id> harness <id1,id2> using positional command verbs and named options, list MCP IDs/harnesses, schema-driven prompts, and explicit verification. Installation registers one declared MCP with selected existing harnesses; no implicit chat launch, harness binary installation or claim of slim packaging.

## Steps

MP04: read-only MCP/harness catalogs and identity/capability contracts. MP05: component-owned schemas and safe prompts (after MP04). MP06: persisted selective bindings and reconciliation (after MP04; coordinate MP05 scope). MP07: preflight/idempotent apply/recovery (after MP04-MP06). MP08: thin CLI commands and keyword-based grammar (after service contracts, no mutation shortcut). MP09: installed-package E2E, compatibility, docs and measurement; acceptance gate for parent.

## Detailed Solution & Technical Design

CLI presentation -> project_api onboarding orchestration -> component public config/status APIs and providers_api -> provider-owned managed configuration adapters. Foundation contains only neutral contracts, validation primitives and atomic file helpers. Components own MCP semantics, schema/defaults/validation/dependencies. Providers own harness paths, native config formats and reload mechanism. Reuse McpServerDeclaration/ExternalMcpServerDeclaration, McpServerEntry, stable managed IDs, ManagedFragmentRegistry and sync_managed_provider_mcp_subset. No launcher switches for specific clients or MCPs, no provider import of runtime.harness, no duplicate registry/writer. Explicit project-scoped (mcp_id,harness_id) bindings must survive later global config refresh. Public MCP IDs are not component IDs, Python module strings or package names; components may own multiple MCPs. Start using servers in installed AUDiaGentic; MP02 remains separate prerequisite for genuinely minimal co-installable wheels. Current vendored bundles must have isolated environments.

## Code Samples & Guidance

User-approved examples (proposed, not implemented):

```text
audiagentic help
audiagentic mcp help
audiagentic mcp list
audiagentic harness list
audiagentic mcp install help
audiagentic mcp install ag-planning harness pi,opencode
audiagentic mcp ag-planning help
audiagentic harness pi help
```

No describe verb or root install-flag aliases. Existing flags remain compatible. Ancillary management keywords (project, component-profile, dry-run, config, non-interactive, output json) require a complete grammar and code-level review before implementation. Existing mcp MODULE MODULE_ARGS and no-command provider passthrough remain unchanged.
