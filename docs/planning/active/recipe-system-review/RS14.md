# Normalize provisioning step path and render helpers

## Description

Small execution slice for RS04. After RS13 characterization tests land, normalize the smallest proven inconsistencies in step path resolution and runtime rendering.

## Dependencies

- RS13 must be complete.

## Proposed solution

Add one domain-neutral helper for step path resolution and, only if tests justify it, one safe runtime render helper for shell/context placeholders. Apply to existing mutating steps without changing their public role. Keep foundation domain-neutral: callers either pass `context["project_root"]` or pre-resolve paths before step construction.

## Implementation steps

1. Add `_resolve_step_path(path, context)` or similar in `provision_steps/base.py` or a new domain-neutral helper module.
2. Define path rules: absolute path unchanged, `~` expanded, relative path anchored to `context["project_root"]` when present, otherwise current behavior.
3. Apply helper to `ConfigSetStep`, `ManagedBlockStep`, and `WriteFileStep`.
4. Decide whether `ShellProvisionStep.cwd` follows the same helper; implement only if tests prove expected.
5. Replace raw `str.format(**context)` with a safe helper if RS13 shows it is still needed.
6. Decide whether `substitute_params()` remains lenient for probes or gains an opt-in strict mode for status commands.
7. Update docs/comments with the final rules.
