# Implement shell output redaction and safe summaries

## Description

Small execution slice for RS05. After RS15 characterization tests land, implement redaction/truncation for shell provisioning outputs without changing command execution semantics.

## Dependencies

- RS15 must be complete.

## Proposed solution

Add a domain-neutral redaction helper and use it at the earliest source: `ShellProvisionStep` result creation. Aggregate sequence outputs should become safe automatically because they copy step outputs.

## Implementation steps

1. Add or reuse a redaction helper for token-like strings, bearer headers, password/api-key pairs, and URL credentials.
2. Replace full stdout in `StepResult.outputs` with `stdout_summary` or redacted/truncated `stdout` according to the test expectation.
3. Redact failure `reason` when it is derived from stdout or exception text.
4. Redact command args in outputs where values look secret-bearing.
5. Ensure dry-run command outputs are also redacted.
6. Update tests from RS15 from expected-unsafe to expected-safe.
