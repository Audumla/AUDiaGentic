# Normalize provisioning step substitution, paths, and artifact ownership

## Description

Review `provision_steps` for inconsistent placeholder and path handling. The factory performs strict `{KEY}` substitution for YAML definitions, while `ShellProvisionStep._render()` later applies raw `str.format(**context)`. Config/file/block steps resolve paths differently, and some direct plugin writes bypass `ArtifactRegistry`. Normalize these mechanics so recipe authors do not need to remember step-specific quirks.

## Steps

1. Compare `_substitute()`, `substitute_params()`, and `ShellProvisionStep._render()`; decide one documented substitution phase for definition params and one for runtime context.
2. Add tests for literal JSON braces, unknown placeholders, optional empty values, and runtime context placeholders.
3. Normalize path resolution rules: project-relative vs absolute vs `~` expansion should be explicit and consistent per step type.
4. Ensure every file/config/block mutation can optionally register ownership in `ArtifactRegistry`.
5. Identify direct writes in dependants that should become `write-file`, `config-set`, managed config, or explicit artifact registration.
