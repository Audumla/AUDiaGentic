# Consolidate Hindsight recipe patterns and plugin recipe duplication

## Description

Review Hindsight recipe dependants for duplicated lifecycle logic. Hindsight already moved guidance-only and declared-step recipes into `RecipeSpec` assembly, but plugin recipes still duplicate install/uninstall source gates, step execution, probe/verify patterns, dry-run strings, and MCP-entry status logic. Consolidate repeated patterns without reintroducing the removed generic `ManagedEntryRecipe` or speculative abstractions.

## Steps

1. Compare `_McpConfigAdapter`, `PluginConfigRecipe`, `_PluginUrlConfigRecipe`, and `_PluginArrayRecipe` for duplicated lifecycle code.
2. Extract only proven shared helpers: source-gated step runner, plugin install/uninstall step execution, probe-then-verify helper, and managed MCP status/sync helper.
3. Keep provider-specific/plugin-specific data in the matrix or row object, not in code branches.
4. Do not merge plugin URL config and plugin array recipes unless tests prove a real common managed-config abstraction exists.
5. Add tests for each plugin recipe path before and after simplification.
