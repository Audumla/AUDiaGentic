# Characterize provisioning step substitution and path behavior

## Description

Small execution slice for RS04. Add tests that document current substitution and path behavior before changing any provisioning step implementation.

## Proposed solution

Test current strict definition substitution, lenient command substitution, shell runtime formatting, JSON brace preservation, optional empty params, and path anchoring behavior.

## Implementation steps

1. Add tests for `_substitute()` on strings, lists, dicts, JSON-like braces, missing params, and empty params.
2. Add tests for `substitute_params()` preserving unknown placeholders.
3. Add tests showing unknown `substitute_params()` placeholders can reach status probes / shell commands as literal `{KEY}` strings.
4. Add tests for `ShellProvisionStep._render()` with runtime context values and missing keys.
5. Add tests for `ConfigSetStep`, `ManagedBlockStep`, and `WriteFileStep` path behavior using absolute, `~`, relative, and context/project-root cases.
6. Compare foundation step behavior with Hindsight `_absolute_project_path()` so RS14 can define whether pre-resolved paths or context `project_root` is canonical.
7. Add artifact registry tests for each mutating step.
