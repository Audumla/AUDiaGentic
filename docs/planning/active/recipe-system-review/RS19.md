# Add recipe architecture and standards guard tests

## Description

Small execution slice for RS07. Add targeted tests that prevent recipe-system standards regressions.

## Proposed solution

Add tests that are narrow and allowlisted, not broad brittle grep bans. The goal is to catch foundation imports from components/runtime orchestration, recipe lifecycle duplication, provider-specific dispatch in generic code, unsafe output patterns, dynamic assembly drift, and missing Hindsight recipe factories.

## Implementation steps

1. Add import-boundary tests for `src/audiagentic/foundation/toolchains/recipe_contract.py`, `recipe_patterns.py`, `artifact_registry.py`, and `provision_steps/*`.
2. Add allowlisted scan for classes overriding `provision()` or `teardown()` outside `recipe_contract.py`.
3. Add targeted scan for provider/capability/entity `if/elif` dispatch in foundation recipe code and generic provider recipe registry.
4. Add a test that every `ProviderRecipeKind` present in the Hindsight matrix has a corresponding `_RECIPE_FACTORIES` entry unless the fallback is explicitly allowlisted.
5. Add assembled recipe integrity tests for `probe`, `install`, `configure`, `verify`, `uninstall`, `prune`, status overrides, and inherited `provision()` / `teardown()`.
6. Reference existing matrix source metadata coverage in `tests/unit/foundation/toolchains/test_architecture_boundaries.py` and extend it only if gaps remain.
7. Add migration grep helper comments/tests to use when RS10/RS12/RS14 remove old names.
8. Wire RS15/RS16 redaction tests into the standards gate after they land.
