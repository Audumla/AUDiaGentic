# Add recipe standards and architecture regression tests

## Description

Add a focused standards gate for the recipe system and dependants. The goal is to prevent future duplication of lifecycle orchestration, provider-specific branches in generic code, foundation layer leaks, and unsafe output handling.

## Steps

1. Add architecture tests proving foundation recipe/provision-step modules do not import components or runtime orchestration.
2. Add grep-style tests or static checks for provider/capability `if/elif` dispatch where registries should be used.
3. Add tests proving no recipe dependant reimplements `provision()` / `teardown()` without explicit allowlist and rationale.
4. Add redaction tests for recipe result details and shell step outputs.
5. Add whole-repo migration checks for renamed/deleted recipe modules per Migration Doctrine.

## Validation

1. `python -m pytest tests/unit/foundation/toolchains tests/unit/providers tests/unit/memory/hindsight` passes.
2. Architecture-boundary tests prove foundation remains domain-neutral and dependency-safe.
3. Static/golden tests catch accidental provider-specific recipe dispatch in foundation or generic providers code.
4. Redaction tests fail if stdout/stderr/secrets are emitted in structured results.
