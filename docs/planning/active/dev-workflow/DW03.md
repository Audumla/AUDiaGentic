# Worktree provenance: required purpose, evidence hold, unmanaged-tree hook, audit trail, archive tags, adopt

## Description

`audiagentic worktree` already records an owner (session, harness, account), creation time and an optional purpose for each worktree it starts, centrally in the user state directory, and `reconcile` reports worktrees git has but no record covers. Projects that migrate onto it (first: bigcherry, which has stray hand-made trees and branches with no record of who made them or why, and holds evidence worth keeping) need provenance gaps closed in the generic core. Project-specific behaviour (branch naming, root, protected trees, checks, PR trailer, ledger and planning moves) stays in settings and in each project's own wrapper; nothing project-named enters the core.

Gaps: (1) a purpose is optional on start; (2) finish cannot be told that a worktree holds evidence that is not yet preserved; (3) trees made by plain `git worktree add` are never recorded until someone notices them; (4) no audit trail outlives a record once a worktree is finished and forgotten; (5) experiment branches are deleted without a durable pointer; (6) existing stray trees cannot be brought under management without recreating them.

## Steps

1. Required purpose: a setting `worktrees.require-purpose` (default false; projects opt in) and the existing `purpose TEXT` argument. When required, `start` refuses without it and says how to give one. The empty string never counts.
2. Audit trail: an append-only event log under the user state directory `worktrees/audit/<repo-id>.jsonl` written by start, adopt, evidence changes, finish (including abandon and discard) and tidy. Each event: time, action, worktree id, path, branch, owner, purpose, plan item, tip, outcome. It is never rewritten, never removed by finish, `audiagentic worktree audit [project PATH] [output json]` reads it; a failed append refuses the action it records. Do not add a file inside the worktree (records stay outside git status by design).
3. Evidence hold: `audiagentic worktree evidence TARGET set REASON | clear` marks a worktree as holding evidence not yet preserved. `finish` and `tidy` refuse while the mark is set, naming the reason, and only `clear` (an audited action) lifts it. `abandon`/`discard-ignored` do not override the mark.
4. Adopt: `audiagentic worktree adopt TARGET purpose TEXT [owner NAME] [item ID]` creates a record for an existing worktree that has none (the `unmanaged` set from reconcile), after checking git lists it and it is not the primary. The adopter is recorded as the creator-of-record with an `adopted` flag so audit does not claim it made the tree.
5. Hook for plain `git worktree add`: `audiagentic worktree hook install [project PATH]` installs a `post-checkout` hook in the repository's common hooks directory that runs `audiagentic worktree adopt` in noninteractive record-only mode for a freshly added tree (the all-zero previous-HEAD checkout). It records provenance (owner from the environment, purpose `unspecified` unless the setting requires one, in which case the record is marked `needs-purpose` and `list`/`prune` show it). The hook never blocks git and never fails a checkout; hook install refuses to overwrite a foreign hook (it reports it). `hook status` and `hook remove` are provided.
6. Archive tags for experiment branches: `finish` and a new `audiagentic worktree retire-branch NAME` write an `archive/NAME` tag at the branch tip before the branch is deleted, when the branch is unmerged or marked experiment (a setting `worktrees.archive-tag-prefix`, default `archive/`). The tag is never deleted by these commands and is pushed only if the project says so.
7. Surface in `list`: purpose, owner, adopted, needs-purpose and evidence mark. `prune` names the evidence mark as a blocker.
8. Docs: update docs/guides/WORKTREES.md (commands, settings, files, limits) and add the settings to PROJECT_SETTINGS.
9. Tests per slice; end-to-end on a scratch repository with a bare remote including plain `git worktree add` with the hook, adopt of a stray tree, evidence hold refusing finish, audit surviving finish, and archive tag restoring an experiment branch.

## Acceptance Criteria

- `worktrees.require-purpose` makes `start` refuse without a non-empty purpose; default behaviour is unchanged.
- An append-only audit log survives finish and forget, is readable through `audit`, and a failed append refuses the recorded action.
- A worktree marked as holding evidence is refused by `finish` and `tidy` (and listed as a `prune` blocker) until the mark is cleared by an audited command; no argument overrides it.
- `adopt` records an existing unmanaged worktree with the adopter recorded as adopter, not creator.
- The post-checkout hook records plain `git worktree add` trees, never blocks or fails git, and never overwrites a foreign hook.
- An unmerged or experiment branch gets an `archive/` tag before deletion; the tag is never deleted by these commands.
- Nothing in the core names a specific project; project differences are settings only; nothing is written inside a worktree.
- docs/guides/WORKTREES.md and project settings docs describe the commands, settings, files and limits.
