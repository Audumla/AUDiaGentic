# Project-agnostic worktree lifecycle: start, list, merge, finish, prune

## Description

Concurrent agent sessions work on AUDiaGentic projects with one task = one branch in its own git worktree = one squash-merged PR. Today's rules (container AGENTS.md: branch from origin/main in its own worktree, never edit the primary checkout, PR + queued squash merge, remove the worktree after merge) left 36 stale worktrees, no ownership or protection, a per-session ad-hoc merge script, cleanup that needed GitHub PR state per branch (squash defeats `git branch --merged`), and gateway request/session records that live inside the worktree and would be destroyed by a careless removal. Provide one project-agnostic lifecycle, owned by the project component, that lets sessions work on PRs independently and concurrently, merge cleanly, and clean up without loss.

## Steps

1. Lifecycle state machine with idempotent, reconcilable operations: CREATING, ACTIVE, DRAINING, MERGE_REQUESTED, MERGED, ABANDONED, QUARANTINED, REMOVED. Audit records survive removal.
2. Central ownership: records in project-scoped user state keyed by canonical repository identity and an immutable worktree id (path, branch, owner session/harness/account, created, lease expiry); atomic writes under a lock; an exclusive renewable owner lease with fencing required for mutating commands; explicit audited transfer/recovery; reconcile against `git worktree list --porcelain` (vanished paths are orphans). Nothing written into the worktree.
3. `worktree start SLUG [item ID]`: fail if fetching the configured remote's default branch fails; validate SLUG/branch with git rules; serialize creation under a project lock; reserve identity atomically; create branch+worktree in one git operation from the fresh remote default branch; roll back partial failures; print the path (the MCP `worktree` value). Plan item is optional metadata.
4. `worktree list [output json]`: state, branch, PR and checks, dirty, ahead/behind default branch, age, owner/lease, processes referencing it (cwd and open files), active gateway work, protected.
5. `worktree merge`: never rewrites the branch implicitly; requires clean tree, live owner lease, expected head SHA; push (force-with-lease only when authorised); open/update the PR with a validated conventional squash title; record the submitted head SHA; submit merge intent to the forge and return (observe later), never hold a session open.
6. `worktree finish` (non-destructive by default) and `prune` (dry-run unless confirmed): remove only when the PR is MERGED with verified association, or work is explicitly ABANDONED and first QUARANTINED (unique commits parked as a ref); inventory unique/unpushed commits, ignored/untracked files (size and secret-looking names need force), locks and submodules; no live lease, no process referencing it, no gateway requests/sessions/pending operations after an atomic DRAINING state and an idle recheck; protected worktrees by canonical path and id are never touched; never `git worktree remove --force` or recursive deletion as a routine fallback; uncertain state (e.g. forge unreachable) means refuse, not guess.
7. Merge serialization on the server: GitHub merge queue with `privacy` and `tests` required on merge-group candidates (workflows handle `merge_group`); else repo auto-merge with strict required checks (accept update/retest churn); last resort a durable project queue with one worker, fencing, retries, crash recovery and head-SHA verification before merge that holds its lease only while merging, never while CI runs, with an explicit failure policy. Never an unprotected direct merge.
8. Adapters behind a provider-neutral core: git (identity, refs, worktrees, cleanliness, unique commits), forge (PR association, checks, merge state/submission; GitHub+gh first, no-forge mode lists and refuses prune/merge), runtime (active work, admission fencing, drain), project policy (default branch and remote discovered, protected worktrees, checks, merge strategy, release rules).
9. Settings (project scope): worktrees root, branch prefix, protected worktrees, merge strategy (squash), required checks. doctor reports inconsistent states, stale/orphaned worktrees and a primary checkout off the default branch without deleting anything.
10. Replace the hand-written steps in the container AGENTS.md and project docs with the commands; retire the ad-hoc merge script.

## Standards

docs/standards/ARCHITECTURE_STANDARDS.md (reuse existing mechanisms: foundation owns the git/process/locking mechanics, components own policy; no parallel loaders, no legacy aliases or shims) and ARCHITECTURE_GUIDELINES.md; docs/design/configuration-model.md (a component owns its settings section and its doctor checks; doctor is read-only); docs/standards/OBSERVABILITY_STANDARDS.md (redaction, bounded evidence); AGENTS.md container rules (primary checkout is fetch/pull only; kill only your own processes; privacy guard before push). Squash-merge and release-please conventions apply to every PR this item produces.

## Acceptance Criteria

- Two sessions can start, work, merge and finish worktrees concurrently with no shared-state coordination by message.
- No removal path can lose unique commits, CLOSED-unmerged work, ignored files above policy, or gateway records with active work; uncertain state refuses.
- Ownership is central, leased and fenced; nothing is written into the worktree.
- Merges are serialized server-side (merge queue preferred) or by the durable project queue; never a direct unprotected merge.
- Works for a project without GitHub in a documented reduced mode (list/start/finish refuse what needs forge evidence).
- AGENTS.md and project docs point to the commands; the ad-hoc merge script is retired.

2026-10-30 slice 3 deletion rules reviewed by GPT (req_wt-planning_038ba40486de, REQUEST CHANGES), triaged. Accepted and now requirements for slice 3b (`finish`/`prune`):
1. Admission fence (CRITICAL): a DRAINING flag plus a 2 s wait is not a fence. Slice 3a adds one that is enforced where agents act: foundation/system/worktree_drain.py markers in the user state dir, checked by foundation.mcp.worktree.resolve_worktree, which every planning/ledger/gateway MCP call goes through (CFG-MCPWT-006). It does NOT cover callers that bypass the resolver (direct Python API, CLI), so finish also refuses on active work and live processes. If the fence or the active-work query cannot be established, deletion refuses.
2. Active work: an agents-owned query, gateway.api.worktree_active_work(root), replaces reading the gateway's files from the project component. An unreadable store raises (refusal), it never reports empty.
3. Merged-work safety (CRITICAL): `tip == PR head` alone is not enough after a squash merge. finish requires an unambiguous PR on this repository whose base is the default branch and whose head SHA equals the local tip (several PRs on one branch name: the one matching the tip), state MERGED, and its merge commit reachable from the fetched remote default branch. Anything else is UNKNOWN and refuses. Ancestry alone is never accepted.
4. Preservation: every removal first writes an immutable local ref refs/quarantine/<worktree-id> at the tip, even for merged work; abandoned or unpublished work additionally gets a verified `git bundle` (checksum recorded) outside the repository. Quarantine refs are only removed by a separate explicit retention step, never by finish or prune. Branch deletion uses -D only after the ref exists.
5. Ignored files: refuse by default whenever unknown ignored content exists. Disposable caches (__pycache__, .pytest_cache, .ruff_cache, .mypy_cache) are allowed. Gateway runtime records (.audiagentic/runtime, .audiagentic/state) are copied to a central archive and verified before removal. `discard-ignored N` must repeat the file count a refusal printed, so the inventory was seen.
6. Crash safety: a durable removal journal (fsynced, central) with phases PREPARED, DRAINED, PRESERVED, WORKTREE_REMOVED, BRANCH_REMOVED, COMPLETE; expected git state revalidated before each destructive phase; tombstone kept; a rerun resumes and a partial removal is never reactivated.
7. Identity: resolve through `git worktree list --porcelain` and the common dir, revalidate under the project lock immediately before removal, refuse nested repositories, initialized submodules, detached HEAD (unless abandoned), git-locked worktrees.
8. prune is read-only in this item: it reports eligibility, exact blockers and the `finish` command to run. Only single-target `finish` deletes; bulk deletion would need a separately approved plan.
Known limit (documented, not solved): shared stashes and tags are repository-wide and are neither checked nor deleted; reflog-only commits in a worktree are covered by refusing a detached HEAD.
