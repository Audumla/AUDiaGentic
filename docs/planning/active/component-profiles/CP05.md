# Guard against cross-profile pollution of the event bus and feature registry

## Description

The event bus (foundation/event/event_bus.py get_bus(), a true process-global singleton with unnamespaced string event types and module-level import-time subscribe() side effects) and the feature/implementation registry (foundation/features/registry.py, module-level global dicts keyed only by (parent, kind, id)) are safe across separate process invocations - each launch gets a fresh singleton - but are NOT safe if two different profiles' components were ever loaded into the same process. Add a defensive guard so this unsupported state fails loudly instead of silently producing event-name collisions or registry bleed. NOTE: a deep-dive (2026-07-04) found roughly a dozen MORE process-global singletons with the same risk profile beyond these two - split out to CP08, since fixing all of them under one item would be unreasonably large. This item (CP05) stays scoped to the two originally-identified singletons; CP08 covers the rest.
