# Audit and add reset/isolation precedent for other process-global registries

## Description

CP05 guards the two originally-identified process-global singletons (event bus, feature registry). CP10 extracts a shared generic-registry utility (with lazy-load and alias support) and migrates language_registry, host_adapter, providers/tags/registry, providers/surfaces/registry (as two instances, per RV95), provision_steps' _STEP_TYPES, and provider_recipes onto it directly (no shims, per ARCHITECTURE_STANDARDS.md:96-97 - old functions deleted, callers updated). This item (CP08) is narrowed to: the two logging singletons (foundation/logging/audit.py:157-195 _instance AiAuditLogger holding one process's audit config + open file handle; foundation/logging/config.py:35-36,183,197 _configured/_loaded_config/_discovered_root, first-call-wins) which are genuinely single-instance config state, not keyed registries, and foundation/components/registry.py (component descriptor registry, _registry/_aliases at registry.py:13-14,17-23). CORRECTED per review RV95 (2026-07-05, verified against code): register()'s alias-stripping only clears aliases owned by the SAME incoming component_id (correct idempotent cleanup, not destruction of another descriptor's aliases). The real defects this item targets are: cross-component alias collisions silently last-win (_aliases[alias] = id with no conflict check against a different existing owner), and an alias can silently shadow-collide with a real component_id already in _registry with no check either way. Once CP10 lands and proves its alias-handling (raise/warn on cross-conflict and shadowing) is correct, foundation/components/registry.py should internally adopt the same Registry instance (aliases=) as its storage rather than getting a bespoke one-off fix - its own public API (register/get_descriptor/all_descriptors, used by 21 callers) stays the real surface, only the internal dict+alias logic is replaced.
