# Files list names only generated CLAUDE.md; the actual edit target is session.yaml

## Notes



## Findings

Two inconsistencies. (1) The Files list contains only 'CLAUDE.md', but the steps correctly say the edit goes into src/audiagentic/config/components/session.yaml with CLAUDE.md regenerated via apply_provider_surfaces. CLAUDE.md's own header says hand edits are overwritten, and the release doctrine forbids editing generated artifacts directly — an agent keying off the Files list could hand-edit the generated file and have the change silently reverted at next surface apply. (2) The step documenting 'the one-profile-per-process constraint from CP05/CP08' misattributes: after the scope narrowings, the profile-per-process guard is CP05 only; CP08's remaining scope is logging singletons + components/registry.py alias handling and has nothing to do with profile identity.

## Conclusion

Update Files to ['src/audiagentic/config/components/session.yaml'] (optionally keep CLAUDE.md listed as a generated output, clearly marked as such), and change the constraint attribution to CP05 alone.
