# Complete registry_utils: built-in lazy loader, catalogued errors, migrate the five ad hoc registries (CP10 remainder)

## Description

Ships the ~80% of CP10 that was never implemented (RV118, verified 2026-07-06 -- none of the five registries are migrated, registry_utils.py has no loader support). ARCHITECTURE_STANDARDS.md sections 11 and 12 already advertise 'the shared registry utility's built-in lazy-loader' as the sanctioned replacement for hand-rolled _loaded/_ensure_loaded() guards -- the standard currently documents vaporware, which this item makes true. Scope: (1) Add loader support to foundation/registry_utils.py Registry: constructor param loader: Callable[[], None] | None; get()/all()/keys()/resolve() invoke it exactly once on first access (a _loaded flag cleared by reset(), so the shared reset fixture restores lazy behavior); registration during loader execution must not recurse the loader. (2) Replace the raw ValueError raises (registry_utils.py:52,74,80 in the current file) with catalogued AudiaGenticError via make_error_factory (section 8 forbids raw ValueError at public boundaries; CP10's original spec said 'modeled on capabilities.py VAL-CAP-001' -- use a new VAL-REG-NNN series since capabilities.py is deleted). Remove the 'Exists for backwards compatibility with tests' framing on pop() (section 10) -- pop is a legitimate API; document it as such or inline its one use. (3) Migrate the five registries, direct call-site migration with the old module-level register_*/get_* functions deleted in the same change (section 10, no shims): components/coding_lsp/language_registry.py (module dict + lazy guard, ~7 external callers: lsp_session_resolution, runtime_resolver, language_servers_sync, lsp_config_api, lsp_recipe, coding_lsp_config), components/providers/services/host_adapter.py (module dict at host_adapter.py:70-90 area, 2 callers incl. host_capabilities), components/providers/tags/registry.py, foundation/toolchains/provision_steps/base.py (_STEP_TYPES), and components/providers/surfaces/registry.py which needs TWO Registry instances sharing ONE loader callable (verified structure: two dicts _renderer_registry/_contribution_renderer_registry behind a single _providers_imported flag -- per RV95, preserve the shared-gate semantics via one loader that populates both). (4) Extend the shared test reset: the new instances' reset() must be reachable from the existing autouse fixtures (tests/conftest.py _reset_test_registries and tests/unit/foundation/conftest.py) -- add a registry_utils-level registry-of-registries or explicit fixture list so clearing state also clears loaders' _loaded flags; this must also keep invalidating loader.py's registration cache (already wired).
