# Make gateway requests durable, idempotent, recoverable, and remotely cancellable

## Description

Replace CLI-lifetime recovery assumptions with service-grade queue ownership. Define durable admission and dispatch identity, idempotent submission, ownership leases/epochs, cancellation observation, crash recovery, and terminal-result uniqueness across service and worker restarts.

## Steps

1. Extend records with schema-versioned submission idempotency, owner epoch/lease, attempt/worker identity, and recovery state only after design review. 2. Make admission and transition writes atomic under the single control-plane authority and safe across crashes. 3. Replace destructive blanket reconciliation with ownership-aware recovery. 4. Ensure remote cancel reaches the owning worker and has explicit requested/acknowledged/terminal semantics. 5. Define retry vs resume vs fail outcomes by provider/session capability. 6. Add crash-point and replay tests for every transition, including exactly-once terminal projection even when execution may be at-least-once.

## Files

agents gateway schemas/store/queue/dispatch/session integration; shared gateway service; timelines/events; migration code; tests

## Validation

Crash injection at admission, dispatch, result write, cancel, and service restart never double-dispatches without detection, never loses a terminal outcome, and never lets stale owners mutate a newer epoch; replayed triggers return the original request identity.

## Effort & Risk

Complex distributed-systems semantics on one machine. Do not claim exactly-once provider execution where the provider cannot supply it; guarantee idempotent admission and explicit ambiguity instead.
