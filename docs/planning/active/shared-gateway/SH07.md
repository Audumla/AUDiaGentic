# Make gateway requests durable, idempotent, recoverable, and remotely cancellable

## Description

Replace CLI-lifetime recovery assumptions with service-grade queue ownership. Define durable admission and dispatch identity, idempotent submission, ownership leases/epochs, cancellation observation, crash recovery, and terminal-result uniqueness across service and worker restarts. SH07 is the single durable job-state authority: gateway job/request state materializes only through SH07 record transitions, fed by capability-declared observation evidence — never by a parallel transport-specific state store.

## Steps

V2 fencing slice is LANDED (see Notes). The remaining scope is implemented in four bounded slices, in this order.

### Slice A — machine-scoped active-work index (prerequisite for recovery)

Recovery must find non-terminal work without scanning every project on disk. Add a machine-scoped index beside the service record, written under the existing per-request mutation lock.

New in `agents_gateway_store.py`:
```python
ACTIVE_WORK_DIR = "active-work"  # <service-root>/<scope>/agent-llm-gateway/default/active-work/

def record_active_work(service_root: Path, project_root: Path, request_id: str,
                       *, dispatch_owner_epoch: str) -> None:
    atomic_write_json(service_root / ACTIVE_WORK_DIR / f"{request_id}.json", {
        "request-id": request_id,
        "project-root": str(project_root),
        "dispatch-owner-epoch": dispatch_owner_epoch,
        "claimed-at": now_iso_z(),
    })

def clear_active_work(service_root: Path, request_id: str) -> None:
    (service_root / ACTIVE_WORK_DIR / f"{request_id}.json").unlink(missing_ok=True)
```
Write in `claim_dispatch` (after the claim persists), clear in `transition_owned_terminal` and in queue rejected/cancelled-before-dispatch paths. Best-effort on clear; recovery tolerates stale entries (it re-reads the record and skips terminals). The service root reaches the store through the existing `_dispatch_owner_epoch` plumbing — add `dispatch_service_root` alongside it in `GatewayQueueManager.enqueue`/`_run_one`; in embedded mode it is None and no index is written (embedded keeps the current one-shot reconcile).

### Slice B — ownership-aware recovery replacing blanket reconciliation

New module `agents_gateway_recovery.py`:
```python
@dataclass(frozen=True)
class RecoveryReport:
    examined: int; requeued: int; interrupted: int; cleared: int; skipped_live: int

def recover_gateway_requests(service_root: Path, *, live_owner_epoch: str) -> RecoveryReport:
    """Run once at service start, after owner claim, before ingress drain."""
    for entry in sorted((service_root / ACTIVE_WORK_DIR).glob("*.json")):
        meta = _read(entry)
        record = store.read_record(Path(meta["project-root"]), meta["request-id"])
        if record["state"] in store.TERMINAL_STATES:
            clear_active_work(...); cleared += 1; continue
        if record.get("dispatch-owner-epoch") == live_owner_epoch:
            skipped_live += 1; continue          # never touch a live owner's work
        if record["state"] == "queued":
            store.release_stale_claim(project_root, request_id,
                                      stale_epoch=record["dispatch-owner-epoch"])  # clears claim fields under lock, expected-revision fenced
            requeued += 1                         # re-admitted via normal enqueue below
        elif record["state"] == "running":
            store.transition_recovered_terminal(project_root, request_id, "interrupted",
                error={"code": "CON-AGW-084", "message": "owning service generation is gone"},
                stale_epoch=record["dispatch-owner-epoch"])   # v2 terminal; fenced on the STALE epoch so a revived owner conflicts loudly
            interrupted += 1
```
Rules: recovery mutates ONLY records whose dispatch-owner-epoch differs from the live epoch (ownership-aware); `running` is conservatively `interrupted`, never auto-retried — retry/resume is a policy decision (Slice D). Register CON-AGW-084 in error-resolutions.yaml. `reconcile_gateway_state` (the blanket version) is retained but called ONLY from embedded-mode client creation; the service path calls `recover_gateway_requests` instead. Wire into `GatewayServiceHost.create` right after the owner claim.

Call sites: `_raise_if_cancelled` in dispatch (by="queue-worker") on first observation; `SessionRuntime.request_cancel`'s loop-side `_set` when it finds a live turn event (by="session-turn", via a small threadsafe callback injected by the queue, mirroring notify_turn_*); recovery when it interrupts a cancel-requested record (by="recovery"). Project into `project_public_status` and the MCP status/wait outputs so a remote canceller can distinguish requested → acknowledged → terminal. Tests: cancel a queued, a running-non-session, a running-session, and an orphaned record; assert exactly one acknowledgement and the correct terminal.

### Slice D — AS21 decision consumption (gated on AS21 landing)

SH07 must not build a second arbiter over transport events. When AS21's projector exists:
```python
# agents_gateway_store.py
def apply_lifecycle_decision(project_root, request_id, decision: Mapping) -> dict:
    """decision = {decision-id, coarse-state, turn_terminal, dependent_work_releasable,
    session_reusable}. Idempotent by decision-id (persisted applied-decision-ids list);
    a duplicate or late decision is a recorded no-op, never a second transition."""
```
The queue's terminal-transition call sites route through this once AS21 feeds them; until then existing O2 terminal behavior feeds transitions directly (current code). Retry-vs-resume policy: resolved per provider/session capability via providers_api evidence — `interrupted` records MAY be resubmitted by an operator (new request, `resumed-from-request-id` link) but are never silently re-executed.

### Crash-point test matrix (Slice B/C validation)
Simulate by killing/dropping at: after claim before start; after start before attempt append; after attempt before terminal; after terminal before index clear; cancel raced with each. Assert: no double terminal, no lost terminal, stale epoch always conflicts, replayed idempotent submission returns the original request identity, recovery report counts match. Docker: real service process kill -9 → restart → recovery leaves live second-service work untouched (two service roots).
