# Close provider-session restart recovery and watchdog gaps

## Description

Make restart recovery truthful and resilient for running gpt-auto provider-session requests. Preserve no-resubmit safety, keep recovered work visible to watchdog supervision, persist proven-unsent checkpoint clears durably, honor admission-frozen activity leases, and isolate watchdog failures per request.

## Steps

1. Register recovered running provider-session requests with the watchdog before invoking recovery, and re-register each scheduled recovery attempt under the existing owner fence. 2. Centralize persist-clear-before-memory-clear for proven-unsent, staged timeout, and cancellation/quiescence paths; emit explicit not_started/non-ambiguous evidence. 3. Resolve and pass the frozen request watchdog lease into provider-session activity relays. 4. Isolate watchdog-pass exceptions per registry entry and continue diagnosing later requests. 5. Add focused crash/recovery, two-restart exact-once, durable-clear, lease-policy, and multi-record watchdog tests. 6. Run GPT audit and live CDP restart validation. 7. Persist prepared/dispatching/proven submission stages; recover only the exact request correlated with a prepared (pre-Send) checkpoint, reopen its provider surface under the same gateway session, and prove dispatch-once behavior.

## Detailed Solution & Technical Design

Keep SessionRuntime/durable request records authoritative. Recovery is observation-only whenever provider side effects are ambiguous. Only a durable prepared checkpoint matching the current request id, unresolved-turn id, pending state, and submission-proven=false may reload the immutable admitted prompt. The provider session is reopened under the same gateway session id and normal dispatch performs the single Send. The checkpoint is advanced to dispatching durably before the browser side effect; dispatching/proven, missing, legacy, or uncorrelated checkpoints never authorize replay. The persisted provider conversation URL/identity is still required for observation-only resume.
