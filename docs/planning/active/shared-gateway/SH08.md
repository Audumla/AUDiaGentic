# Add fair machine-wide resource arbitration and backpressure

## Description

When measured machine-wide contention shows the existing gateway limits are insufficient, add the smallest resource-admission and backpressure policy needed to resolve that concrete bottleneck. Do not predefine a universal scheduler taxonomy.

## Steps

Evidence-gated: Slice A ships alone first and its captured evidence decides whether Slices B/C are built at all, and for exactly which resource key.

### Slice A — contention evidence capture (always safe to ship)

New module `agents_gateway_contention.py` — a sampler owned by the service host (thread started next to the ingress poller, 10s cadence, disabled in embedded mode):
```python
@dataclass(frozen=True)
class ContentionSample:
    sampled_at: str
    per_profile: dict[str, dict]   # {profile: {pending, running, active_running, idle, max_concurrency}}
    per_resource: dict[str, dict]  # {resource_key: {running, pending, distinct_projects}}
    ingress_pending: int

def resource_key_for(profile: Mapping) -> str:
    """Derive from provider capability facts, never provider-name conditionals:
    execution surface identity from providers_api — 'endpoint:<host-fingerprint>'
    for HTTP providers, 'local-exclusive:<provider-id>' when the provider
    declares exclusive local compute (e.g. one rig), else 'cli:<provider-id>'."""
```
Persist NDJSON to `<service-root>/contention/<yyyymmdd>.ndjson` (atomic append, 14-day prune). Additionally record per-request wait facts on the record at start: `queued-wait-seconds` (started_at - created_at) — one field, computed in `start_owned_attempt`. Expose a redacted `contention_summary()` in `service_status` (max wait p95 per resource key over the retained window). GATE: only when a summary shows a resource key with sustained cross-project starvation (documented threshold in the item at decision time, e.g. p95 wait > 60s while another project holds all slots for >10min) do Slices B/C proceed — record the evidence file reference in this item before implementing.

### Slice B — admission policy for the ONE evidenced resource key

New module `agents_gateway_admission.py`:
```python
@dataclass(frozen=True)
class AdmissionPolicy:
    resource_key: str
    max_concurrent: int            # machine-wide, across ALL profiles/projects sharing the key
    max_deferred: int              # bounded wait queue; beyond it → reject
    fair_share: bool = True        # FIFO per project, round-robin across projects

class ResourceGateRegistry:
    """Service-scoped singleton owned by the host; embedded mode has none."""
    def acquire(self, policy: AdmissionPolicy, project_root: Path, request_id: str,
                ) -> AdmissionTicket | AdmissionDeferred:
        ...
    def release(self, ticket: AdmissionTicket) -> None: ...
```
Implementation: one `threading.BoundedSemaphore(max_concurrent)` plus a deque-of-deques (per-project FIFO, round-robin pop) per resource key, mirroring `_ProfileQueue`'s lock discipline (mutate under one lock, I/O outside). Wire into `GatewayQueueManager._run_one` AFTER the profile compute-slot acquire and BEFORE the runner call — profile concurrency stays the inner gate, resource admission the outer machine-wide gate; a `AdmissionDeferred` beyond `max_deferred` transitions the record `rejected` with a new registered error `RES-AGW-090` ("machine-wide resource admission queue is full for <key>") and reason facts `{resource-key, waiting, running}` persisted on the record. Policy source: an `admission:` block in the provider descriptor (validated schema addition), resolved through providers_api — config over code, no scheduler taxonomy.

### Slice C — status/metrics + restart accounting

`service_status` gains `admission: {key: {running, deferred, max_concurrent}}` from the registry snapshot. Restart preservation: the registry is in-memory; admitted-work accounting after restart is reconstructed from SH07's active-work index during recovery (count running per resource key before opening the gate). Tests: competing two-project load never exceeds max_concurrent (thread-barrier test asserting the registry's high-water mark), starvation test (project A floods, project B still schedules within N slots — round-robin proof), deferred bound rejects with RES-AGW-090, restart reconstructs counts, and a no-policy configuration changes nothing (inert default).
