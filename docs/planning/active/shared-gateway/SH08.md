# Add fair machine-wide resource arbitration and backpressure

## Description

Move beyond per-profile in-memory concurrency limits to machine-wide scheduling across projects, harness sessions, providers, models, GPUs/endpoints, and context-isolated workers. Prevent one project from monopolizing the shared gateway while keeping policy config-driven.

## Steps

1. Define typed resource/capability declarations and admission keys without provider-name conditionals. 2. Specify global, per-project, per-role/profile, and per-endpoint concurrency/queue limits plus fairness policy. 3. Add bounded queues, priority classes, starvation protection, cancellation, and transparent rejection/defer reasons. 4. Expose safe status/metrics without prompts or secrets. 5. Verify scheduling remains deterministic under worker failure and restart. 6. Add load tests with competing projects and constrained fake resources.

## Files

shared gateway scheduler/admission modules; agent/provider capability contracts; config descriptors; operational status surfaces; tests

## Validation

Load tests show configured limits are never exceeded, one project cannot starve another, queue growth is bounded, and restart preserves admitted-work accounting.

## Effort & Risk

Complex policy surface. Keep the first implementation small and measurable; do not conflate model telemetry with scheduling authority.
