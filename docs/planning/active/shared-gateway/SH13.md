# SH07 C2 initialize gateway-owned profile registry

## Description

Make shared gateway profile authority real at service startup. The gateway, not a project-local profile file, must construct and own the registry used by every request.

## Steps

1. Add a gateway configuration loader/registry factory beside agents_gateway_profiles.py that reads the gateway-owned profile definitions and creates an immutable GatewayProfileRegistry snapshot with generation/config_digest per profile. 2. Initialize it exactly once in GatewayServiceHost/GatewayServiceApplication startup before readiness and ingress; call set_gateway_registry(registry). 3. Add an atomic reload_profile_registry() service operation: load/validate candidate config, construct a complete new registry, swap the pointer under a short lock, and retain the previous registry on failure. 4. Publish only redacted reload outcome/generation metadata. 5. Reject shared-mode requests when the requested profile is absent or disallowed; do not fall back to project-local limits. 6. Preserve embedded compatibility only when no shared service host is active. 7. Existing running requests retain their snapshot; queued stale snapshots reject with CON-AGW-101/resubmit-required. 8. Add a production-path test with two project roots proving one global lane limit, live reload/generation rejection, and no interruption of a running request. 9. Add a self-review test for secret/path redaction in status and queue overview.

## Files

src/audiagentic/components/agents/agents_gateway_profiles.py; src/audiagentic/components/agents/agents_gateway_service_host.py; src/audiagentic/components/agents/agents_gateway_service_application.py; src/audiagentic/components/agents/agents_gateway_api.py; tests/unit/agents/test_agents_gateway_profiles.py; tests/integration/agents/test_gateway_e2e_states.py

## Validation

Focused profile/API/queue/service tests; reload success/failure/concurrency tests; standalone service-path test proving running work survives reload and queued stale work is rejected.

GatewayServiceHost.create now loads gateway-owned profile definitions from a machine-scoped gateway-profiles.yaml (audiagentic_home()/config/, overridable via gateway_profiles_config param) through agents_gateway_profiles.load_gateway_registry_from_config(), and calls set_gateway_registry() before the store/server are constructed — so shared mode is registry-authoritative from the first admitted request, not a manual wiring step. host.close() clears the registry. 2026-07-20 steps 3-9 landed via SH13 implementation:
- **Step 3 (atomic reload, off-thread):** `reload_profile_registry()` now builds the new registry on a worker thread via ThreadPoolExecutor (config I/O + YAML parsing doesn't block the calling thread). Atomic swap under `_gateway_registry_lock`; previous registry retained on failure. Config path recorded at startup so reload can re-read from the same source.
- **Step 4 (redacted event):** On successful reload, publishes `agents.llm.gateway.profile-reloaded` event with only config-path (filename), old/new generation summaries (profile ids, generations, config digests — no secrets). Event topic registered in agents/events.yaml and agents_event_topics.py.
- **MCP/service reload+status:** Service operation `reload_gateway_profiles` wired in GatewayServiceApplication.invoke(). New MCP tools: `agent_llm_gateway_profiles_reload(config_path?)` and `agent_llm_gateway_profiles_status()` for operator access. Capability `gateway-profiles.reload` declared.
- **Step 5 (absent profile rejection):** Already covered by RES-AGP-001 from InMemoryGatewayRegistry.resolve_snapshot(). Proven in `test_absent_shared_profile_rejected_not_fallback`.
- **Step 6 (embedded compatibility):** Already covered — no registry = embedded mode via snapshot_from_resolved_profile(). Proven in `test_embedded_compatibility_when_no_shared_registry`.
- **Step 7 (running retains, queued stale rejected):** CON-AGW-101 rejection in GatewayQueueManager.enqueue() and _run_one() dispatch gate. Running requests keep their admission-time snapshot — the validator checks against current registry; a running request's worker thread was validated before starting and never re-checked. Proven in `test_stale_queued_snapshot_rejected_on_reload`.
- **Step 8 (production-path test with reload + stale rejection):** `test_stale_queued_snapshot_rejected_on_reload` — two project roots, max-concurrency=1, first request runs, second queues, reload changes generation, queued request rejected CON-AGW-101, running request completes. Added `test_reload_concurrency_no_state_corruption` — concurrent reload and admission during a running request proves atomic swap prevents torn state.
- **Step 9 (redaction self-review):** `test_redacted_status_no_secrets_in_overview` — gateway overview and reload result contain no secret values or api-key keys.
