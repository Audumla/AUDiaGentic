# ACP wire negotiation and live client qualification (SH62b)

## Description

Pinned ACP wire/SDK negotiation and live-client qualification for the SH62a adapter. Split from SH62 because it needs a real ACP client (and the pinned agent-client-protocol 0.11.0 behaviour for JSON-RPC error mapping) that is not available in the hermetic environment.

## Steps

1. Pin ACP wire version 1 (integer) and the tested SDK; confirm initialize negotiation advertises only implemented capabilities (loadSession today) and refuses unsupported protocol versions.
2. Verify how the SDK serializes the registered errors (CON-ACP-001 prompt outstanding, CON-ACP-002 work failed/rejected, VAL-ACP-003 prompt without text, CON-AGW-167): they are AudiaGenticError, not RequestError, so confirm the JSON-RPC error a client actually sees and map them to RequestError with the registered code in data if needed.
3. Qualify with a real ACP client: prompt concurrency (second prompt refused), cancel races, late output after cancel, reconnect/reload behaviour of load_session/resume_session against durable Work, close_session cancelling outstanding Work.
4. Decide and document the reconnect story: ACP 0.11 has no client retry identity, so a transport retry is a new prompt.
