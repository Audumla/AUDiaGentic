# Workflow-driven gateway reconciliation, retention, and replaceable queue backends

## Description

Add a compact operator-management application for durable gateway state without coupling policy to the current filesystem store or in-process scheduler. The workflow owns management-operation lifecycle; evidence readers classify targets; existing request/session transition authorities own lifecycle mutation; archive/purge are a separate retention concern. Define queue and record-store ports now so MQTT, NATS JetStream, RabbitMQ, Redis Streams, or another broker can replace the current queue later without changing gateway semantics.

## Steps

1. Add `gateway-management-operation` to agents/workflows.yaml with only accepted -> running -> completed|failed. Keep LIVE/PROVEN_DEAD/UNKNOWN evidence and changed/unchanged/blocked target dispositions out of the operation state machine.
2. Define closed DTOs and ports: ManagementCommand/Result, WorkEvidenceReader, GatewayQueueBackend, GatewayRecordRepository, ArchiveRepository. Adapters must not own transition, retention, or process policy.
3. Implement a durable operation store with operation-id idempotency and conflict rejection. Acceptance acknowledges receipt only; it never claims effects completed.
4. Implement read-only census and dry-run reconcile first. Join current-owner/attempt fencing, queue claim facts, SH22 worker evidence, and AS91 session/process evidence into LIVE, PROVEN_DEAD, or UNKNOWN. Absence, age, silence, timeout, empty local queue, or missing local handle are never PROVEN_DEAD.
5. Apply reconcile through the existing request/session terminal-transition authorities with expected revision, attempt epoch, and owner epoch. UNKNOWN and stale-fence results are blocked with no mutation.
6. Implement archive as a retention transition over terminal records only, preserving execution outcome, timelines, session/provider continuation references, and predecessor/successor links. Archive must not add values to the execution-state workflow.
7. Implement purge only for already-archived, retention-qualified records after safety revalidation. Require explicit confirmation/policy, retain a redacted tombstone where referential/audit integrity requires it, and report recoverability.
8. Expose one application contract through service/client/MCP/CLI parity. Provide operator workflows for status, drain, reconcile --dry-run/apply, archive, purge, and clean/reset composition. Bulk commands select through repository queries, never filesystem globs.
9. Add backend capability/health projection and an outbox/claim contract so admission plus durable publication cannot create an untracked request. MQTT is an adapter option/notification transport unless it can satisfy the full claim/ack/redelivery/fencing contract; broker delivery never becomes lifecycle authority.
10. Add restart, duplicate delivery, reconnect-at-deadline, mixed live/stale, multi-project, and backend contract tests. Use SH11 soak to certify automatic/shared mode before changing the default.

## Detailed Solution & Technical Design

Architecture boundaries:
- `GatewayManagementApplication` orchestrates operations but owns no provider/process mechanics.
- `agents/workflows.yaml` declares management-operation lifecycle; the generic workflow validator remains host-agnostic and needs no gateway dependency.
- `WorkEvidenceReader` returns only LIVE, PROVEN_DEAD, UNKNOWN plus bounded reason/source/fence facts. SH22 and AS91 supply evidence; they do not terminalize/archive/purge.
- Existing gateway request/session stores remain the only execution lifecycle authorities.
- Retention is orthogonal metadata/repository state. A closed/failed session can retain a durable provider chat reference and be resumed as a linked generation after its browser tab/process is gone.
- `GatewayQueueBackend` minimum semantics: durable publish, exclusive fenced claim, lease/heartbeat, ack terminal delivery, nack/requeue, dead-letter routing, depth/health, drain admission, and idempotent recovery. Queue state is delivery state, not request lifecycle state.
- Every destructive effect rechecks preconditions at the mutation boundary; no operation trusts an earlier census snapshot.
- Operation states: accepted, running, completed, failed. Target dispositions: changed, unchanged, blocked. Evidence: live, proven-dead, unknown.
