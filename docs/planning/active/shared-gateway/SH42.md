# Deliver shared gateway tooling documentation observability and installed qualification

## Description

Release qualification for each implemented, advertised stage: standalone ingress, caller-local nodes, individual qualified joined surfaces, and external A2A/ACP separately. No universal gate forces all stages to ship together.

## Steps

1. Update owning CLI/MCP/config/schema/errors/events/instruction contributions for operations actually delivered.
2. Update packaged help/deployment/migration guides and appropriate ownership labels for that stage.
3. Check compact authorized outputs, redacted correlated traces, applicable retention and honest terminal/uncertain states.
4. Run installed and live qualification for the supported topology and advertised capabilities; qualify each joined harness/version/platform individually.
5. Record source review, applicable test/live evidence and ledger coverage; report each stage independently.

## Detailed Solution & Technical Design

Reuse canonical request/session/Context/Work APIs and existing owner documentation/instruction contributions. No second output projection, diagnostics store or Provider capability matrix. Apply metadata/schema/API parity, authorization, redaction and compact response requirements to the delivered operations.

Stage 1 closes with SH37 standalone service evidence. Stage 2 adds SH38 node/reconnect/workspace evidence. Stage 3 adds SH39/SH40 and SH41 proof for each advertised native surface. Stage 4 adds SH43 wire/continuation evidence. A stage can ship with unsupported capabilities explicitly absent; zero native proofs cannot be called working joins. Protocol qualification does not block native attachment or server-only serving.

Review changed imports/config registration/composition using an exact checkout; no specific reviewer host is required. Measure startup/resource use and admission/dispatch overhead for the shipped topology. Broader percentiles, replay/probe/lock/WAL benchmarks are follow-up unless a measured issue or explicit target warrants them. Keep concrete gates: help has no app/browser startup; no lock spans native/human waits; bounded payloads/buffers/replay; compact nonduplicated output. Pin wire/SDK versions only for protocols actually exposed; future specs trigger review, not speculative implementations.

Independent target-state review observability/delivery clarification: distinguish source caller workspace identity from recipient placement even when initial policy requires equality. Private caller locators and credentials must not leak into public diagnostics. Record stage-specific admission, preparation, effect authorization, receipt/cursor, artifact publication and recovery timings so infrastructure tests cannot masquerade as native execution proof. Return canonical response text and explicitly bounded artifact transfer; recipient-local paths are not client-accessible artifact URLs. Retention must preserve active, unresolved and unacknowledged custody evidence.

User-mandated error-management gate: reuse canonical error catalogue, FailureClass/ObservationPhase/SideEffectState/RecoveryDisposition, request-owned observation journals and resource timelines. For each node admission/preparation/authorization/effect/receipt/ACK/artifact/publication/recovery boundary, specify the owning state, registered error code, bounded reason, retry/wait/reconcile/terminal policy, causal correlation and elapsed/queue/lock timing. Log connection liveness separately from actual execution progress. Preserve original/historical command identity plus current channel epoch/generation and custody cursor; never use logs as effect authority. Retry only proven safe operations with bounded backoff and cancellation, silently recover transient connectivity where safe, and never replay an uncertain effect. Diagnostic writes must not hold grants/request locks across I/O or undo committed success; custody write uncertainty must prevent ACK/new effects. Keep public tool responses compact with explicit diagnostics/evidence retrieval. Use existing retention/rotation owners with active/unresolved/unacknowledged/pinned protection; do not create a second telemetry store or scheduler.

Terminal Dev GPT design at source004ef17d8: canonical request/receipt state remains authoritative; observations, connection liveness and synthetic activity never prove effect acceptance/completion or authorize replay. Implement directly in the SH38 vertical path, not a tracing framework. Reuse record_timeline_event/store.record_gateway_timeline for milestones, append_observation for redacted stage facts, existing diagnostics enums and error catalogue, RecoveryDeferred/work_index for bounded recovery and journal_retention for maintenance. Before request association, the existing connection/service owner emits bounded structured diagnostics; use the existing operational sidecar primitive only when cross-resource durable audit is required.

Failure/recovery matrix: invalid credential/grant -> deny before admission/effect; invalid role/frame/sequence/identity -> close channel and preserve state; transient disconnect with proven no effect -> bounded reconnect/revalidation; preparation timeout -> reconcile retained preparation, not blind resend; revoke/drain -> prohibit new effects while accepting authorized historical custody; root/profile drift -> blocked until repaired binding/configuration; persistence failure -> read durable canonical state because a raised write may have committed; worker failure before effect -> retry only with explicit nonexecution proof; worker failure after intent -> uncertain/reconcile exact command; cancellation before intent -> canonical cancel CAS wins; after intent -> pending/uncertain until native/canonical outcome; receipt gap/mismatch -> stop stream and resume exact cursor; cursor persistence uncertainty -> poison stream, no ACK/effect advancement; artifact integrity failure -> prohibit publication, bounded immutable refetch; publication/cancel race -> preserve canonical winner, no overwrite or replay.

Prioritize first-cause NodeChannelFailure in the existing transport owner: bounded registered code, reason category, stage, validated frame type/sequence, current generation and UTC time; never retain frame payload/exception string. Preserve the first causal failure across teardown and distinguish normal close/replacement/revocation from protocol rejection. Request-associated runtime boundaries emit node.admitted/queue-claimed/dispatch-deferred; connected/disconnected/revoked; prepare-started/prepared/prepare-rejected; effect-requested/authorized/denied/intent-retained; worker-terminal; receipt-retained/committed/acknowledged; artifact-verified/rejected; publication-completed/conflict; reconcile-started/deferred/completed. Emit native-accepted only where actual native proof exists, not worker start.

Detailed traces correlate request/session/correlation, command/worker/attempt, original node/gateway epochs, current channel generation, grant revision and receipt log/sequence/digest where available. Measure local stage durations with monotonic_ns and correlate across machines with identities/UTC; never subtract unrelated monotonic clocks. Keep compact status to execution location, stage, bounded reason/error and safe recovery disposition; use existing explicit authenticated diagnostics/observations/evidence reads for detail. Check existing observation projection allowlists so needed fields survive rather than silently disappear.

Retries use existing policy owners: only idempotent reconnect/receipt observation/immutable artifact fetch may retry, bounded with cancellation/backoff and eventual durable defer. Proposed immediate reconnect baseline 0.5–15s jitter, four attempts then RecoveryDeferred; verify existing policy compatibility before implementing, not a separately hard-coded loop. Node-aware startup recovery requeues only proven unsent admitted records; uncertain effect states reconcile original node command; terminal custody without publication retrieves verified output. Ordinary local recovery must never execute a node-placed request.

Retention: reuse newest100 eligible histories, capped daily journal heads/segments and eligible terminal five-day expiry. Active/unresolved/recovery-required/pinned and unacknowledged custody/incomplete artifact/unresolved publication evidence remain protected. Recovery-action journals remain control evidence until explicit purge. Coalesce repeated equivalent connect/heartbeat diagnostics; never sample the first failure, effect/ownership/custody/terminal event or changed recovery disposition. Best-effort trace sink failures produce bounded sanitized warning and an in-process counter without recursive logging; they cannot reverse committed success. Authoritative receipt/checkpoint/persistence uncertainty prohibits further ACK/effect progression.
