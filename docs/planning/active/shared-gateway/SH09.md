# Move cross-process gateway triggers onto a durable external event transport

## Description

Evolve the current in-process EventBus contract so external event adapters can deliver work to the shared gateway across harness processes. Introduce a proper queue/broker transport (MQTT or another selected implementation) without coupling gateway application logic to one vendor. Event subscribers remain thin adapters: validate/translate the delivery envelope, invoke the public idempotent admission API, acknowledge according to the transport outcome, and publish through owned event APIs; they do not own dispatch, retries, persistence, or job policy.

## Steps

1. Characterize existing agents.llm.gateway.* and lifecycle topic contracts, correlation metadata, subscriber failure behavior, and event-driven job dead-letter/replay paths. 2. Define transport requirements: durable delivery, consumer ownership, acknowledgement, redelivery, ordering scope, backpressure, authentication, local/offline behavior, and topic versioning. 3. Select/prototype the first external transport through EventBusProtocol and document why. 4. Map event delivery identity to the gateway idempotency key. 5. Add reconnect, duplicate, out-of-order, poison-message, broker-unavailable, and dead-letter recovery tests. 6. Preserve direct local IPC submission for synchronous management/status operations.

## Files

foundation event transport implementation/config; thin gateway event ingress adapter plus public admission API; topic descriptors; dead-letter/replay integration; tests and operations docs

## Validation

A trigger published from a separate process is durably admitted once despite redelivery; broker outage has an explicit degraded outcome; lifecycle events retain correlation and are consumable cross-process; poison messages do not block the queue. Gateway core imports no broker/MQTT implementation; event handlers import no gateway store/queue/dispatch internals.

## Effort & Risk

Complex operational dependency. MQTT is a candidate, not a foregone conclusion; selection must be driven by delivery and deployment requirements.

## Standards

AR25; Architecture Standards §§1,4,5,6,7; Observability Standards.

## Notes

Depends on SH07 and AR25. Event transport carries the SH02 execution envelope or a durable reference to it; it must not rely on the publisher's process environment.
