## Description

Slice of SH41. Disposable human-serving App Server/thread test: passive attach, human coexistence, correlated prompt/result, atomic admission, reconnect, no-kill. Publish only proven facts. Depends on SH53.

## Steps

4. Test two independent callers, human activity, atomic busy rejection, exact acceptance receipts and request-specific results.
5. Test disconnect, reconnect, stale identity and non-destructive detach.
6. Publish only individually proven capabilities through evidence.build_record / write_evidence; leave the rest false with an explicit unsupported reason.

MEASURED on codex-cli 0.166.0 linux-amd64 with a local deterministic stub model (probes/stub_model.py): conditional-admission is UNSUPPORTED: turn/start on a thread with an active turn does not reject or queue, it steers: the second caller gets the ACTIVE turn's own id, the model receives an extra request inside that turn and the active turn's output changes. correlated-result is UNSUPPORTED for concurrent callers (they share the active turn id) although idle callers are attributed by native turn id. `codex queue` returns a native message id and does not interrupt the stream but delivers into the same active turn at its next model request. So the Codex app-server surface cannot satisfy SH46's mandatory conditional-admission/correlated-result: readiness stays UNSUPPORTED, which is the correct evidence-backed verdict for this route; safe delivery would have to be gateway-side queueing until thread/status is idle (non-atomic: a human can start a turn between the check and turn/start), which SH40's own text forbids claiming as atomic.
