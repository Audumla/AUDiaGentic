# Implement A2A and external ACP interoperability over qualified session targets

## Description

User clarified A2A and ACP are both required. Reuse existing Agents protocol projections over canonical Context/Work and qualified joined/owned execution; no native A2A requirement on the four harnesses. Design governed by SH35/SH36 and canonical execution contract.

## Steps

1. Audit superseded AS65/AS66 against current A2A/ACP semantic adapters, SDK/wire versions and owning public ports.
2. Add owner-validated optional joined target to Context binding and explicit Work->execution target propagation; no adapter registry/native metadata routing.
3. Correct protocol message identity/idempotency, continuation and version/capability negotiation; preserve distinct identical-text messages.
4. Make async response/terminal/cancel/auth semantics truthful and scoped through canonical owners.
5. Qualify actual external A2A and ACP clients, joined and owned routing, schemas/help/metadata and two-client multi-turn/restart behavior.

## Detailed Solution & Technical Design

Existing protocols/a2a server/card/mapping and protocols/acp agent/server/mapping are semantic seams, not proof of deployable standards compliance. Agents application/Context/Work owns target binding, idempotency, state, waits and authorization; protocols translate only. A2A context maps canonical Context, task maps Work; external ACP session maps Context, distinct from gateway/native session. Expose target Context correlation from authorized join/status APIs so other clients can use standard context IDs without custom native routing fields. Existing submit_agent_work defaults to new/owned execution and uses reserved idempotency metadata; fix through explicit owner admission. Do not trust arbitrary existing context/task IDs across principal or agent. Source hazards: content-hash message identity in both adapters; A2A taskId ignores a new message; ACP prompt reads output immediately/returns end_turn without terminal proof and initialize echoes input version. Native join remains gated by SH39/SH41 and external detach SH40. Internal node channel is not another A2A scheduler. No outbound arbitrary remote-agent discovery is added.
