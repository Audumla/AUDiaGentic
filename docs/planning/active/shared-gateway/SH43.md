# Implement A2A and external ACP interoperability over qualified session targets

## Description

Stage 4 required eventual interoperability; not a prerequisite for standalone gateway, caller-local node execution or qualified native joining releases. User clarified A2A and ACP are both required. Reuse existing Agents protocol projections over canonical Context/Work and qualified joined/owned execution; no native A2A requirement on the four harnesses. Design governed by SH35/SH36 and canonical execution contract.

## Steps

1. Audit superseded AS65/AS66 against current A2A/ACP semantic adapters, SDK/wire versions and owning public ports.
2. Add owner-validated optional joined target to Context binding and explicit Work->execution target propagation; no adapter registry/native metadata routing.
3. Correct protocol message identity/idempotency, continuation and version/capability negotiation; preserve distinct identical-text messages.
4. Make async response/terminal/cancel/auth semantics truthful and scoped through canonical owners.
5. Qualify actual external A2A and ACP clients, joined and owned routing, schemas/help/metadata and two-client multi-turn/restart behavior.

## Detailed Solution & Technical Design

Terminal Dev GPT staged implementation seed: extend existing Work owner with atomic accepted-message metadata and immutable dispatch intent under existing locks, plus the smallest parent acceptance lock for contextless sender/project/agent/message lookup. Input/history/queue links are repairable projections of accepted command, never latest input. Continuation preserves Work identity and validates lifecycle/ownership/target; terminal continuation rejects. Add correlated terminal wait public-port parity outside locks before thin A2A/ACP corrections and real SDK-client qualification. No adapter-local dedupe, parallel task store or scheduler.

Primary-source validation refines version terminology: ACP wire version is integer1, distinct from optional PythonSDK0.11.0/currentstable0.12.1; v2 is draft with different prompt acceptance semantics and is not target support. A2A1.0 JSON-RPC uses SendMessage (not legacy message/send), with message.taskId/contextId and actual typed request/response aliases; blockingdefault versus returnImmediately must match the selected published schema. CurrentoptionalSDKpins1.1.2/0.11.0 require explicit compatibility assessment versusverifiedcurrent1.2.3/0.12.1. Pin one tested wire/SDK target, never mix0.3/A2A1.0 orACP1/v2draft. Sources and unresolvedselection are retained in the associated review; no conformance claim yet.
