# Canonical Work identity and continuation

## Description

Slice of SH43 (A2A and external ACP interoperability). Atomic message acceptance, idempotency, immutable target selection, authorized Context/Work continuation and crash consistency. Distinguish identical text from identical message identity. Depends on SH38's ownership contracts.

## Steps

1. Extend the canonical Context/Work owners behind gateway/application.py with authenticated message identity, a payload digest and an immutable validated execution target.
2. Commit acceptance and dispatch intent atomically before queueing; repair a missing input or queue projection using the same identity.
3. Enforce issuer/subject, project, Context, Work and target scope at acceptance and at continuation.
4. Distinguish same-key replay, changed-payload conflict and distinct messages with identical text.
5. Continuation lifecycle: existing Work keeps its identity; context-only input creates new Work; terminal Work rejects continuation.
6. Expose canonical terminal waiting through the public ports, outside mutation locks.
