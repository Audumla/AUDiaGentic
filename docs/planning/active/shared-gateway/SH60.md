# Canonical Work identity and continuation

## Description

Slice of SH43 (A2A and external ACP interoperability). Atomic message acceptance, idempotency, immutable target selection, authorized Context/Work continuation and crash consistency. Distinguish identical text from identical message identity. Depends on SH38's ownership contracts.

## Steps

Slices (order SH60a -> SH60b -> SH60c -> SH61/SH62), each one worktree and one PR via `audiagentic worktree ship`:
SH60a Identity and atomic acceptance (work/contracts.py, store.py, service.py, inputs.py, record validation):
1. Canonical delivery identity = (authenticated principal, optional verified delegated subject, protocol, project-id, context-id, target-generation, protocol-message-id). A2A uses the protocol-supplied message id; ACP generates a unique owner command id per accepted prompt (no durable client retry identity exists).
2. Store in the Work-owned record, in ONE atomic record.json replacement under the existing agent_work_lock_path/StartupLock: Work and Context association, accepted message identity, canonical payload digest (text, inputs, immutable intent; excludes created_at), the durable payload, the frozen execution target and dispatch intent, and the stable command/request idempotency identity. inputs.ndjson becomes a repairable projection, never the commit point.
3. Same identity + same digest returns the original receipt; same identity + different digest is a registered conflict; different identity with identical text is a separate accepted command. Historical records without the new fields stay readable and are never replayed.
SH60b Dispatch and continuation (work/service.py, store.py, gateway/application.py, request admission):
4. After the commit, reconstruct inputs, gateway admission and the execution link idempotently via store/_admission.py admit_record and existing queue ownership; dispatch is rebuilt from the durable command, never from latest_work_input. A crash after acceptance never creates a second native effect.
5. Continuation: taskId/workId appends a new command to the existing non-terminal Work (needs sequential execution history because link_execution allows one execution id today); contextId only creates new Work; terminal Work rejects new continuation but returns the original receipt for an exact committed replay; a closed Context rejects.
SH60c Authenticated ports and waiting (gateway/application.py, client.py, remote_client.py, service/application.py, shared_ingress.py, errors/events):
6. Add accept_agent_work_message(project_root, *, context_id, message, delivery_identity, work_id=None) and wait_agent_work(project_root, work_id, *, timeout_seconds=120.0) to GatewayApplication, GatewayClient and remote_client. delivery_identity is built by trusted ingress, never taken from the caller. Establish a trusted principal context at ingress first (shared_ingress _ACTIONS has no Context/Work actions today). wait returns correlated Work state, execution identity and terminal/interrupted disposition, waits outside every mutation lock, and a timeout returns the non-terminal state.
7. Register distinct errors (delivery conflict, unauthorized scope, terminal continuation, invalid identity, terminal result unavailable) and bounded Work milestones (message.accepted, message.replayed, message.conflict, dispatch.repair, execution.linked, work.terminal) through foundation.observability.
