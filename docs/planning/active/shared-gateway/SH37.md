# Implement standalone shared-service ingress and keyword lifecycle CLI

## Description

Stage 1: standalone keyword CLI, authenticated remote clients and server-hosted execution, independently releasable before nodes, joined harnesses and external protocols. Reuse the existing host/client/request/session owners. Contract: docs/design/shared-gateway-execution-contract.md.

## Steps

1. Separate pure help and gateway composition from interactive startup.
2. Deliver gateway serve config FILE, explicit connect configuration, help and basic status; reuse existing lifecycle owners for additional implemented operations.
3. Add versioned authenticated shared ingress behind TLS, project/action grants, bounded payloads and a non-public loopback backend.
4. Map configured server project IDs to real server-local roots through existing owner scope; one configured service profile. Never accept client filesystem paths or add a separate registry.
5. Validate installed independent service, two clients, terminal output and restart/disconnect recovery; release this slice without waiting for later stages.

## Detailed Solution & Technical Design

Stage 1 extends existing Agents service/host/client/queue/request/session APIs; CLI/MCP/HTTP handlers translate only. Provider execution remains behind providers_api. Preserve existing owned execution, durable request admission, terminal evidence and no-blind-replay semantics. The wheel is the initial deployment; slimming packages is separate.

Freeze only server/connector fields, defaults, connection writer and credential handling needed for this stage. Validate authentication, principal/project/action scope, TLS front-door trust and backend exclusion. Reuse a concrete configured credential/identity profile; do not build a generic delegation framework. HTTP MCP-specific authorization applies only if that transport is exposed. Never expose legacy local dashboard/control routes remotely or auto-fallback to local embedded execution.

Node transport/schema, node authorization/receipts, native qualification, joined bindings and protocol Work continuation belong to later stages, not stage 1 prerequisites. Scope architecture review to changed imports, registration and composition. Measure startup/resource and request overhead against a stated baseline; optimization is required for demonstrated regressions, not a universal benchmark programme.

### Verified reuse and boundary constraints
Use the concrete reuse map in docs/design/shared-gateway-execution-contract.md: ManagedServiceStore/Lifecycle/Owner, StandaloneGatewayClient, existing queue/session/recovery, Foundation I/O/config/schema/path/errors and owning implementation binding. Keep gateway grants and native readiness in their component owners, not Foundation. Trace launcher dispatch, commands/gateway.py, service/bootstrap.py, Agents MCP declarations and configured factories at the delivered revision. Existing Provider-internal imports are baseline debt: remediate touched/exercised edges through narrow Provider-owned operations, not helper re-exports or a blanket new framework. No full-gateway compliance claim until remaining prohibited edges are resolved.
