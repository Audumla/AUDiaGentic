# Installed native admission requires packaged model-source defaults and contracts

## Notes

Follow-up exact public surface resolution in the original isolated ACP test root showed unavailable / disabled-provider. The test root's feature state had not yet enabled Codex. This was configuration setup, NOT proof that installed Codex0.153.4 or its ACP bridge was unsupported. Read-only production-root inventory resolves owned ACP as declared supported, but attach-existing remains unsupported and native joins unqualified. The independent CLI qualification explicitly enabled Codex through Foundation feature state in isolated test workspaces and passed two real executions; no production profile or global catalog was changed.

## Findings

Independent installed-service native admission failed before dispatch with CFG-CONF-001: Providers model-sources-default.yaml omitted from wheel. Inventory also found component-owned agent-jobs and ledger JSON contracts excluded by the current narrow package-data list. Earlier source and application-double TLS tests could not expose this. The production Codex ACP profile also correctly rejected unresolved/unvalidated current surface; qualification must not relabel it supported or silently fall back.

## Conclusion

Include Provider contract YAML and a single canonical component-contract JSON package pattern (remove duplicate narrower JSON entries). Extend installed-release/Docker asset checks for actual runtime defaults and schemas. Qualify an explicitly configured isolated CLI profile, preserving live global catalog and Codex user configuration. Keep SH37 in_progress until actual native transport and recovery proof completes.
