# Crash between pre-submit checkpoint and provider Send

## Notes

Finding incorporated in implementation: submission-state=prepared is persisted before any Send action; dispatching is persisted before the CDP side effect; only a request-id-matched prepared checkpoint reloads the frozen admitted prompt and reopens the session. Ambiguous/legacy checkpoints stay observation-only. Focused tests pass. Independent GPT review is still pending.

## Findings

- - **Severity**: high
    - **Finding**: A running GPT-auto request can be interrupted after gateway owner takeover when the session has no provider-session-ref yet. The current turn writes unresolved-turn-pending/recovery-state=side-effect-may-have-started immediately before browser submit, but a process exit in the intervening window leaves no durable distinction between prepared and Send-dispatched. Restart recovery treats the missing provider binding as an identical rehydrate error, retries it six times, then transitions the request to interrupted.
    - **Evidence**: BigCherry req_example_06178dc57433: request timeline has only initial preflight and attempt-start events; session binding is null; provider-metadata has project-url and target-id but no chat-url/provider-session-id; observations stop before provider conversation binding; gateway owner takeover occurs four seconds after the request's first turn activity; recovery exhausts with CON-AGW-084 rooted in CON-AGW-124.
- - **Severity**: high
    - **Finding**: Recovery must distinguish a durable pre-send prepared checkpoint from a side-effect-dispatched/ambiguous checkpoint. Only the explicit prepared state may load the frozen admitted prompt and reopen/start a project chat. Missing checkpoint, interrupted send, or any ambiguous state must remain observation-only and must never replay.

## Conclusion

SH34 needs an explicit durable submission boundary and an exact-once safe restart path for the proven pre-send window. The current generic bounded retries cannot repair a missing provider binding and only delay interruption.
