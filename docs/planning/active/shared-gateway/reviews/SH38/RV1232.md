# Close native execution integration gates for draining, verified terminal proof and artifact publication

## Notes



## Findings

Terminal GPT design assessment identified three P1 integration gates before enabling native routing: (1) valid credential + disabled work grant must authenticate only justified original accepted-work reconciliation in DRAIN capability, not interrupt already accepted work or admit new effects; credential invalidation remains separate. (2) only trusted supervisor-generated immutable verified worker identity/process/result may produce direct terminal-from-intent; peer JSON and cleanup-return alone are not proof. (3) protected typed output envelope must retain unambiguous durable proof kind, preserve public receipt/ACK digest compatibility, and central publisher must validate original identities/hash then publish exact assistant text under current read policy, not envelope JSON. Additional runtime requirement: deferred DB epoch rotation until old worker terminal write and verified closure, prepared-unsent retirement only after durable custody and exact never-authorized evidence.

## Conclusion

Keep native effects disabled. Implement and test these gates in the existing owners; independent primitive approvals do not establish end-to-end readiness. Close only after actual runtime integration and qualifying tests, not merely design discussion.
