# Bound node prepare-reject retry instead of spinning indefinitely with coarse error codes

## Notes



## Findings

Discovered during the first real two-machine native-execution qualification (brutus<->Windows gateway): when the node deterministically rejects a prepare request (PreparationRejected), the gateway retries indefinitely with no backoff and no terminal disposition. Observed 213 identical attempts in ~40 seconds for one record. The cycle: each reject ends the node's quiescent cycle -> node sends receipt-ready -> gateway's mark_ready fires notify_node_changed -> queue drains -> NodeRunner prepares again -> node rejects again, forever. Nothing ever makes the request terminal on a deterministic (non-transient) rejection. Separately, the gateway only sees a coarse registered code because NodeRecipientRuntime._safe_code collapses every exception to one of VAL/CON/IO-AGND-001, and RecipientFailure (_remember) retains only the first error, hiding the actual recurring cause from diagnostics. In this qualification session the deterministic rejections were all harness configuration errors (fictional caller_root, placeholder binding-sha256 instead of the real computed hash, missing node-side profile registry, stale local receipt state) -- not product bugs -- but a real misconfigured node (e.g. a genuinely unsupported workspace binding or missing local profile) would spin in the exact same unbounded loop.

## Conclusion

Two options to evaluate, not yet implemented: (a) a bounded attempt count or backoff specifically when the reply is a prepare-rejected whose evidence proves no effect occurred (safe to bound since no native work was ever attempted); (b) a finer, still-safe/non-leaking reason code distinguishing configuration-mismatch rejections (e.g. workspace-binding-mismatch, profile-unavailable) from transient ones, so an operator isn't stuck reading identical generic retries with no actionable signal. Keep existing never-infer-no-effect-from-timeout-alone and never-replay-uncertain-effect invariants intact; this is about bounding/classifying a *proven* deterministic non-effect rejection, not relaxing any uncertainty handling. Not assigned/started; raised as a tracked finding from live qualification, for whoever picks up the remaining RV1232/SH38 work next.
