# Recover definitively unauthorized bound node commands without replaying uncertain effects

## Notes



## Findings

During full-path artifact/custody integration, a queued command can become canonically bound but never obtain durable effect authorization before a disconnect. Existing recovery correctly treats every non-null bind as observation-only, so an authorization-id absent/not-authorized bind can remain blocked although the central authority never permitted native execution. This is distinct from authorized/uncertain commands, which must never replay. A late authorization callback races with any rebind policy and must lose by canonical owner/attempt/revision identity CAS.

## Conclusion

After normal sender/publication readiness, assess with Dev GPT a narrow positive no-authorization recovery disposition using original canonical metadata, current owner and a retired original connection, preserving immutable prior binding evidence via existing recovery control journals and original prompt provenance. Never infer no-effect from send timeout or peer absence alone. Do not change bound-command replay behavior without owned atomic negative-proof/attempt fencing and late-authorization race tests. Authorized or uncertain commands remain original-command reconciliation only. Track explicitly; no automatic cleanup/resend added in current finite transport slices.
