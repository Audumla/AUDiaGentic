# Make node failure diagnosis and recovery a required delivery gate

## Notes

This records an outstanding implementation gap, not a claim the approved transport/admission primitives deliver runtime observability. Dev GPT design requested in the existing review conversation.

## Findings

User explicitly requires exceptional error handling, logging, observability and recovery. Existing observability standard requires resource-owned durable milestones and redacted degraded-service outcomes. Current node primitives establish custody but node channel failure retains only a generic code; node stage traces, reason taxonomy, repair classification, correlated timings and runtime fault-injection evidence are not yet delivered. Existing gateway request journals, diagnostics vocabulary, work index, registered AGND errors, timelines and retention owners must be reused rather than duplicated.

## Conclusion

Design with Dev GPT before runtime enablement. Require every failure boundary to preserve truthful effect state and identify retry-safe, wait/reconnect, reconcile-required or terminal disposition with a compact public status and explicit detailed trace retrieval. Never infer success from heartbeat or replay uncertain effects. Keep instrumentation best-effort outside critical mutation locks; custody persistence failures prohibit ACK/effect progression. Protect active/unresolved/unacknowledged evidence from retention.
