# Implement supervised execution nodes and node-local workspace authority

## Description

Delivery follow-up to SH35/SH36. Central gateway controls local execution against caller files through one enrolled independently supervised node. No MCP-scoped second lifetime mode.

## Steps

1. Reuse managed-service lifetime and configure node enrollment/workspace grants.
2. Add outbound authenticated versioned WSS channel with bounded queues/checkpoints and independent control I/O.
3. Resolve manifests/provider/platform facts on execution node, centralize only authorized identity/digest/storage scope.
4. Fence node boot epochs/writer claims and reconcile after disconnect without duplicate dispatch.
5. Prove local file authority, blocked-MCP survival, restart/revocation and no second scheduler.

## Detailed Solution & Technical Design

Depends on shared ingress delivery and final reviewed SH35/SH36 contract. Gateway owns FIFO/request/session, node owns effects and receipts. Scope by principal/node/workspace; no remote Path.resolve or fake checkout. One profile/process, local credentials, no arbitrary remote roots. Preserve existing worker/factory boundaries and browser execution placement. Use existing owner artifact access where available; otherwise report node-local-only availability explicitly. New transfer infrastructure is separate work.

### Final GPT implementation-entry constraints
Specify node boot epoch and writer identity, bounded command/evidence frame schema/version, producer sequence and checkpoint ownership, heartbeat versus native readiness, node-local manifest attestation and protected persistent receipt location before coding the channel. Gateway central scope is principal/node/workspace; never fabricate a server checkout or trust a client-provided platform hint. Depends on SH37 ingress; SH41 native qualification can proceed independently.

### Deep-review node authority and receipt decisions
The admission/recovery addendum defines separate gateway owner and node WAL facts, epoch/generation/digest-bound commands and native acceptance receipt ordering. Node accepts effects only under current scoped authorization; disconnected stale epochs cannot obtain new sends. Prepared, effect-intent and accepted receipts differ; a crash after effect intent cannot be inferred unsent. Require current command-scoped authorization before effect; reuse authorized dispatch where it satisfies the documented revocation ordering. A separate confirmation round trip needs demonstrated justification. No offline lease/skew mode in MVP. Freeze checkpoint/retention policy and authorization linearization/revocation ordering before implementation. No distributed exactly-once claim or second Work authority.

### Reuse and distinct ownership
Reuse existing Foundation lifecycle, process and lock primitives. A process lock, service client lease, gateway writer claim and exact native-instance control ownership are distinct contracts; do not treat one as proof of another. Agents owns missing node/workspace authorization and receipt semantics. Extend neutral primitives only for a demonstrated stage-specific gap; no node-specific Foundation framework.
