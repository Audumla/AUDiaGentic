# Implement supervised execution nodes and node-local workspace authority

## Description

Delivery follow-up to SH35/SH36. Central gateway controls local execution against caller files through one enrolled independently supervised node. No MCP-scoped second lifetime mode.

## Steps

1. Reuse managed-service lifetime and configure node enrollment/workspace grants.
2. Add outbound authenticated versioned WSS channel with bounded queues/checkpoints and independent control I/O.
3. Resolve manifests/provider/platform facts on execution node, centralize only authorized identity/digest/storage scope.
4. Fence node boot epochs/writer claims and reconcile after disconnect without duplicate dispatch.
5. Prove local file authority, blocked-MCP survival, restart/revocation and no second scheduler.

Immediate delivery gate from the independent target-state sanity review: finish ONE same-node/read-write/owned vertical path through trusted stdio source context, shared ingress, canonical admission, existing queue, WSS work dispatch, NodeExecutionOwner, Provider execution, receipts and exact-text publication. Demonstrate actual local file access/effect and response retrieval with a remote gateway, then disconnect/restart/unknown-effect behavior. Additional generic modes or helper abstractions must not replace that proof.

## Detailed Solution & Technical Design

Implement the terminal Dev-GPT reviewed node design against existing GatewayQueueManager RequestRunner and canonical request store. Wire uses existing websockets asyncio dependency on a separate loopback listener proxied to /shared/v1/nodes/connect; do not hand-build upgrade/framing in existing HTTP server. Command identity freezes request/command IDs, node boot epoch, connection generation, gateway owner epoch, binding/grant revision, workspace ID and payload digest. Node resolves its own actual workspace/provider/manifest; branch node admission before server manifest creation and never resolve a foreign path centrally.

Central command/authorization/receipt checkpoint fields extend canonical request schema/migration and owned mutators, not another command/Work database. Revisioned node/workspace/principal grants live in the owning server config. Add a dedicated validated operator config writer/live replacement with one service-scoped cross-process authorization lock shared by revoke and effect-authorize, then existing per-request lock. No network or provider call under either lock. Authorization request-record commit is the revocation linearization point; revoke first denies, authorize first permits only that one attempt.

Node receipt owner is private sqlite3 WAL+synchronous FULL, serialized access, exact command/digest dedupe, monotonic prepared/effect-intent/native-accepted/terminal and durable same-transaction receipt outbox with producer sequence. A new effect-authorize exchange immediately before local effect-intent is required: existing gateway queue ownership cannot order a remote cached grant against revocation. Reconnect authenticates new epochs and reconciles exact command; intent/unknown acceptance never replays. Bounded inline text uses existing protected gateway response artifacts; larger node-local files report unavailable until separately qualified transfer. Start with owned worker execution; provider-session and EXTERNAL joined targets require later binding/native evidence. Isolated contract/receipt implementation may proceed during SH37 live qualification; do not enable node placement before gate completion.

Terminal GPT minimal ACK decision: use one contiguous serialized acceptance stream per authenticated node/log incarnation and a small durable service-side cursor; do not add historical receipt arrays or a second command database. For C+1, canonical receipt commit precedes checkpoint commit, then ACK outside locks, then next receipt. Crash between writes replays against existing exact latest receipt. S<=C returns persisted cumulative checkpoint without reapplying; gaps/changed pending replay/newer canonical pending state fail closed. Prohibit production receipt application outside this owner. Reuse managed-service owner lock via a narrow neutral owner_guard for epoch+running fence and both writes; no extra stream lock/network/native work inside. Node immutable log incarnation and local ACK cursor live in existing receipt SQLite, preserved on epoch rotation; new DB incarnation cannot silently inherit old checkpoint. ACK is receipt custody, not completion/artifact success. No deletion/compaction in this slice; unresolved/unacked data remains protected.

Caller-workspace contract clarified by the user: initially assume the recipient runs on the caller's machine. The caller's local MCP stdio process derives the source workspace from its trusted invocation/project context and passes that identity through the gateway with each request. Source workspace and recipient execution placement are separate concepts; a statically configured recipient workspace must not silently replace the caller's workspace. For same-machine execution, resolve and authorize the actual caller workspace locally and allow the configured writable execution mode. Determine machine identity through enrolled node/host identity, not path equality, hostname guesses or gateway location. The gateway may be on another machine and must not canonicalize a foreign path. For cross-machine recipients, support read-only access only when an explicitly available access mechanism and recipient execution mode enforce it; a path string alone does not provide access. Unsupported remote access or unenforceable read-only execution rejects explicitly. No automatic clone, checkout, file synchronization, patch transfer or environment provisioning in the initial implementation. Expand those capabilities later from observed usage requirements.
