# Implement external-session detach and durable prompt delivery fencing

## Description

Follow-up to SH36. Safe external binding/session routing, no-kill lifetime and write-ahead native prompt delivery with human-safe queue/cancellation/recovery. Requires qualified existing native surfaces; does not build missing integrations.

## Steps

1. Add ownership-aware detach and audit all close/reaper/purge/failure/shutdown paths.
2. Implement canonical session registration, opaque node locator/generation, writer claims and external-target dispatch separate from owned ACP preparation.
3. Persist intent before first native effect; reconcile node receipt/native correlation and fence uncertainty.
4. Integrate native conditional admission with remote FIFO, cancellation race, grant revocation and trusted self-cycle detection.
5. Verify request-specific result proof and all crash boundaries; retain unresolved receipts.

## Detailed Solution & Technical Design

Gateway canonical request/session state; node WAL receipt evidence only. States/facts and recovery table in canonical design. Acceptance is not response completion. Exact definitive evidence may resolve after renewed authorization; otherwise terminal delivery-uncertain plus generation fence. No blind retry/exactly-once claim. Human/shared native turn cannot be interrupted by own-request cancellation. Steering rejected until result attribution and capability proven. No-kill includes parent process, TUI and shared daemon.

### Final GPT implementation-entry constraints
Specify one active remote writer for each exact native instance/session, with generation/epoch fencing, durable pre-effect WAL commit and crash boundary, exact native acceptance receipt identity, crash recovery dispositions, configured bounded reconciliation deadline and terminal delivery-uncertain semantics before implementation. Expiry releases compute reservation but never clears uncertain delivery/generation fence. Only same-command definitive evidence plus renewed authorization may settle without operator action; no implicit resend.
Audit existing bindings.py EXTERNAL duplicate handling, controls.py dispatch-before-save and agent_session.py close shutdown semantics. Add kill-sensitive tests across every SessionRuntime/reaper/purge/shutdown path, preserving OWNED behavior. Depends on SH38 node and SH39 strict admission; SH41 proof gates actual native operation.

### Deep-review WAL crash and revocation contract
Preserve durable facts and ordering from docs/design/shared-gateway-admission-recovery.md. Prepared and effect intent can share a record when no effect intervenes; separate acknowledgement phases or public lifecycle states are not required. Critical pre-effect and receipt records require documented platform durability, not just atomic rename; logs may batch but cannot weaken WAL barriers. Same command deduplication and renewed authorization govern recovery. Never clear uncertainty on deadline or delete unresolved/unacknowledged receipt state through history retention. Effect authorization is bounded under partitions; already accepted native work is distinct from authority to dispatch future work.

### Reuse and distinct ownership
Reuse Foundation process/service/locking and neutral session ownership primitives; preserve distinct gateway writer versus native-instance ownership. Component-owned effect receipts and no-kill policy cannot be delegated to a generic lease. Reuse atomic I/O where adequate, while testing actual platform durability required by pre-effect evidence rather than assuming rename is sufficient.
