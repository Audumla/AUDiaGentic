# A2A wire transport and live client qualification (SH61b)

## Description

The SDK-backed A2A 1.0 JSON-RPC transport for the SH61a semantic adapter, with real-client qualification. Split from SH61 because it needs the pinned a2a-sdk (1.1.2, extra `a2a`, not installed in the dev environment) and a real authenticated A2A client.

## Steps

1. Install the pinned `a2a` extra in the qualification environment and record the SDK's exact 1.0 wire models; resolve the items marked unverified in SH61 notes: role value spelling, bare text part, taskId/contextId inside the message, returnImmediately/blocking configuration shape, JSON-RPC error codes for terminal and unknown tasks.
2. Add a thin SDK request handler that maps SendMessage / GetTask / CancelTask onto A2aServerAdapter; no second task store.
3. Register the transport through the existing gateway ingress and composition, authenticated by the existing principals and tokens (shared_ingress), with the Agent Card security scheme and URL declared by the transport.
4. Map registered Work errors (CON-AGW-161, 162, 167) to the SDK's error responses.
5. Qualify with a real authenticated A2A client: multi-turn same Context, replay and conflict, taskId continuation, cancel, restart, Agent Card discovery; publish only what is proven.

(1) Wire is proto3 JSON: Message{messageId, contextId, taskId, role ROLE_USER|ROLE_AGENT, parts[Part{text|raw|url|data}]}, there is NO `kind` discriminator in 1.0 (a part is identified by which field is set); Task{id, contextId, status{state TASK_STATE_*}, artifacts, history}. (2) Methods: SendMessage, GetTask, CancelTask (plus SendStreamingMessage, SubscribeToTask, list/push-config) over JSON-RPC. (3) returnImmediately is a bool on SendMessageConfiguration, default false = blocking. (4) A client MUST send the `A2A-Version: 1.0` header; a request without it is treated as 0.3 and refused with -32009 VERSION_NOT_SUPPORTED. (5) Error codes: TaskNotFound -32001, TaskNotCancelable -32002, PushNotificationNotSupported -32003, UnsupportedOperation -32004, ContentTypeNotSupported -32005, VersionNotSupported -32009, InvalidParams -32602. (6) Task states: SUBMITTED, WORKING, COMPLETED, FAILED, CANCELED, INPUT_REQUIRED, REJECTED, AUTH_REQUIRED, matching the SH61a mapping. DONE in this change: protocols/a2a/sdk_handler.py, A2aSdkRequestHandler(RequestHandler): a thin pb<->adapter conversion that owns no task store (the SDK's DefaultRequestHandler/TaskStore are deliberately not used; Work is the single authority); streaming, resubscription, task listing, push config and the extended card answer with the SDK's own unsupported errors; Work/adapter failures are mapped (CON-AGW-* -> InvalidParams carrying the code, missing Work -> TaskNotFound, finished task cancel -> TaskNotCancelable, rich parts -> ContentTypeNotSupported, anything else -> InternalError with no detail). tests/unit/agents/test_a2a_sdk_handler.py: raw JSON-RPC over a real Starlette ASGI app built with create_jsonrpc_routes, AND the SDK's own client (ClientFactory/send_message/get_task/cancel_task) against it. CI: the `a2a` extra is now `a2a-sdk[http-server]==1.1.2`, tests/ci/requirements.txt gains only the new pins (no existing pin changed), ci-tests and ci-full install `.[test,acp,a2a,gpt-auto,node]`, and test_ci_inputs asserts that, because the SDK tests importorskip and would otherwise skip silently. HONEST SCOPE: this is SDK-to-our-handler over an in-process ASGI wire, i.e. real SDK models and a real SDK client, but the same SDK on both ends; it is NOT an independent third-party A2A client and not a network run. NOT done (SH65b/c): mounting the routes in the gateway service behind shared_ingress authentication (the handler currently takes ports built by the caller and has no principal), the Agent Card served at the well-known path with the real URL and security scheme, and a run from a separately implemented client over a socket. The mapping of CON-AGW-162 (terminal Work) to InvalidParams is a choice, not read from the spec.
