# A2A wire transport and live client qualification (SH61b)

## Description

The SDK-backed A2A 1.0 JSON-RPC transport for the SH61a semantic adapter, with real-client qualification. Split from SH61 because it needs the pinned a2a-sdk (1.1.2, extra `a2a`, not installed in the dev environment) and a real authenticated A2A client.

## Steps

1. Install the pinned `a2a` extra in the qualification environment and record the SDK's exact 1.0 wire models; resolve the items marked unverified in SH61 notes: role value spelling, bare text part, taskId/contextId inside the message, returnImmediately/blocking configuration shape, JSON-RPC error codes for terminal and unknown tasks.
2. Add a thin SDK request handler that maps SendMessage / GetTask / CancelTask onto A2aServerAdapter; no second task store.
3. Register the transport through the existing gateway ingress and composition, authenticated by the existing principals and tokens (shared_ingress), with the Agent Card security scheme and URL declared by the transport.
4. Map registered Work errors (CON-AGW-161, 162, 167) to the SDK's error responses.
5. Qualify with a real authenticated A2A client: multi-turn same Context, replay and conflict, taskId continuation, cancel, restart, Agent Card discovery; publish only what is proven.

(1) Wire is proto3 JSON: Message{messageId, contextId, taskId, role ROLE_USER|ROLE_AGENT, parts[Part{text|raw|url|data}]}, there is NO `kind` discriminator in 1.0 (a part is identified by which field is set); Task{id, contextId, status{state TASK_STATE_*}, artifacts, history}. (2) Methods: SendMessage, GetTask, CancelTask (plus SendStreamingMessage, SubscribeToTask, list/push-config) over JSON-RPC. (3) returnImmediately is a bool on SendMessageConfiguration, default false = blocking. (4) A client MUST send the `A2A-Version: 1.0` header; a request without it is treated as 0.3 and refused with -32009 VERSION_NOT_SUPPORTED. (5) Error codes: TaskNotFound -32001, TaskNotCancelable -32002, PushNotificationNotSupported -32003, UnsupportedOperation -32004, ContentTypeNotSupported -32005, VersionNotSupported -32009, InvalidParams -32602. (6) Task states: SUBMITTED, WORKING, COMPLETED, FAILED, CANCELED, INPUT_REQUIRED, REJECTED, AUTH_REQUIRED, matching the SH61a mapping. DONE in this change: protocols/a2a/sdk_handler.py, A2aSdkRequestHandler(RequestHandler): a thin pb<->adapter conversion that owns no task store (the SDK's DefaultRequestHandler/TaskStore are deliberately not used; Work is the single authority); streaming, resubscription, task listing, push config and the extended card answer with the SDK's own unsupported errors; Work/adapter failures are mapped (CON-AGW-* -> InvalidParams carrying the code, missing Work -> TaskNotFound, finished task cancel -> TaskNotCancelable, rich parts -> ContentTypeNotSupported, anything else -> InternalError with no detail). tests/unit/agents/test_a2a_sdk_handler.py: raw JSON-RPC over a real Starlette ASGI app built with create_jsonrpc_routes, AND the SDK's own client (ClientFactory/send_message/get_task/cancel_task) against it. HONEST SCOPE: this is SDK-to-our-handler over an in-process ASGI wire, i.e. real SDK models and a real SDK client, but the same SDK on both ends; it is NOT an independent third-party A2A client and not a network run. 2026-11-02 SH65b target state (GPT-reviewed, verified against main). DECISION: SEPARATE ASGI FACADE, not embedding. A small independently supervised uvicorn app, bound to 127.0.0.1 only, is a CLIENT of the gateway through the existing remote client; it forwards the CALLER's own bearer so the gateway still authenticates the real principal, enforces project/action grants and builds the delivery identity (no facade credential, no token store, no second authority). Rejected: embedding ASGI in the stdlib gateway process (second HTTP stack, asyncio vs threads, a facade bug could take the gateway down) and teaching http_transport A2A itself (bypasses the SDK). This revises step 3 above ("register through the existing gateway ingress"): the ingress is reused for AUTHORIZATION, not for hosting. Facts that shape it: the gateway binds IPv4 loopback only, so remote A2A needs an externally managed TLS reverse proxy; StandaloneGatewayClient takes one credential at construction, so the facade needs request-scoped credential selection (bounded clients keyed by a non-reversible fingerprint of the credential + project + gateway identity, idle eviction, reacquire after lease/epoch invalidation, never cache authorization). Routes: /a2a/{project-id}/{agent-id}, resolved only against server-configured projects and publication.a2a definitions. Missing/invalid bearer -> 401, valid but not granted -> 403; the Agent Card may be public and declares HTTP bearer. A blocking SendMessage needs submit AND read (accept then wait_agent_work): check the principal's capabilities from /shared/v1/health BEFORE accepting, so a submit-only caller is refused before an effect, not after. Config: an Agents-owned `agents.a2a` settings subsection (enabled, loopback port, externally advertised HTTPS base URL), reject non-loopback bind and non-HTTPS advertised URL for non-loopback hosts, no new env vars, plus an agents doctor check; card URLs derive from the validated base URL, never a Host header. SLICES: SH65b-1 operation parity in shared ingress (THIS PR: open_agent_context=submit, get_agent_context=read, read_agent_work_output=read, cancel_agent_work=cancel were missing, so the adapter could not work over shared ingress; close/list context and list Work stay local-only); SH65b-2 facade + per-caller client/lease management with real-loopback uvicorn tests (two principals, denied grants, expiry, reconnect, concurrency); SH65b-3 publication/settings/doctor/docs and card discovery with the SDK client over a socket; SH65c independent-client qualification (separately implemented client, TLS proxy, real provider run, multi-turn, cancel, restart, replay/conflict) with recorded versions. Grants remain project-wide (collaborative), so any principal granted `read` on a project can read any Work output in it: this is the existing model, not new isolation.
