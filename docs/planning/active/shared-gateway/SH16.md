# SH07 Pi gateway agent surface and isolation

## Description

Make the Pi harness executable as a gateway-managed agent. Pi currently resolves as a profile but fails UNS-AGW-076 because its descriptor is no-isolation and it has no ACP launch adapter.

## Steps

1. Reuse AS13’s managed bridge recipe/probe/version pattern to provision pinned Pi CLI, pi-mcp-adapter, and pi-acp; do not add a second installer abstraction. 2. Reuse AS28’s provider-neutral session-surface/session transport factory when available; until then keep the Pi ACP adapter behind providers_api and out of agents. 3. Reuse AS17’s process ownership/tree cleanup and runtime evidence for Pi child lifecycle; do not add a Pi-specific process supervisor. 4. Use the existing gateway request runtime path to create request-local Pi state: PI_CODING_AGENT_DIR, explicit --session-dir, Windows home/temp/XDG redirects, manifest, cleanup/quarantine. 5. Keep the requested repository as cwd and document shared project .pi/working-tree semantics separately from agent-state isolation. 6. Promote the Pi descriptor only after the reused generic lifecycle/transport tests prove the declared tier. 7. Add only Pi-specific adapter, capability evidence, provisioning, and integration tests; link failures to AS13/AS17/AS28 rather than duplicating their generic work.
