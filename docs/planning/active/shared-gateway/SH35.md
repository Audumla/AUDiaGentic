## Detailed Solution & Technical Design

### Authoritative design
Sections Source seams through Execution identity and grants in docs/design/shared-gateway-execution-contract.md define the canonical decisions; docs/design/shared-gateway-joined-harnesses.md maps scenarios. Replace earlier overlapping candidates with that contract. Actual current protocol is gateway-service-v3 and local-only. A new shared ingress is an explicit versioned contract, not relaxed local guards or implicit local fallback.

### Frozen topology and service decisions
Reuse current gateway client/host/lifecycle with a supervised server and independently supervised caller-local node. Server-hosted project root resolves from operator registry; node-local workspace root resolves only on enrolled execution node. Central storage scope is identity-based, never a fabricated foreign checkout. Authenticated HTTPS front door and outbound WSS node connection enforce principal/project/node grants; existing loopback dashboard is not forwarded. Local recover never kills a remote PID. Shared server survives zero leases. Separate process composition supports pure help and gateway-only startup; no provider selection or lifecycle logic in protocol adapters.

### CLI and migration
Canonical word-based gateway serve/connect/status/drain/resume/stop/recover and gateway node serve/status grammar, complete config precedence, output/help and operator policy are specified in the design. Follow Architecture section 4: no default legacy aliases/shims. Migrate affected callers/docs/tests and remove obsolete paths in implementation; any external obligation needs a documented bounded exception first. Current local mode remains an intentional separate transport, not remote fallback.

### Packaging and surface closure
Initially qualify existing wheel/component dependencies and actual footprint. MP02 slim distributions remain separately pending. Owner metadata, exact MCP descriptions, errors/events, schemas, instructions, guides, OS supervision and trace access are required deliverables, not afterthoughts. Do not hand-edit generated instructions.

### Pending delivery ownership
SH37 owns standalone shared ingress and CLI; SH38 owns supervised execution nodes; SH42 owns tooling/docs/observability and installed qualification. SH39/SH40/SH41 own joined-session qualification/delivery under SH36. SH35 completion is planning-only and does not complete these delivery items.

## Effort & Risk

Large: current standalone transport is intentionally local-only and embeds filesystem authority. Highest risks are path/project identity, per-client/operator scope, recovery/idempotency after network ambiguity, component-profile isolation, browser/service placement and accidental local fallback. Reuse existing host/worker/lifecycle reliability; do not expand into a distributed scheduler, arbitrary file sync or a second gateway implementation.
