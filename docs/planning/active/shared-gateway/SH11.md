# Cut over all gateway consumers and retire in-process ownership

## Description

Migrate harness MCP surfaces, event-driven jobs, session operations, status/cancel/wait callers, and tests to the shared gateway client; make `automatic` the default gateway management implementation only after staged soak evidence; then retire unfenced direct binding and singleton-ownership assumptions. Gateway management selection must move from ad hoc environment-mode branching toward the component standards implementation model so management options can be switched declaratively. The in-process engine is retained only as the explicit `embedded` implementation because the service hosts that engine internally.

## Steps

Amended per RV687 and the 2026-07-18 gateway-management decision: the gateway management choices are exclusive component implementations. `automatic` remains the required final/default implementation for this migration. `mcp-gateway` is introduced only as a deferred implementation family contract; no concrete third-party MCP gateway is implemented in SH11.

### Slice A — define gateway management as exclusive implementations

Update the agents component descriptor shape before changing runtime behavior:

```yaml
# src/audiagentic/config/components/agents.yaml
implementation-cardinality: exclusive
```

Add implementation descriptors under `src/audiagentic/config/components/agents/implementations/`:

```text
embedded.yaml       explicit local engine binding for tests/dev/one-shot use
standalone.yaml     explicit endpoint+token connection to an already running gateway
automatic.yaml      discover-or-start the managed local shared service; default after soak
mcp-gateway.yaml    deferred optional family placeholder; disabled/non-default, no concrete provider
```

Required descriptor rules:
- `automatic` is the target default after Slice E, not before soak.
- `embedded` remains explicit and fenced; it never claims sharing semantics.
- `standalone` requires endpoint/token configuration and never auto-starts.
- `mcp-gateway` exists only as a documented deferred implementation contract unless/until a concrete implementation such as Open MCP gateway is selected in a separate plan item.
- Options live in each implementation's `options-schema`; no provider-specific `if/elif` or hard-coded implementation registry is allowed in the client.

Initial option sketch:

```yaml
embedded:
  allow-with-live-shared-owner: {type: enum, values: [warn, refuse], default: warn}
standalone:
  endpoint: {type: string, required: true}
  token-file: {type: string, required: true}
automatic:
  idle-grace-seconds: {type: number, default: 0}
  service-root: {type: string, required: false}
  startup-timeout-seconds: {type: number, default: 30}
mcp-gateway:
  lifecycle-mode: {type: enum, values: [external, managed, unsupported], default: external}
  endpoint: {type: string, required: false}
  command: {type: list, required: false}
  token-file: {type: string, required: false}
  health-probe-timeout-seconds: {type: number, default: 10}
  protocol-version: {type: string, required: false}
```

Validation: component descriptor loading sees exactly one active implementation; `automatic` can be marked schema-default only at Slice E. Until then current env behavior may still choose the implementation for compatibility.

### Slice B — implementation resolver and compatibility env bridge

Introduce a small implementation resolver behind `get_gateway_client()`:

```python
@dataclass(frozen=True)
class GatewayManagementSelection:
    implementation_id: Literal["embedded", "standalone", "automatic", "mcp-gateway"]
    options: Mapping[str, Any]
    source: Literal["component-config", "env-override", "schema-default"]
    is_default: bool
```

Resolution order during migration:
1. explicit `AUDIAGENTIC_GATEWAY_MODE` env override, with aliases `in-process -> embedded` and warnings during soak;
2. component implementation selection/config;
3. schema default, initially existing behavior, finally `automatic` in Slice E.

Runtime factory rules:
- `embedded` returns renamed `EmbeddedGatewayClient` and runs the coexistence guard.
- `standalone` returns `StandaloneGatewayClient` using configured endpoint/token.
- `automatic` uses the SH05/SH10 bootstrap path to discover or start the managed service, then returns `StandaloneGatewayClient`.
- `mcp-gateway` raises a clear unsupported/deferred configuration error until a concrete implementation plan lands. It must not silently fall back to embedded or automatic.

Move blanket `reconcile_gateway_state` call sites inside the embedded client's first-use path only; service/automatic paths use SH07 Slice B `recover_gateway_requests`.

### Slice C — management surface for switching and config

Add a management surface that follows `CREATING_A_COMPONENT.md` for implementation-backed components:

```python
agents_gateway_get_config(implementation_id: str | None = None) -> dict
agents_gateway_set_config(implementation_id: str, updates: dict) -> dict
agents_gateway_select_implementation(implementation_id: str) -> dict
```

The tools/API must be generic:
- return `{implementation, config, schema, enabled, is_default}`;
- serialize implementation option schemas with provenance where available;
- validate updates through the implementation `options-schema`;
- never add `set_open_mcp_gateway_*` or other implementation-specific tools;
- status-hook reports `details.implementation: {enabled, is_default, id, source}` without overloading top-level component enabled state.

Provider-facing activity tools continue to call the stable gateway client contract and do not receive management tools.

### Slice D — embedded rename, coexistence guard, and conformance harness

Retain the RV687 behavior, now expressed as the `embedded` implementation:

```python
_MODE_ALIASES = {"in-process": "embedded"}
```

`EmbeddedGatewayClient` must warn/refuse beside a live provable shared owner according to `embedded.allow-with-live-shared-owner` / `AUDIAGENTIC_GATEWAY_EMBEDDED_ALLOW` during migration.

Inventory and conformance matrix:

- `agents_gateway_events.py` via client only;
- `agent_jobs/control.py` and `agent_jobs/event_observer.py` via event/client contract only;

Parametrize submit/status/wait/cancel/session flow suites over `embedded`, `standalone`, and `automatic` using fake providers only. `mcp-gateway` is included only as an unsupported-selection test until a concrete implementation exists.

### Slice E — opt-in soak for automatic implementation

Ship a component-profile overlay selecting `automatic` for the `ag-agents-gateway` MCP server/profile, not the base default yet. Soak gates, each recorded with evidence before Slice F:
- multi-project two-harness sharing on Windows and POSIX;
- crash/restart with SH07 recovery;
- upgrade/version-skew old client vs new service gives clean version refusal;
- session lifecycle via AS08 once landed;
- cancellation acknowledgement via SH07 Slice C;
- SH08 Slice A contention evidence enabled;
- SH10 lifecycle gates green, including CLI/signal/integration proofs;
- conformance matrix green for `embedded`, `standalone`, and `automatic`.

### Slice F — default flip and deletion of stale ownership assumptions

1. Mark `automatic` as the schema/default implementation and set `_DEFAULT_MODE = "automatic"` only as a compatibility mirror.
2. Exercise rollback once in CI by selecting `embedded` and `standalone` through the implementation config, not only environment variables.
3. Delete the `in-process` alias after the rollback window.
4. Delete singleton-ownership assumptions that guard nothing, module-singleton reconcile-at-import paths, stale config flags, and obsolete in-process-only tests superseded by the conformance matrix.
5. Keep `embedded` as an explicit implementation for unit/CI/one-shot use.
6. Final dependency scan: core/API/service modules import no MCP/FastMCP; every MCP/event/CLI adapter reaches gateway behavior only through `get_gateway_client()`/`StandaloneGatewayClient`/the generic management API.

### Slice G — deferred MCP gateway implementation family contract

Do not implement a concrete MCP gateway in SH11. Leave `mcp-gateway` as a documented optional implementation family with unsupported runtime behavior until a separate plan item names a concrete implementation.

Future item acceptance criteria for something like Open MCP gateway:
- add a concrete implementation descriptor or descriptor family with options-schema;
- define whether lifecycle is `external`, `managed`, or `unsupported`;
- define endpoint/auth/protocol/version/health semantics;
- map submit/status/wait/cancel/session behavior to the stable gateway client contract;
- add conformance tests proving parity or explicitly documented unsupported operations;
- add lifecycle tests for attach/start/stop/recover behavior;
- add rollback from that implementation back to `automatic`.

### Validation

No caller obtains embedded binding implicitly. Gateway management selection is exclusive, descriptor-backed, and switchable. `automatic` is the final default after soak. `embedded` and `standalone` remain explicit alternatives. `mcp-gateway` is visible as future extensibility but cannot accidentally route production traffic until a concrete implementation passes conformance. Two projects and multiple harnesses share one discovered service by default; rollback is exercised through implementation selection; final dependency scans prove adapters do not own lifecycle, lease, dispatch, or process policy.
