# Cut over all gateway consumers and retire in-process ownership

## Description

Migrate harness MCP surfaces, event-driven jobs, session operations, status/cancel/wait callers, and tests to the shared gateway client; make self-managed service mode the default only after staged soak evidence; then delete the obsolete in-process singleton and single-owner reconciliation paths.

## Steps

1. Build a consumer inventory and migration matrix. 2. Add opt-in shared mode and side-by-side behavioral conformance runs without dual-dispatching production requests. 3. Run multi-project soak, crash/restart, upgrade/version-skew, provider isolation, session, cancellation, and resource-contention gates on Windows and POSIX. 4. Switch defaults with a documented rollback window. 5. Remove the in-process backend, stale config flags, compatibility shims, and obsolete tests once the external obligation window is closed. 6. Update architecture/operations docs and ledger evidence.

## Files

all gateway client consumers; composition/config defaults; removal of in-process backend paths; integration/e2e/soak tests; documentation

## Validation

No production caller imports or constructs the old queue/session owner; two projects and multiple harnesses use one discovered service by default; rollback was exercised before deletion; full affected suites and cross-OS lifecycle gates pass. The final dependency scan proves core/API/service modules do not import MCP/FastMCP and every MCP/event/CLI adapter reaches gateway behavior only through approved public APIs.

## Effort & Risk

Complex integration/cutover. Deletion is required once the migration obligation ends; do not leave permanent dual ownership.

## Standards

AR25; Architecture Standards §§1–7; migration/deletion discipline.

## Notes

Final shared-gateway migration item. Depends on SH02–SH10, AR25, and the AS08 session-integration handoff.
