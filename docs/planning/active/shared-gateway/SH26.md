# Machine-scoped gateway archive retention policy

## Description

Provide an explicit machine-owned configuration authority for gateway archive retention and purge eligibility. Shared-gateway destructive policy must not be silently invented in code or weakened by one project.

## Steps

1. Define machine-scope retention schema: enabled/disabled, minimum age, bounded batch size, legal protected classes, and optional tombstone policy only if another contract requires it.
2. Define precedence/conflict rules; project-local configuration cannot weaken machine policy.
3. Snapshot policy identity/digest onto SH24 purge operations at admission and revalidate before deletion.
4. Expose redacted status/config through the operator management surface only.
5. Add migration/default policy. Until explicitly configured, purge yields BLOCKED/RETENTION_POLICY_UNAVAILABLE rather than deleting.

## Detailed Solution & Technical Design

Policy evaluation belongs in an application/domain service consumed by SH24, not workflow YAML, ArchiveRepository, MCP arguments, or broker messages. Archive may ship before purge policy is configured.

## Code Samples & Guidance

Illustrative machine policy:
```yaml
gateway-retention:
  purge-enabled: false
  minimum-archive-age-seconds: 0  # invalid unless purge-enabled remains false
  max-batch-size: 100
  protected-classes:
    - referentially-pinned
```
Production defaults must fail closed: absent/disabled policy blocks purge. Final field names and nonzero minimums follow the owning config descriptor and validation.

## Files

Machine-scoped agents/gateway retention configuration descriptor and resolver; retention policy domain/application service; narrow operator status/config projection; SH24 purge integration; schema, precedence, restart, race, redaction and policy tests.

## Validation

No implicit retention duration; project config cannot shorten machine minimum; mid-operation policy change fences deletion; missing policy blocks safely; status reveals policy identity without protected paths/data; restart preserves policy behavior.

## Effort & Risk

Medium. Incorrect precedence could permit accidental cross-project deletion.

## Standards

arch-standards config-over-code and ownership; shared machine policy cannot be weakened by project scope; observability/redaction standards.

## Acceptance Criteria

- There is no implicit purge age and no hard-coded project override.
- Missing or disabled machine policy produces BLOCKED/RETENTION_POLICY_UNAVAILABLE.
- A project cannot shorten or weaken the machine policy.
- Policy identity/digest is snapshotted at admission and revalidated immediately before deletion.
- Status exposes safe policy identity/effect but no paths, prompts, output, provider references, or secrets.
- Archive remains usable without purge policy; SH11 cutover is not blocked.
