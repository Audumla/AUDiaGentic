# Run the gateway as an explicit standalone local control-plane service

## Description

Add a manually started standalone gateway service and local authenticated transport so multiple harness processes can share one queue/session control plane. The service transport is a thin protocol adapter over the same framework-neutral application/control-plane API proven by SH03; all state transitions, dispatch, recovery, and lifecycle behavior remain behind that API. Convert persisted gateway state from single-process assumptions to explicit single-authority service ownership before enabling auto-start.

## Steps

1. Select and document a cross-platform local transport and endpoint/authentication scheme; bind locally by default. 2. Implement the standalone service host using the control-plane contract and PR05 process primitives. 3. Make request state transitions, cancellation, waiting/status, reconciliation, and session registry service-owned; remove thread-lock assumptions at service boundaries. 4. Add protocol health/version/capability endpoints and bounded client retry semantics. 5. Bound long-lived process state including event correlation-chain retention. 6. Add crash, restart, concurrent-client, malformed-client, and security tests. 7. Keep explicit configuration to choose in-process or standalone during this phase.

## Files

new shared gateway service/client transport modules; agents gateway store/queue/api/session integration; foundation event retention where required; CLI/service entry point; tests

## Validation

Two independently started harness clients submit, observe, cancel, and continue work through one service without double dispatch; service restart yields deterministic recovery; local unauthenticated/mismatched clients are rejected; Windows and POSIX tests pass. Transport modules import only the public service/client API and protocol scaffolding; the gateway core has no dependency on MCP or the selected local transport framework.

## Effort & Risk

Complex. This changes the authoritative writer and failure domain. Do not combine with automatic discovery or default cutover.

## Standards

AR25; Architecture Standards §§1,3,4,6,7.

## Notes

Depends on SH03, AR25, and PR05. Reuses PR05 lifecycle safety rather than inventing gateway-local PID/lock/reaping logic.
