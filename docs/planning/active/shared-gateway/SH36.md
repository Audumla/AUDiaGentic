# Design capability-qualified registration and control of existing harness sessions

## Description

Complete the planning contract for joining already-running user-owned Claude Code, Codex, Pi and OpenCode sessions, injecting prompts through already-present qualified native/ACP surfaces, and safe shared-human lifecycle/concurrency/recovery. Design-only; missing integrations and runtime implementation remain separate.

## Steps

1. Incorporate terminal Round2 and capability-authority GPT findings through planning reviews.
2. Freeze canonical identity, capability admission, external no-kill ownership, node-local authority, WAL and native concurrency contracts.
3. Define ACP versus native surface qualification and resolve ASA terminology without inventing a protocol.
4. Create bounded implementation/probe/installed-validation items and metadata/documentation inventory.
5. Obtain terminal exact-head final GPT standards/code-seam audit; close findings and complete only the design acceptance criteria.

## Detailed Solution & Technical Design

### Authoritative contract
Use docs/design/shared-gateway-execution-contract.md sections Capability-based admission through Completion boundary and the scenario matrix in docs/design/shared-gateway-joined-harnesses.md. This supersedes earlier speculative candidates. Scope: four named harnesses only, no new integrations installed/built at join, no substitute children or terminal keystrokes.

### Admission and source-backed gaps
User requires capability-qualified actual existing sessions only. Reuse SessionSurfaceDeclaration, ResolvedSessionSurface, existing inventory and Provider public resolution; derive the matrix from that authority. Add only missing typed joined facts and passive instance readiness. Confirmed current resolver gaps: unknown installed version falls back to constraint; missing inventory proof can pass; adapter callable existence is not live attachment. Strict join requires actual execution-node version/platform, exact native current identity, EXTERNAL safe detach, prompt delivery/native human-safe admission, correlated completion/output and one writer. Reject before canonical registration; previously valid sessions losing evidence suspend routing. Optional steer/interrupt are independently gated, queue-only can qualify.

### Identity, lifetime and delivery
Canonical gateway session ID is public routing identity. Immutable external binding stores node/workspace/generation/surface/evidence and versioned opaque node locator; native refs remain node-private. Context groups work, not another handle registry. Explicit external-target dispatch must not fall through owned ACP preparation. Supervised node owns effects/receipts, gateway owns requests/FIFO. Audit every cleanup path for detach only. Persist dispatch intent before effects; lost ack is uncertain, not replay permission. Native acceptance/start/settle/verified output differ. Exact definitive evidence can reconcile with renewed authorization; otherwise bounded delivery-uncertain and fenced generation. Preserve native human approvals, cancel own queued work only, and reject trusted caller dependency cycles including async self-poll.

### Protocol and evidence
ACP remains the existing standardized transport for qualified owned/resume semantics. Native adapters use the same neutral session contract but are not represented as universal live ACP attachment. ASA has no identified canonical source contract; final GPT review must resolve the term or explicitly document it as unverified, with no implementation dependency invented. Current four joined paths are unproven: inventory/read-only candidate research is not runtime qualification. Missing integrations remain future work.

### Standards and surfaces
Provider adapters are requester-blind behind providers_api. Thin CLI/MCP/service adapters use owning domain API. No second registry/scheduler or speculative foundation framework. Exact owner config/schema/error/event/tool/parameter/help/instruction/documentation changes and redacted timeline/receipt contracts are required in delivery slices.

### Pending delivery ownership and order
SH41 starts read-only/disposable qualification research first to establish feasible native interfaces; it does not install/build missing integrations. SH39 owns strict capability admission; SH40 owns external detach and durable delivery; SH38 supplies the supervised node; SH42 closes surfaces and real installed qualification. Capability metadata is enabled only after SH41 proof, not because the generic infrastructure exists. SH36 completion is design-only, never completion of these items.

## Validation

Planning checks plus final exact-head GPT source/standards review resolving contradictions and code-seam feasibility. Future native qualification must use disposable current-version instances, preserve human UI, prove exact existing attachment/control, human race handling, no-kill every cleanup path, two-client queue, per-request output attribution, blocked MCP/self-cycle refusal, WAL crash/lost-ack recovery, stale identity/epoch refusal, reconnect/config drift and installed multi-machine operation. All four currently unproven remains a truthful research result, never a successful feature claim.

## Effort & Risk

Large and validate-first. Joining an existing human-owned transport is a different capability from launching managed ACP children. Highest risks are unsupported native attachment, inherited process cleanup killing external owners, self-MCP deadlock, competing native controllers, duplicate prompts after reconnect, and misattributed human/steered output. Keep other providers, automatic ownership transfer, keystroke automation and blind cross-machine failover out of MVP.

## Standards

Architecture sections 1-8 and implementation guidelines: approved Provider public API, no adapter internals imports, one authority, typed evidence, no default legacy compatibility paths, registered errors/events, bounded idempotent retries and safe content. Observability standards: correlated redacted durable timelines. Project prompt/provenance/profile/planning/ledger/no-stash doctrine.
