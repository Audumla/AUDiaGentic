# Implement gateway leases, graceful drain, and idle self-shutdown

## Description

Provide the first self-managed gateway lifecycle mode over the framework-neutral service API, consuming PR06/PR07 ManagedService mechanics. Foundation owns lease and guarded-stop mechanics; gateway supplies only its domain quiescence facts and component idle policy. Continuous-service/service-manager mode is a later extension if an actual deployment need arises.

## Steps

Core slice LANDED 2026-07-18 (see Notes): quiescence contract, idle self-shutdown, operator service_status/drain/resume/stop{force}, record-only recover_unprovable_owner, host wiring, unit+integration tests. Remaining slices, code-level:

### Slice A — CLI wiring

Extend the existing `audiagentic gateway` command group (same module that owns `gateway serve`):
```python
@gateway_group.command("status")
def gateway_status_cmd():
    client = _standalone_client_from_env()      # endpoint+token resolution shared with serve
    print(json.dumps(client.service_status(Path.cwd()), indent=2))

@gateway_group.command("drain")   # -> client.service_drain(Path.cwd())
@gateway_group.command("resume")  # -> client.service_resume(Path.cwd())
@gateway_group.command("stop")    # --force flag -> client.service_stop(Path.cwd(), force=force)

@gateway_group.command("recover")
@click.option("--confirm", is_flag=True)
@click.option("--reason")
def gateway_recover_cmd(confirm, reason):
    # Deliberately NOT an HTTP operation: recovery targets a dead/unprovable
    # service, so it goes straight to the store via the lifecycle module.
    from audiagentic.components.agents.agents_gateway_lifecycle import recover_unprovable_owner
    print(json.dumps(recover_unprovable_owner(confirm=confirm, reason=reason), indent=2))
```
CLI handlers contain zero lifecycle logic — dispatch to client/module only (arch test below enforces it).

### Slice B — OS-shutdown handling in the service process

In `gateway serve` (the process entry, not the host class):
```python
def _install_shutdown_signals(host: GatewayServiceHost) -> None:
    def _handler(signum, _frame):
        # Drain-first: refuse-force semantics make no sense on SIGTERM; report and force.
        try:
            host.lifecycle.request_stop(force=True)   # reports affected work in the log
        except Exception:
            host.shutdown()
    for sig in (signal.SIGINT, signal.SIGTERM):
        with contextlib.suppress(OSError, ValueError):
            signal.signal(sig, _handler)
```
Windows: SIGTERM maps from CTRL_CLOSE/taskkill only partially — also register `signal.SIGBREAK`; a hard TerminateProcess is covered by the next start's owner-claim liveness check plus SH07 Slice B recovery (document; no handler can run). Exit code 0 on drain-complete, 1 on forced.

### Slice D — remaining lifecycle proofs (integration + Docker)

1. Crashed-client: acquire a lease with ttl=1s from a subprocess, kill -9 it, assert the idle loop's expire_leases sweep reaches zero and idle exit proceeds (host-level test; extends test_gateway_lifecycle idle tests with a real subprocess).
2. Reconnect-at-deadline: idle grace 0.5s; at ~0.4s a new client attaches (state still running → lease granted); assert exit cancelled and `service_status` shows the lease; then release and assert exit completes. Also assert the draining-window behavior: a connect attempt AFTER drain begins receives CON (lease refused in draining) and the exit still completes — documented, deterministic.
3. Long-running-job: BUSY quiescence held by a real fake-provider request for > grace; assert no drain until terminal.
4. Docker (mutable gate): `docker stop` (SIGTERM) on a serving container → record ends stopped/failed-with-class, no orphaned children (process-tree scan), restart claims cleanly. Windows host equivalent via taskkill (graceful) and /F (hard-kill → next-start recovery path).

### Deferred (unchanged)
Continuous-service adapters (systemd/Windows-service wrappers) remain a later optional slice per the 2026-07-17 sponsor decision; the signal handling in Slice B is deliberately shaped so a service manager's stop maps onto the same drain path.

## Validation

With no clients but active gateway work, the foundation-managed service stays alive because gateway quiescence is false; after the last lease and work complete it exits after configured grace; a reconnect during grace cancels exit; no owned process/session is orphaned. An explicitly confirmed unprovable-owner recovery mutates only the durable record, preserves redacted diagnostic evidence, and never signals the recorded PID. PR06/PR07 validate generic lease/race/ownership safety, while gateway tests validate quiescence and authorization. Architecture tests prove MCP/CLI adapters do not own lease tables, drain state, shutdown gates, or process policy.

## Effort & Risk

Complex shutdown state machine and cross-OS orchestration. Force stop must be explicit and must report affected work.
