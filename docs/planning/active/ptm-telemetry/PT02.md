# Per-Harness Provider Capability Matrix

## Description

Create a per-harness capability document that answers not just 'can this harness talk to OpenRouter?' but also 'can AUDiaGentic monitor, budget, and intelligently schedule work across providers?' This is the scheduling layer differentiator.

For each harness (Claude Code, Codex CLI, OpenCode, Goose, Qwen Code, Cursor, Cline, etc.), document:
- Supported providers (Anthropic, OpenAI, OpenRouter, Gemini, Azure OpenAI, Ollama, llama.cpp, LM Studio, vLLM, LiteLLM, local OpenAI-compatible endpoints)
- Authentication (API key, OAuth, subscription login, browser login, PAT, local only)
- Endpoint configuration (custom base URL, multiple providers, per-model provider, failover, routing)
- Telemetry (credits, quota, session remaining, rate limits, cost estimation, context remaining)
- Observability (streaming token counts, token usage events, provider latency, retries, billing information)
