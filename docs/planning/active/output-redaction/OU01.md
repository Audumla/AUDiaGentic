# Correct output redaction: undo the in-flight fan-out, enforce at egress boundaries only

## Description

REOPENED 2026-07-16 (RV507). OU01 v1 fanned redact_text out to ~60 in-flight call sites and folded diagnostic channel names (stdout/stderr/output/input/prompt) into the SHARED sensitive-key matcher. The result is backwards: diagnostics are blanked everywhere, while the destinations that actually persist or publish (git-managed surfaces, managed blocks, audit log) have no guard at all. This revision undoes that and lands the original stated intent — stop output reaching files/logs/git where it could be misused — as a small number of ENFORCED boundaries rather than 66 opt-in calls.

SCOPE RULE: redaction belongs where data becomes durable or shareable. Not in memory. Not on the config-write path.

## Steps

ORDER OF WORK (corrected 2026-07-16 after a live regression): 1 -> 2 -> 4 -> 5 -> 3 -> 7 -> 8. Steps 1-2 make the matcher honest. Steps 4-5 BUILD the enforced boundaries. ONLY THEN does step 3 delete the in-flight calls. Do not run step 3 early: doing so removed the only guard on a value that reaches the user and leaked a credential into action_needed.

0. BASELINE — `python -m pytest tests/unit/foundation/logging tests/unit/foundation/test_component_server_errors.py -q`. Record the 2 known-red tests in test_component_server_errors.py (they expect lowercase [redacted] and key-preserving output; HEAD emits uppercase [REDACTED] whole-match and has since commit 8611be29). Inventory the current fan-out: `rg -c "redact_text|redact_env_like|redact_error_envelope|summarize_structure|safe_metadata" src --glob '!redaction.py'` — expect ~66 across 19 files. Do not start until you can name which destination each site protects; most protect none.

1. UN-FOLD THE SENSITIVE-KEY MATCHER (undo the RV328 over-reach — do this first, it unblocks the rest).
   The current SENSITIVE_KEY_PATTERN is `prompt|key|token|secret|password|authorization|output|auth|input|stdout|stderr`. The last group are DIAGNOSTIC CHANNEL names, not secret names; they arrived via OU01 PHASE 1 (RV328) which folded component_server.py's tool-ARG key set into the shared matcher, where it now blanks every structural summary. Split it:
     SECRET_KEYS = key|token|secret|password|authorization|auth   -> value blanket-replaced with [REDACTED]. Correct: these values ARE secrets.
     BULK_KEYS   = stdout|stderr|output|input|prompt              -> value passed through redact_text and truncated, NOT blanked. These values are diagnostics that may CONTAIN a secret; redact_text already removes the secret.
   Keep `is_sensitive_key` meaning SECRET_KEYS only. Add `is_bulk_key` for the second class. Update _summarize_value, _redact_error_value and safe_metadata to route BULK_KEYS through content-redaction + truncation.
   component_server.py keeps its tool-arg behaviour by passing its own extra keys explicitly at ITS call site — do not push a narrow need back into the shared matcher again. That is the exact mistake being undone.
   PROOF THIS IS SAFE (already verified): redact_text leaves clean diagnostics untouched ('npm ERR! 404 Not Found: @walodayeet/hindsight-pi' passes through verbatim) and surgically fixes credentials ('https://user:pw@host/api' -> 'https://[REDACTED]@host/api').

2. MAKE THE CONTENT MATCHER KEY-PRESERVING. `\b(api_key|token|secret|password)\b\s*[:=]\s*\S+` currently replaces the WHOLE match, so 'failed with token: sk-abc' becomes 'failed with [REDACTED]' — losing that it was a token at all. Replace only the value: 'token: [REDACTED]'. This is what the 2 red tests always expected.

3. REMOVE THE IN-FLIGHT FAN-OUT — ONLY AFTER STEPS 4 AND 5 HAVE LANDED. ORDERING IS LOAD-BEARING, NOT COSMETIC (corrected 2026-07-16): this step was originally listed BEFORE the egress boundaries were built, and an agent following it in that order deleted redact_text from providers/services/self_provided_lsp_handler.py, producing a LIVE SECRET LEAK — action_needed came back as 'token=sk-secret-value install failed'. Caught only because a test asserted it. Deleting the scattered guards before their replacement EXISTS leaves a window with NEITHER. Build the boundary first (steps 4-5), prove it catches a planted secret, THEN delete the in-flight calls and confirm the same planted secret is still caught. Each deletion must be justified by 'an enforced boundary downstream now covers this value', not merely by 'this is in-flight'. (this is the 'clears the rubbish' step — OU01 v1 put these calls in; delete them, but last).
   Delete redact_text calls from: adapters/base_runner.py finalize_run (10), foundation/steps/shell.py (7), foundation/steps/callable.py (4), toolchains/probes.py (3), providers/adapters/pi/hooks.py (3), providers/services/self_provided_lsp_handler.py (3), harness/rig.py (2), harness/pi/runner/agent_run.py (2), coding_lsp/lsp_diagnostics.py (2), and the remaining in-memory sites. These build result objects and stream to a terminal; none is a durable destination. Values flow untouched in memory.
   DO NOT delete: protocols/streaming/sinks.py RawLogSink/NormalizedEventSink (step 4 — these DO write to disk), release/local_release.py (step 4 — error paths that reach logs), agent_jobs/event_observer.py summarize_structure/safe_metadata (already the correct boundary shape).
   Each deletion must be justified by 'this value does not reach a file, log, or git'. If it does, it belongs in step 4 instead.

4. ENFORCE AT THE EGRESS BOUNDARIES — few, and AT THE WRITER so a new caller cannot forget.
   COPY THE MODEL THAT ALREADY WORKS: append_operational_record does not redact, it REJECTS (CON-OPR-002) when a sensitive-shaped key appears at any depth, and its two callers pre-sanitise. One boundary, enforced, 2 call sites. That is the target shape.
   Apply to: (a) RawLogSink / NormalizedEventSink disk writes — OU01 v1 correctly called this 'the most impactful fix'; keep it; (b) logging/audit.py; (c) agent_jobs dead-letter; (d) MCP response emission in foundation/mcp/component_server.py.
   Prefer reject-or-sanitise at the writer over redact-at-the-caller.

5. CLOSE THE GIT-MANAGED GAP (new scope; the highest-value part, and never covered by OU01 v1).
   surfaces/manager.py, toolchains/managed_block.py, toolchains/artifact_registry.py write generated surfaces and managed blocks into GIT-TRACKED files and today have ZERO redaction and no fail-closed check. This is the one destination that is both durable AND shareable. Give them the same fail-closed sensitive-key check operational records has. A secret reaching a generated surface gets committed.

6. EXPLICIT NON-GOAL — NEVER REDACT THE CONFIG-WRITE PATH. Provider config legitimately CARRIES secrets: mcp_config env blocks hold API keys and writing them is the entire feature. Config is the SOURCE of the secret, not a leak of it. Redacting there breaks MCP auth. Add a comment at the managed-config writer stating this and pointing here, or a future reader will 'fix' the apparent omission. Protection for config is ownership/scoping and gitignore, not redaction.

7. FIX THE 2 STALE TESTS to the contract landed in steps 1-2 (they are red at HEAD today). Do NOT simply update them to current behaviour — that ratifies blanking diagnostics.

8. VALIDATE — `python -m pytest tests/unit/foundation -q` (expect the 2 red tests to go green; 9 -> 7 known failures, remainder tracked by RV503/MO02). Key tests: a Bearer token in provider stdout is [REDACTED] in the RawLogSink file on disk; 'https://user:secrettoken@github.com/...' never appears verbatim in local_release output; a diagnostic like 'npm ERR! 404 Not Found' survives an error envelope INTACT (the regression this whole revision exists to fix); a secret-shaped value cannot reach a generated surface. Re-run the touch-point inventory from step 0 and record the new count — the number must go DOWN.

## Validation

1. SENSITIVE_KEY_PATTERN is split: SECRET_KEYS blanket-replaced, BULK_KEYS content-redacted + truncated. No caller re-folds narrow keys into the shared matcher. 2. The content matcher is key-preserving ('token: [REDACTED]', not '[REDACTED]'). 3. Redaction call-site count is materially DOWN from 66 and every remaining site is a durable/shareable destination. 4. Every egress boundary (RawLogSink, NormalizedEventSink, audit log, dead-letter, operational records, MCP responses) enforces sanitisation AT THE WRITER. 5. Git-managed writers (surfaces/manager.py, managed_block.py, artifact_registry.py) have a fail-closed sensitive-key check. 6. The config-write path is NOT redacted and carries a comment saying why. 7. A clean diagnostic survives an error envelope intact. 8. redact_text's pattern set lives in exactly one place; no module defines a local variant. 9. The 2 previously-red component_server tests pass against the new contract.

## Effort & Risk

Mid. Step 3 (deleting ~60 calls) is broad but mechanical and each deletion is justified by a single question: does this value reach a file, log, or git? Step 5 is the only genuinely new work. Main risk is someone 'restoring' a deleted in-flight redact_text or re-folding narrow keys into the shared matcher — both are the exact mistakes being undone, so the rationale must be in the code comments, not only here. Second risk is over-correcting into the config-write path and breaking MCP auth (step 6). Do steps 1-2 first: they are small, they make the rest testable, and they turn the 2 red tests into a real signal.
