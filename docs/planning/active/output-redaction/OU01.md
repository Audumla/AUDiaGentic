# Fan out shared redaction primitive to non-recipe stdout/stderr capture sites

## Description

Companion to recipe-system-review RS05/RS15/RS16. Those items confirmed that provisioning shell steps capture raw, unredacted stdout/stderr into structured results. The same unredacted-capture shape exists outside the recipe system in modules RS05 explicitly must not touch: `foundation/workflow/invocation/steps.py::ShellStep` (the workflow-layer sibling that RS04/SL09 deliberately keeps separate from `ShellProvisionStep`), `components/source_control/git_commits.py`, provider adapters/hooks that shell out (`components/providers/adapters/*/hooks.py`, `*/adapter.py`), and harness runners (`runtime/harness/pi/runner/agent_run.py`, `runtime/harness/opencode/runner/__init__.py`). This item audits those call sites and applies the shared redaction primitive RS16 builds at `foundation/logging/redaction.py`, rather than duplicating redaction logic per subsystem.

Dependency: RS16 must land first — this item consumes the shared primitive it creates; do not build a second redaction utility here.

## Steps

Depends on RS16 landing first (`foundation/logging/redaction.py::redact_text()`/`redact_env_like()`). Do not start until that module exists and its tests pass.

1. `git grep -n "subprocess.run\|subprocess.Popen\|\.stdout\|\.stderr" -- src/audiagentic/foundation/workflow/invocation/steps.py src/audiagentic/components/source_control/git_commits.py src/audiagentic/components/providers/adapters src/audiagentic/runtime/harness/pi/runner/agent_run.py src/audiagentic/runtime/harness/opencode/runner/__init__.py` and classify each match as: (a) leak — raw output flows into a return value, log call, or persisted record; (b) already-safe — output is discarded, only exit code used; (c) binary/no-op — not text output.
2. For `foundation/workflow/invocation/steps.py::ShellStep` (the RS04-confirmed sibling of `ShellProvisionStep`): apply the same `redact_text()` treatment to its `outputs`/`reason` fields at the same boundary points RS16 patched in `shell.py`. This is composition (import and call), not a merge of the two classes — the SL09 won't-merge doctrine between `ShellStep` and `ShellProvisionStep` still holds; only the redaction call is shared.
3. For `components/source_control/git_commits.py`: find where git command output or remote URLs are captured/logged; if a remote URL can carry embedded credentials (`https://user:token@host/...`), add a URL-credential-stripping regex to `redact_text()`'s pattern set in `foundation/logging/redaction.py` (extend `_DEFAULT_PATTERNS`, do not fork a second copy) and apply it at this module's output boundary.
4. For provider adapter hooks that shell out (`components/providers/adapters/*/hooks.py`, `*/adapter.py`): identify which adapters actually capture subprocess output into a result/log (many may only check exit codes — confirm before touching). Apply `redact_text()` only where output is captured into a structured/returned value.
5. For harness runners (`runtime/harness/pi/runner/agent_run.py`, `runtime/harness/opencode/runner/__init__.py`): same treatment — apply at the boundary where subprocess/agent output is persisted or returned, not inside the streaming/interactive path (do not change interaction semantics, matching RS05's own constraint).
6. Add characterization-then-fix tests per touched module, mirroring RS15/RS16's pattern: one test proving the leak before the fix (or skip this if the module has no existing test file — in that case go straight to a post-fix test, noting in this item's notes why no characterization test was added).
7. Run the full test suite for each touched subsystem: `python -m pytest tests/unit/foundation/workflow tests/unit/source_control tests/unit/providers -v` (adjust paths to match actual test locations — confirm with Glob before assuming).

## Validation

1. Every leak classified in step 1 is either fixed (routed through `redact_text()`/`redact_env_like()`) or explicitly documented as already-safe/binary with a one-line rationale in this item's Notes.
2. No command-execution semantics changed in any touched file — diff review confirms only output-capture/redaction lines changed.
3. `git_commits.py` credential-URL stripping is covered by a test asserting a URL like `https://user:secrettoken@github.com/...` never appears verbatim in logged/returned output.
4. Full relevant test suites pass: `python -m pytest tests/unit/foundation/workflow tests/unit/source_control tests/unit/providers -v` (confirm exact directory names before running).
5. `redact_text()`'s pattern set lives in exactly one place (`foundation/logging/redaction.py`) — no module in this item defines its own regex list.

## Effort & Risk

Mid. Investigative fan-out across modules owned by different subsystems (workflow, source_control, providers, runtime/harness) rather than a single-owner refactor. Risk is scope creep across unrelated call sites — mitigate by touching only the boundary where output is persisted/surfaced, not execution logic, and by reusing RS16's primitive rather than writing new redaction logic per site.
