# Fan out shared redaction primitive to non-recipe stdout/stderr capture sites

## Description

Companion to recipe-system-review RS05/RS15/RS16. Those items confirmed that provisioning shell steps capture raw, unredacted stdout/stderr into structured results. The same unredacted-capture shape exists outside the recipe system in modules RS05 explicitly must not touch. This item audits ALL subprocess output-capture call sites across the codebase and applies the shared redaction primitive from `foundation/logging/redaction.py`, rather than duplicating redaction logic per subsystem.

Dependency: RS16 must land first — this item consumes the shared primitive it creates; do not build a second redaction utility here.

## Steps

Depends on RS16 landing first (`foundation/logging/redaction.py::redact_text()`/`redact_env_like()`). Do not start until that module exists and its tests pass.

### Phase 1: Extend redaction primitive (if needed)

0. Audit `DEFAULT_REDACT_PATTERNS` in `foundation/logging/redaction.py` against the following additional patterns needed by this plan:
   - URL-embedded credentials: `https://user:password@host/...` pattern (for git remote URLs in local_release.py stderr and git_commits.py)
   - TWINE_PASSWORD / PyPI token format (if not covered by existing `api_key/token/password` pattern)
   - Add any missing patterns to `_DEFAULT_PATTERNS`; do NOT fork a second regex copy.

### Phase 2: HIGH RISK sites (fix first)

1. **`components/release/local_release.py`** — Apply redaction at output boundaries:
   a. In `_publish_pypi()`: apply `redact_text()` to `proc.stderr` before returning in result dict and before constructing error messages.
   b. In `_create_git_tag()`: apply `redact_text()` to `exc.stderr` before `logger.warning()` and before returning in result dict. Consider adding the URL-credential-stripping regex to `DEFAULT_REDACT_PATTERNS` if git URLs with embedded credentials could appear in stderr.
   c. In `_create_github_release()`: apply `redact_text()` to `proc.stderr` before returning in result dict.
   d. Verify no command-execution semantics changed — only output-capture/redaction lines changed.

2. **`components/providers/protocols/streaming/sinks.py::RawLogSink`** — Apply redaction before disk write:
   a. Add `redact_text()` call in `RawLogSink.write()` to redact each line before writing to disk. This is the most impactful fix: prevents credential-bearing provider output from persisting on disk.
   b. Consider whether `NormalizedEventSink` also needs redaction — its `write_event()` includes a `"message"` field (line 207) that contains raw stream text; this persists to `events.ndjson` on disk.
   c. Do NOT add redaction to `InMemorySink` or `ConsoleSink` at this boundary — the provider execution pipeline already returns these values through `base_runner.py::finalize_run()` which is a separate boundary (step 3).

### Phase 3: MEDIUM-HIGH RISK sites

3. **`components/providers/adapters/base_runner.py`** — Apply redaction at the finalize boundary:
   a. In `finalize_run()`: apply `redact_text()` to `stdout_text` and `stderr_text` before storing in result dict (lines 205-207) and before passing to `persist_completion()` / `normalize_provider_result()` / `build_synthetic_fallback()`.
   b. In the `AudiaGenticError` constructor (lines 274-286): apply `redact_text()` to stdout/stderr in the details dict — note that errors.py `_redact_value()` truncates but does NOT pattern-redact stdout/stderr, so redaction must happen at this call site.
   c. Apply `redact_text()` to the command string as well (RS16 precedent) in case a literal secret was passed as an argument.

4. **`runtime/harness/pi/runner/agent_run.py:95-112`** — Agent smoke test:
   a. Apply `redact_text()` to log file contents before writing to sys.stdout (line 112). The file write path is the streaming Popen redirect — redaction at the boundary where output is surfaced, not in the streaming path.

5. **`runtime/harness/pi/install/__init__.py`** and **`runtime/harness/opencode/install/__init__.py`** — npm install subprocesses:
   a. Identify where stdout/stderr are captured into return values or error messages.
   b. Apply `redact_text()` at the output boundary (before returning or logging).

### Phase 4: MEDIUM RISK sites (workflow + providers)

6. **`foundation/workflow/invocation/steps.py::ShellStep`** — Apply redaction to structured outputs:
   a. After building the StepResult, apply `redact_text()` to `"stdout"` output value and to `reason` before returning (line 176-184).
   b. Apply `redact_text()` to the joined command string in case a literal secret was passed as an argument.
   c. Do NOT change execution semantics — streaming path, progress callback, timeout handling unchanged.

7. **`foundation/workflow/invocation/steps.py::CallableStep`** — Apply redaction:
   a. Apply `redact_text()` to stdout and stderr before storing in StepResult outputs dict (lines 221-222).
   b. Apply `redact_text()` to the reason field (line 224).

8. **`components/providers/adapters/*/hooks.py`** — Provider hooks:
   a. For each adapter that captures subprocess output into structured result dicts, apply `redact_text()` at the boundary where stdout/stderr are assigned to dict values.
   b. Confirm before touching: many hooks may only check exit codes and not capture output.

### Phase 5: Additional medium-risk sites

9. **`runtime/harness/rig.py`** — Embedded rig launcher:
   a. Apply `redact_text()` to stderr/stdout in error exception message (line 83) on launch failure.

10. **`components/coding_lsp/lsp_diagnostics.py`** — LSP batch diagnostics:
    a. Apply `redact_text()` to stderr before storing in error details dict (line 184).

### Phase 6: LOW RISK — confirm already-safe

11. For each LOW RISK site (items 14-20), add a one-line comment documenting why redaction is not needed at that boundary (e.g., `# Low risk: only git SHA output, no credential content possible`).

### Phase 7: Testing

12. Add characterization-then-fix tests per touched module, mirroring RS15/RS16's pattern:
    - One test proving the leak before the fix (or skip if the module has no existing test file — go straight to a post-fix test, noting in this item's notes why no characterization test was added)
    - Key test: assert that a URL like `https://user:secrettoken@github.com/...` never appears verbatim in logged/returned output from local_release.py
    - Key test: assert that a Bearer token or API key appearing in provider stdout is redacted before being written to RawLogSink disk files
13. Run full test suites for each touched subsystem:
    - `python -m pytest tests/unit/foundation/workflow -v`
    - `python -m pytest tests/unit/foundation/logging -v` (redaction.py)
    - `python -m pytest tests/unit/source_control -v` (confirm paths first)
    - `python -m pytest tests/unit/providers -v` (confirm paths first)
    - `python -m pytest tests/unit/release -v` (confirm paths first)

## Validation

1. Every HIGH and MEDIUM-HIGH risk site has redaction applied at its output boundary — diff review confirms only output-capture/redaction lines changed.
2. No command-execution semantics changed in any touched file — only output-capture/redaction lines changed.
3. URL-credential stripping is covered by a test: `https://user:secrettoken@github.com/...` never appears verbatim in logged/returned output from local_release.py on error paths.
4. Provider CLI output redacted before disk persistence: RawLogSink write path applies `redact_text()`; verify with test that a Bearer token appearing in provider stdout is `[REDACTED]` in the log file.
5. base_runner finalize_run: both result dict and persisted completion contain redacted stdout/stderr.
6. Full relevant test suites pass (step 13 above).
7. `redact_text()`'s pattern set lives in exactly one place (`foundation/logging/redaction.py`) — no module in this item defines its own regex list.
8. Every LOW RISK site has a one-line comment documenting why redaction is not needed.

## Effort & Risk

Mid-high. Investigative fan-out across modules owned by different subsystems (release, providers, workflow, runtime/harness, coding_lsp) rather than a single-owner refactor. The `RawLogSink` fix in step 2b is the highest-impact change: it prevents credential-bearing provider output from persisting on disk.

Risk is scope creep across unrelated call sites — mitigate by touching only the boundary where output is persisted/surfaced, not execution logic, and by reusing RS16's primitive rather than writing new redaction logic per site.

The `_redact_value()` in errors.py (which truncates but does NOT pattern-redact stdout/stderr) must be addressed at each call site rather than modified in-place — modifying it would affect all error paths, which is a broader change than this item's scope. Document this distinction clearly.

## Standards

§15 (Output Redaction) — all subprocess output-capture boundaries must apply redact_text(). §8 (Error Handling) — error details never include raw stdout/stderr. §9 (Logging) — module-level logger only.
