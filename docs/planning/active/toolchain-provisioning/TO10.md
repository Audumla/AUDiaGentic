# ProvisionStep unified step model

## Description

Introduce a ProvisionStep protocol in foundation/toolchains/provision_step.py that gives every execution primitive — shell commands, config-key writes, managed rule blocks, file writes — a common run(context) / revert(context) / dry_run(context) interface.

This is the foundation layer for TO11 (CompensatingSequence) and TO12 (recipe migration). It does NOT change any callers, recipe classes, lifecycle orchestration, or YAML schema yet.

**Why this unification is valid:**

ConfigPatcher already captures revert state in OwnedChange.prior_value. managed_block already has apply_managed_block / remove_managed_block as inverse pairs. File writes can capture prior file existence/content during run(). Shell operations are not automatically reversible and need an explicit revert command, or no-op best-effort revert when none is declared.

The primitives split into two groups:
- Self-reverting: ConfigSetStep, ManagedBlockStep, WriteFileStep — revert is derived from captured run() state or inverse operation
- Explicit-revert: ShellProvisionStep — caller declares the revert command or leaves it None

**Relationship to existing step system:** ShellProvisionStep wraps ShellStep for normal argv commands. For shell-only commands such as pipes, ShellProvisionStep owns the shell subprocess execution unless ShellStep is extended in the same change. The workflow step system (SequenceStep, SelectStep, ConditionalStep) stays for non-provisioning orchestration. ProvisionStep is narrowly scoped to installable-integration lifecycle operations.

**S1 — Layer boundary constraint:** provision_step_from_dict lives in foundation/ and CANNOT import HindsightBackendConfig or any components/ type. The factory takes params: dict[str, str] only. Callers in components/ build this dict from backend config before calling the factory.

## Steps

1. **Define `ProvisionStep` protocol** in `foundation/toolchains/provision_step.py`:
```python
class ProvisionStep(Protocol):
    id: str
    def run(self, context: dict) -> StepResult: ...
    def revert(self, context: dict) -> StepResult: ...
    def dry_run(self, context: dict) -> StepResult: ...
```

2. **Implement `ShellProvisionStep`** — wraps `ShellStep` for the argv `run` path, wraps an optional revert `ShellStep` for `revert`. Supports `shell=True` for commands such as `curl ... | bash` that cannot be represented as argv; in that mode ShellProvisionStep owns the shell subprocess execution. If `revert_command` is None, `revert()` returns `StepResult(status='skipped', reason='no revert declared')`.

3. **Implement `ConfigSetStep`** — wraps `ConfigPatcher.set_key(path, key_path, value)`. `run()` calls `set_key` and records the `OwnedChange`. `revert()` uses `OwnedChange.prior_value` to call `remove_key` if prior value was absent, or `set_key(prior_value)` if prior value existed. If `run()` never completed, `revert()` skips safely.

4. **Implement `ManagedBlockStep`** — wraps `apply_managed_block(path, block_id, text)`. `revert()` calls `remove_managed_block(path, block_id)`.

5. **Implement `WriteFileStep`** — writes content to a path, optionally creating parent dirs. `run()` records whether the file existed and prior content when needed. `revert()` deletes the file if it did not exist before `run()`, or restores prior content if it existed.

6. **Implement `provision_step_from_dict(data, params)`** — factory for later YAML deserialization. Validates `type` against known step types; resolves placeholders against supplied `params` at construction time. The factory does not know which params are required by Hindsight; it only substitutes keys provided by the caller.

7. **Export from `foundation/toolchains/__init__.py`**: `ProvisionStep`, `ShellProvisionStep`, `ConfigSetStep`, `ManagedBlockStep`, `WriteFileStep`, `provision_step_from_dict`.

- `src/audiagentic/foundation/toolchains/provision_step.py` — new module (primary deliverable)

## Validation

- ShellProvisionStep.run(): success -> StepResult(status='ok'); command failure -> StepResult(status='failed').
- ShellProvisionStep.run(shell=True) executes a pipe command through shell subprocess path and returns failed on non-zero exit.
- ShellProvisionStep.revert() with no revert command -> StepResult(status='skipped'), not error.
- ConfigSetStep.run() on empty file -> creates key; subsequent .revert() -> key absent.
- ConfigSetStep.run() on file with existing key -> overwrites; .revert() -> restores prior value.
- ConfigSetStep.revert() before successful run() -> StepResult(status='skipped'), no mutation.
- ManagedBlockStep.run() / .revert() round-trip: block present after run, absent after revert.
- WriteFileStep.run() / .revert() round-trip covers created file and overwritten file.
- provision_step_from_dict({'type': 'shell', 'command': ['pip', 'install', 'X']}, params={}) -> valid ShellProvisionStep.
- provision_step_from_dict({'type': 'unknown', ...}, ...) -> raises AudiaGenticError(code='VAL-PSTEP-001', message='Unknown ProvisionStep type: unknown') — never raw ValueError (S8).
- All existing unit tests pass (this item adds code only, touches no existing callers).

## Effort & Risk

Mid complexity, low risk. This item creates a new module with no callers, so it should not regress existing behaviour. Main risks are reversible state capture and shell=True execution. Keep tests focused on exact rollback state and error shapes.

## Standards

- S1 (Layering): provision_step_from_dict lives in foundation/toolchains/ and MUST NOT import HindsightBackendConfig or any components/ type. The factory signature is provision_step_from_dict(data: dict, params: dict[str, str]). The caller in components/ builds the params dict from backend config.
- S8 (Error handling): Unknown type in provision_step_from_dict raises AudiaGenticError(code='VAL-PSTEP-001'), not ValueError. All public-boundary exceptions use AudiaGenticError.

## Notes

Prerequisite for TO11 (CompensatingSequence) and TO12 (recipe migration).

**ArtifactRegistry integration:** `ConfigSetStep`, `ManagedBlockStep`, and `WriteFileStep` may accept optional `ArtifactRegistry | None` plus `recipe_id`. When provided, `run()` registers owned artifacts after successful mutation so a later prune in a separate process can discover them. Registry support is not required for in-process rollback, but is required for cross-session prune.

**Placeholder params:** Hindsight callers must pass params such as {"URL": backend.base_url, "MCP_URL": backend.mcp_url, "KEY": backend.api_key}. The foundation factory only substitutes supplied params; it does not construct or require Hindsight-specific keys.
