# SA11 — Add distribution content manifest and security scan

## Description

Ensure wheels and source distributions contain only intended public files. Build artifacts in clean CI, generate a content manifest, and scan for unexpected files. Based on SEC-16 from the security audit.

## Steps

1. Build the wheel and source distribution in a clean CI environment
2. Generate a content manifest listing all files in both artifacts
3. Compare against an explicit allowed package-content allowlist
4. Extract both artifacts and run secret scanning
5. Run privacy and machine-specific-value scanning on extracted contents
6. Verify ignored runtime directories (`.audiagentic/runtime/`, `.audiagentic/sessions/`, `.audiagentic/logs/`) are absent
7. Store the manifest as a CI artifact for review
8. Fail CI on unexpected file additions

## Files

- `.github/workflows/security-package-scan.yml` (new)
- `pyproject.toml` (package-data globs may need updating)

## Validation

- [ ] Unexpected file addition fails CI
- [ ] Build artifacts pass secret and privacy scanning
- [ ] Runtime directories (`.audiagentic/runtime/`, `.audiagentic/sessions/`, `.audiagentic/logs/`) are absent from artifacts
- [ ] `.env`, credentials, logs, sessions, caches, local databases, and runtime state are absent
- [ ] Package-data changes require review of the explicit manifest
- [ ] Build reproducibility from a clean checkout is verified

## Effort & Risk

Mid complexity. Requires CI workflow configuration and manifest management. Low risk — scanning is additive and non-destructive.

## Standards

- SEC-16 — Build artifacts must be scanned, not only source files

## Notes

Depends on SA01 (secret scanning) for the scan infrastructure and SA03 (packaged config policy) for the portability validator.
