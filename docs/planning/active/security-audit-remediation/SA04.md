# SA04 — Resolve rig model registry ownership

## Description

Separate portable model profiles from machine-discovered model inventory in the rig embedded models registry. Based on SEC-03 from the security audit.

## Steps

1. Inspect `src/audiagentic/runtime/rig/embedded/models.json` and classify every field
2. Move authored portable profiles into a public catalogue at `src/audiagentic/config/rig/model-profile-catalogue.json`
3. Move detected or selected models into runtime state (private, untracked)
4. Update package-data globs in `pyproject.toml` to exclude machine inventory
5. Update loaders to read from the new public catalogue path
6. Update tests to use the new path
7. Add migration behavior if existing users rely on the old path
8. Verify the public catalogue contains no local paths, IPs, hostnames, ports, model downloads, or hardware assignments

## Files

- `src/audiagentic/runtime/rig/embedded/models.json`
- `src/audiagentic/config/rig/model-profile-catalogue.json` (new)
- `pyproject.toml`
- Loader files that reference the old path

## Validation

- [ ] Machine inventory is absent from built distributions (wheel and sdist)
- [ ] Public catalogue is portable (no local paths, IPs, hostnames, GPU assignments)
- [ ] Runtime discovery never writes into package source
- [ ] All existing tests pass with the new path
- [ ] Package build tests confirm machine inventory files are absent from the wheel

## Effort & Risk

Mid complexity. Requires careful separation of authored vs. generated content. Risk of breaking existing users if migration path is not handled.

## Standards

- SEC-03 — Ambiguous ownership of `runtime/rig/embedded/models.json`

## Notes

Depends on SA03 (packaged config policy) for the portability validator. Coordinate with SA03 implementation.
