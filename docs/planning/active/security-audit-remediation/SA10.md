# SA10 — Scan planning, reviews, ledgers, and fixtures

## Description

Prevent non-code tracked content from becoming a secret and privacy bypass. Apply secret and privacy scanning to documentation, planning files, release ledgers, and test fixtures. Based on SEC-13 from the security audit.

## Steps

1. Include all documentation and ledger formats (`.md`, `.ndjson`, `.jsonl`, `.log`) in secret scans
2. Add structured ledger input validation to prevent secret-bearing fields from being persisted
3. Redact planning extracts before they are written to tracked files
4. Replace real identities and topology in test fixtures with synthetic values
5. Add review guidance for pasted command output (reject or redact raw environment dumps)
6. Ensure release ledger cannot persist secret-bearing fields
