# SA10 — Scan planning, reviews, ledgers, and fixtures

## Description

Prevent non-code tracked content from becoming a secret and privacy bypass. Apply secret and privacy scanning to documentation, planning files, release ledgers, and test fixtures. Based on SEC-13 from the security audit.

## Steps

1. Include all documentation and ledger formats (`.md`, `.ndjson`, `.jsonl`, `.log`) in secret scans
2. Add structured ledger input validation to prevent secret-bearing fields from being persisted
3. Redact planning extracts before they are written to tracked files
4. Replace real identities and topology in test fixtures with synthetic values
5. Add review guidance for pasted command output (reject or redact raw environment dumps)
6. Ensure release ledger cannot persist secret-bearing fields

## Files

- `docs/planning/` (scan target)
- `docs/releases/` (scan target)
- `tests/fixtures/` (scan target)
- Ledger API modules
- Planning extraction modules
- `tests/security/test_tracked_content_scanning.py` (new)

## Validation

- [ ] Markdown, NDJSON, JSONL, snapshots, and fixtures are scanned
- [ ] Raw environment and command dumps are rejected or redacted before persistence
- [ ] Release ledger cannot persist secret-bearing fields
- [ ] Test fixtures use synthetic paths, hosts, identities, and credentials
- [ ] No real user names, hostnames, or endpoint addresses appear in fixtures

## Effort & Risk

Mid complexity. Requires extending existing scan infrastructure to cover non-code file types. Low risk — scanning is additive.

## Standards

- SEC-13 — Planning documents and release ledgers can leak operational information
- SEC-24 — Session and provider thread identifiers are sensitive operational data

## Notes

Depends on SA01 (secret scanning) for the scan infrastructure and SA06 (redaction) for the redaction pipeline.
