# SA08 — Split tracked project policy from private project configuration

## Description

Provide a safe source-controlled project policy lane (`.audiagentic-project/`) without exposing local instances or secrets. Based on SEC-10 from the security audit.

## Steps

1. Define `.audiagentic-project/` directory structure with strict schemas
2. Add schemas for `project.yaml`, `roles.yaml`, `provider-requirements.yaml`, `quality-gates.yaml`
3. Prohibit credential and endpoint-instance fields in the tracked policy schemas
4. Define merge precedence: tracked policy < user-global < project-private < machine-private < environment
5. Update documentation and CLI status to show layer source
6. Keep `.audiagentic/` always private and always ignored
7. Ensure private runtime configuration never merges back into the tracked policy files

## Files

- `.audiagentic-project/project.yaml` (new)
- `.audiagentic-project/roles.yaml` (new)
- `.audiagentic-project/provider-requirements.yaml` (new)
- `.audiagentic-project/quality-gates.yaml` (new)
- Schema files for the new directory
- CLI status module
- Documentation

## Validation

- [ ] Project policy is reproducible and safe to commit
- [ ] Credential-like fields are forbidden by schema validation
- [ ] Endpoint URLs and absolute paths are forbidden unless explicitly classified as public project metadata
- [ ] Private values cannot be projected back into tracked policy files
- [ ] Layer source is visible in CLI status output
- [ ] Private runtime configuration never merges back into tracked policy files

## Effort & Risk

Mid complexity. Requires schema design and merge precedence implementation. Low risk — additive change that doesn't affect existing behavior.

## Standards

- SEC-10 — No explicit safe lane for tracked project policy
