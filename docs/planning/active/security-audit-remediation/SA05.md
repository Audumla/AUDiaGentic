# SA05 — Add first-class `SecretRef`

## Description

Prevent raw credentials from becoming normal persisted configuration values by introducing a typed `SecretRef` contract. Based on SEC-14 from the security audit.

## Steps

1. Define `SecretRef` contract and schema supporting `environment`, `keyring`, and `process-injected` sources
2. Update provider, MCP, plugin, hook, and endpoint config contracts to use `SecretRef` instead of raw strings
3. Resolve secrets only at the final execution boundary (never during config loading)
4. Ensure status and error paths never return resolved values
5. Reject raw secret fields in persisted desired state with validation errors
6. Add migration diagnostics for existing configs that use raw values
7. Update all config schemas to distinguish environment variable name fields from raw secret fields
8. Ensure generated documentation may list variable names but never values

## Files

- `src/audiagentic/config/secret_ref.py` or equivalent (new)
- Provider descriptor schemas
- MCP config schemas
- Plugin and hook config schemas
- Endpoint config schemas
- Config validation modules
- `tests/security/test_secret_ref.py` (new)

## Validation

- [ ] Raw API key fields fail validation with clear error messages
- [ ] Secret references round-trip safely through serialization/deserialization
- [ ] Resolution values never appear in logs, status output, or operational records
- [ ] Missing secrets produce actionable but redacted errors
- [ ] Schemas reject raw credential-bearing fields
- [ ] APIs accept `SecretRef` rather than `str` for credential parameters
- [ ] Resolved values are not returned in status objects
- [ ] Resolved values are not written into generated config unless the provider strictly requires it and the destination is private with restrictive permissions
- [ ] Error messages never include resolved values

## Effort & Risk

Complex. This is a foundational architectural change that touches many components. Risk of breaking existing config loading if not carefully migrated. Requires coordination across all config consumers.

## Standards

- SEC-14 — Persisted configuration must use secret references
- SEC-20 — Environment-variable names are safe; environment-variable values are not

## Notes

This is the most impactful architectural change from the audit. It should be implemented with a migration path — existing raw-value configs should produce deprecation warnings before being rejected. Coordinate with SA06 (redaction) and SA08 (tracked project policy).
