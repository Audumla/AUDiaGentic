# SA19 — Test credentials and canaries standard

## Description

Establish a convention for unmistakably synthetic test credential values and canary tests that prove public boundaries reject credential-bearing content. Based on SEC-19 from the security audit.

## Steps

1. Document the required convention in a test standards file or README
2. Use unmistakably synthetic values: `example-token-not-a-secret`, `test-api-key-redacted`, `AUDIAGENTIC_TEST_SECRET`
3. Ensure no realistic provider key format is used outside scanner-specific test directories
4. Add canary tests that prove public boundaries reject credential-bearing prompts and records
5. Keep fixture values under a dedicated scanner-test directory with exact-path allowlist entries

## Files

- `tests/security/` (new directory)
- `tests/security/README.md` (new)
- `tests/security/test_canaries.py` (new)

## Validation

- [ ] No realistic provider key format (`sk-*`, `ghp_*`, etc.) appears outside scanner-specific tests
- [ ] Canary test proves a credential-shaped value in a prompt is detected/rejected
- [ ] Test fixtures contain no real user names, hostnames, or endpoint addresses
- [ ] All test credential values are unmistakably synthetic

## Effort & Risk

Simple test additions. Low risk — tests only, no production code changes.

## Standards

- SEC-19 — Test credentials and canaries need an explicit standard
