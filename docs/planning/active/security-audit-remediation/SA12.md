# SA12 — Add secret incident response procedure

## Description

Provide a deterministic response procedure when leaked material is discovered in the repository. Based on SEC-18 from the security audit.

## Steps

1. Create `docs/security/SECRET_INCIDENT_RESPONSE.md`
2. Document immediate credential rotation steps
3. Document history and artifact search (Gitleaks, TruffleHog, `git log --all`)
4. Document `git filter-repo` usage for history cleanup
5. Document coordination for force pushes and branch protection
6. Document package and release invalidation
7. Add post-remediation verification checklist
8. Ensure the procedure never instructs maintainers to reproduce a live secret in an issue or plan

## Files

- `docs/security/SECRET_INCIDENT_RESPONSE.md` (new)

## Validation

- [ ] Procedure is actionable by a local agent with no prior context
- [ ] Rotation precedes history cleanup in the documented workflow
- [ ] No step instructs reproducing a live secret value
- [ ] Commands for Gitleaks, TruffleHog, and `git filter-repo` are included
- [ ] Post-cleanup verification steps are documented

## Effort & Risk

Simple documentation task. Low risk — no code changes.
