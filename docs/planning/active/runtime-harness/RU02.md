# Remove components' direct runtime-harness dependency (project + session)

## Description

Product components import runtime.harness directly to call its public forwarding functions (build_runtime_sync, default_config_path, query_rig_server_version, version_info): components/project/project_components.py:27 (now narrowed to a read-only harness_cli_available check), components/project/project_api.py:11, components/session/session_api.py:12, components/session/session_runtime_status.py:18,36,77. This crosses from product components into runtime orchestration -- a layering violation -- even though every call target is already a public facade function in runtime/harness/__init__.py, not an internal.

Use the existing registered capability/composition seam employed by foundation lifecycle, or a narrow composition-root binding, so components depend on a foundation-owned capability rather than the runtime package name directly.
Project and session lifecycle behavior should work when no harness is active.
