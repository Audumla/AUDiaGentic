# Error-resolutions.yaml coverage audit — add 79 missing error codes, enforce config-driven messages, update Standard 8

## Description

Audit revealed that 79 of 188 unique error codes used in source code (42%) have no entry in any error-resolutions.yaml file. Additionally, all errors use inline messages in AudiaGenticError(...) calls rather than looking up the message from YAML via get_error_message(code). This violates Standard 8's intent that error ownership be split between code (identity) and config (resolution), and creates a maintenance burden where changing an error message requires editing Python source.

## Violations found

### Two categories of non-compliance

1. **Missing YAML entries** — 79 codes used in code but absent from all 8 error-resolutions.yaml files. The fallback `get_error_resolution(code)` returns the raw code string, producing unhelpful diagnostic output.
2. **Inline messages bypassing YAML lookup** — even where YAML entries exist, all sites use `AudiaGenticError(code="...", message="hardcoded text")` with inline messages that shadow whatever the YAML file might contain, making YAML values stale/unreachable.

## Fixes required

### Phase 1: Create missing error-resolutions.yaml files

Create new YAML files for domains that currently lack coverage:

1. **`config/components/agents/error-resolutions.yaml`** — AGW and AGP codes (28 codes)
2. **`config/components/planning/error-resolutions.yaml`** — PLN codes (15 codes)
3. **Extend `config/components/release/error-resolutions.yaml`** — add RELEASE codes (6 new entries)
4. **`config/components/memory/error-resolutions.yaml`** — MEM and RSPEC codes (6 codes)
5. **Extend `config/components/providers/error-resolutions.yaml`** — OPENAI codes (6 new entries)
6. **`config/components/foundation/error-resolutions.yaml`** — COMP, DESC, INTERACT, EVT, CFG codes that belong in foundation (add to existing file: 13 new entries)
7. **Extend `config/components/agent-jobs/error-resolutions.yaml`** — AGJ, EXEC, STAGE codes (4 new entries)

For each code, populate the resolution text from the inline message currently used at that site in Python source.

### Phase 2: Update Standard 8 in ARCHITECTURE_STANDARDS.md

Add explicit rule requiring all error codes to have YAML coverage before they are used. The standard should state:
- Every `AudiaGenticError` raised with a canonical code must have that code registered in the owning component's `error-resolutions.yaml`
- Inline `message=` at raise site is acceptable as the operator-facing statement (Standard 8 already states: "message is the concise operator-facing statement raised by code")
- `resolution` in YAML is optional agent/operator guidance
- A lint check or CI gate should be added to prevent new codes from being introduced without YAML registration
