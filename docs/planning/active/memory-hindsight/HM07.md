# Contained Hindsight orchestration, lifecycle wiring, status

## Description

Orchestrate Hindsight provider setup inside the Hindsight memory implementation package without embedding Hindsight into the providers component. Memory core owns backend config only. `components/memory/hindsight/` owns Hindsight-specific strategy resolution/install/teardown/status and may use small, explicit generic provider seams. Providers own generic recipe interfaces, descriptor lookup, and generic config writers only.

## Steps

['memory/hindsight/recipes.py: apply_hindsight(project_root) -> iterate installed+enabled providers via controlled descriptor/read-model seam; for each resolve_hindsight_strategy + build_hindsight_recipe(backend); run recipe.provision({}). teardown_hindsight(project_root[,provider_id]) -> recipe.teardown({}).', 'Memory core lifecycle seam: select_implementation/set_config/enable/disable only persists memory state and returns/emits a generic refresh-needed hint. It must NOT call apply_hindsight, apply_provider_surfaces, providers services, provider writers, or provider observers.', 'Contained orchestration seam: a memory/hindsight management tool or lifecycle observer consumes the refresh hint and invokes memory/hindsight apply/teardown. If an observer is needed, it lives as an adapter boundary with architecture tests; do not place Hindsight code in providers.', 'Backend switch (url/token/bank change): memory/hindsight apply detects stale owned artifacts/entries and rewrites them. Memory core reports config changed; Hindsight implementation executes reconciliation.', 'Status: memory/hindsight status reports per provider {strategy_kind, state(verified|absent|error|blocked), source_status, owned_artifacts}. memory_status reports only backend implementation/config health plus neutral refresh-needed state if present.', 'Concurrency/idempotency: provision is idempotent; teardown tolerant of already-removed artifacts; unit tests use fake recipes and never execute host-native installers.']

## Effort & Risk

Complex. DEPENDS ON HM03/HM04/HM05/HM06 (needs builder + all strategy kinds). Risk: native-installer provisioning is slow/env-changing — gate on opt-in + Docker for tests; do not run host installers in unit tests. Highest risk is boundary regression: Hindsight must remain contained to memory/hindsight and not leak into provider core.

## Notes

This replaces both bad extremes: memory core must not push provider surfaces, and providers core must not embed Hindsight. Use a small contained memory/hindsight boundary adapter when cross-component coordination is unavoidable.
