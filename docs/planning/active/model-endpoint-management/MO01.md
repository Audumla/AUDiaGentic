# Define provider-owned model endpoint contract

## Description

Define the provider-owned model endpoint contract: the project-level model-endpoints desired-state shape and how it binds to the consolidated managed-config machinery (MO06), not a new bespoke spec. Decides where model endpoint state lives, how multiple local/custom models are represented, how aliases/defaults interact with agent profiles, and how the model kind reuses the ManagedConfigSpec reader/writer/remover contract. Scope stays under providers; agents continue to bind jobs to provider/model only. The full contract + comprehensive capability matrix (with FILL placeholders for unverified per-provider fields) now lives in docs/reference/PROVIDER_MODEL_ENDPOINT_CAPABILITIES.md — this item points at it rather than restating it.

## Steps

1. Validate current provider config, model catalog, agent profile, recipe, and managed-config (MCP/LSP) ownership flows.
2. Define the canonical project config for multiple model endpoints (endpoint id, display name, connector, base URL, api-key-ref, model id, context window, max output tokens, capabilities, provider-overrides, default selection) per the reference doc's Managed Model Shape.
3. Define the CONNECTOR taxonomy as an endpoint field (openai-compatible | anthropic | gemini | openrouter | litellm | ollama | native-vendor), replacing the single protocol: openai-compatible. Include connector-specific fields (anthropic version, gemini api-version, openrouter routing prefs / namespaced model-id) — many are FILL until confirmed per agent.
4. Add a per-provider supported-connectors declaration on the descriptor so projection only targets agents that can carry the endpoint's connector, rendered in that agent's native form (native connector preferred; openai-compatible fallback). Model aggregators (OpenRouter, LiteLLM proxy, Portkey) as their own connector.
5. Define the model kind as a consumer of the consolidated ManagedConfigSpec from MO06 (config path, reader/writer/remover, format, refresh mode, supports flags) — do NOT add a third *ConfigSpec dataclass.
6. Fix the ownership mapping explicitly: owner_scope = provider id (matches MCP), managed_id = model-endpoints/<endpoint-id>; define collision behavior for provider-visible names.
7. Decide the relationship to default-model, model-aliases, runtime catalogs, and agent profiles (agents keep provider/model binding; endpoint projection is provider-owned).
8. Keep docs/reference/PROVIDER_MODEL_ENDPOINT_CAPABILITIES.md authoritative for the finalized contract + connector decisions.
