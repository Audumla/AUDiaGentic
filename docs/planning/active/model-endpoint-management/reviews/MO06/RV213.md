# ManagedConfigSpec extraction must handle non-identical MCP/LSP fields

## Notes

Revalidated MO06 against current descriptor dataclasses. MCP and LSP config specs are conceptually overlapping but not identical: MCP currently has `refresh_mode`, `reload_fn`, and `remote`, while LSP does not. The target abstraction must preserve those semantics rather than flattening them away.

## Findings

1. MO06 is still the correct prerequisite before adding model config. 2. The target `ManagedConfigSpec` should support optional fields or a small capability/options map so MCP-specific `remote` and reload behavior survive. 3. Loader migration must keep existing YAML keys (`mcp_config`, `language_servers_config`) backward-compatible while internally building the unified spec. 4. Registry extraction should be parameterized by filename/top-level key, with MCP registry output unchanged by tests. 5. No model endpoint code should land inside MO06; it is a behavior-preserving refactor only.

## Conclusion

Incorporated into the refreshed reference doc. MO06 remains valid but must treat the two current specs as overlapping shapes with feature-specific fields, not byte-for-byte identical dataclasses.
