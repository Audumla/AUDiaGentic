# Fix local-openai catalog schema validation

## Description

Isolated bug fix pulled out of MO02. local_openai/catalog.py emits status: "available" and context-window: None, but provider-model-catalog.schema.json requires status in {active,deprecated,experimental} and an integer context-window >= 1. Catalog refresh for this provider cannot persist valid output until fixed. Independently valuable and unblocks valid catalog persistence today, ahead of the larger model-endpoint work.

## Steps

1. Map upstream OpenAI-compatible /v1/models status values onto the schema enum (default active; treat missing as active).
2. Provide a context-window fallback (endpoint-declared, override, or a documented default >= 1) instead of None.
3. Ensure supports-structured-output stays boolean.
4. Add a catalog validation test that the emitted payload passes provider-model-catalog.schema.json.

3. Unit test: absent context-window uses a positive-integer fallback.
