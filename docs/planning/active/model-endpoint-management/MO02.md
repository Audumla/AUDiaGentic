# Implement managed model endpoint sync service

## Description

Add provider-owned model endpoint sync machinery mirroring MCP sync. This service reconciles desired model endpoint entries into provider-specific config formats while preserving unmanaged user entries and tracking ownership in runtime state.

## Steps

1. Add model endpoint dataclasses/helpers for provider-visible entries.
2. Add provider service APIs: `sync_managed_provider_models`, `sync_managed_provider_models_subset`, `list_provider_models_config`, and `reload_provider_models`.
3. Add runtime ownership registry `.audiagentic/runtime/providers/managed-model-endpoints.json`.
4. Use `FragmentStore` and `reconcile_fragments` for structured entries.
5. Add provider status fields for model config support, managed model count, config path, refresh mode, collisions, and action-needed reload text.
6. Fix `local-openai` catalog schema mismatch while touching model catalog behavior.
7. Expose management through providers MCP only after service tests are green.

## Validation

1. Unit tests for ownership preserve/update/remove/rename behavior.
2. Unit tests for collisions with unmanaged provider entries.
3. Unit tests for status output and reload-required/file-watch behavior.
4. Unit test proving local-openai catalog output validates.
5. Run focused provider unit tests: model catalog, provider config, status, MCP sync analogs.

## Effort & Risk

Complex. Biggest risk is duplicating MCP sync poorly. Keep service thin and reuse fragment reconciler. Do not use managed text blocks for JSON/TOML/YAML model entries.
