# Bind model-endpoint kind onto shared reconcile + capability recipes

## Description

Add provider-owned model endpoint sync by binding a new model kind onto the consolidated managed-config machinery from MO06 — NOT by cloning services/mcp.py into services/models.py. The reconcile engine (foundation/toolchains/fragments.py, payload is Any), the generalized ManagedFragmentRegistry, and the sync/reload core already exist after MO06; this item supplies the model-specific desired-entry builder, registers model management as a provider capability recipe (reusing ProviderCapabilityRecipe/Registry for status/dry_run/lifecycle/provenance/action_needed), and wires the reconcile trigger. Env-projection and extension-storage providers are handled by different vehicles (see steps), not the fragment reconciler.

## Steps

1. Add model endpoint dataclasses/helpers producing (name, payload) desired entries. Builder input is the MATERIALIZED-ENDPOINT list derived from `model-sources` (MO01): in this item only local-endpoint sources materialize (1:1); vendor-account/aggregator materialization (MO07) later feeds the same builder input — do not design the builder against raw endpoint declarations or it breaks when sources arrive. Managed ids per class per MO01 step 6.
2. Expose thin model APIs (sync_managed_provider_models, sync_managed_provider_models_subset, list_provider_models_config, reload_provider_models) as wrappers over the shared sync_managed_config / reload_provider_config from MO06 — no reimplementation of the reconcile loop.
3. Instantiate the generalized ManagedFragmentRegistry at .audiagentic/runtime/providers/managed-model-endpoints.json (a second instance, not a second module).
4. Register model-endpoint management as a provider capability recipe (ProviderRecipeKind for model config) so status/dry_run/lifecycle/provenance/action_needed are reused; bind NoAutomationRecipe for manual/blocked providers.
5. Handle env-projection providers (OpenHands/Aider) as a launch-env contribution capability recipe, NOT via reconcile_fragments.
6. Add a sibling _sync_provider_models call in reconcile.py::reconcile_provider and register model-sync action handlers in the existing dispatch-table style (lsp_projection _ACTION_HANDLERS pattern).
7. Add provider status fields (model-config-supported, managed-model-count, model-config-path, refresh mode, collisions, action-needed reload text).
8. Register the canonical MEP error-code family in src/audiagentic/config/components/providers/error-resolutions.yaml BEFORE first use (§8 — a code raised without YAML registration is a defect): VAL-MEP-001 invalid model-source/endpoint declaration; VAL-MEP-002 endpoint connector not supported by target provider; VAL-MEP-003 alias/default resolves to a disabled or unknown source; CON-MEP-001 collision with an unmanaged provider entry; CON-MEP-002 provider config read/write/parse failure during sync; CON-MEP-003 provider reload failed or manual reload required. Resolution text describes remediation, not the message. External-connectivity failures (unreachable/auth/rate-limit during catalog refresh) follow the classification guideline delivered by MO08.
9. Add the model_source_* management tool group to the providers MCP server, mirroring the lsp_manage pattern (lsp_add_language/lsp_remove_language/lsp_set_language_option/lsp_list_languages): model_source_list, model_source_add(source_id, config), model_source_update(source_id, updates), model_source_remove(source_id), model_source_set_enabled(source_id, enabled). Every mutation validates against model-sources.schema.json, writes .audiagentic/config/model-sources.yaml (same file humans may edit directly), and supports apply=True (reconcile after write) + dry_run. Tools mutate DESIRED STATE only — never provider config files (same invariant as recipes). Per-model control maps through the taxonomy: local-endpoint = source per model (set_enabled/remove); custom-entries = model-filter via model_source_update; key-injection = source-level all-or-nothing surfaced in status. Tool names are pinned in the reference doc Service shape section.
10. Pin neutral type: MaterializedModelEntry(source_id, model_id, visible_name, connector, endpoint, capabilities, limits, auth_ref) contains no provider-native container/key/casing. Descriptor-selected adapter renderers convert it to the payload accepted by ManagedConfigSpec.writer; services/models.py never imports adapter modules by name or branches on provider_id.
11. Mutation semantics: dry_run=true performs validation + computes desired/provider diffs but writes neither model-sources.yaml, ownership registry, nor provider config; apply=false atomically writes desired state only; apply=true writes desired state then reconciles. If reconcile fails, desired state remains committed and result reports applied=false/action_needed (no false rollback claim).
12. Reconcile runs on every provider state branch: enabled provider receives desired entries; disabled provider receives an empty desired set for model managed_ids so owned entries are pruned. Collision means no overwrite and ok=false; non-colliding entries may apply and exact partial outcome is returned.
13. Timeline identity: component=providers, resource-kind=provider-model-config, resource-id=<provider-id>, event model-config.{planned|updated|removed|collision|reload-required}; attributes contain counts/managed ids only, never payloads or auth refs.

## Effort & Risk

Complex. Primary risk is re-mirroring MCP sync instead of reusing the MO06 foundation core, forcing env-projection/extension-storage through the reconciler, or branching on connector/provider with if/elif (§2 violation). Keep the model service to desired-entry building + capability-recipe registration only. local-openai catalog fix moved to MO05.

## Standards

- arch-standards — §1 providers may consume foundation sync primitives but foundation names stay domain-neutral; §2 connector/provider dispatch must be registry/YAML driven with no if/elif on provider_id or connector; §8 use canonical VAL-MEP-*/CON-MEP-* errors and keep remediation in error-resolutions.yaml; §9 module logger and no secret logging; §10 no cloned reconcile loop or parallel model-sync API; §11 use shared lazy registry utility.
- component-creation — provider component owns downstream projection/status surfaces; providers MCP exposure waits until service tests pass.
- observability-standards — model sync mutates durable provider config, so emit redacted timeline events for create/update/remove/collision/reload outcomes.
