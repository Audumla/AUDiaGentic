# Consolidate managed-config descriptors, registry, and sync core

## Description

Behavior-preserving refactor that removes the existing duplication between McpConfigSpec and LanguageServersConfigSpec BEFORE the model-endpoint kind is added, so the model kind is born into the consolidated shape rather than added as a third clone. This is the reuse foundation for all subsequent MO work: one ManagedConfigSpec, one ManagedFragmentRegistry, one sync/reload core. No behavior change to MCP or LSP — guarded by their existing tests.

## Steps

1. Introduce a single ManagedConfigSpec (config_path, reader, writer, remover, refresh_mode, format, reload_fn, remote, kind label) and either fold McpConfigSpec/LanguageServersConfigSpec into it or make ProviderDescriptor hold managed_configs: dict[kind, ManagedConfigSpec].
2. Replace _build_mcp_config + _build_language_servers_config with one loader builder; keep YAML keys backward-compatible.
3. Generalize managed_mcp_registry.py into one ManagedFragmentRegistry parametrized by filename + top-level key; keep managed-mcp-servers.json as one instance.
4. Extract the shared reconcile/reload core of mcp.py::_sync_managed_entries into sync_managed_config / reload_provider_config; rewire MCP and LSP sync to call it.
5. No new feature surface — MCP and LSP behavior must be identical.

## Validation

1. Existing MCP sync unit tests pass unchanged (ownership/rename/collision/preserve-unmanaged).
2. Existing LSP projection tests pass unchanged.
3. Descriptor loader tests: mcp_config and language_servers_config still load via the consolidated builder.
4. Registry tests: one generalized registry round-trips the MCP ownership file identically.
5. Architecture-boundary tests still pass.

## Effort & Risk

Complex. Touches two working, test-covered subsystems and every provider YAML that declares these blocks. Risk is behavioral regression — mitigate by keeping it a pure refactor gated on the existing MCP/LSP suites, with no model-kind code in this item.
