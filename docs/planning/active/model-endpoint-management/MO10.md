# Reuse model catalog read surface and fix per-request model precedence

## Description

Reviewer prerequisite with two bounded fixes. The repository already exposes providers_api.list_provider_models and the ag-providers-mgmt MCP tool list_provider_models; enhance that existing surface instead of adding provider_models_available. Separately, gateway dispatch puts resolved profile model in packet_ctx['model-id'], but several real adapters prefer provider_cfg['default-model']. Add one provider-local selection helper and use it consistently in real adapters.

## Steps

1. Extend existing providers_api.list_provider_models(project_root, provider_id, refresh=False). Keep current response keys; add ok, reason, catalog_present, stale where available. Missing catalog returns models=[] and reason=no-catalog-found; descriptor without fetch_catalog_fn returns reason=no-catalog-support.
2. Keep MCP tool name list_provider_models; add optional refresh argument to its wrapper and descriptor text. refresh=true calls existing fetch_provider_catalog once, then reads the catalog. On failure return cached catalog when present plus ok=true, refresh_ok=false, redacted error_code/reason/action_needed; no cached catalog returns ok=false.
3. Add resolve_execution_model(packet_ctx, provider_cfg): packet_ctx model-id, then packet_ctx model-alias only if already resolved/allowed by caller contract, then provider default. Prefer omitting alias fallback if gateway guarantees model-id. Helper lives in providers adapter/base utility, not foundation.
4. Audit and update real adapters: opencode, codex, claude, cline, qwen, local_openai. Inspect Gemini separately because it delegates model semantics through prompt tags; record explicit no-change or fix. Stubs/unsupported adapters excluded.
5. Every command adapter uses selected model in argv and result metadata; local_openai request body uses selected model. No adapter independently reimplements precedence.
6. Add focused API/MCP compatibility and per-adapter argv/request tests.

## Validation

1. Existing list_provider_models callers/response fields remain compatible; no provider_models_available symbol/tool exists.
2. Missing/unsupported catalog reason shapes are distinct and deterministic.
3. refresh success fetches once and returns new catalog; refresh failure returns redacted cached result; no-cache failure returns ok=false.
4. Parameterized adapter test proves packet model overrides provider default for every real adapter; default remains fallback; neither means model flag omitted or canonical required-model error.
5. Gemini audit outcome is recorded/tested.
6. Existing provider/catalog/gateway tests green.

## Effort & Risk

Simple. Both changes are thin and test-covered; the only care point is not inventing a second catalog path — wrap the existing read/fetch functions only. No dependency on MO01/MO02/MO06/MO07.
