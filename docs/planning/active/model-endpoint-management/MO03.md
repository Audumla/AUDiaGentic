# Add first-wave local model provider adapters

## Description

Implement only the first structured-file slice: resolve OpenCode's conflicting config path/container and implement Pi + OpenCode model adapters on the MO06 shared core. Codex/OpenHands and Qwen/Goose move to separate items so one small agent owns one bounded migration.

## Steps

1. BLOCKING GATE (RV314): resolve the installed OpenCode file/container contract — .opencode/config.json vs .opencode/opencode.json and provider vs providers — with recorded evidence per the MO09 protocol. Evidence sources, in order: (a) inspect the installed tool's own config loading (opencode binary docs/`opencode --help`/config-schema output), (b) upstream docs matching the installed version, (c) empirical test — place a distinctive provider entry in each candidate file/container and observe which one `opencode models --verbose` reflects. Record tool version + evidence in docs/reference/model-source-evidence/opencode.md. If evidence cannot be gathered, the OpenCode half of this item CLOSES as blocked: bind NoAutomationRecipe with action_needed naming the exact unknown (file path + container key) and complete Pi independently — Pi delivery is never blocked by this gate.
2. Express the winning OpenCode path/container through its provider descriptor ManagedConfigSpec. Runtime harness consumes the same descriptor/contribution; it contains no second path/container constant and imports no provider component internals.
3. Migrate existing OpenCode MCP and LSP surfaces atomically to the winning file before adding model entries. Whole-repo grep old path/container strings; update fixtures and harness templates in same step.
4. Implement Pi model reader/writer/remover for home-scoped models.json. Preserve unmanaged provider blocks/models; use source-id block + model-id identity; dry-run exposes home path and requires explicit apply for writes outside project root.
5. Implement OpenCode model reader/writer/remover only after step 1 succeeds. Preserve unmanaged provider/model entries and share the file writer/merge primitive used by MCP/LSP so three independent writers cannot clobber each other.
6. Add provider descriptor declarations and golden/roundtrip/collision tests. Unresolved OpenCode remains blocked without preventing Pi completion.

## Validation

1. Pi roundtrip: unmanaged blocks/models preserved; two managed models update/remove independently.
2. Home-scoped Pi dry-run performs zero writes and reports target path; apply writes only after explicit request.
3. OpenCode evidence pins one path/container for installed version or status remains blocked with action_needed.
4. If enabled, OpenCode MCP/LSP/model writes share one file and sequential operations preserve all three sections plus unmanaged content.
5. Architecture test: runtime harness contains no provider path/container literals after migration and does not import providers internals.
6. Focused provider/harness tests green; whole-repo old-path grep empty when migration occurs.

## Effort & Risk

Complex. OpenCode path mismatch, OpenHands settings schema, and Goose model-provider config shape are prerequisites, not implementation details. Codex user-level config is sensitive (project config ignores provider keys). Do not force env-projection through the reconciler.
