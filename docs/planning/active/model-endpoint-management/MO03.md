# Add first-wave local model provider adapters

## Description

Implement managed model endpoint adapters for the most important local/custom endpoint consumers: Pi, OpenCode, OpenHands, Goose, Codex, and Qwen. Each adapter owns its provider config format and exposes reader/writer/remover functions to the central model sync service.

## Steps

1. Validate installed/current config shape for OpenCode before writing: `opencode.json` vs `.opencode/config.json`, `provider` vs `providers`.
2. Add Pi adapter for `models.json` providers map and models array.
3. Add OpenCode adapter for custom provider models and default model selection.
4. Add OpenHands adapter for CLI/env projection first, then settings file only after storage is validated.
5. Add Goose adapter for custom provider JSON files.
6. Add Codex adapter for user-scope `config.toml` model providers with explicit consent/action-needed behavior.
7. Add Qwen adapter for `settings.json` `modelProviders`.
8. Wire descriptor `model_config` metadata in each provider YAML.
9. Add golden tests for each adapter preserving unmanaged entries.

## Validation

1. Golden tests for each provider config writer.
2. Roundtrip tests: read existing unmanaged config, apply two managed local models, update one, remove one, preserve unmanaged.
3. Reload/action-needed tests per provider refresh mode.
4. Integration-ish tests using temp project roots only, no real provider launch needed.
5. Run provider adapter test subset.

## Effort & Risk

Complex. Codex user-level config is sensitive because docs say project config ignores provider keys. OpenCode config file/key shape mismatch must be resolved before writing. OpenHands persistent settings may need discovery beyond current repo.
