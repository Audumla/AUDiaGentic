# Add first-wave local model provider adapters

## Description

Implement first-wave model endpoint adapters, annotated by config mechanism because the mechanism determines the reuse vehicle. Structured-file providers (Pi, OpenCode, Goose, Codex, Qwen) contribute a reader/writer/remover trio to the consolidated ManagedConfigSpec and reconcile via fragments. OpenHands is env-projection (a launch-env capability recipe, NOT the fragment reconciler). local-openai is the AG-side catalog bridge (MO05 fixes its schema). Per-provider adapter spec fields (config path, container keys, active-model pointer, auth, refresh, sources) with FILL placeholders are in docs/reference/PROVIDER_MODEL_ENDPOINT_CAPABILITIES.md.

## Steps

1. VALIDATION GATE (blocker, not a step): resolve OpenCode config target — harness installer writes .opencode/config.json with top-level providers, while descriptor/MCP/LSP use .opencode/opencode.json with provider. Reconcile before writing any OpenCode model config.
2. VALIDATION GATE (blocker): confirm OpenHands .openhands/settings.json schema before any file write; until then use env-projection only.
3. Pi (structured-file): reconcile providers.<id>.models[] by model id, preserve unmanaged models.
4. OpenCode (structured-file): custom provider.<id>.models map + top-level model default selection.
5. OpenHands (env-projection): launch-env contribution recipe (LLM_BASE_URL/LLM_MODEL/LLM_API_KEY, openai/<model-id> prefix); settings-file writer only after gate 2.
6. Goose (structured-file): custom provider JSON files (paths/keys are FILL in the matrix — confirm before writing).
7. Codex (structured-file, USER-GLOBAL): ~/.codex/config.toml model_providers + active model/model_provider, consent-gated with explicit action-needed.
8. Qwen (structured-file): settings.json modelProviders.
9. Wire each provider's model kind into its YAML via the consolidated ManagedConfigSpec (MO06).
10. Golden tests per adapter preserving unmanaged entries.

[RUNTIME:harness] src/audiagentic/runtime/harness/pi/templates/home/agent/models.json, pi/install/config.py — reconcile with managed reconcile path
[TEST] tests/unit/providers/ — golden + roundtrip (apply/update/remove, preserve unmanaged) per adapter

## Validation

1. Golden tests for each provider config writer.
2. Roundtrip tests: read existing unmanaged config, apply two managed local models, update one, remove one, preserve unmanaged.
3. Reload/action-needed tests per provider refresh mode.
4. Integration-ish tests using temp project roots only, no real provider launch needed.
5. Run provider adapter test subset.

## Effort & Risk

Complex. OpenCode path mismatch and OpenHands settings schema are prerequisites, not steps — treat as validate-first gates. Codex user-level config is sensitive (project config ignores provider keys). Do not force env-projection through the reconciler.
