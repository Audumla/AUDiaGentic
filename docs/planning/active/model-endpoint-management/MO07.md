# Enable remote-account model sources (key injection + filtered custom entries)

## Description

Implement remote-account projection after a separate source-catalog item supplies normalized discovered models. This item owns projection selection, native key injection, custom-entry materialization, disable/prune, alias validation, and status; it does not implement network fetch/cache logic.

## Steps

1. Consume normalized SourceCatalogResult from the source-catalog prerequisite; no network calls in model_sources.py.
2. Select projection from descriptor data only: vendor-key-injection exact vendor key first, else supported connector custom-entries, else none. Return a typed ProjectionDecision; no provider/vendor/source-class branches.
3. Resolve api-key-ref EXCLUSIVELY through MO15's secret-ref resolver + launch-env contribution seam (RV315 resolved: the prerequisite item now exists — MO15 delivers resolve_secret_ref, ProviderRecipeKind.LAUNCH_ENV, and the launch-time injection path). Do not add local env parsing. Resolved key values exist only inside writer/launch invocation, per MO15's redaction guarantee.
4. Native env injection contributes {env-name: secret-ref} via the MO15 launch-env seam (deferred resolution at spawn); native config injection resolves via MO15 inside the writer call and emits the connectivity managed entry. Custom entries filter normalized catalog and feed MO02 MaterializedModelEntry.
5. Disable is transactional by ownership kind: prune config/custom entries and remove launch-env contribution; failures report exact residual managed ids/action_needed and never claim disabled projection complete.
6. Alias/default validation runs after materialization and before provider config write. VAL-MEP-003 includes source/model ids only.
7. Status consumes projection decision + SourceCatalogResult: mode, enabled, count, freshness/staleness, last error class, residual ownership, action_needed. No secret refs/values.
9. RV353 EVIDENCE GATE: do not consume the current provider×vendor matrix until reopened MO09 completes correction. Bind declarations only from fact-specific terminal anchors. Pi native-vendor injection and custom-entry projection are separate modes; Qwen auth types/modelProviders replace the false OpenAI-only assumption; Codex config parsing, OpenCode credential listing, and OpenHands env recognition are not execution proof. Any affected pair still blocked/unverified remains unprojected.
