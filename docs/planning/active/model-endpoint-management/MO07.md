# Enable remote-account model sources (key injection + filtered custom entries)

## Description

Implement remote-account projection after a separate source-catalog item supplies normalized discovered models. This item owns projection selection, native key injection, custom-entry materialization, disable/prune, alias validation, and status; it does not implement network fetch/cache logic.

## Steps

1. Consume normalized SourceCatalogResult from source-catalog prerequisite; no network calls in model_sources.py.
2. Select projection from descriptor data: verified vendor key path, supported connector custom entries, or none. Return only caller-consumed model decision data; no provider/vendor branches.
3. Resolve api-key-ref only inside the provider-owned writer or MA17 execution launch path using MO15 secret resolution. Do not expose ProviderRecipeKind or create a public launch-env operation family.
4. Native launch injection contributes secret references to explicit execution composition; native config injection and custom entries use the MA16/MO02 model-projection family.
5. Disable prunes source-owned projection and removes execution launch contribution; partial failure reports residual owned ids/action_needed.
6. Validate aliases/defaults after materialization and before provider write.
7. Status combines projection decision and source catalog without secrets.
8. Bind declarations only from corrected fact-specific evidence; blocked/unverified pairs remain unregistered and unprojected.

1. Decision tests cover verified projection paths and none without name branches. 2. Secret values appear only inside writer/execution launch. 3. Disable reports residual ownership and prunes only source scope. 4. Custom entries use MO02; no second reconcile path. 5. Validation precedes mutation. 6. No network or requester imports in model_sources.py. 7. Every automatic pair traces to corrected evidence and explicit registration. 8. No public ProviderRecipeKind or compatibility route.
