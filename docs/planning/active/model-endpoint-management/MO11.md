# Provider interrogation MCP tools: deep describe_provider read surface

## Description

Add one read-only describe_provider(provider_id) composition tool on ag-providers-mgmt. It joins existing provider-owned reads only: descriptor summary, provider status/probe, execution support, model catalog, and managed config ownership. It does not import agents, read agent profiles, perform new discovery, or duplicate status/catalog logic.

## Steps

1. Add a stable providers/services/execution.describe_execution_support(provider_id) helper that reports mode adapter|descriptor|stub|unsupported|none from _adapter_module_path + descriptor execution data without importing/running adapter modules. Do not call private helpers from providers_api directly.
2. Add providers_api.describe_provider(project_root, provider_id) composing list_provider_descriptors/get descriptor, build_provider_status(include_probes=True), MO10 list_provider_models(refresh=False), execution helper, and read-only managed ownership registries. No duplicated probes/catalog parsing/model resolution.
3. Config surfaces serialize as {kind, configured, path_scope, resolved_path, format, refresh_mode, capabilities}; resolve callable paths through MO06 helper. Redact home prefix to ~ in operator output where appropriate; never serialize callable reprs or secret refs.
4. Managed surface section reports ownership registry names/counts only. Missing/corrupt registries use canonical error/reason shape from MO06; do not silently claim empty on corruption.
5. Omit agent profile joins: agents owns profiles and providers→agents import would leak ownership. Return related_tools:["agent_list_profiles"] or documented pointer only.
6. Expose existing MCP server tool describe_provider and declaration text.
7. Tests: full provider fixture, minimal provider, unknown provider, corrupt registry, redaction canary, and tracked-file read-only invariant.

## Validation

1. describe_provider(opencode) composes exact existing status/catalog/descriptor values; no duplicate fetch/probe occurs.
2. Execution modes tested for real adapter, descriptor runner, stub, unsupported, none without importing/running adapters.
3. Callable/relative/absolute config paths serialize deterministically through MO06 resolver; no callable repr.
4. Missing registry is empty/reason; corrupt registry surfaces canonical error.
5. Output contains no secret refs/values/key-bearing URLs/home credential paths.
6. No providers import of audiagentic.components.agents; response points to agent_list_profiles instead.
7. Read-only test snapshots only known provider project/runtime config paths and proves mtimes/content unchanged.
8. Existing providers MCP tests green.
