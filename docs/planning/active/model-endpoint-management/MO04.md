# Extend model management to remaining compatible providers

## Description

Extend model management to remaining providers, expressing the four-state support taxonomy (auto/manual/unsupported/blocked) through existing primitives rather than ad hoc status. Manual/unsupported/blocked providers bind NoAutomationRecipe (foundation/toolchains/recipe_patterns.py) — its guidance-only lifecycle (probe ABSENT + action_needed) IS the manual-status implementation, no new code. Support status and priority are orthogonal (separate columns in the capability matrix). Covers Continue, Cline, Roo, Aider, Plandex, and native/account-derived providers.

## Steps

1. Continue (structured-file, per RV241 + RV322): ship the INCUMBENT `.continue/config.json` (JSON) `models[]` writer — it is the file this repo already manages for MCP (same reader/writer conventions). DO NOT block on MO09: JSON-first is the default even if the Continue matrix cell is blocked/tool-not-installed. Only if MO09 later verifies the installed version REQUIRES the newer YAML config, migrate MCP + models to it atomically per §10 in a follow-up change. Never manage the two kinds in different files. Materialization snippet in reference doc.
2. Cline (extension-storage): bind NoAutomationRecipe (supported-manual) until VS Code extension settings/profile storage is validated — storage format is FILL in the matrix.
3. Roo (extension-storage): fix misleading descriptor access_mode: env (forces auth-ref; does not model extension-managed profiles) BEFORE any adapter; NoAutomationRecipe until storage validated.
4. Aider (env-projection): bind a ProviderRecipeKind.LAUNCH_ENV contribution recipe via the MO15 seam if/when the execution adapter becomes real (currently `execution: stub` — the contribution registers inert with action_needed per the MO15 rule; the pair stays manual/blocked in status until the bridge exists).
5. Plandex (structured-file, adapter stub): custom provider/model writer after execution/config path is wired; config path/format are FILL.
6. Gemini/Claude/Copilot/Antigravity: mark native/account-derived/unsupported via NoAutomationRecipe unless a validated custom-endpoint path exists.
7. Update provider READMEs with adapter-local detail ONLY: config surface specifics, verification notes, manual-mode instructions, and whether manual mode is terminal or a path to later auto-support exists — plus a link to docs/reference/PROVIDER_MODEL_ENDPOINT_CAPABILITIES.md. READMEs must NOT duplicate the capability matrix (support status/priority/connector tables); the reference doc is the single authoritative running record and must be updated in the same change as any support-status or connector-fact change.
8. Host adapter rule: services/host_adapter.py already exists and is config-loaded from config/components/providers/hosts.yaml. Do not create another adapter. Add extension-storage methods/fields only after a verified, host-generic storage contract exists; until then Cline/Roo remain NoAutomationRecipe.
9. Bound implementation: Continue structured writer is the only automatic file adapter in this item. Aider/Plandex stay blocked until their existing execution stubs become real; this item records status/guidance, not speculative writers.
