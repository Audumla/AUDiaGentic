# Cross-harness model availability overview: one read-only introspection surface

## Description

Sponsor direction 2026-07-18: 'introspect the providers and then the models exposed'. Compose the reads that already exist into one coherent overview instead of forcing tool-by-tool assembly: enabled providers/harnesses, their execution + model-projection capability state, configured model sources (local endpoints and vendors) with enablement, cached catalog contents (with freshness), and which models are currently materialized into which harness configs. Strictly read-only, derived entirely from existing stores — no new persistence, no network (cached catalog data only), no scheduling logic.

## Steps

1. Inventory the existing reads to compose: list_providers, describe_provider, list_provider_models, model_source_list, MO17's catalog read, projection ownership registry contents, and MA19 capability facts (including blocked-evidence facts so the overview honestly shows WHY a harness has no models).
2. Define one typed overview result (frozen dataclass + schema per the locked typed-contract rule): sources → catalog summary (count, freshness, filter) → materialized-to (provider, managed-id count) → provider execution/enablement state. Include blocked reasons from evidence facts verbatim.
3. Implement as one providers_api read composing existing service reads; expose one providers-MCP tool. AR25: the MCP tool translates and serializes only.
4. Do NOT include usage/limits (PT01 owns; leave a typed placeholder field only if PT01's contract already names it — otherwise nothing), and do NOT read live networks.
5. Tests: overview against fixtures with a vendor source (fresh/stale/missing cache), a local endpoint, a blocked provider, and a disabled source.

## Files

## Validation

1. One call answers: what vendors/sources exist, what models they expose, where those models are materialized, and which harnesses can execute them (or why not). 2. No network, no mutation, no new store. 3. Blocked harnesses surface their recorded evidence reason. 4. AR25 boundary tests pass.
