# Reconcile expired BigCherry sessions and preserve provider evidence

## Description

Investigate and repair the lifecycle gap where provider-backed BigCherry requests remain running/orphaned after their session expires or the gateway loses its live owner. Preserve visible provider failures and partial output as diagnostics, but only mark completed when request-owned terminal evidence is proven.

## Steps

- Correlate durable request, session, provider target, and CDP evidence for stale BigCherry records.
- Have GPT review the proposed lifecycle and recovery design before implementation.
- Terminalize running requests whose owning provider session is expired/non-live with explicit durable evidence and no false success.
- Ensure stale active session records are reconciled and cannot block later queued work.
- Add focused regression coverage for session expiry, orphaned request cleanup, and fail-closed capture.
- Restart the gateway and run a live BigCherry/CDP smoke test, then obtain a final GPT review.

## Detailed Solution & Technical Design

Treat SessionRuntime/session records as lifecycle authority. When a provider session is terminal and has no live owner, reconcile linked non-terminal requests through the existing transition authority, preserving cancel/failure reason, provider URL/target, activity sequence, and any visible partial response. Do not use synthetic activity as proof of provider progress and do not capture or complete from an uncorrelated tab. Make reconciliation idempotent and observable.

High: touches lifecycle reconciliation and shared gateway state; must avoid false terminalization of genuinely live provider work.

## Standards

- Fail closed on request/session/provider mismatch.
- SessionRuntime and durable transitions are terminal authority.
- Never auto-resubmit ambiguous provider prompts.

## Acceptance Criteria

- No request remains running solely because its owning provider session expired or became non-live.
- A visible partial response is retained as failure evidence, never promoted to success without request-owned terminal proof.
- Synthetic activity cannot prevent outer inactivity/session cleanup.
- Recovery is idempotent, bounded, and does not reopen an uncorrelated ChatGPT target.
- Live test evidence includes request lifecycle and matching CDP target state.
- All automatic terminalization records the exact session id, close reason, request state, owner/revision fence, and capture disposition.
