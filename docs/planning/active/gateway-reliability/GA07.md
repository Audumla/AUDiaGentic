# Bounded reconciliation before accepting terminal request failure

## Description

Before exposing a terminal failed request as final, perform a bounded provider/session recheck that can recover visible completion or prove the request is not recoverable without replaying ambiguous work.

## Steps

- Define failure classifications and reconciliation budget.
- Recheck durable session binding and provider/CDP evidence.
- Recover visible response or safe pre-submit retry.
- Expose pending reconciliation without blocking ordinary status reads.
- Add unit, integration, and live validation coverage.

## Detailed Solution & Technical Design

Run a bounded passive provider reconciliation in the dispatch failure boundary before persisting terminal failure. Reuse complete_execution_from_provider for strict two-snapshot prompt/assistant identity and completion-witness validation. If it captures a correlated completed response, return completed; otherwise preserve the original failure path and record a reconciliation timeline event. Never send a prompt from reconciliation and never use synthetic activity as evidence. Status polling remains read-only and non-blocking.
