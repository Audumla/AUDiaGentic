# Reclaim idle owned GPT tabs and prevent unowned-tab accumulation

## Description

Confirm timeout-based cleanup for gateway-owned conversation tabs and determine why project/list navigation tabs are accumulating outside the durable ownership ledger. Preserve arbitrary user-owned tabs and unresolved provider turns.

## Steps

- Trace runtime ownership and exact reaper skip/close decisions for a terminal expired session whose leased tab remains open beyond the 2h threshold.
- Add request/session/project identity and reaper-decision observability without recording raw prompt/DOM data.
- Correct stale in-memory page ownership or terminal-session protection so an idle, terminal leased tab can be closed after final CDP identity and activity revalidation.
- Inventory gateway-created project/list navigation tabs; close only those with explicit durable ownership and a safe lifecycle.
- Add deterministic tests for timeout, live/pending protection, expired sessions, CDP target replacement, and unowned user tabs.
- Restart only with no active requests and validate a real eligible tab is reclaimed.

## Detailed Solution & Technical Design

Use the durable lease target ID and canonical conversation identity as the only authority to close a physical ChatGPT conversation. For an owned target past its idle deadline, determine why the runtime protects/skips it by checking live turn state and page ownership; do not assume an in-memory owner is stale. Preserve live/pending/unresolved turns and perform final CDP target and activity revalidation before closing. Do not sweep arbitrary unleased pages, including manually opened project routes. For gateway-created navigation tabs, introduce explicit ownership/cleanup only where the creation path can durably identify the exact target. Add redacted per-decision trace events (protected reason, age threshold result, identity check, close outcome) and test each branch.
