# Recover active requests across remote browser CDP outages and new target generations

## Description

User requirement: browser may close and restart independently of gateway. Detect CDP loss, retain active requests/session FIFO and durable submitted-turn identity, wait for configured endpoint to return, then reattach matching conversations or reopen exact saved URLs without resubmitting or foreground tab cycling. Existing socket generation reconnect and active-chat reconcile exist; runtime recover currently performs one ensure_available, whose remote-endpoint-down path fails immediately. Treat a connection attempt deadline as an attempt bound, not provider completion/failure.

## Steps

- Define one shared endpoint-recovery coordinator for CdpClient/PythonCdpBridge/PersistentChat and gateway queue integration; do not add competing retry loops.\n- On endpoint loss, invalidate bridge/session handles and physical target/window ownership generation, publish truthful recovering/offline state, preserve request/turn/binding/checkpoints, and block new side effects and queued followers.\n- Retry endpoint discovery with bounded backoff until demand ends, cancel/shutdown or the existing outer budget expires; never launch an unconfigured local browser.\n- On return, reconnect to the new websocket generation, enumerate targets, prefer restored tabs, or create exactly one background tab for the saved URL.\n- Reconcile completed/generating/ambiguous requests using request-owned prompt/assistant/terminal evidence; no ambiguous send replay.\n- Coordinate idle reattachment and physical lease ownership with GA15; keep GA07/GA13/GA14/GA19/GA20/GA21 as dependency boundaries.

## Detailed Solution & Technical Design

Audit existing recover/ensure_available and worker recovery paths first; extend one shared runtime recovery coordinator per endpoint rather than add competing socket/provider/queue retry loops. On connection loss invalidate bridge/session handles and physical target/window ownership generation, publish truthful recovering/browser-offline status, preserve request/turn/bindings/checkpoints, prevent new side effects and queued follower dispatch, and retry endpoint discovery with bounded backoff until demand ends, explicit cancel/shutdown or existing configured outer recovery/inactivity/request budget expires. Remote endpoint must not silently launch a local browser. On return establish fresh CDP connection and generation, enumerate new targets, match canonical conversation/project identity, prefer restored tabs; if absent create exactly one background tab for saved conversation and update physical binding. Reconcile each active request against its own prompt/assistant/turn evidence; capture completed outputs or resume observation while generating. Send-intent ambiguity must never trigger automatic replay. Prepared/proven-unsent requests may proceed only under existing owner/CAS fencing. Idle sessions reattach lazily rather than reopening every historical tab. Missing durable URL and target gone is explicit reconcile-required, not fresh-chat replay. Observe endpoint downtime and retry/backoff/last success/target remap as redacted bounded events; synthetic client heartbeat must not count as genuine provider progress or reset internal inactivity. Existing timer defaults remain unchanged and should be documented/tested.
