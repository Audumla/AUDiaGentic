# Shared startup-lock timeout releases another thread's lock and masks timeout errors

## Notes



## Findings

Current StartupLock.__enter__ calls _release_thread_lock after acquire(timeout) returns false. That helper unconditionally calls lock.release(), releasing the actual holder's in-process mutex. TO-PROC-002 is emitted dynamically by _process_error but has no error resolution registration; persisted BigCherry failures show the resulting ValueError. Add a timed-contender concurrency regression, separate reference release from acquired-lock release, guarantee reference release if filesystem unlock raises, and register process lock timeout in foundation.

## Conclusion

Implement and validate the shared primitive before further gateway live recovery.
