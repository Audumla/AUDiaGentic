# Central request lifecycle state: stale requests, phantom active-work entries, liveness, error-banner completion

## Description

Gateway requests are tracked by a central active-work index whose entries carry only the request id and the caller's absolute worktree path; the request record itself lives inside that worktree. When a worktree is deleted (or is on another machine) the entry is orphaned, doctor counts it as an active request, and nothing ends it. Separately, requests whose provider turn has finished stay running because an expired activity lease only records a diagnostic, status activity_at ignores the owner heartbeat, and an error-banner failure with a complete answer ends failed with no retrievable response. Observed 2026-11-17/18: 33-35 "running" requests of which 58 of 67 index entries pointed at removed worktrees and 64 had no record; project-capacity 2 leaves a bigcherry project effectively serial; 22 idle GPT tabs accumulated (sweep stalled; fixed for the hang in PR 474).

Design constraint: the lifecycle store and its rules are provider- and harness-neutral. gpt-auto, Claude and other harness specifics stay behind the existing provider adapter contract; core code sees only neutral signals (owner heartbeat time, completion witness, response text available).

## Steps

- Central store: the gateway service owns request lifecycle state (id, project identity, state, owner heartbeat, response artifact) in its own state directory, keyed by request id. The worktree path becomes a recorded attribute used to locate the working tree, never the key or the only copy of lifecycle state. Migrate existing records; no dual-write shim.
- Phantom cleanup: an index entry whose record or project root is gone is closed and dropped (with a log line), and is not counted by doctor or by capacity.
- Liveness: status exposes the owner heartbeat time as its own field; activity_at keeps meaning provider activity.
- Expired-lease completion: a running request with an expired lease and a reconcile-required disposition runs the existing reconcile (same prompt proven, quiet assistant turn, completion witness); on proof it completes and frees its slot, otherwise nothing changes.
- Error banner: an EXT-GPTAUTO-003 request-error-alert on a non-generating page with a complete answer stores that answer as the response artifact and completes the request; agent_task_response returns it.
- Stale slot release: leases and capacity for terminal or vanished requests are released automatically.
- Tab sweep: per-pass log summary and closing of tabs whose session has ended (timeouts already shipped in PR 474).
- Config: review project-capacity (currently 2 for gpt-auto); a config decision for the owner.

## Detailed Solution & Technical Design

One boxed PR per step, each with its own test. The central store is a gateway-owned neutral store (see CC43 for the shared resource-record store); it must not import provider or harness modules. Remote shared-gateway mode (audiagentic gateway connect) already runs execution on the server; this makes request state independent of the client's filesystem. Related: GA09 (routing by owning checkout), GA27 (orphaned requests), GA07, GP51, GP28, AS136, GA15.

## Validation

Per-step unit tests: phantom entry dropped and not counted; status exposes owner heartbeat; expired-lease running request completes only on reconcile proof; error-banner answer is retrievable and completes the request; hung tab does not stop the sweep. Live check after a gateway restart: doctor active count equals the number of real non-terminal requests.

## Effort & Risk

Large. The central-store migration is the risk: records must move without losing in-flight requests; do it as its own step with a drain first. Core stays neutral: reviewed for no provider or harness imports.

## Standards

Follow ARCHITECTURE_STANDARDS.md. Foundation and gateway core stay domain-neutral; provider specifics only through adapter contracts; error codes registered with resolutions; record substantive changes in the release ledger.

## Acceptance Criteria

- No active-work entry or capacity slot survives for a request whose record or worktree is gone.
- Doctor's active-request count matches real non-terminal requests.
- Status exposes owner liveness separately from provider activity.
- A finished lane with an expired lease completes or stays visibly unresolved; it never holds a slot indefinitely.
- An error banner with a complete answer completes the request and the answer is returned by agent_task_response.
- Request lifecycle state does not depend on a caller's filesystem path, and core code imports no provider or harness module.
- Idle owned tabs are closed and each sweep pass is logged.
