# Consolidate provider automation vocabulary and validation without widening family contracts

## Description

Consolidate genuinely shared provider vocabulary ownership and validation while preserving the distinct public mode sets of provider automation families. This item owns only the provider slice of CC50's vocabulary policy.

## Steps

- Add shared narrow Literal aliases for ProviderAutomationMode (plan/apply/prune/status), ProviderReconcileMode (apply/prune/status), and ProviderApplyStatusMode (apply/status)
- Keep family-facing aliases mapped to the appropriate narrow shared alias; type GeneratedSurfaceMode as ProviderAutomationMode
- Use _families.yaml as runtime authority for supported modes and replace duplicated handler mode sets with catalogue-backed validation
- Consolidate ProviderIsolationTier across provider_execution, ProviderDescriptor, and agents execution_context through providers_api; retain separate McpLaunchIsolationTier
- Confirm and remove the stale descriptors.base CapabilityAuthority alias; retain the catalogue-owned provisioned/operational/evidence-only vocabulary
- Define ObserverInstallationTiming for session-open/first-turn/lazy, distinct from foundation LifecycleInstallation mechanism values
- Add string-compatible validation for CLI lifecycle and self-provided-LSP result states, and type managed-MCP status reasons while preserving their serialized values
- Provider streaming: inventory actual control values; keep configuration/wire fields string-compatible, add internal policy enums only where ingress parsing is implemented, and correct invalid-event and event-write-policy validation
- Provider capability catalogue: retain _capabilities.yaml as mechanism-schema authority; remove duplicated Python validation/dispatch drift rather than create a partial hand-authored enum
- Model source catalog: retain model-source JSON Schema as authority for source-class and model-discovery, including none; centralize source validation and preserve serialized values
- Export only necessary provider public types through providers_api, update callers, and run focused provider, architecture-boundary, serialization, and type-checking tests

## Detailed Solution & Technical Design

Provider representation decisions:

- Mode sets remain plain-string Literal aliases because callers and configuration pass strings. Three shared aliases remove value duplication without widening family contracts.
- The family catalogue is the runtime source of truth for supported modes; handler-local sets are derived or replaced.
- ProviderIsolationTier is the one provider-wide execution concept and is exposed through the approved providers_api boundary. McpLaunchIsolationTier is separate.
- ObserverInstallationTiming describes observer activation timing and is distinct from foundation LifecycleInstallation, which describes installation mechanism.
- CLI/self-LSP states and managed-MCP reason fields stay wire-compatible strings with narrow validation unless every ingress path normalizes them to enum instances.
- Streaming policy values require a corrected inventory first: invalid-event policy includes quarantine; event-write behavior currently distinguishes locked append from an unlocked fallback, not locked trim. Represent configuration as Literals/validation unless an internal parsed policy object is introduced.
- Capability mechanism schemas come from _capabilities.yaml and include real and conceptual forms. Model source class/discovery values come from the model-source schema; discovery includes none. Derive validation from these sources rather than duplicating them in a partial enum.
