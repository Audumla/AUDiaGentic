# Consolidate provider automation vocabulary and validation without widening family contracts

## Description

Consolidate genuinely shared provider vocabulary ownership and validation while preserving the distinct public mode sets of provider automation families. This item owns only the provider slice of CC50's vocabulary policy.

## Steps

- Add shared narrow aliases in providers/contracts for ProviderAutomationMode (plan/apply/prune/status), ProviderReconcileMode (apply/prune/status), and ProviderApplyStatusMode (apply/status)
- Keep family-facing aliases (CliLifecycleMode, ManagedMcpMode, etc.) mapped to the appropriate narrow shared alias; type GeneratedSurfaceMode as ProviderAutomationMode
- Use the provider family catalogue (_families.yaml) as runtime authority for supported modes; replace duplicated handler _SUPPORTED_MODES checks with shared catalogue-backed validation
- Consolidate ProviderIsolationTier across provider_execution, ProviderDescriptor, and agents execution_context through the providers public API; keep McpLaunchIsolationTier separate
- Confirm descriptors.base CapabilityAuthority is unused and remove it; retain the capability catalogue's distinct provisioned/operational/evidence-only authority vocabulary at its owner
- Define ObserverInstallationTiming for session-open/first-turn/lazy; do not collide with foundation LifecycleInstallation, which represents observation mechanism
- Add narrow validation for CliLifecycleState and SelfProvidedLspState while keeping mapping/wire fields string-compatible
- Type get_managed_entry_status.reason as ManagedMcpEntryStatusReason while preserving its current serialized values
- Export only necessary provider public types through providers_api and update all callers
- Run focused provider, architecture-boundary, serialization, and type-checking tests

## Detailed Solution & Technical Design

Provider representation decisions:

- Mode sets remain plain-string Literal aliases because callers and configuration pass strings. Three shared aliases remove value duplication without widening family contracts.
- The family catalogue is the runtime source of truth for each family’s supported modes; handler-local frozensets are derived or replaced.
- ProviderIsolationTier is the one provider-wide execution concept and must be defined once, then used by provider execution, provider descriptors, and agents through the approved providers_api boundary.
- McpLaunchIsolationTier is a different capability and remains distinct.
- ObserverInstallationTiming is distinct from foundation LifecycleInstallation: timing versus installation mechanism.
- Result/reason fields remain compatible plain strings unless an explicit parser normalizes them into enum instances at every ingress boundary.

2. **McpEntryStatusReason → EntryStatus** — shorter, same meaning; "MCP" and "Reason" are redundant (lives in mcp.py).

## Architecture Assessment Against Architecture Standards Md

### Cross-Component Duplication Issue
**IsolationTier** is defined in agents.contracts.execution_context with the same values as providers.contracts.provider_execution.ProviderIsolationTier. Per §1, product components may depend on foundation and approved platform public APIs — agents should import from providers_api, not define its own copy.

### Consolidation Opportunity (Same Component, Same Intent)
The 7 *Mode Literals share the same 4-value vocabulary with identical semantics within the providers component. Per §3 ("Types are unified only when they share ownership, lifecycle, validation, and semantics"), these ARE the same concept — provider automation operation mode — used across multiple sub-contracts of the same component.

### What NOT to Consolidate
- CliLifecycleResult.state values ({"installed", "uninstalled", "skipped", "failed"}) are NOT the same as StepResult.status ("ok", "failed", "skipped", "planned"). Same word, different lifecycle — keep separate.
- MCP entry status reasons ('no mcp_config', 'stale', etc.) are specific to the managed-MCP status check — not shared with any other contract.

## Proposed Design

### New StrEnum: ProviderAutomationMode (providers.contracts.shared)
**Location**: `providers/contracts/shared.py` (new module for shared provider automation types)
**Values**: PLAN, APPLY, PRUNE, STATUS

Each family contract imports from this instead of defining its own Literal. Families that support a subset (e.g., SelfProvidedLspMode = {"apply", "status"}) validate against the enum at handler time rather than having a separate type.

**Why consolidation is valid here**: Same component, same semantic meaning, same lifecycle (mode → dispatch → result). The 7 Literals are not independent consumers — they're sub-contracts of the providers component sharing one vocabulary.

### New StrEnum: CliLifecycleState (providers.contracts.cli_lifecycle)
**Values**: INSTALLED, UNINSTALLED, SKIPPED, FAILED
Replace the hardcoded frozenset in CliLifecycleResult.__post_init__ with enum membership check.

### New StrEnum: SelfProvidedLspState (providers.contracts.self_provided_lsp)
**Values**: PROVISIONED, NEEDS_ACTION, UNKNOWN
Add validation to SelfProvidedLspResult.__post_init__.

### New StrEnum: McpEntryStatusReason (providers.services.mcp.mcp — internal)
**Values**: NO_MCP_CONFIG, READ_FAILED, ABSENT, STALE, MATCH
Used in get_managed_entry_status(). Internal to the mcp service layer.

### Convert Existing Literals to StrEnum (providers.contracts)
- ProviderIsolationTier → StrEnum: FULL_ISOLATION, PARTIAL_ISOLATION, NO_ISOLATION
- McpLaunchIsolationTier → StrEnum: EXACT, ADDITIVE, UNSUPPORTED
- CapabilityAuthority → StrEnum: AUTOMATION, OPERATIONAL, EVIDENCE_ONLY

### Fix Cross-Component Duplication (agents.contracts.execution_context)
Delete the agents-side IsolationTier Literal. Import ProviderIsolationTier from the approved providers_api.

### Type GeneratedSurfaceMode properly
GeneratedSurfaceMode = str has zero type safety. Convert to Literal or import ProviderAutomationMode.

## Migration Strategy

1. Create ProviderAutomationMode in providers/contracts/shared.py
2. Convert ProviderIsolationTier, McpLaunchIsolationTier, CapabilityAuthority to StrEnum (same modules)
3. Fix agents-side IsolationTier duplication
4. Replace each *Mode Literal with ProviderAutomationMode import
5. Add CliLifecycleState and SelfProvidedLspState enums with validation
6. Add McpEntryStatusReason for internal mcp service use
7. Remove _SUPPORTED_MODES frozensets (derive from enum instead)
8. Type GeneratedSurfaceMode properly
