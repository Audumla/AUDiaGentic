# Extract a foundation resource-record store from the three parallel component stores

## Description

Deep-dive finding 2026-07-18. Three components carry the same persisted-record mechanics under different names: agent_jobs/jobs_store.py, agents/agents_gateway_store.py, and agents/agents_gateway_sessions_store.py — the sessions store docstring even says it 'follows agents_gateway_store conventions exactly'. Byte-identical or near-identical between at least two of the three: _redact_error (identical twice), per-id threading.Lock registry with guard (identical twice), f'{prefix}_{uuid4().hex[:16]}' id generation (five variants across the tree incl. lease_/mf_/client_), read-json-validate-with-schema-and-map-errors, list-dir-skip-unreadable, require-id-validate-atomic_write_json, and locked transition: read → workflow transition_allowed → dict copy → updated-at → underscore→dash key mapping → redact error → write → timeline 'state.changed' with from/to. This passes the Architecture Standards §3 bar for foundation extraction: the MECHANICS (locked read-modify-write, validated atomic persistence, timeline emission) are domain-neutral with three independent consumers; domain ownership (schema stem, workflow yaml, paths, id prefix, error-code prefix) stays with each component as binding configuration. RV12 asked for exactly this reuse in the AG08 era and it never happened.

## Steps

1. Freeze the seam: a foundation ResourceRecordStore (foundation/system or foundation/observability-adjacent — decide with architecture owner; it composes io + workflow + observability + contracts.schema_registry, all already foundation) parameterized by: schema stem, workflow (path+name), record-path/timeline-path resolvers, id-field name + prefix, component/resource-kind for timelines, error-factory. Public surface: generate_id, build+validate hook, read, write, list (skip-unreadable), transition(new_state, updates), append-to-list-field helper, mark-flag helper (cancel-requested pattern), and the redacted-error mapper.
2. Migrate agents_gateway_sessions_store first (newest, cleanest, fully conforming), then agents_gateway_store (keep its extra attempt/output-chunk logic component-side), then jobs_store (smallest surface; keep its sequential-id generation quirk OR migrate job ids to uuid prefix in the same change if the sequential scan has no dependent — verify first).
3. Preserve every existing error CODE verbatim per store (the codes are public contract; the mechanics are not) — the store takes the component's error factory.
4. Delete the migrated private helpers in the same change (no dual path). Keep each component's schema/workflow/paths files untouched.
5. Cross-process posture: do NOT solve multi-process locking here — that is SH07's scope (see the SH07 review filed 2026-07-18). But design the seam so SH07 can swap the per-process lock for the PR06 StartupLock+revision-CAS pattern in ONE place instead of three.
6. Optional same-pass micro-cleanups if trivially absorbed, else skip: foundation/steps/factory.py local _Registry → registry_utils.Registry (gains reset_all_registries test isolation); a foundation helper for dual-key dash/underscore payload lookup (currently hand-rolled as _payload_get/_params_get/key.replace('_','-') in at least four modules).
7. Full gateway + jobs + sessions suites, plus the AR25/protocol-adapter and boundary suites, must pass unchanged.
