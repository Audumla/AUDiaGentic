## Phase 1 detail — LSP tool descriptions
Target: coding-lsp.yaml, add tool-descriptions block for ag-lsp server (21 tools)

Each tool's purpose (from lsp_api.py function mapping):
- lsp_capabilities: Return available server capabilities for a file's language server
- lsp_symbols: Search workspace-wide symbol definitions by query string
- lsp_doc_symbols: Return document outline (symbol tree) for a single file
- lsp_definition: Navigate to the definition of a symbol at position
- lsp_hover: Show hover tooltip with type/doc info for symbol at position
- lsp_references: Find all references to a symbol, optionally excluding declaration
- lsp_type_definition: Navigate to type definition of expression at position
- lsp_implementation: Navigate to implementation(s) of interface/abstract method at position
- lsp_call_hierarchy: Show callers or callees (incoming/outgoing) for function at position
- lsp_symbol_context: Return enclosing symbol context (class/function scope chain) at position
- lsp_code_actions: List available code actions (fixes, refactors) for range in file
- lsp_format_preview: Preview formatting changes for a file or range without applying
- lsp_organize_imports_preview: Preview import reorganization changes without applying
- lsp_diagnostics: Return diagnostics across workspace files with severity/limit filters
- lsp_rename_preview: Preview rename changes across all references before applying
- lsp_file_diagnostics: Return diagnostics for a single file with timeout protection
- lsp_changed_diagnostics: Return diagnostics only for recently changed files (batch limit)
- lsp_inlay_hints: Show inline type hints and parameter names for a range
- lsp_signature_help: Show function signature and current parameter at position
- lsp_type_hierarchy: Navigate supertypes or subtypes of class/interface at position
- lsp_completion: Trigger autocomplete suggestions at position, optionally with trigger character

No Python code changes needed — lsp_mcp.py already uses plain @mcp.tool() decorator.

## Phase 3 detail — rich format implementation
### base.py changes
Add ToolDescriptionSpec dataclass alongside McpServerDeclaration:
```python
@dataclass(frozen=True)
class ToolDescriptionSpec:
    description: str
    parameters: dict[str, str] = field(default_factory=dict)  # param_name -> description
```
Change McpServerDeclaration.tool_descriptions type from `dict[str, str]` to `dict[str, str | ToolDescriptionSpec]`.

### loader.py changes
In _load_mcp_server_declaration (line ~143), when parsing tool-descriptions values:
- If value is a string → keep as-is (backward compatible)
- If value is a dict → construct ToolDescriptionSpec from description + parameters keys

### component_server.py changes
In _AutoDescFastMCP.tool():
- After resolving description from YAML, check if it's a ToolDescriptionSpec
- If so, augment the tool's JSON Schema with parameter descriptions by modifying the properties' "description" fields
- This requires post-processing the schema that FastMCP generates — may need to wrap the parent.tool() call to inject into the registered tool info

### Proof-of-concept servers
Start with ag-lsp (all 21 tools have well-defined parameters) and/or ag-agents-gateway.
