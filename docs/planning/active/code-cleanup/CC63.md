# gpt-auto: surface the Chromium remote-debugging consent gate as an operational precondition

## Description

Chromium now gates remote debugging on the default browser profile behind an interactive consent prompt. Until a human clicks Allow, the DevTools HTTP discovery endpoints return 404 and a websocket connect blocks. The connect path itself is fixed (see ledger chg_20260810_073400_the-gpt-auto-chatgpt-browser-p_2620, commit 0660f63a2) and consent persists once granted, but the precondition is currently undocumented and the failure mode is opaque: an operator sees only a timeout or a puppeteer 'HTTP Not Found', with nothing pointing at a dialog waiting in the browser.

gpt-auto must run on the default profile, because the logged-in ChatGPT session and the AUDiaGentic workspace live there. A dedicated --user-data-dir is therefore not an available workaround and should not be recommended anywhere.

## Steps

- Document the consent prompt as a gpt-auto operational precondition, alongside the existing 'browser must already be running with --remote-debugging-port' requirement
- Make the connect timeout error name the likely cause, e.g. 'connect timed out -- a browser permission dialog may be awaiting approval'
- Decide and record whether first-run consent must be granted before a gpt-auto session can be considered unattended-capable
- Correct any docs that recommend a dedicated --user-data-dir for gpt-auto (contradicts the default-profile requirement)

## Validation

- With consent not yet granted, a gpt-auto session open fails with an error naming the permission dialog rather than a bare timeout
- With consent granted, repeated session opens succeed without further prompting (verified this session: two consecutive runs, no second dialog)
- gpt_auto.yaml documents the default-profile requirement and the consent precondition
- No remaining documentation recommends a separate --user-data-dir for gpt-auto

## Effort & Risk

Low risk: diagnostics and documentation only, no change to the working connect path. The main judgement call is whether unattended operation needs an explicit pre-flight consent check or merely a clearer error.

## Notes

Discovered while restoring gpt-auto after it stopped connecting. Three misleading signals cost significant debugging time and are worth recording: the port is LISTENING and accepts TCP while every DevTools endpoint 404s; launching the browser with the debug flag while it is already running silently forwards to the existing process and prints a 'DevTools listening' banner without enabling anything; and the browser writes a valid DevToolsActivePort file even while discovery is refused. Brave's binary predated the failure by two days, so a browser update was NOT the cause -- the consent gate was.
