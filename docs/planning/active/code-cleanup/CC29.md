# Config-driven skill rendering templates: Trigger/Do/Do not/Root surface labels in base.py

## Description

Skill file rendering templates in `base.py` contain hardcoded section labels and structure text that becomes user-facing content in provider skill files (AGENTS.md, CLAUDE.md skills). These should be config-driven, following the same pattern as MCP tool-descriptions.

## Steps

['1. Define SkillRenderSpec dataclass with preamble and label fields\n2. Add skill-rendering: block to each provider YAML with current hardcoded labels as baseline content\n3. Wire loading in component loader to populate SkillRenderSpec from YAML\n4. Refactor render_frontmatter_skill() and render_flat_skill() to use config-driven template rendering\n5. Verify generated skill files are byte-identical to pre-refactor output']

## Files

- base.py (render_frontmatter_skill, render_flat_skill) — replace f-string concatenation with config-driven template
- provider YAML files (claude.yaml, codex.yaml, roo.yaml, etc.) — add skill-rendering section with current labels as baseline
- SkillDefinition or new SkillRenderSpec in base.py — dataclass for loaded template config

## Validation

['- All provider skill files render identically before/after refactor\n- A provider with custom label values (e.g., "Action:" instead of "Do:") renders the custom labels correctly']

## Exact line numbers in base.py

### render_frontmatter_skill (lines 320-339)
Input: SkillDefinition with fields: name, description, title, tag, trigger(list), do(list), dont(list)
Output: frontmatter skill file content for codex-style providers

Variable substitutions:
- {skill.name} → from SkillDefinition.name
- {skill.description} → from SkillDefinition.description  
- {skill.title} → from SkillDefinition.title
- {skill.tag} → from SkillDefinition.tag
- trigger_lines → "\n".join(f"- {item}" for item in skill.trigger)
- do_lines → "\n".join(f"- {item}" for item in skill.do)
- dont_lines → "\n".join(f"- {item}" for item in skill.dont)
- root_label → from parameter

Hardcoded labels that should be config-driven:
1. Frontmatter separator: "---"
2. Frontmatter keys: "name:", "description:"
3. Managed header constant: MANAGED_MARKDOWN_HEADER (line 161 — this stays as code, it's a protocol marker)
4. Heading format: "# {title}" — heading level is hardcoded to 1
5. Preamble sentence: "Use this skill for canonical `@{tag}` launches."
6. Section label: "Trigger:"
7. Section label: "Do:"
8. Section label: "Do not:"
9. Footer format: "Root surface: `{root_label}`"

### render_flat_skill (lines 342-358)
Input: SkillDefinition + provider_name, launch_example parameters
Output: flat skill file content for roo/claude-style providers

Hardcoded labels:
1. Managed header constant: MANAGED_MARKDOWN_HEADER (stays as code)
