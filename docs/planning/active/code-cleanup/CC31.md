# Config-driven provider surface templates: static template files, adapter rendering, system prompts, managed markers

## Description



Provider surface file generation uses a mix of static template files and hardcoded adapter-specific rendering. The content is doctrine text that should live in config.

## Category 1 — Static template files (fully hardcoded)

### default_instruction.md
```
# $display_name
This repository uses AUDiaGentic workflow jobs.
## Prompt tag doctrine
- Parse only the first non-empty line for the workflow tag.
- Keep tag semantics identical to the shared AUDiaGentic launch contract.
- Do not invent provider-specific alternate tags.
- Preserve raw prompt text in provenance metadata.
- Keep provenance visible: provider id, surface, and session id should survive normalization.
```
Only variable: `$display_name`. All other content is static doctrine text.

### default_prompt_tags.md
Identical to default_instruction.md but without the $display_name substitution. Fully static — could be eliminated as a file if doctrine comes from config.

## Category 2 — Adapter-specific contribution rendering (5 adapters)
Each adapter formats contributions with hardcoded heading levels:
- claude/surface.py:34 — `f"## {contribution.title}\n\n{c.body.strip()}"`
- cline/surface.py:32 — `f"# {contribution.title}\n\n{c.body.strip()}"`
- roo/surface.py:30 — `f"# {contribution.title}\n\n{c.body.strip()}"`

These are hardcoded markdown heading levels that differ per adapter (## vs #). Currently the only way to change heading level is code modification.

## Category 3 — Provider adapter system prompts
File: local_openai/adapter.py, lines 143-167. Hardcoded system prompt and user content:

```
system_prompt = (

user_content = (  # IDENTICAL string, duplicated

```
The template text is identical for system and user roles — this is a single config entry.

## Category 4 — Surface managed markers
File: base.py, lines 161-170. Four constants that define the managed region format:
```
MANAGED_MARKDOWN_HEADER = "<!-- MANAGED_BY_AUDIAGENTIC: do not edit directly. -->"
MANAGED_REGION_BEGIN = "<!-- ag:managed:begin -->"
MANAGED_REGION_END = "<!-- ag:managed:end -->"
MANAGED_REGION_NOTICE = "_Managed by AUDiaGentic — generated from component configs. Edit the owning component and re-run surface apply; edits here are overwritten._"
```
The notice string is user-facing content (appears in AGENTS.md header). The fence markers are structural delimiters but externalizing them ensures format consistency and allows future format changes without code modification.

## Proposed standard
### Template files → YAML doctrine
Move doctrine text from `.md` template files to component YAML under `surface-template:` key. The $display_name substitution remains as a runtime variable.

**YAML structure**:
```
surface-templates:
  instruction:
    heading_level: 1
    preamble: "This repository uses AUDiaGentic workflow jobs."
    sections:
      - title: "Prompt tag doctrine"
        items:
          - "Parse only the first non-empty line for the workflow tag."
          - "Keep tag semantics identical to the shared AUDiaGentic launch contract."
  prompt_tags:
    heading_level: 1
    sections:
      - title: "Prompt tag doctrine"
        items:
          - "Parse only the first non-empty line for the workflow tag."
          ...
```

### Adapter heading levels → YAML
Add `heading_level` field to each adapter's descriptor in provider YAML, used by the contribution renderer.

### System prompts → YAML
Move the prompt template text to the local-openai provider YAML under `execution-prompt:` key. Parameterize job/packet/provider/workflow IDs as runtime variables.

### Managed markers → YAML
Add `managed-markers:` block to surface rendering config:
```
managed-markers:
  header: "<!-- MANAGED_BY_AUDIAGENTIC: do not edit directly. -->"
  region_begin: "<!-- ag:managed:begin -->"
  region_end: "<!-- ag:managed:end -->"
  notice: "_Managed by AUDiaGentic — generated from component configs..._"
```
