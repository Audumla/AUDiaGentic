# Post-completion critical review: broken tests + unimplemented decision + standards gap

## Notes



## Findings

CC26 was marked `completed`, but a post-completion critical review found the migration left broken tests and one decision unimplemented. Verified 2026-07-09 against working tree on branch proof/release-please-live.

### Positive (compliant)
- All 7 target modules deleted (cli_io, paths, home, config.py, observability.py, interaction.py, util.py); all replacement packages/modules created. No long-lived shims — migration atomic per Decision list.
- No stale *import* statements to old module paths anywhere in src.
- Layer boundaries respected: no foundation import of runtime.harness/rig/update or components (only runtime.system.platform, which is pre-existing and outside the plan's forbidden list).
- deep_merge relocated to foundation.config.merge; logging/config._deep_merge and paths/resolution.py both delegate to it (Decision 12).
- launcher.py shrunk to 218 LOC; 7 command modules extracted; pyproject entrypoint intact; `--help` works.
- Interaction split clean; the `_backend_mod._backend` module-reference pattern in api.py correctly preserves runtime backend reassignment and resolved the circular import. Focused foundation tests pass.

### Finding 1 (BLOCKER) — 5 tests broken by the move, item still marked completed
Decision 4 moved foundation/home.py -> foundation/paths/home.py, but two test files still monkeypatch the deleted module by STRING literal:
- tests/unit/coding_lsp/test_provider_lsp_provision.py:47,68,98
- tests/unit/provisioning/test_dynamic_agent_config.py:153,229
All 5 fail: `ModuleNotFoundError: No module named 'audiagentic.foundation.home'` / `ImportError in monkeypatch.derive_importpath`.
Fix: retarget the 5 strings to `audiagentic.foundation.paths.home.global_harness_runtime`. Production consumers import global_harness_runtime lazily from that module, so the patch target is valid.
Root cause: the plan's Validation step scanned only `src` with `rg` for residual imports, and the focused test list omitted these two files. String-literal references (monkeypatch.setattr / mock.patch / importlib.import_module) are invisible to an import-oriented grep and were never re-scanned; the full suite was not run before completion.

### Finding 2 (NON-COMPLIANCE) — Decision 7 CliBackend->print_message not implemented
Decision 7 explicitly directed wiring CliBackend's announcement/status output through foundation.cli_io.print_message and named the raw prints 'a real duplication'. Implemented backend.py still uses raw `print(...)  # noqa: T201` throughout ask() and push_status(); print_message exists and is unused by this backend. Either wire it through or amend Decision 7 to record why raw print was retained.

### Finding 3 (MINOR DEVIATION) — paths/__init__ exports
Decision 3 said to re-export find_project_root/find_repo_root/REPO_ROOT/SRC_ROOT from foundation/paths/__init__.py. They are not exported; all consumers use narrow submodule imports (paths.project / paths.package). This works and is arguably cleaner, but the plan text was neither followed nor updated to record the choice.

## Conclusion

CC26 should not have been marked completed with 5 failing tests. Item-level actions: (1) fix Finding 1 monkeypatch targets and run the FULL suite; (2) resolve Finding 2 (wire print_message or amend Decision 7); (3) note or apply Decision 3 deviation.

Standards / process outcome: the primary control ALREADY EXISTED and was skipped. CREATING_PLANS.md Sec 5 Definition of Done item 3 mandates the full `python -m pytest tests/unit` suite be green, not just added tests — running it would have surfaced all 5 failures. ARCHITECTURE_STANDARDS.md Sec 10 already mandates atomic + test-driven migration. So no doctrine was wrong; the gap was verification completeness for module move/rename/delete, plus discoverability (CREATING_PLANS.md is NOT registered in plan_list_standards, so an agent following its own 'read standards first' rule never sees it).

Applied fixes (2026-07-09):
1. CREATING_PLANS.md Sec 5 DoD item 3 strengthened: for a module move/rename/delete, an import-shaped `src`-only grep is insufficient — the residual-reference scan must cover the whole repo including tests/ for string-literal references (monkeypatch.setattr, mock.patch, importlib.import_module, patch decorators, dotted config/YAML), and only the green FULL suite proves the move landed.
2. ARCHITECTURE_STANDARDS.md Sec 10 Migration Doctrine: added a 'Move/rename/delete verification' rule carrying the same requirement. This is the API-reachable location — arch-standards IS returned by plan_list_standards and IS the standard CREATING_PLANS.md tells implementers to read for any src/ item — so the rule is now discoverable via the planning API, not only by reading the unregistered process guide.

No reclassification of CREATING_PLANS.md as a standard was needed; the durable rule now lives in the registered standard, with the process guide restating it at the DoD gate.
