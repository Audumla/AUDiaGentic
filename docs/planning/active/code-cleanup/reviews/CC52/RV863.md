# Vocabulary source-of-truth and scope review

## Notes



## Findings

1. CC52 repeats the rejected global rule “use StrEnum for all new enums.” Most listed values are configuration, schema, or persisted wire strings. Adopt CC50’s representation policy: preserve source-owned/wire values as strings with Literal aliases and central validation; use StrEnum only after explicit boundary parsing into internal runtime values.

2. Several proposed vocabularies are factually incomplete or wrong:
   - InvalidEventPolicy omits the existing default/value quarantine.
   - EventWritePolicy proposes locked-trim, which does not exist; current implementation supports locked-append and otherwise performs an unlocked append. First decide whether an unlocked mode is intentional and validate it.
   - MechanismSchema omits active values including cli-install-recipe, managed-config-spec, lsp-self-support-spec, obs-transport-note, acp-feature-note, boolean-set, tier-enum, surfaces-struct, and none.
   - DiscoveryMode omits none, an accepted model-source schema value and an actual SourceCatalogResult outcome.
   - ApprovalState omits pending and expired; both are first-class schema/runtime states.
   - ReviewRecommendation omits rework and block and invents fail; Review aggregation proposes majority-pass while runtime implementation currently supports all-pass, although JSON Schema also declares majority-pass. This is a schema/implementation inconsistency to resolve, not an enum migration.
   - Gateway client mode values are in-process, standalone, and automatic—not in-process and remote.
   - Profile-slot values are active, idle, and pending; queued is queue-state, not a profile slot.

3. Mechanism schema, source class, discovery mode, approval state, and review vocabulary already have declarative sources (provider/model-source JSON Schema, capability catalogue YAML, or agent-job JSON Schema). Their optimization is to remove duplicative Python validation and derive checks/types from their source—not to add hand-authored enums.

4. The proposed “single-value but extensible” enums for AggregationRule and RecoveryReason are speculative, contrary to the evidence-led-scope rule. For recovery, preserve the typed recovery metadata shape and add a Literal alias/validator only if duplicate validation is actually present.

5. ErrorKind is too generic and inappropriate as a global agents enum. AudiaGenticError.kind is a component-owned diagnostic classification; its values may be open-ended and should remain owned at each error boundary. Do not enumerate log/error labels merely because they recur.

6. ACP terminal tool statuses are raw transport input. A Literal alias plus ingress validation is appropriate, but it must first distinguish tool-status values from turn stop_reason values. They are not one shared “turn status” vocabulary.

7. CC52 spans providers, foundation, agents, and agent-jobs with unrelated source authorities. Split it by owner/source after triage. CC50 remains the umbrella policy; CC51 retains provider automation-mode/isolation work. Keep only a tightly scoped remaining provider streaming/catalog slice in a successor item.

## Conclusion

CC52 should not proceed as a single enum-migration item. First correct the source inventories and resolve the review-bundle schema/runtime inconsistency. Then split into source-owned validation work (catalogue/schema), internal streaming-policy behavior where justified, agents gateway runtime values, and any remaining foundation wire validation. Keep stateful/wire contracts string-compatible unless ingress parsing is explicitly part of the change.
