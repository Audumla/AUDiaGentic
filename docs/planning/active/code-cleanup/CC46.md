# Generic managed-service supervisor restart

## Description

Add a generic foundation-layer supervisor capable of restarting an independently managed service process without restarting the MCP/tool host. The supervisor must preserve service identity, coordinate ownership transfer, and expose safe restart semantics for the gateway and future managed services.

## Steps

1. Add restart method to ManagedServiceLifecycle facade (uses existing starter + shutdown)
2. Add service_restart operation to GatewayServiceApplication with graceful/force + readiness-timeout parameters
3. Add request_restart to GatewayLifecycleController
4. Ensure persisted request recovery runs before replacement readiness
5. In-process host returns explicit unsupported result
6. Add restart timeline events (restart-requested, restart-draining, restart-completed, restart-failed)
7. Add unit tests for restart coordination and failure paths
8. Add gateway integration test proving MCP connectivity across worker replacement
9. Document deployment modes

## Detailed Solution & Technical Design

GROUNDING UPDATE (validated 2026-07-25):

Existing infrastructure already in place:
- ManagedServiceStore: atomic read/write, state transitions, lease coordination, owner_epoch tracking
- ManagedServiceOwner: claim/retire with process ownership verification
- ManagedServiceStarter: start_or_attach with restart path (prepare_restart_record → new owner_epoch)
- ManagedServiceShutdown: drain → guarded stop with quiescence checks
- ManagedServiceLifecycle: composition facade over starter + shutdown
- GatewayServiceApplication: operation router with CAPABILITIES list
- GatewayLifecycleController: operator drain/stop/resume + idle self-shutdown

What's ALREADY proven:
- Owner-epoch transfer via prepare_restart_record() (new uuid4 epoch, expire leases, reset to starting)
- Lease semantics with expected_epoch checks (optimistic concurrency for client leases)
- Process ownership verification via observe_process + ownership_matches
- Transition engine state machine with stopped→starting restart path
- Timeline events on all record mutations via record_timeline_event

What's NET-NEW (the actual work):
1. Restart operation exposed at GatewayServiceApplication level (service_restart operation)
2. Restart lifecycle coordination in GatewayLifecycleController
3. Timeline events for restart milestones (restart-requested, restart-draining, restart-completed, restart-failed)
4. Force vs graceful restart policy with readiness timeout
5. Persisted request recovery before replacement readiness
6. In-process host returns explicit unsupported result
7. Unit tests for ownership transfer during restart and restart failure paths
8. Integration test proving MCP connectivity survives worker replacement

Restart sequence (using existing primitives):
1. Acquire restart lease (prevent concurrent restarts via a dedicated mechanism)
2. request_drain() — transition to draining state
3. wait_for_quiescence() or apply force policy
4. stop_if_quiescent() — guarded stop
5. New owner_epoch: start_or_attach() with fresh declaration → new worker
6. Wait for health/readiness of replacement
7. Publish restart-completed

Error handling:
- Worker startup failure → record failed state, preserve diagnostics
- Readiness timeout → force kill old worker, transition to failed
- Replacement conflict (another process claimed the service) → abort with conflict
- Stale owner epoch during restart → reject (someone else owns it)

NOT needed: separate ManagedServiceSupervisor class — ManagedServiceLifecycle already composes starter + shutdown; restart is just a new coordination method on the existing facade.

managed_service_supervisor.py is NOT needed — ManagedServiceLifecycle already composes the right primitives. The restart method lives there.

Gateway API addition:
def service_restart(self, *, graceful: bool = True, readiness_timeout: float = 15.0):
    '''Restart the gateway worker process without restarting MCP host.'''
    if self._lifecycle is None:
        raise service_validation_error(27, "restart requires standalone service host")
    return self._lifecycle.request_restart(graceful=graceful, readiness_timeout=readiness_timeout)
