# Generic managed-service supervisor restart

## Description

Add a generic foundation-layer supervisor capable of restarting an independently managed service process without restarting the MCP/tool host. The supervisor must preserve service identity, coordinate ownership transfer, and expose safe restart semantics for the gateway and future managed services.

## Steps

['Define a generic ManagedServiceSupervisor contract for start, readiness, drain, stop, replacement launch, owner-epoch transfer, and restart outcome.', 'Separate service supervisor process state from service worker process state; the supervisor remains alive while replacing the worker.', 'Implement restart sequencing: acquire restart lease, reject new work or drain, wait for quiescence or apply explicit force policy, stop the worker, launch the replacement with the same endpoint/token/service root, wait for health/readiness and new owner evidence, then publish completion.', 'Define failure behavior for worker startup failure, stale owner records, readiness timeout, replacement conflict, and partial restart. Preserve the last diagnostic and make recovery/manual intervention explicit.', 'Add generic lifecycle events and status fields for restart-requested, restart-draining, restart-started, restart-ready, restart-completed, and restart-failed.', 'Expose the operation through the gateway service application/client as service_restart, including graceful/force and readiness-timeout parameters.', 'Ensure persisted request recovery runs before readiness and existing client leases do not silently transfer across owner epochs.', 'Add reusable unit tests for supervisor ownership transfer and restart failure paths, then gateway integration tests proving MCP/tool connectivity remains available while only the gateway worker is replaced.', 'Document deployment modes: standalone supervisor, externally managed service, and in-process test host. In-process hosts must return an explicit unsupported result rather than pretending to restart.']
