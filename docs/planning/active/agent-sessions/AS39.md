# AS19 Stage-2 Slice A: transport-observation-only status observer resolver (no ingress, no hooks)

## Description

AS19's full scope (steps 1-9 of the parent item) includes managed-hook/plugin installation, a loopback HTTP ingress, and lifecycle reconciliation — all needed for Recipe B/C harnesses. That full scope is what has repeatedly timed out when attempted as a single gateway agent task. This item carves out only the Recipe A path (declared transport-observation, e.g. OpenCode ACP) which needs none of that machinery: AS28 already delivers neutral TransportObservation values in-process, and the generic normalizer (normalize_harness_status_observation) already exists in providers/contracts/harness_status_observer.py. What's missing is the resolver that turns a prepared transport into a StatusObserverLease and hands its observe_transport callable to the session pipeline — pure in-process wiring, no network, no config writes, no Docker required for this slice.

## Steps

1. Add `src/audiagentic/components/providers/services/harness_status_observer_resolution.py` with a single function `resolve_transport_observation_lease(request: StatusObserverRequest) -> StatusObserverResult` that ALWAYS returns a `mechanism=transport-observation` lease (this slice hard-codes Recipe A; do not add hook/plugin branching here — that is Stage-2 Slice B, a separate item).
2. The resolver validates: agents component enabled, provider enabled and registered, `request.surface_id` matches a known Recipe-A surface (start with `opencode-acp` only — do not hardcode a list of future surfaces). Any mismatch returns `StatusObserverResult(ok=False, supported=False, state=UNSUPPORTED, error_code=...)` — never guesses a similarly named surface.
3. On success, build a `StatusObserverLease(binding_id=<new opaque id>, observe_transport=<closure over normalize_harness_status_observation>)`. The `observe_transport` closure signature is `(observation: TransportObservation) -> StatusEvidence | None` — it calls the existing `normalize_harness_status_observation(lease, observation)` from `providers/contracts/harness_status_observer.py`. Binding IDs use `secrets.token_hex` or equivalent existing bounded-random helper already used elsewhere in the codebase (search for the pattern used by other opaque binding IDs, e.g. in session_binding.py or agents_gateway_sessions.py, and reuse it — do not invent a new ID scheme).
4. Add `providers_api.open_harness_status_observer(request: StatusObserverRequest) -> StatusObserverResult` as the single public entry point wrapping the resolver. `close_harness_status_observer(binding_id)` just invalidates the lease reference (this slice does not need durable index/prune — the lease lives only as long as the SessionRuntime handle that holds it).
5. Wire the lease creation point into whatever SessionRuntime/session-open code path already receives the AS28 `PreparedSessionTransport` (search `rg "PreparedSessionTransport" src/audiagentic/components/agents` to find the exact call site). Call `providers_api.open_harness_status_observer(...)` immediately after the transport is prepared, store the returned lease on the session runtime object, and call `lease.observe_transport(obs)` wherever `TransportObservation` values are currently received from the AS28 observation sink — do NOT change what happens with the resulting `StatusEvidence` yet (publishing/timeline wiring is a later slice); for this slice it is sufficient that the mapping executes without raising and produces a `StatusEvidence | None` per observation.
6. Do not add: HTTP ingress server, any hook/plugin config writer, lifecycle reconciler, or a `harness-status-observers.json` registry. If the session-open code path AS19 needs to attach to does not exist yet or is substantially different from what's assumed above, report that back rather than inventing a parallel path.
7. Add tests in `tests/unit/providers/test_harness_status_observer_resolution.py`: unsupported surface_id returns UNSUPPORTED; agents disabled returns UNSUPPORTED; opencode-acp surface returns a valid lease with a non-empty binding_id; the lease's observe_transport correctly forwards ACTIVITY/TOOL_REQUESTED/PERMISSION_REQUESTED observations to StatusEvidence and returns None for terminal/error observations (reuse assertions similar to the existing normalize_harness_status_observation tests if any exist — check `tests/unit` for prior coverage first).
8. Add one integration-shaped test proving the wiring point (step 5) actually calls open_harness_status_observer and threads observations through it — use a fake/stub transport, not a real OpenCode process; Docker/real-surface proof is out of scope for this slice per AS19's own validation note (Docker required only before an execution evidence tier, which this slice does not claim).
9. Run `python -m pytest tests/unit/providers/test_harness_status_observer_resolution.py tests/unit/agents/ tests/unit/foundation/transports/ -q --tb=short` and confirm zero regressions against the known pre-existing failures.

## Detailed Solution & Technical Design

The key design constraint that keeps this slice small and gateway-timeout-friendly is refusing all Recipe B/C machinery. AS19's full item conflates three genuinely separable concerns: (a) mapping a neutral observation to canonical evidence — already done; (b) resolving which mechanism a surface uses — this slice, in-process, no I/O; (c) installing a persistent hook/plugin/ingress when the mechanism requires one — explicitly NOT this slice. Because OpenCode ACP (the first and only currently-declared surface) uses Recipe A exclusively, a correct and useful observability path exists without touching (c) at all.

The resolver deliberately hardcodes the single known surface rather than reading a descriptor list, because AS19's own RV718 correction says observer/lifecycle declaration lives in the AS29 resolved-surface snapshot, not a separate `ProviderDescriptor.harness_status_observers` list (RV718 point 1 explicitly supersedes the original step 1 as written). If AS29's resolved-surface snapshot already carries a way to check 'this surface's lifecycle mechanism is transport-observation', prefer reading that over hardcoding — check `foundation/transports/session_surface.py` for a `LifecycleSource`/`LifecycleInstallation` field before assuming a hardcoded string comparison is the only option; use the AS29 snapshot's declared mechanism field if one already exists there instead of re-deriving it.

The wiring point in step 5 is the riskiest part of this slice because it depends on exactly how the current SessionRuntime code receives AS28 observations — this is why the task explicitly says to search for the real call site and report back if it doesn't match assumptions, rather than inventing a parallel one (which would create the very duplicate-path problem AS19's notes warn against).

## Code Samples & Guidance

```python
# src/audiagentic/components/providers/services/harness_status_observer_resolution.py
from __future__ import annotations

import secrets

from audiagentic.foundation.transports.harness_status_observer import (
    StatusEvidenceSourceKind,
    StatusObserverLease,
    StatusObserverRequest,
    StatusObserverResult,
    StatusObserverState,
)
from audiagentic.components.providers.contracts.harness_status_observer import (
    normalize_harness_status_observation,
)

# Slice A: the only currently-declared Recipe-A surface. Do not pre-populate
# future surfaces here — each addition requires its own probe per AS27.
_RECIPE_A_SURFACES = frozenset({"opencode-acp"})


def resolve_transport_observation_lease(
    request: StatusObserverRequest,
    *,
    agents_enabled: bool,
    provider_enabled: bool,
) -> StatusObserverResult:
    if not agents_enabled or not provider_enabled:
        return StatusObserverResult(
            ok=False, supported=False, state=StatusObserverState.UNSUPPORTED,
            error_code="UNS-PROV-OBS-001",
        )
    if request.surface_id not in _RECIPE_A_SURFACES:
        return StatusObserverResult(
            ok=False, supported=False, state=StatusObserverState.UNSUPPORTED,
            error_code="UNS-PROV-OBS-002",
        )

    binding_id = f"obs_{secrets.token_hex(16)}"

    def _observe(observation):
        # lease is bound by closure below after construction
        return normalize_harness_status_observation(lease, observation)

    lease = StatusObserverLease(binding_id=binding_id, observe_transport=_observe)
    return StatusObserverResult(
        ok=True, supported=True, state=StatusObserverState.READY,
        binding_id=binding_id, launch_environment={}, managed_ids=[],
    )
```

Note the closure-ordering subtlety: `_observe` references `lease` before it's constructed — this works in Python because the closure only resolves `lease` at call time, not definition time, but double-check with a quick test that `lease.observe_transport(obs)` behaves correctly rather than raising `NameError` (it will not, since `lease` is a module/function-local free variable resolved at call time, but confirm via the actual test in step 7 rather than assuming).

Before implementing, run `rg "PreparedSessionTransport" src/audiagentic/components/agents -l` and read the exact call site(s) to confirm where to insert the `open_harness_status_observer` call — do not guess the integration point from this plan text alone.
