# Seed real Agent Definition / Role / Execution Profile content

## Description

AS62 built the Agent Definition CRUD/resolution mechanism (dataclass + validate + from/to-dict + Store, mirroring Role and ExecutionProfile) but nothing in the plan sequence owns turning it into populated, real content. Confirmed by research 2026-08-04: AS62 itself never mentions seeding; AS64/65/66/69 all assume Agent Definitions already exist as data (AS64 checks capabilities against an existing definition, AS65/66 publish existing definitions over ACP/A2A, AS69 records identity digests of existing bindings) -- none of them creates one. This item closes that gap.

A first real instance already exists as of 2026-08-04 (created ad hoc, not as part of a plan item): execution profile `rig-tester` (local-openai / audiagentic-rig, the rig's local llama-server test model), role `placeholder` (minimal, schema-satisfying only), and agent definition `rig-tester-agent` composing them -- all in this repo's own `.audiagentic/config/`, with regression coverage in `tests/unit/agents/test_project_rig_tester_agent.py`. That proves the CRUD/resolution path end-to-end but is not real usable content (empty role instructions, no advertised skills, no publication).

## Steps

1. Decide what "real" content means for this repo: likely candidates are the roles/prompts already living in `agent_jobs`'s `@tag` prompt-launch mechanism (flagged elsewhere as slated for rework -- see project memory `project_agent_jobs_rework_pending.md`) or any harness-native Skill content that should have an Agent Definition wrapper.
2. For each candidate, create a real ExecutionProfile (if one doesn't already fit), a real Role with actual instructions/required_capabilities, and an AgentDefinition composing them, via the existing CRUD API/MCP tools (`agent_create_execution_profile`/`agent_create_role`/`agent_create_definition` on `ag-agents-mgmt`) -- not by hand-writing YAML.
3. Decide publication flags per definition (`internal`/`acp`/`a2a`) based on actual intended exposure, not defaults.
4. Add regression tests per created definition following the pattern in `tests/unit/agents/test_project_rig_tester_agent.py` (real project config, read-only assertions, no writes into `.audiagentic/runtime/`).
5. Replace or retire the placeholder `rig-tester-agent`/`placeholder` role once real content exists, or explicitly keep it as a deliberate minimal smoke-test fixture -- state which.
