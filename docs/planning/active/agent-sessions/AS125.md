# Close inactive GPT browser tabs after two hours without changing session state

## Description

Add a resource cleanup policy that closes a provider tab when the represented gateway session has had no activity for more than two hours. This is physical tab cleanup only: it must not fail requests, replace defaults, resume sessions, or mutate logical session lifecycle.

## Steps

- Track last validated session activity separately from request response/recovery clocks.\n- Add configurable two-hour tab-idle threshold.\n- Reaper checks quiescence and closes only the matching page handle.\n- Leave durable session binding, default binding, and provider URL unchanged.\n- Avoid closing tabs with active turns, pending requests, or unresolved fences.

## Detailed Solution & Technical Design

Implement cleanup in the GPT-auto runtime/browser lifecycle, not response policy. A periodic reaper enumerates owned page handles, checks active-turn/pending-request state, and compares last validated activity to the cleanup threshold. It calls close_page only when quiescent and records a bounded cleanup event. Reopening/resume remains an explicit or normal default-selection concern and is not triggered by cleanup.

## Validation

Fake clock tests cover active tab protection, exactly-over-threshold close, unresolved-session protection, no session/default mutation, idempotent cleanup, and restart/reopen behavior.

## Effort & Risk

Medium: browser resource cleanup can race active work if quiescence checks are incomplete.

## Standards

Session lifecycle/resource policy; AS92.

## Acceptance Criteria

- Quiescent tabs older than two hours are closed.\n- Active/pending/unresolved tabs are never closed.\n- No request failure, default replacement, or session close is emitted.\n- Cleanup is configurable and idempotent.
