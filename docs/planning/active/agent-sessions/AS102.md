# Redaction and sanitization contract for public projections

## Description

Define one least-privilege public metadata projection for status, metadata, and live-read surfaces. gateway/store/_records.py currently copies the full durable metadata mapping, violating unknown-field exclusion.

## Steps

1. Inventory metadata keys and classify public/internal/sensitive/provider-native/deprecated.
2. Define one agents-owned typed allowlist/schema; unknown keys excluded.
3. Implement one pure sanitizer used by status, metadata, output/live-read, and recovery responses.
4. Remove direct full mapping copies from public helpers.
5. Coordinate AS92 schema to reference only sanitized metadata; omit metadata until available.
6. Add differential cross-surface and nested-field tests.

Authority boundary: GP48 supplies the diagnostic classification/evidence model; AS102 supplies only the public allowlist, redaction, deterministic bounds, and truncation behavior. AS102 must not infer lifecycle or build a second diagnostic classifier.

## Detailed Solution & Technical Design

Sanitizer accepts read-only mapping and returns a new typed public value. It does not mutate records, infer permissions from names, or keep endpoint-specific allowlists. Structural allowlisting runs before shared redaction; redaction is defense in depth, not authorization.

## Code Samples & Guidance



## Files

agents gateway/store/_records.py; one public metadata projector/schema; AS92 response path/schema; AS86/AS87 live-read paths; cross-surface tests.

## Validation

Unknown, provider-native, diagnostic, credential-shaped, and nested extras are excluded. Every public surface returns the same subset. No full metadata copy remains. Schema rejects undeclared fields.

## Effort & Risk

Bounded code but contract-sensitive; permissiveness creates a durable leak surface.

## Standards

Least privilege; unknown fields excluded; one policy authority; authorization before redaction; provider-neutral contracts.

## Acceptance Criteria

- One enforcement point governs every public projection; no surface formats its own output around it.
- Secrets, credentials, tokens, raw stdout/stderr and unredacted exception text are absent from every record, log and projection.
- Unknown fields are excluded by default.
- Assistant content and lifecycle evidence remain separate lanes.
- Composition identity appears as digest prefixes only.
- The existing operational-record mechanism was extended rather than duplicated.
- An architecture test fails when a new unallowlisted field reaches a public surface.
- The bounded diagnostic projection is the only public route for GP48 evidence; ordinary task status contains no diagnostic fields.
- Diagnostic output has a closed schema, hard encoded-size bound, deterministic truncation indicator, and requester-safe redaction; no paths/URIs/raw provider payloads pass through.

## Sequencing Decided 2026 08 09

**"Open early, close late" — decided after adversarial review (RV920). This replaces both the original "late gate" reading and the intermediate proposal of a small `AS102-core` slice.**

The intermediate proposal was to land a cheap preparatory slice (extend `CON-OPR-002`, exclude-by-default, the architecture test) before the first new public projection. That framing was withdrawn under challenge and should not be revived: this item's own `effort_risk` names the reachability guard — proving no surface can format its own output *around* the enforcement point — as the hard part, and that guard is exactly what the proposed "core" contained. Calling it small understated it.

Also confirmed while reviewing: the shared redaction primitives already exist and are already consumed at the MCP boundary (`redact_text`, structural denylist detection, `safe_metadata()` with a fixed allowlist, with explicit comments forbidding local variants). What this item adds is therefore **architectural** — forcing every public session projection through one allowlisted mechanism — not primitive-building.

**The separation that actually works is by when dependencies exist, not by effort:**

1. Purely internal mechanics may proceed without this item — AS93's in-memory buffer, AS87's internal output reader.
2. The central enforcement point **and** its reachability/conformance guard must land **with or before the first new public projection**. This is the non-negotiable part: if AS93/94/95 each ship their own local sanitization and this item centralizes them afterwards, that *is* the retrofit the item exists to prevent.
3. Each later public surface registers its allowlist through the established mechanism as it lands.
4. This item closes only after the final cross-surface audit confirms every status / metadata / output / timeline / control-audit projection participates.

Keep at work: M and as one item — do not split. Residual work after the enforcement point is real (future surface shapes cannot be exhaustively defined before AS94/95 exist) but is the easier half.
