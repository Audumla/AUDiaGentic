# Relay capability-gated agent output through a separate content-observation lane

## Description

Replace ACP-result-derived and environment-only output chunking with a provider-neutral, capability-gated content stream. Preserve the existing durable final request output contract; add optional live assistant-text delivery as independently atomic event files plus an indexed cursor, with explicit retention, gap, authorization, crash-recovery, Windows, Linux, and Docker semantics. Content is never lifecycle evidence, operator diagnostics, raw protocol persistence, tool arguments/results, or hidden reasoning.

## Steps

0. Depend on AS28 and AS29. AS19/AS21 consume lifecycle evidence only; they must never import or receive content events.
1. Add `foundation/transports/agent_output.py`:
```python
class AgentOutputKind(StrEnum):
    ASSISTANT_TEXT_DELTA = "assistant-text-delta"
    ASSISTANT_FINAL = "assistant-final"
    TOOL_SUMMARY = "tool-summary"

@dataclass(frozen=True)
class AgentOutputEvent:
    session_ref: str | None; turn_ref: str
    sequence: int; kind: AgentOutputKind
    text: str; observed_at: str; is_final: bool = False

OutputSink = Callable[[AgentOutputEvent], Awaitable[None] | None]
```
Reject empty/oversized text, missing turn id/sequence, non-monotonic sequence, and every unlisted kind. There is intentionally no `thought`, raw tool arguments/results, native payload, native event name, or arbitrary metadata field.
2. Extend AS28 `AgentSessionTransport.prompt` to accept separate `ObservationSink` and `OutputSink`; provider adapters map raw frames independently. ACP/native adapters may emit only channels enabled in AS29 `content`; a stream with no `assistant-text` declaration passes no text. A final transport result carries a bounded `final_output` only as a compatibility summary, never the source of streaming reconstruction.
3. Add `agents_gateway_output.py` as the sole agents content owner. Register a per-turn `OutputRelay` before prompt dispatch; enforce allowed kind, exact session/turn binding, sequence monotonicity, max fragment bytes, max cumulative bytes, and backpressure. Relay writes a new schema-validated `output.ndjson` line:
```json
{"contract-version":"v2","request-id":"req_...","session-id":"ses_...",
 "turn-id":"req_...","sequence":7,"kind":"assistant-text-delta",
 "text":"...","observed-at":"...","final":false}
```
Use per-request atomic append/lock. A disabled policy keeps only an in-memory bounded final summary; a relay failure disables content delivery for that turn but does not fail/control the harness turn.
4. Add `agent-output-event.schema.json` and component configuration `agents.gateway.output`: `enabled`, `persist`, `max-fragment-bytes`, `max-turn-bytes`, `retention-events`, and `allow-tool-summary`. Defaults: assistant text disabled until the surface is validated; hidden reasoning always unavailable; tool summaries false; prompt/tool payload capture impossible by schema. Validate config bounds at component startup.
5. Replace `_write_output_chunk` and `_session_output_from_result` in `agents_gateway_dispatch.py`. One-shot and session paths submit output only to `OutputRelay`; dispatch reads the relay's bounded final summary for the existing result contract. Delete ACP event iteration/overflow reconstruction. The user-facing output read operation is `GatewayApplication.read_request_output(project_root, request_id, cursor, limit)`, exposed by SH04 only after project/context authorization; AS09 may poll this cursor but cannot merge it into the metadata-only status stream.
6. Add provider API helpers only for resolved content capability/transport preparation; providers never write AG output files. Add architecture tests forbidding `AcpEvent`, `event.ext`, raw frame parsing, or output-file writes outside provider adapters/foundation tests and `agents_gateway_output.py`.
7. Test redaction/channel rejection, exact correlation, duplicate/out-of-order/oversize fragments, disabled policy, bounded retention, persistence failure isolation, concurrent request isolation, cursor authorization/expiry, session two-turn output separation, and fake ACP/native transports emitting identical normalized content. Docker proof is required before any real surface enables assistant text.
8. Deliberately do **not** reuse `ComponentOutputEvent`/`ComponentOutputSink`: that contract is only component progress/log messaging and may carry arbitrary `data`; it is not a correlated, retention-controlled user-content contract. Do not publish content on the foundation EventBus, `record_timeline_event`, or `append_operational_record`: their payload/attribute paths are metadata/operational evidence and the latter explicitly rejects output-shaped fields.
9. Reuse `agents_paths.gateway_root`/request paths, `StartupLock`, `atomic_write_json`-style durability, `load_ndjson` read semantics, and SH04 authorization. Add one agents-local `append_agent_output_record` that acquires the existing per-request `StartupLock`, appends+flushes+fsyncs one schema-validated content line, and releases it. Do not use `atomic_write_ndjson(..., append=True)`: it performs read-rewrite and is unsafe for concurrent streaming writers. The content file remains outside timelines/operational sidecars and uses a separate content schema/redaction validator.10. This replaces the prior output.ndjson append design. Do not append NDJSON: SIGKILL can leave a partial final line and atomic_write_ndjson(append=True) is read-rewrite unsafe under concurrent writers. Store each validated stream event at .audiagentic/runtime/gateway/<request-id>/output/events/<20-digit-sequence>.json using atomic_write_json, and maintain output/index.json under StartupLock(output/output.lock). The index has contract-version, request-id, turn-id, first-sequence, last-sequence, event-count, byte-count, truncated, and delivery-state (active|closed|degraded). Write the event file then atomically advance the index. On open under the same lock, scan/adopt contiguous valid files above indexed last sequence; an indexed missing/corrupt file marks delivery degraded and yields a stable content gap. Keep accepted files for the request lifetime; when a byte/event cap is reached set truncated=true and reject later deltas without rewriting older content.
11. Preserve the current request-record output field as the durable final-result/public-status contract. AS31 does not disable or replace it. The relay writes sidecar deltas only when streaming policy is enabled; terminal dispatch continues to write bounded final output through agents_gateway_store.transition_owned_terminal. Do not duplicate final text in a sidecar event unless a versioned surface proves it differs and the content policy enables it.
12. Add service capability requests.output-read.v1 and closed read_llm_request_output(request_id, after_sequence, limit) service/client/application operation. It reuses GatewayServiceApplication's canonical project-root validation and active client lease; it creates no second authorization model. Return only request-id, turn-id, events, next-after-sequence, truncated, delivery-state, and gap. Reject cross-project paths, malformed cursor, nonpositive/over-limit page, or a request absent from that project. AS09 may use it; status polling remains content-free.
13. Replace the environment variable only after preserving its opt-in default through typed agents component config: gateway-output-streaming.enabled=false, max-event-bytes, max-turn-bytes, max-events, page-limit. Validate values on load. Assistant text requires both this policy and AS29 validated content channel; no reasoning capture option exists. Existing final request output is independent of this toggle.
14. Platform/crash matrix: run deterministic Windows and Linux tests for StartupLock, index/event recovery, path handling, concurrent writers, byte cap, cursor gaps, and index rebuild. Linux Docker runs two Python processes and a fake stream, then SIGKILL after event file write/before index advancement; restart adopts that contiguous event exactly once. Real harness Docker content proof is mandatory before any Linux surface enables assistant text. Docker is not a substitute for Windows direct tests.

## Files

`foundation/transports/agent_output.py` (new); AS28 transport contract/adapters; AS29 descriptor manifest; `agents_gateway_output.py` (new); output/config JSON schemas; `agents_gateway_dispatch.py`; SH04 application/client output read operation; AS09 cursor integration; focused provider/agents/Docker tests.

## Validation

A validated fake surface can stream only declared assistant text through the relay; its content never appears in StatusEvidence, session timelines, AS16 diagnostics, tool fields, or raw provider event storage. An unvalidated surface and all reasoning channels emit no content. Cursor readers are project/context authorized and see ordered bounded fragments; relay failure cannot incorrectly terminalize or cancel a turn. Streaming uses atomic per-event files and an indexed cursor: a crash after event write/before index advance is recovered exactly once; an indexed missing event returns a stable gap/degraded result; cap exhaustion is reported without deleting prior content. Existing final output remains available through the request status contract. The new service operation requires the existing active lease and canonical project root. Windows direct and Linux direct tests pass; Linux Docker proves two-process race and SIGKILL recovery before a Linux surface enables streaming.

## Effort & Risk

Content has materially different confidentiality and retention rules from lifecycle evidence. This item deliberately creates a separate lane instead of widening TransportObservation or StatusEvidence.
