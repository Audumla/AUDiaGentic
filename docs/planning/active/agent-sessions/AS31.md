## Notes



## Goal

Replace ACP-result/environment-specific output handling with one provider-neutral, capability-gated assistant-content relay and one final-output selector. Preserve the existing durable final request output contract. Content must remain separate from lifecycle evidence, diagnostics, timelines, tool payloads, and hidden reasoning.

## Dependencies

AS19 transport/output sinks and AS29 resolved content capability are required. AS21 lifecycle decisions and AS30 protected binding identity are consumed but never widened by content. AS57 provides authorized public reads. AS65/AS66 consume those reads after this authority is stable.

## Foundation Output Contract

Define/consolidate `foundation/transports/agent_output.py` with a minimal event shape:

- Interaction Session ID and turn/request identity only;
- source sequence and/or source sequence range;
- assistant text delta or assistant final kind;
- bounded text;
- observed time and final flag where proven.

Do not include raw provider session ref, arbitrary metadata, native event name, hidden thought/reasoning, raw tool arguments/results, Agent Card metadata, A2A task payloads, or a generic tool-summary channel in v1.

Extend `AgentSessionTransport.prompt` to accept independent `ObservationSink` and `OutputSink`. Provider adapters map native frames separately. A surface with no validated AS29 assistant-text channel emits no content even if raw frames contain text.

## Output Relay

Add/consolidate `agents_gateway_output.py` as the sole live-content owner. Register one `OutputRelay` per turn before prompt dispatch. It must:

- enforce exact project/request/session/turn binding;
- enforce kind/channel authorization from the frozen AS29 snapshot and AS64 restrictions when available;
- reject missing/duplicate/lower/out-of-order source sequences according to the surface ordering contract;
- bound source fragment bytes, coalesced fragment bytes, cumulative turn bytes, event count, and memory/backpressure;
- coalesce provider deltas by max bytes, short flush interval, final/turn boundary, and backpressure;
- assign strict AUDiaGentic relay sequence and retain source sequence range;
- maintain a bounded in-memory final summary when persistence/streaming is disabled;
- degrade/disable content delivery for the turn on relay/storage failure without failing, cancelling, or terminalizing provider execution.

## Sole Storage Design

Use atomic per-event files and one locked atomic index. Do not use NDJSON append or read-rewrite append.

Suggested layout:

```text
.audiagentic/runtime/gateway/<request-id>/output/
  output.lock
  index.json
  events/<20-digit-relay-sequence>.json
```

Each event is schema validated and written with `atomic_write_json`; then `index.json` advances under `StartupLock`. The index contains contract version, request/turn identity, first/last sequence, event/byte counts, truncated flag, delivery state (`active|closed|degraded`), and gap/recovery metadata.

On reopen under the same lock:

- adopt contiguous valid event files beyond indexed last sequence exactly once;
- mark degraded/gap when an indexed file is missing/corrupt;
- never silently skip or rewrite history;
- retain accepted events for request lifetime;
- set truncated and reject later deltas when caps are reached without deleting earlier content.

## Existing Final Output Contract

The current durable request record final-output field remains the authoritative completed/public result during the AS63 migration. AS31 does not replace it with the sidecar stream.

Implement one final-output selector that handles:

- normal assistant final output;
- coalesced streaming text plus explicit final;
- partial assistant text with transport failure;
- tool-only/no-assistant turns;
- cancellation;
- timeout;
- missing terminal output;
- malformed/conflicting content events;
- provider-native final-output read where separately validated.

The selector consumes bounded relay state, AS21 lifecycle/finalization facts, and the neutral turn result. Transports/adapters cannot choose or persist the public final output directly. Insufficient evidence returns a typed degraded/unknown result rather than fabricated success.

Do not duplicate final text in sidecar events merely because a final request output exists. Sidecar final is enabled only when the exact surface proves a distinct useful final content event and policy allows it.

## Dispatch Migration

Remove direct `_ENV_STREAM_OUTPUT`, `_write_output_chunk`, ACP event iteration, overflow reconstruction, and any output-file write outside `agents_gateway_output.py`.

One-shot and session dispatch paths write through the relay/final selector. Terminal dispatch continues to call the existing durable request transition helper exactly once with bounded final output.

## Configuration

Use typed agents component configuration, default disabled for live assistant streaming. Include bounded values for:

- enabled/persist;
- max source event bytes;
- max coalesced fragment bytes;
- max turn bytes;
- max events;
- flush interval;
- page limit/retention behavior.

No reasoning-capture option exists. Live content requires local policy, a validated AS29 channel and any AS64 publication restriction.

## Authorized Reads

Provide one internal/application read contract such as `read_llm_request_output(request_id, after_sequence, limit)` during compatibility, later adapted by AS63 naming, using existing SH04 canonical project-root validation and active client lease. It returns only request/turn IDs, redacted events, next cursor/sequence, truncated, delivery state, and gap. It creates no runtime/session as a side effect. AS57 owns the combined public live turn-event/output surface.

AS65/AS66 must consume this read contract or AS57; they must not open output files directly.

## Acceptance Criteria

- One content contract, relay/storage owner, and final-output selector exist.
- Live content is bounded, redacted, capability/policy gated, and project authorized.
- Hidden reasoning and raw tool payloads are impossible by contract/schema.
- Content failure never changes lifecycle or transport execution.
- Existing final request output remains authoritative and available through the AS63 migration.
- Old ACP/environment-specific output paths are deleted.
- AS57 is the public read authority; AS65/AS66 are projections only.
- No second task, protocol or artifact content authority exists.
