# Recover proven orphaned turns through task-owned cleanup

## Description

Detect a proven dead owned harness during an active turn and recover without manually releasing asyncio locks or mutating scheduler sets. Track the owning turn task/request and process evidence, move through normal lifecycle, and let existing owner finally blocks reclaim lock/semaphore/accounting exactly once.

## Steps

0. Preserve the already-landed slices: turn timeout/silence timeout/cancel wiring are policy/cancel mechanisms, not orphan proof; `agents.session.orphaned` is declared but must not be emitted until proven-dead ownership evidence exists.

1. Locate the live session runtime ownership structures before editing: `rg "class SessionRuntime|request_cancel|turn_task|session.turn|orphaned|child_pid|creation" src/audiagentic/components/agents src/audiagentic/foundation`. Reuse existing task ownership, process evidence, and finally blocks; do not manually release `asyncio.Lock`, semaphores, `pq.running`, or `pq.idle`.

2. Extend `SessionRuntime`/session handle state with explicit current-turn ownership if it is not already present:
```python
current_turn_request_id: str | None
current_turn_id: str | None
current_turn_task: asyncio.Task | None
owned_process_evidence: OwnedProcessEvidence | None
closing_deadline_at: float | None
```
Use existing AS17/foundation process evidence types if available. Evidence must include owned/adopted vs external, pid/process identity/creation time where supported, and an observation timestamp.

3. Add a pure predicate helper, e.g. `is_proven_owned_turn_dead(handle, now) -> ProvenDeadResult`, with these rules:
- true only when the handle owns/adopted the process and the process identity proves the same child/descendant is dead or unrecoverably exited during a non-terminal current turn.
- false/conservative for unknown process state, missing identity, external/unowned process, stale pid reuse risk, timeout/silence alone, or missing current-turn task.
- result carries a bounded reason code, never raw process command lines, prompts, protocol payloads, or secrets.

4. Implement reaper entry point, e.g. `SessionRuntime.reap_proven_orphan(now=None) -> OrphanReapResult`, or a queue/session manager helper if that is the existing ownership boundary. It may inspect non-quiescent handles but may act only on `is_proven_owned_turn_dead(...) == true`.

5. On proven death, transition through normal lifecycle:
- record one redacted session timeline event on `agents.session.orphaned` with session id, turn id/request id, evidence reason code, and ownership mode.
- mark session closing/failed through existing session store helpers, using close reason `failed-orphaned` or an existing registered equivalent; extend schema/error resolution only if missing.
- cancel/signal the owning turn task or close the transport through existing foundation seams.
- let the owning task's `finally` path release locks/slots/accounting exactly once.

6. Add bounded force-close only after a closing deadline and only for proven owned/adopted descendants through AS17/foundation process cleanup. Never signal external processes. Unknown remains non-actionable and should produce diagnostic evidence at most.

7. Coordinate SH07 request outcome by calling the existing durable request transition authority only once. Do not add a new recovery/reconciliation API. The active request should terminalize as failed/interrupted according to SH07's registered lifecycle contract; if that contract is still absent, leave a TODO note and test the session-side orphan event only.

8. Add tests before broad integration:
- fake owned child exits mid-turn -> active to closing/failed once, one orphan event, owner finally releases lock/slot once.
- unknown process state -> no orphan event, no kill, no state change.
- external process -> no signal/kill.
- pid reuse/stale identity -> conservative no-action.
- silence timeout -> no orphan event.
- force-close deadline uses only owned descendant cleanup seam.
- pending next turn fails/unblocks without deadlock after owner cleanup.

9. Docker validation is required before AS26 completion: real owned process tree dies mid-turn, no descendant remains after force-close deadline, and an external process fixture is not signalled.
