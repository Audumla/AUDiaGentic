# Expose capability-gated external session controls

## Goal

Expose validated AS19/AS29 generic Interaction Session controls through the shared gateway application/client/MCP surface without provider-native commands, provider-name branches, or a second lifecycle/control authority.

## AS59 alignment and precedence

Disposition: keep/amend  
Authority: AS59

- AS58 remains the sole protocol-neutral public/application control authority for Interaction Sessions and turns.
- AS65 external ACP and AS66 A2A/harness delegation must call AS58/application services; they cannot invoke provider transports or native control adapters directly.
- AS58 is not an ACP server, A2A server, delegation router or provider-specific control registry.
- AS19 defines control actions/dispositions; AS29 defines exact validated support; AS30 authorizes binding/generation/ownership; AS21 determines lifecycle/reuse effects.
- A control acknowledgement never terminalizes a task/turn, marks a session reusable, releases a queue slot or fabricates output.
- During AS63 migration, existing request IDs initially serve as AgentTask IDs. Control idempotency remains bound to the canonical AUDiaGentic session/turn/action identity.
- External ACP context/session IDs, A2A task/context IDs and harness delegation IDs are secondary mappings and cannot authorize a control by themselves.
- Agent delegation operations (`agents_find`, `agents_delegate`, task result/status) belong to AS66 AgentTaskService and are not session controls. Only cancel of an already-mapped task/turn may translate into an AS58 canonical control.
- No implementation under AS58 proceeds before AS59 Gate 0 confirms there is no competing external control, ACP passthrough or delegation-control plan.

## Dependencies

- AS19 typed control actions, idempotency, and dispositions;
- AS29 immutable generic capability snapshot and handler registration;
- AS30 binding/project/execution/composition context and ownership authorization;
- AS21 terminal/reuse authority;
- validated provider handlers such as Pi RPC or Codex App Server adapters;
- AS57 read surface for clients that need to observe results;
- AS63 compatibility mapping for AgentTask/request identity;
- AS65/AS66 as protocol adapters after this service is stable.

## Discoverable capability snapshot

Expose a redacted per-session capability view derived from the frozen AS29/AS30 snapshot and any AS64 restrictions. Include generic family/action, supported/unsupported state, maturity/evidence level, bounded constraints, and ownership/topology limits. Exclude adapter refs, commands, config paths, raw native names, provider refs, tokens, Role internals, Agent Definition internals, Agent Card metadata, and unvalidated candidate actions.

Capabilities do not change during a session generation. A stale client snapshot cannot force an unsupported action; dispatch revalidates against the binding's frozen snapshot.

## External request contract

Define typed requests for only accepted generic actions, initially as proven:

- cancel turn;
- interrupt turn;
- steer turn;
- respond to correlated permission;
- close/detach Interaction Session;
- queued follow-up where independently implemented and validated;
- optional state/inspection reads remain AS57 read operations, not controls.

Each request includes canonical project/session/generation/turn/request-or-task identity, client control ID, action, and closed bounded payload. No native command/payload escape hatch.

Do not add raw A2A operations, agent discovery/delegation, Agent Card selection, provider session refs, ACP-native method names or arbitrary plugin payloads.

## Authorization and topology

Validate:

- authenticated active gateway client lease or authorized internal caller;
- canonical project root;
- exact AS30 Interaction Session generation/binding;
- exact frozen execution/composition context where required;
- requested turn/current-turn relationship;
- ownership mode and whether action is legal for owned/adopted/external topology;
- exact frozen AS29 capability and validated provider handler;
- outstanding correlated permission request where applicable;
- payload size/type and policy.

Cross-project, stale generation, wrong binding, changed composition, provider-ref guessing, protocol-ID-only authorization, and unauthorized external attachment controls fail before provider dispatch.

## Dispatch and idempotency

Use one agents application service that dispatches typed action through `providers_api`/the authoritative live transport. Persist or index idempotency by `(binding/session generation, turn, action, client-control-id)` using existing durable request/idempotency primitives if restart semantics require it.

Return canonical accepted, unsupported, already-terminal, rejected, uncertain, and authorization/conflict errors. Repeated requests return the original result. Do not retry uncertain provider submissions automatically.

Protocol adapters translate their requests into this closed contract:

```text
external ACP cancel/permission/close -> AS58 canonical action
A2A task cancel -> resolve mapped AgentTask/turn -> AS58 cancel when applicable
harness agents_cancel -> resolve AgentTask -> AS58 cancel when currently executing
```

No adapter may bypass task/session mapping or directly call an underlying ACP/RPC/App Server method.

## Lifecycle and audit

A control result is an acknowledgement only. It cannot terminalize durable request/AgentTask or Interaction Session state, release locks/queue slots, mark session reusable, or fabricate output. Subsequent AS19 evidence and durable authorities determine effects.

Record bounded redacted audit/timeline facts: AUDiaGentic IDs, generic action, disposition, timestamp, actor/client lease ID, policy/authorization result, and stable error code. Never record native command/payload, raw provider ref, permission secret, steering/follow-up content beyond existing protected request policy, raw Agent Card, raw A2A message, or provider raw response.

## Provider rollout

Start with fake transports and independently validated provider surfaces. Enable real actions only after exact AS29 version/platform probes. No adapter is selected by provider name in agents; AS29 factory/handler registration controls dispatch.

Native harness subagent controls do not become AS58 controls merely because the harness supports them. AS66 handles delegation through AgentTaskService.

## Service/client/MCP parity

Add matching closed operations to gateway application, service transport, client, and MCP schemas. All surfaces return the same canonical result and authorization behavior. A capability read may show unsupported actions, but invoking one returns explicit unsupported without side effect.

The MCP control surface is for operating an existing canonical task/session. The separate AS66 delegation MCP surface creates/queries AgentTasks and must reuse AS58 for cancellation rather than duplicating it.

## Validation

- capability snapshot redaction/immutability;
- authorized accepted action through fake transport;
- unsupported, already-terminal, rejected, uncertain, malformed, stale, changed-composition and unauthorized cases;
- cross-project/binding/generation/turn rejection;
- protocol-ID-only authorization rejection;
- idempotent duplicate and restart behavior;
- permission correlation/default-deny;
- owned/adopted/external close/detach semantics;
- topology/loopback policy;
- API/client/service/MCP parity;
- external ACP, A2A cancel and harness cancel map to the same canonical control decision;
- acknowledgement never changes lifecycle or releases work;
- no provider-native values above adapters;
- delegation tool calls cannot enter provider control handlers directly;
- real actions enabled only after exact platform/version probe.

## Acceptance criteria

- External clients discover and invoke only generic validated actions.
- One authoritative transport/provider handler executes each control.
- Unsupported actions fail explicitly without fallback.
- Audit is bounded/redacted.
- Controls remain separate from lifecycle evidence, terminal authority and AgentTask delegation.
- AS65/AS66 consume AS58 and create no protocol-specific control authority.
