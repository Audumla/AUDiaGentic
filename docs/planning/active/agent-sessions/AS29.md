## Goal

Provide one provider-owned, exact surface/version/platform manifest and resolver for identity, transport, controls, lifecycle observation, content, generic management capabilities, and validation. It is the sole session-surface declaration and resolution work item.

## Sole Declaration Owner

Extend the existing typed `ProviderDescriptor`/loader/spec path with exactly one `session_surfaces` list keyed by `(surface_id, version_constraint)`. Do not add parallel `session_control_surfaces`, `harness_status_observers`, runtime YAML registries, documentation scanners, or generic capability dispatch registries.

A session-surface entry contains typed sections for:

- transport factory registration;
- identity/mapping operations;
- ownership and ref scope/namespace;
- generic controls;
- lifecycle observation source, installation, correlation, ordering, and effective level;
- user-content channels and bounds;
- generic external-management capability families;
- exact platform/version validation evidence.

Native commands, config paths, adapter refs, tokens, raw event names, payload samples, and secrets remain provider-private and are absent from the resolved snapshot.

## Foundation Value Model

Define or consolidate frozen provider-neutral types such as:

- `SessionSurfaceRef(provider_id, surface_id, resolved_version, platform)`;
- `ResolvedSessionSurface`;
- identity operations: open, attach-existing, resume-by-ref, discover;
- mapping facts: returns opaque ref, concurrent attachments, attach while active, share, replacement relation, same project/context requirements, identity-context requirements, ref scope/namespace;
- ownership modes: owned, adopted, external;
- control support for AS19 canonical actions;
- lifecycle source: transport, hook, plugin, native-api, structured-output, none;
- installation: none, managed-hook, managed-plugin, structured-output;
- content channels: assistant text/final only where bounded and proven;
- validation: declared, probe-required, validated, blocked, unsupported;
- effective observability/capability maturity levels.

`REPLACED` is normally an AUDiaGentic relation implemented by explicit open-new, not an assumed native provider action. `share-existing` remains non-executable until a real consumer and probe exist.

## Generic Capability Families

Carry generic session management capabilities in the resolved surface as small typed family/action records. They may include state read, final-output read, cancel, interrupt, steer, permission response, follow-up enqueue, inspection, compaction/retry evidence, attach/resume/discovery, and close/detach semantics.

Rules:

- declaration and executable validation are separate;
- one provider may introduce a generic family when semantics are clear and unsupported behavior is explicit;
- agents dispatches typed family/action only and never branches on provider name;
- a declared candidate is not executable until exact adapter/probe validation passes;
- AS58 exposes selected capabilities externally; AS29 only declares/resolves them;
- a model feature, Role requirement, Agent skill or protocol publication option is not a session-surface capability;
- delegation-tool integration facts remain non-executable until AS66 defines and validates their consumer contract.

## Resolver

Implement/consolidate `providers/services/session_surface_resolution.py` and expose only `providers_api.resolve_session_surface(...)` plus transport preparation APIs.

Resolution must:

1. validate project/provider enablement;
2. read explicit configured surface selection from the AS60 Execution Profile snapshot or the provider's explicit declared default;
3. determine exact installed version and runtime platform using existing provider/foundation helpers;
4. select only an exact matching descriptor entry;
5. verify registered transport/observer/capability factories;
6. enforce validation/effective-level ceilings;
7. return an immutable redacted `ResolvedSessionSurface` snapshot;
8. return deterministic unsupported/misconfigured results without launching a child.

No installed-first selection, name similarity, alternate surface fallback, runtime surface switching, Role-based selector, Agent-skill selector, or provider-specific branch in agents is allowed.

## Pi Selection

Pi RPC and Pi ACP are independent entries and factories. The AS60 Execution Profile selects exactly one for a new session. The resolved choice and capability snapshot are persisted by AS30 and remain frozen for the generation. Configuration changes affect future sessions only. Neither surface becomes default merely because its executable is installed, and neither inherits capabilities from the other.

## Validation And Evidence Rules

- Product-supported platforms and locally validated platform evidence are distinct.
- A surface is publisher/executor eligible only for the current platform when exact version/mode/correlation proof is validated.
- Linux Docker evidence cannot promote Windows support and vice versa.
- Non-validated routes cannot claim effective O2+ lifecycle, content streaming, attach/resume, or advanced controls.
- Content channels require explicit byte/event bounds.
- Duplicate surface/version, invalid enum/control combinations, missing factories, and incompatible declared/effective levels are schema/loader errors.
- Legacy mixed OpenCode ACP/CLI facts must be split into exact separate surfaces; ACP resume and CLI `run --session` are not one route.
- Native subagent support, MCP support, plugin support or extension support does not imply A2A support.
- A2A publication is allowed only after AS64/AS66 project the validated effective capability subset for an Agent Definition.

## Migration

Migrate AS19 observer lookup, AS19 transport preparation, AS30 bindings, AS31 content, provider configurations and AS60 surface selection to the frozen snapshot. Temporary internal readers may translate old fields for one implementation window; no new writer emits old fields. Delete superseded descriptor fields after all callers migrate.

Internal traffic uses frozen dataclasses. Do not add a standalone JSON schema unless an actual external serialized contract requires it. Public diagnostics, if needed, use an explicit allow-list and exclude factories/native details.

## Acceptance Criteria

- `session_surfaces` is the sole runtime declaration owner.
- Exactly one immutable surface/capability snapshot is resolved before execution.
- Capability truth is surface/version/platform specific.
- Pi ACP and Pi RPC coexist without dual ownership or fallback.
- AS19, AS30, AS31, AS40/41, AS58 and AS60 consume the same snapshot.
- Shared agents/gateway code contains no provider-specific selector.
- Execution Profiles select; Roles require; Agent Definitions publish; none redefines AS29 truth.
- AS65/AS66 consume only redacted validated projections and create no parallel capability authority.
