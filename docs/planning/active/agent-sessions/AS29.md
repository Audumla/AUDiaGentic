# Publish one resolved provider session-surface capability manifest

## Description

Replace the separately planned session-control and status-observer declaration islands with one provider-owned, surface/version-specific manifest. The manifest declares identity, control, lifecycle observation, content streaming, installation, and validation separately; providers resolve it through providers_api and agents receives only a frozen, neutral snapshot.

## Steps

0. AS28 is the prerequisite; this item changes its descriptor shape before its provider factories are implemented. Create no global capability enum and do not load reference documentation at runtime.
1. Add neutral foundation value types in `foundation/transports/session_surface.py`, with no components imports:
```python
class SessionIdentityOperation(StrEnum):
    OPEN = "open"; ATTACH_EXISTING = "attach-existing"
    RESUME_BY_REF = "resume-by-ref"; DISCOVER = "discover"

@dataclass(frozen=True)
class SessionSurfaceRef:
    provider_id: str; surface_id: str; resolved_version: str

@dataclass(frozen=True)
class ResolvedSessionSurface:
    ref: SessionSurfaceRef
    identity: SessionIdentityCapabilities
    controls: Mapping[SessionControlAction, ControlSupport]
    lifecycle: LifecycleObservationCapabilities
    content: ContentStreamCapabilities
    validation: SurfaceValidation
```
`ResolvedSessionSurface` contains booleans/enums/scalar limits only—no callable, command, config path, raw protocol identifier, secret, or native payload.
2. Add provider descriptor dataclasses and loader/schema support for exactly one `session_surfaces` list keyed by `(surface_id, version_constraint)`. Each YAML entry has `transport_factory_ref`, `identity`, `controls`, `lifecycle`, `content`, and `validation`. `lifecycle.installation` is either `none`, `managed-hook`, `managed-plugin`, or `structured-output`; only its provider-local adapter ref may contain native mechanics. Replace AS28's planned `session_control_surfaces` and AS19's parallel surface lookup with references into this single entry; retain their specialized contracts/services.
3. Define strict schemas/enums: identity operations are `supported|unsupported`; ownership modes are `owned|adopted|external`; lifecycle source is `transport|hook|plugin|native-api|structured-output|none`; content channels are `assistant-text|assistant-final|tool-summary`; validation is `declared|probe-required|validated|blocked|unsupported`; effective observability is `O0|O1|O2|O3|O4`. Reject a non-`validated` route declaring effective O2+, a content channel with no byte/event bounds, duplicate surface/version, or an adapter ref with no registered provider factory.
4. Add `providers/contracts/session_surface.py` and `providers/services/session_surface_resolution.py`. `resolve_session_surface(project_root, provider_id, surface_hint)` probes/enforces provider enablement, obtains exact installed version, selects only an exact matching descriptor entry, validates its evidence tier and registered adapter, and returns `ResolvedSessionSurface`. A mismatch returns a stable unsupported snapshot; it must never pick a different surface by name similarity or documentation claim.
5. Expose only `providers_api.resolve_session_surface(...)` and make `prepare_provider_session_transport(...)` return `PreparedSessionTransport(transport, surface, effective_provider_ref)`. AS19 observer open/close and AS30 binding operations receive the same immutable `surface` snapshot rather than re-resolving separately. Agents never imports descriptor types, adapter modules, or protocol types.
6. Add `session-surface-capability.schema.json` for JSON-facing provider contract serialization and a generated redacted diagnostic payload. Do not expose factory refs, commands, managed IDs, tokens, output samples, or raw native names.
7. Migrate in order: descriptor/loader tests; resolver; AS28 OpenCode ACP surface; AS19 lifecycle adapter lookup; AS30 binding; AS31 content. Delete superseded descriptor fields only after every existing caller uses `session_surfaces`; temporary readers may translate old fields internally in providers for one migration release, but no new writer emits them.
8. Test descriptor invalid combinations, exact version selection, disabled provider, absent factory, validation/effective-level ceiling, immutability, no provider imports in agents, and two fake surfaces with identical provider but different controls/lifecycle/content proving no cross-surface bleed.
9. Implement the manifest as a typed extension of the existing `ProviderDescriptor`/loader/`PROVIDER_SPEC` path and resolve it through `descriptors.registry.get_descriptor` plus `providers_api`; do not add a runtime YAML registry, scan documentation registries, or create a generic capability dispatcher. Reuse `CapabilityEvidence` and `ProviderCapabilityFact` for provenance, but keep `session_surfaces` as the sole typed execution declaration.
10. Remove the proposed standalone `session-surface-capability.schema.json` unless a real external provider API needs serialization. Internal resolver traffic uses frozen dataclasses. If a public diagnostic mapping is needed, render an explicit allow-list from `ResolvedSessionSurface` through the existing providers API pattern; it cannot expose adapter refs/commands/native names.
11. Add platforms to each session_surfaces declaration/evidence record as normalized target triples (at least windows-amd64 and linux-amd64 where supported), each with tool version, probe artifact, validation state, and effective level. Resolver selects current runtime platform and returns unsupported when no validated platform entry exists; it never borrows Linux Docker proof for Windows. Platform detection stays in providers/foundation system helpers, never agents.

## Files

`foundation/transports/session_surface.py` (new); provider descriptor base/loader/schema/config; `providers/contracts/session_surface.py`; `providers/services/session_surface_resolution.py`; `providers/providers_api.py`; AS28/AS19 contracts/adapters/tests; JSON schema and architecture-boundary tests.

## Validation

A gateway receives one immutable resolved snapshot for a selected provider surface; it cannot observe adapter refs or native values. An unvalidated O3 candidate resolves with effective O0 and cannot enable lifecycle status, content streaming, attach/resume, or advanced control. An exact pinned validated fake surface can enable only its declared channels. No gateway module imports a provider descriptor or protocol type.

## Effort & Risk

Cross-cutting descriptor migration. Avoid generic execution/config blobs: the manifest is capability metadata only; provider-local factories and existing managed-hook/plugin families retain all native implementation.
