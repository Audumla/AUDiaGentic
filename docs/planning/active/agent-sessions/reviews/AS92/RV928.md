# Not a prerequisite for the read/control chain — downstream consumer, not infrastructure

## Notes

External adversarial review 2026-08-09, checking whether AS92 (S/basic, smallest in the chain) gates the others. It does not. AS92's snapshot_for_request() is a downstream public projection: it takes a durable request record plus an optional SessionLifecycleDecision and produces an AgentStatusSnapshot. AS93's upstream machinery is SessionEvidenceProjection.accept(), which receives correlated StatusEvidence and produces SessionLifecycleEvidence — it does not need AS92's projector to emit metadata events. The flow is: status/lifecycle evidence -> SessionEvidenceProjection -> (AS93 metadata stream | SessionLifecycleDecision -> AS92 snapshot). AS92 is therefore a sibling/downstream consumer of the lifecycle decision, not infrastructure beneath AS93.

## Conclusion

AS92 blocks none of AS87, AS93, AS94 or AS95 — record it as independent so the chain is not wrongly serialized behind it. No scope correction needed to the item itself. Still worth landing early as a scheduling preference (not an architectural dependency): it is small, known contract debt, and closes a real gap where agent-status is emitted publicly but absent from the declared/versioned schema. Explicitly do NOT add an AS94 -> AS92 dependency; AS94's current design does not require AgentStatusSnapshot in its status events and introducing that coupling would be gratuitous.
