# AS29 delegated manifest design audit

## Notes



## Findings

The audit identifies the existing ACP-only path (`providers_api.prepare_provider_acp_launch` -> dispatch -> `SessionRuntime.open_session`) and specifies one descriptor-owned `session_surfaces` manifest. It recommends frozen foundation-neutral types, provider resolver gating by exact version and current platform evidence, unvalidated surfaces projecting O0/unsupported behavior, and no external JSON schema until a real serialized contract exists. It correctly preserves RV716: no `session_control_surfaces`; AS28 targets AS29's manifest.

## Conclusion

Accepted as a detailed design baseline. Before implementation, reconcile naming with the existing AS30 `ResolvedSessionSurface`/`SessionMappingCapabilities` rather than duplicate types; stage AS28 neutral protocol types, then AS29 descriptor/resolver, then AS28 provider factories and gateway migration.
