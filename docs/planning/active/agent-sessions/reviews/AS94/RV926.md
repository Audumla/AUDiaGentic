# Delegate channel failure semantics rather than duplicating them; stale AS101 language; request/task id ambiguity

## Notes

External adversarial review 2026-08-09. Three findings. (1) Ownership duplication: AS94 step 4 lists 'a cursor whose generation, request, task or turn does not match'. Generation belongs to AS93's in-memory metadata source; if AS94 validates it independently, generation semantics exist in two places. Correct split is AS94 owns outer cursor syntax and context binding, AS93 owns metadata-source generation/retention semantics, AS87 owns output-source retention/corruption semantics — AS94 passes the embedded source position down and surfaces the source's own gap outcome. (2) Stale AS101 language: AS94's threat-model section still describes AS101 as the project-isolation owner, and an acceptance criterion still reads 'an authorized caller can observe a live turn' — both dangling after the AS101 rewrite and the recorded local/internal deployment decision. (3) Identity ambiguity: AS94 alternates between 'request' and 'task' ids; the gateway-facing API is request-ID based, so this may be manufacturing a second cursor identity from legacy wording.

## Findings



## Conclusion

Three edits. (1) Rewrite the cursor step so AS94 owns only outer syntax/context binding and delegates generation/retention to AS93 and truncation/corruption to AS87. (2) Replace 'authorized caller' with 'in-project caller' and delete the AS101 ownership narrative, stating the project-boundary rule directly. (3) Confirm whether request-id and task-id are genuinely two identities the cursor must bind; if not, normalize the plan to one canonical id. Also narrow Blocked-by conceptually: only AS87's paged-read half is a real prerequisite (see RV925), not its final-output selector.
