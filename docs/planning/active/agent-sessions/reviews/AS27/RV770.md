# Separate OpenCode platform support from local observability validation

## Findings

### 1. YAML claimed validation beyond proven platforms
The opencode.yaml `session_surfaces` for opencode-acp listed windows-amd64, darwin-arm64, and darwin-amd64 alongside linux-amd64 in the same platform group. The parent-level `validation_state` was DECLARED (not VALIDATED), but the structure implied cross-platform validation when linux-amd64 was the only locally proven platform.

### 2. No inventory gate in resolver
The session-surface resolver used YAML platform entries directly without cross-checking against the AS27 harness observability inventory. This meant descriptor YAML could claim O1+ validated status on platforms without local probe evidence, bypassing the inventory authority.

### 3. Rule 3b was too restrictive
The declaration validation rule (Rule 3b) required ALL platforms to be VALIDATED when the parent was VALIDATED. This prevented legitimate configurations where a surface is validated on some platforms but not others — which is exactly the case for opencode-acp (linux-amd64 proven, other platforms vendor-supported only).

## Conclusion

Implemented three changes:

1. **opencode.yaml**: Separated product support from local validation. Parent remains DECLARED/O1; linux-amd64 platform entry is VALIDATED/O1; windows-amd64, darwin-arm64, darwin-amd64 are DECLARED/O0. Added capability_facts entries for hinv-opencode-acp and hinv-opencode-cli-session.

2. **Session surface resolver inventory gate**: Added `_get_inventory_proof()` helper and step 7b that rejects VALIDATED/O1+ claims on platforms not in the AS27 inventory's `platform_evidence`. Unknown (provider, surface) pairs are NOT gated — only surfaces already in the inventory are checked.

3. **Rule 3b relaxed**: Changed from "ALL platforms must be validated" to "at least one platform must be validated" under a VALIDATED parent. This allows mixed platform states while still preventing empty validation claims.

Updated lifecycle documentation to explicitly distinguish vendor product support (windows/macOS/linux) from local observability validation evidence (linux-amd64 only for opencode-acp).

Added regression test file `test_as27_rv770_inventory_gate.py` with 5 test classes covering:
- Vendor cross-platform support alone does not make a surface publisher-eligible
- OpenCode Windows/Darwin local status publication is rejected until local probe
- YAML resolver cannot promote a platform absent from inventory evidence
- The locally proven platform preserves existing behavior
- YAML/inventory consistency for any validated O1 transport observation platform
