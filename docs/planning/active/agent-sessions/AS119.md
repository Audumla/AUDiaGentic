# Recover stale GPT-auto DOM without failing the active request

## Description

When a live ChatGPT conversation's DOM is stale, a same-conversation refresh can reveal the already-completed response. The gateway must reconcile that response within the original request instead of failing it and permanently blocking follow-up turns.

## Steps

- Handle GPT-auto correlation/observation conflicts as recoverable within the active turn.
- Perform one bounded refresh and stable reread of the canonical conversation without resubmitting.
- Persist the recovered full response and complete the original request when correlation is proven.
- Retain unresolved provider binding and expose explicit reconciliation-pending diagnostics when proof is still unavailable.
- Keep provider-terminal failures fail-closed and add regression coverage.

## Detailed Solution & Technical Design

Change gpt_auto turn observation so frozen-response-correlation-conflict and composer/action observation stalls enter a reconciliation phase. Reuse the retained canonical chat URL and existing refresh helper, then require unique prompt correlation, terminal evidence, and response stability before adopting the response. No new prompt may be sent. Persist observation-failure provenance separately from provider-terminal failure; normal continuation may perform at most one provider-authoritative recovery claim for that epoch. Preserve source session lineage and use the existing output artifact commit ordering.
