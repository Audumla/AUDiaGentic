# Supervise interactive ACP child trees through a narrow foundation seam

## Description

Replace the stale nonexistent ManagedProcess-registry design with the actual reusable requirement: foundation-owned OS process evidence and safe tree supervision for SDK-spawned interactive stdio children, while ACP retains connection/protocol lifecycle ownership. This supports hard failure cleanup and AS26 without using ManagedService records as session records.

## Steps

1. Define the minimal adopt/observe/stop contract for an already-spawned connected child, reusing ProcessEvidence, ownership matching, supervised_process, and kill_process_tree. 2. Keep SDK stdio/process context in AcpSessionTransport; adopt only OS lifetime evidence. 3. Define PID reuse refusal and owned versus external behavior. 4. Define hard-parent-death guarantees honestly per OS: shared supervisor/Job Object where available; no atexit-only claim. 5. Project neutral foundation process facts to existing agents session events in SessionRuntime. 6. Narrow architecture tests to prohibit direct OS signalling outside approved foundation seams, while allowing transport protocol shutdown.

## Files

Foundation system interactive-child supervision/evidence seam; ACP transport integration; agents projection; platform-specific unit/integration/Docker tests. No global registry, ManagedService record, or duplicate session store.

## Validation

Graceful close, transport exception, gateway SIGKILL/fake descendant, PID-reuse mismatch, and external ownership behave deterministically; Linux descendant cleanup and Windows Job Object behavior have platform-appropriate proof; ACP connected stdio remains functional; no duplicate lifecycle authority.

## Effort & Risk

Mid. Cross-platform hard-death guarantees are the risk; claims must match proven OS behavior.

## Standards

Architecture Standards; Architecture Guidelines; Observability Standards where events/timelines are involved; docs/reference/PROVIDER_CAPABILITY_REFERENCE. Reuse foundation paths, workflow, events, process evidence, and managed-service seams before adding component-local machinery.

## Notes

Rebased after RV656. register_managed_process/ManagedProcess.stop do not exist and are no longer the target. AS26 consumes this narrow evidence/stop seam.

RV681 CORRECTIVE SLICE IMPLEMENTED 2026-07-18 (claude): (1) Windows pid_alive no longer conflates ERROR_ACCESS_DENIED with dead — an unopenable-but-existing process reads as alive, closing the StartupLock stale-break steal hazard; (2) observe_process now populates all declared ownership comparisons the platform exposes (POSIX group_identity via getsid, Linux command_fingerprint via /proc cmdline) instead of creation identity only; (3) ACP children are adopted into a gateway-owned kill-on-close Job Object at AcpSessionTransport.open (new foundation adopt_pid_into_kill_job, refactored from supervised_process._assign_to_kill_job), so a hard-killed gateway no longer orphans agent trees on Windows; the handle is closed last in transport.close(); (4) SessionRuntime captures child pid + creation identity at open (handle fields + session.opened timeline attribute) so diagnostics/reaping have OS facts. REMAINING AS17 SCOPE: the formal adopt/observe/stop contract, PID-reuse refusal on stop, owned-vs-external behavior, POSIX hard-death honesty documentation, SessionRuntime projection of foundation process facts into session events, and the architecture tests prohibiting direct OS signalling outside foundation seams.

RV720 incorporated on 2026-07-19: the POSIX hard-parent-death acceptance must be made honest before implementation. An in-process adopter cannot guarantee child-tree death after the gateway is SIGKILLed on POSIX; process groups and atexit do not provide it. DECIDED (b): narrow the guarantee to graceful/exception cleanup plus identity-safe next-start orphan reconciliation, explicitly stating that immediate descendant death after a hard gateway kill is NOT claimed on POSIX. The Linux Docker acceptance must test whichever choice is made, not the currently-unimplementable property. Related tests (shared with AS26): process-dead vs process-unobservable distinction; external processes never signaled; owner-task finalization releases lock/slot exactly once.

IMPLEMENTED 2026-07-19 (pi): formal adopt/observe/stop contract in `foundation/system/adopted_process.py`. Provides `adopt_child()` (captures ProcessEvidence + Windows Job Object for hard-death guarantee), `observe_child()` (verifies continued ownership — detects PID reuse), `stop_child()` (terminates only when ownership holds; refuses external processes and PID-reused PIDs). AcpSessionTransport.open() now uses the formal contract instead of inline adoption. SessionRuntime projects foundation process facts (child-pid, child-creation-identity) into session.opened timeline and SESSION_OPENED_TOPIC events. Architecture boundary test added: `test_process_signal_boundaries.py` prohibits direct os.kill/taskkill/kill_process_tree outside foundation/system/.
