# Deliver managed, model-faithful Codex live sessions through codex-acp

## Description

Complete Codex ACP live-session support using the existing provider-neutral ACP/session seam and landed SH04 gateway. Make the bridge a managed provider runtime dependency, ensure requested/effective model identity is honest, and prove real lifecycle behavior. No gateway transport changes or one-off generic installer abstraction.

## Steps

1. Keep the existing launch builder but route it through the approved providers_api seam. 2. Reuse existing provider CLI lifecycle, toolchain recipe/probe, and foundation SequenceStep to install/reconcile the Codex CLI plus bridge; introduce a narrower provider-owned dependency declaration only if reuse cannot express the verified lifecycle. 3. Production dispatch must use the managed executable or fail stably; implicit npx -y network installation is explicit dev/test fallback only. 4. Empirically prove bridge model forwarding; apply model_id or reject mismatches before recording an effective model. 5. Reconcile ACP resume claims using the installed bridge/version. 6. Prove permission default-deny, cancellation, two-turn memory, clean close/tree cleanup, cold start, and submitter disconnect through SH04.

## Files

Codex provider adapter/config/README, existing provider lifecycle and providers_api seams, focused unit/integration/Docker tests. No new gateway/session transport.

## Validation

Clean Docker apply installs both executables; missing bridge is detected separately; offline post-install session works; reinstall is idempotent; prune removes owned packages and preserves unrelated npm packages; requested model is applied or rejected; fake/real bridge process trees close cleanly. Credentialed remember/recall remains opt-in and secrets never persist.

## Effort & Risk

Mid. Main risks are unmanaged runtime mutation, dishonest model reporting, and upstream bridge/version behavior.

## Standards

Architecture Standards; Architecture Guidelines; Observability Standards where events/timelines are involved; docs/reference/PROVIDER_CAPABILITY_REFERENCE. Reuse foundation paths, workflow, events, process evidence, and managed-service seams before adding component-local machinery.
