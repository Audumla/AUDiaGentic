# Codex live-session support via codex-acp (stdio ACP bridge)

## Description

Opt the codex provider into gateway live sessions through the existing AS04 capability seam. Codex has no native --acp mode; the official bridge is @agentclientprotocol/codex-acp (ACP server over stdio driving Codex App Server underneath). Because the seam is provider-neutral, the entire integration is one launch-builder module — no gateway, runtime, or transport changes.

OPEN — managed install (sponsor question 2026-07-16): codex's CLI itself is managed via config/providers/codex.yaml cli_install (npm @openai/codex), but codex-acp is NOT — the npx fallback is an unmanaged ad-hoc runtime install (acceptable for e2e, against install doctrine for production). The descriptor model supports exactly one cli_install per provider; add an auxiliary-install extension (e.g. aux_installs: [CliInstallRecipe] on the descriptor, consumed by the same npm toolchain provisioning/reconcile path) and declare {toolchain: npm, package: '@agentclientprotocol/codex-acp', executable: codex-acp} for codex. Once provisioned, the local-binary branch in build_acp_launch becomes the normal path and npx stays as last-resort fallback.

5. OPEN — npx cold-start latency vs the 120s transport open timeout; recommend managed install (step 2) in provider docs.
