# Assistant output relay: coalescing, caps and delivery state

## Description

Provide the production live assistant-output relay required by AS94: provider output flows through one gateway-owned, request-scoped bounded OutputStore with durable ordering, caps, recovery, and final-response deduplication. Public projection remains owned by AS94 and AS102; this item does not add a second public response API or lifecycle classifier.

## Steps

1. Wire the existing output sink through real stateless and session turns.
2. Persist bounded request-owned output deltas with durable ordinals and restart recovery in one OutputStore.
3. Deduplicate deltas against the authoritative final-response artifact and expose typed paged read/source state for AS94.
4. Add cap, coalescing, crash/restart, duplicate-final, and provider/session integration tests.
5. Keep public sanitization and response projection at AS102/AS94; do not create another output authority.

## Detailed Solution & Technical Design

OutputRelay owns authorization, coalescing, caps, and lifecycle. OutputStore exclusively owns paths, locking, event/index serialization, recovery, and reads. Crash protocol: reconcile numeric ordinals, write the next event atomically, then write the advanced index atomically. Recovery adopts a valid event beyond the index exactly once; conflicting ordinals are registered corruption errors. Numeric parsing/fixed-width names prevent 10-before-2. Source sequence is metadata and may be absent. Delivery states distinguish open, closed, truncated, degraded; validation rejection is not degradation.

## Code Samples & Guidance

Define AgentOutputSink.emit(event). Session prompt receives observation_sink and output_sink separately. StoredOutputEvent carries internal ordinal plus optional source_sequence_start/end. Gateway owns relay context and awaits close in finally.

## Files

agents gateway/output.py; new gateway/output_store.py or focused package; gateway dispatch/session runtime; foundation agent_output/session protocols; ACP and GPT-auto producers; agents output event/index schemas and strict config; unit/integration/recovery tests; AS87 seam.

## Validation

Production gateway turn persists assistant output without test-only append. Thought/tool/diagnostic content cannot enter sink. Ordering handles 2/10 and sequence=None. Crash after event write recovers once. Close/timer/caps flush under fake time. Index includes current event and correct truncation/degradation. Strict config rejects string truthiness. Architecture test proves one writer/reader authority.

## Effort & Risk

Large advanced cross-layer work. Privacy leakage and crash consistency are primary risks.

## Standards

Typed least-privilege channels; one persistence authority; bounded memory/time; explicit degraded state; deterministic recovery; strict config; component-owned contracts.

## Acceptance Criteria

- A production provider/session turn sends assistant output through the gateway-created relay; no test-only append path is required.
- Observation, assistant output, thought/tool content, and diagnostics remain separate; unauthorized content cannot enter the relay.
- One OutputStore is the sole writer, reader, index, and recovery authority.
- Coalescing flushes by size/time/boundary/close and preserves optional source sequence ranges.
- Event ordinals are durable and numeric; crash after event write is adopted exactly once and corrupt/missing data reports a gap.
- Count/byte caps persist truncated state; storage failure persists degraded state without terminalizing execution; rejected input is not degradation.
- Strict config and fake-time tests cover wiring, ordering, recovery, caps, close, and faults.
