# Assistant output relay: coalescing, caps and delivery state

## Description

Finish the live assistant-content relay so it bounds what it stores and survives a crash. `OutputRelay` (`gateway/output.py`) already exists and is real — per-turn registration, sequence monotonicity, fragment/turn byte caps, atomic per-event persistence, degrade-on-failure. Three mechanisms are missing.

This item is mechanism only: coalescing, caps, recovery. Channel authorization and content redaction are excluded and owned later.

## Steps

1. Add coalescing to `OutputRelay` — by max bytes, short flush interval, and final/turn boundary. Today every delta persists as its own event, which is what makes an event-count cap necessary.
2. Add the `max_events` cap alongside coalescing (the two are one change — a cap without coalescing just truncates a normal turn).
3. Add delivery state (`active|closed|degraded`) to `index.json`, and the reopen path: under the same lock, adopt contiguous valid event files beyond the indexed last sequence exactly once; mark degraded/gap when an indexed file is missing or corrupt; never silently skip or rewrite history.
4. Write the `OutputRelay` test suite. There are currently zero tests for `gateway/output.py` — `test_agent_output_contract.py` covers the foundation `AgentOutputEvent` type, not the relay.

## Validation

- Coalescing by size, by time, and at the final/turn boundary; source sequence range preserved across a coalesced event.
- Duplicate, out-of-order and oversize fragments rejected.
- Cumulative cap reached sets truncated and rejects later deltas without deleting earlier content.
- Concurrent requests isolated.
- Storage failure degrades the turn's content delivery without failing, cancelling or terminalizing provider execution.
- Crash after an event write but before the index advances adopts that event exactly once on reopen.
- An indexed but missing or corrupt event reports a gap rather than silently skipping.

## Acceptance Criteria

- Provider deltas coalesce by size, by time, and at the final/turn boundary, with the source sequence range preserved.
- Event count and cumulative byte caps both hold; reaching a cap sets truncated and rejects later deltas without deleting earlier content.
- A crash after an event write but before the index advances adopts that event exactly once on reopen.
- An indexed but missing or corrupt event reports a gap — history is never silently skipped or rewritten.
- Delivery state (`active|closed|degraded`) is recorded and readable.
- A storage failure degrades content delivery for the turn without failing, cancelling or terminalizing provider execution.
- `gateway/output.py` has a real test suite where it previously had none.
- It remains the sole content writer.

## Codebase Verification 2026 08 05

**Verified against the tree. Every premise in this item holds. Specifics for the implementer:**

**`OutputPolicy` (`gateway/output.py:56`) carries exactly three fields** — `enabled`, `max_fragment_bytes`, `max_turn_bytes` — matching the `agents.yaml` `gateway.output` block. There is no `max-events` and no flush-interval setting. Both need adding to the policy, its `from_config`, and the config block, in the same change as the coalescing logic.

**`_OutputIndexState` (`gateway/output.py:139`) carries** `seq-start`, `seq-end`, `total-bytes`, `event-count`, `is-truncated`. It has **no** `delivery-state`, **no** `contract-version`, **no** request/turn identity, and **no** gap/recovery metadata — all four of which this item's step 3 requires. Note `is_truncated` already exists on the dataclass but is only ever read/written through `to_dict`/`from_dict`; confirm it is actually set when a cap is hit, since that is one of this item's validation lines.

**No reopen or adopt-on-restart logic exists at all.** `_update_index()` (line 444) unconditionally overwrites `index.json` from in-memory state. `_OutputIndexState.from_dict` exists but has no caller that reconstructs state from disk on reopen. Step 3's "adopt contiguous valid event files beyond the indexed last sequence exactly once" is entirely unbuilt.

**Good news — the locking infrastructure is already there.** `_persist_event` (line 400) already wraps its writes in `with StartupLock(lock_path, timeout=10.0)`, and `_get_lock_path()` resolves a per-request lock. Step 3's "under the same lock" needs no new machinery; extend the existing critical section to cover the index advance.

**Confirmed: zero tests.** `tests/unit/agents/` has no `test_agents_gateway_output.py` or equivalent. `test_agent_output_contract.py` covers the foundation `AgentOutputEvent` type only, as this item states.
