# Implement the OpenCode ACP session-surface vertical slice

## Description

Deliver the first real, version-pinned implementation of AS28/AS29/AS19/AS21 for OpenCode ACP. This item proves only the declared lifecycle/control surface; assistant content streaming stays disabled unless AS31’s separate content policy and probe pass.

## Steps

0. Require AS28, AS29, AS19, and AS21. Pin the installed OpenCode binary version in the fixture before editing descriptor YAML. A mismatch exits as unsupported and writes no provider configuration.
1. Add `providers/adapters/opencode/session_control.py`. `build_transport(context, surface)` must invoke only the provider-local ACP launch builder, wrap raw ACP in `AcpAgentSessionTransport`, and translate raw frames to AS28 `TransportObservation`. It accepts no raw callback from agents.
2. Register the exact surface in `config/providers/opencode.yaml`:
```yaml
session_surfaces:
  - surface_id: opencode-acp
    version_constraint: "==<docker-probed-version>"
    transport_factory_ref: audiagentic.components.providers.adapters.opencode.session_control:build_transport
    identity: {open: supported, attach-existing: unsupported, resume-by-ref: <probe-result>, discover: unsupported, ownership_modes: [owned]}
    controls: {cancel-turn: cooperative, interrupt-turn: unsupported, steer-turn: unsupported, respond-permission: default-deny, close-session: supported}
    lifecycle: {source: transport, declared_level: O3, validation_state: validated, effective_level: O3, correlation: request-scoped, ordering: per-turn, installation: none}
    content: {channels: [], validation_state: probe-required}
```
Use actual probe values, never placeholders. Do not add hooks, plugins, MCP entries, environment token emitters, or config mutation.
3. Add `providers/adapters/opencode/status_observer.py`. Its lease maps only AS28 neutral kinds: `turn-accepted/activity→active`, `tool-requested→tool-active`, `tool-finished→tool-completed`, `permission-requested→awaiting-permission`, `terminal→terminal`, `transport-error/closed→unknown-or-failed` according to AS19’s canonical enum. It rejects missing turn correlation, duplicate/lower sequence, unknown kind, and undeclared status. It never reads ACP extension payloads.
4. Register provider-local factories in the AS29 resolver and AS19 observer resolver. `resolve_session_surface(..., "opencode-acp")` must return the fixed snapshot; `prepare_provider_session_transport` returns its transport plus that snapshot; `open_harness_status_observer` returns an attach-only lease with empty environment/managed IDs.
5. Write Docker probes: start `opencode acp --cwd <fixture>`, record `opencode --version`, initialize/open, run two correlated turns, induce a safe tool call and permission request where supported, request cancel, close, and capture the ordered redacted neutral observation trace. The probe asserts whether the protocol actually delivers every claimed lifecycle event; downgrade descriptor declared/effective level if it does not.
6. Add tests: exact version matching; provider disabled; no hooks/config writes; raw ACP→neutral mapping; neutral→StatusEvidence mapping; no raw extension access in observer; per-turn ordering/correlation; cancel acknowledgement does not terminalize; duplicate/late events; two-turn FIFO; child close; and AS21 state/decision projection. Add an AST rule forbidding `Acp*` imports under agents.
7. Do not enable AS31 content channels in this item. If the probe observes assistant text, record it in capability facts as a candidate only and create/execute AS31’s content-specific probe before YAML enables `assistant-text`.
8. Reuse `providers/adapters/opencode/acp.py:build_acp_launch` as the provider-local launch primitive and the existing `AcpSessionTransport` canonical/bounded callback semantics. AS32 adds only the AS28 composition adapter and AS19 neutral-observation mapper; it must not implement another OpenCode subprocess launcher, raw JSON-RPC parser, event buffering policy, permission policy, or child cleanup routine.
9. Existing ACP-level tests continue to test `AcpEvent`/raw mapping in foundation. New provider tests feed `TransportObservation` to the observer; new agents tests use a fake `AgentSessionTransport`. This preserves the architecture boundary while retaining existing ACP behavior characterization.
10. Add platform evidence to the OpenCode probe artifact. Windows direct runs managed executable/path launch, two-turn FIFO/cancel/close and Job Object/adopted-child cleanup through foundation tests. Linux Docker pins image/package digest, runs opencode acp in an isolated container, executes open/two-turn/tool/cancel/close, captures redacted trace, and verifies POSIX descendant death. Descriptor YAML lists only platforms whose own trace passes; unsupported platforms remain absent/O0.

## Files

OpenCode provider descriptor and adapters; AS28/AS29/AS19 provider registrations; Docker fixture/probe trace; focused providers/agents architecture and integration tests.

## Validation

The real pinned OpenCode ACP surface yields only neutral observations and validated canonical evidence. It writes no harness configuration and has no ACP imports in agents. A changed version/unsupported event set resolves to O0/unknown and no session decision advances. Output content remains disabled and absent from status/timelines.

## Effort & Risk

First end-to-end implementation validates the generic seams. Its actual observed event set is authoritative over the proposed YAML; no claimed O3 event may be retained if the Docker trace does not prove it.
