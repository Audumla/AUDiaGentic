# Preserve provider-cancelled output and failure evidence

## Description

A Codex/Luna provider can return stop_reason=cancelled after a tool execution fails, while the gateway records cancellation with no error or retrievable output. Distinguish explicit gateway cancellation from provider-side cancellation, preserve any assistant output as a verified response artifact, and expose a bounded canonical error/evidence record.

## Steps

- Capture provider-side cancellation provenance and bounded failed-tool evidence in the neutral ACP session result.
- Persist non-empty assistant output before terminalizing provider-cancelled requests.
- Map provider-side cancellation/tool failure to a canonical failed outcome while retaining explicit caller cancellation as cancelled.
- Add regression tests for output artifact delivery, error code, and explicit cancellation semantics.

## Detailed Solution & Technical Design

Extend SessionTurnResult metadata with bounded provider cancellation provenance and failed-tool count/identifiers. The ACP transport marks whether its cancellation signal was actually set and records failed tool-call IDs from ACP events. Session dispatch treats stop_reason=cancelled as caller cancellation only when the gateway/session cancel signal is proven; otherwise it creates an explicit provider-boundary AudiaGenticError, persists any final_summary through OutputStore, and transitions to failed. The full response operation remains the only response delivery surface and dereferences the request-owned artifact.
