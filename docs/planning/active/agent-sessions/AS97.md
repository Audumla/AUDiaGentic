# Prove OpenCode ACP permission, tool, cancel and rollback behaviour

## Description

Close the behavioural proof gaps for the OpenCode ACP surface. The transport works and is validated — `opencode-acp` is marked validated in the observability inventory with a real e2e anchor, and `build_acp_launch` has construction-level unit coverage. What that proves is a plain prompt round-trip and nothing beyond it.

Five specific behaviours have no coverage anywhere in the tree — confirmed by direct search of both the unit and e2e suites.

## Steps

1. Tool-call stimulus probe (KEEP): native OpenCode stimulus → existing ACP transport → canonical TOOL_REQUESTED/TOOL_FINISHED observation. No OpenCode-specific tool-call implementation. If a deterministic stimulus cannot be demonstrated, undeclare/mark `tool-calling` UNPROVEN.
2. Permission-request probe (narrow): does real OpenCode emit a permission request that maps to the declared `waiting-permission` status? Do not re-prove default-deny or the policy callback. If deterministic native stimulus cannot be obtained, remove/mark `waiting-permission` UNPROVEN.
3. Declaration audit (centre of gravity): retain only statuses actually observed by probes 1-2; remove/mark unproven claims; leave cancellation, permission response, failed-open rollback and content gating to their owning layers.
4. If OpenCode later gains cancellation support, prove only its adapter/wire translation then — do not reopen agent/session semantics in this item.
