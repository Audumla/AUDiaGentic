# Deliver managed model-faithful Codex ACP sessions through codex-acp

## AS59 disposition

Disposition: keep  
Authority: AS59  
Position: Platform track, position 10.

- Codex ACP is one exact AS29 surface; it is a separate identity from Codex CLI, App Server and TUI.
- Not blocked by AS59. Depends on AS52 for cleanup.

## Description

Implement Codex ACP as one exact AS29 surface using the existing `codex-acp` bridge, shared ACP transport, provider lifecycle recipes, and shared gateway. Make the bridge an explicitly managed provider dependency, verify that requested model identity reaches Codex unchanged, and prove real two-turn/control/cleanup behavior. Do not add a Codex-shaped agents path, gateway transport, or generic installer abstraction solely for this bridge.

## Dependencies

- AS19/AS21/AS29/AS30/AS31 foundation.
- Existing Codex provider descriptor/adapter and ACP launch builder.
- Existing provider CLI lifecycle, toolchain recipe/probe, package management, and `SequenceStep` seams.
- AS52/foundation child-process cleanup.

## Steps

1. Characterize the installed Codex CLI, `codex-acp` bridge, existing launch builder, package ownership, model arguments, ACP initialization, resume advertisement, and process tree.
2. Represent Codex CLI and bridge as separately probed managed dependencies using the existing provider lifecycle/toolchain machinery. Add a provider-owned dependency type only when the current typed recipe cannot represent the verified lifecycle; do not introduce a generic installer for one consumer.
3. `plan` and `status` perform no mutation. `apply` installs/reconciles the pinned owned dependencies. `prune` removes only AUDiaGentic-owned packages/config and preserves unrelated global packages.
4. Production launch resolves the managed executable paths and exact validated versions. It never runs implicit `npx -y`, auto-downloads from the network, searches an unapproved global install, or mutates packages at session start. Missing/mismatched dependencies fail with registered errors.
5. Register one AS29 `codex-acp` surface and provider-private transport factory through `providers_api`. Raw ACP remains private; agents receives only AS19 contracts.
6. Probe model fidelity by requesting two distinct supported model IDs and observing the effective model from authoritative bridge/Codex evidence. Apply the exact requested model or reject before execution; never record the requested value as effective without proof.
7. Probe identity/binding behavior: stable returned ref, two-turn memory, invalid ref handling, and native resume advertisement. Keep `resume_by_ref` disabled until exact bridge/runtime proof passes AS49 requirements.
8. Prove default-deny permission behavior, cancellation acknowledgement versus terminal evidence, two-turn FIFO, submitter disconnect, deterministic close, and owned process-tree cleanup.
9. Keep credentials opt-in and runtime-scoped. Never persist tokens, auth payloads, raw ACP frames, or provider refs in logs/config/evidence artifacts.
10. Add offline-after-install and idempotent apply/prune tests so a prepared environment can run without network package mutation.

## Files

- Codex provider descriptor and private ACP adapter/launch builder.
- Existing provider lifecycle/toolchain/package recipe and `providers_api` seams.
- Capability/probe evidence for exact bridge and CLI versions.
- Focused unit/integration tests and Linux Docker fixture; Windows direct tests where the surface is promoted.

## Validation

- clean apply installs/reconciles CLI and bridge separately;
- missing bridge is distinguished from missing Codex CLI;
- repeated apply is idempotent and prune preserves unrelated packages;
- post-install offline session opens and runs;
- requested model is actually applied and reported or request fails before dispatch;
- exact surface returns protected binding behavior and two-turn memory;
- permission default-deny, cancellation, disconnect, close, and tree cleanup pass;
- no implicit session-start network mutation;
- resume remains disabled without exact proof.

## Acceptance criteria

- Codex ACP launches only from managed validated dependencies.
- Production never performs implicit `npx -y` or equivalent network installation.
- Requested/effective model identity is honest and evidence-backed.
- Two-turn memory, permission default-deny, cancellation, submitter disconnect, and cleanup are proven for the exact versions.
- Codex details remain provider-private behind the canonical platform.

## Effort & Risk

Mid. Primary risks are unmanaged runtime mutation, dishonest model reporting, and bridge/version behavior changing independently of Codex CLI.

## Standards

Reuse the existing provider lifecycle, toolchain, package ownership, ACP, process, AS19/AS21/AS29/AS30/AS31, and `providers_api` seams. Exact version/platform probes control promotion.
