## Goal

Give AG full-fidelity `pi --mode rpc` observation evidence for sessions launched via the existing maintained `pi-acp` ACP wrapper, without spawning a second Pi process, without AG independently driving/commanding the session, and without modifying or forking `pi-acp` itself.

## Runtime Isolation

Reuse the existing per-request runtime root and isolation already implemented by `pi/acp.py::build_acp_launch` (unique `PI_CODING_AGENT_DIR`, `HOME`, session-dir, etc. under `request_runtime_root`). No separate Pi-specific runtime tree is created by this item. Add, within that same runtime root, a per-request Unix domain socket (POSIX) or named pipe (Windows) at a deterministic path that AG creates and listens on before launch. This is a duplex IPC endpoint, not a file being polled/tailed.

## Codec Process Layer

Implement a tee shim substituted at the existing `PI_ACP_PI_COMMAND` hook in `providers/adapters/pi/acp.py::_materialize_pi_command_wrapper` (today a transparent exec/passthrough `.cmd`/`.sh` script). The shim:

- spawns the real `pi --mode rpc` binary as its own child process (the one and only Pi process for this session);
- passes `pi-acp`'s stdin straight through to the real child's stdin, byte-for-byte, untouched -- `pi-acp` remains the single writer, so there is no command multiplexing and no request-ID correlation risk;
- fans out the real child's stdout to two sinks: (a) back to `pi-acp` unchanged, so its ACP behavior is provably identical to today, and (b) connected out to AG's per-request socket/named pipe, read-only;
- performs strict UTF-8 LF-delimited JSONL parsing only on the AG-bound copy (sink b) -- the pi-acp-bound copy (sink a) is raw passthrough and must never be transformed;
- applies maximum frame size and bounded parse errors on the AG-bound copy only;
- captures stderr as bounded diagnostics only;
- terminates deterministically when either the real Pi child exits or `pi-acp` closes its end, and its own exit must not be distinguishable by `pi-acp` from today's direct exec.

On the AG side, implement a private receiver in `providers/adapters/pi/rpc_tap.py` (or similar) that connects to the socket/pipe, applies the same strict JSONL codec, and treats the connection as read-only telemetry ingress. No raw frame publication outside the adapter.

## As19 Transport Implementation

This item does NOT implement an independent `AgentSessionTransport` (no open/prompt/control lifecycle of its own). Prompt, control (cancel/close), and session lifecycle continue to flow exclusively through the existing `AcpSessionTransport`/`pi-acp` path. This item implements only an observation ingestion component that layers additional `TransportObservation`s onto the same session the ACP transport already owns, sourced from the tapped RPC stream instead of (or in addition to) the ACP `sessionUpdate` frames. AS41 maps these into AS19 evidence as enrichment, not as a competing lifecycle authority. No hook/plugin/tap becomes a parallel prompt path.

## Binding And Capability Registration

After exact probes pass:

- extend the existing `pi-community-acp` AS29 surface's declared observation capability/evidence quality using tapped-RPC evidence, rather than registering a new `pi-rpc` surface;
- persist no additional session binding -- the tap rides on the binding already created for the `pi-acp`-driven session (AS30);
- leave unproven evidence kinds unsupported/effective O0 until validated per kind;
- do not claim RPC-derived control capabilities (cancel/steer/permission-response) beyond what `AcpAgentSessionTransport.control()` already proves -- the tap is observation-only.

## Cleanup And Recovery

Tie the shim's and the socket/pipe's lifetime to the same gateway session/request lifecycle already governing the `pi-acp` launch. Cleanup must run on:

- normal close (pi-acp session close cascades to shim exit);
- prompt cancellation;
- timeout;
- tap codec/protocol error (must not affect the underlying pi-acp session -- a tap failure degrades observation evidence, never terminates or corrupts the driven session);
- process crash (either the shim or the real Pi child);
- gateway/service shutdown;
- gateway restart discovery of abandoned runtime directories/sockets;
- failed shim installation before pi-acp launch (fall back to the existing transparent passthrough so the ACP session still launches without the tap, degraded to no enrichment).

Recovery must identity-check owned processes/sockets and remove or quarantine abandoned runtime directories deterministically. The tap must never become a single point of failure for the underlying ACP session.

## Required Concurrency Proof

Run two simultaneous Pi sessions (each launched via pi-acp with the tap installed) and prove:

- exactly one real `pi --mode rpc` process per session (never two);
- distinct runtime roots, sockets/pipes, and shim processes per session;
- no event/response cross-contamination between the two tapped streams;
- `pi-acp`'s own behavior (session outcome, ACP event stream received) is bit-for-bit identical whether or not the tap is installed;
- independent cleanup of each tap without affecting the other session.

## Acceptance Criteria

- Exactly one `pi --mode rpc` process exists per pi-acp-driven session; the tap never causes or requires a second Pi process.
- pi-acp's stdin remains single-writer; AG never issues commands into the tapped session.
- pi-acp's own ACP behavior is provably unaffected by the tap's presence.
- AG receives full native RPC event/response fidelity via a read-only, non-file-based (socket/named-pipe) channel.
- Tap failure degrades observation evidence only; it never terminates, corrupts, or duplicates the underlying ACP session.
- AS41 can map tapped RPC evidence as enrichment through shared AS19 contracts with no Pi branch in agents.
