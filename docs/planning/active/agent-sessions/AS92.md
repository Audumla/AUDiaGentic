# Canonical request status projection

## Description

Finish canonical provider-neutral lifecycle projection and its public contract. Mapping mostly exists, but rejected outcomes, schema ownership, duplicated attachment/time logic, and unrestricted metadata remain unresolved.

## Steps

1. Map durable rejected to AgentOutcome.REJECTED with exhaustive tests.
2. Replace local _now_iso with foundation.time.now_iso_z.
3. Consolidate session lookup and status attachment into one agents gateway function used by submit/get/wait/list.
4. Add an agents-owned public request/status response schema at response version 2; do not put derived agent-status in the private durable-record schema.
5. Define status snapshot fields explicitly.
6. Omit unrestricted metadata or route it through AS102's single allowlist.
7. Add tests proving all response paths share the projector and provider-native states never escape.

## Detailed Solution & Technical Design

Keep durable record, ephemeral runtime facts, and derived public response separate. One project_request_response function obtains runtime facts once, invokes the pure status projector, and applies AS102 metadata sanitization. The agents-owned schema references a reusable status definition and excludes raw exceptions, provider states, lane fields, and free-form metadata.

## Files

agents status projection module; gateway/api.py; store public projection helper; new agents public request/status schema; status/API contract tests; AS102 seam.

## Validation

Exhaustive state/outcome matrix includes rejected/cancelled/interrupted/failed/success. Submit/get/wait/list are structurally equivalent for same facts. Public and durable schemas validate independently; durable record has no derived status. Unknown/provider-native fields and unrestricted metadata are absent.

## Effort & Risk

Small size, medium public-contract risk. Avoid conflating durable/public schemas or duplicating metadata sanitizers.

## Standards

Provider-neutral public contracts; one projection authority; component ownership; reuse foundation time; unknown fields excluded.

## Acceptance Criteria

- The public request status carries one canonical provider-neutral snapshot.
- Every mapping is asserted, and the interrupted invariant holds — it never collapses into cancelled or failed.
- A durable terminal fact always beats a stale ephemeral decision.
- The durable store remains the single terminal authority; the adapter is pure and no second projector exists.
- The response schema incremented explicitly, and every in-repository consumer was migrated in the same change.
- Any retained legacy field renders from the same canonical snapshot, never from independent inference.
- The read path creates no runtime and mutates no state.

## Notes

RV907 incorporated. AS102 owns metadata allowlisting; AS92 must omit free-form metadata until that authority is used.

Remaining work is: declare the field in the appropriate response schema, increment the contract version explicitly, and add the serialization/compatibility tests.
