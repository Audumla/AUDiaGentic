# Add Claude harness completion and failure events to the gateway

## Description

Add a Claude harness plugin for the agents component that emits a request-owned event into the active gateway session when a request completes or fails, allowing the gateway to update lifecycle/activity state without relying on polling alone.

## Steps

- Define a neutral completion/failure event contract with request, session, turn, attempt, outcome, and bounded error fields.\n- Implement the Claude harness plugin hook and gateway event ingress.\n- Authenticate and correlate events to the active request/session; reject stale, foreign, duplicate, or out-of-order events.\n- Persist event evidence and use it to drive terminal transitions and activity lease updates.\n- Expose only slim public status while retaining protected diagnostics.

## Detailed Solution & Technical Design

Create a provider-neutral session event envelope carrying event-id, request-id, session-id, turn-id, attempt-epoch, sequence, event kind, emitted-at, and sanitized outcome/error code. The Claude harness adapter publishes completion or failure after its own provider result is final. Gateway ingress validates ownership and monotonic sequence, writes durable timeline evidence, and lets the request state machine perform exactly-once terminalization. A duplicate event is acknowledged idempotently; a mismatched session/request is rejected without mutating the active session.

## Code Samples & Guidance

{event:'request.completed', request_id, session_id, turn_id, attempt_epoch, sequence, outcome:'completed'}\n{event:'request.failed', request_id, session_id, turn_id, attempt_epoch, sequence, error:{code,reason}}
