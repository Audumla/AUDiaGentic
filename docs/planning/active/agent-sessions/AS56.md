# Wire the layered status snapshot into SH07 request-status projection

## Goal

Complete the public `execution-request` status projection using AS21 foundation status types and the existing SH07 durable request authority. It includes response-versioning and all in-repository consumer migration so no follow-on integration fragment is required.

## Required baseline inspection

Locate:

- the existing public/redacted SH07 request projection and read API;
- any already-landed `agents_status_projection.py:snapshot_for_request` implementation/tests;
- current wire schema/version and service/client/MCP consumers;
- AS21 `snapshot_from_decision` and runtime decision source.

Preserve and extend landed pure adapter behavior rather than creating another projector.

## Pure adapter

Implement/consolidate:

```python
snapshot_for_request(
    record: PublicRequestRecord,
    *,
    decision: SessionLifecycleDecision | None = None,
) -> AgentStatusSnapshot
```

Rules:

- SH07 durable completed -> terminal/success;
- failed -> terminal/failed;
- cancelled -> terminal/cancelled;
- interrupted -> terminal/interrupted, never cancelled/failed and never a separate lifecycle;
- queued -> pending;
- nonterminal + AS21 decision -> map through the canonical AS21 adapter;
- no durable terminal fact and no decision -> unknown/conservative;
- durable terminal fact always wins over stale ephemeral decision;
- read only public/redacted fields, never raw provider/binding/content fields.

## Public response integration

Increment the public execution-request response schema to its next explicit version and add one canonical `agent-status` field serialized from `AgentStatusSnapshot`.

Migrate every in-repository application/client/MCP consumer in this plan. Preserve the prior external response only behind the existing explicit schema/version negotiation path for one documented compatibility version; render any legacy status fields from the same canonical snapshot or durable record. Do not maintain a second projector, silently replace an unversioned field, or infer status independently in compatibility code.

The API/client/MCP read path remains side-effect free and must not create a runtime, acquire execution ownership, or mutate request/session state.

## Files

- existing AS21 status contracts/adapters;
- `agents_status_projection.py`;
- SH07 public projection/store/application/client/MCP schema as required;
- focused adapter, compatibility, serialization, and architecture tests.

## Validation

- completed/failed/cancelled/interrupted mappings;
- interrupted invariant;
- queued/running/unknown cases;
- durable terminal precedence over conflicting decision;
- cancellation acknowledgement remains nonterminal;
- exact response schema/version compatibility;
- all in-repository clients consume canonical projection;
- no provider-native fields or raw ref/content leakage;
- read creates no runtime and changes no lifecycle state.

## Acceptance criteria

- Public request status contains one canonical provider-neutral snapshot.
- SH07 remains the terminal authority.
- Legacy compatibility, if externally required, is versioned and rendered without a second projector.
- Adapter, wire-schema versioning, and all in-repository consumer integration are completed in this plan.
