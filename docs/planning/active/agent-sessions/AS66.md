# Add A2A and controlled agent delegation

## Goal

Publish selected Agent Definitions through A2A and let AUDiaGentic call trusted remote A2A agents through the same task service.

A2A is an adapter/transport, not another runtime or task engine.

## Service boundaries

Use two small ports:

- `AgentTaskService`: submit/read/cancel local agent work; AS63 owns it.
- `AgentDelegationService`: find/describe/delegate/status/result/cancel; chooses local task dispatch or remote A2A.

The A2A server and client are adapters wired to these ports. Harness extensions/MCP tools call `AgentDelegationService`, not A2A directly.

No service locator or global agent registry is introduced. Trusted remote agents may be supplied by existing configuration through an injected catalogue/source if needed.

## Initial A2A scope

- generate a basic Agent Card from Agent Definition identity and skills;
- accept a message/task and map it to AgentTask;
- expose status, final output and cancel using existing services;
- call explicitly configured trusted remote Agent Cards;
- use direct local dispatch for local agents;
- keep remote IDs separate from provider session refs.

Do not add broad discovery, push notifications, multiple transports or multi-turn task machinery until proven necessary.

## Harness delegation

Expose a small common tool surface:

- `agents_find`;
- `agents_delegate`;
- `agents_task_status`;
- `agents_task_result`;
- `agents_cancel`.

Integration order:

1. Pi extension, preserving its familiar subagent-style call where practical.
2. Shared MCP server for Claude Code, Codex and OpenCode.
3. OpenCode custom tool/plugin only if it materially improves the experience.

Delegation modes may be simple configuration values:

- `audiagentic-only`;
- `prefer-audiagentic`;
- `native-allowed`;
- `native-only`.

## Safety and limits

Start default-deny with explicit source/target permission, bounded task/context/artifacts, recursion depth, timeout and cancellation. Do not build a general policy engine; reuse current policy/configuration seams.

## Work

1. Implement local delegation through AgentTaskService first.
2. Add A2A Agent Card and server adapter.
3. Add trusted remote A2A client adapter.
4. Add the harness extension/MCP projection.
5. Prove implementer -> reviewer with one local case, then one remote case.
6. Reassess whether task-to-turn mapping remains sufficient.

## Do not add

- a separate A2A task store/runtime;
- raw A2A SDK use in harnesses or agents core;
- automatic internet-wide agent discovery;
- a new workflow engine;
- copied agent/profile/role snapshots;
- complex delegation graphs or budget frameworks.

## Acceptance criteria

- Local and remote agents use one delegation service.
- A2A is replaceable through a clear injected transport adapter.
- Harnesses can delegate to AUDiaGentic agents through extension/MCP tools.
- Existing gateway/session/output/control machinery is reused.
- The first implementation remains small and demonstrable.
