# Add only required capability checks

## Goal

Reject an Agent Definition before launch when its current Role or published interface requires a capability the selected harness surface or model does not provide.

AS29 remains the sole harness/session-surface capability authority.

## Design

Prefer a pure admission check over a new capability domain model.

Use:

- AS29 resolved surface facts;
- existing model metadata;
- simple Role requirements;
- Execution Profile restrictions.

Add model facts only for demonstrated current needs, initially text, vision, tool calling or context limit. Unknown means unsupported.

## Boundary

Keep composition and validation as pure functions unless model facts require I/O. When I/O is required, inject the existing model metadata source or one narrow source boundary. Do not create a capability service, registry, store, snapshot or public catalogue merely for naming consistency.

## Work

1. Inventory existing model and provider metadata.
2. Define the minimum Role requirement vocabulary used by real Roles.
3. Check surface/model support during Agent Definition admission.
4. Add only the ACP/A2A publication checks those adapters actually require.
5. Return a simple success/failure result; do not persist a capability object.
6. Add architecture tests proving AS29 facts are not copied or re-owned.

## Reassess before AS65

Delete unused facts and abstractions. If current Roles and interface publication need no model-specific checks beyond existing metadata, reduce or close this item rather than implementing a new layer.

## Acceptance criteria

- Unsupported requirements fail before launch.
- AS29 capability ownership remains singular.
- Model facts are minimal and evidence-backed.
- No capability registry, store, snapshot, service wrapper or compatibility path is introduced.
