# Add only required capability checks

## AS59 disposition

Disposition: keep  
Authority: AS59  
Position: Composition track, position 7 (last gated item).

- Admission-time capability checks only. AS29 remains the sole harness/session-surface capability authority.
- This item is explicitly a reassess-or-close item: if demonstrated Roles need no model-specific checks beyond existing metadata, reduce or close it rather than building a layer.

## Goal

Reject an Agent Definition before launch only when its demonstrated Role or published interface requires a capability the selected harness surface or model does not provide.

AS29 remains the sole harness/session-surface capability authority.

Tool/MCP/permission capability matching is out of scope. Each harness uses its existing configured/default tools and permissions.

## Design

Prefer a pure admission check over a new capability domain model.

Use:

- AS29 resolved surface facts;
- existing model metadata;
- simple Role requirements;
- Execution Profile restrictions.

Add model facts only for demonstrated current needs, such as text, vision or context limit. Unknown means unsupported.

Do not infer or normalize tool availability across harnesses.

## Boundary and composition

Keep composition and validation as pure functions unless model facts require I/O. Pure checks are called directly and are not registered as services.

When I/O is required, runtime/bootstrap supplies the existing model metadata source through the foundation composition graph and injects it into Agent Definition/AgentTask admission. Do not create a capability service, registry, store, snapshot or global lookup merely for DI consistency.

## Work

1. Inventory existing model and provider metadata.
2. Define only the Role requirement vocabulary used by real Roles.
3. Check surface/model support during Agent Definition admission.
4. Add only the ACP/A2A publication checks those adapters actually require.
5. Return a simple success/failure result; do not persist a capability object.
6. Inject any stateful model metadata source through foundation composition.
7. Add architecture tests proving AS29 facts are not copied or re-owned and pure checks do not depend on the composition framework.
8. Confirm no tool/MCP/permission policy or cross-harness tool abstraction is introduced.

## Reassess before AS65

Delete unused facts and abstractions. If current Roles and interface publication need no model-specific checks beyond existing metadata, reduce or close this item rather than implementing a new layer.

## Validation

This item may legitimately close as "not needed" — validate that outcome as
rigorously as an implementation.

- Inventory first: `grep -rn "capability" src/audiagentic/components/providers/services/session/`
  plus the Role requirement vocabulary from AS61. If no demonstrated Role needs a
  check beyond existing metadata, record that finding on this item and close it;
  the inventory *is* the deliverable in that case.
- If checks are needed: a test proves an unsupported demonstrated requirement
  fails **before launch**, with no child process spawned.
- A test proves AS29 facts are read, never copied or re-owned — assert the check
  holds no capability state of its own.
- Pure checks are callable without constructing the composition graph.
- `grep` confirms no capability registry, store, snapshot or service wrapper was
  introduced.
- `python -m pytest tests/unit` green.

## Acceptance criteria

- Unsupported demonstrated requirements fail before launch.
- AS29 capability ownership remains singular.
- Model facts are minimal and evidence-backed.
- Existing harness tool configuration remains untouched.
- Stateful metadata dependencies are injected through foundation composition only when required.
- No capability registry, store, snapshot, service wrapper or compatibility path is introduced.

## Standards

- `arch-standards` §3 Evidence-led scope — this is the governing standard for
  this item. Add model facts only for a demonstrated current need; if no
  demonstrated Role requires one, close the item rather than building a layer.
- `arch-standards` §3 Ownership and Abstraction — AS29 remains the sole
  capability authority. Facts are read, never copied or re-owned.
- `arch-standards` §1 Dependency Boundaries — pure checks are plain functions
  called directly, not registered services. Inject a stateful model-metadata
  source through composition only if I/O is genuinely required.
- `arch-standards` §4 Public Contracts — admission refusal is an
  `AudiaGenticError` with a stable code raised before any process is launched.
