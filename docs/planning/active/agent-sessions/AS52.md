# Complete identity-safe supervision for interactive session child processes

## AS59 disposition

Disposition: keep  
Authority: AS59  
Position: Platform track, position 6.

- Sole identity-safe process adopt/observe/stop seam. Foundation observes OS lifetime only; protocol ownership stays in the transport.
- Not blocked by AS59.
- Much of the baseline may already be landed -- characterize `foundation/system/adopted_process.py` and the existing architecture test before editing. AS53, AS50 and AS51 all consume this.

## Goal

Finish the narrow foundation-owned adopt/observe/stop behavior for SDK/transport-spawned interactive children while preserving protocol ownership in the transport. Do not create a global process registry or use managed-service records as session records.

## Existing baseline to preserve

The repository may already contain:

- improved process-liveness handling that distinguishes dead from unobservable/access-denied;
- process evidence including creation identity, POSIX session/group identity, and Linux command fingerprint where available;
- `foundation/system/adopted_process.py` with `adopt_child`, `observe_child`, and `stop_child`;
- Windows Job Object adoption for kill-on-parent-close;
- child PID/creation identity recorded on session handles/timeline;
- an architecture test prohibiting direct OS signalling outside foundation process modules.

Characterize these files/tests first. Do not reimplement already-landed behavior.

## Remaining scope

1. Confirm one canonical adopted-child contract and migrate any remaining inline adoption/stop callers.
2. Make stop identity-safe: refuse PID reuse, mismatched creation identity, unknown ownership, and external processes.
3. Define owned, adopted, and external behavior separately.
4. Keep ACP/RPC/App Server protocol close in transports; foundation only observes/stops OS lifetime.
5. Project bounded neutral process facts into existing session diagnostics/evidence without making process facts lifecycle authority.
6. Ensure every transport/session close path releases Job Object/process handles last and idempotently.
7. Document/prove OS guarantees honestly:
   - Windows: Job Object hard-parent-death only where tested;
   - POSIX: graceful/exception cleanup plus identity-safe next-start orphan reconciliation; no immediate descendant-death claim after gateway SIGKILL unless a real external supervisor is implemented.
8. Preserve the direct-signal architecture boundary.

## Files

- existing `foundation/system/adopted_process.py`, process evidence, supervised process/tree stop;
- AS19 protocol adapters and session runtime process projection;
- platform-specific unit/integration/Docker tests;
- no new registry, process store, generic daemon, or session record.

## Validation

- graceful close and transport exception;
- Windows gateway hard-kill/Job Object descendant cleanup;
- Linux/POSIX graceful cleanup and next-start orphan reconciliation;
- process dead vs unobservable;
- PID reuse/mismatched identity refusal;
- external process never signalled;
- owned/adopted stop only through foundation seam;
- protocol connection remains functional before close;
- no duplicate lifecycle authority;
- owner task finalization releases queue/locks exactly once.

## Acceptance criteria

- All interactive child signalling uses one identity-safe foundation seam.
- External and unproven processes are never signalled.
- Platform claims exactly match passing tests.
- AS53 can consume proven-dead ownership evidence without manually releasing locks or mutating queue sets.

## Standards

- `arch-standards` §3 Ownership and Abstraction — one identity-safe foundation
  seam owns adopt/observe/stop. No global process registry, and managed-service
  records are not session records.
- `arch-standards` §4 Public Contracts — refusals (PID reuse, unknown ownership,
  external process) are `AudiaGenticError` with stable codes; process command
  lines never reach logs or evidence.
- `arch-standards` §6 Platform and Provider Boundaries — protocol ownership
  stays in the transport; foundation observes OS lifetime only.
- `arch-standards` §7 Enforcement — the existing architecture test prohibiting
  direct OS signalling outside foundation process modules must stay green, and
  platform claims must match passing tests exactly.
