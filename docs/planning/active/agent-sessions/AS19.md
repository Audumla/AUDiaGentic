# Declare and reconcile surface-specific harness status-observer capabilities

## Description

Implement the provider-owned, surface/version-specific status-observer capability on top of AS28's provider-neutral session transport/control seam. The gateway obtains validated canonical status evidence without knowing ACP, harness hooks, plugins, config formats, or native status values. Providers declare and resolve the concrete surface; AS28 supplies neutral `TransportObservation` values and optional native control capabilities; AS19 adds observer configuration/ingress and converts observations into `StatusEvidence`; AS21 alone projects session/request decisions. OpenCode ACP is the first attach-only implementation, but ACP remains private to its adapter.

## Steps

0. AS28 is a hard prerequisite. Import the canonical execution-status enum and `AgentSessionTransport`/`TransportObservation` only from their neutral foundation contract. Do not add an agents↔providers enum dependency, an ACP type to any providers_api signature, or a second status enum.
1. Add typed descriptor support in `providers/descriptors/base.py` and `loader.py`: `HarnessStatusObserverCapability(surface_id, version_constraint, mechanism, supported_statuses, correlation_fields, event_ordering, evidence, adapter_ref)`, carried as `ProviderDescriptor.harness_status_observers`. `mechanism` is closed to `transport-observation`, `managed-hook`, `managed-plugin`, or `structured-output`; `adapter_ref` resolves a provider-local factory only. Validate duplicate `(surface_id, version_constraint)`, invalid canonical enum values, missing required correlation fields, and an adapter ref on every supported declaration. Add provider YAML only after a probe and retain `capability_facts` as the evidence link.
2. Add `providers/contracts/harness_status_observer.py` and matching JSON payload/result schemas. Define `HarnessStatusObserverRequest(project_root, provider_id, surface_id, session_id, request_id, correlation_id, accepted_statuses, binding_id)` and `HarnessStatusObserverResult(ok, supported, state, binding_id, launch_environment, managed_ids, removed_ids, error_code, action_needed)`. `state` is `ready|configured|unsupported|unknown|needs-action`; `launch_environment` is the only launch mutation visible to agents. Add `StatusEvidence(status, session_id, request_id, correlation_id, observed_at, sequence, source_kind, semantic_strength, verification_tier)` with no raw payload field.
3. Reuse the existing Hindsight-style provider mutation families for persistent observer installation. The AS19 resolver must choose a descriptor-declared route and call `providers_api.manage_hook_entries(...)` for managed hooks or `providers_api.manage_plugin_entry(...)` for a proven plugin; it must not create a parallel `harness-status-observers.json` registry or a duplicate writer. Use ownership scope `agents/status-observer/<provider-id>/<surface-id>` and entry IDs beginning `agents-status-observer-`; `plan`/`status` do not mutate, `apply` reconciles desired entries, and `prune` reconciles empty desired entries. Transport-observation and structured-output mechanisms write no provider config. A status observer must never use managed MCP as a fallback unless a probe proves an MCP notification-forwarding control surface.
4. Implement `providers/services/harness_status_observer_resolution.py` and `providers_api.open_harness_status_observer(...)` / `close_harness_status_observer(...)`. Resolution requires agents enabled, provider enabled, exact surface/version, registered observer adapter, and a successful existing-family reconciliation result when a persistent integration is needed. It returns an opaque `StatusObserverLease` containing `binding_id`, `launch_environment`, and `observe_transport(TransportObservation) -> StatusEvidence | None`. A mismatch returns `supported=False/state='unknown'`; it never selects a similarly named transport or protocol. `close` invalidates the binding only; lifecycle reconciliation owns persistent prune.
5. Materialize hook/plugin delivery in agents without making it a control channel. `agents_harness_status_observer.py` owns an in-memory loopback-only `ObserverIngress`, a random 256-bit token per `binding_id`, bounded request body/timeout, and bindings owned by `SessionRuntime`. `SessionRuntime` first receives AS28's `PreparedSessionTransport`, creates/registers its observer binding, calls `providers_api.open_harness_status_observer`, merges only `lease.launch_environment` through the prepared transport's sanctioned launch context, and invalidates the binding on every close/failure. Static provider-rendered hook/plugin commands invoke `python -m audiagentic.components.agents.harness_status_emitter`; it POSTs one bounded record `{provider-id, surface-id, binding-id, token, event-name, payload}`. Ingress validates token/binding/project/session and calls one providers_api normalizer. Raw payload is never persisted, published, or returned; a hook may observe only and cannot cancel/interrupt/steer a turn.
6. Add `providers_api.normalize_harness_status_observation(...)`, implemented by provider-local adapters. It receives either a neutral `TransportObservation` through `lease.observe_transport` or the validated raw ingress envelope and returns `StatusEvidence | None`. The adapter maps native event names/payloads, redacts, extracts sequence, and validates enum/correlation. Agents receives only `StatusEvidence`, publishes `agents.turn.status.observed`, and appends redacted `session.status.observed` timeline evidence. Neither publisher nor timeline transitions session/request state. Replace the current ACP-specific callback projector only by forwarding AS28 transport observations through this lease; preserve bounded delivery/callback isolation at the ACP adapter boundary.
7. Wire reconciliation using the Hindsight lifecycle pattern. An agents lifecycle observer calls `providers_api.reconcile_harness_status_observers(project_root)` on agents install/enable/config-change and calls it with `active=False` on disable/uninstall. After provider enablement changes, a provider-owned reconcile event triggers the same public operation for that provider. The reconciler discovers all/enabled providers through providers_api, applies declared persistent observer routes for enabled providers, and prunes all previously owned routes when agents/provider status becomes inactive. Before session launch, resolve again so a missed in-process lifecycle event cannot leave a live session without its declared observer.
8. Implement OpenCode first in `providers/adapters/opencode/status_observer.py` and `config/providers/opencode.yaml`: declare the proven `opencode-acp` surface/version with `mechanism: transport-observation`, register an adapter that maps AS28 `TransportObservation` values to `StatusEvidence`, and return empty environment/no managed IDs. Do not add `hooks_config`, a plugin entry, an ingress command, or a second raw ACP parser. The underlying ACP mapping stays in the AS28 OpenCode transport factory.
9. Add tests at each seam: descriptor validation; Hindsight-family hook/plugin apply/prune ownership/collision/foreign preservation; transport-observation no-write; agents/provider lifecycle enable-disable and missed-event preflight; token rejection, expired binding, wrong project/session, oversized body, duplicate/late sequence, and emitter failure; OpenCode neutral observation mapping/version mismatch/unknown observation; no `Acp*` import in agents observer/session logic; and AS21 consumer tests showing duplicate/unknown evidence has no terminal side effect. Docker is mandatory before an `execution` evidence tier.

## Detailed Solution & Technical Design

Next slice: add `agents_harness_status_evidence.py` as sole agents-side evidence sink. Accept StatusEvidence plus immutable session/request/turn correlation from SessionRuntime. Validate exact binding; reject None, stale/duplicate/lower sequence, unknown status, and observer exceptions. Persist only bounded scalar evidence through existing session timeline/store helper, then publish exactly one `agents.turn.status.observed` event using an owned topic constant. Sink returns accepted/rejected so observation stays best-effort. Never transition requests, mutate output, cancel, or project lifecycle. Tests: accepted activity, duplicate/lower sequence, mismatched correlation, no raw/native fields, exception isolation. Wire after lease.observe_transport in `_prompt`.

## Validation

No agents observer/session code imports or receives an `Acp*` type. Enabling agents plus an enabled declared provider uses existing Hindsight-style managed-hook/plugin ownership operations only where the provider declaration proves a persistent mechanism; disabling either prunes only those existing-family owned IDs; transport-observation routes make no config write. A session obtains a neutral prepared transport, creates an opaque observer binding, rejects unbound/forged emitter posts, publishes only canonical `StatusEvidence`, and invalidates the token on close. OpenCode ACP reaches AS19 only as neutral `TransportObservation`. A version mismatch, adapter/ingress failure, unknown observation, sequence gap, duplicate, or late terminal evidence remains conservative and cannot mutate SH07 or session state except through AS21.

## Effort & Risk

Complex but bounded by AS28. Main risks are duplicating Hindsight's installed-artifact ownership, ACP leakage through public observer types, unauthenticated ingress, and confusing observations with controls. Reusing managed hook/plugin public operations, foundation-only transport types, opaque per-session leases/tokens, and AS21-only projection are mandatory.

## Standards

Architecture Standards; Architecture Guidelines; Observability Standards where events/timelines are involved; docs/reference/PROVIDER_CAPABILITY_REFERENCE. Reuse foundation paths, workflow, events, process evidence, and managed-service seams before adding component-local machinery.
