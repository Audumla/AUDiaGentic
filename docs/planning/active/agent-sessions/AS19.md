# Establish canonical session transport, observation, and evidence contracts

## Goal

Create the one provider-neutral live-session transport/control contract and the one normalized status-evidence ingress used by every surface. Complete the migration away from ACP-shaped gateway/session APIs and preserve the already-landed transport-observation resolver slice without creating parallel registries or mappers.

## Scope and absorbed work

It owns:

- provider-neutral transport, prompt, result, observation, and control contracts;
- provider public transport-preparation contracts and composition registration;
- private ACP/native adapters that map provider frames to neutral observations;
- normalized `StatusEvidence`, observer leases, generic transport-observation mapping, and the sole agents-side evidence sink;
- architecture migration/deletion gates that prevent raw ACP/provider types above adapters.

Managed hook/plugin installation and the multi-harness probe matrix are completed by AS54, but they must use the contracts and ownership rules defined here.

## Required repository characterization

Before editing:

1. Locate existing `foundation/transports/agent_session.py`, ACP wrappers, provider preparation APIs, session runtime injections, cancellation maps, output extraction, observation sinks, and observer resolver/lease implementations.
2. Preserve any landed neutral-contract slices and tests; extend or migrate them instead of creating renamed duplicates.
3. Locate all direct `AcpEvent`, `AcpLaunch`, `AcpResult`, `AcpSessionTransport`, raw `.ext['acp']`, `on_event=`, `cancel_signal=`, and public ACP launch API use under agents.
4. Locate existing process supervision/adoption seams and use them; AS19 does not create a new process manager.

## Canonical foundation contracts

Define or consolidate under `foundation/transports/agent_session.py`:

```python
class SessionControlAction(StrEnum):
    CANCEL_TURN = "cancel-turn"
    INTERRUPT_TURN = "interrupt-turn"
    STEER_TURN = "steer-turn"
    RESPOND_PERMISSION = "respond-permission"
    CLOSE_SESSION = "close-session"

class ControlDisposition(StrEnum):
    ACCEPTED = "accepted"
    UNSUPPORTED = "unsupported"
    ALREADY_TERMINAL = "already-terminal"
    REJECTED = "rejected"
    UNCERTAIN = "uncertain"
```

The canonical contract must include frozen/provider-neutral forms of:

- `SessionPrompt` with AUDiaGentic turn/request identity, prompt body, deadline, and local cancellation token;
- `SessionOpenResult` and `SessionTurnResult` with bounded neutral results and no raw protocol payload;
- `SessionControlRequest` with AUDiaGentic session/turn/request identity, action, client idempotency ID, and a closed canonical payload;
- `SessionControlResult` with disposition, correlation result, and stable error code only;
- `TransportObservation` with neutral kind, AG/provider-safe correlation refs, sequence, observed time, correlation quality, and bounded scalar attributes;
- `AgentSessionTransport.open/prompt/control/close/is_alive`.

Neutral observation kinds are intentionally lower level than canonical status: turn accepted, activity, tool requested/finished, permission requested, terminal, transport error, and transport closed. No prompt text, assistant output, hidden reasoning, tool arguments/results, raw provider event name, arbitrary metadata, secrets, or native error object may appear.

## Provider preparation seam

Consolidate provider contracts and `providers_api` around:

- `PreparedSessionTransport` containing the transport, immutable resolved AS29 surface, and effective protected provider reference metadata;
- `prepare_provider_session_transport(...)` as the only agents-facing construction operation;
- provider-local registered factories selected by AS29;
- deterministic unsupported results before process launch when the exact surface/version/platform/factory is unavailable.

`prepare_provider_acp_launch`, `ProviderAcpLaunchResult`, provider launch builders, raw adapter imports, and ACP method names become provider-private. Retain `run_acp_prompt` only for genuine non-session one-shot callers.

## Private protocol adapters

ACP, Pi RPC, Codex App Server, native APIs, structured CLI, and process-only execution implement the same neutral transport protocol. Raw protocol parsing stays inside foundation/provider adapters.

The ACP wrapper must:

- delegate open/prompt/close to existing ACP mechanics;
- map bounded raw ACP events into neutral `TransportObservation` values;
- expose only controls actually proven for the exact surface;
- return `UNSUPPORTED` rather than emulate interrupt/steer/permission;
- preserve permission default-deny until correlated response support is proven;
- keep raw event extensions and provider IDs private.

## Control semantics

- Idempotency key: `(session-id, turn-id, action, client-control-id)`.
- Repeating an accepted request returns the original disposition.
- `UNSUPPORTED` changes no lifecycle state.
- `ALREADY_TERMINAL` is a successful no-op.
- `REJECTED` means a known request was refused.
- `UNCERTAIN` means submission may have occurred before transport loss and forces conservative reconciliation.
- A control acknowledgement never releases a queue slot, completes a turn, or terminalizes SH07/session state.
- Steering is append-only/exactly-once where native support is proven.
- Permission response requires a correlated outstanding permission request and a closed allow/deny payload.

## Status-observer and evidence seam

Define or consolidate frozen contracts for:

- `StatusObserverRequest` bound to project/provider/surface/session/request/turn/binding identity;
- `StatusObserverResult` and an opaque in-memory `StatusObserverLease`;
- `StatusEvidence` with canonical status, AG correlation, observed time, sequence, source kind, semantic strength, and verification tier;
- no raw payload field.

Use the AS29 resolved surface lifecycle declaration as the sole observer-mechanism source. Do not add `ProviderDescriptor.harness_status_observers` or a second runtime registry.

For `lifecycle.source=transport`, use one generic neutral `TransportObservation -> StatusEvidence | None` mapper constrained by the resolved surface. Do not create per-provider mappers for the same neutral vocabulary. Provider-specific normalizers are permitted only for raw hook/plugin/native envelopes that did not pass through the neutral transport.

Preserve the already-landed observer resolver/lease wiring as baseline. Generalize any hard-coded OpenCode-only route to AS29 surface facts when the resolver is ready; do not regress the existing best-effort observation threading.

## Agents evidence sink

Add or consolidate one agents-owned sink that:

- accepts only `StatusEvidence` plus immutable session/request/turn correlation;
- validates binding, project, session, request/turn identity, status vocabulary, ordering, duplicate/lower sequence, and observer exceptions;
- persists only bounded scalar evidence through the existing session timeline/store helper;
- publishes exactly one owned status-observed topic when accepted;
- returns accepted/rejected and remains best effort;
- never changes lifecycle state, output, cancellation, queue ownership, or request terminal state.

Preparation order is fixed:

1. resolve immutable AS29 surface;
2. open observer lease from that surface;
3. prepare transport with only the sanctioned observer launch context;
4. open transport;
5. persist AS30 binding and bind canonical correlation.

Do not mutate an already-prepared transport with later environment changes.

## Session runtime migration and deletion

Migrate `SessionRuntime` and dispatch in one compatibility window:

- replace ACP-shaped injected factories and results with `PreparedSessionTransport`, `AgentSessionTransport`, `SessionPrompt`, `SessionTurnResult`, and `ObservationSink`;
- rename event callbacks to observation sinks and consume only neutral kinds/attributes;
- remove raw ACP extension parsing and native event names from agent events;
- submit cancellation through canonical control requests; keep a local cancellation token only for timeout/owner cleanup;
- make dispatch consume AS31/final neutral output instead of reconstructing from ACP events;
- preserve FIFO locks, deadlines, queue accounting, request-to-turn mapping, timeline writes, and owner `finally` cleanup.

Delete obsolete public ACP session APIs, constructors, imports, callbacks, fakes, and fixtures after migration. Do not keep a second live-session path.

## Process boundary

Transport implementations reuse `foundation/system/process.py`, `supervised_process.py`, `adopted_process.py`, and existing tree-stop/Job Object mechanisms. Protocol close and OS stop remain distinct. Direct OS signalling outside approved foundation process modules is prohibited. AS52 completes any remaining adopted-child behavior.

## Validation

Required tests:

- fake ACP/native/process transport conformance;
- open/prompt/control/close parity;
- all control dispositions and idempotency;
- permission default-deny;
- bounded observation/redaction/correlation/order handling;
- observer lease success, unsupported, close/invalidation, exception isolation, duplicate/late evidence;
- session FIFO, timeout, cancellation race, transport crash, child death, and no double release;
- migration characterization for OpenCode open -> two turns -> output -> cancel -> close;
- unsupported surface creates no child/process;
- architecture/AST/grep gates preventing ACP/provider-native types and raw payload parsing in agents;
- no production importer of removed public ACP session launch/result APIs.

Docker evidence is required before any real surface is promoted beyond candidate/declared support, but the neutral contract itself uses fake conformance fixtures.

## Acceptance criteria

- One canonical transport/control/observation contract exists.
- One normalized evidence ingress and agents evidence sink exist.
- Agents contains no ACP/RPC/App Server/provider-native session type or raw protocol parser.
- Observers cannot control or transition lifecycle.
- Control acknowledgement cannot terminalize or release work.
- Provider factories are selected only through AS29 and `providers_api`.
- All old ACP-shaped session paths are deleted or explicitly retained only for non-session one-shot use.
- AS21, AS29, AS30, and AS31 can consume these contracts without provider-name branches.
