# Configurable GPT-auto refresh recovery from silence and interruption signals

## Description

Extend AS119 from a one-shot experimental probe into the production recovery workflow requested by the live BigCherry failures. A GPT-auto turn must refresh its existing conversation tab after four minutes without validated real activity, or immediately when a configured provider interruption signal is observed, initially the exact Connection interrupted message. Refresh must never resend the prompt.

## Steps

- Add provider configuration for real-activity silence threshold (default 240 seconds), maximum same-tab refresh attempts (default 3), and final grace after the last refresh (default 600 seconds).\n- Add a dedicated interruption DOM signal with exact text matching; keep generic error-alert as a separate terminal/error diagnostic.\n- Track last validated real activity, last refresh completion, refresh count, trigger reason, and per-attempt result.\n- Reset inactivity and recovery counters on validated request-owned assistant/user/tool activity.\n- Share one refresh primitive and one budget across silence, interruption, and correlation-recovery paths.\n- After the final grace expires, fail with bounded unresolved evidence; never create a new session or resubmit.

## Detailed Solution & Technical Design

Implement a response-observation state machine in turn.py. Real activity is a correlated message-id/text/count/tool change; generating/stop/busy/static snapshots are advisory only. At each poll, evaluate completion first, then interruption-triggered refresh, then silence-triggered refresh, then provisional failure. The refresh operation navigates the current page to the immutable conversation URL, waits for a fresh snapshot, and returns to observing. A trigger is edge/debounced so a persistent alert cannot consume all attempts in one loop. Completion after refresh wins over the prior interruption. Preserve the unresolved fence on exhaustion.
