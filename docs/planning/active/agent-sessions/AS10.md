# Build-out: resume-after-death via ACP session/load + provider-native resume fallback

## Description

Phase-2 durability: a session whose process died (or was reaped) can be resumed with its conversation context if the provider supports it. Two mechanisms, in preference order: (a) ACP loadSession — at initialize, check the agent's advertised capabilities; if loadSession is supported, a new child can connection.load_session(provider-session-ref) and continue; (b) provider-native resume — opencode persists sessions itself; `opencode run --session <id>` continues one via the one-shot CLI path (no live process needed). provider-session-ref persisted by AS03 is the anchor for both.

## Steps

1. Verify opencode's ACP initialize response capabilities (loadSession?) empirically on brutus; record findings on this item. 2. Transport: optional resume(provider_session_ref) on AcpSessionTransport gated on the advertised capability. 3. Runtime: reopen path for records in state expired/failed-orphaned when a session-id request arrives and policy allows (explicit 'resume: true' request field — never silent). 4. CLI fallback: opencode adapter run() already extracts session_id; add optional session pass-through arg. 5. Tests + live validation.
