# Explicitly resume a dead provider session as a new linked generation

## Description

Provide explicit resume-after-death only where both runtime protocol advertisement and verified provider capability evidence support it. Preserve terminal record meaning by creating a new AUDiaGentic session generation linked to the dead generation while reusing the provider session reference; never silently reactivate a terminal record or start a fresh conversation.

## Steps

1. Add an explicit resume request contract naming the prior session; absence means no resume. 2. Persist resumed-from-session-id/generation and preserve project/profile/SH02 context identity. 3. Retain and inspect ACP initialize capabilities; call loadSession only when advertised. 4. Require matching verified surface/version capability through providers_api; disagreement or missing evidence is conservative. 5. Route any provider-native CLI fallback through providers_api, never agents/foundation provider heuristics. 6. Return a registered unsupported/conflict error rather than silently creating new context. 7. Probe the installed OpenCode/Codex bridge versions and reconcile descriptor/reference claims before enabling either.

## Files

Foundation neutral ACP load-session support; agents request/session-generation policy; providers_api capability/CLI seam if proven; provider evidence/docs; unit and Docker tests.

## Validation

A fake ACP advertising loadSession resumes retained context into a new linked generation; missing capability and descriptor/runtime disagreement fail conservatively; project/profile/context mismatch is rejected; terminal source record remains terminal; no silent fresh session or child orphan. A real installed-version Docker probe is required before a provider is marked supported.

## Effort & Risk

Mid and evidence-gated. Risk is corrupting durable terminal semantics or claiming provider resume without proof.

## Standards

Architecture Standards; Architecture Guidelines; Observability Standards where events/timelines are involved; docs/reference/PROVIDER_CAPABILITY_REFERENCE. Reuse foundation paths, workflow, events, process evidence, and managed-service seams before adding component-local machinery.

## Notes

Rebased after RV651. Do not add terminal-to-active workflow transitions. AS13/AS14 provider probes may supply the evidence; until then support stays unknown/unsupported.
