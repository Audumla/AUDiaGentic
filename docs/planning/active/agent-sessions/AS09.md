# Build-out: remote channeling to active sessions (attach, live events, send)

## Description

Phase-2 sponsor goal: 'later I want to be able to channel communications remotely to active sessions'. Session-id (AS02/AS03) is the address. Deliver an attach surface: subscribe to a session's live event stream (the transport on_event callback fans out to attached observers) and send prompts into it from a remote client. Transport-agnostic design so non-coding applications can reuse it.

## Steps

1. Design: event fan-out (per-session bounded ring buffer + subscription cursor, reusing the transport's bounded-delivery budgets); auth/scoping story for remote callers; MCP streaming constraints (MCP tools are request/response — likely cursor-poll tool agent_llm_session_events(session_id, after_sequence) first, push later via AS08 supervisor). 2. Implement cursor-based event read. 3. Send-into-session = existing session-id request path (AS04) — verify multi-client serialization semantics. 4. Tests.

## Notes

Design constraint per RV518 (overseer R&D 2026-07-17): remote channeling must include a SAFE in-flight interaction primitive. Cancelling an awaited prompt() kills the transport by design, so 'bump a stalled turn' cannot be caller-side cancellation — it needs protocol-level cancel+continue, or provider-native injection (Codex App Server turn/steer, AS14). Same-session continuation after a terminal turn is verified and needs no new machinery. Also see RV517: channeling/control surfaces graduate into the agents component (summary/status reads, continuation/bump control), not a new component.
