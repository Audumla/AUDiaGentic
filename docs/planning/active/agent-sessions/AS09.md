# Add bounded redacted remote event polling for active sessions

## Description

Remote send into an existing session already uses the normal session-id submission path and SH04 service. Add only the missing transport-neutral observation capability: authenticated, project-scoped, cursor-based polling of a bounded redacted normalized session-event stream. Push transport and in-flight control are out of scope.

## Steps

1. Freeze the cursor token/sequence, maximum page size, retention, expiry, and deterministic gap response. 2. Consume corrected AS18 normalized events and existing EventEnvelope correlation metadata. 3. Keep the bounded buffer/cursor agents session-domain-owned; do not turn FileEventStore into a cursor platform for one consumer. 4. Add one SH04 closed operation/client/MCP read surface. 5. Return metadata-only redacted event projections; never prompt, output, tool arguments, raw protocol payloads, or secrets. 6. Verify existing remote session-id submission remains FIFO. 7. Keep cancel/steer/interrupt separate until protocol-specific semantics are proven.

## Files

Agents session event projection/cursor module, SH04 application/client/MCP operation, existing event constants, targeted tests. Avoid adding cursor branches to the session monolith where a cohesive module is clearer.

## Validation

A second standalone client polls ordered pages without duplicates, resumes from a cursor, receives a stable gap for expired history, cannot cross projects/contexts, sees no content-bearing fields, and can submit a later turn without violating FIFO. Mutable Docker uses a fake streaming ACP child across two processes.

## Effort & Risk

Mid. Main risks are cursor contract stability and accidental content disclosure.

## Standards

Architecture Standards; Architecture Guidelines; Observability Standards where events/timelines are involved; docs/reference/PROVIDER_CAPABILITY_REFERENCE. Reuse foundation paths, workflow, events, process evidence, and managed-service seams before adding component-local machinery.

## Notes

Rebased after RV650. Remote send is already present. Initial delivery is request/response polling only and depends on corrected/stable AS18 normalization.
