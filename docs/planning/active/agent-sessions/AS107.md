# Detach durable provider-session state from request retention

## Description

Define ownership, retention pins, relocation, and eventual release for durable provider/session state that may currently live under an opening request runtime directory. A request archive/purge must not destroy a resumable agent conversation merely because its local tab/process is gone.

## Steps

1. Inventory generic session resume dependencies on opening request IDs/runtime roots and provider-owned durable files.
2. Define provider-neutral retention-pin projection for session lineage, bindings, preserved runtime roots, and resume capability.
3. Expose a read-only `is_request_retention_pinned`/pin-reason contract consumed by SH24 purge.
4. Decide whether durable session state remains request-owned, relocates to session-owned storage, or is explicitly detached; migrate atomically with lineage preservation.
5. Define release/expiry policy independent of volatile handles/pages/processes.
6. Validate with generic session fake, ACP session provider, and gpt-auto durable chat resume.

## Detailed Solution & Technical Design

Volatile transport handles are not durable conversation identity. Missing page/process/runtime objects never imply provider conversation death. SH24 v1 blocks purge with REFERENTIALLY_PINNED and does not invent relocation or unpin policy.

## Code Samples & Guidance

Provider-neutral pin projection:
```python
@dataclass(frozen=True)
class RequestRetentionPin:
    request_id: str
    pinned: bool
    reason: Literal["resumable-session-lineage", "durable-runtime-root", "none"]
    session_ids: tuple[str, ...]  # internal/redacted operator projection
```
SH24 consumes the read-only result; it does not infer or clear pins.

## Files

Generic session lineage/binding/runtime-root persistence and projection; retention-pin reader public contract; atomic relocation/detach service if selected; SH24 purge integration; generic fake, ACP, MCP/A2A and gpt-auto resume tests.

## Validation

Archiving/purging unrelated requests does not affect sessions; a pinned opening request cannot purge; relocation crash cannot expose two conflicting authorities or lose resume; closed gpt-auto tab resumes the same provider chat ID after request archival; provider-neutral tests contain no gpt-auto branch.

## Effort & Risk

Medium/high: provider-specific durable state must be normalized without leaking provider-native details or weakening binding immutability.

## Standards

arch-standards §§3,4,6,7; session binding immutability; provider-neutral public contracts; observability redaction.

## Acceptance Criteria

- Any request referenced by resumable session lineage or a durable session runtime root is REFERENTIALLY_PINNED.
- Missing volatile page/process/handle state never clears a pin or proves conversation death.
- SH24 cannot purge a pinned request and cannot invent an unpin/relocation policy.
- If state is relocated/detached, the migration is atomic, restart-safe, preserves immutable lineage/provider reference, and has one authority.
- Generic fake, ACP and MCP/A2A-backed agent tests exercise the same public contract without provider-ID branches.
- A closed gpt-auto tab resumes the identical provider conversation after unrelated archive work, demonstrating the provider-specific validation without provider-specific production policy.
