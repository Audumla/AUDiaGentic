# Adopt completed provider responses after refresh before terminal failure

## Description

When a refresh exposes a complete request-owned response after the gateway has observed an interruption, stale DOM, or provisional correlation conflict, persist and expose that response instead of leaving the request failed with an unresolved fence.

## Steps

- Add a post-refresh correlation pass using the original prompt anchor and assistant identity/text.\n- Persist the response artifact before changing lifecycle state.\n- Make reconciliation idempotent and safe for already-terminal records.\n- Distinguish recovered success from operator adoption when evidence is ambiguous.\n- Keep unresolved state only when ownership/completion cannot be proven.

## Detailed Solution & Technical Design

After each same-tab refresh, run normal response observation against the immutable request prompt anchor. If completion witnesses, assistant identity, stable text, and no auth veto validate, use the existing terminal ordering to write the request-owned artifact and transition completed. For already-failed unresolved requests, provide a guarded reconcile/adopt operation that can attach the artifact only when the durable session binding and request correlation match; otherwise retain failed/unresolved evidence.
