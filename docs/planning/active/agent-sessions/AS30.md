# Persist provider session bindings and capability-gated harness mappings

## Description

Make the AG-session-generation ↔ provider-session/thread relationship a first-class durable binding governed by the AS29 resolved session surface.

Agents owns the protected binding record and durable binding index. Providers own construction/validation of opaque provider refs and execution of capability-gated surface operations. AS30 must not redefine AS28 transport/control, AS17/AS28 process ownership, AS19/AS21 observability, AS31 content, or provider configuration.

The gateway may always persist an opaque ref returned by a validated open operation. It may attach, resume, discover, share, or replace only when the exact resolved provider/harness surface explicitly declares and validates that operation for the same identity, project, and execution context.

## Steps

0. Depend on AS28 and AS29. AS28 supplies transport/control and process ownership behavior; AS29 supplies the resolved session surface, identity context, and operation capabilities. Do not use `provider-session-ref` as an untyped resume switch after AS30.

1. Establish the authority table before coding:

| Concern | Authority |
|---|---|
| AG session workflow state | Existing `agents_gateway_sessions_store` and `gateway-session` TransitionEngine |
| AG ↔ provider session identity | AS30 binding record and index |
| Legal mapping operation | AS29 resolved surface capability |
| Live active/idle/terminal state | Observability/lifecycle capability from AS19/AS21 |
| Process ownership and termination | AS17/AS28 |
| Provider configuration | Existing provider configuration services |

2. Add `foundation/transports/session_binding.py` with neutral values: `BindingRelation` (`OPENED`, `ATTACHED`, `RESUMED_FROM`, `REPLACED`), `ProviderSessionRef`, and `SessionBindingIntent`. Treat `ProviderSessionRef.value` as opaque protected data: no parsing, logging, path use, filename use, display, or cross-surface reuse.

3. Extend AS29's resolved session surface with operation-specific `SessionMappingCapabilities`: `open_new`, `returns_opaque_ref`, `resume_by_ref`, `attach_existing`, `discover_existing`, `share_existing`, `replace_existing`, `concurrent_attachments`, `attach_while_turn_active`, `ref_scope`, `ref_namespace`, `requires_same_project`, and `requires_same_execution_context`. Unknown means unsupported. Runtime consumes normalized validated capability, not harness names.

4. Keep per-harness surface coverage as evidence/probe data attached to AS29/AS30, not as an independent runtime registry. Each supported or planned harness surface needs an evidence row and probes, but executable truth remains the AS29 resolved surface manifest.

5. Bump `foundation/contracts/schemas/agent-llm-session.schema.json` from v1 to v2. Replace top-level `provider-session-ref` with a required protected `binding` object containing `binding-id`, `generation`, `provider-id`, `surface-id`, `surface-version`, `provider-session-ref`, `provider-ref-key`, `relation`, `ownership`, `predecessor-binding-id`, `identity-context-fingerprint`, `execution-context-fingerprint`, and `created-at`.

6. Define `provider-ref-key` as `SHA-256(provider id + surface id + surface ref namespace + AS29 identity-context fingerprint + exact opaque provider session ref)`. Store exact `surface-version` for compatibility evidence, but do not include executable version in the stable key unless the surface explicitly declares a version-specific ref namespace. Resume/attach compatibility is decided by resolved surface capability plus compatibility predicate.

7. Add v1 read migration beside existing session-store schema validation. A v1 record migrates in memory to generation `1`, relation `opened`, ownership `owned`, and no predecessor. Migration grants no attach, resume, discovery, sharing, or replacement entitlement; it does not query the harness, discover external sessions, infer identity, or reactivate terminal records. All writes become v2.

8. Add `agents_gateway_session_bindings.py`. It owns `create_open_binding`, `attach_binding`, `resume_binding`, `replace_binding`, binding retirement, and index rebuild. Use a project-local `session-binding-index.json` mapping `provider-ref-key` to active AG binding ids.

9. Protect every binding-index read-modify-write with `foundation.system.process.StartupLock` and `foundation.io.atomic_write_json`, following the idempotency-index pattern. Do not use a module-global lock, thread-only lock, `ManagedFragmentRegistry`, or provider config fragment mechanisms. On unreadable index, rebuild only from validated v2 AG session records under the project lock; never discover provider sessions during recovery.

10. Enforce ownership and attachment rules. A provider-ref key may have at most one active owned binding. Additional non-owning attachments are allowed only when the exact surface validates `attach_existing` and `concurrent_attachments`. Collision checks must re-read protected records and compare provider, surface, identity context, and exact opaque ref.

11. Add provider contract/API support only for surface operations, not AG binding mutation. Providers may open, attach, resume, or replace at the resolved surface and return or validate opaque refs. `agents_gateway_session_bindings.py` mutates AG binding records and indexes. `providers_api` refuses operations whose AS29 capability is missing or unvalidated.

12. Forbid all fallback behavior: no alternate surface, alternate account, alternate project, display name, most-recent session, CLI continue/latest, interactive picker, transcript matching, UI scraping, or endpoint-family inference.

13. Refactor SessionRuntime open transaction: resolve exact surface → create `SessionBindingIntent(OPENED)` → provider opens transport/session → provider returns opaque ref → persist v2 protected record → atomically update binding index → expose live handle. If persistence fails, legally close the owned transport, remove provisional index state, record cleanup failure if needed, and never expose an unbound usable handle.

14. Refactor AS08 same-generation continuation. Reuse the current AG generation only when the binding matches exactly, identity/project/execution context are compatible, the live handle still belongs to that binding, and observability says no turn is active and the session is reusable. A stored ref alone is insufficient.

15. Refactor AS10 resume. Resume never mutates a terminal source record back to active; it creates a new AG session id and generation, records `RESUMED_FROM`, links `predecessor-binding-id`, calls provider resume only when `resume_by_ref` is validated, and preserves source terminality. If exact resume is unsupported, require an explicit replacement or new-session request.

16. Refactor AS14 external/live attach. Attach requires `attach_existing`, explicit `external` or `adopted` ownership, exact opaque ref, compatible identity/project/context, safe observability state, and `concurrent_attachments` when another binding exists. Non-owned close detaches; adopted follows transferred lifecycle authority; owned close/terminate follows AS28 and surface capabilities.

17. Keep replacement explicit. `REPLACED` means AG deliberately opened a different provider session because the old binding could not legally or safely continue. It creates a new binding, links predecessor, leaves source terminal, and must not be reported as successful resume. Fork/clone/import/branching remain out of scope unless AS29 and the relation model are extended separately.

18. Emit redacted binding lifecycle facts containing binding id, relation, generation, ownership, provider, surface, surface version, ref-key prefix, predecessor binding id, and outcome. Never emit raw provider ref, raw identity context, opaque-ref-derived paths, attach secrets, or cloud conversation tokens. Register explicit errors for unsupported/unvalidated operation, context mismatch, identity mismatch, duplicate owner, unsupported concurrent attachment, stale binding, provider-ref collision, persistence failure, index corruption, unsafe live state, and non-reusable session.

19. Add generic tests for v1 migration, v2 schema validation, open persistence rollback, protected ref redaction, exact identity/project/context matching, denied unadvertised operations, duplicate owner race across processes, allowed owner-plus-attachment, denied unsupported concurrency, resume source terminality, replacement-is-not-resume, index corruption/rebuild, stable ref key across compatible upgrades, different identity context creating a different key, collision re-read exact-ref comparison, external/adopted/owned close behavior, no latest/name/UI/transcript fallback, and continuation denied while active but allowed when observable reusable.

20. Add a probe checklist per harness surface as evidence: open returns a stable machine ref, exact resume resumes expected history, invalid resume does not open unrelated sessions, attach joins the same live session, non-owned close detaches, discovery returns exact refs in scope, concurrency allows only valid observer/interactive behavior, and observability distinguishes process-live from turn-complete. Missing or failed probes keep the operation disabled.

21. Platform acceptance: run direct Windows and Linux jobs for migration, duplicate-ref race, owner-plus-attachment race, stale lock, index rebuild, owned/external close, compatible upgrade identity stability, and identity-context separation. Run Linux Docker two-process crash/race tests for kill while holding lock, kill between record and index write, valid-owner rebuild, allowed attachment preservation, no duplicate owners, and no provider-session discovery during recovery. Job Object/process-tree behavior remains AS17/AS28.

## Validation

AS30 is complete when:

1. v2 session records contain one explicit protected binding.
2. Raw provider refs never appear in events, paths, filenames, metrics, or ordinary diagnostics.
3. Surface operations are denied unless AS29 resolves validated support for that exact provider/surface/identity/project/context.
4. Unknown capability defaults to unsupported.
5. Open-only surfaces cannot attach, resume, discover, share, or replace.
6. Exact resume creates a new linked AG generation and preserves source terminality.
7. Same-generation continuation and attach consume observability state; process liveness alone never authorizes reuse.
8. Concurrent clients cannot create duplicate owned bindings.
9. External/adopted close detaches or follows transferred authority instead of blindly terminating.
10. Provider-ref identity is scoped by AS29 identity context and ref namespace.
11. Compatible harness upgrades do not accidentally create duplicate binding identity.
12. Recovery rebuilds AG binding state only from protected AG records and never discovers external provider sessions.
13. No harness capability is inherited from a related harness, different surface, endpoint family, documentation table, or candidate route without a passed probe.

## Effort & Risk

This is a complex AS slice because it combines schema migration, durable indexing, capability enforcement, and cross-process races.

Primary risks:

- treating a stored opaque ref as permission to resume or attach;
- mixing provider-owned surface operations with AG-owned binding mutation;
- including executable version in identity keys and splitting valid bindings after harmless upgrades;
- treating interactive `continue latest` or display-name selection as exact resume;
- leaking protected refs through logs, events, filenames, metrics, or diagnostics;
- confusing process liveness with session reusability;
- enabling concurrent writers or duplicate owned bindings;
- treating editor threads, terminal sessions, ACP sessions, and underlying harness sessions as one identity;
- allowing documentation/candidate evidence to become runtime truth before probes pass.

## Standards

- Durable records use existing schema validation and atomic-write helpers.
- Cross-process coordination uses `StartupLock`.
- Opaque provider refs are protected data.
- All operation support is evidence-backed and versioned through AS29 resolved surfaces.
- Unknown capabilities default to unsupported.
- Runtime code consumes normalized capabilities and does not branch on harness names.
- Session workflow state remains in the existing TransitionEngine.
- AS30 owns AG binding/index state; providers own opaque-ref construction/validation and surface operation execution.
