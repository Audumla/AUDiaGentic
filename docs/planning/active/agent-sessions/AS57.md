# Expose authorized live turn events and assistant-output reads

## Goal

Provide an external gateway surface for authorized clients to observe a live session turn using bounded redacted lifecycle/status events and AS31 assistant-output fragments. Reuse canonical internal lanes; do not expose provider-native frames or create a second session/event/content authority.

## Dependencies

AS19/AS21 canonical evidence/status, AS30 binding/project/context authorization, AS31 output storage/read, AS48 metadata polling behavior, and the existing shared gateway service/client lease model.

## Public model

Expose two logically separate channels through one client-facing read surface:

- metadata/status events from AS48;
- user assistant output from AS31.

They may share an outer turn envelope/cursor response, but must retain separate event kinds, retention/gap states, redaction policy, and source sequence. Never merge assistant text into lifecycle evidence or metadata events.

Define a bounded public envelope containing only:

- request/session/turn IDs;
- public sequence/cursor;
- timestamp;
- channel (`status|output`);
- canonical redacted status event or assistant text fragment;
- next cursor, has-more, gap, truncated, and delivery state.

No provider ref, native event name, raw protocol payload, prompt, hidden reasoning, tool arguments/results, auth token, stack trace, or control capability is present.

## Authorization and side effects

Use existing shared gateway canonical project-root validation, authenticated active client lease, and AS30 session/binding context. A reader must be authorized for the exact project/session/request.

Reads must not:

- create/open a runtime or provider transport;
- take the session turn/FIFO lock;
- renew execution lifetime or a process lease;
- advance queue/request state;
- cancel, steer, follow up, respond permission, or close;
- mark evidence consumed in a way that changes lifecycle.

## Cursor, gaps, and reconnect

Use opaque/integrity-checked cursor semantics grounded in the AS48 metadata generation and AS31 output relay/index. Support bounded page reads and reconnect after client disconnect.

Return deterministic gaps for:

- metadata buffer expiry/service restart;
- output truncation/retention;
- corrupt/missing indexed output event;
- cursor generation/request/turn mismatch.

Do not claim durable replay for in-memory metadata. Output durability is only what AS31 proves. A client can always retrieve the final durable request status/output after terminalization through existing APIs.

## Service/client/MCP surface

Add closed application/client/service operations and an MCP tool only after pure read helpers and authorization tests pass. Prefer one operation with explicit channel selection or one combined ordered page; do not create SSE/WebSocket/push in the first slice unless the existing shared service already has a safe reusable streaming primitive.

Polling/tailing cannot block prompt execution or hold global/session locks while waiting. Use bounded wait/long-poll only if it reuses an existing cancellation-aware service primitive.

## Validation

- active turn metadata and output ordered per their declared channel;
- reconnect from cursor without duplicate accepted events;
- deterministic metadata restart gap and output truncation/degraded gap;
- cross-project/session/request rejection;
- malformed/oversized cursor/page rejection;
- no runtime creation/turn lock/queue mutation/lifecycle renewal;
- client disconnect/reconnect while provider continues;
- final durable record remains readable;
- no raw/native/content leakage across channel boundaries;
- Docker tail fixture with fake streaming transport and service restart.

## Acceptance criteria

- Authorized clients can observe a live turn without controlling it.
- Status and content remain separate canonical lanes.
- Cursor/gap behavior is explicit and bounded.
- Provider-native frames never leave adapters.
- Reading has no execution side effect.
