# Make GPT-auto CDP target location configuration-driven

## Description

Allow GPT-auto to attach to a browser/CDP endpoint located on another machine, with the endpoint fully owned by provider configuration rather than hardcoded loopback and port values.

## Steps

- Extend cdp configuration with endpoint and validate it.
- Replace hardcoded CDP URL and readiness address construction with the configured endpoint.
- Separate local browser process acquisition from remote attach-only operation.
- Add deterministic tests for endpoint resolution, remote readiness, and no local launch path.
- Update provider configuration documentation/defaults.

## Detailed Solution & Technical Design

Add an explicit cdp.endpoint URL to the GPT-auto settings schema and packaged defaults. GptAutoConfig.cdp_url returns that endpoint. Readiness probing parses the configured endpoint rather than opening 127.0.0.1. Remote endpoints are attach-only: the runtime must not launch, inspect, or terminate a local browser when the configured endpoint is non-loopback. Local browser management remains available for loopback endpoints. Local-only DevToolsActivePort fallback is rejected for remote endpoints. Validate endpoint scheme/host/port and avoid exposing unauthenticated CDP broadly; deployment guidance should prefer loopback plus SSH/VPN.

## Validation

Run focused config and runtime tests, then the full GPT-auto suite. Verify the default resolves to the configured loopback endpoint, a remote HTTP/WebSocket endpoint is accepted, readiness probes the configured host, and an unavailable remote endpoint fails without launching a local browser.

## Effort & Risk

Medium/high. CDP is full browser control and endpoint misconfiguration could attach to the wrong authenticated browser. Remote mode must be explicit and process ownership must remain local-only.

## Standards

Configuration-owned target identity; no hardcoded machine location; fail closed on invalid/unsafe endpoint configuration; no git stash.

## Acceptance Criteria

- No production GPT-auto code constructs the target from a hardcoded 127.0.0.1 or fixed port.
- The effective target is visible in provider configuration and included in runtime identity.
- Remote CDP attach never launches or kills a local browser.
- Existing local loopback behavior remains valid.
- Focused and full GPT-auto tests pass.
