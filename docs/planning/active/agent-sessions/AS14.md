# Codex App Server transport: shared live sessions, steer/interrupt, native resume

## Description

Second transport kind alongside stdio ACP: Codex App Server's native JSON-RPC interface (codex app-server --listen ws://127.0.0.1:<port>). Unlike the ACP bridge, App Server supports MULTIPLE clients on one live Codex session — a human runs the TUI against it (codex --remote ws://...) while the gateway connects to the same server and drives the same thread. This is the sponsor's remote-control scenario done natively: thread/list, thread/read, thread/resume, turn/start, turn/steer (inject instructions into a RUNNING turn), turn/interrupt, streamed events, approval handling.

## Steps

1. Design first (this is not light code): a foundation transports module for App Server (websocket JSON-RPC client) exposing the same neutral-event surface as ACP — map App Server stream events into the frozen canonical kinds so the SessionRuntime and dispatch reuse everything above the transport; requires an MA18-style review for the new transport binding (event mapping table).
2. Session model fit: an App Server session's process is NOT owned by the gateway (external server) — SessionRuntime needs an 'external process ownership' mode where close() detaches (ends our client connection) instead of terminating, and the reaper's cleanup guarantees apply only to owned processes. Persist the ws endpoint + thread id as provider-session-ref (this also delivers AS10-style resume natively via thread/resume).
3. Capability seam: second adapter hook (e.g. build_app_server_connect) or a launch-mode discriminator on the existing seam — decide in design.
4. turn/steer maps naturally onto queued-turn semantics but is a distinct operation (inject into the running turn vs queue a new turn) — expose as an explicit API/MCP operation, not silently.
5. Security: ws transport is experimental upstream — bind localhost only or SSH tunnel; no TLS/auth assumptions; never persist tokens in records (Standard 8).
6. Tests with a fake App Server; live validation against a real codex app-server with a concurrent TUI client.
