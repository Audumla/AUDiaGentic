# Trial bench: drive MA plan items through sessionful implement→review→revise coordination

## Description

R&D lane for a repeatable commander/overseer → worker-agent delegation loop. The immediate goal is not a polished product surface; it is to discover the smallest reliable control contract for delegating one plan item per live ACP session, detecting actual completion vs premature stall, issuing bounded continuation bumps, reviewing final work, and recording agent/model capability evidence. Use MA plan items as realistic work packets and preserve findings in a lightweight audit under `.audiagentic/research/agent-overseer/` until the pattern is ready to graduate into code/docs.

## Steps

1. Define the v0 overseer contract: one ACP session per plan item; initial task prompt includes plan id, acceptance criteria, validation commands, ledger requirement, final-summary-and-stop instruction; controller does not inspect every action.
2. Define sparse monitoring signals: ACP terminal `result` is primary done; counters/timestamps for meaningful event kinds (`tool-call`, `file-change`, `terminal-output`, `assistant-message`, `status`, `usage`, `permission-request`) are heartbeats; durable filesystem signals (ledger fragment with `plan-item-ids`, plan state/linkage, file mtimes) are secondary evidence because bus events may not cross process boundaries.
3. Define stall classification and bump policy: no bump while CPU/tool/file/terminal activity continues; if the session is alive but has no meaningful heartbeat for a configured idle window, send a same-session continuation prompt; cap bumps; distinguish premature stop (terminal result without validation/ledger/final contract) from wedge (no terminal result after idle + bump budget).
4. Define shutdown safety: after terminal result or controller stop, call ACP close, then verify the root process and descendants are gone; terminate/kill remaining descendants after grace windows; record orphan cleanup outcome in the audit.
5. Run at least two R&D trials: MA33/opencode as baseline from the 2026-07-16 session, then another simple MA item through the v0 template. For each, record profile id, provider, resolved model id, plan id, task class, prompts/bump count, terminal result status, validation result, process cleanup result, and controller intervention.
6. Use findings to decide implementation split: keep trial-only code under `.audiagentic/research/agent-overseer/` until the pattern is proved; then graduate reusable pieces into the existing `agents` component rather than a new component by default.
7. Define the production agents MCP shape before coding: a sessionful plan-item delegation submit/read surface, summarized progress/status read that exposes last heartbeat/terminal/stall classification without streaming every ACP event, explicit same-session continuation/bump control, cleanup verification, and review-handoff metadata.
8. Keep cross-process lifetime guarantees out of AS11. If worker sessions must survive MCP host death or be shared/adopted across processes, hand off to AS08 detached supervisor design; AS11 may document the need but must not imply process-local SessionRuntime provides it.
9. Consume provider-owned capability/model identity facts from MO07/MA19 only through public APIs. The overseer/capability log may record profile/provider/routed model/performance evidence, but must not implement gateway/source introspection or provider-specific model-name heuristics.
10. Reuse RE01 patterns where they fit: capability-only prompts, existing template renderer, planning MCP propagation assertions, correlation metadata, and loop guards. Keep reviewer-agent automation separate from implementation/revision delegation unless a future design explicitly unifies them.
