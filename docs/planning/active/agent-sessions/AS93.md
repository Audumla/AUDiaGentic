# Bounded in-memory session metadata event polling

## Description

Add a cursor-based read over a bounded in-memory stream of provider-neutral session metadata, so a caller can observe a live session's lifecycle without controlling it.

Mechanism only: buffer, cursor, ordering, gaps. Content-free by construction — this stream carries lifecycle metadata, never assistant output. Cryptographic/tamper integrity and field redaction are excluded and owned by AS102. Caller authorization is not deferred to a hardening item — none exists post-AS101-rewrite; AS101 is project isolation, not caller authorization, so a read is scoped to the requesting project only, with no per-caller filtering within it. Structural cursor validation — length/parser bounds, session-context mismatch, and generation/restart deterministic-gap semantics — is in scope here, per RV921's distribution of the retired AS103.

## Steps

1. Check for an existing bounded buffer in the agents event/timeline seams and reuse it if equivalent; otherwise add one owner module.
2. Define immutable cursor and page values: cursor carries session id, next sequence, issued-at and a per-process generation; page carries events, next cursor, gap and has-more.
3. Implement one bounded per-session buffer. Defaults: 256 retained events per session, 25 default page size, 50 maximum. Restart or expiry returns a deterministic gap naming the reason, the from-sequence and the next available sequence.
4. Source events from the `SessionEvidenceProjection.accept()` seam — its already-correlated `SessionLifecycleEvidence` (session id, turn id, sequence, kind, correlation id, timestamp, source) — not from the bare `SessionLifecycleDecision` it derives. `SessionLifecycleDecision` carries only coarse_state/accepts_new_turn/session_reusable/turn_terminal/dependent_work_releasable/evidence_state/reason — none of session id, turn id, sequence, timestamp or correlation id — so it cannot by itself be normalized into a correlated event (RV924). Normalize the evidence to: sequence, timestamp, session id, turn id, kind, coarse state, flags, source, correlation id, bounded diagnostic code.
5. Implement `poll_session_events(project_root, session_id, cursor=None, page_size=None)` as a side-effect-free helper: clamps page size, returns ordered non-duplicated pages, reports deterministic gaps.
6. Polling must not create or attach a runtime, take the session turn lock, renew execution ownership, alter queue state, keep a session alive, or mutate any lifecycle or request record. This is the load-bearing constraint of the item.
7. Add the gateway application/client/MCP read operation only after the pure helper and its tests pass. (RV924: reconsider whether this item needs its own standalone public MCP surface at all, since AS94 immediately supersedes it with the real public live-turn read; demote to an internal/application read primitive unless a standalone metadata-only consumer is proven before this step starts.)

## Acceptance Criteria

- The stream is bounded, in-memory, cursor-based and content-free by construction.
- Pages are ordered and non-duplicated; page size is clamped; retention is bounded.
- Restart or expiry returns a deterministic gap and never implies durable replay.
- Polling creates no runtime, takes no turn lock, renews no execution lifetime, advances no queue state and mutates no record — asserted directly, not by inspection. This is the load-bearing property.
- A concurrent poll during a later prompt leaves FIFO unchanged.
- The pure helper and its tests pass before any MCP surface is added.
