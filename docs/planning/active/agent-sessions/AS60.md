# Rename current agent profiles to execution profiles

## Goal

Rename the existing provider/model execution configuration to `ExecutionProfile` without changing queue, admission or session behavior.

The project YAML, agents public CRUD API, and `ag-agents-mgmt` MCP are one configuration-management path. They are not separate definitions.

Shared-gateway mode additionally resolves authoritative admission facts such as provider, model, execution parameters, generation and queue limits. This is deployment-specific resolution of the selected Execution Profile, not a second management surface.

Expose both execution modes through one framework-neutral resolution boundary. Do not create another profile authority.

An Execution Profile contains only:

- provider and model;
- selected AS29 session surface or provider-declared default;
- launch/execution parameters;
- concurrency, queue and existing session-lifetime settings.

It does not contain role instructions, runtime tool sets, permissions, skills, ACP/A2A publication or copied capability claims.

## Current code to migrate

Characterize and migrate together:

- `components/agents/models.py::AgentProfile` and `AgentProfilesStore`;
- `components/agents/agents_api.py` project-local load/save/resolve operations;
- `components/agents/agents_manage_mcp.py` management MCP wrappers;
- `config/components/agents.yaml::ag-agents-mgmt` management declaration and metadata;
- `components/agents/agents_gateway_profiles.py` shared-gateway registry, lane key and immutable admission value;
- `agents_gateway_api.py` profile resolution and module-level registry access;
- project config path, seed data, schemas, error codes, status output, tests, docs and dotted references.

The immutable gateway admission value is required for stale-generation rejection and queue-lane identity. Preserve that behavior under simple terminology such as `ResolvedExecutionProfile`. Do not add a broader snapshot hierarchy or persist copied profile definitions.

## MCP disposition in this item

- Rename `ag-agents-mgmt` tools and metadata directly to Execution Profile terminology. It remains a management MCP with `propagate: audiagentic` and delegates only to the public agents API.
- Do not duplicate validation, YAML access or profile mutation in the MCP adapter.
- `ag-agents` is not part of the management rename by default. Gate 0 must prove whether provider-side profile resolution has a current consumer. If it has none, delete that activity server and provider propagation instead of renaming it forward.
- Do not expose runtime MCP selection or harness tool policy through Execution Profile in this item. Existing provider/runtime materialization remains authoritative.

## Boundary and wiring

Provide one narrow execution-profile public API/resolver that returns the resolved execution facts required by admission. It uses project configuration in embedded/project mode and the shared-gateway authority in shared mode.

- Management MCP and CLI call the public CRUD/config API.
- AgentTask/gateway admission calls the resolution API.
- Callers do not import YAML stores or concrete registries.
- The shared gateway host/composition root supplies the active resolver explicitly.
- Remove module-global registry selection where owned by this migration without introducing a container.
- Do not add a service locator or new registry.
