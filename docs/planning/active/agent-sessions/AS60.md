# Refactor current agent profiles into execution profiles

## Goal

Rename and clarify the current `AgentProfile`/gateway-profile concept as `ExecutionProfile`: a reusable mapping of provider, model, selected AS29 session surface, non-secret execution parameters and admission/resource policy.

This slice is primarily a terminology and ownership refactor. It must preserve current gateway behavior and must not introduce roles, logical agent identity, A2A skills or public interface policy.

## Execution prerequisite

AS59 Gate 0 must be closed before implementation starts. Its plan inventory, ownership map, baseline test matrix, local amendment blocks and contradiction-closure report are mandatory inputs.

Do not begin this item merely because the design exists. The executor must first verify AS59 records `AS60 ready: yes` and names no unresolved profile/store/registry contradiction.

## Current baseline

The current `AgentProfile` binds `provider_id`, `model_id`, optional alias and `params`. The shared gateway additionally resolves immutable profile generation/config digest, concurrency, queue limits and execution parameters. Characterize and migrate these existing implementations instead of adding a parallel profile store or registry.

## Contract

Define frozen/validated forms for:

- `ExecutionProfileDefinition` — persisted reusable definition;
- `ExecutionProfileSnapshot` — immutable admission/execution snapshot;
- `ExecutionProfileGeneration` or existing generation string;
- `ExecutionProfileRegistry` — gateway-owned authority in shared mode;
- project-local compatibility resolution for embedded mode;
- explicit `session_surface_id` selection, resolved only through AS29.

An execution profile may contain only:

- provider ID;
- model ID/alias;
- explicit AS29 session-surface selection or provider-declared default selection policy;
- non-secret launch/execution parameters;
- admission policy such as max concurrency and queue size;
- bounded session defaults such as idle/max lifetime where already supported;
- resource/sandbox references already owned by existing execution/isolation contracts.

It must not contain:

- system instructions;
- tools or permissions;
- role behavior;
- A2A skills/identity;
- ACP/A2A publication policy;
- copied provider-surface capability claims;
- raw commands, credentials or provider session refs.

## Steps

1. Consume the completed AS59 Gate 0 profile inventory and baseline tests.
2. Rename data models, stores, APIs, snapshots, registries, diagnostics and tests from agent/gateway profile to execution profile where the object is execution/admission configuration.
3. Rename identifiers from `agent_profile_id`/`profile_id` to `execution_profile_id` where unambiguous. Preserve generic `profile_id` only in transitional wire/config readers.
4. Add explicit session-surface selection to the execution profile, but resolve and validate all capabilities through AS29. Do not copy AS29 fields into profile data.
5. Update SH02 execution manifest/runtime digest inputs to name and freeze the execution-profile ID, generation and digest.
6. Update queue lane keys and stale-generation validation without changing queue semantics.
7. Update project-local YAML and machine-scoped gateway profile configuration to a new contract version. Provide one bounded read migration from the existing agent-profile format; all new writes use execution-profile terminology.
8. Keep `submit_llm_request` behavior working through compatibility aliases until AS63.
9. Add architecture gates forbidding new `AgentProfile` production types after migration, except explicit compatibility readers.
10. Update any additional affected plans found during AS59 execution before closing R1.

## Validation

- existing profile CRUD/resolution behavior migrates without duplicate stores;
- shared and embedded modes resolve equivalent immutable snapshots;
- stale generation and queue lane behavior remain correct;
- session-surface selection is exact and unsupported selection launches no process;
- secrets remain excluded from snapshots/digests/public output;
- old config reads once and writes only the new contract;
- no role, skill or interface fields enter execution profiles;
- Windows/Linux direct and existing gateway Docker tests pass.

## Acceptance criteria

- `ExecutionProfile` is the sole reusable provider/model/execution/admission mapping.
- Current `AgentProfile` production terminology is removed or isolated to migration aliases.
- AS29 remains the sole capability truth for selected harness surfaces.
- Existing gateway/session behavior is unchanged apart from names and explicit surface selection.
- R1 findings are recorded in AS59 before AS61 begins.
