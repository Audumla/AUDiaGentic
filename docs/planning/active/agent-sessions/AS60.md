# Rename current agent profiles to execution profiles

## Goal

Rename the existing provider/model execution configuration to `ExecutionProfile` without changing queue, admission or session behavior.

The project YAML, agents public CRUD API, and `ag-agents-mgmt` MCP are one configuration-management path. Shared-gateway mode resolves additional admission facts; it is not a second management authority.

An Execution Profile contains only provider/model, selected AS29 surface or provider default, launch parameters, queue/admission settings and existing session-lifetime settings. It does not own Role, runtime tools, permissions, skills or ACP/A2A publication.

## Current code to migrate

Migrate together:

- `components/agents/models.py::AgentProfile` and `AgentProfilesStore`;
- `components/agents/agents_api.py` load/save/resolve operations;
- `components/agents/agents_manage_mcp.py` and descriptor metadata;
- `components/agents/agents_gateway_profiles.py` registry, lane key and immutable admission value;
- profile resolution in `agents_gateway_api.py`;
- config paths, seeds, schemas, error codes, status, tests and docs.

Preserve the immutable admission value needed for stale-generation rejection and queue-lane identity under simple terminology such as `ResolvedExecutionProfile`. Do not create a wider snapshot system.

## MCP disposition

- Rename `ag-agents-mgmt` directly to Execution Profile terminology; keep it a thin management adapter.
- Retain `ag-agents` operations only where Gate 0 proves a current harness consumer. Remove or replace unevidenced profile-configuration access.
- Do not add runtime tool selection to Execution Profile.

## Public boundary and composition

Provide one narrow Execution Profile public API/resolver. Project and shared modes may have different concrete implementations behind that contract.

- Management MCP/CLI call CRUD/config APIs.
- Gateway admission calls the resolver.
- Runtime composition selects the resolver implementation by stable ID and injects it into the application host/gateway path.
- Core code does not import stores, concrete registries or the composition graph.

## Legacy exemption interaction

The AS59 legacy exemption does not cover profile code materially changed by this item.

When AS60 closes:

- the Execution Profile resolver and any touched stateful repository/registry are configured composition dependencies;
- touched callers have no module-global registry getter/setter or fallback construction path;
- the application host may still call unrelated legacy startup code, but it may not construct or rediscover the migrated resolver;
- no compatibility alias from Agent Profile to Execution Profile remains.

Do not migrate unrelated stores or startup modules solely for consistency.
