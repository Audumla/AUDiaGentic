# Expose redacted queue-authoritative compute diagnostics

## Description

Add the bounded O2 operator view that is actually needed: per-request/session computing, queued-on-session, quiescent/idle, duration, pending count, and profile slot attribution. Queue accounting is the sole authority; diagnostics are transient read-only projections, not another scheduler state store.

## Steps

1. Define applicability for persisted queued, running non-session, running session, queued-on-turn-lock, quiescent session, and terminal requests; use absent/not-applicable rather than false labels. 2. Add a locked immutable queue snapshot/lookup for running/idle/pending/slot facts. 3. Add a small immutable SessionRuntime diagnostic snapshot for identifiers, pending count, activity clocks, and lock state only. 4. Project one compact session_compute section and request compute_state without persisting it. 5. Preserve redaction. 6. Reconcile counts with pq.running/pq.idle and avoid starting runtime merely to answer a durable-only read when no live data exists.

## Files

Gateway queue snapshot, cohesive session diagnostic projection, gateway API/SH04 response, targeted unit/race/integration tests.

## Validation

Active, queued-on-session, quiescent, non-session, terminal, and max-concurrency-one transitions map deterministically; overview/request counts reconcile with one queue snapshot; no prompt/output/tool/secret fields; race-focused tests show no impossible slot count.

## Effort & Risk

Mid, read-only. Risk is inconsistent duplicate derivation, avoided by queue authority plus immutable snapshots.
