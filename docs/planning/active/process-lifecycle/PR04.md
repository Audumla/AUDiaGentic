# Shared embedded rig: single-authority refcounted lifecycle (fix cross-harness kill, races, unsafe reaping)

## Description

The embedded rig (llama-server) is designed to be shared: one rig per machine, launched under StartupLock by whichever harness arrives first (runtime/harness/rig.py), tracked in rig.json plus a PID-file client registry (runtime/rig/registry.py), and stopped by shutdown_rig_if_last when the last client detaches (commands/launch.py). VRAM constraint: exactly ONE rig may exist. Review findings (2026-07-06) show the design intent is not delivered:

1. CRITICAL — opencode runner kills the shared rig unconditionally. opencode/runner/__init__.py:178-181 does kill_process_tree(ctx.rig_pid) in finally. rig_pid marks the STARTER, not the last user: if harness A starts the rig and harness B attaches (reuse path, rig_pid=None), A's exit kills the rig under B mid-session. Two competing shutdown mechanisms exist (unconditional kill vs refcounted shutdown_rig_if_last); the unconditional one always wins.
2. CRITICAL — attach/detach not serialized with startup. register_client() runs in _cmd_launch AFTER launch_rig_if_needed returns, outside the StartupLock; shutdown_rig_if_last takes no lock at all. Race: B reuses the rig under the lock but has not yet written its client file; A exits, counts 0 clients, kills the rig; B talks to a dead endpoint. (Same start/stop race PR03 challenge 4 describes.)
3. HIGH — reap_orphan_rigs kills EVERY llama-server.exe/llamafile on the machine (registry.py:162), including processes audiagentic never started (e.g. the user's independent llama-swap servers). Unsafe.
4. HIGH — model-mismatch kill ignores live clients. read_rig_state(expected_model=...) (registry.py:59-62) kills the running rig whenever the requested profile differs, without consulting the client registry — harness B launching with a different model silently destroys A's session.
5. MEDIUM — hard-kill of the last harness leaks the rig (VRAM held indefinitely). Cleanup relies on finally + a SIGTERM handler that is ineffective on Windows (console close/taskkill are not catchable SIGTERM). Nothing stops the rig until a NEXT launch adopts/reaps it.
6. MEDIUM — PID-reuse hazard: client files are bare PIDs checked with pid_alive; a reused PID counts a dead client as live so the rig never stops; rig.json pid has the inverse hazard.
7. LOW — write_rig_state is non-atomic (plain write_text; no temp+os.replace); torn reads cause readers to unlink rig.json, leaving a live rig untracked — which finding 3 then kills.
8. LOW — adopt_rig_state (registry.py:104) records the REQUESTED model name without verifying the server actually serves it — silent wrong-model attach.

Goal state: the client-registry refcount is the SINGLE shutdown authority; all attach/detach/count/kill transitions are serialized under the same StartupLock as startup; reaping only ever touches audiagentic-owned processes; the rig stops promptly after the last harness detaches even on hard kill; one rig per machine is preserved.

## Steps

**Validate-first:** reproduce finding 1 (start pi harness → start opencode harness sharing the rig → exit opencode → observe rig dead under pi) and finding 3 (start an unrelated llama-server → launch harness with no rig.json → observe unrelated server killed). Capture as failing integration tests before fixing.

1. SINGLE SHUTDOWN AUTHORITY: delete the unconditional kill_process_tree(ctx.rig_pid) in opencode/runner/__init__.py finally block. All rig shutdown flows through shutdown_rig_if_last. Audit for any other direct rig kills outside registry.py (grep kill_pid/kill_process_tree callers). rig_pid on AgentContext becomes informational only (or remove it if nothing else consumes it — grep first).
2. SERIALIZE LIFECYCLE UNDER ONE LOCK: move register_client() inside launch_rig_if_needed so registration happens while start.lock is still held (both the reuse and fresh-start branches). Rework shutdown_rig_if_last to acquire the SAME StartupLock (global_harness_runtime()/rig/start.lock): deregister → count live clients → re-check count → kill + clear state, all under the lock. Callers in commands/launch.py drop their own register_client call.
3. LOCK-HELD LIVENESS (replaces bare PID files): each client creates its client file and HOLDS an exclusive OS lock on it (msvcrt.locking on Windows / fcntl.flock on POSIX) for the life of the process. Liveness test = try-acquire: acquirable ⇒ dead ⇒ prune. Crash/hard-kill releases the lock automatically — removes the PID-reuse hazard AND makes _live_client_count correct after force-kills. Keep pid+start_time in the file body for diagnostics only.
4. SAFE REAPING: rewrite reap_orphan_rigs to kill only processes audiagentic can prove it owns: match candidate PIDs against (a) pids recorded by write_rig_state / a spawn journal in runtime/rig/, and (b) command line containing the audiagentic rig bin dir path (global_harness_runtime()/rig/bin) or the tracked rig port. Never kill by image name alone. On Windows use wmic/Get-CimInstance CommandLine or psutil if available; on POSIX pgrep -f against the bin dir path.
5. MODEL-SWITCH POLICY: in launch_rig_if_needed, when the live rig's model differs from the requested profile, check live client count (under the lock): if >0 raise a clear error (EXT-RIG: rig busy serving model X for N clients; stop other harnesses or use that model); if 0, stop and relaunch with the new profile. Move the kill out of read_rig_state — reading must be side-effect-free regarding live rigs (keep dead-pid/stale-file cleanup only).
6. IDLE WATCHDOG for hard-kill leak: keep the --background launcher (runtime/rig/embedded/cli.py launch_background) alive as a small detached supervisor after health-check instead of exiting: poll the clients dir every ~10s; when 0 lock-held clients persist past a grace window (~60s), acquire start.lock, re-check, stop llama-server, clear rig.json, exit. Spawn it DETACHED_PROCESS/new-session so PR01 Job Objects never capture it. Parent still gets the JSON handshake (print result then detach — e.g. double-spawn or close stdout). The watchdog itself is covered by step 4's ownership rules.
7. ATOMIC STATE WRITES: write_rig_state via temp file + os.replace (mirror foundation save_yaml_file pattern).
8. ADOPT VERIFICATION: adopt_rig_state must compare the probed server model against the requested profile; refuse adoption (return None) on mismatch instead of recording the requested name.
9. Regenerate/verify both harness runners still pass smoke; update PR01-adjacent docs/comments that reference the old rig_pid kill.

## Validation

1. Failing-first integration repros for findings 1 and 3, then green after fix.
2. Two-harness share: start pi, start opencode against same rig; exit the STARTER; assert rig alive and second harness still functional; exit second; assert rig stopped and rig.json cleared.
3. Race test: concurrent launch + shutdown loops (threads/processes) — no window where a client holds a reused endpoint to a dead rig; no double rig.
4. Reap safety: launch a decoy llama-server (or stub exe named llama-server) NOT owned by audiagentic; run reap_orphan_rigs; assert decoy untouched, owned orphan killed.
5. Model switch: with a live second client, launching a different profile raises the busy error and leaves the rig running; with zero clients it swaps.
6. Hard-kill leak: force-kill (taskkill /F) the last harness; assert watchdog stops the rig within grace window; verify on Windows AND POSIX (POSIX path in Docker per project gate — env-changing tests must run in the Docker image, never host-gated).
7. Lock-held liveness: simulate PID reuse (stale client file, lock not held) → counted dead; held lock → counted live even if pid file body is garbage.
8. Existing pi/opencode smoke paths green; ruff check clean.

## Effort & Risk

Mid effort, medium risk. Riskiest piece is the detached idle watchdog (step 6): it must escape PR01 Job Objects yet remain reap-able via step 4's ownership rules; keep it tiny and side-effect-free apart from the guarded stop. Lock-held liveness needs platform-split code (msvcrt vs fcntl) — isolate in foundation/system/process.py with unit tests per platform. Steps 1-2 are small, high-value, and can land first as their own commit; steps 6 (watchdog) is separable if it drags. Regression watch: single-harness UX must not change (start, run, exit → rig stops).
