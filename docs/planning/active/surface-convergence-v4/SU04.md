# Phase 2.3: remove agent_jobs and obsolete trigger authority

## Description

Retire the substantial agent_jobs compatibility subsystem after callers have moved to canonical agents/work/foundation/provider ownership. Remove AgentTask and AgentTaskFactory compatibility authorities and route delegation through parent Work to child Work.

## Steps

1. Classify every agent_jobs module and symbol into agents, work, foundation, providers, or protocol adapter ownership.
2. Migrate callers and durable records to the owning public surface; preserve correlation and parent/child Work identity.
3. Delete obsolete agent_jobs modules, aliases, trigger authority, and compatibility tests once zero production references remain.
4. Add architecture scans that fail on reintroduction of agent_jobs, AgentTask, or AgentTaskFactory.
5. Validate queue, gateway, MCP, event, retry, resume, and protocol paths after deletion.

## Detailed Solution & Technical Design

Delegation is a Work relationship, not a second task model. Protocol adapters translate only; they do not regain dispatch or persistence authority. Preserve stable public error codes and redacted lifecycle timelines while removing the obsolete implementation.
