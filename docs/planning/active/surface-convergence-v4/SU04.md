# Phase 2.3: remove agent_jobs and obsolete trigger authority

## Description

Retire the remaining agent_jobs compatibility subsystem after the AG16/SU02/SU03 cutover. The inventory is now explicit: prompt parsing/templates/context and launch belong under agents/work admission; event trigger loading belongs to canonical Agents catalog configuration; packet execution belongs to provider execution; approvals/dead-letter/event observation belong to gateway operations. No production caller may retain the legacy package once those seams are migrated.

## Steps

1. Move prompt syntax, parser, aliases, targets, templates, context, launch, and session-input behavior to agents/work-owned modules with stable canonical imports.
2. Move trigger loading/matching to the canonical Agents configuration trigger owner and route event observer integration through gateway/work events.
3. Move packet execution to provider execution and approvals/dead-letter/event observer responsibilities to gateway operations, preserving public error/timeline contracts.
4. Migrate all production and test callers, then delete components/agent_jobs and its component descriptor/configuration.
5. Add a zero-reference architecture scan and run gateway, provider, work, and integration suites before closing.

## Detailed Solution & Technical Design

Delegation is a Work relationship, not a second task model. Protocol adapters translate only; they do not regain dispatch or persistence authority. Preserve stable public error codes and redacted lifecycle timelines while removing the obsolete implementation.
