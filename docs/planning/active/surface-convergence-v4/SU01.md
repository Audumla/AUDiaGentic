# Phase 0: inventory and reconcile the agent-surface cutover

## Description

Establish the current-tree baseline for the v4 agent-surface convergence before implementation. Reconcile the populated v4 runsheet against existing AS72/AS84/AS85/AS101/AS102/AS104 and active provider/session plans, classify every legacy seam, and record the current branch/base SHA without changing implementation code.

## Steps

1. Record current branch, HEAD, remote comparison, clean-tree status, and the populated runsheet revision.
2. Inventory agent_jobs, legacy role_api/agent_definition_api/execution_profile_api, mutable canonical models, duplicated capability/session types, provider load paths, surface resolution, gateway admission, and public projectors.
3. Map each finding to an existing plan item or a new v4 item; identify conflicts and ordering constraints.
4. Reconcile runsheet references and dependencies in plan metadata without duplicating owned implementation items.
5. Produce a checked-in inventory artifact or plan notes that state the exact Phase 1/2/3 gates and the stop condition before canonical CapabilityId work.

## Detailed Solution & Technical Design

Treat the runsheet as the execution contract and the current tree as authoritative when it differs from the reviewed remote SHA. Use read-only searches and plan/ledger metadata first. Do not implement compatibility aliases or a new canonical capability model during this phase. The inventory must distinguish configuration, capability, evidence, mechanism, policy, state, and projection ownership and must identify the exact production callers that block destructive removal.
