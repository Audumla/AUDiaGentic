# Phase 2.2: freeze canonical agent and execution projections

## Description

Make canonical AgentDefinition and ExecutionProfile values immutable and deterministic so admission, retry, resume, and provider materialization cannot observe mutation drift. Keep Role immutability/store replacement with AS84 as one invariant and do not create duplicate models.

## Steps

1. Confirm Phase 0 ownership map and AS84 Role/RoleStore boundary.
2. Freeze AgentDefinition with slots, immutable role-id tuples, and immutable advertised-skill tuples.
3. Freeze ExecutionProfile parameters recursively and instances as immutable tuples; remove default mutation paths.
4. Migrate callers that relied on mutation to explicit replacement at the owning repository/config boundary.
5. Add mutation-resistance, canonicalization, and fingerprint tests, including retry/resume equality.

## Detailed Solution & Technical Design

Use value objects at the configuration boundary and explicit replacement for changes. Do not hide mutable dictionaries behind frozen outer objects. Fingerprints must exclude prose, clocks, and mutable metadata. AS84 owns Role/RoleStore and manifest resolution; AS85 owns freezing the resolved manifest at admission.
