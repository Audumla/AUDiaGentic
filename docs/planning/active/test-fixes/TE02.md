# Fix failing unit tests — categorize and update tests to match new codebase behavior

## Description

Originally an inventory of 92 failing tests taken on 2026-07-29. Re-measured on 2026-08-02/03 with two things the original pass did not have: **the actual CI conclusion**, and **a Docker lane that was actually executed**. Both changed the picture materially.

**CI has been red for 100 consecutive runs**, 2026-07-18 to 2026-08-02 (96 `failure`, 4 `action_required`, zero success). Because `docker-tests` declares `needs: tests`, every one of those runs reported the entire 15-image Docker matrix as **`skipped`** — not failed. A skipped job is not a red X, so nothing ever surfaced it. Items were being closed against local runs the whole time.

So this item is not "some tests are failing". It is: **the project has had no working test gate for over two weeks, and no Docker-tier signal at all.**

The good news from actually running it: the Docker lane works. Built and ran `Dockerfile.test` to completion — 35 failures across 16 files, on Linux, from the current tree, and **the failure set overlaps CI's heavily**. CI red is reproducible locally in Docker. That makes this tractable: iterate in a container instead of push-and-pray.

## Detailed Solution & Technical Design

### Why the Docker tests never run

Four independent reasons, none of which produces a red signal.

1. **CI reports `skipped`, not `failed`** — `docker-tests` needs `tests`, which has failed 100/100 runs.
2. **Six images are never referenced by CI at all**, including the two most recently built.
3. **They self-skip locally.** 441 tests carry `mutates_host`; `tests/conftest.py` skips them unless `AUDIAGENTIC_DOCKER_TESTS=1`. `pytest tests/integration/providers/test_provider_full_lifecycle.py` on the host prints `99 skipped — provider lifecycle tests run in Docker` and exits 0.
4. **The main image excludes them by design.** `run_suite.sh` runs `-m "not mutates_host and not opt_in and not docker and not requires_docker"`. Correct — the specialised images own that coverage — but it means the image most people would call "the Docker tests" runs none of the Docker-only tests.

The mechanism is sound: every specialised image sets `ENV AUDIAGENTIC_DOCKER_TESTS=1`. **This is a wiring failure, not a design failure.**

**Two marker defects found alongside:**
- `requires_docker` matches **0 tests**, while the legacy `docker` alias it was meant to replace matches 8. `pyproject.toml` documents `requires_docker` as preferred and `docker` as kept for compatibility; the migration never happened. Every exclusion must name both, and one naming only `requires_docker` excludes nothing.
- `test_gateway_crash_matrix_docker.py` and `test_gateway_opencode_docker.py` each exist **twice**, under `tests/integration/agents/` and `tests/e2e/agents/`. The `mutates_host` markers are on the e2e copies; the Dockerfile CMDs run the integration copies.

### Why the suite cannot run in parallel

CI uses `-n auto --dist loadgroup`. Measured on 32 CPUs:

| Run | Time | Result |
|---|---|---|
| `pytest tests/unit` serial | 417-490s | green |
| `-n auto --dist loadgroup` | 50s | 10 failures |
| `-n auto --dist loadfile` | 65s | 1 failure |
| partitioned runner (5 phases) | 84s | green 1 run in 3 |

So the ~8 minute cost is not inherent — it is the cost of running serially. But parallel is not reliably green, and **marking tests cannot fix it**: three consecutive partitioned runs produced one green and two with a *different* failing test each. The set of parallel-unsafe tests is not a fixed list; it is emergent from shared global state and shifts with worker packing.

**Root cause.** The root `tests/conftest.py` has an autouse `_reset_test_registries` fixture that clears the feature registry and resets the component, provider-descriptor and language registries **before every unit test in the repository**. The whole suite then depends on lazy repopulation being perfect on every access, and it is not — pi's contribution renderer, registered from a custom `surface.py` at import time, is never restored after a reset. Serially one fixed module order happens to warm what is needed; in parallel each worker sees a different order.

Corroboration: `tests/docker/run_suite.sh` is already deliberately serial, commenting that lifecycle/surface hooks "share process registries and toolchain caches which are not safe under xdist's parallel test processes." Someone hit this and worked around it by giving up parallelism in that lane.

**Suggested fix:** make reset-and-repopulate exact, or stop resetting global registries per test and give the few tests that need a clean registry an explicit fixture. The second is likely correct — an autouse global reset for 4102 tests to serve a handful is the wrong default.

Also on this pile: CI shows `OSError: [Errno 98] Address already in use` at gateway test setup, a port-binding collision under parallel execution not reproducible on Windows.

### What has already been done (2026-08-02/03)

- `--dist loadfile` established as correct; `loadgroup` is not.
- `no_parallel` now genuinely isolates. It previously only added an `xdist_group`, which pins a module to one worker while that worker still runs unrelated tests — it never provided the guarantee its docstring claimed. `tests/conftest.py` now deselects `no_parallel` tests from any `-n` run and reports the held-back count via `pytest_terminal_summary`, so a green parallel run cannot be mistaken for a complete one. `AUDIAGENTIC_SERIAL_PHASE=1` opts back in. Detection checks both `config.option.numprocesses` and `config.workerinput`, because the collection hook also runs inside each worker where `numprocesses` is unset.
- `tools/run_unit_suite.py` added: five phases (non-foundation parallel, foundation parallel, serial `no_parallel`, then two files in their own processes because they register components against synthetic config trees that replace the live registries and error catalogue).
- Launch-builder failures are no longer swallowed — `prepare_provider_session_transport` reports `unavailable_code`/`unavailable_message` instead of a bare `transport=None`. This paid off immediately: the Docker run reported `RES-PIACP-002 'Pi CLI not found while preparing isolated Pi ACP launch'` rather than `assert None is not None`.
- AS41's gate extended from `requires_npm` to also require the `pi` and `opencode` CLIs — the Docker image ships Node but no provider CLIs, so an npx-only gate let the tests run and fail.

### Related unregistered-error-code defect

38 of 70 statically-resolvable `make_error(...)` codes are absent from the error catalogue, plus 22 sites computing `number=` dynamically that cannot be checked statically. `test_error_resolutions.py` regexes for quoted code literals, and `make_error` builds the code from kwargs, so none are visible to it. These raise `ValueError` instead of the intended error — but only once resolutions have been loaded, which is why the defect is order-dependent. Confirmed live in the Docker run, where `RES-PIACP-002` constructed successfully because the catalogue had not yet loaded. Tracked separately as AS72.

## Effort & Risk

Large but highly parallelisable; each category lands independently.

Steps 1-5 are hours, not days, and carry almost no risk — they are workflow and config wiring. They should not be bundled with the rest, because until they land nobody can measure anything reliably.

Steps 6-9 are mechanical once the baseline is known. The main risk is **scope illusion**: step 1 may clear a meaningful fraction at zero cost, so re-measure before estimating.

Step 10 is the genuinely hard one. The registry-reset design is load-bearing for 4102 tests and the surfaces registry already carries several rounds of accumulated workarounds for reset handling, which suggests a comment-level patch will not hold.

Step 3 carries unknown cost: six images have never run, and two weeks of unrun matrix entries may have rotted independently of anything here. Expect surprises there rather than assuming they pass.

## Standards

- `arch-standards` §7 Enforcement — "architecture rules must have proportionate automated checks", and "validation scope matches the change; do not call a subset the full suite". A gate red for 100 consecutive runs enforces nothing, and `needs:` turns one red job into fifteen silently skipped ones. An 8-minute serial suite is one that gets skipped; making it ~1 minute makes the rule followable.
- `arch-standards` §4 Public Contracts — error codes are a stable public contract; codes that cannot be constructed are broken contracts. Failures must be classified and degraded state reported, not swallowed into a bare `None`.
- `arch-standards` §3 Evidence-led scope — every count and timing here is measured: run counts and dates from the GitHub API, the failure list from `gh run view --log-failed` on run 30736632437, timings from this machine, the Docker results from an actual container run. Items that could not be verified are marked as such rather than inferred.
- `CREATING_PLANS.md` §5 — the Definition-of-Done "full unit suite green" checkbox was satisfied locally while the real gate was red throughout. The checkbox needs to mean the actual gate.
