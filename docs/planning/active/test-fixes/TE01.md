# Fix test suite failures: circular import, CFG-PATHS-001, Windows permissions, schema validation

## Description

### Test failure summary

**Host suite**: 157 failed, 1916 passed, 316 skipped, 1 error in ~67s
**Docker suite**: Additional failures in container (release-bootstrap CLI CFG-PATHS-001, comprehensive provider test)

### Root cause categories

#### 1. Circular import: Registry.register(replace=True) triggers recursive load_providers()

Call chain:
```
_registry.pop(key) with replace=True
 -> _ensure_loaded()
 -> _ensure_provider_modules_registered()
 -> importlib.import_module("audiagentic.components.providers")
 -> adapters/__init__.py : load_providers()
 -> _discover_adapter_packages() imports aider/surface.py
 -> register_contribution_renderer("aider", ..., replace=True)
 -> _contribution_renderer_registry.pop("aider") — triggers ANOTHER _ensure_loaded()
 -> claude/hooks.py -> restrictions_loader.py -> package.py
 -> find_repo_root() fails with CFG-PATHS-001 in pip-installed context
```

Affected files:
- `src/audiagentic/foundation/registry_utils.py:77` — `register()` calls `self.pop(key)` on replace
- `src/audiagentic/foundation/registry_utils.py:163` — `pop()` always calls `_ensure_loaded()`
- `src/audiagentic/components/providers/surfaces/registry.py:57` — `register_contribution_renderer` uses `replace=True`
- All surface modules that call `register_renderer` or `register_contribution_renderer` at import time

Affected tests (~120 failures):
- `tests/integration/lifecycle/test_component_lifecycle.py` — all parametrized variants (install, disable, enable, uninstall, roundtrip, no_sync_field)
- `tests/e2e/cli/test_component_cli.py` — component install/status/uninstall lifecycle
- `tests/e2e/cli/test_release_bootstrap_cli.py` — all 6 release-bootstrap tests
- `tests/e2e/cli/test_install_file_content.py` — all 8 file content tests
- `tests/integration/planning/test_planning_provisioning.py` — all 10 planning provisioning tests
- `tests/integration/release/test_end_to_end_release_flow.py`
- `tests/unit/providers/test_provisioning.py` — all provider CLI and reconcile tests
- `tests/unit/memory/` — memory status, backend config, hindsight provision tests
- `tests/unit/lifecycle/test_harness_seam.py` — lifecycle handler tests
- `tests/integration/jobs/test_job_approvals.py`

#### 2. find_repo_root() at module level in package.py

`src/audiagentic/foundation/paths/package.py:54` executes `REPO_ROOT = find_repo_root()` at import time.
This breaks when the package is pip-installed (wheel) or when running from tmp_path.
The error propagates to any adapter that indirectly imports `package.py` (claude/restrictions_loader.py).

#### 3. Windows permission errors in MCP sync during fresh install

```
PermissionError: [WinError 5] Access is denied:
  'C:\Users\mgs\.gemini\antigravity\mcp_config.json'
  'C:\Users\mgs\.claude\mcp.json'
```

`src/audiagentic/components/providers/services/mcp_sync.py:34` calls `sync_all_provider_mcp_servers()`
during component install, which tries to write to provider home directories.
On Windows these may be locked by the running provider process or owned by another user.

Affected test:
- `tests/e2e/lifecycle/test_fresh_install.py::test_fresh_install_creates_scaffold_and_manifest`

#### 4. Schema validation error in fresh install

`assert not list(validator.iter_errors(project_cfg))` fails with "None is not of type 'object'".
A field in the generated project config is None instead of an object/dict.

Affected test:
- `tests/e2e/lifecycle/test_fresh_install.py::test_fresh_install_creates_scaffold_and_manifest`

#### 5. Missing uninstall recipe for antigravity provider (Docker only)

`src/audiagentic/components/providers/adapters/antigravity/descriptor.yaml` has no `cli_install.uninstall` step.
Test `test_cli_providers_have_install_recipe[antigravity]` asserts all CLI providers have both install and uninstall.

### Considered solutions

#### Solution A: Add `bypass_loader=True` to Registry.pop() + remove replace=True from surface registrations

**Changes:**
1. `registry_utils.py`: Add `bypass_loader` parameter to `pop()` — when key not in `_items`, skip `_ensure_loaded()` entirely since there is nothing to load/evict.
2. `surfaces/registry.py`: Remove `replace=True` from both `register_renderer` and `register_contribution_renderer`. These are initial registrations at module import time; no prior value exists.

**Pros:** Minimal code change (2-3 lines). Fixes the recursion by default path — pop on non-existent key is a no-op without triggering loader. Safe because initial registration never needs replacement.

**Cons:** If a test or hot-reload scenario re-registers the same key, it would need to call `pop()` explicitly first (unlikely in current codebase).

#### Solution B: Add `dry_pop` internal method to Registry and use in surface registrations

**Changes:**
1. `registry_utils.py`: Add `_pop_if_exists(key)` that skips `_ensure_loaded()` when key not present.
2. `surfaces/registry.py`: Change `register_contribution_renderer` to call `self._pop_if_exists(key)` before `self._items[key] = value`.

**Pros:** More explicit about intent. Preserves existing `replace=True` semantics for external callers.

**Cons:** More invasive. Requires modifying registration API surface. External callers that use `replace=True` would still trigger loader on miss.

#### Solution C: Guard _ensure_loaded() with recursion detection at Registry level

**Changes:**
1. `registry_utils.py`: Add `_recursion_depth` counter. When `_ensure_loaded()` detects depth > 1, skip loading and log warning.
2. No changes to surface modules needed.

**Pros:** Fixes issue everywhere without touching consumer code. Self-healing.

**Cons:** Masks underlying architectural problem. Could hide legitimate bugs where recursive registration indicates broken module ordering. The `_loading` flag already exists but is set/cleared per-call and does not protect against sequential (not nested) invocations from `pop()`.

#### Solution D: Defer provider module loading to explicit init call

**Changes:**
1. Remove all module-level `register_renderer` / `register_contribution_renderer` calls from surface modules.
2. Create a `load_all_surfaces()` function that explicitly imports and registers all surfaces in controlled order.
3. Call this from the component lifecycle observer instead of relying on import-time side effects.

**Pros:** Eliminates circular import risk entirely. Cleaner module architecture — no hidden import-time side effects.

**Cons:** Large refactoring across ~15 adapter surface modules. Requires adding explicit loading call to every code path that needs renderers (CLI, MCP tools, provisioning).

#### For CFG-PATHS-001 in package.py

**Solution E: Lazy REPO_ROOT resolution**
Replace module-level `REPO_ROOT = find_repo_root()` with a lazy property or `@lru_cache` function. Consumers call `get_repo_root()` instead of accessing `REPO_ROOT` directly.

**Pros:** Works in both dev and pip-installed contexts. Backward compatible via property alias.

**Cons:** Requires updating all import sites that use `REPO_ROOT` (claude/restrictions_loader.py and potentially others). Adds indirection to a simple constant.

#### For Windows permission errors

**Solution F: Catch and log PermissionError in MCP sync, do not abort install**
The mcp_sync already wraps each provider sync in try/except; extend to catch PermissionError alongside existing exceptions. This is consistent with the documented behavior that MCP sync failures are non-fatal warnings.

**Pros:** Minimal change. Aligns with existing error handling philosophy (sync failures warn, do not abort).

**Cons:** Does not fix the underlying Windows file-lock issue; just makes it non-fatal.

#### For antigravity missing uninstall recipe

**Solution G: Add uninstall step to antigravity descriptor**
The provider installs via script; uninstall should remove the installed executable/config. If truly uninstallable, add `uninstall` ShellStep that removes the installed binary.

---

### Preferred option

**A + F + G** — Surgical fixes for each root cause:

1. **A**: `Registry.pop(bypass_loader=True)` when key absent + remove `replace=True` from surface registrations. This is the smallest change with maximum impact (~120 test failures resolved). The rationale: `pop()` on a non-existent key should never trigger lazy loading because there is nothing to evict and no reason to ensure all items are registered first.

2. **F**: Extend mcp_sync exception handling to catch `PermissionError`. This resolves the Windows fresh-install failure without requiring docker for every test run.

3. **G**: Add `uninstall` ShellStep to antigravity provider descriptor. One-line YAML fix that satisfies the comprehensive test assertion.

**Why not C (recursion guard):** It masks a legitimate architectural issue where registration triggers loading during loading. Fixing the trigger point (Solution A) is more correct than suppressing the symptom.

**Why not D (deferred loading):** The refactoring scope is too large for the benefit gained. Solution A resolves the immediate failure while preserving current module structure. If deferred loading becomes desirable later, it can be a follow-up refactor.

**Why not E (lazy REPO_ROOT):** `find_repo_root()` already supports env var override and works in dev checkout. The CFG-PATHS-001 error only surfaces because of the circular import chain (root cause 1). Fixing root cause 1 prevents `package.py` from being imported during provider loading, which eliminates this secondary failure.

## Notes

The Registry._loading guard at line 53 already prevents nested _ensure_loaded() calls, but pop() triggers _ensure_loaded() BEFORE _loading is checked because register() calls pop() synchronously within the loader's execution context. The _loading flag protects against truly recursive entry into _ensure_loaded(), but does not prevent sequential pop-triggered loads from a different registry instance sharing the same loader function.
