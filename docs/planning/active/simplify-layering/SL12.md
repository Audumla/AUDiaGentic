# Extract five install patterns to foundation/toolchains recipe_patterns.py

## Description

With boundary stamping and action_needed promotion delivered by SL11, the five reusable install patterns instantiated by copy in hindsight/recipes.py (1064 lines, ~250 genuinely domain-specific) can be extracted to foundation as data-parameterized pattern classes returning plain RecipeResult. Rule-of-three satisfied WITHIN current code: installer block has 3 in-file copies, entry pattern has 2 + the services/mcp adapter.

Patterns to extract:
(a) DeclaredInstallerRecipe: install/uninstall step dicts, source-status gate, status-command probe, params. Covers the triplicated installer block in PluginConfigRecipe, _PluginUrlConfigRecipe, and one other (~100 lines across 3 sites). HooksInstallerRecipe as subclass supplying row data + provenance.
(b) ManagedEntryRecipe: FragmentStore + injected registry io + owner scope + entry name/payload builder. Covers _PluginArrayRecipe and _McpConfigAdapter — the recipe face of SL10's fragment engine. _McpConfigAdapter's probe/verify currently delegate to HindsightMcpRecipe reader-comparison; fold that comparison into ManagedEntryRecipe.probe(expected payload). If wiring covers HindsightMcpRecipe entirely, DELETE it and HindsightTarget; migrate their unit tests to the pattern.
(c) CompositeRecipe: children list with per-primitive RecipeResult field merge and state combination table (~175 lines of mechanical merging).
(d) NoAutomationRecipe (was GuidanceOnlyRecipe): guidance statuses + action_needed string — generic shape parameterized by text.
(e) OwnedFileRecipe: path, expected_dict_fn, post_configure hook for Windows repair scenario.

Target: recipe_patterns.py beside recipe_contract — all data-parameterized, all returning plain RecipeResult, zero component imports (boundary-tested like fragments.py). Hindsight/recipes.py shrinks to ~350-400 lines of domain content: param vocabulary, plugin JSON schema, Windows plugin repair hooks, rule text, per-row pattern wiring.

## Steps

1. Extract DeclaredInstallerRecipe to foundation/toolchains/recipe_patterns.py: fields = install_steps/uninstall_steps (dicts), status_command, source_status, gate_message/notes, params; optional CommandProbe; install/uninstall = gated run_steps. HooksInstallerRecipe as subclass supplying data + provenance — rename if 'hooks' or 'row' is hindsight-specific vocabulary (Std §1 domain-neutral naming); use generic parameter names and adapt hindsight vocabulary at the wiring layer. De-duplicate the 3 in-repo instantiation sites via delegation (pick composition OR mixin — no parallel paths).
2. Extract ManagedEntryRecipe: FragmentStore wrapper with injected registry io, owner scope, entry name/payload builder. _PluginArrayRecipe becomes wiring (store from row-declared reader/writer/remover with signature adaptation). _McpConfigAdapter becomes wiring (store from descriptor spec, managed-mcp registry io, HINDSIGHT_MANAGED_ID); fold its probe/verify reader-comparison into ManagedEntryRecipe.probe(expected payload). Evaluate HindsightMcpRecipe consumer count — if PluginConfigRecipe._inner wiring covers it, DELETE HindsightMcpRecipe + HindsightTarget and migrate unit tests to pattern.
3. Extract CompositeRecipe (children: list[recipe]; per-primitive merge; state combination table) and NoAutomationRecipe (statuses + action_needed) and OwnedFileRecipe (path, expected_dict_fn, post_configure hook). Hindsight classes become thin wiring subclasses or direct instantiations in strategies.py.
4. Boundary test: recipe_patterns.py imports nothing from audiagentic.components (mirror test_fragments.py guard pattern).
5. Migrate hindsight unit tests that pin implementation details of deleted/absorbed classes; keep behavior goldens as safety net. Full unit suite + integration/e2e green; ruff clean.
6. Update providers/services/recipes.py and hindsight READMEs/docstrings: foundation = lifecycle + patterns (SL11 boundary + SL12 patterns); providers = registry + provenance overlay; capability = data + wiring.
