# Descriptor bloat

## Description

`ComponentDescriptor` (src/audiagentic/foundation/components/base.py, frozen dataclass) carries ~20 fields. Most components use a subset. The fat dataclass forces every consumer to carry unused fields and obscures which fields matter per component.

SCOPE CORRECTION vs original draft: the original said 'every component constructs the descriptor' and estimated '8+ component loaders'. That is WRONG. `ComponentDescriptor(...)` is constructed in exactly TWO places, both in `foundation/components/loader.py` (the provisional at ~line 123 and the final at ~line 144). All descriptors are built centrally from YAML by `register_from_yaml()`. Components do NOT hand-construct descriptors. This massively de-risks the refactor: construction changes are confined to one file.

Field CONSUMERS (read `.field`) span ~17 files (38 attribute reads): mcp_collector, registry, loader, system_prompt, hooks, reconcile, lifecycle, component_server, mcp_projection, external_mcp_probe, runtime/lifecycle/components.py, component_mcp + tests. These read fields like `.mcp_servers`, `.external_mcp_servers`, `.harness_instructions`, `.lifecycle_observer`, `.lifecycle_hook`, `.implementation_cardinality`, `.post_install`, `.status_hook`.

DECISION POINT (resolve before coding): two viable approaches — (A) keep a flat frozen dataclass but GROUP construction via small focused sub-dataclasses internally, OR (B) full mixin/composition split. Given consumers read ~38 flat attributes, a full split forces touching all 17 files. RECOMMENDED: approach (A-lite) — keep flat public attribute API (zero consumer changes), introduce focused grouping ONLY where it reduces loader noise. See steps.

## Steps

**Pre-work / validate-first:** Confirm the construction-site count by grep `ComponentDescriptor(` — expect 2 real sites in loader.py (plus test fixtures). If hand-constructed descriptors exist outside loader.py + tests, STOP and re-scope.

**RECOMMENDED APPROACH (A-lite): preserve flat attribute API, reduce construction surface.**
The value here is reducing maintenance noise, NOT changing the data model. A full mixin split that breaks 38 attribute reads is high-cost / low-value (original assessment: 'no immediate value').

1. Keep `ComponentDescriptor` flat and frozen so all `.field` reads in the 17 consumer files keep working unchanged.
2. Add a classmethod `ComponentDescriptor.from_yaml(data: dict, *, yaml_path: Path) -> ComponentDescriptor` that absorbs the parsing currently inlined in `loader.register_from_yaml` (files tuple, mcp_servers, external_mcp_servers, harness_instructions, scalar fields). This moves construction logic off the loader and onto the descriptor, shrinking loader.py to orchestration.
3. Extract the repeated sub-parsers (`_parse_files`, `_parse_mcp_servers`, `_parse_external_mcp_servers`, `_parse_harness_instructions`) as module-level helpers in base.py so the provisional-descriptor path (loader.py ~123) and final path (~144) share them — today they duplicate this.
4. Add field-group DOC comments in base.py clustering the ~20 fields by concern (identity / files / mcp / lifecycle-hooks / feature) so the relevance-per-component is documented even though storage stays flat.

**IF approach (B) full split is chosen instead (only if user explicitly wants the data model changed):**
1. In base.py define nested frozen dataclasses: `BaseDescriptor`(component_id, display_name, description, detection_marker, aliases, scope, core, type), `FileSpec`(files, depends_on, yaml_path), `McpSpec`(mcp_servers, external_mcp_servers), `LifecycleSpec`(post_install, lifecycle_observer, lifecycle_hook, status_hook, harness_instructions), `FeatureSpec`(implementation_cardinality).
2. Compose into `ComponentDescriptor` holding the 5 sub-objects.
3. ADD backward-compat `@property` shims for every currently-read flat attribute (`mcp_servers` -> `self.mcp.mcp_servers`, etc.) so the 17 consumer files do NOT need editing. This is mandatory to keep effort bounded.
4. Update the 2 construction sites in loader.py to build sub-objects.
5. Update test fixtures that construct `ComponentDescriptor(...)` directly (test_component_registry, test_component_scope, test_component_loader_ids, test_component_mcp_launch_shape).
