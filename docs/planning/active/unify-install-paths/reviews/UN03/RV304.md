# Standards reconciliation: §15 probe output, §10 clean removal, §8 codes for probe parser

## Notes

Cross-checked UN03 against ARCHITECTURE_STANDARDS.md.

## Findings

1. §10 Migration Doctrine: replacing the four private _resolve_probe_* closures must DELETE them outright (no shim), grep the repo incl tests/ for their names, and prove a green full suite. Add explicitly.
2. §15 Output Redaction: the command-probe path (CommandProbe / _resolve_probe_command) captures subprocess output; where that output is surfaced in a ProbeResult.detail or any structured return/log, redact via redact_text(). Pure boolean/exit-code probes that discard output are §15-exempt ('captured-and-discarded output when only exit code is used') — call out which probes are exempt so the agent doesn't over-redact.
3. §8 Error Handling: probe_from_spec on a malformed/unknown prefix must raise a registered AudiaGenticError code (e.g. VAL-PROBE-NNN) added to the owning foundation/toolchains error-resolutions owner first, not a raw ValueError. The current closures likely slice strings without validation; define the error path.
4. §2 Config Over Code: the prefix->resolver mapping must be a (prefix, handler) registry, not an if/elif chain on prefix strings, so new probe kinds are added by registration.
5. §3: keep probe_from_spec cohesive; if it grows, the registry split handles it.

## Conclusion

Incorporate into UN03. Emphasize the (prefix,handler) registry (§2) and the §15 exempt-vs-redact distinction.
