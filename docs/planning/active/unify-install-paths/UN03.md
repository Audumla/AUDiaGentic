# Fold component-dependency probe resolvers and install flow into the toolchains probe/recipe vocabulary

## Description

`foundation/components/dependencies.py` is a third partial re-derivation of the probe→install→verify shape. It loads dependency declarations from component YAML, builds SequenceStep/SelectStep trees via `toolchains/loader.build_step`, and runs them through the workflow runner — which is fine — but it also implements its own probe mini-language (`_resolve_probe_binary`, `_resolve_probe_all_binaries` for 'all-binaries:a,b', `_resolve_probe_path` with ~ expansion, `_resolve_probe_command` with its own subprocess.run/timeout/error handling) that duplicates `foundation/toolchains/probes.py` (`CommandProbe`, `tool_available`, `safe_command_parts`).

**Solution:**

1. **Single probe vocabulary in toolchains/probes.py.** Extend it with the spec-string parser currently private to dependencies.py: `probe_from_spec(spec: str) -> Probe` supporting `binary:`, `all-binaries:`, `path:` (with home expansion), `command:` prefixes. Each returns a probe object with a uniform `check() -> ProbeResult` (CommandProbe already has this shape). dependencies.py's closures become thin calls into this parser.
2. **Reuse, not rewrite, the execution.** Dependencies remain 'workflow steps, no separate orchestration lane' (per the module docstring) — do NOT force them into full ProvisioningRecipe lifecycles; they have no uninstall/prune semantics today and inventing them is scope creep. The consolidation is limited to: (a) probes come from toolchains/probes, (b) steps come from the unified step system (automatic once UN01 lands), (c) result/reporting uses the unified StepResult vocabulary.
3. **Optional stretch (decide during implementation, do not commit blindly):** if after UN01+UN02 the `DeclaredStepRecipe` covers dependencies' select-by-package-manager pattern via a SelectStep inside an InstallManifest, migrate component dependencies to registry-dispatched recipes keyed `(component_id, 'dependency', name)`. Only do this if it deletes more code than it adds — measure by diff stat; otherwise record a note and stop at probe unification.

## Effort & Risk

Effort: ~1 session (probe unification) + optional 1 session (stretch). Risk: LOW — pure internal refactor behind stable YAML schema and public API. Main hazard is subtle probe semantics drift (timeout values: dependencies.py uses 10s, CommandProbe defaults 15s in DeclaredStepRecipe usage) — keep per-call timeouts explicit and match existing values.
