# Audit remaining bespoke installers (harness pi/opencode, release-please, LSP language servers) — migrate to recipe contract or document exemption

## Description

Beyond the two main lanes, four installers were identified but not audited in depth during the consolidation analysis (2026-07-12). Each independently implements some subset of probe/install/verify/uninstall and may be a candidate for `DeclaredStepRecipe`/`ProvisioningRecipe` — or may have a legitimate reason to stay bespoke. This item is the disposition pass: for each, either migrate it onto the unified contract or record a written exemption with rationale in its README, so no installer's status is ambiguous.

**Inventory to audit:**

1. **runtime/harness/pi/install/** (config.py, patches.py, constants.py) — pi harness installation, includes template/home provisioning and patching. Likely partially exempt: harness install may be entangled with runtime provisioning events; but any 'run installer command, probe result' portions should ride DeclaredStepRecipe.
2. **runtime/harness/opencode/install/** — same question for the opencode harness.
3. **components/release/release_please/install.py** (+ manage.py) — installs the release-please workflow files/templates into the project. This is mostly WriteFileStep/ManagedBlock-shaped work; strong candidate for a declared-step recipe with prune semantics (managed workflow files are exactly what artifact ownership tracking in RecipeResult.artifacts_owned is for).
4. **components/coding_lsp/language_servers_sync.py** (+ language_registry.py, coding_lsp_bootstrap.py) — installs/synchronizes language servers per feature YAML. Already consumes toolchains detection; the sync loop (desired-set vs installed-set, add missing, remove stale) resembles the hindsight prune-stale pattern in provision.py — evaluate whether registry dispatch + prune fits.

**Also in scope, decision-only:** the two reconcile loops — providers/services/reconcile.py (probe host → enable/disable → apply/prune surfaces) and memory/hindsight/provision.py `reconcile_hindsight` (enabled set → apply, stale set → prune, disabled → teardown). They rhyme; assess whether a shared 'reconcile(desired_ids, all_ids, apply_fn, prune_fn, teardown_fn)' helper in foundation earns its keep or whether the shared skeleton is too small to abstract. Record the decision either way; do not force an abstraction.

**Per-installer method:** (a) read the module and its tests; (b) classify each operation as declared-step-shaped (shell/config/write/managed-block), probe-shaped, or genuinely bespoke (event wiring, template rendering with logic, API calls); (c) if ≥70% of the module is declared-step-shaped, migrate; otherwise exempt with rationale; (d) migrations follow the UN02 pattern: recipe + registry key + boundary adapter preserving existing result payloads.

## Steps

1. VALIDATE FIRST: green baseline for harness install tests, release-please tests, coding-lsp sync tests.
2. Audit runtime/harness/pi/install and opencode/install; write disposition (migrate/exempt + rationale) into this item; implement migrations if chosen.
3. Audit components/release/release_please/install.py; expected outcome: migrate file provisioning to WriteFileStep/ManagedBlockStep-based DeclaredStepRecipe with artifacts_owned tracking; keep GitHub API interactions (auth, workflow dispatch) out of recipes.
4. Audit components/coding_lsp/language_servers_sync.py; expected outcome: language-server install/uninstall commands become declared-step recipes keyed (implementation_id, 'language-server', feature); the desired/stale sync loop stays a caller-side reconcile like hindsight's.
5. Decide the shared-reconcile-helper question with a diff-stat measurement; record decision.
6. For every module left bespoke, add an 'Install-path exemption' note to its README stating why (so future audits don't re-litigate).
7. Update docs/reference or architecture standards if a new norm emerges ('all installers ride ProvisioningRecipe unless exempted in README'); consider proposing it as a standard via plan_list_standards conventions.
8. Record ledger change event.
