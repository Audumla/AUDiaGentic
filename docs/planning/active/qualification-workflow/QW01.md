This item was moved from the gpt-auto-conversation project; its canonical owner is qualification-workflow. Scope covers planning item/review CRUD, state/list tools, and management/config tools exposed by the planning MCP server.

## Detailed Solution & Technical Design

Add src/audiagentic/components/planning/contracts.py. Define ItemState, ItemStateFilter, ReviewState, ReviewStateFilter, Work, Skill, Priority, PageLimit (1..100), and Offset (>=0). Use PlanItemCreate/PlanItemUpdates/PlanReviewCreate/PlanReviewUpdates models with optional-in-presence fields, extra=allow for intentional custom sections, supported aliases, and model_fields_set/exclude_unset so omitted means untouched while explicit null remains compatible. plan_update_item/update_review must exclude protected identity, storage, link, and state fields; state changes use plan_set_state/plan_set_review_state. planning_set_config gets only a typed outer request; descriptor options_schema remains authoritative for implementation-specific keys. FastMCP/Pydantic owns missing args, wrong types, static literals, bounds, and unknown top-level arguments. Invoked cross-field, protected-field, empty-update, append, dynamic-config, existence/kind, and persisted workflow checks use AudiaGenticError and registered VAL-PLN-* codes. Do not add tags or typed response models in QW01.

## Code Samples & Guidance

### Append contract

`append` is a list of section names, not content. The content must be in
`updates`:

```json
{
  "item_id": "GP06",
  "updates": {"notes": "new text"},
  "append": ["notes"]
}
```

The broken call that motivated this item was:

```json
{
  "item_id": "GP06",
  "updates": {},
  "append": ["DIAGNOSTIC PROBE ec9f1a"]
}
```

That previously returned success while making no visible change because
`updates` was empty and the append value was treated as a section key. The
same behavior was reproduced across GP01, GP06, HI18, HI138, and TO01.
The workaround was fetch-then-concatenate into `updates.notes`.

The implementation now rejects malformed calls with bounded, actionable
errors:

- `VAL-PLN-027`: append supplied without update content.
- `VAL-PLN-028`: an append entry is absent from `updates`.

Raw append values are deliberately excluded from error details because they
could contain prompts, credentials, or PII.

### Proposed typed request model

Use FastMCP/Pydantic models with optional-in-presence update fields:

```python
AppendField = Literal[
    "description", "steps", "detailed_solution", "code_samples",
    "files", "validation", "effort_risk", "standards",
    "acceptance_criteria", "notes",
]

class PlanItemUpdates(BaseModel):
    model_config = ConfigDict(extra="forbid")
    title: str | None = None
    description: str | None = None
    steps: str | None = None
    detailed_solution: str | None = None
    code_samples: str | None = None
    files: str | None = None
    validation: str | None = None
    effort_risk: str | None = None
    standards: str | None = None
    acceptance_criteria: str | None = None
    notes: str | None = None
    work: Literal["S", "M", "L"] | None = None
    skill: Literal["basic", "intermediate", "advanced"] | None = None
    state: Literal["pending", "in_progress", "completed", "superseded", "deprecated"] | None = None
    priority: Literal["P0", "P1", "P2", "P3"] | None = None
    order: Annotated[int, Field(ge=0)] | None = None
    tags: list[NonEmptyString] | None = None
```

Runtime validators must additionally enforce non-empty supplied fields,
unique tags, unique append entries, and
`append ⊆ updates.model_fields_set`. Legal state transitions and persisted
project policy remain domain-layer checks.

`additionalProperties=false` is a potentially breaking change because the
current API may accept arbitrary custom body sections. Audit real callers and
existing payloads before enabling it.
