# Placeholder: retire the per-type runtime/harness/<type>/ package requirement once HA06+HA07 land

## Description

PLACEHOLDER -- do not implement until HA06 (ACP broadening, itself blocked on the AS19 foundation) and HA07 (generic materialize) both land. 'Harness' is a capability (declares interactive/agent launch capability + a materialize capability), not a hardcoded identity -- pi and opencode are just the two providers that currently clear that bar. runtime/harness/__init__.py's _mod() dispatcher (get_harness_type()'s own resolution is already fully open/config-driven, no hardcoded list) still requires runtime.harness.<type>.install/runner to exist as an actual importable Python package via importlib -- that's the one remaining piece of transitional debt tying 'harness' to a closed set.
