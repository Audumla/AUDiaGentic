# Converge Pi harness materialization on managed owners

## Description

Separate Pi runtime assets from provider/project configuration. Runtime retains binaries, embedded runtime home, models, and bounded package patches; provider config and surfaces use final MA16 families.

## Steps

1. Characterize Pi mutations and assign each to runtime asset, CLI desired state, managed MCP, provider-specific configuration, generated surface, model projection, or third-party patch.
2. Freeze golden ownership manifest.
3. Runtime calls each required providers_api family explicitly; no universal reconcile, second gateway, or provider internals.
4. Keep embedded runtime-home assets registered and runtime-owned.
5. Move Pi provider serializers/mechanics into providers.
6. Adopt exact provider/project entries only; prune only owned scope.
7. Gate package patches by version/precondition/idempotence/atomic restoration.
8. Migrate install/refresh/uninstall together and delete stale wrappers, serializers, aliases, and compatibility routes.
9. Verify uninstall preserves models, logs, and user assets.

## Detailed Solution & Technical Design

Runtime layer keeps only: binaries, embedded runtime home, models, bounded package patches (mcp_exclusive_patch.py already lives under components/providers/adapters/pi/, correctly out of runtime), ephemeral runtime-root allocation, request cleanup.

Remove/move from runtime/harness/pi/:
- mcp_format.py's independent serializer (_entry_to_pi_cfg, read_pi_mcp_json, write_pi_mcp_json) -- consolidate onto the shared foundation/mcp/json_format.py projection per RU03, matching the pattern OpenCode's mcp_format.py already uses.
- install/__init__.py's local mcp_config_path/read_mcp_config/write_mcp_config/remove_mcp_config wrappers (~157-176) -- remove once mcp_format.py is consolidated.

Runtime boundary (folds in RU04's ownership doctrine, scoped to Pi): runtime SHOULD own native harness resolution, install/lifecycle composition, runner argument/environment construction, ephemeral runtime-root allocation, request cleanup, rig attachment, embedded runtime-home assets, bounded upstream package patches. Runtime should NOT own MCP selection policy, provider serializers, provider capability declarations, model-source ownership, or provider/project surface writers -- those move to the providers component.
