# Align launch recipe mechanism across one-shot, ACP, and interactive kinds

## Description

AUDiaGentic launches a provider CLI in three shapes (one-shot execution, ACP live session, interactive TUI) with three different degrees of recipe-ness: one-shot is declarative via the descriptor execution: block for 7 providers; ACP and interactive are hand-written Python only. The launch spec value is duplicated (AcpLaunch and InteractiveLaunch are byte-for-byte identical dataclasses; one-shot never surfaces its spec as a value). Align all three onto one layered mechanism: recipe (or hand-written builder escape hatch) -> normalized ProviderLaunch spec -> kind-keyed spawn strategy. Key insight (from live design review): Pi's interactive 'conditionals' are a config-modeling artifact (mutually-exclusive tools control modeled as three overlapping booleans no_all/no_builtin/allow) not irreducible logic -- fix the data model (tools.mode enum) and extend the recipe's existing flag-map vocabulary (approval-mode-flags is already an enum->flags map; model-flag is already a value-flag) rather than adding a conditional mini-language to YAML. Full design in the approved plan file elegant-crunching-shell.md.
