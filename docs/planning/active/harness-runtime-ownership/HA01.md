# Converge OpenCode harness materialization on managed owners

## Description

Remove OpenCode runtime ownership of provider/project configuration. Runtime retains CLI/runtime assets and composes final MA16 provider families; provider and surface owners manage their state.

## Steps

1. Characterize OpenCode install/refresh outputs and unmanaged-content behavior.
2. Consume MO03 canonical path/container decision.
3. Classify each action as CLI desired state, model projection, managed MCP, generated surface, or runtime-owned asset.
4. Runtime calls each required providers_api family explicitly and sequences partial results. No universal reconcile, provider internals, or second gateway.
5. Installer owns executable/runtime assets only; provider families own provider config and surfaces.
6. Adopt exact legacy state only; collide otherwise.
7. Migrate install and refresh together, then delete runtime writers, wrappers, reconcile calls, aliases, and compatibility paths.
8. Add import, ownership, partial-failure, and no-alternate-writer tests.

## Detailed Solution & Technical Design

Runtime layer keeps only: CLI/runtime executable lifecycle, ephemeral runtime-root allocation, request cleanup, and calling providers_api family functions explicitly.

Remove from runtime/harness/opencode/install/__init__.py:
- _build_agents_md() (writes AGENTS.md) -- superseded by the already-existing components/providers/adapters/opencode/surface.py render_contributions (make_single_file_contribution_renderer('AGENTS.md')), which is currently unused/dead code sitting alongside the runtime duplicate.
- _build_opencode_provider_config() (builds baseURL/apiKey/models block written to .opencode/config.json) -- move into a providers-owned OpenCode config family under MA16's locked provider API families.

Runtime boundary (folds in RU04's ownership doctrine, scoped to OpenCode): runtime SHOULD own native harness resolution, install/lifecycle composition, runner argument/environment construction, ephemeral runtime-root allocation, request cleanup, rig attachment. Runtime should NOT own MCP selection policy, provider serializers, provider capability declarations, model-source ownership, or provider/project surface writers (AGENTS.md, provider config blocks) -- those move to the providers component.
