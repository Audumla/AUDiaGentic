# Converge OpenCode harness materialization on managed owners

## Description

Relocated from managed-config-consistency MA03 (RV362) — deferred runtime/harness migration, unchanged in scope. Remove OpenCode runtime installer ownership of project MCP, model/provider, and instruction files. Runtime installs CLI and requests neutral reconciliation; providers/surface managers own project configuration.

## Steps

1. Characterize install/refresh outputs from runtime/harness/opencode/install: `.mcp.json`, `AGENTS.md`, `.opencode/config.json`, reload marker, commands, and failure behavior. Seed unmanaged content in each fixture.
2. Resolve canonical OpenCode config path/container under MO03 evidence (`.opencode/config.json` vs `.opencode/opencode.json`, `provider` vs `providers`). This item consumes the decision; it does not research or choose independently.
3. Define one composition-root operation `reconcile_installed_harness(project_root, harness_id)` using a neutral contribution registry. Ordered stages: provider managed config reconcile → provider surfaces apply → reload request. Return per-stage status, changed paths, action_needed; no provider-specific branches.
4. OpenCode installer performs only executable install/probe, then calls composition operation. Delete `_build_mcp_config`, `_build_agents_md`, `_build_opencode_provider_config`, and whole-file `materialize_agent_config` project writes.
5. Provider OpenCode adapter/descriptor owns MCP/model config desired entries and serializer. Surface renderer owns AGENTS.md. Harness config supplies neutral desired local endpoint/model data through contribution input, not direct file shape.
6. Adoption: existing file entries exactly matching old generated payload become managed; mismatches/unmanaged content remain user-owned and collide rather than overwrite.
7. Refresh invokes same composition operation; no alternate writer. Partial failure preserves earlier committed ownership and reports failed stage; never falls back to whole-file overwrite.
8. Delete OpenCode runtime read/write/remove wrappers and stale paths after callers migrate. Add architecture grep for project config literals in runtime harness.
9. Add OpenCode harness install README doctrine: executable installation is harness-owned; all durable project mutations are provider/surface owned; orchestration uses MA11 recipes/steps where applicable.

## Files

[RUNTIME] runtime/harness/opencode/install/__init__.py — CLI lifecycle only
[COMPOSITION] neutral harness reconcile contribution seam
[COMPONENT:providers] OpenCode descriptor/adapter desired config contributions
[COMPONENT:providers] surface manager owns AGENTS.md
[TEST] OpenCode install/refresh/adoption/cross-kind tests

## Validation

1. Characterization fixture proves required capability parity without whole-file overwrite.
2. Seeded unmanaged MCP/provider/model/AGENTS content survives install and refresh.
3. Exact old generated entries adopt; differing same-name entries report collision.
4. Install and refresh call one composition operation; writer call count proves no alternate path.
5. Runtime OpenCode harness contains no `.mcp.json`, `AGENTS.md`, `.opencode/*.json`, provider/container key literals after migration.
6. Stage failure returns deterministic partial result/action_needed and ownership registry remains readable.
7. Focused runtime/provider/surface integration tests green.

## Effort & Risk

Complex fresh-install migration. Gate on MO03 canonical OpenCode path decision and MO06 managed core. No compatibility writer fallback.
