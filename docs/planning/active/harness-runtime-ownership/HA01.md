# Converge OpenCode harness materialization on managed owners

## Description

Relocated from managed-config-consistency MA03 (RV362) — deferred runtime/harness migration, unchanged in scope. Remove OpenCode runtime installer ownership of project MCP, model/provider, and instruction files. Runtime installs CLI and requests neutral reconciliation; providers/surface managers own project configuration.

## Steps

1. Characterize OpenCode install/refresh outputs and unmanaged-content behavior.
2. Consume canonical OpenCode path/container decision from MO03.
3. Define one composition-root harness reconcile operation over provider public reconciliation plus surface application and reload.
4. Installer handles executable only, then calls composition operation.
5. Providers/surface renderer own desired config/surfaces.
6. Adopt exact legacy payload only; collide otherwise.
7. Refresh uses same composition path; report partial failure.
8. Delete runtime config writers/wrappers and add boundary guards.
9. Document ownership; reusable command sequencing uses completed `foundation.steps` where it reduces current duplication.

## Files

[COMPOSITION] neutral harness reconcile contribution seam

## Validation

1. Characterization fixture proves required capability parity without whole-file overwrite.
2. Seeded unmanaged MCP/provider/model/AGENTS content survives install and refresh.
3. Exact old generated entries adopt; differing same-name entries report collision.
4. Install and refresh call one composition operation; writer call count proves no alternate path.
5. Runtime OpenCode harness contains no `.mcp.json`, `AGENTS.md`, `.opencode/*.json`, provider/container key literals after migration.
6. Stage failure returns deterministic partial result/action_needed and ownership registry remains readable.
7. Focused runtime/provider/surface integration tests green.

## Effort & Risk

Complex fresh-install migration. Gate on MO03 canonical OpenCode path decision and MO06 managed core. No compatibility writer fallback.
