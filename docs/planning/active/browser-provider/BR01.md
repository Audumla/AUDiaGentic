# gpt-auto: Standalone browser-driven ChatGPT client — no pi dependency

## Description

A novel pi provider that drives a real browser instance (Chrome/Edge) to interact with ChatGPT. The provider simulates keyboard input into the ChatGPT tab, then gathers the response via DOM reading. This enables using ChatGPT as an LLM backend even without API access, by controlling the browser directly.

**Core workflow:**
1. Detect running Chrome/Edge browsers and enumerate their tabs
2. Give user a countdown timer to focus/select the target ChatGPT tab
3. Connect via Chrome DevTools Protocol to the selected tab
4. Inject the prompt (via simulated keystrokes or CDP DOM injection)
5. Poll for response via DOM reading
6. Stream the response back through pi's provider interface

**Descriptor update (BR01):** The gpt_auto.yaml provider descriptor has been updated to follow the same strict capabilities pattern as other providers (pi, opencode, aider, etc.), adding launch mechanism, harness_observability, model-config-projection evidence, and model-local-state evidence.

## Effort & Risk

- **Content**: **Complexity**: Advanced — requires Playwright MCP integration, async streaming, and browser automation orchestration.

**Risks:**
- ChatGPT UI changes could break DOM selectors (mitigate with resilient selectors and fallbacks)
- Rate limiting on GitHub polling if using that transport (mitigate with appropriate intervals)
- CDP connection instability — tabs can close, browsers can restart
- Security: the provider needs access to local browser state
- ChatGPT Plus features may differ from browser version
- Very slow compared to direct API providers (~30s-5min per request)
- Playwright Chrome extension must be installed
- Only one conversation per ChatGPT tab at a time

**Mitigations:**
- Multiple response methods (DOM primary, GitHub fallback)
- Graceful degradation with timeouts and error messages
- Clear documentation of prerequisites (Playwright extension, ChatGPT logged in)

## Design Principles

- **Zero external connectivity** — no API keys, no HTTP calls to OpenAI, no GitHub. Only Playwright MCP → Chrome → ChatGPT.
- **Fully self-contained** — all code lives in `adapters/gpt_auto/` only.
- **Reuses existing session** — login state, cookies, and extensions are already in the browser.

## Timeout Error Handling

- **Tab selection timeout** — if no ChatGPT tab found within `tab_selection_timeout`, return error.
- **Response wait timeout** — poll DOM every 2s for up to `response_wait_timeout` seconds.
- **Connection errors** — Playwright MCP not running → clear error message.
- **Tab closed mid-request** — detect and report as provider error.

## Why Playwright Mcp Over Raw Cdp Pyautogui

- Connects to existing Chrome tabs via the Playwright browser extension
- Reuses current login state, cookies, and extensions — no auth setup needed
- Proper typing, focus, Enter/Tab/Escape/arrows/shortcuts support
- DOM reading for response extraction — no need for raw CDP JavaScript eval
- Pi can use it through `pi-mcp-adapter` (already supported)
- No need for Chrome to be started with special flags

```python
def select_chatgpt_tab(playwright_mcp: McpClient) -> BrowserPage:
    """Use Playwright MCP to find and select a ChatGPT tab."""
    pages = playwright_mcp.call("browser_snapshot")  # or browser_page_list
    chatgpt_pages = [p for p in pages if "chat.openai.com" in p.url]

    # Display options with countdown
    display_tabs(chatgpt_pages, timeout=5)
    
    # Re-query to get the currently focused tab
    active = playwright_mcp.call("browser_snapshot")  # focused/active tab
    return active.active_page
```

### Response Reading via DOM
```python
def read_response(page: BrowserPage) -> str:
    """Read the last assistant message from ChatGPT's DOM."""
    # Playwright MCP can:
    # browser_snapshot → get current page state with accessibility tree
    # browser_element_handle → get element content by selector
    # browser_evaluate → run JavaScript on the page
    
    result = page.evaluate('''
        const messages = document.querySelectorAll(
            '[data-testid="message"], [data-message-author-role]'
        );
        const lastAssistant = [...messages].filter(m => 
            m.dataset.messageAuthorRole === "assistant" || 
            m.getAttribute("data-message-author-role") === "assistant"
        ).pop();
        return lastAssistant?.innerText || "";
    ''')
    return result
```

### Alternative: GitHub Commit Transport

For the GitHub transport (robust for long/complex responses):
1. The injected prompt includes instructions to commit response to a repo
2. After typing + Enter, poll GitHub for new commits on `browser-agent-responses` branch
3. Parse the committed file content as the response
4. Requires ChatGPT Plus with tool calling in browser

```python
def poll_github_response(
    owner: str, repo: str, branch: str = "browser-agent-responses",
    timeout: int = 300
) -> str | None:
    last_sha = get_head_sha(owner, repo, branch)
    deadline = time.time() + timeout
    
    while time.time() < deadline:
        current_sha = get_head_sha(owner, repo, branch)
        if current_sha != last_sha:
            return parse_file_content(owner, repo, branch, "response.md")
        time.sleep(5)
    return None
```

```python
def stream_browser_agent(model, context, options=None):

    stream = createAssistantMessageEventStream()
    
    async def run():
        output = AssistantMessage(
            role="assistant", content=[], api=model.api,
            provider=model.provider, model=model.id,
            usage={...}, stopReason="stop"

            tab = select_tab(browser, target_url_pattern="chat.openai.com")
            
            # 3. Inject prompt

            # 4. Poll for response
            response_text = poll_for_response(
                repo_owner="my-org", 
                repo_name="browser-agent-responses",
                timeout=300
            )
            if not response_text:
                # Fallback to DOM reading
                response_text = read_response_from_dom(tab)
            
            # 5. Stream text chunks back
            output.content.append({"type": "text", "text": ""})
            stream.push({"type": "text_start", "contentIndex": 0, "partial": output})
            
            for chunk in split_into_chunks(response_text):
                output.content[0]["text"] += chunk
                stream.push({
                    "type": "text_delta", 
                    "contentIndex": 0, 
                    "delta": chunk,
                    "partial": output
                })
            
            stream.push({"type": "text_end", "contentIndex": 0, "content": response_text, "partial": output})
            stream.push({"type": "done", "reason": "stop", "message": output})
        except Exception as e:
            stream.push({"type": "error", "reason": "error", "error": output})
        finally:
            stream.end()
    
    asyncio.create_task(run())
    return stream
```

## Component Browser Detection Tab Selection

### Chrome DevTools Protocol Connection
Chrome/Edge expose a remote debugging port on `localhost:9222` by default. The CDP provides:
- `http://localhost:9222/json/list` — list all tabs with URLs, titles, IDs
- WebSocket connection to each tab via `ws://localhost:9222/devtools/page/<id>`

## Component Prompt Injection

### Method 1: CDP-based (primary, fast)
```python
async def inject_via_cdp(tab: Tab, text: str):
    """Use CDP to directly set the textarea content."""
    async with cdpsession.connect(tab.webSocketDebuggerUrl) as session:
        # Find the input element and type into it
        await session.send('Input.dispatchKeyEvent', {
            'type': 'keyDown',
            'windowsVirtualKeyCode': ord(text[0]),
            'text': text,
        })
        # Or use DOM.setAttributeValue for direct injection
```

```python
import pyautogui

def inject_via_keyboard(tab: Tab, text: str):
    """Simulate real keyboard input."""

    pyautogui.typewrite(text, interval=0.05)  # human-like typing speed
```

## Component Response Transport Github

### The GitHub Commit Protocol
1. A dedicated repo exists with a branch `browser-agent-responses`
2. The prompt instructs ChatGPT to commit its response as a file
3. After injecting the prompt, poll for new commits on that branch
4. Parse the committed file to extract the response text
5. Delete/overwrite the file after reading (or use a counter-based filename)

### GitHub Polling
```python
def poll_for_response(
    repo_owner: str,
    repo_name: str,
    branch: str = "browser-agent-responses",
    timeout: int = 300  # 5 minutes
) -> str | None:
    """Poll GitHub for new commits containing the response."""
    last_commit_sha = get_head_sha(repo_owner, repo_name, branch)
    
    deadline = time.time() + timeout
    while time.time() < deadline:
        current_sha = get_head_sha(repo_owner, repo_name, branch)
        if current_sha != last_commit_sha:
            # New commit — extract response from the file
            content = get_file_content(repo_owner, repo_name, branch, "response.md")
            return parse_response(content)
        time.sleep(5)  # poll every 5 seconds
    
    return None  # timeout
```

### Fallback: DOM-based Response Reading
```python
async def read_response_from_dom(tab: Tab) -> str:
    """Read the response directly from ChatGPT's DOM."""
    async with cdpsession.connect(tab.webSocketDebuggerUrl) as session:
        # Evaluate JavaScript to extract message content
        result = await session.send('Runtime.evaluate', {
            'expression': '''
                // Find the last assistant message in the chat
                const messages = document.querySelectorAll('[data-testid="message"]');
                const lastAssistant = [...messages].find(m => 
                    m.getAttribute("data-message-author-role") === "assistant"
                );
                return lastAssistant?.innerText || "";
            '''
        })
        return result.get('result', {}).get('value', '')
```
