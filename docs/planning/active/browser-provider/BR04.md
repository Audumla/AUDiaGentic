# CDP session transport for gpt-auto so the gateway manages ChatGPT conversations as first-class sessions

## Description

Fold gpt-auto's tab->conversation->project mapping into a real AgentSessionTransport so the agent gateway can manage ChatGPT conversations with the same lifecycle it gives ACP sessions (open, serialized turns, keep-alive, idle/lifetime timeouts, quiescence, close, and AS49 resume-by-ref via conversation-id). Today gpt-auto is only a one-shot process provider: queue/dispatch.py routes it through execute_isolated_provider_turn (disposable subprocess per call) because _is_session_request only fires for ACP-session requests, and prepare_provider_session_transport returns transport=None for gpt-auto (no build_acp_launch, no session_surfaces declaration). The mapping in tab_state.py is provider-internal state keyed by project name; the gateway session-id is never linked to a ChatGPT conversation-id and clients cannot explicitly resume a conversation through the gateway.

The gateway side needs no changes: SessionRuntime (gateway/session/sessions.py) is transport-agnostic and already hosts any AgentSessionTransport via the injectable _provider_prepare_fn seam. The work is (a) a new gpt_auto/session_transport.py implementing the 5-method AgentSessionTransport protocol over the existing CDP code (workspace.ensure_workspace, prompt_injector.inject_prompt, dom_reader.wait_for_response, tab_state mapping), (b) widen prepare_provider_session_transport to build the CDP transport for a gpt-auto surface instead of returning transport=None, (c) declare a session_surfaces entry for gpt-auto in config/providers/gpt_auto.yaml plus a non-ACP surface hint (currently _build_default_surface_hint hardcodes '<provider-id>-acp'), and (d) an evidence probe proving a full open->prompt->terminal turn on at least one platform (the AS29 resolver gates on evidence.validated=true per platform, inventory proof RV770).

## Steps

- Design the GptAutoSessionTransport: open() -> ensure_workspace/activate mapped tab -> SessionOpenResult (returning conversation-id as provider_session_ref); prompt() -> inject_prompt + wait_for_response, emitting bounded TransportObservation (turn-accepted, activity, terminal) through the sink -> SessionTurnResult with final_summary; control() -> CANCEL_TURN (press stop), CLOSE_SESSION (mark closed/leave tab), others unsupported; close() idempotent; is_alive() -> tab present / CDP reachable (no owned child PID; gateway already tolerates child_pid=None).
- Implement src/audiagentic/components/providers/adapters/gpt_auto/session_transport.py reusing workspace.py, prompt_injector.py, dom_reader.py, cdp_client.py, tab_state.py; no gateway changes.
- Widen prepare_provider_session_transport (providers/services/execution/public_execution.py) with a non-ACP branch for the gpt-auto surface that builds the CDP transport; keep the ACP path untouched.
- Add a session_surfaces declaration for gpt-auto in src/audiagentic/config/providers/gpt_auto.yaml (surface_id e.g. gpt-auto-cdp, identity_operations open/resume-by-ref supported, controls cancel-turn/close-session supported, lifecycle_source, content_channels assistant-text, evidence + per-platform evidence).
- Handle the surface hint: add a non-ACP default hint path (gateway/session/dispatch.py _build_default_surface_hint currently hardcodes '<provider-id>-acp') so a sessionful gpt-auto request resolves instead of failing at 'no surface-id match'.
- AS49 resume wiring: resume_provider_ref flows into the transport's open() which navigates /c/{conversation-id}; validate_resume_eligibility must pass (surface declares resume-by-ref supported + evidence.validated=true).
- Add tests: unit tests for the transport mapping/control/close logic with a fake CDP client; integration probe test that opens a real ChatGPT conversation and drives one turn (this also produces the AS29 evidence reference).
- Update plan item state to completed only after gateway sessionful dispatch over gpt-auto is live-verified (open + continue + close), ledger event recorded.

## Detailed Solution & Technical Design

Architecture: the transport is the interchangeability seam already proven by ACP. AgentSessionTransport (foundation/transports/agent_session.py:474) is a 5-method Protocol; SessionRuntime hosts any implementation. gpt-auto already has all the pieces: tab_state.py persists project_name -> {tab_id, workspace_url, conversation_id} in .audiagentic/runtime/providers/gpt-auto-state.json; workspace.find_workspace activates the mapped tab and navigates /c/{conversation-id} (resume) or /project (fresh); adapter.py:287 writes the mapping back after each run. The transport wraps these:

- open(): ensure_workspace(project_name, conversation_id=None) -> if resume_provider_ref set, use it as conversation_id so open() resumes that exact conversation. Persist the resolved conversation-id into tab_state. Return SessionOpenResult.
- prompt(): build prompt from SessionPrompt.body (self-contained — ChatGPT is a pure chat provider, all info must be in the prompt), inject_prompt + wait_for_response with the on_chunk sink emitting ACTIVITY/TURN_ACCEPTED observations, then TERMINAL with stop_reason; return SessionTurnResult(final_summary=response text).
- control(): CANCEL_TURN maps to pressing the stop control via CDP; CLOSE_SESSION to marking the tab closed/idle; INTERRUPT/STEER/RESPOND_PERMISSION -> ControlDisposition.UNSUPPORTED.
- close(): idempotent; does not close the user's browser tab (external browser ownership), just detaches CDP and updates tab_state.
- is_alive(): tab still in browser list and CDP reachable.

Wiring seams that are currently ACP-only:
1. prepare_provider_session_transport (public_execution.py:512) resolves an AS29 surface then requires load_acp_launch_builder -> build_acp_launch and wraps in AcpAgentSessionTransport. Add a gpt-auto branch that returns the CDP transport. transport.open() returning the conversation-id gives AS49 resume-by-ref for free.
2. _build_default_surface_hint (gateway/session/dispatch.py:28) hardcodes f'{provider_id}-acp'. Needs a gpt-auto hint (e.g. gpt-auto-cdp).
3. gpt_auto.yaml has no session_surfaces block; pi.yaml:145 is the shape to copy (identity_operations, ownership_modes, controls, lifecycle_source, content_channels, evidence.validated, platforms, adapter_ref).

Constraint: resolve_session_surface gates on evidence.validated=true per platform plus inventory proof (AS27 RV770). So 'managed properly' also requires a real probe: open a ChatGPT conversation via CDP, drive one full turn, prove open->prompt->terminal. The live-verified tab-reuse and response-detection runs already performed are the raw material. Evidence discipline matters: do not claim tool-calling/steer/permission unless a probe proves them.

2. prepare_provider_session_transport returns a gpt-auto transport (not None) when the surface resolves; ACP providers still get AcpAgentSessionTransport (no regression).
3. Surface resolution: resolve_session_surface('gpt-auto', SurfaceHint('gpt-auto-cdp')) is supported with evidence.validated on the probed platform.
4. Live probe tests/gpt_auto/test_session_transport_live.py: open a real ChatGPT conversation via CDP, drive one turn, assert TERMINAL + final_summary, then close; also serves as the AS29 evidence reference.
5. End-to-end: gateway sessionful request (session-keep-alive) against a gpt-auto execution profile opens, continues, and closes the session through SessionRuntime; verify session record + binding written with provider-session-ref = conversation-id. Requires a running browser with a ChatGPT tab. Pace live runs to avoid bot detection (6 test conversations already triggered it).

## Effort & Risk

Complexity: advanced — protocol mapping, event-loop transport, evidence gate. Risks: (1) ChatGPT UI/DOM changes break selectors (mitigate with existing resilient dom_reader), (2) bot detection from frequent live runs — batch probe runs and use existing humanization (think-delay, jittered delays), (3) is_alive/child_pid semantics differ from ACP (external browser, no owned child) — gateway already best-effort on child_pid=None, (4) AS29 evidence gate requires a genuine probe per platform; claim only what is proven (no steer/permission claims), (5) surface hint default is ACP-only today — must add gpt-auto hint or sessionful requests fail at resolution.

## Acceptance Criteria

- gpt-auto exposes a real AgentSessionTransport with idempotent open/prompt/control/close lifecycle and closed observation kinds.
- Provider preparation returns the CDP transport for the validated gpt-auto surface without regressing ACP transports.
- Gateway session records keep gateway session ID distinct from provider conversation ID and persist conversation ID as provider-session-ref.
- A fake-CDP unit suite and one rate-limited live evidence probe prove a substantive terminal turn.
- Gateway-level open/continue/close works through SessionRuntime; explicit resume uses the persisted provider ref.
- No additional live browser load is run without owner approval.

## Notes

The gateway session-id must NOT be conflated with the ChatGPT conversation-id — the conversation-id is the provider_session_ref stored in the AS30 binding. The existing one-shot path must keep working unchanged; the transport is additive. Known gap being closed: _build_packet_ctx does not pass conversation-id into packet_ctx today, so explicit client resume is not possible until this lands.
