# Per-event tracked ledger store: no shared append file

## Description

Every PR that calls record_change_event appends one line to the single tracked docs/releases/CURRENT_RELEASE_LEDGER.ndjson, so as soon as one PR merges every other open PR conflicts in that file (GitHub mergeability and auto-merge ignore union merge drivers). Root cause: record writes a unique per-event fragment (gitignored runtime dir), then sync appends it to the one tracked file and purges the fragment. Two further conflict sources: git-commit stamping rewrites the whole ndjson, and plan-item-ids linking edits the plan item's Ledger-events section.

## Steps

Slice 1 (this item's first PR): store, loader, readers, archive.
1. Paths: events-dir (tracked, default docs/releases/events) and a generated-dir (untracked, .audiagentic/runtime/ledger/generated); ledger_events_dir(), ledger_generated_dir(). Retire the runtime fragments dir and the sync manifest. The current-ledger key stays but names the FROZEN legacy baseline, read-only.
2. record_change_event writes <events-dir>/<sha256(event-id)>.json atomically and write-once (canonical JSON, same schema/inputs/ids/timestamps). Same id + same immutable content = exists; different content = hard failure. A reader verifies digest == filename and path containment. An add/add conflict on one event file is desirable and must never be unioned.
3. One loader (new ledger/current_events.py): iter_events(project_root, ref=None) = frozen baseline (tolerant of legacy anomalies; deterministic synthetic id legacy-line-<n>-<sha8> for rows without event-id; unknown legacy change-class and missing timestamp accepted as-is, sorted first) + events dir (strict schema); ref reads use git ls-tree + git cat-file so a tagged release is reproducible. Order: baseline line order, then (timestamp-utc, event-id). Duplicate id across sources: identical = one event, different immutable content (git-commits excluded) = error. IDs in the historical ledger are released, never pending.
4. Switch every reader to the loader: ledger_api (get_pending_events, get_fragment, archive_for_release, status), audit, current_summary, archive, git_commits, bootstrap. get_current_summary, get_audit_report and bootstrap render in memory or write ONLY under the generated dir; no tracked summary is written by a normal operation.
5. sync_ledger becomes validation and diagnostics; it never appends, rewrites or purges.
6. Archive (release finalize, main only): the pending set = loader events minus historical ids; it writes only LEDGER.ndjson (released status and release id) and the release docs; it never edits or deletes baseline or event files, so there is no modify/delete conflict and no allowlist for deletions. Historical ids are authoritative: an event already in the historical ledger with the same identity is released and skipped, a different identity fails closed; a retry is idempotent at every write boundary.
Slice 2: plan-item links derived at read time from plan-item-ids; remove the Ledger-events/Change Log writing subscriber and the outbox together (planning component). Slice 3: release workflow and templates (stop staging the current ndjson, finalize stages LEDGER.ndjson and release docs only), git-commit stamping (keep disabled; never rewrite an aggregate; if enabled stamp only events added by that commit), docs, consumer migration note, conversion command for stale branches that still append to the frozen file.

## Validation

Real git merges in a temp repo: two branches each record an event (including a shared plan-item-id) and merge in both orders with no conflict and no custom merge driver, including a release finalized between branch creation and merge. Loader: baseline + events stable order; duplicate id identical/different; digest!=filename, malformed JSON, escaped paths, invalid role all rejected; legacy anomalies (row without event-id, unknown change-class, missing timestamp) loaded tolerantly with deterministic synthetic ids; ref reads match working-tree reads. Archive: crash injection at each write boundary then repeat finalize; stale branch carrying an already archived event; events of the next release preserved; baseline and event files never modified. Normal reads leave the tracked tree clean. Performance with the 1,611-row baseline plus 1,000/5,000/10,000 event files, including get_pending_events grouping. Standard suites tests/unit/ledger tests/unit/release tests/integration/release tests/unit/planning tests/unit/architecture.

## Acceptance Criteria

- Two PRs that each record a change event merge in either order with no conflict in any ledger file, and recording never writes a tracked shared file.
- record_change_event inputs, the change-event schema, event ids and timestamps are unchanged.
- No code reads the baseline ndjson except the loader; the loader reads any git ref.
- The 1,611 legacy rows of the consumer baseline (21 without event-id) all load and none is dropped or edited.
- Release finalize archives by event id into LEDGER.ndjson only, is idempotent after a crash at any write boundary, and a stale branch cannot resurrect a released event.
- Normal summary/audit/status operations leave the tracked tree clean.
- No compatibility shim: the old fragments dir, sync manifest, aggregate append and whole-file stamping are removed; a migration note and a conversion command cover stale branches and consumers.
