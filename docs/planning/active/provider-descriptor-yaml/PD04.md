# Update registry and adapter import mechanism

## Description

Wire provider discovery to YAML and adopt the shared mechanism by COMPOSITION (PD08 D2) — no rewrite of the component or feature registries.

## What changes
1. components/providers/descriptors/registry.py: keep the public surface (register, get_descriptor, all_descriptors, canonical_provider_ids, provider_alias_map, _register_feature_implementation, interrogate, _probe_cli). Internally, replace the bare `_registry: dict[str, ProviderDescriptor]` with a composed `DescriptorRegistry[ProviderDescriptor]`. The `_register_feature_implementation` coupling stays exactly as-is (PD08 #5).
2. Discovery moves from import-side-effects to YAML: add a `load_providers()` entrypoint that calls iter_descriptor_files(config/providers/) + the provider loader, replacing the per-adapter `register(ProviderDescriptor(...))` calls. Determine the single call site that currently triggers adapter import (providers/adapters/__init__._discover_adapter_packages) and repoint it: adapters are still imported for their SURFACE registrations, but descriptors now come from YAML. Verify whether surface registration also lived in descriptor.py — if so, keep a minimal surface-registration import path.
3. Provider load order: providers must be registered before any consumer queries them. Preserve the current eager-load trigger point (whatever imports adapters today) but have it call load_providers().

Containment rule (reviewed 2026-06-26): provider discovery/registry must not
import or load Hindsight-specific implementation modules. It loads
`config/providers/*.yaml` only. Hindsight orchestration imports generic provider
descriptor/recipe seams from its own `components/memory/hindsight/` package.

## What does NOT change (PD08 D2)
- foundation/components/registry.py — untouched.
- foundation/features/registry.py — the 5 multi-key dicts stay; no delegation to a unified store.
- No type-agnostic foundation registry that all three delegate to. DescriptorRegistry[T] is a reusable helper, adopted by providers now and by components/features only if/when they migrate.

## Validation

- all_descriptors() after load_providers() returns the same provider id set as the old import-side-effect path.
- _register_feature_implementation still fires per provider: feature registry contains each provider's ImplementationDescriptor + impl-features (assert).
- provider_alias_map / canonical_provider_ids unchanged.
- foundation/components/registry.py and foundation/features/registry.py are byte-identical (not modified).
- No import cycle: provider loader (components) -> foundation/descriptors -> foundation only.
- grep: no `audiagentic.components.providers.*` module imports `audiagentic.components.memory.hindsight`.

## Effort & Risk

Effort: mid. Risk: medium — the subtle part is the discovery/trigger repoint (surface registrations historically rode on adapter import alongside descriptor registration). Mitigate by separating the two concerns explicitly and asserting both descriptor set AND surface set are intact after the change.

## Execution guidance for lighter agents

- Treat descriptor loading and adapter/surface import as two separate concerns.
- Do not remove adapter imports until a test proves provider surfaces still load.
- Preserve `_register_feature_implementation` behavior exactly; feature registry
  coupling is intentionally out of scope for this migration.
- Do not import `components.memory.hindsight` from any provider module. Hindsight
  consumes generic provider seams; providers do not consume Hindsight.
- Stop and request review if registration order becomes lazy in a way that lets
  consumers query an empty provider registry.

## Decisions inherited from PD08 (2026-06-26)
- Registry consolidation is by COMPOSITION of DescriptorRegistry[T], NOT a tri-registry delegation rewrite. Feature/component registries are out of scope for this plan.
- _register_feature_implementation stays in the provider registry and keeps delegating to the feature registry.

## Superseded
The earlier 'unified type-agnostic foundation registry that component+feature+provider registries delegate to' design is dropped — see PD08 D2 for rationale (5-dict feature mismatch, no provider benefit, added coupling).
