# Migrate provider descriptors to YAML (bulk migration)

## Description

Migrate all 11 provider descriptors from Python to YAML under config/providers/, using the PD02 loader. Each adapter KEEPS its hook module(s) (catalog.py / hooks.py); only descriptor.py is replaced by a YAML file + (where needed) extracted hook functions.

## Reference YAML — common case (config/providers/claude.yaml)
```yaml
provider-id: claude
display-name: Claude (Anthropic)
description: Anthropic's Claude Code CLI...
url: https://claude.ai/code
access-mode: cli
prompt-aliases: [cld]
instruction-file: CLAUDE.md
skill-surface-path: '.claude/skills/{tag}/SKILL.md'
cli-probe: [claude, --version]
cli-install:
  toolchain: npm
  package: '@anthropic-ai/claude-code'
  executable: claude
permissions: {can-write-files: true, can-execute-shell: true, can-browse-web: true, can-read-env: true, notes: '...'}
host-capabilities:
  - {host: vscode, capability-id: anthropic.claude-code, display-name: Claude Code}
agent-files:
  - {rel-path: CLAUDE.md, managed: true, description: Project instructions / system prompt}
  - {rel-path: .claude/rules/prompt-tags.md, managed: true, description: Canonical prompt tag rules}
  - {rel-path: .claude/settings.json, managed: false, description: Claude Code user settings}
fetch-catalog-fn: 'audiagentic.components.providers.adapters.claude.catalog:fetch_claude_catalog'
mcp-config:
  config-path: '.mcp.json'
  format: mcp-json
  refresh-mode: file-watch
  reader: 'audiagentic.foundation.mcp.json_format:read_mcp_json'
  writer: 'audiagentic.foundation.mcp.json_format:write_mcp_json'
  remover: 'audiagentic.foundation.mcp.json_format:remove_mcp_json'
```

## Reference YAML — custom install + LSP hook (config/providers/pi.yaml)
```yaml
provider-id: pi
access-mode: none
cli-install:
  package-manager: pi-harness
  package-name: audiagentic-pi-harness
  executable: pi
  install:   {type: callable, id: install,   ref: 'audiagentic.components.providers.adapters.pi.hooks:pi_install'}
  uninstall: {type: callable, id: uninstall, ref: 'audiagentic.components.providers.adapters.pi.hooks:pi_uninstall'}
  probe-fn:  'audiagentic.components.providers.adapters.pi.hooks:pi_probe'
on-lsp-enabled: 'audiagentic.components.providers.adapters.pi.hooks:pi_ensure_lens'
mcp-config:
  config-path: '.mcp.json'
  refresh-mode: restart-required
  reader: 'audiagentic.foundation.mcp.json_format:read_mcp_json'
  writer: 'audiagentic.foundation.mcp.json_format:write_mcp_json'
  remover: 'audiagentic.foundation.mcp.json_format:remove_mcp_json'
```

## Hook extraction
Move the inline functions out of each descriptor.py into a sibling module so the YAML ref resolves:
- claude: _fetch_claude_catalog -> adapters/claude/catalog.py:fetch_claude_catalog
- pi: _pi_install/_pi_uninstall/_pi_ensure_lens/_pi_probe -> adapters/pi/hooks.py:pi_* (pi already has hooks.py)
- providers with probe_fn (qwen,copilot,roo,continue,opencode,openhands): move _*_probe -> adapters/<p>/hooks.py:<p>_probe
- catalog fetchers (opencode,local_openai): -> adapters/<p>/catalog.py
Shared reader/writer/remover already live in foundation.mcp.json_format / per-adapter config modules — reference them directly, do not duplicate.

Out of scope / containment (reviewed 2026-06-26): do not migrate
`config/components/memory/hindsight_matrix.yaml` into `config/providers/*.yaml`.
Provider YAML may expose generic seams such as `mcp-config` and `cli-install`;
backend-specific recipes, source URLs, recall/retain rules, Hindsight install
commands, and per-backend provider matrices remain under the owning
implementation package (`components/memory/hindsight/`).

## Providers (11): claude, codex, qwen, goose, pi, opencode, roo, copilot, plandex, continue_, local_openai. (aider, cline, gemini, openhands also have descriptor.py — confirm full adapter list with iter_modules and migrate ALL, not just the original 11.)

## Validation

- Every adapter package discovered by pkgutil.iter_modules has a corresponding config/providers/<id>.yaml.
- No config/providers/<id>.yaml contains backend-specific sections or keys such as `hindsight`, `memory-recipe`, `recall/retain`, or Hindsight source/install command data.
- For each provider: loaded ProviderDescriptor == current Python descriptor (provider_id, display_name, access_mode, permissions, agent_files, host_capabilities, cli_probe, cli_install.install/uninstall/probe_fn, mcp_config callables, fetch_catalog_fn, on_lsp_enabled, instruction_file, skill_surface_path, receive_lsp_mcp, prompt_aliases).
- cli-install declarative form: built install/uninstall steps equal build_step(toolchain,...) output for npm/uv/brew/vscode cases.
- All referenced dotpaths resolve (no VAL-DESC-001 at load).
- Hook modules contain no descriptor-registration side effects (pure functions).

## Effort & Risk

Effort: complex (11+ providers, hook extraction). Risk: medium-high — per-provider fidelity. Mitigations: golden-comparison test against the live Python object for every provider; migrate custom cases (goose/pi) first; keep Python descriptors in place until PD05 so comparison is possible. Watch: providers whose probe_fn closes over adapter state, and any reader/writer that isn't a top-level importable symbol (must be promoted to module level to be ref-able).
