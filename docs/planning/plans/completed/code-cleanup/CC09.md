# A30 (optional) — VS Code .vscode/extensions.json recommendations

## Description

Provider-declared VS Code extensions are tracked internally but not surfaced to VS Code. No version/metadata from installed extensions.

## Steps

Generate `.vscode/extensions.json` during reconcile/install/uninstall. Derived from enabled providers' `host_capabilities` with `host == 'vscode'`. Read `package.json` from `~/.vscode/extensions/<ext>/` for version/metadata.

**New file:**
- `providers/services/extensions_json.py` — `build_recommendations()`, `write_extensions_json()`, `prune_extensions_json()`

**Modified files (5):**
- `providers/services/host_capabilities.py`, `providers/services/reconcile.py`, `providers/services/lifecycle.py`, `providers/providers_api.py`, `providers/services/status.py`

## Files

New: `providers/services/extensions_json.py`
Modified: 5 files — see plan

## Validation

'.vscode/extensions.json' created/updated during reconcile, version/metadata from package.json, idempotent, user-preserved unmanaged recommendations.

## Architecture Standards Assessment

**Standards risk: Standard #4 (Platform Independence).** Must not hardcode VS Code paths or CLI. Use a pluggable host adapter. The generation logic should check `host == 'vscode'` at runtime and delegate to the host adapter for path resolution.

## Resolution Assessment

**Complexity: Easy.** Straightforward implementation.

**Solution:** Add `extensions_json.py` in `providers/services/`. During reconcile, if `host == 'vscode'`, generate `.vscode/extensions.json`. Read `package.json` from installed extensions for version/metadata. Keep user-preserved unmanaged recommendations. CC09 and ML03 are the same work.

**Files:** 1 new file, 5 integration points (host_capabilities.py, reconcile.py, lifecycle.py, providers_api.py, status.py).
