# Flatten feature state nesting with composite keys

## Description

Feature state uses 3-level nesting: `component -> features[kind][id]` and `component -> implementations[id] -> features[kind][id]`. The `get_implementation_feature_enabled_explicit` function requires 30 lines of defensive isinstance checks and `.get()` chaining.

## Proposed Solution

Flatten to composite keys: `language:python`, `language:cpp`. Or introduce a `FeaturePath` dataclass that encapsulates the nesting logic.
