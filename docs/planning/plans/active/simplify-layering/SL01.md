# Descriptor bloat

## Description

`ComponentDescriptor` carries 20+ fields. Most components use only a subset (e.g., `session` uses MCP servers and harness instructions but not external MCP servers or dependencies). The fat dataclass forces every consumer to carry unused fields and obscures which fields are relevant for a given component.

## Proposed Solution

Split `ComponentDescriptor` into composable mixins:
- `BaseDescriptor` — id, display name, description, detection marker, scope, core flag
- `FileDescriptorMixin` — files, lifecycle modes
- `McpServerMixin` — mcp servers, external mcp servers
- `LifecycleMixin` — hooks, observers, post-install
- `FeatureMixin` — implementation cardinality, feature kinds

Compose via nested dataclasses or a flat descriptor that delegates to focused sub-objects. Reduces per-component memory footprint and makes validation scoped to relevant fields.

## Architecture Standards Assessment

**Standards risk: Standard #3 (Logic Containment — God objects).** However, this is a dataclass, not a god object. The "fat dataclass" is not causing bugs — it carries unused fields. Splitting into mixins is a structural improvement, not a bug fix.

## Resolution Assessment

**Complexity: Complicated.** Cross-cutting refactor with high effort and no immediate value.

**Solution:** Split `ComponentDescriptor` into composable mixins (BaseDescriptor, FileDescriptorMixin, McpServerMixin, LifecycleMixin, FeatureMixin). Requires updating all component loaders, registries, and consumers. Every component that constructs or consumes the descriptor must be updated.

**Why complicated:** Cross-cutting refactor touching every component. High effort, no immediate value. The dataclass works as-is; the unused fields are a maintenance concern, not a correctness issue.

**Files:** 8+ — descriptor split, all component loaders, registries, consumers.

## Effort & Risk

Effort: High. Risk if unchanged: Technical debt, but not breaking.
