# Options resolution lacks provenance

## Description

`resolve_options` merges layers (descriptor defaults -> component options -> feature/implementation state) but discards which layer provided each value. When debugging why an option has an unexpected value, there's no audit trail.

## Proposed Solution

Return a `ResolvedOption` dataclass `(value, source: str)` alongside the resolved dict, where `source` is one of `'descriptor-default'`, `'component-state'`, `'feature-state'`, `'implementation-state'`. Add an MCP tool `get_option_provenance` for debugging. Keep the existing `dict[str, Any]` return for callers that don't need provenance, but make the enriched version available.

## Effort & Risk

Effort: Low. Risk if unchanged: Debugging difficulty grows with adoption.
